# Phase 6 기획 — MVP 완성도 다듬기 (데이터·기능 정비, 버그 수정, UI 개선)

> 이어서 읽기: [Phase 5 기획](phase5-plan.md)
> Phase 5에서 특성/기술 전투 로직을 대거 완성하면서 사용자가 Phase 6으로 명시적으로 이월한 3개 항목(헤롱헤롱 성별 데이터, 샘플파티/샘플 저장, 로그 UI 정비)을 그대로 가져왔고, 여기에 더해 Phase 6 전체의 성격을 "새 대규모 기능보다는 기존 데이터·기능 재점검, 작은 버그 수정, UI 개선 — MVP 완성도를 다듬는 페이즈"로 사용자가 확정했다(2026-08-26).

## 0. 이 문서의 성격

Phase 1~5는 매번 "새 엔진 인프라를 만드는" 확장 페이즈였다. Phase 6은 방향이 다르다 — 새 기능보다는 지금까지 쌓인 것들을 다시 살펴보고 다듬는 데 집중한다. 이 문서는 두 부분으로 나뉜다:

- **§1**: Phase 5에서 이미 "이건 Phase 6에서 한다"고 확정해둔 3개 항목. 배경·요구사항은 phase5-plan.md에 이미 적혀있던 걸 그대로 옮겨왔다.
- **§2**: 사용자가 이번에 확정한 "다듬기" 방향에 따른 정비 후보. Phase 5 §5(발견된 버그)와 같은 성격의 living 섹션이라, 작업하면서 계속 추가·정리한다 — 지금 적힌 건 착수 시점에 이미 알려진 것들뿐이고 전수 조사 결과가 아니다.

- `types/pokemon.ts`에 `PokemonGenderCategory`("both"/"male-only"/"female-only"/"genderless")와 `Pokemon.genderCategory` 신설. 로스터 42종 전수 조사(Bulbapedia 성비 기준) 결과 39종이 "both", **메타그로스·타부자고**만 무성별, **캥카**만 암컷 전용 — male-only는 이 로스터에 해당 종이 없었다.

- `types/status.ts`의 `VolatileCondition`에 `"attract"` 신설 — ingrain/leechSeed와 같은 "배틀 끝까지 유지"형(1v1이라 교체로 해제될 일이 없음). `resolveAction`에서 걸려있는 동안 매 행동 판정마다 50% 확률로 행동불능(`ATTRACT_ACTION_BLOCK_CHANCE`, `volatileConditions.ts`).

**추가 확장(사용자 요청, 2026-08-27): 대전 로그·매치업 페이지에서도 샘플 불러오기**

파티 편성 화면 전용으로 끝내지 않고, 다른 두 화면에도 샘플 기능을 연결했다. `useSlotPresets`(저장소)는 세 화면이 전부 공유 — 한 화면에서 저장한 샘플이 나머지 두 화면에도 그대로 보인다.

- **대전 로그 페이지**(`BattleSetupCard.tsx`/`useBattleSetup.ts`): 슬롯 타입이 파티 편성 화면과 완전히 같은 `PartySlot`이라 저장/불러오기 둘 다 그대로 이식 — `useBattleSetupSlot`에 `loadSlot(slot)` 추가.
- **매치업 페이지**(`MatchupSlotCard.tsx`/`useMatchup.ts`): 슬롯 타입이 다르다(`MatchupSlot`은 기술을 4개가 아니라 1개(`moveId`)만 갖고, 랭크 상태(`stages`)를 별도로 가짐) — 사용자 확인 결과 (1) **불러오기만 지원, 저장 기능 자체는 뺀다** (2) 불러올 때 **기술 배치는 가져오지 않는다**(포켓몬을 바꾸면 항상 그러듯 기술/랭크는 초기화)로 확정. `useMatchupSlot`에 `loadFromPartySlot(partySlot)` 신설 — `pokemonId`/`activeMegaForm`/`ability`/`item`/`nature`/`points`만 옮기고 나머지는 `EMPTY_MATCHUP_SLOT` 기준으로 리셋.
- 스모크 테스트(브라우저, 두 화면 다 새로 띄운 서버로 확인): 대전 로그 페이지에서 샘플 불러오기 → 포켓몬+기술까지 정확히 복원. 매치업 페이지에서 같은 샘플 불러오기 → 포켓몬은 복원되지만 "기술 선택"은 비어있는 상태(의도대로 기술 미포함) 확인.

## 2. MVP 완성도 다듬기 (신규, 사용자 확정 2026-08-26)

사용자가 이번에 Phase 6의 성격을 확정했다: "전체적으로 다시 한번 데이터나 기능들을 다듬고, 기타 작은 버그들 처리, UI변경 등 MVP의 완성도를 다듬는 페이즈." 아래는 착수 시점 기준으로 이미 알려진 정비 후보다 — Phase 5 §5(발견된 버그)와 같은 패턴으로, 작업하면서 계속 채워나간다.

## 4. §2-1 중 아키텍처 재검토가 필요했던 2건 — 결론

2026-08-26에 §2-1 정비 후보를 훑으면서 나머지 항목(우격다짐 도구 상호작용·잠꼬대 정밀화·멘탈허브)은 자체적으로 완결했지만, 아래 2건은 "고치면 더 정확해지지만 판정 순서/구조 자체를 바꿔야 하는" 성격이라 섣불리 손대지 않고 재확인만 하고 남겨뒀었다. 둘 다 결론이 났다.

- ~~**매치업 페이지 미반영 축**~~ — **Phase 6.5로 분리(2026-08-26)**. 사용자 확인: 매치업 페이지도 "1대1 대결" 페이지인 이상 반영돼야 하는 로직은 전부 반영돼야 한다 — 단, 토글(켜고 끄기)로 "이전 턴에 이런 일이 있었다고 가정"을 사용자가 직접 선택하는 방식으로. 여기에 스피드 비교 기능 신설까지 묶어서 범위가 커져 별도 문서로 분리했다. 자세한 내용은 [phase6.5-plan.md](phase6.5-plan.md) 참고.
- ~~**기습의 범위 밖 케이스**~~ — **재검토 결과 수정 불필요로 확인·종결(2026-08-27)**. 당초 우려는 "상대가 실제로 데미지 기술을 쓸 수 있는 상태인지(상태이상으로 행동 자체가 막히는 경우 포함)까지 반영하려면 판정 순서 자체를 바꿔야 한다"였는데, Bulbapedia로 본가 규칙을 먼저 확인해보니 **애초에 반영할 필요가 없는 것으로 확인됐다** — 본가에서도 기습은 상대가 그 턴에 "선택한" 기술의 카테고리만으로 판정하고, 그 기술이 마비/잠듦/냉동/트루언트 등으로 실제 실행되는지는 전혀 고려하지 않는다(Bulbapedia: "Sucker Punch only depends on the move the target has selected, and is not affected by any consideration of whether the attack was actually executed"). 이 프로젝트의 기존 구현(`battleSimulator.ts`의 `defenderMove.category`만 확인)이 이미 정확했다. 판정 순서 변경도, 코드 수정도 불필요 — 조사만으로 종결.
