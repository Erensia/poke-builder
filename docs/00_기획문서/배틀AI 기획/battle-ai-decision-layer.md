## 0. 공통 엔진 문서 대비 변경 사항 (중요)

이 레이어를 설계하는 과정에서 공통 엔진의 출력 형식 일부가 함께 수정되었다. `battle-ai-common-engine.md`를 v1.1로 갱신할 때 아래 내용을 반영해야 한다.

| 필드 | 기존(v1.0) | 변경(v1.1) | 사유 |
|---|---|---|---|
| `hits_to_kill` | `{ count, certainty, probability }` (이산 분류) | `{ expected, worst_case }` | 데미지 롤 편차를 확률 가중 기대값으로 반영 |
| `hits_to_be_killed` | `{ count, certainty, probability }` (이산 분류) | `{ expected, worst_case }` | 상대 보유 기술 4개의 사용 확률을 반영한 기대값으로 전환 |

`worst_case`는 기존 이산 분류(`{ count, certainty, probability }`) 형식을 그대로 유지한다.

## 1. 파티 성향 처리 방침

파티 성향(대면/사이클/전개) 자동 분류(구 B안)는 채택하지 않는다.

| 단계 | 방식 | 상태 |
|---|---|---|
| 1단계 | 성향 구분 없는 범용 가중치 세트 하나로 전체 판단 | **본 문서의 범위 (지금 여기)** |
| 2단계 | 사용자가 파티/포켓몬에 직접 태그 지정 → 태그별 가중치 오버레이 | 범위 외 (다음 단계) |
| 3단계 | 파티 구성 자동 분석 후 성향 추론 | 장기 검토, 현재 미채택 |

## 2. 상대 기술 사용 확률 모델 (`hits_to_be_killed.expected` 산출용)

상대의 보유 기술 4개를 분류하여 사용 확률(가중치)을 부여한다.

| 분류 | 조건 | 가중치 처리 |
|---|---|---|
| 제외 | 상성 배율 0 (무효) | `weight = 0` |
| 중복 함정 | 이미 필드에 설치된 효과와 동일한 설치기 (예: 이미 깔린 스텔스록) | `weight = 0` (강제) |
| 변화기 전반 (설치기·랭크업기 등, 직접 데미지 없음) | 위 두 경우 제외한 나머지 변화기 | 고정 `w_status = 0.15` (기술 1개당, 여러 개면 균등 분배) |
| 공격기 | 유효 데미지 존재 | 데미지 비례 분배 (아래 수식) |

```
남은_가중치 = 1.0 − (변화기_개수 × w_status)
weight_i = (damage_i / Σ damage_j) × 남은_가중치     # j는 모든 공격기
```

```
E[damage_per_turn] = Σ (weight_i × damage_i)
hits_to_be_killed.expected = 잔여체력 / E[damage_per_turn]
```

### 2-1. 랭크업기 리스크 별도 처리

랭크업기(칼춤·용의춤 등)는 가중치 조정 대상이 아니다. 이번 턴 기대 데미지에는 기여하지 않으므로 위 계산에서는 flat 변화기와 동일하게 취급한다. 대신 **미래 리스크**로 별도 플래그를 둔다.

```
risk_flag = true   if 상대가 보유한 변화기 중 랭크업(공격 관련 스탯 상승) 효과가 하나라도 있음
```

### 2-2. 모델 보정 (2026-09-24)

v1 모델은 상대 피해를 체계적으로 낮게 봤다 — 변화기마다 0.15씩 떼고, 남은 확률도 약한 공격기에까지 데미지
비례로 나눠서다. 잠자기 루프(§4-1)의 원인이었고, 벽의 가치도 작게 계산됐다. 세 가지 보정을 파라미터로 넣었다.

| 보정 | 내용 | 파라미터 | 채택값 |
|---|---|---|---|
| 지금 효과 없는 변화기 제외 | HP가 가득인데 회복기, 올릴 스탯이 전부 +6인 랭크업기, 이미 자기 편에 깔린 벽, 이미 상태이상인 대상에게 거는 상태이상기 → 가중치 0 | `threatStrictWaste` | true |
| 변화기 가중치 | 의미 있는 변화기 1개당 사용 확률 | `threatStatusWeight` | 0.08 (v1 0.15) |
| 공격기 분배 날카로움 | 공격기 사용 확률 ∝ 데미지^k (k = 1이면 v1) | `threatSharpness` | 3 |

```
남은_가중치 = 1.0 − (의미 있는 변화기 개수 × statusWeight)
weight_i   = (rate_i^k / Σ rate_j^k) × 남은_가중치
```

**평가 방법 주의**: 그리디 봇은 항상 최선기만 쓰므로 그리디 승률만 보면 "상대는 최선기만 쓴다" 쪽으로 과적합된다.
그래서 새 모델 AI와 v1 모델 AI를 직접 붙이는 `sim:ai -- h2h`로도 비교했다(STATUS=1 파티, 각 400판).

| 설정 | 그리디 상대 | h2h vs v1 모델 |
|---|---|---|
| v1 (0.15, k 1, 제외 없음) | 247 | — |
| 제외만 | 250 | |
| 제외 + 0.08 | 252 | 196 : 196 |
| 제외 + k 3 | 249 | |
| **제외 + 0.08 + k 3 (채택)** | **253** | **196 : 197** |
| 극단: 제외 + 0 + k 20 (변화기 무시·최선기만) | 255 | 202 : 192 |

결과는 전부 오차 범위(±10) 안 — **모델 보정은 승률을 거의 바꾸지 않는다**. 채택 이유는 승률이 아니라 논리적
타당성(효과 없는 변화기를 쓸 거라고 보는 건 틀림)과 피해 과소평가 완화다. 극단값은 "상대가 랭크업기를 절대 안
쓴다"는 가정이 돼 사람 상대로 랭크업 경계가 약해질 수 있어 채택하지 않았다.
코드: `opponentMoveModel.ts`의 `DEFAULT_THREAT_MODEL`(v1은 `V1_THREAT_MODEL`), 평가 중에는 `withThreatModel`로 적용.

## 3. 자신의 기대 타수 (`hits_to_kill.expected`)

데미지 롤(85~100%) 편차로 인해 "몇 타에 끝나는지"가 확률적으로 갈리는 경우, 확률 가중 평균으로 계산한다.

```
예) 난수2타 62% (나머지는 3타)
hits_to_kill.expected = (2 × 0.62) + (3 × 0.38) = 2.38
```

확1타/확2타처럼 확정적인 경우는 `expected = count` 그대로 사용한다.

## 4. 핵심 점수 공식 — HP 교환식 (v2, 2026-09-24 채택)

> v1 원안(`exchange_advantage = d − c` + 속도 보정 ±0.5 + 교체 템포 −0.3)은 시뮬레이션에서 결함이 확인되어
> 이 식으로 교체했다. 경위와 수치는 §11 참고. 원안은 코드에 `scoring: "spec"`으로 남아 있다.

**원칙**: 모든 옵션을 같은 단위 — **각자 최대 HP 대비 비율** — 로 비교한다. "처치 후 남는 여유 턴 수"(d − c)는
포켓몬마다 HP·내구가 달라서 옵션끼리(특히 기술 사용 vs 교체) 비교할 수 없기 때문이다.

옵션을 고른 뒤 그 대면을 끝까지 이어간다고 보고, 결과를 "상대 HP 제거 비율 − 내 HP 손실 비율"로 매긴다.

```
c = hits_to_kill.expected      # 내가 상대를 쓰러뜨리는 기대 턴 수
d = hits_to_be_killed.expected # 상대가 나를 쓰러뜨리는 기대 턴 수
p = 선공 확률(0~1)              # 선공 1 / 동속 0.5 / 후공 0 — 선제공격손톱 확률까지 섞인 값
my  = 대면 시작 시 내 HP / 내 최대 HP       # 교체는 진입 비용을 뺀 뒤
opp = 상대 현재 HP / 상대 최대 HP
lost = 이번 턴 공격하지 않으면 1(교체·회복·랭크업), 공격하면 0

def race_value(c, d, p, my, opp, lost):
    if c == ∞ and d == ∞: return 0                 # 서로 못 쓰러뜨림
    opp_hits = c + lost − p                          # 내가 처치할 때까지 상대가 때리는 횟수
    if opp_hits < d:                                 # 이기는 대면
        return opp − my × max(0, opp_hits) / d       #   상대 전부 제거 − 그동안 내가 잃는 HP
    my_hits = max(0, d − (1 − p) − lost)             # 지는 대면: 쓰러지기 전까지 내가 때리는 횟수
    return opp × min(1, my_hits / c) − my            #   깎은 만큼 − 내 남은 HP 전부
```

| 옵션 | 점수 |
|---|---|
| 공격기 사용 | `race_value(c, d, p, my, opp, 0)` |
| 교체 | `race_value(c, d, p, my, opp, 1) − entry_cost / max_hp` (c·d·p는 교체 후 다음 턴 기준) |
| 유턴류(맞히면 교체, 교대 가능 포켓몬 있을 때) | 아래 `pivot_value` — 교대 포켓몬이 없거나 한 방에 쓰러뜨리면 일반 공격기로 평가 |
| 회복기 | `race_value(내 최선 공격의 c, 회복 후 d, p, 회복 후 my, opp, 1) + (회복 후 my − 지금 my)`. 광합성류(날씨별 회복량)·잠자기(완전 회복 + 2턴 잠든 상태로 c 재계산)도 포함. **회복 순이득 ≤ 0이면 `−∞`**(§4-1) |
| 랭크업기 | §4-2 — 랭크업을 적용한 state로 c·d·p를 모두 재계산(`effect_value`, 명중 1). 배턴터치 보유 시 "올린 뒤 넘기기"와 큰 쪽. 이미 +6 등으로 변화가 없으면 `−∞`. (v1: `race_value(랭크업 후 최선 공격의 c, d, p, my, opp, 1)`, `setupAware: false`) |
| 효과 변화기(상태이상 부여·상대 랭크다운·벽·설치기) | §4-1 `effect_value` — 실패하면 `−∞` |
| 배턴터치 | 유턴류 `pivot_value`와 같음(chip = 0, 명중 1, 후보는 내 랭크를 이어받은 상태로 평가) |
| 날씨·필드·트릭룸·도발·앙코르·사슬묶기 | §4-3 — `effect_value`에 지속 턴 자르기(c·d·p) |
| 방어류(방어·판별·킹실드·니들가드·토치카·패스트가드·버티기·길동무) | §4-4 — 엔진 한 턴 시뮬레이션 + 재평가, 묶음별 판단 |
| AI-A1 변화기(흑안개·신비의부적·아쿠아링/뿌리박기·씨뿌리기·혼란·헤롱헤롱·하품·희망사항·배북) | §4-6 — 효과 변화기(§4-1)·회복기·랭크업기(§4-2) 틀에 편입 |
| AI-A2 변화기(대타출동·잠꼬대·울부짖기/날려버리기·추억의선물) | §4-7 |
| 그 외 변화기(썰렁개그·스왑류·멸망의노래 등 Tier 2) | 아직 설계 안 함 — 선택하지 않음(`−∞`). 목록은 1.8-backlog §4-1 |

모든 옵션에서 공통으로 `risk_flag`면 `trade_risk_penalty_base(0.1) × risk_aversion`을 뺀다.

**유턴류(유턴·볼트체인지·퀵턴 등, `selfSwitchAfterDamage`)** — 맞히면 엔진이 교체를 강제하므로 "남아서 계속
쓰는" 계산 대신 공격 + 교체로 평가한다(2026-09-24 추가).

```
hit_rate   = 한 번 맞혔을 때 깎는 상대 현재 HP 비율
chip       = opp × hit_rate
after_hit  = 교체 후보들을 "hit_rate만큼 HP가 줄어든 상대" 기준으로 다시 평가한 교체 옵션
active_hit = 지금 포켓몬이 상대 공격을 한 번 맞을 때 잃는 HP 비율

switch_in(후보, lost) = race_value(후보 c, 후보 d, 후보 p, 후보 my, 후보 opp, lost) − 후보 진입 비용 비율
best = max over 후보 [ p × switch_in(후보, 1)                       # 선공: 들어온 후보가 이번 턴 한 대 맞음
                     + (1 − p) × (switch_in(후보, 0) − active_hit) ] # 후공: 지금 포켓몬이 맞고 후보는 안전하게 등장
pivot_value = accuracy × (chip + best) + (1 − accuracy) × (−active_hit)   # 빗나가면 교체 없이 한 대 맞음
```

| 항목 | 설명 |
|---|---|
| 선공 처리 | 별도 ±0.5 보정 대신 경기 계산 안에서 "선공이면 상대가 마지막 한 번을 못 때림"(`− p`)으로 반영 |
| 교체·회복·랭크업 | 이번 턴 공격을 안 하므로 "상대가 한 번 더 때린다"(`+ lost`). 원안의 고정 템포 페널티(−0.3)를 대체 |
| 진입 비용 | 교체 시 설치물로 잃는 HP 비율을 그대로 뺀다(원안의 ×1.5 가중치는 단위가 HP 비율이 되어 불필요) |
| risk_flag | 랭크업기 보유 상대 경계. HP 비율 단위라 원안(0.4)보다 작은 0.1 |

## 4-1. 효과 변화기 — 적용 후 재평가 + 이월 항 (2026-09-24 추가)

**설계 판단**: 별도의 다턴 탐색 구조를 두지 않는다. `race_value`는 이미 "이 비율로 대면을 끝까지 이어가면"이라는
여러 턴짜리 모델이고, 변화기 이득은 대부분 **그 비율을 바꾸는 것**(화상 → 상대 물리 화력 반감, 마비 → 선공 역전
·행동불능, 벽 → 받는 피해 반감, 랭크다운 → 화력/내구 변화)이라 race_value 안에서 흡수된다. race_value가 볼 수 없는
것은 **대면이 끝난 뒤에도 남는 효과**(설치기, 남은 벽 턴)뿐이라 이것만 명시적 이월 항으로 더한다.
완전한 다턴 탐색(가상 runTurn 반복)은 판단 시간이 수십 배로 늘고, 교체·공격까지 새 구조로 옮기지 않으면 옵션끼리
같은 식으로 비교한다는 원칙이 깨져서 채택하지 않았다.

```
1. state를 복제하고 변화기의 지속 효과만 직접 적용(엔진을 돌리지 않음)
     상태이상: 상대 status / 랭크다운: 상대 stages / 벽: 내 편 screens / 설치기: 적용 없음(현재 대면 무관)
2. 같은 평가 함수로 현재 대면을 다시 계산 → c′, d′, p′   (새 계산 로직 없음 — 평가기가 이미 state에서 읽는다)
3. 지속 턴으로 자름(벽만): covered = 벽 턴 수 − 1 + 이 기술의 선공 확률
     d′ = d_벽 ≤ covered ? d_벽 : covered + (1 − covered / d_벽) × d_원래
4. effect_value = 명중률 × race_value(c′, d′, p′, my, opp, 1)
               + (1 − 명중률) × race_value(c, d, p, my, opp, 1)
               + w_carry × carry
```

| 효과 | 재평가에 반영되는 경로(코드) | carry(이월 항, HP 비율) |
|---|---|---|
| 독·맹독·화상 | `turnsToKo`의 지속 데미지, 화상 물리 반감(`computeStatusAttackMultiplier`) | 0 |
| 마비 | 행동불능 12.5%(`actionFactor`), 스피드 반감(`buildTurnOrderActor`) → p′ | 0 |
| 잠듦 | 막히는 턴(`blockedTurns`)이 상대 처치 턴에 더해짐 | 0 |
| 상대 랭크다운 | `estimateMoveHits`가 상대 stages를 읽음(심술꾸러기·클리어바디류·미러아머 반영) | 0 |
| 벽 3종 | `screenFor` → 방어 배율 ×2, 위 3단계로 지속 턴 자름 | 남은 벽 턴 × 막는 피해 비율 × 다음에 맞을 포켓몬의 턴당 손실(이기는 대면이면 지금 포켓몬, 지는 대면이면 대기 포켓몬 평균) |
| 스텔스록·압정뿌리기 | 없음(c·d·p 그대로, 이번 턴 공격 손실만) | 상대 대기 포켓몬별 등장 데미지 증가분 합(`calcEntryHazardDamage`) |
| 독압정 | 〃 | 접지·독 면역 아닌 대기 포켓몬마다 독 3턴분(1층 3/8, 2층 맹독 누적분 − 1층분) |
| 끈적끈적네트 | 〃 | 접지 대기 포켓몬 1마리당 0.1 고정(스피드 −1 근사) |

- 맹독은 `turnsToKo`가 현재 카운터로 계산하면 매 턴 1/16 고정으로 과소평가되므로, 대면 기간(원래 c, 최대 6턴)의
  평균 카운터로 적용한다.
- **실패 판정**(같은 변화기를 매 턴 반복하지 않게 하는 핵심 장치) — 엔진 판정을 그대로 옮겼다(`effectMoveFails`):
  이미 걸린 벽, 최대로 깔린 설치기, 오로라베일 날씨 조건, 이미 상태이상인 상대, 타입·특성 면역(`isImmuneToStatus`,
  부식 포함), 필드 차단(`isStatusBlockedByField`), 신비의부적, 황금몸, 매직미러(설치기 포함), 대타출동, 풀 타입의
  가루 기술 면역, 방음. 랭크다운이 실제로 아무 스탯도 못 바꾸면(−6·클리어바디 등) 역시 선택하지 않는다.
- 효과가 상대 편에만 남는 상태이상은 상대가 교체해도 유지되지만, 그 이득은 아직 셈하지 않는다.

**회복 순이득 조건(회복 루프 방지)**: 회복기 점수는 "회복 후 계속 공격한다"는 가정인데, 다음 턴의 AI가 다시 회복을
고르면 가정이 깨진다. 잠자기에서 "잠자기 → 2턴 잠 → 다시 잠자기"가 반복되며 상대 HP가 전혀 줄지 않는 루프가
시뮬레이션에서 나왔다. 그래서

```
회복 순이득 = 회복 후 HP − 지금 HP − (회복에 쓰는 턴 수) × (상대가 최선 공격기만 쓸 때 턴당 피해)
             # 회복에 쓰는 턴 = 1, 잠자기는 1 + 잠든 턴
순이득 ≤ 0 이면 회복기 점수 = −∞
```

턴당 피해를 사용 확률 모델(§2)이 아니라 **최선 공격기 기준**으로 잡는 건, 사용 확률 모델이 변화기에 가중치를
나눠서 실제 피해를 절반 가까이 낮게 보는 경우가 있었기 때문이다(루프 사례의 원인). 루프 판정은 보수적이어야 한다.

## 4-2. 랭크업기 재평가 + "올린 뒤 배턴터치" (2026-09-24 추가)

**v1의 구멍**: 랭크업기는 "랭크업 후 내 처치 턴(c)"만 다시 계산하고 선공(p)·버티는 턴(d)은 그대로 뒀다. 그래서
고속이동(스피드만)·철벽/코스믹파워(방어만)는 이득이 0으로 계산됐고, 용의춤·나비춤도 공격 쪽 이득만 셌다.
또 랭크업 점수는 "올린 뒤 **내가 직접** 싸운다"만 봐서, 번치코처럼 올린 랭크를 배턴터치로 후발 스위퍼에게
넘기는 운용은 판단 기준에 없었다(이미 쌓인 랭크를 넘기는 배턴터치 자체는 §4에서 평가됐음).

**1) 적용 후 재평가로 통일** — §4-1과 같은 구조. 복제한 state에 자기 랭크 변화(심술꾸러기 반영, 명중/회피 랭크
포함)와 HP 비용(소울비트류 `costsHpFraction`, HP가 모자라면 실패)을 적용하고 c′·d′·p′를 모두 다시 계산한다.

```
setup_self = race_value(c′, d′, p′, my − 비용, opp, 1) − 비용
```

**2) 올린 뒤 배턴터치(한 수 더 내다보기)** — 배턴터치를 고를 수 있고 교대 후보가 있을 때만.

```
hit      = 랭크업 후 상대 공격 한 번에 잃는 HP 비율 (my′ / d′)
hp_pass  = my − 비용 − hit                          # 이번 턴(랭크업 턴)에 한 대 맞은 뒤
후보     = 올린 랭크(랭크·명중/회피·급소 — 엔진 baton 인계와 동일)를 이어받은 교대 후보 평가
setup_pass = − 비용 − hit
           + max over 후보 [ p′ × switch_in(후보, 1) + (1 − p′) × (switch_in(후보, 0) − min(hp_pass, hit)) ]
           # 넘기는 턴은 유턴류·배턴터치 pivot_value와 같은 처리. hp_pass ≤ 0 이면 −∞(넘기기 전에 쓰러짐)

score = max(setup_self, setup_pass)
```

- 여러 번 쌓은 뒤 넘기는 계획을 한 번에 세우지는 않는다. 대신 매 턴 "한 번 더 올리기(랭크업 옵션) vs 지금
  넘기기(배턴터치 옵션)"를 다시 비교하므로 결과적으로 여러 번 쌓고 넘기는 흐름이 나올 수 있다.
- 가속(턴 종료 스피드 +1)처럼 **가만히 있어도 쌓이는 랭크**는 아직 셈하지 않는다(다음 턴부터의 이득).

## 4-3. 3단계 변화기 — 날씨·필드·트릭룸·도발·앙코르·사슬묶기 (2026-09-24 추가)

§4-1과 같은 "적용 후 재평가"다. 복제한 state에 효과를 적용하고 c′·d′·p′를 다시 계산한 뒤, **지속 턴으로 자른다**.
벽에만 쓰던 자르기를 c·d·p 전부로 일반화했다.

```
covered = 지속 턴 − 1 + 이 기술의 선공 확률        # 이번 턴(먼저 움직이면 이번 턴 상대 행동부터) + 남은 턴
c′ = blend(c_효과, c_원래, covered)                 # §4-1의 blend — covered 안에 끝나면 효과값 그대로
d′ = blend(d_효과, d_원래, covered)
p′ = share × p_효과 + (1 − share) × p_원래         # share = min(1, covered / 효과 적용 후 대면 길이)
```

| 효과 | 적용(복제 state) | 재평가에 반영되는 경로 | 지속 턴 | 실패 판정 |
|---|---|---|---|---|
| 날씨(비바라기·쾌청·모래바람·설경) | `weather` | 날씨 위력 보정·쓱쓱류 스피드 — 양쪽 모두 | 5(+바위) | 이미 같은 날씨 |
| 필드(4종) | `field` | 필드 위력 보정·사이코필드 우선도 차단 — 양쪽 모두 | 5(+그라운드코트) | 이미 같은 필드 |
| 트릭룸 | `trickRoomTurnsRemaining` | 턴 순서(`compareTurnOrder`) → p | 5 | 이미 트릭룸 |
| 도발 | 상대 volatile `taunt` | 상대 기술 모델이 변화기를 뺌 → 랭크업 경계(risk_flag)·회복 가중치 사라짐 | 3 | 이미 도발·아로마베일 |
| 앙코르 | 상대 volatile `encore`(직전 기술) | 상대 기술 모델이 그 기술만 봄 — 직전이 변화기면 상대 공격 없음(d ↑) | 3 | 상대가 아직 기술 안 씀·이미 앙코르·아로마베일 |
| 사슬묶기 | 상대 volatile `disable`(직전 기술) | 상대 기술 모델이 그 기술을 뺌 | 4 | 위와 같음 |

- 전제 작업: **상대 기술 사용 확률 모델이 도발·앙코르·사슬묶기 상태를 반영**하도록 고쳤다(`allowedByVolatiles` —
  AI 자신의 선택지와 같은 규칙). 이전에는 PP만 봐서, 도발당한 상대도 변화기를 쓸 거라고 계산했다.
- 날씨·필드·트릭룸은 대면이 끝난 뒤에도 남지만 **이월 항은 0**(다음 대면의 유불리를 모름). 날씨 턴 종료 데미지
  (모래바람)·그래스필드 회복도 아직 `turnsToKo`에 없다.
- 도발의 이득은 이 틀에서 작게 나온다: 상대 모델에서 변화기 확률(0.08)이 공격기로 옮겨가 d는 오히려 약간 줄고,
  남는 건 risk_flag 페널티 제거뿐이다. "랭크업·회복을 막는다"는 진짜 가치는 상대의 **미래** 랭크업을 모델링해야
  셀 수 있다(범위 외).
- 썰렁개그(날씨 + 사용 후 교체)는 교체 평가가 따로 필요해 아직 고르지 않는다.
- `phase3Aware: false`면 이 표의 효과를 고르지 않는다(비교용).

## 4-4. 방어류 — 엔진 한 턴 시뮬레이션 + 재평가 (2026-09-24 추가)

방어류의 이득은 대부분 **그 한 턴의 턴 종료 효과**(상대의 독·화상·씨뿌리기 데미지, 내 먹다남은음식, 가속, 날씨·
트릭룸·도발 남은 턴 소모)와 **방어 성공 부가효과**(킹실드·니들가드·토치카)에서 나온다. AI의 c·d 계산은 상태이상
지속 데미지만 알아서, 이걸 AI 쪽에 다시 구현하는 대신(직접 적용 방식) **실제 엔진 `runTurn`으로 그 한 턴을
돌려 보고** 결과 state로 재평가한다(사용자 결정). 엔진이 바뀌면 자동으로 따라가고, 특성·도구 상호작용이 전부 들어간다.

```
mix = 상대 기술 사용 확률 모델(§2)의 후보 — 확률 5% 미만 제외, 큰 순 최대 4개, 합 1로 재정규화
      (상대가 방어를 예상하고 랭크업하는 경우도 모델 확률대로 섞인다 — 사용자 결정)
for (상대 기술 m, 확률 w) in mix:
    S1 = runTurn(복제 state, 나 = 방어류(연속 횟수 0으로 강제 성공), 상대 = m, 난수 0.5 고정)
    값_m = (opp − opp₁) − (my − my₁) + [둘 다 살아 있으면] race(c₁, d₁, p₁, my₁, opp₁, lost=0)
성공 = Σ w × 값_m                       # 이번 턴은 양쪽 다 행동을 쓴 셈이라 lost = 0
실패 = race(c, d, p, my, opp, lost=1)   # 연속 사용 실패 = 아무것도 안 하고 맞음
score = q × 성공 + (1 − q) × 실패,   q = (1/3)^연속 횟수   (엔진 mirroredEffects와 같은 확률)
```

**묶음별 판단(사용자 요청 — `protectGroups`로 묶음별 켜고 끄기)**

| 묶음 | 기술 | 따로 판단하는 것 |
|---|---|---|
| block(순수 방어) | 방어·판별 | 기본형 — 상대 행동 무효 + 턴 종료 효과 1회. 상대가 변화기를 쓰면 헛수고(모델 확률대로) |
| punish(성공 시 이득) | 킹실드·니들가드·토치카 | 기본형 + 접촉 페널티(엔진이 처리 — 상대 행동이 접촉기인 확률만큼만 이득) |
| priorityGuard | 패스트가드 | 상대 행동 후보에 선공 공격기가 없으면 무의미(−∞). 있으면 그 확률만큼만 막음 |
| endure | 버티기 | 어느 상대 행동에서도 "HP 1로 버팀"이 안 일어나면(이번 턴 안 쓰러짐) 무의미(−∞). 버티면 HP 1 이후의 대면(기사회생류 위력·가속 누적·남은 턴 소모)을 재평가 |
| destinyBond | 길동무 | 내가 먼저 움직이고 이번 턴 쓰러지면 동반 기절 — 교환 가치 = 상대 남은 HP 비율 − 내 남은 HP 비율((a)안). 교환 **후** 대기 포켓몬끼리의 유불리((b)안)는 모든 옵션을 파티 단위로 평가해야 공정해서 "파티 단위 평가" 주제로 넘김 |

- **동률 처리**: 방어류는 동률(±0.1)이면 다른 기술보다 뒤(§7 4순위에 1.5). 턴 종료 효과 같은 뚜렷한 이득이
  없으면 "둘 다 한 턴 쉼"이라 공격과 점수가 같아지는데, 그때 방어를 고르면 의미 없는 방어가 반복된다.
- **한계**: 난수 고정이라 "전형적인 한 결과"만 본다(급소·확률 추가효과 분포 없음). 다음 턴부터의 c₁·d₁은 여전히
  턴 종료 효과를 모른다(먹다남은음식은 방어한 그 한 턴만 정확). 길동무가 다음 턴까지 유지돼 발동하는 경우는
  한 턴 시뮬레이션에 안 잡힌다.
- **검증 중 발견한 엔진 버그(수정, 사용자 확인)**: 공격기의 랭크 변화(오버히트 특공 −2, 인파이트, 니트로차지,
  브레이크클로의 상대 방어 하락)가 **빗나가거나 방어로 막혀도 적용**되고 있었다. 방어 시뮬레이션에서 "막힌 오버히트로
  상대 특공이 −2"가 돼 방어 가치가 부풀려진 게 계기. 본가대로 명중·방어 안 막힘·데미지 > 0(또는 대타 명중)일 때만
  적용하도록 고쳤다(`mirroredEffects.ts`). 변화기의 랭크 변화는 무관.

## 4-5. 파티 단위 평가 — 대면표 + 이어지는 대면(미니맥스) (ver.1.8 추가)

**문제**: §4의 `race_value`는 지금 1:1 대면이 끝나는 순간까지만 본다. 그래서 (1) 교체로 살려 둔 포켓몬의 HP가 나중에
쓰인다는 것, (2) 교환 뒤의 수 싸움("3:2에서 교환하면 2:1"), (3) 교착 대면에서 빠져나올 이유, (4) 길동무 교환 뒤의
판세를 모른다.

**합의(사용자, 2026-09-24)**: 판세 값 = HP 합 차이 + λ × 마릿수 차이((b)안), 상대의 다음 포켓몬 선택은 미니맥스,
PR 2개(①: 대면표·이어지는 대면 + 공격·교체·유턴류·강제 교체 연결, ②: 변화기·랭크업·회복·방어류·길동무 (b)안 세부 +
설치기 이월 항 정밀화).

```
대면표  pair(i, j) = { 내 턴당 피해율(상대 최대 HP 대비), 상대 턴당 피해율(내 최대 HP 대비, §2 사용 확률 모델), 선공 확률 }
        # 살아 있는 내 i × 상대 j, 쓸 때만 계산·결정 1회 캐시. 지금 나와 있는 두 마리는 물러나지 않는 한 현재 랭크,
        # 그 외(대기·한 번 물러난 포켓몬)는 랭크 0. HP가 깎인 상태의 처치 턴 = 남은 HP ÷ 턴당 피해율(turnsToKo 규칙)
판세    F = Σ 내 남은 HP 비율 − Σ 상대 남은 HP 비율 + λ × (내 남은 마릿수 − 상대 남은 마릿수)
대면    c, d, p → 두 갈래: 이김(확률 q, 내 HP = race_value와 같은 식으로 남은 만큼) / 짐(1 − q, 상대 HP 남은 만큼)
        q = sigmoid((d − 상대가 때리는 횟수) / σ),  σ = noise × max(1, 평균 턴 수)
이어짐  쓰러진 쪽이 다음 포켓몬을 고른다(나: 최대, 상대: 최소 — 미니맥스). 새로 나오는 쪽은 설치물 등장 비용을 치르고,
        이긴 쪽은 남은 HP로 계속 싸운다. 한 편이 전멸하거나 교착(c = d = ∞)이면 끝. 자발적 교체는 없다.

party_race(첫 대면 c, d, p, my, opp, lost) = Σ_갈래 q × [ HP 교환 + λ × 첫 대면에서 쓰러진 마릿수 차 + (F_끝 − F_첫 대면 직후) ]
```

- **모든 옵션에 적용**: 옵션 점수식(§4·§4-1~§4-4)이 부르는 `race_value`를 전부 `party_race`로 바꾼다 — 옵션마다 첫 대면
  (누가 누구와, 옵션 자체의 c·d·p)만 알면 되므로 점수식 구조는 그대로다. 교체·유턴류·배턴터치 후보는 들어오는 포켓몬이
  첫 대면에 서고, 물러난 포켓몬은 그때 HP로 대기에 남는다(유턴류 후공 갈래는 한 대 맞은 HP로). 유턴류가 빗나간 갈래는
  파티 모드에서 "이번 턴을 날린 채 대면을 이어감"(lost = 1)으로 본다(다른 갈래와 같은 기준).
- **왜 확률 갈래인가(구현 중 발견)**: 처음엔 대면 승패를 결정적으로 나눴는데(`race_value`와 같은 `>` 비교), 그리디 봇
  상대 800판에서 **435승(끔 458승)**, 교체 1,092 → 1,675회로 오히려 나빠졌다. 원인: 여유 0.02턴 차이로 이기고 지는 뒤쪽
  대면 하나가 파티 전체의 판세(HP + 마릿수)를 통째로 뒤집어, 난수·급소·모델 오차(첫 대면은 이산 난수 분포, 대면표는 HP
  선형 비례) 수준의 차이가 점수를 2~3점씩 흔들었다 → 교체 왕복(아보크→윈디→아보크 등). 승패를 여유 턴의 시그모이드로
  섞자 해소됐다(§11 표). 근소하게 "뒤집혀 이긴" 갈래는 이긴 쪽에 원래 HP의 5%를 남긴다.
- **교착**: 첫 대면이 서로 피해 0이면 이어지는 계산도 0이라, 칠 수 있는 포켓몬으로 교체하는 쪽이 자연히 높다.
- **총대장(AI 보정)**: 엔진은 교체로 나온 뒤에야 쓰러진 동료 수를 센다. AI가 대기 포켓몬(교체 후보·대면표)을 평가할 때는
  "지금 나온다면" 셀 같은 편 기절 수로 위력 배율을 계산한다(`moveDamage.ts`). 나와 있는 포켓몬은 엔진이 센 값.
- **한계**: 자발적 교체를 모델링하지 않으므로 "들어갔다 다시 나오는" 계획은 세우지 않는다(매 턴 다시 판단). 상대도
  교체하지 않는다고 본다 — 아래 ②의 결과를 가른 가정. 비용: 3선출 기준 대면표 최대 9칸.
- **독압정(항상 적용)**: 이미 깔린 독압정 위로 대기 포켓몬이 나오면 대면표에서 독(2층 맹독, 카운터 2 근사) 상태로 계산한다
  (접지·타입/특성 면역·필드 차단 제외). ②와 별개로 대면표 자체의 규칙이라 `partyEffects`와 무관.

`attachParty`, 채점은 `decision.ts` `race()`. `partyAware: false`면 이전 동작.

### §4-5 ② 효과를 이어지는 대면에 남기기 (ver.1.8, 구현 완료 · **기본값 끔**)

①은 변화기 효과(상대 상태이상·랭크다운·벽 등)와 랭크업이 **첫 대면에만** 반영되고, 이어지는 대면(대면표)은 원래 state
기준이었다 — 예: 칼춤으로 올린 랭크가 다음 상대와의 대면에서는 사라진다. ②는 이걸 옵션별 대면표로 이어 준다.

| 잠꼬대 | 공격기처럼 — 잠든 턴 b 동안은 나갈 수 있는 기술(엔진과 같은 후보)의 평균 피해율, 깬 뒤는 최선 공격기. 상대가 잠든 채 잠꼬대를 가졌으면 상대 위협에도 같은 식 | 깨어 있음(사용 조건)·나갈 기술 없음 |
| 울부짖기·날려버리기 | 상대 예비마다(균등 무작위): 상대가 먼저 한 대(우선도 −6) → 예비가 설치물을 밟고 등장, 원래 상대는 랭크 초기화 → 그 대면을 평균. 등장 비용으로 쓰러지면 파티 모드에서 그 state에서 이어짐 | 예비 없음·흡반/뿌리박기·이번 턴 안에 내가 쓰러짐·방음(울부짖기)·대타(날려버리기) |
| 추억의선물 | 파티 모드 전용 — 내 HP 전부 손실 + (자신 기절·상대 −2/−2 state에서 이어지는 판세). 후공인데 이번 턴에 쓰러지면 랭크다운 없이 기절만 | 파티 단위 평가 꺼짐·내릴 스탯 없음 |

- **대타의 "절대 데미지"**: 처치 턴 계산의 피해율은 "현재 HP 대비"라, HP가 낮으면 한 방 데미지가 현재 HP로 잘려
  대타를 깨는 턴이 수십 턴으로 부풀었다(구현 중 diag로 발견: HP 47/182에서 d 1.1 → 23.5). 기술 추정에 한 번 맞힐 때의
  평균 데미지(최대 HP 대비, `MoveHitEstimate.damageFraction`)를 추가해 대타 계산에만 쓴다.
- **엔진 버그 수정**: 추억의선물·미스트버스트에 `selfFaints`가 없어 사용자가 기절하지 않았다(추억의선물은 −2/−2를 공짜로).
  데이터에 추가 → regress 해시 변경(§12). 목숨걸기(자기 HP만큼 고정 데미지 + 기절)는 데미지 로직 자체가 없어 트랙 M.
- **결과**(`a2Aware` 켬/끔): 그리디 일반 800판 490 / 491, STATUS=1 400판 255 / 258, h2h 일반 199:199 · STATUS=1 196:199 — 전부 오차 안. STATUS=1 선택 횟수: 대타출동 48 ·
  울부짖기류 18 · 추억의선물 2. 그리디 봇은 잠들지 않고(잠꼬대 무관) 교체하지 않아(울부짖기의 "교체 강요" 이득 없음) 이 기술들의
  가치가 드러나기 어려운 상대다. 턴당 판단 평균 44ms·최대 320ms, NaN 0.

## 5. 위험 회피 성향 (`risk_aversion`)

전자(타이브레이커에서만 고려)와 후자(항상 페널티 반영)를 이진 선택하지 않고, 하나의 연속값 파라미터로 통합한다.

```
risk_aversion ∈ [0.0, 1.0]
결정 시점: 배틀 시작 시 1회, 균등분포 U(0,1)에서 샘플링 (배틀마다 재추첨)
```

| risk_aversion | 실질 동작 |
|---|---|
| 0에 가까움 | 페널티 거의 0 → 근소한 차이일 때만 영향 |
| 1에 가까움 | 항상 뚜렷한 페널티 |
| 0.3~0.7 | 그 사이 — "적당히 신중한" 성향 |

이 파라미터는 향후 다른 "성향에 따라 흔들려야 하는" 지점에도 재사용 가능하도록 범용으로 설계한다.

## 6. 하드 오버라이드 규칙 (점수 계산 전 선(先)체크)

점수식만으로는 상대에게 반격 기회 자체가 없는 상황(내가 선공으로 확실히 처치)이 다른 옵션에 밀려 역전될 수 있음이 검증 과정에서 발견되었다. 이는 튜닝으로 해결 불가한 논리 구조상의 예외이므로, 점수 비교보다 우선 체크한다.

```
if 선공 확률 == 1 AND worst_case.count == 1 AND worst_case.certainty == "guaranteed" AND accuracy == 1.0:
    해당 옵션 즉시 채택, 점수 계산 생략
```

- `accuracy == 1.0`(필중)은 engine-extension §7-3에서 추가 — 명중률 100% 미만 원턴킬 기술이 "확정 처치"로 오인되는 걸 막는다.
- 기합의띠·옹골참·탈은 생존 보장 후처리(engine-extension §3-0)가 worst_case를 먼저 2타로 바꾸므로 여기 걸리지 않는다.
- 선공 판정에는 여왕의위엄·테일아머·사이코필드의 우선도 차단이 이미 반영돼 있다(차단되면 c = ∞).

이 조건 외의 모든 경우는 옵션 전부 동일한 점수식으로 비교한다 (예외 규칙 추가 금지 — 필요성이 생기면 이 문서를 개정하여 검토).

## 7. 동률 처리 (타이브레이커)

`score` 차이가 임계값(±0.1, HP 비율 단위) 이내일 때 적용.

1. `worst_case.count == 1`인 옵션을 우선 배제 (근소한 우위보다 즉사 리스크 회피 우선)
2. `entry_cost`가 더 낮은 쪽
3. 방어 상성 배율이 더 낮은(안 맞는) 쪽
4. 그래도 같으면 **이번 턴 처치 가능한 공격기(c ≤ 1) > 그 외 기술 > 교체** (2026-09-24 보강 — 이전: 기술 > 교체,
   `tieAttackFirst`). HP 교환식은 "결국 이기는 대면이면 몇 턴 걸리든" 같은 점수를 줘서, 지금 잡을 수 있는데
   철벽을 쓰는 선택(점수 차 0.001)이 동률에서 뽑혔다(§4-2 검증 중 발견). 처음엔 "공격기 전체 > 변화기"로 넣었으나
   STATUS=1 파티 800판에서 471 vs 492승으로 오히려 손해였다 — 동률 구간의 변화기는 대부분 실제로 이득이라, 처치
   가능한 공격기로만 좁혔다. 상대가 못 때리는데(d = ∞) 랭크업을 +6까지 쌓는 건 시간만 쓸 뿐 손해가 없어 그대로 둔다.

## 8. 최종 의사코드

```
options = common_engine.evaluate()   # 6개 옵션, battle-ai-common-engine.md v1.1 출력

# 0단계 — 하드 오버라이드 (§6)
for option in options:
    if option.option_type == "move"
       and option.first_probability == 1
       and option.hits_to_kill.worst_case.count == 1
       and option.hits_to_kill.worst_case.certainty == "guaranteed"
       and option.accuracy == 1.0:
        return option

# risk_aversion: 배틀 시작 시 1회만 샘플링해 재사용 (매 턴 재추첨 금지)
risk_aversion = battle_state.risk_aversion

# 1단계 — 점수 계산 (§4 HP 교환식)
for option in options:
    c, d, p = option.hits_to_kill.expected, option.hits_to_be_killed.expected, option.first_probability
    my, opp = option.hp_fraction, option.opponent_hp_fraction
    if option.is_pivot:                                   # 유턴류·배턴터치
        score = pivot_value(option)
    elif option.support == "other":
        score = -inf
    elif option.support == "effect":                      # §4-1
        score = hit_chance * race_value(c′, d′, p′, my, opp, 1) \
                + (1 - hit_chance) * race_value(c, d, p, my, opp, 1) \
                + w_carry * option.carry
    elif option.support == "heal":
        if option.heal_net_gain <= 0: score = -inf        # 회복 루프 방지 (§4-1)
        else:
            score = race_value(option.best_kill_turns, option.d_after_heal, p, option.healed_fraction, opp, 1) \
                    + (option.healed_fraction - my)
    elif option.support == "setup":
        score = race_value(option.c_after_setup, d, p, my, opp, 1)
    elif option.option_type == "switch":
        score = race_value(c, d, p, my, opp, 1) - option.entry_cost / option.max_hp
    else:
        score = race_value(c, d, p, my, opp, 0)
    if option.risk_flag:
        score -= 0.1 * risk_aversion
    option.score = score

# 2단계 — 최고점 선택 + 동률 처리
best = max(options, key=score)
if best.score == -inf: return options[0]                 # 전부 선택 불가면 첫 옵션
candidates = [o for o in options if o.score == best.score or best.score - o.score < 0.1]

if len(candidates) > 1:
    candidates = [o for o in candidates if o.hits_to_be_killed.worst_case.count != 1] or candidates
    candidates.sort(key=lambda o: o.entry_cost)
    candidates.sort(key=lambda o: o.type_matchup.defensive)
    candidates.sort(key=lambda o: 0 if o.is_attack and o.hits_to_kill.expected <= 1
                                  else 1 if o.option_type == "move" else 2)  # 처치 가능 공격기 > 기술 > 교체
    return candidates[0]

return best
```
