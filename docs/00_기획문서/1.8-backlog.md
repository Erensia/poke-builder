# ver.1.8 백로그

## 0. 이 문서의 성격

ver.1.7(`1.7-backlog.md`, 착수 전 계획 문서)와 별개로, 사용자가 전달한
`백로그 1.8 수정 내용.txt`(다운로드 파일, 2026-09-18)를 이 프로젝트의 백로그 문서 형식으로
옮겨 적은 것이다. **아직 착수 전** — 다만 원본 텍스트를 그대로 옮기지 않고, 각 항목을
실제 코드·데이터와 대조하는 착수 전 조사를 먼저 진행했다(계획 문서보다 실제 코드가
우선이라는 이 프로젝트의 기존 원칙 — ver.1.5 §7, ver.1.6 §3-1/§3-4, ver.1.7 §0 등에서
반복 확인된 패턴). 그 결과 원본 요청 중 일부는 "문구만 바꾸면 되는 것"과 "실제로는 로직이
아예 없거나 이미 다른 형태로 구현돼 있는 것"이 섞여 있음이 드러났다 — 항목별로 구분해
기록했다.

원본 텍스트의 UI 문구(특성 설명문 등)는 사용자가 준 문구를 한 글자도 안 바꾸고 그대로
옮겼다 — 구현 시에도 그 문구를 정확히 반영할 것(조사 표기 자동 매칭 등 부가 지시사항 포함).

구성:
- **트랙 J — 포켓몬 도감 설명문(특성) 수정** (§1): 특성 문구 8건. 이 중 §1-1(갈지자걸음)·
  §1-9(총대장)는 착수 전 조사 결과 **엔진 로직이 아예 없는** 것으로 확정돼 단순 문구

  63싱글배틀 전용이라 새 문구가 요구하는 "아군(동료)" 조건이 애초에 성립하지 않는 문제가
  있어 사용자 확인이 필요하다. 나머지(§1-2·§1-3·§1-4·§1-7·§1-8)는 이미 구현된 로직과
  대조해 문구만 바꾸면 되는 것으로 확인됐다.
- **트랙 K — 포켓몬 도감 페이지 폼별 종족값·특성 표기 정비** (§2): 대상 5종 전부 이미

**상태**: 트랙 J(PR #132)·트랙 K 완료. AI 후속 과제(아래 이관 절)는 파티 단위 평가부터 설계 합의 후 착수.

### ver.1.7에서 이관(2026-09-24)

ver.1.7(배틀타워 AI 어려움 난이도)을 마무리하며 넘긴 AI 후속 과제. 착수 순서·버전 배정은 착수 시 사용자와
다시 정한다(규모가 커서 별도 버전으로 뗄 수도 있음). 상세 근거는 `배틀AI 기획/battle-ai-decision-layer.md` §11-1.

- **파티 단위 평가**(가장 큰 구조적 한계): 지금 점수식은 현재 1:1 대면만 본다. 내 대기 포켓몬 × 상대 대기
  포켓몬 대면표로 모든 옵션을 평가해 "3:2에서 교환하면 2:1" 같은 수 싸움을 반영. 길동무 교환 후 판단((b)안),
  교체 후보 선택, 서로 피해를 못 주는 교착 대면(방어 연타·첫 선택지 반복) 처리가 여기에 걸려 있다.
- **쉬움 난이도(불완전 정보)** — 1.7 §3-4: 관측한 정보만 쓰는 상태 추적 + 안 드러난 기술 추정.
- **3선출 AI** — 1.7 §3-4: 6빌드 중 3마리 선출 규칙.

- **도발 가치 보정**: 상대의 미래 랭크업·회복을 모델링해야 도발의 진짜 가치를 셀 수 있음.
- **파티 단위 평가 합의 사항(2026-09-24)**: 설계안(대면표 + 이어지는 대면 계산)으로 진행.
  ① 최종 점수 = 남은 HP 비율 합 차이 + λ × 남은 마릿수 차이(λ 시작값 0.5, 튜닝 대상) — (b)안.
  ② 상대의 다음 포켓몬 선택은 미니맥스(양쪽 다 최선). ③ PR 2개: (1) 대면표·이어지는 대면 계산 + 공격·교체·유턴류·
  강제 교체 연결, (2) 변화기·랭크업·회복·방어류·길동무 (b)안 + 설치기 이월 항 정밀화. 상세는 착수 시
  `배틀AI 기획/battle-ai-decision-layer.md` §4-5에 기록.
  **① 완료**: 대면 승패를 확률 갈래(σ 0.5)로 나누는 보정 포함 — 결정적으로 나누면 오히려 나빠졌다(435 vs 458승).
  채택안 그리디 상대 485승(끔 458), AI끼리 443:355. 총대장 AI 보정(대기 포켓몬 기절 수 반영) 포함. 상세는 §4-5·§11.
  **② 완료(기본값 끔)**: 변화기·랭크업(계속 남는 효과), 벽·날씨·필드·트릭룸·도발류(지속 턴 — 사용자 요청으로 포함),

  나빠(상대가 교체하지 않는다는 가정 탓으로 추정) `partyEffects: false`로 머지(사용자 결정, 2026-09-25). 상세는 §4-5 ②.
- **상대의 자발적 교체 모델링**(② 재활성화의 전제, 신규): 이어지는 대면이 "상대는 쓰러질 때만 교체"라고 가정해, 교체하는

## 1. 트랙 J — 포켓몬 도감 설명문(특성) 수정

### §1-1. 갈지자걸음 — 문구 변경 + 신규 로직 필요

현재문구(확인됨, `abilities.json:785`): `혼란 상태일 때 회피율이 올라간다.`
수정문구: `혼란 상태일 때 회피율이 50% 상승한다(랭크업과 중첩 가능).`

**착수 전 코드 확인**: `abilities.json`에 이 특성 전용 필드가 전혀 없다 — 순수 플레이버
텍스트일 뿐, 실제로 회피율에 영향을 주는 엔진 로직이 없다(랭크 기반 회피율
`accuracyStages.evasion`과는 별개 축으로 추가 배율을 곱하는 처리 자체가 없음). 참고할 기존
패턴: 모래숨기(`weatherOpponentAccuracyMultiplier`, 날씨 조건부 상대 명중률 배율,
`types/ability.ts:219`)가 정확히 같은 구조("랭크 기반 회피율과는 별개 축이라 중첩 가능")를
쓰고 있음 — 이를 본떠 "혼란 상태 조건부" 버전(가칭 `confusedOpponentAccuracyMultiplier`)을
신설해 상대 명중률에 곱하도록 배선하면 됨(회피율 50% 상승 = 명중률 1/1.5배 환산, 정확한
공식은 착수 시 본가 자료 대조). **단순 문구 수정이 아니라 신규 엔진 로직 추가 작업.**

**대상**: `src/data/abilities.json`(문구), `src/types/ability.ts`(필드 신설), 명중률 계산부
(모래숨기 적용 지점과 동일한 곳 — 착수 시 위치 확인).

**상태**: 완료 — 본가 규칙(상대 명중률 ×0.5, 사용자 확정)으로 `Ability.confusedOpponentAccuracyMultiplier` 신설, `battle/hitChance.ts`(엔진·AI 공용 명중 계산)에서 방어측이 혼란일 때 모래숨기와 같은 축으로 곱한다(랭크 회피율과 중첩, 틀깨기류에 무시). 문구는 원문 그대로.

- **특성 쪽 추가 발견(AI-A1 중)**: 마이페이스 — 설명은 "혼란 상태가 되지 않는다"인데 엔진에 혼란 면역 처리가 없다(데이터 필드 없음).
- **스텁·필드 없음 3**: 생명의물방울(1v1에서도 자기 회복 유효), 페어리록·자기장조작(1v1에서도 제한적으로 의미 있음 — 재검토).

**1.3 전수 감사에서 빠진 이유**: 1.3 §1은 "effect 텍스트에 키워드가 있는데 대응 스키마 필드가 비어 있는" 엔트리를
찾았다 — 필드가 아예 없는 기술은 비교 대상 자체가 아니어서 걸리지 않았다.
**재발 방지(제안)**: 시나리오 테스트에 "모든 변화기는 한 턴 실행 시 state를 실제로 바꾸거나, 의도적 제외 목록(더블 전용 등)에
있어야 한다"는 자동 검사를 추가.

**진행 순서**: AI-A1·A2 다음, 교체 모델링 전(§4). 배우는 포켓몬 수·실전 빈도 순으로 묶어 PR을 나눈다. 엔진 수정이라
regress 해시가 바뀔 수 있음 → 기술별로 수정 전후 비교 후 §12 기록. 각 기술의 AI 평가도 같은 PR에서 붙인다.
