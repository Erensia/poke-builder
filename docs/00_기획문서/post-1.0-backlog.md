# Post-1.0 백로그 — 서비스 개발 완료 이후 업데이트 후보

## 0. 이 문서의 성격

Phase 8(배틀타워 리뉴얼)은 **파티 선출·교체 인프라**만 담당한다. 그 위에 얹히는 선택적 UI 개선·QoL은
인프라 의존성이 없으므로 여기 모아두고, **서비스 개발 완료(ver.1.0) 이후 ver.1.0.x 업데이트**로 처리한다.

- 여기 항목은 "6슬롯 빌더 + 3선출 화면이 실제로 도는 걸 본 뒤에" 확정하는 게 정확하다 — 지금 상세 설계하면
  리뉴얼 후 재작성될 가능성이 높다.
- Phase 8 착수 결재 때 스코프 경계로 쓴다: **Phase 8 = 인프라, 이 문서 = 1.0.x 개선**.

## 1. 파티 빌더 — 타입 상성 요약 컴포넌트 개편안

### 1-1. 대상

- 컴포넌트: `src/components/TypeCoverageSummary.tsx` (+ `TypeCoverageSummary.css`)
- 집계 로직: `src/lib/partyAnalysis.ts`의 `computeTypeCoverage` / `getPartyMembers`
- 렌더 위치: `src/components/PartyBoard.tsx:117` (`<TypeCoverageSummary slots={slots} />`)

### 1-2. 현재 방식

- 공격 타입 18종을 나열하고, 각 타입 칸에 "이 타입 기술에 약한/견디는 파티원 **수**"를 뱃지로 표기
  (`×4 n` / `×2 n` / `½ n` / `¼ n` / `면역 n`).
- 타입 칸을 누르면 하단에 "그 타입에 대해 등배가 아닌 파티원 목록 + 각자 배율"이 펼쳐진다.
- 즉 **타입 축은 있지만 포켓몬별 표는 없다** — 개별 포켓몬의 방어 상성은 클릭해야 보인다.

### 1-3. 개편안 — 포켓몬 × 타입 매트릭스

선택한 6마리를 항상 표로 펼쳐, 포켓몬별 방어 상성을 한눈에 본다.

**레이아웃**

| | 몬1 | 몬2 | 몬3 | 몬4 | 몬5 | 몬6 | **종합** |
|---|---|---|---|---|---|---|---|
| 노말 | ½ | | ×2 | | | 면역 | 취약 |
| 불꽃 | ×2 | ½ | | ×4 | | | 취약 |
| 물 | | | ½ | | ½ | | 강점 |
| … (18타입) | | | | | | | |

- **가로축(열)**: 빌드한 6마리 포켓몬 전부(선출 3마리로 좁히지 않음). 헤더에 포켓몬 아이콘/이름 + (메가 시 폼 태그).
- **세로축(행)**: 방어 상성 기준이 되는 **공격 타입 18종 전체 (18행 고정)**.
  - 사용자 표현의 "포켓몬의 총 타입"은 이 18종 축을 의미. 파티에 등장하는 타입만 추리지 말고 전부 표기
    (빈 행이 정보 — "아무도 안 걸리는 타입"도 보임). 필터 토글 없음 (1-5 확정).
- **셀(포켓몬 × 타입)**: 그 포켓몬이 해당 타입 기술을 받을 때의 방어 배율.
  - 표기는 **현재 방식 그대로**: `½` / `¼` / `×2` / `×4` / `면역`. 등배(×1)는 공란.
  - 색상도 현재 `cnt cnt-weak / cnt-quad / cnt-resist / cnt-quadresist / cnt-immune` 클래스 재사용.
  - 메가스톤 장착 반영은 `getPartyMembers`가 이미 `getEffectiveForm`으로 처리 중 — 그대로 사용.
- **종합 열 (6마리 열 다음, 7번째 열)**: 그 타입 행에 대해 파티 전체가 **취약 / 보통 / 강점** 중 무엇인지.
  - **판정 규칙 (확정, 2026-09-02)**. 그 타입 행에서
    `w` = 약점 인원 수(배율 > 1: `×2`·`×4`), `r` = 저항 인원 수(배율 < 1: `½`·`¼`·면역)일 때:

    | 결과 | 조건 |
    |---|---|
    | **강점** | `r ≥ w` **그리고** `r ≥ 2` |
    | **취약** | `w − r ≥ 2` |
    | **보통** | 그 외 |

    - 두 조건은 상호배타적(강점은 `r ≥ w`, 취약은 `w ≥ r + 2`). 겹치지 않는다.
    - `면역`은 저항(`r`)에 포함 — 사용자 예시에서 "무효 2마리"를 "저항 2마리"와 동일 처리.
    - `×4`·`¼`도 현재는 **인원 1로만** 집계(가중치 없음). 필요 시 1.0.x에서 재검토.
    - 검증한 예시 (w, r → 결과): (1,1)→보통 · (1,2)→강점 · (2,2)→강점 · (2,3)→강점 ·
      (3,1)→취약 · (3,2)→보통. 전부 일치.

### 1-4. 상호작용

- 현재의 "타입 클릭 → 하단 상세 패널" 동작은 표 자체가 상세를 대체하므로 **제거.**
  대신 행(타입) 헤더 hover 시 그 타입 설명, 셀 hover 시 배율 툴팁 정도.
- 파티가 비었을 때 문구(`포켓몬을 배치하면 상성 요약이 표시됩니다.`)는 유지.

### 1-5. 확정 사항 (2026-09-02)

- **행 개수**: **18행 고정.** 필터 토글 없음. 빈 행(아무도 안 걸리는 타입)도 그대로 표기 — 그 자체가 정보.
  좁은 폭에서 18×7 표는 가로 스크롤 처리.
- **기준 인원**: **빌드한 6마리 전부.** 선출 3마리로 좁히지 않는다(선출 방식과 무관하게 6마리 매트릭스 유지).
- **행 정렬**: **타입 고정 순서.** "취약 행 위로" 같은 동적 정렬 없음 — 매번 같은 위치에서 찾도록.
  순서는 `POKEMON_TYPES`(`src/types/pokemon-type.ts`) 배열 순서를 따른다.
- **기존 컴포넌트 처리**: `TypeCoverageSummary`(수량 집계형 `TypeCoverageCell` + 클릭 상세 패널)는
  **완전 폐기.** 매트릭스가 대체하며 병행 표시하지 않는다. `computeTypeCoverage`/`TypeCoverageCell`도
  다른 소비처가 없으면 함께 제거하고, 매트릭스용 집계 함수(`getPartyMembers` + 포켓몬×타입 배율 표)를
  `partyAnalysis.ts`에 새로 둔다.

## 2. 포켓몬 프로필 — 이니셜 뱃지 → 실제 포켓몬 이미지

### 2-1. 현재 방식

포켓몬 프로필(아바타)은 전부 **이름 첫 글자 + 타입 색 그라디언트**로 그려진다.

- 렌더 패턴: `pokemon.name.at(0)` + `linear-gradient(135deg, TYPE_COLORS[type0], TYPE_COLORS[type1 ?? type0])`
- 등장 위치 및 크기:

  | 위치 | 클래스 | 크기 | 모양 |
  |---|---|---|---|
  | 파티 빌더 슬롯 (`PartySlotCard.tsx:94`) | `.party-slot-avatar` | 36×36 | radius 10px |
  | 배틀 셋업 카드 (`BattleSetupCard.tsx:97`) | `.party-slot-avatar` 재사용 | 36×36 | radius 10px |
  | 매치업 슬롯 (`MatchupSlotCard.tsx:125`) | `.matchup-slot-avatar` | 42×42 | radius 11px |
  | 도감 리스트 (`PokedexPage.tsx:270`) | `.pokedex-list-avatar` | 28×28 | 원형 |
  | 도감 상세 (`PokedexPage.tsx:128`) | `.pokedex-detail-avatar` | 56×56 | 원형 |

  (`ItemDexPage`의 `.itemdex-detail-avatar`는 아이템용이라 대상 아님.)

### 2-2. 목표

각 위치 크기에 맞는 포켓몬 이미지를 구해 이니셜 뱃지를 대체한다. 이미지가 없거나 로드 실패 시
현재의 이니셜+그라디언트로 **폴백**.

### 2-3. 결정해야 할 것

- **이미지 소스 & 키잉**. 현재 `pokemon.json`은 한글 이름을 `id`로 쓰고 전국도감 번호·스프라이트 URL 필드가 없다. 후보:
  - (a) `pokemon.json`에 `dexNo`(전국도감 번호) 필드 추가 → 번호로 스프라이트 파일/CDN 참조.
    로스터를 세대별로 확장 중이므로 병합 스크립트에 `dexNo` 채우는 단계 추가 필요.
  - (b) 스프라이트를 레포에 번들(`public/sprites/`)하고 `dexNo`(또는 슬러그)로 파일명 매칭.
  - (c) 외부 CDN 직접 참조(PokéAPI 스프라이트 raw, Pokémon Showdown 스프라이트 등). 오프라인/속도/안정성 트레이드오프.
- **스프라이트 스타일**. 위치별로 다르게:
  - 28×28 도감 리스트 → 박스 아이콘(dex box icon)류 작은 픽셀 이미지.
  - 36~56px → gen5 도트 / Showdown 스프라이트, 또는 HOME 렌더(고해상도라 축소 시 선명).
  - 픽셀 아트면 작은 크기에서 `image-rendering: pixelated`, HOME 렌더면 일반 스케일.
- **메가 폼**. `megaEvolutions[].form`(예: `"리자몽-메가X"`)도 별도 이미지가 필요. 폼 키로 매칭.
  없으면 기본 폼 이미지로 폴백.
- **라이선스**. 포켓몬 스프라이트/아트워크는 저작권물. 개인·비영리 토이 프로젝트 범위에서만 사용한다는 전제 확인.

### 2-4. 구현 메모

- 5개 위치가 같은 로직(이미지 or 폴백)을 쓰므로 **공유 `<PokemonAvatar pokemonId size formLabel />` 컴포넌트로 통합**하면서 교체.
  현재는 컴포넌트마다 `avatarGradient` 계산이 중복돼 있다(`PartySlotCard`·`BattleSetupCard`·`MatchupSlotCard` 거의 동일, `PokedexPage`는 함수형).
- `<img>` `loading="lazy"` + `onError`로 폴백 스위치.
- `object-fit: contain`, 배경은 기존 그라디언트를 옅게 깔아도 됨(투명 스프라이트 뒤 배경).
