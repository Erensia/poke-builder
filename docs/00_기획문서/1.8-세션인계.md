## 작업 규칙 (사용자 확정)

- 기획 문서보다 **코드가 우선** — 코드를 먼저 확인한다. 설계가 필요한 건 설계안을 먼저 제안하고 합의 후 구현.
- 항목마다 dev에서 브랜치 → PR을 dev로 **squash 머지**(PR 1개 = 커밋 1개). 머지한 브랜치는 삭제(원격 자동 삭제 켜짐).
  dev → main은 **ver.1.8 끝에 merge commit**으로.
- 기획 문서만 바꾸는 변경은 dev에 직접 커밋. 기능 작업 중 발견한 버그는 그 기능 커밋에 포함.
- 머지 때 README 최신화. 커밋 메시지 끝에 Co-Authored-By / Claude-Session 줄.
- 커밋 전 `npm run lint` + tsc(`npx tsc -b`) + `npm run test:ai`.
- **엔진 변경**: `node scripts/battle-ai-sim.mjs regress 300` 해시를 전후 비교해 `battle-ai-decision-layer.md` §12에 기록.
  데이터·엔진 변경이 섞이면 "이전 데이터 + 새 코드" 해시를 따로.
- **AI 튜닝 판정**: 그리디 승률 + h2h. 벤치는 **5개 병렬**(줄이지 말 것 — 사용자 지시), 켬/끔 토글로 비교:
  `node scripts/battle-ai-sim.mjs greedy 800 [params]` ×2(켬/끔), `STATUS=1 … greedy 400` ×2, `STATUS=1 … h2h 200 '{켬}' '{끔}'`.
  벤치 도중 작업 트리를 바꿀 거면 `git worktree`로 벤치 전용 체크아웃을 만들어 돌린다(sim은 시작 시 코드를 한 번 읽음).
- 벤치가 도는 동안 다음 항목을 이전 브랜치 끝에서 따서 진행, 앞 PR이 squash 머지되면 `git rebase --onto origin/dev <이전 끝> <브랜치>`.
  다음 항목 사전 조사를 미리 해 두고, 결정할 점은 바로 보고.
- **브라우저 화면 검증은 사용자에게 맡긴다**(claude-in-chrome 직접 사용 금지). 부탁 전에 해당 작업 브랜치를 원격에 올려 두고
  사용자에게 PC에서 전환 방법을 안내. 테스트 중 localStorage `champions-party-sim.party.v1`(파티 자동저장)은 절대 지우지 말 것.
- 한국어로 답한다(사용자는 영어가 어렵다).
