# Phase 4 기획 — 후속 메커니즘 & 데이터 완성도

> 이어서 읽기: [Phase 3 기획](phase3-plan.md) · [Phase 3 작업 현황](phase3-status.md)
> Phase 3에서 신규 스키마가 필요한 핵심 메커니즘(반동·다단히트·2턴 차지기·날씨/필드·상태이상 6종 전수 재검증·도구 위력 보정률 41종·배짱 면역 무시)을 전부 마쳤다. 이 문서는 그 과정에서 "필요한 건 확인됐지만 이번 스코프엔 안 넣기로 한 것"을 한데 모은 백로그다 — 새로 발견한 문제가 아니라 전부 Phase 3 문서에 이미 흩어져 있던 항목을 정리·재우선순위한 것.

## 0. 이 문서의 성격

Phase 3 문서(§1~8)에 "스코프 밖", "후속 작업", "미구현" 등으로 표시된 항목을 전부 훑어서 여기로 옮겼다. 항목마다 원래 어디서 발견됐는지 링크해뒀으니, 배경이 더 필요하면 그쪽을 보면 된다. 우선순위는 "얼마나 많은 걸 새로 지어야 하는지"와 "지금 로스터(23마리)에서 실제로 체감되는 빈도"를 같이 봤다.

## 1. 회복(HP/PP) 엔진 — 가장 많은 후속 항목이 걸려있는 기반 작업

**지금 프로젝트엔 HP/PP를 회복시키는 기술·도구가 단 하나도 구현돼 있지 않다.** 데미지를 깎는 쪽만 있고 채우는 쪽이 없는 셈이라, 이 엔진 하나를 만들면 아래 항목들이 한꺼번에 풀린다.

- **잠자기(Rest)**: 체력+상태이상 모두 회복 + 2턴 강제 수면. [1-4](phase3-plan.md#1-4-상태이상-치료-효과--완료) 작업 때 발견 — `curesStatus`만으론 표현 안 됨
- **먹다남은음식**: 턴 종료 시 최대 HP 1/6 회복
- **큰뿌리**: 흡수 계열 기술(뿌리박기·힘흡수 등) 회복량 1.3배
- **조개껍질방울**: 데미지를 준 만큼의 1/8을 자신도 회복(드레인펀치 등 흡수기와는 별개 축)
- **자뭉열매·오랭열매**: HP 1/2 이하일 때 자동 소모돼 회복(비율/고정치)
- **과사열매**: PP 0인 기술의 PP 10 회복
- **상태이상 자동회복 나무열매 8종**(리샘열매·버치열매·유루열매·복슝열매·복분열매·배리열매·시몬열매): 상태이상에 걸리는 "그 순간" 자동 소모 — `curesStatus`(명중 시점에 치료)와 트리거 시점이 다름
- **광합성·뿌리박기** 등 회복형 변화기: [1-9](phase3-plan.md#1-9-위력-가변형-기술의-effect-텍스트-누락--완료)에서 확인된, `power: null` + `effect: ""`인 상태 변화 기술 다수(도발·최면술·중력·사슬묶기 등)도 회복류는 이 엔진이 선행돼야 함

(출처: [4-2-2](phase3-plan.md#4-2-2-도구표에서-이번에-스코프-밖으로-남긴-것-후속-작업), [phase3-status.md](phase3-status.md#잠자기rest-관련-후속-작업-1-4-작업-중-발견))

## 2. 명중률 전용 배율 배선 — 이미 있는 슬롯에 정확한 값만 꽂으면 됨

`resolveAction`의 `accuracyExtraMultiplier`가 여전히 1로 고정돼 있다. 도구표 작업으로 정확한 값이 이미 확보됐다:

- 반짝가루 0.9(상대가 나에게 쓰는 기술 명중률), 광각렌즈 1.1(내가 쓰는 기술), 포커스렌즈 1.2(상대보다 늦게 움직일 때만)
- `Item`에 `accuracyMultiplier` 계열 필드 추가 + `computeHitChance` 호출부에 배선

**우선순위 높음** — 4-1(날씨)·4-2(도구 위력)와 같은 성격의 "배선만 하면 되는" 작업이라 가장 빠르게 처리 가능. 데이터도 이미 있음.

(출처: [3-5](phase3-plan.md#3-확인이-필요한-파생-규칙), [4-2-2](phase3-plan.md#4-2-2-도구표에서-이번에-스코프-밖으로-남긴-것-후속-작업))

## 3. 날씨/필드 지속시간 시스템

- **날씨에 지속 턴 개념이 아예 없음**: 필드는 5턴 카운트다운이 있는데 날씨는 한번 고르면(또는 특성으로 자동 적용되면) 무제한 지속. 본가는 날씨도 5턴 지속이 기본
- **날씨 연장 도구 4종**(뜨거운바위·차가운바위·보송보송바위·축축한바위) + **필드 연장 도구**(빛의점토) + **그라운드코트**(필드 5→8턴): 전부 "지속시간 연장"이라 날씨 카운트다운부터 먼저 있어야 함
- **날씨 변화 기술**(비바라기 등): 데이터는 있지만 특성처럼 배틀 중 자동 적용 안 됨

이 셋은 서로 얽혀있어서 "날씨 카운트다운 도입" 하나를 먼저 하면 나머지가 순서대로 풀리는 구조.

(출처: [6-5](phase3-plan.md#6-5-후속-작업으로-남긴-것-문서-기록만-이번엔-미구현), [4-2-2](phase3-plan.md#4-2-2-도구표에서-이번에-스코프-밖으로-남긴-것-후속-작업))

## 4. 공간 변화 — 트릭룸

`moves.json`에 있고 5마리가 배울 수 있는데 `turnOrder.ts`의 턴 순서 계산에 전혀 배선 안 돼 있다(우선도/스피드로만 정렬, 트릭룸의 "스피드 역전" 반영 안 됨). `BattleState`에 지속 턴 카운터 하나 추가하고 `compareTurnOrder`에서 스피드 비교 방향만 뒤집으면 되는, 비교적 단순한 작업.

(출처: [6-5](phase3-plan.md#6-5-후속-작업으로-남긴-것-문서-기록만-이번엔-미구현))

## 5. 필드 개별 기술 상호작용

필드 기본 효과(위력 배율·상태이상 면역·우선도 차단·그래스 회복)는 Phase 3에서 끝냈지만, 개별 기술 특수 상호작용은 스코프 밖으로 남겼다: 그래스슬라이더(그래스필드에서 우선도 +1), 대지의파동(필드별 타입 변경+위력 2배), 비밀의힘(필드별 확률 부가효과), 아이언롤러(필드 파괴), 자연의힘(필드별 다른 기술 발동), 미스트버스트/와이드포스/라이징볼트/사이코블레이드(필드 조건부 위력 변화). 각 기술이 실제 로스터에 있는지부터 재확인 필요.

(출처: [6-2](phase3-plan.md#6-2-필드그래스미스트사이코일렉트릭-기본-지원--신규-스키마) 마지막 항목)

## 6. 우선도·상태이상·기타 개별 도구 효과

도구표에서 각각 서로 다른 개별 메커니즘이 필요해 미룬 항목들:

| 도구 | 필요한 메커니즘 |
|---|---|
| 하양허브 | 능력 하락을 원래대로 되돌림(1회용) |
| 구애스카프 | 스피드 1.5배 + "교체 전까지 같은 기술만" 제약 |
| 전기구슬 | 피카츄 전용 스탯 배율(로스터에 피카츄 없어 우선순위 낮음) |
| 기합의띠·기합의머리띠 | HP 1 남기고 버티기(1회용/확률부) |
| 멘탈허브 | 헤롱헤롱·도발 등 특정 행동방해 일괄 해제(1회용) |
| 선제공격손톱 | 우선도 동률 타이브레이크 확률 조정 |
| 왕의징표석 | 데미지 시 10% 추가 풀죽음 확률 |
| 검은철구 | 스피드 0.5배 + 의사 땅타입 부여 |
| 초점렌즈 | 급소율 랭크 +1 |
| 아름다운허물 | 교체 방해 무시(1v1엔 교체 자체가 없어 사실상 의미 없음) |

우선순위 낮음 — 각각 영향 범위가 좁고(도구 1개당 기술/상황 1개) 서로 재사용 가능한 부분이 적다.

(출처: [4-2-2](phase3-plan.md#4-2-2-도구표에서-이번에-스코프-밖으로-남긴-것-후속-작업))

## 7. UI 정합성 갭

- **`AbilityPickerModal`이 메가진화 고정 특성을 안 보여줌**: 계산(`getEffectiveAbilityId`)은 메가폼이면 항상 `mega.ability`를 쓰도록 이미 정확한데, 특성 선택 모달은 여전히 `pokemon.abilities`(기본 특성 목록)만 보여줘서 유저가 고른 값과 실제 적용되는 값이 달라 보일 수 있다. 메가진화 중이면 선택 UI 대신 "고정: 가뭄" 같은 안내로 바꾸는 게 자연스러움
- **일렉트릭필드를 배우는 포켓몬 미확인**: Phase 3에서 기술 데이터는 추가했지만 어떤 포켓몬 `learnset`에도 안 넣음(그래스/미스트/사이코필드는 6마리 확인됨)

(출처: [6-3](phase3-plan.md#6-3-부수-발견--메가진화-특성이-전혀-반영되지-않던-버그-버그-이번에-같이-수정), [6-5](phase3-plan.md#6-5-후속-작업으로-남긴-것-문서-기록만-이번엔-미구현))

## 8. 데이터 완성도

- **변화기 `effect` 텍스트 누락 다수**: [1-9](phase3-plan.md#1-9-위력-가변형-기술의-effect-텍스트-누락--완료) 작업 중 재스캔에서 확인 — 도발·최면술·중력·사슬묶기 등 `power: null` + `effect: ""`인 상태변화 기술이 다수 남아있음. 효과 자체가 뭔지 텍스트도 없는 상태라 데이터 보강이 최우선(구현은 그 다음)
- **해동 기술 7종 데이터 없음**: 나무위키 기준 얼음 상태에서 쓰면 자동 해동되는 기술 10종 중 3종(불사르기·열사의대지·플레어드라이브)만 현재 335개 기술 데이터에 있음. 성스러운불꽃·스팀버스트·열탕·크로스플레임·화염바퀴·화염볼·휘적휘적포는 애초에 기술 자체가 없음
- **`Ability.setsWeather` 양쪽 동시 보유 시 우선권 규칙 미확인**: 지금은 실효 스피드가 빠른 쪽이 이긴다고 임시로 정했는데 챔피언스 실제 규칙(본가는 스위치인 순서 기준) 확인 필요

(출처: [1-9](phase3-plan.md#1-9-위력-가변형-기술의-effect-텍스트-누락--완료), [7-2](phase3-plan.md#7-2-새로-추가한-것), [6-1](phase3-plan.md#6-1-날씨-배경색--날씨-변화-특성-자동-발동))

## 9. 설계 범위 밖 — 파티 단위 확장이 먼저 논의돼야 함

1v1 단일 대전 시뮬레이터라는 지금 설계 전제 자체를 안 건드리면 의미가 없는 항목들. Phase 4에서도 굳이 손대지 않는 게 맞다고 보고, 파티 배틀 확장을 언젠가 논의하게 되면 그때 같이 검토:

- **엔트리 해저드**(독압정 등): "교체" 개념이 없으면 무의미
- **집단구타**: 위력이 파티 전원의 공격 종족값 기반이라 파티 개념 필요
- **고스트다이브의 "상대 방어 무시"**: 나이트헤드류(`fixedDamage`)처럼 방어 무시 전용 필드를 추가하면 되긴 하지만, 1v1 범위 안에서도 할 수 있는 작업이라 파티 확장과는 무관 — 우선순위만 낮게 잡아둠
- **잠꼬대**("배운 기술 중 하나를 무작위로 사용"): 파티 확장과 무관하지만 별도 메커니즘이 필요해서 함께 낮은 우선순위

## 10. 제안 순서
