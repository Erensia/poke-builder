# ver.5.1 백로그

5.0 마무리에서 넘어온 미수정 한계 가운데 **실제로 고칠 것만** 추렸다(2026-10-22 사용자와 확정). 이전 버전: `5.0-backlog.md`(5.0 종료 — 랭크배틀·랭크배틀용 AI, 마무리 절에 한계 전체).

5.1은 마이너 버전이라 **전체 리팩토링은 하지 않는다**. 항목별 브랜치 → PR 1개(커밋 1개) → `dev` squash, 마지막에 `dev` → `main` PR 제목 `ver5.1`(CLAUDE.md). 챔피언 AI 강화(평가식 개선)·학습 이득 개선·시나리오 파일 분할은 6.0 이후로 미룬다.

## ① 기능·개선 작업

### A1 모바일 실기기 검증과 수정 — **제외**(2026-10-22)

- 사용자가 모바일 실기기에서 랭크 프로필·게이지·구간 화면·판단 대기 시간을 이미 확인·검증했다(시간이 걸리긴 했지만 정상 작동). 5.0 "확인 대기"가 해소돼 5.1 작업 항목에서 뺀다. 다른 문서가 번호로 참조하므로 A2~A5는 번호를 유지한다.

### A2 샘플 등급 승률표 저장과 증분 측정

- **문제**: 등급(`samplePartyTiers.json`)만 저장돼 있고 승률표는 없어, 샘플이 늘 때마다 전체 재측정(약 2시간, `rank-party-tiers.mjs 5 --write`, 12코어)이 필요하다. 샘플 16의 등급은 임시 "중"이다.
- **방향**: 승률표를 JSON으로 저장하고, 새 샘플은 기존 샘플과의 쌍(약 35쌍)만 측정해 표에 더한 뒤 등급을 다시 매긴다. 샘플 16도 이때 정식 측정한다. 측정 방식·등급 경계는 5.0 그대로이고, 측정 스크립트와 데이터만 바뀌어 앱 코드 영향은 없다.
- **확인할 것**: 증분 결과가 전체 재측정과 같은 등급을 내는지(몇 쌍 표본 대조), 등급 경계가 샘플 수에 의존하면 어떻게 다시 매길지, `test:rank-ai`의 "모든 샘플 등급 보유" 검사와의 정합.

### A3 랜덤 구축 상대 정리

- **난이도**: 랜덤 구축 상대는 해당 등급 샘플 대비 하 60.0%·중 43.8%·상 44.6%로, 하등급에서 샘플보다 강해 몬스터볼 난이도가 소폭 올랐다. 해당 등급 샘플 수준에 맞추는 방법(구축 휴리스틱 조정 또는 등급별 구축 약화)을 착수 때 정한다. 측정으로 효과를 먼저 확인하고 코드에 반영한다(5.0 규칙).
- **`MAX_MEGAS`**: 랜덤 구축의 메가 2마리 제한과 설정 화면 안내("메가진화 포켓몬은 최대 2마리")는 파티 규칙(메가 수 제한 없음)과 다른 생성 휴리스틱이다. 규칙에 맞출지 휴리스틱으로 유지할지 정한다(난이도 조정과 함께 보는 것이 자연스럽다).

### A4 랭크 AI 측정 보강 (선택 — 시간이 있을 때)

- 5.0 사다리 측정은 무작위 3마리 파티 기준이었다. **샘플 파티 기준 재측정**, 3선출 약화(`selectvs`), `riskAversion` 고정을 측정에 넣어 단계 격차(P0~P4, 마스터볼 4~1)가 실사용 조건에서도 단조 증가하는지 확인한다.
- 병렬 측정은 12프로세스면 메모리 부족으로 백그라운드 대기가 중단될 수 있다 → 포그라운드 `until` 루프, 측정 중 `src/` 수정 금지(5.0 규칙). 시간 추정은 병렬 실측 배수(판당 약 4.6초)를 곱한다.
- 결과가 나쁘면 AI 단계 설정을 바꿀지는 측정 뒤 따로 결정한다. 이 항목은 **측정·판정까지**가 범위다.

### A5 터치에서 안 보이는 `title` 설명을 `InfoTooltip`(ⓘ)으로 (5.0 이월 한계 — 이 작업만 5.1에 넣는다)

- **배경**: `title="…"`로만 설명하는 곳은 터치에 호버가 없어 안 보인다. A4(4.1)처럼 필요한 곳만 공용 `InfoTooltip`으로 옮긴다. 현재 `InfoTooltip` 사용처는 `AiMemoryModal`·`BattleSetupScreen`(+자신)뿐이다.
- **착수 때 먼저 할 일**: 어디가 필요한지 정한다(요청 시 목록부터 — 4.1 마무리 규칙). 2026-10-22 `src/**/*.tsx` 조사에서 속성 `title=` 약 50곳 중 `Modal`·`Fold`·`FactorCard`·`AllocationGrid`의 **컴포넌트 prop**(제목)은 대상이 아니다. 설명 목적 후보:
  - **토글·입력 설명**: `MatchupSlotCard`의 가정 토글("상대 도구를 빼앗은 것으로 계산", "곡예 발동 후라고 가정 — 스피드 2배", 급소 토글의 막힌 사유), 랭크 표시 `기본 N (±n랭크)`.
  - **비활성 사유**: `BattleSetupScreen` 진행 버튼(`blockedReason`), `BattleSeriesPanel`·`RankPanel` 시작 버튼(`startBlockedReason`), `DefenseInferencePanel`의 "먼저 포켓몬을 골라 주세요"·메가진화 잠금 사유. 모바일은 `disabled` 버튼이 눌리지 않아 사유가 안 보이므로, 버튼 옆 한 줄 안내가 더 맞을 수 있다.
  - **성격 목록**: `CandidateCards`·`DefenseInferencePanel` 칩의 `natureNames.join(", ")`.
  - **표·그래프 호버**: `TypeChartTable`(`공격 → 방어: ×배율`)·`TypeCoverageSummary`(타입·배율·약점 개수)·`DefenseInferencePanel` 분포 점, `BattleBoard` HP 요약·상태 설명. 칸마다 ⓘ를 둘 수 없어 표 아래 한 줄 안내나 탭 시 상세로 풀지 정한다.
  - **아이콘 버튼 이름**: `BattleSetupCard`·`PartySlotCard`의 "포켓몬 변경"·"이 빌드를 샘플로 저장", `MoveDexPage` 정렬 방향은 설명이 아니라 라벨(`aria-label`)에 가까워 설명 대상에서 뺄 수 있다.
- **방식**: 위 묶음마다 `InfoTooltip`(ⓘ) / 버튼 옆 안내 문구 / 그대로 둠을 정하고, 착수 때 사용자에게 확인한다. 모바일 말풍선 폭·위치는 A4 때 방식(PC 호버, 모바일 ⓘ 탭)을 따른다. 터치 영역은 `tap-target` 마커 규칙(4.1 A2), 새 pseudo-element 규칙은 4.1 "얻은 규칙(CSS)"을 따른다.
- **범위 밖**: 노력치 역산 미지원 기술(고정 데미지·자이로볼·속임수·셸암즈·쓰러진 다단히트)은 이번에 넣지 않는다(요청이 올 때만).
