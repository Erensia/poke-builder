## 착수 때 논의 정리 (2026-10-19)

세부 설명은 R1·R3 각 항목의 "착수 때 논의할 것"에 있다. 여기는 **먼저 답이 있어야 다음이 풀리는 순서**로 모은 것이다.

**A. 범위·순서**
1. 작업 순서 R1 → R2 → R3 확정, R2·R3 통합 여부(R3 논의 4번).
2. R1 PR 분할(ⓐ 순수 함수+검증 스크립트 ⓑ `RankSave`·판 결과 연동 ⓒ 화면) 확정.

**B. R1 규칙의 빈틈 (문서 규칙을 읽고 찾은 것)**
1. **연승 카운트 리셋 시점**: 승급·강등·마스터볼 진입 때 연승이 이어지는가. 경험치제 구간의 연승이 마스터볼 첫 판 배율(×1.1~)에 이어지는가.
2. **경험치제 구간의 연패**: 패배 -1/4는 연패에 관계없이 고정인가(마스터볼과 달리 연패 가중 없음으로 읽힘).
3. 초기 레이팅(R1 논의 1번): 승수 = 구간 누적 전체 승수 / 연승 보너스 1.1배의 대상(합산 점수 전체 vs 추가 점수만) / 반올림.
4. 강등 수치(R1 논의 2번): 게이지 0에서 패배 → 아래 단계 3/4. 하이퍼볼 4 → 슈퍼볼 1 같은 **볼 경계 강등**도 허용하는가(문서는 "바로 아래 단계"만 명시).
5. 마스터볼의 무승부·이탈: 패배 -20에 연패 배율까지 적용하는가(문서상 그렇게 읽힘). 무승부가 실제로 나오는 경우(턴 상한 등)를 엔진에서 확인.
6. 상대 매칭: 랭크·레이팅에 따라 상대가 달라지는가(R2·R3와 연결).

**C. 화면·저장**
1. 랭크배틀 화면 구성(프로필·시작·파티 편성)과 기존 배틀타워 화면의 관계, 파티·선출 UI 재사용 여부.
2. 저장 키 이름, 이력 보관 개수·형식, 랭크 초기화 확인 정책.
3. 랭크 아이콘 방식(이모지/스프라이트)·원형 게이지(CSS/SVG)·모바일 폭 배치.

**D. 시즌·보상 같은 확장은 이번 범위 밖으로 가정** — 필요하면 사용자가 추가 요청.

## ① 기능 작업

### R1 배틀타워 랭크배틀 시스템 (2026-10-19 사용자 요청, 4.1에서 5.0으로 이동)

기존 배틀 프런티어(연승·전적)와 **기능을 분리**한 별도 시스템이다. 랭크 전용 연승·연패 카운터와 저장(`RankSave`)을 따로 둔다.

#### 규칙 — 확정

**랭크 구성**: 몬스터볼 → 슈퍼볼 → 하이퍼볼 → 마스터볼. 몬스터볼·슈퍼볼·하이퍼볼은 각각 **4~1의 4단계**(4가 가장 낮고 1이 가장 높다, 총 12단계 + 마스터볼).

**몬스터볼~하이퍼볼 (경험치제)**

- 단계마다 게이지를 1로 보고, 1승에 **+1/4**(4승 승급), 1패에 **-1/4**.
- 연승 보너스: **2연승째부터** 한 판마다 기본 1/4 **대신** 1/2 상승(합산 3/4 아님).
- **승급은 초과분을 이월한다**: 예) 몬스터볼 1의 게이지 3/4에서 2연승째로 +1/2 → 합계 5/4 → 슈퍼볼 4에 게이지 1/4로 올라간다. 게이지를 하나의 연속 눈금으로 본다.
- **단계 강등 존재**: 게이지 0에서 패배하면 바로 아래 단계의 3/4로 내려간다(연속 눈금 기준). 몬스터볼 4의 게이지 0에서는 더 내려가지 않는다. (세부 수치는 기본안 — 착수 때 확인)

**마스터볼 진입**

- 하이퍼볼 1의 게이지가 전부 차면 마스터볼로 올라가며 **초기 레이팅이 산정**된다.
- 초기 레이팅 = 기본 1300 + 몬스터볼~하이퍼볼 구간의 **승수에 따른 추가 점수(1승당 2점)** + **연승 보너스 레이팅(1.1배)**. 승수의 기준(구간 누적 전체 승수인지)·연승 보너스가 곱해지는 대상·반올림 등 **세부는 착수 때 토의한다**.

**마스터볼 (레이팅제)**

- 승리 시 기본 **+20**, 패배 시 기본 **-20**. **강등은 없고(하이퍼볼로 내려가지 않는다) 레이팅 하한은 0**.
- 승리일 때의 **턴 수 보정**(선형, **승리에만 적용** — 패배는 턴 수와 무관하게 기본 -20):
  - 30턴 이하는 1턴 빠를 때마다 **+1**(20턴 이하에서 **최대 +10**).
  - 40턴 초과는 1턴 늦을 때마다 **-1**(50턴 이상에서 **최대 -10**).
  - 31~40턴은 보정 없음.
  - 턴 수는 **판이 끝난 시점의 턴 번호**(교체·강제 교체 턴 포함)를 쓴다.
- **연승·연패 배율**: 2연승부터 승리 점수 ×1.1, 3연승 ×1.2, 4연승 ×1.3, 5연승 ×1.4 … 계속 상승(상한 없음). 2연패부터 차감 레이팅 ×1.1, 3연패 ×1.2, 4연패 ×1.3 … 계속 상승(상한 없음).
- **계산 순서**: (기본 20 ± 턴 보정) × 연승·연패 배율, 마지막에 반올림.

**연승·연패 정의**

- 랭크 전용으로 따로 센다(프런티어의 `streak`와 별개).
- 이탈(새로고침·창 닫기)과 무승부는 **패배로 처리**하며 **연패에도 포함**된다.

**저장**: 별도 `RankSave` 타입을 신설한다(프런티어 `FrontierSave`와 분리). 저장 키는 착수 때 정한다(기본안: 별도 `localStorage` 키 — 파티 자동저장·프런티어 키와 겹치지 않게).

**표시**: 랭크 아이콘 · 게이지 막대(**원형**) · 승패 직후 계산 내역 반영 · **이력 저장**(보관 개수·형식은 착수 때 논의).

**UI(개발안 추가)**: **사이드 메뉴에 "랭크배틀" 추가**. 랭크 프로필 · 랭크 배틀 시작 · 파티 편성 등의 화면 구성. **상세 설계는 착수 때 논의**한다.

#### 기존 코드 현황(2026-10-19 확인)

- 화면 이름은 "배틀타워"(`BattleLogPage.tsx`), 코드 이름은 "배틀 프런티어". 이미 있는 것: 연승(`streak`)·최대 연승(`best`)·샘플별 전적·상대 대기열·이탈=패배 정산(`lib/battleSeries.ts`, `hooks/useBattleSeries.ts`), 저장은 `localStorage['champions-party-sim.battle-frontier.v1']`(`lib/storage.ts`의 `createLocalStorageStore` 팩토리). 랭크배틀은 이것과 기능을 분리하되 **저장 팩토리·이탈 정산 방식은 재사용**할 수 있다.
- 상대는 샘플 파티 무작위 순서의 AI이고 AI 성향(`riskAversion`)은 판마다 `sampleRiskAversion()`으로 새로 뽑는다. 무승부는 지금 패배로 처리한다.
- 사이드 메뉴는 `Sidebar.tsx`.

#### 착수 때 논의할 것

1. 초기 레이팅 산정 세부(승수 기준·연승 보너스 1.1배의 대상·반올림).
2. 게이지 강등 세부(0에서 패배 → 아래 단계 3/4) 확인.
3. 랭크배틀 화면 구성(프로필·시작·파티 편성)과 기존 배틀타워 화면과의 관계(파티·선출 UI 재사용 여부).
4. 이력 저장 방식(개수 상한·표시 위치)과 초기화 버튼 정책(랭크 초기화는 별도 확인).
5. 아이콘 방식(볼 이모지/스프라이트 — 기존 `lib/sprites.ts` 확인)·원형 게이지 구현(CSS/SVG)·모바일 폭 배치.

#### 구현 방향(안)

계산은 UI와 분리한 순수 함수 파일(예: `lib/battleRank.ts`, 판 결과 → 새 랭크 상태)로 만들고, 규칙 표를 전수 확인하는 단위 검증 스크립트(`scripts/`, `ssrLoadModule` 방식)를 같이 남긴다. 엔진·AI·역산 해시는 건드리지 않는다. ⓐ 순수 함수 + 검증 스크립트 ⓑ `RankSave` 저장·판 결과 연동 ⓒ 화면(사이드 메뉴·프로필·원형 게이지·계산 내역·이력) 순으로 PR을 나누는 것을 검토한다(PR은 커밋 1개 규칙, 화면은 사용자 PC·모바일 확인을 위임).

### R2 랭크별 AI 성향 차등 (R1 뒤, 2026-10-19 사용자 결정)

R1이 들어간 뒤 랭크에 따라 상대 AI 성향(`riskAversion` 분포·상대 샘플 선택 등)을 다르게 하는 작업. 작업량이 커서 R1과 분리했다. R1은 랭크 상태를 AI 설정 쪽에서 읽을 수 있는 형태로 노출해 둔다. AI 판단을 바꾸므로 `sim:ai regress`·`test:ai` 해시가 바뀔 수 있다 — 의도한 변화인지 확인하고 기준값을 다시 기록한다.

### R3 랭크배틀용 AI 개발 (R1 뒤, 2026-10-19 사용자 추가 요청)

랭크배틀에서 맞붙는 상대 AI를 **랭크배틀 전용으로 개발**하는 작업. 지금 배틀타워의 상대는 샘플 파티 + 판마다 `sampleRiskAversion()`(U(0,1))으로 뽑은 성향의 범용 AI(`chooseAiAction`)다.

**R2와의 관계**: R2는 "랭크에 따라 같은 AI의 성향·상대 샘플을 **차등**"하는 작업이고, R3는 "랭크배틀을 위한 AI **자체**(의사결정·팀 선출·상대 모델·탐색 등)를 만드는" 작업이다. 범위가 겹칠 수 있어 착수 때 **R2를 R3에 흡수할지, 둘로 나눌지** 먼저 정한다(아래 논의 4번).

#### 착수 때 논의할 것

1. "랭크배틀용 AI"의 목표 — 더 강한 AI인지, 사람처럼 보이는 AI인지, 랭크 구간별로 단계 난이도가 있는 AI인지.
2. 개발 범위 — 기존 `lib/battle/ai/`(평가식 `evaluator`·결정 `decision`·탐색 `search`·상대 모델·`teamSelect` 선출)에서 **무엇을 켜고 무엇을 새로 만들지**. 랭크 전용 `DecisionParams` 프리셋만으로 되는지, 새 로직이 필요한지.
3. 상대 파티 구성 — 샘플 파티 무작위 그대로인지, 랭크·레이팅에 맞는 파티를 고르거나 따로 만들지(파티 풀 신설은 `SP` 샘플 추가와 별개).
4. R2와의 분담 — 합칠지 나눌지, 나눈다면 R2는 성향 분포만·R3는 로직 쪽으로 경계를 어디에 둘지.
5. 성능 — 탐색 AI는 `aiWorker`를 쓴다. 랭크 판에서 대기 시간 상한(모바일 포함).
6. 검증 — AI를 바꾸므로 `test:ai`·`sim:ai regress` 해시가 바뀐다. 기준 AI 대비 승률(`sim:ai` 모드)로 "더 강해졌다/단계가 나뉜다"를 수치로 확인하는 방법과 합격선. 기준값 재기록은 의도한 변화로 확인한 뒤.
7. 배틀 사이의 학습 — 상대 패턴 학습(`opponentMemory`)을 랭크 판에서 쓸지(판 간 누적 허용 여부).

#### 구현 방향(안)

R1의 랭크 상태가 AI 설정 쪽에서 읽히는 형태가 된 뒤(R1 ⓑ) 시작한다. 상세 설계는 목표(논의 1번)가 정해진 뒤 이 절에 채운다.
