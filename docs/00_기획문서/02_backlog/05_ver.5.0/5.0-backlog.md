## ① 기능 작업

### R1 배틀타워 랭크배틀 시스템 (2026-10-19 사용자 요청, 4.1에서 5.0으로 이동)

기존 배틀 프런티어(연승·전적)와 **기능을 분리**한 별도 시스템이다. 랭크 전용 연승·연패 카운터와 저장(`RankSave`)을 따로 둔다.

#### 규칙 — 확정

**랭크 구성**: 몬스터볼 → 슈퍼볼 → 하이퍼볼 → 마스터볼 → **챔피언**(마스터볼 레이팅 2500 이상). 몬스터볼·슈퍼볼·하이퍼볼은 각각 **4~1의 4단계**(4가 가장 낮고 1이 가장 높다, 총 12단계 + 마스터볼 + 챔피언).

**몬스터볼~하이퍼볼 (경험치제)**

- 단계마다 게이지를 1로 보고, 1승에 **+1/4**(4승 승급), 1패에 **-1/4**.
- 연승 보너스: **2연승째부터** 한 판마다 기본 1/4 **대신** 1/2 상승(합산 3/4 아님).
- **승급은 초과분을 이월한다**: 예) 몬스터볼 1의 게이지 3/4에서 2연승째로 +1/2 → 합계 5/4 → 슈퍼볼 4에 게이지 1/4로 올라간다. 게이지를 하나의 연속 눈금으로 본다.
- **단계 강등 존재**: 게이지 0에서 패배하면 바로 아래 단계의 3/4로 내려간다(연속 눈금 기준). **볼 경계도 넘는다**(하이퍼볼 4 → 슈퍼볼 1, 슈퍼볼 4 → 몬스터볼 1). 몬스터볼 4의 게이지 0에서는 더 내려가지 않는다.
- **연패 가중 없음**: 패배는 연패 수와 무관하게 -1/4 고정. 연패가 반복될 때의 난이도 보정은 AI 쪽에서(R3).
- **연승은 이어진다**: 승급·강등 때 끊기지 않고, 마스터볼 진입 뒤 첫 판 연승 배율에도 반영된다(진입 승리까지 센 연승 수 + 1 번째 승리로 계산).

**마스터볼 진입**

- 하이퍼볼 1의 게이지가 전부 차면 마스터볼로 올라가며 **초기 레이팅이 산정**된다.
- 초기 레이팅 = (기본 1300 + 몬스터볼~하이퍼볼 전 구간 **누적 승수 × 2점**) × **연승 보너스 1.1배(조건부)**. 소수점 둘째 자리까지.
- **1.1배는 합산 점수 전체에 곱한다 — (a)안 확정(2026-10-19)**. 적용 조건은 둘 중 하나라도 맞을 때:
  1. 마스터볼 승급 시점에 **연승 중**(승급 승리를 포함해 **2연승 이상**; 승급은 항상 승리로 이뤄지므로 1연승만으로는 조건이 되지 않는다고 해석 — 연승 배율이 2연승부터인 것과 같은 기준).
  2. 연승 중이 아니더라도 몬스터볼~하이퍼볼 전 구간 누적 **승수 − 패수 ≥ 10**(이탈 패배도 패수에 포함).
  둘 다 아니면 1.1배 없이 (1300 + 2×승수)이다.

  | 방식 | 식 | W=25 | W=40 | W=60 | W=100 |
  |---|---|---|---|---|---|
  | (a) 합산 점수 전체 | (1300+2W)×1.1 | 1485.00 | 1518.00 | 1562.00 | 1650.00 |
  | (b) 추가 점수에만 | 1300+2W×1.1 | 1355.00 | 1388.00 | 1432.00 | 1520.00 |
  | 보너스 없음(참고) | 1300+2W | 1350.00 | 1380.00 | 1420.00 | 1500.00 |

  (a)−(b)는 승수와 무관하게 항상 **130.00**(= 1300×0.1). (b)의 보너스는 W=40에서 +8점에 불과해 사실상 무의미하고, (a)는 +130점의 고정 보상이다. W=25는 연승만으로 올라간 최소 승수(1/4 + 24×1/2 ≥ 12).

  **가계산 (2026-10-19, 누적 30승 · 7연승으로 진입, (a)안 확정)**: 보너스 없음 1360.00 / (a) (1300+60)×1.1 = **1496.00** / (b, 폐기) 1300+60×1.1 = 1366.00. 위 비교표는 (a)/(b) 선택 근거로만 남긴다.

**마스터볼 (레이팅제)**

- 승리 시 기본 **+20**, 패배 시 기본 **-20**. **강등은 없고(하이퍼볼로 내려가지 않는다) 레이팅 하한은 0**. 레이팅은 **소수점 둘째 자리까지** 저장·표기한다.
- 승리일 때의 **턴 수 보정**(선형, **승리에만 적용** — 패배는 턴 수와 무관하게 기본 -20):
  - 30턴 이하는 1턴 빠를 때마다 **+1**(20턴 이하에서 **최대 +10**).
  - 40턴 초과는 1턴 늦을 때마다 **-1**(50턴 이상에서 **최대 -10**).
  - 31~40턴은 보정 없음.
  - 턴 수는 **판이 끝난 시점의 턴 번호**(교체·강제 교체 턴 포함)를 쓴다.
- **연승·연패 배율**: 2연승부터 승리 점수 ×1.1, 3연승 ×1.2, 4연승 ×1.3, 5연승 ×1.4 … 계속 상승(상한 없음). 2연패부터 차감 레이팅 ×1.1, 3연패 ×1.2, 4연패 ×1.3 … 계속 상승(상한 없음).
- **계산 순서**: (기본 20 ± 턴 보정) × 연승·연패 배율, 마지막에 **소수점 둘째 자리로 반올림**(부동소수 오차를 막으려고 매 판 `Math.round(x*100)/100`).

**챔피언 (마스터볼 상위, 2026-10-19 사용자 추가)**

- 마스터볼에서 레이팅이 **2500점 이상**이면(2500.00 포함) 신규 랭크 **챔피언**이다. 마스터볼의 최상위 등급이다(2026-10-19 "초과"에서 "이상"으로 확정).
- **챔피언은 마스터볼과 같은 레이팅제**를 그대로 쓴다. 레이팅이 2500 미만으로 내려가면 **마스터볼로 돌아가고**, **챔피언 달성 이력은 남긴다**(`RankSave`에 달성 여부·최초 달성 시점·최고 레이팅을 따로 기록).
- **달성 연출**을 넣는다(2026-10-19 사용자 선호). 최초 달성과 재달성 때 같은 연출을 쓸지, 방식(모달/배너)은 화면(ⓒ)에서 정한다.
- 아이콘은 사용자가 넣은 `public/sprites/Rank/` PNG 5종(`Champs_{Poké,Great,Ultra,Master}_Ball_Tier_Icon.png`, `Champs_Champion_Tier_Icon.png`)을 **그대로 사용**한다(확정, 인라인 SVG 안은 폐기).

**연승·연패 정의**

- 랭크 전용으로 따로 센다(프런티어의 `streak`와 별개).
- 이탈(새로고침·창 닫기)은 **패배로 처리**하며 **연패에도 포함**된다(경험치제 구간 -1/4, 마스터볼 -20×연패 배율). 무승부는 엔진에 TOD 룰·턴 상한이 없어 발생하지 않는다(발생하면 패배와 같게 처리). AI전이라 턴 상한 무승부는 형평성이 낮다고 보고 두지 않는다(2026-10-19 결정).

**저장·시즌**: 별도 `RankSave` 타입을 신설한다(프런티어 `FrontierSave`와 분리).
- 저장 키는 `localStorage['champions-party-sim.battle-rank.v1']` — `lib/storage.ts`의 다른 키(`...battle-frontier.v1` 등)와 같은 형식의 별도 키.
- **이력 = 랭크 판마다 한 줄**(날짜 · 상대 샘플 · 승/패/이탈 · 턴 수 · 게이지·레이팅 변화와 계산 내역), **최근 50판만 보관**(확정, 2026-10-19). 랭크 프로필 화면에서 볼 수 있다.
- **수동 초기화 = 시즌 기록 저장 후 초기화**(확정, 2026-10-19 — 초기 구현에서만. 이후 30일 자동 초기화 ⓓ 추가). 랭크 화면의 "랭크 초기화" 버튼 + 확인(앱 안 모달 — 네이티브 `confirm`은 자동화에서 탭이 멈추므로 쓰지 않는다). 초기화 직전 상태를 **N시즌**(1시즌, 2시즌 …)으로 저장하고 랭크는 몬스터볼 4·게이지 0, 연승·연패 0, 이력 비움으로 되돌린다. 시즌 기록에 담는 것:
  - **초기화 직전 레이팅**(마스터볼 이상일 때) — 마스터볼 미도달이면 레이팅이 없으므로 **도달한 볼·단계**를 저장(기본안).
  - **시즌 중 최대 레이팅**.
  - **챔피언 달성 여부**: 달성했다면 달성 사실을 남기고, 달성하지 못했다면 최대 레이팅만 표시한다.
  - **초기화 직전 사용한 파티**(랭크 판에서 마지막으로 쓴 파티의 스냅숏).
  - **승리한 수**(그 시즌 랭크 판 전체 승수, 경험치제 구간 포함).
  - 랭크 프로필 화면에서 **시즌별 기록 목록**을 볼 수 있다. 이전에 정한 "챔피언 달성 이력은 초기화에서 지우는가" 문제는 시즌 기록이 이력을 보존하므로 해소된다.

### R3 랭크배틀용 AI 개발 (R1 뒤, 구 R2 랭크별 AI 성향 차등 통합 — 2026-10-19 사용자 결정)

랭크배틀에서 맞붙는 상대 AI를 **랭크배틀 전용으로 개발**하는 작업이다. 기존 R2(랭크에 따라 `riskAversion` 분포·상대 샘플 선택을 차등)는 이 항목에 **통합**했다. 지금 배틀타워의 상대는 샘플 파티 + 판마다 `sampleRiskAversion()`(U(0,1))으로 뽑은 성향의 범용 AI(`chooseAiAction`)다.

R1은 랭크 상태(볼·단계·레이팅·연승·연패)를 AI 설정 쪽에서 읽을 수 있는 형태로 노출해 둔다. AI 판단을 바꾸므로 `sim:ai regress`·`test:ai` 해시가 바뀐다 — 의도한 변화인지 확인하고 기준값을 다시 기록한다.

#### 확정된 요구

- **연패 난이도 보정**: 경험치제 구간(몬스터볼~하이퍼볼)에는 연패 가중이 없는 대신, 연패가 반복되면 AI 수준을 낮추거나 상대 파티 조합을 일부러 쉽게 고르는 추가 난이도 조정을 둔다(2026-10-19).

#### 설계 (2026-10-19 확정 — 사용자 결정 3건 + 외부 의견(GPT) 검토 반영)

**방향**: 새 AI를 만들지 않는다. 기존 AI(`lib/battle/ai/`)를 그대로 쓰고, 랭크·연패에 맞는 **AI 설정(프로필)과 상대 파티를 고르는 정책 계층**만 추가한다. 엔진·판단 로직은 건드리지 않는다(특정 약점이 측정으로 확인될 때만 별도 검토). 정책 함수는 판단을 하지 않고 설정만 반환한다.

**두 축**
- **AI 프로필 사다리** P0(약) ~ P3(현재 앱 AI = `APP_DECISION_PARAMS`) + **P4(챔피언 전용, 더 강함)**. 프로필 = `decisionParams` + 3선출 방식 + `riskAversion` 분포 + 학습 메모리 사용 여부. 약화 수단 후보(측정 후 확정): 탐색 끔 → 상대 모델 끔 → `partyAware`/`oppSwitchAware`/`mySwitchAware` 끔 → 변화기 `*Aware` 끔 → (필요하면) 낮은 확률 차선책 선택. P4는 `depth 2`·`seeds`·`budget` 확대 등 탐색 강화이며 **모바일 대기 시간 상한을 지키는 범위**에서만(성능 측정 필수).
- **샘플 파티 강도 등급**(35개 → 하/중/상). AI를 고정하고 파티끼리 `h2h`로 재서 승률 순으로 나눈다. **AI 프로필 후보는 4~5개이지 35개가 아니다**(35는 샘플 파티 수).

**정책 `resolveRankAiPolicy({ state, lossStreak, seed })` → `{ profile, partyPool }`** (수치는 측정 뒤 확정)
- 기본 단계: 몬스터볼 P0 · 슈퍼볼 P1 · 하이퍼볼 P2 · 마스터볼 P3 · **챔피언 P4 + 상등급 파티**. 볼 안의 4~1 단계에서는 파티 등급만 서서히 올린다.
- **연패 보정(경험치제 구간만, 마스터볼 이상은 연패 배율이 있어 없음)**: **파티 등급을 먼저 내리고, 하한(하등급)에서도 연패가 이어지면 AI 단계를 내린다**(사용자 결정). 시작 연패 수·단계 폭은 측정 뒤 정하되 초안은 3연패 → 파티 한 등급, 5연패 → 두 등급, 하등급 이후의 연패 → AI 한 단계씩. P0 아래로는 내려가지 않는다. **이기면 즉시 복구**.
- 무작위성은 상대 파티 선택과 `riskAversion`에서만 얻는다(프로필 확률 혼합은 쓰지 않는다 — 규칙이 설명되지 않음). 같은 입력·시드면 같은 선택(재현성).
- 학습 메모리(`opponentMemory`)·3선출 방식은 프로필에 포함해 단계별로 켜고 끈다.

**배치**: `src/lib/battle/ai/rankProfile.ts`(카탈로그 + 정책), `src/data/samplePartyTiers.json`(측정 스크립트가 생성 — 샘플 파티 JSON에 필드를 넣으면 SP 작업이 늘어서 분리. 등급 없는 새 샘플은 중등급 폴백). 연동: `useRankBattle`의 `pickOpponent`(상대 파티), `BattleLogPage.tsx`의 `mode === "rank"` 분기(`decisionParams`·`riskAversion`·선출). 배틀타워 일반 경로는 그대로.

- **c8 결과(2026-10-20, 회사 PC, 12조각 병렬 · 약 20분)**: A(`depth 2`) 112승 · B(앱 AI) 89승 · 무 1 → **55.7%**(표본 202판, 95% 신뢰구간 약 ±7%p라 50%와 확실히 구분되지는 않음, z≈1.6). 판단 시간은 A 쪽 평균 **1.7초 · 최대 18초 · 3초 이상 17.6%**(12개 병렬 부하 상태라 절대값은 부풀려졌지만 배수는 유효) — 현재 앱 AI의 수십~수백 ms에 비해 크게 늘어 **모바일 대기 시간 상한을 넘길 가능성이 크다**. 결론: `depth 2`는 P4 후보로 승률 이득이 작고(+5.7%p, 합격선 55~65% 하한 근처) 시간 비용이 커서 **단독으로는 채택하지 않는다**. P4는 (1) 더 큰 표본으로 `depth 2` 재확인 + 실기기 시간 측정, (2) 탐색 외 수단(학습 메모리 누적 허용·`seeds` 증가·3선출 강화) 중에서 S2에서 정한다.

**실수 모델 (노이즈) 설계 — 확정(2026-10-19)**
- 약화 수단이 플래그 끄기만으로는 부족해서 둔다. `DecisionParams.mistake?: { rate: number; margin: number }` — 꺼짐(`undefined`)이 기본이라 `regress` 해시·`test:ai`가 바뀌지 않는다(`search`·`opponentModel`과 같은 패턴).
- 적용: `chooseAiAction` 끝, `chosen`이 정해진 직후. `scored`에서 `chosen`을 뺀 선택지 중 점수가 **최선 − margin 이내**인 것이 있으면 확률 `rate`로 그중 하나를 **균등** 선택(없으면 원래 선택 유지). 엉뚱한 실수(무조건 무작위)는 막고 "그럴듯한 차선책"만 실수 후보로 한다.
- **확정 처치 하드 오버라이드(`isHardOverride`)는 실수에서 제외**(AI가 바보처럼 보이지 않게). 이 때문에 약화 폭에 한계가 생길 수 있다 — P0가 충분히 안 약해지면 `rate` 상한을 올리거나 제외를 푸는 쪽을 검토(`ponytail:` 주석으로 한계 표기).
- **탐색이 켜진 프로필(P3·P4)에는 쓰지 않는다**(탐색 값이 `scored`와 달라 합성이 복잡). 실수 모델은 P0~P2(탐색 끔)용. 강제 교체(`chooseAiForcedSwitch`)에도 적용하지 않는다.
- 재현성: `ChooseAiOptions.rng?: () => number`(기본 `Math.random`). 시뮬레이터는 판마다 시드 고정 난수를 넘긴다. `aiWorker`는 `Math.random`.
- **S2 측정 계획**: 기반 c7(전부 끔) 또는 c3, 상대 앱 AI. `rate` {0.1, 0.2, 0.3, 0.5} × `margin` {0.3, 1.0, 무한}, 설정당 400판. 인접 단계 격차 55~65%가 나오는 `rate`를 골라 P0~P2를 정한다. 함께 잴 약화 수단: 3선출 `random`/`first`(`selectvs` 모드가 이미 있음), `riskAversion` 고정.

**S2 1차 측정 결과 — 실수 모델 `rate`×`margin` (2026-10-20, 회사 PC, 설정당 400판 · 약 80분)**
- 조건: A = c7(탐색·상대 모델·`*Aware` 전부 끔) + `mistake{rate,margin}`, B = 현재 앱 AI(`APP_DECISION_PARAMS`), 시드 1~200 좌우 교대, A 승률(무승부 제외, 95% 신뢰구간 ±4.5~4.9%p). `margin` "무한"은 1e9.

| rate \ margin | 0.3 | 1 | 무한 |
|---|---|---|---|
| (기준) c7 실수 없음 | 39.9% | | |
| 0.1 | 41.4% | 39.3% | 39.2% |
| 0.2 | 39.3% | 37.3% | 38.7% |
| 0.3 | 38.7% | 33.8% | 33.0% |
| 0.5 | 36.6% | 31.0% | **29.8%** |

- 해석 1: `rate` 0.1~0.2는 기준선(39.9%)과 구분되지 않는다(오차 ±4.8%p). **`margin` 0.3은 `rate`를 올려도 거의 효과가 없다**(점수 차 0.3 이내 차선책이 드물어서). 효과는 `margin` ≥ 1에서 `rate`에 비례해 단조 감소.
- 해석 2: 가장 약한 설정 r0.5-m무한도 **29.8%(앱 AI 대비 약 30:70)** — 설계 때 우려한 대로 약화 폭에 한계가 있다(평가식이 강하고, 확정 처치(`isHardOverride`)를 실수에서 뺐다). r0.3-m무한(33.0%)과 r0.5-m무한(29.8%)의 차이는 오차 안이라 **`rate`만 올려서는 P0/P1이 갈리지 않는다**.
- 인접 단계 후보(앱 AI 대비 승률 기준 **잠정**, 인접 직접 대전은 미측정): P3 앱 AI 50% · P2 탐색 끔(c1 45.2%) 또는 c7(39.9%) · P1 r0.3-m1~무한(33~34%) · P0 r0.5-m무한(29.8%). P1↔P0 격차(약 3~4%p)가 55% 기준에 모자라 **합치거나 다른 수단이 필요**하다.
- 아직 안 한 것(다음 세션 후보, 위에서 아래로 효과가 클 것으로 예상): (a) `rate` 0.7~1.0 확대, (b) **확정 처치 제외를 푼 변형**(`isHardOverride`도 실수 후보 — 코드 변경 필요, 작은 PR), (c) 3선출 `random`/`first`(`selectvs` 모드), (d) `riskAversion` 고정, (e) 인접 프로필끼리 직접 `h2h`(합격선 55~65% 판정은 앱 AI 대비가 아니라 **인접 쌍 직접 대전**으로).
- **S2 2차 측정 — `rate` 확대 · `hardOverride` (2026-10-20, 집 PC 16코어, 설정당 400판 · 6설정 약 1시간)**: 조건은 1차와 같다(A = c7 + 실수 모델, B = 앱 AI, `margin` 무한, 시드 1~200). PR #309로 `MistakeParams.hardOverride`(기본 false) 추가.

| 설정 | A 승 | B 승 | 무 | A 승률 (±95%) |
|---|---|---|---|---|
| r0.7 (확정 처치 제외) | 89 | 309 | 2 | 22.4% (±4.1) |
| r1.0 (확정 처치 제외) | 70 | 330 | 0 | 17.5% (±3.7) |
| r0.3 + hardOverride | 130 | 269 | 1 | 32.6% (±4.6) |
| r0.5 + hardOverride | 101 | 297 | 2 | 25.4% (±4.3) |
| r0.7 + hardOverride | 70 | 330 | 0 | 17.5% (±3.7) |
| r1.0 + hardOverride | 53 | 345 | 2 | **13.3%** (±3.3) |

- 해석: `rate`를 0.7~1.0으로 올리면 1차 바닥(29.8%)을 넘어 17~22%까지 내려간다. 확정 처치를 푼 `hardOverride`는 같은 `rate`에서 추가로 약해지는 폭이 작다(r0.5: 29.8→25.4, r1.0: 17.5→13.3). 앱 AI 대비 승률로 보면 후보 사다리는 P3 50% · P2 c1 45%/c7 40% · P1 r0.3 33% · r0.5 25~30% · P0 r1.0 13~17%로 **3~4단 이상이 갈린다**. 인접 직접 대전(h2h)과 `selectvs`·`riskAversion` 고정은 미측정.

- 기록 못 한 것: 선공·후공별 승률(시뮬레이터 h2h는 좌우 교대 합산만 출력). 합격선 판정 단계에서 필요하면 `scripts/battle-ai-sim.mjs` h2h에 선후공 집계를 추가한다.
- 재현 명령(저장소 루트, Git Bash, 25시드 조각을 `SEED_FROM`으로 나눠 병렬 합산): `OFF`=`{"statusAware":false,"setupAware":false,"phase3Aware":false,"a1Aware":false,"a2Aware":false,"trackMAware":false,"tier2Aware":false,"partyAware":false,"oppSwitchAware":false,"mySwitchAware":false}`에 `"mistake":{"rate":0.5,"margin":1e9}`를 합친 JSON을 A, `APP`(위 c8 명령의 `APP`)을 B로 `node scripts/battle-ai-sim.mjs h2h 200 "$A" "$APP"`.
