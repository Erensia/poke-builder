## 새 PC(집·회사)에서 처음 할 일

   `git log --oneline -5`에 PR #305 커밋(`a4b601c`, "랭크 30일 자동 초기화 … R1 ⓓ")과 그 뒤 docs 커밋들이 보여야 한다.

3. (선택) 엔진·AI 동작이 이 PC에서도 같은지 `bash docs/00_기획문서/02_backlog/05_ver.5.0/verify-kit/verify.sh`(약 3.5분, 아래 "검증 킷"). 전부 PASS여야 한다.

## 작업 규칙 (CLAUDE.md가 git에 있으니 그것이 우선, 요약)

- 브랜치 흐름 `dev` → 항목 브랜치 → PR(커밋 1개, squash) → `dev` → `main`(merge commit, PR 제목 `ver5.0`). 코드를 고칠 때만 적용.
  수정 요청이 오면 새 커밋을 얹지 말고 `git commit --amend` + `git push --force-with-lease`.
- 커밋 메시지는 한국어, 끝에 `Co-Authored-By`·`Claude-Session` 줄(해당 시). 기능 작업 중 발견한 버그는 그 기능 커밋에 같이.
- 머지 뒤: `git fetch` → `dev` 최신화 → feature 브랜치 **로컬·원격 모두 삭제**(`git branch -D` + `git push origin --delete`; `delete_branch_on_merge: false`).
- `docs/**`만 고치면 브랜치·PR 없이 `dev`에 바로 커밋·push. 코드(`scripts/` 포함)가 섞이면 PR.
- 코드는 `ponytail` 스킬로. 새 메이저 버전(5.0) 끝에는 **전체 리팩토링 → 엔진 로직 테스트·기능 테스트**.
- 브라우저가 필요한 확인(화면·모바일·드래그)은 사용자에게 위임 — 정확한 명령·체크리스트를 주고, 먼저 로컬 브랜치를 그 PR 브랜치로 전환해 둔다.
  `localStorage['champions-party-sim.party.v1']`(편집 중 파티)·`...party-presets.v1`은 지우거나 덮어쓰라고 안내하지 않는다. 랭크 확인용 콘솔 스니펫은 `champions-party-sim.battle-rank.v1`만 건드린다.
  네이티브 `confirm/prompt`를 쓰는 버튼(파티·슬롯 프리셋, 배틀비디오 모달)은 자동화로 누르지 않는다(코드 리뷰로 대체).
- (작업 PC 경험) PR 머지는 사용자가 GitHub에서 직접 Squash and merge 하고 "머지했어"라고 알려 준다 — 그 환경 권한 시스템이 `gh pr merge`를 거부했다. 이 PC에서 허용돼 있으면 확인 후 진행해도 된다.
- (Windows 작업 PC 경험) `python3`는 스토어 스텁이라 `python`(+`PYTHONUTF8=1`) 사용, 소스 파일 다수가 CRLF라 문자열 치환 전에 `\r\n`을 정규화했다.

## R3 랭크배틀용 AI — 시작 지점

### 요구(확정)
랭크배틀 전용 AI. 랭크별 성향·상대 샘플 차등을 포함한다. **경험치제 구간(몬스터볼~하이퍼볼)에는 연패 가중이 없는 대신, 연패가 반복되면 AI 수준을 낮추거나 상대 파티 조합을 일부러 쉽게 고르는 난이도 보정**을 둔다.
랭크 상태는 이미 `useRankBattle().save.state`(`gauge`·`rating`·`streak`·`lossStreak`·`champion`)와 `rankOf(state)`(볼·단계)로 읽을 수 있다.

### (설계 확정 전 메모 — 아래 두 절은 backlog가 우선) 사용자와 먼저 정할 것
1. 목표: 랭크가 오를수록 강해지는 곡선인지, 같은 강도에 연패 보정만 둘지.
2. 강해지는 수단: 성향(`riskAversion`) 분포 / 탐색 깊이·켜고 끄기 / 상대 모델·학습 / 강한 샘플 파티 선택.
3. 상대 파티: 샘플 파티에 강도 등급을 매겨 랭크·연패에 맞게 고를지.
4. 연패 보정: 몇 연패부터·몇 단계·연패가 끊기면 즉시 복구할지.
5. 검증 합격선: 기준 AI 대비 승률 몇 %로 "더 강해졌다 / 단계가 나뉜다"를 판단할지.

### 단순 시작안 (제안 — 미확정, 사용자가 안 정리해줘 하면 이걸로)
- **프리셋 3단**: 약 = 탐색 끔·상대 모델 끔·일부 `*Aware` 끔 / 중 = 탐색 끔(평가식만, 수십 ms) / 강 = 지금 앱 기본(`APP_DECISION_PARAMS` = 탐색 오라클 + 상대 모델). 몬스터볼=약, 슈퍼볼=약~중, 하이퍼볼=중, 마스터볼=강, 챔피언=강+상위 등급 파티.
- **샘플 35개 강도 등급**: `sim:ai`로 샘플끼리·기준 AI와 대결시켜 승률 순으로 상/중/하 등급(스크립트 신설) → 랭크별 상대 풀 가중.
- **연패 보정**: 연패 3 → 프리셋·파티 등급 한 단계 하향, 5 → 두 단계, 이기면 즉시 복구(경험치제 구간만).
- **검증**: `h2h` 모드로 프리셋 간 강약 순서와 격차 확인. 합격선은 사용자와 합의.

### AI 코드 지도 (`src/lib/battle/ai/`)
- 진입: `index.ts`(`chooseAiAction`·`chooseAiForcedSwitch`·`sampleRiskAversion`), 화면 호출 `aiClient.ts`(`chooseAiActionAsync`, Web Worker + 시간 한도, `APP_DECISION_PARAMS`).
- 판단: `evaluator.ts`(점수), `decision.ts`(`DecisionParams` — `*Aware` 토글·`threat*`·`party*` 가중, `DEFAULT_OPPONENT_MODEL`), `search.ts`(`SearchParams`·`PRODUCT_SEARCH_PARAMS`: 탐색 깊이·시드 수·`topK`·`budget`), `partyEval.ts`, `opponentMoveModel.ts`·`opponentMemory.ts`(상대 모델·학습), `teamSelect.ts`(3선출 `chooseAiSelection`).
- 호출 위치(`src/components/BattleLogPage.tsx`): AI 성향 뽑기 `setAiRiskAversion(sampleRiskAversion())`(대전 시작, ~320행), AI 선출 `aiSelectionFor`(~331행), 행동 `chooseAiActionAsync({... decisionParams: APP_DECISION_PARAMS})`(~551행). **랭크 모드는 `mode === "rank"`로 구분** — 랭크별 `decisionParams`·성향은 여기서 `useRankBattle().save.state`를 읽어 정하면 된다.
- 상대(샘플 파티) 선택: `src/hooks/useRankBattle.ts`의 `pickOpponent`(주석 `ponytail:` — R3에서 이 함수를 랭크·연패 기반으로 교체). 샘플 파티는 `src/data/samplePartyPresets.json`(35개, `style`·`group` 필드).
- 설계 문서: `docs/00_기획문서/03_battleAI_DEV/`(`ai-판단기준-요약.md`부터, 세부 `battle-ai-decision-layer.md` §번호).

### 시뮬·검증 도구
- `npm run sim:ai -- <mode> [판 수] [파라미터 JSON]` — 모드: `regress`(엔진 동작 해시) · `ai` · `greedy` · `h2h`(AI A 대 AI B, 파라미터 비교용) · `style` · `selectvs`(선출 A/B) · `diag`. 환경변수 `POOL=samples`(샘플 파티 풀) 등 — 스크립트 머리말 주석 참고(`scripts/battle-ai-sim.mjs`).
- `npm run test:ai`(시나리오), `npm run test:rank`(랭크 규칙), `npm run bench`(판정).
- **R3는 AI 판단을 바꾸므로 `regress`·`ai`·`greedy`·`h2h` 출력과 `test:ai` 기대가 바뀔 수 있다** — 의도한 변화인지 확인하고 `verify-kit/baseline/`을 다시 기록한다. 엔진(`src/lib/battle/`의 AI 밖)·`damageFormula`·역산은 건드리지 않는 것이 기본이라, `regress` 해시(엔진 동작)·`test:damage`·`test:inference` 결합 해시는 **R3 뒤에도 그대로**여야 한다.

### 검증 킷 (`verify-kit/`)
4.0 때 쓰던 통합 검증을 이 폴더로 옮겼다(원래는 작업 PC의 로컬 메모리 폴더에만 있었음). `bash docs/00_기획문서/02_backlog/05_ver.5.0/verify-kit/verify.sh`(저장소 루트 기준 자동). tsc·oxlint·build·`test:ai`·`test:damage`·`test:inference`(결합 해시 `10040ffa0108c9a3`)·`regress 200`(해시 `e029e39a…`)·`regress 20000`·계산 함수 차분 해시·그리디/스테이터스/h2h/ai 출력을 `baseline/`과 비교해 전부 PASS여야 한다. 실행 중 `verify-work/`가 생기는데 커밋하지 않는다(삭제).
**R3 작업에서는 AI 출력 항목(그리디·h2h·ai60·regress20000 전 턴 로그 해시 등)이 의도적으로 달라진다** — 엔진 해시(`regress 200`)·`test:damage`·`test:inference` 해시만 그대로면 엔진은 무변경이다.
