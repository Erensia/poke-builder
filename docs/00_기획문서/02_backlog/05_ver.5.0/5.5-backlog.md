### F1 앱 상대 AI가 샘플의 `fixedPicks`를 선출에 쓴다 — **완료**(2026-10-29, PR #345, `dev`)
- **결과**: `aiSelectionFor`가 `setup.fixedPicks.b`를 `buildableIndices` 풀 위치로 바꿔 `chooseAiSelection`의 `fixed`로 넘긴다(`BattleLogPage.tsx` 3줄). 랭크배틀·프런티어 상대도 `loadSample("b", ...)`로 들어와 샘플이면 같이 적용된다(착수 전 확인 ① 확정). 엔진·데이터 변경 없음, `tsc -b`·`oxlint`·`build`·`test:ai`·`validate:data`·`test:sample` 통과, 사용자 화면 확인 완료(`real-cycle-zard-y`).
- (아래는 확정 당시 계획)
- **문제**: 5.4 E3은 내 편 선출 화면만 `fixedPicks`와 연동했다. 앱의 상대 AI 선출(`BattleLogPage.tsx`의 `aiSelectionFor`)은 `chooseAiSelection(full, side, { size })`만 불러 `fixed`를 넘기지 않는다. 선출 AI(`teamSelect.ts`의 `fixed` 옵션)와 시뮬레이터·벤치(`selectvs`, `POOL=picks`)는 이미 `fixedPicks`를 쓰므로, 벤치로 잰 강도와 앱 안 상대의 선출이 어긋날 수 있다.
- **방향**: `setup.fixedPicks.b`(포켓몬 id)를 `buildableIndices("b")` 풀 안의 위치로 바꿔 `fixed`로 넘긴다. 기존 `fixedPickIndices`는 슬롯 인덱스를 돌려주지만 `chooseAiSelection`의 `fixed`는 풀 위치(파티 인덱스)를 기대하므로 **변환 기준을 맞춘다**(`aiSelectionFor`의 `pool[p]` 매핑과 같은 기준). 지정이 없거나 빠진 마리는 지금처럼 AI가 채운다(`fixed` 후보가 없으면 `chooseAiSelection`이 전체로 되돌아간다).
- **근거**: 5.2 M5에서 고정 선출 대 AI 선출이 316 : 284(52.7%, ±4%p라 구분 안 됨)로 작성자 선출이 약해지지는 않고, 후보 조합이 줄어 선출 계산이 약 3배 빠르다(고정 150ms · AI 481ms).
- **범위 결정(2026-10-29)**: 앱에는 3선출의 난이도 구분이 없고 `aiSelectionFor`는 한 경로다 → **샘플을 불러온 AI 상대는 항상 `fixedPicks`를 적용**한다(랜덤 구축 상대·`fixedPicks` 없는 샘플은 지금처럼 전부 AI 선출). 새 설정은 만들지 않는다.
- **착수 전 확인**: ① 랭크배틀·배틀 프런티어도 `handleProceed`를 거치는데 그 상대가 `loadSample` 경로로 들어와 `fixedPicks`가 붙는지(붙으면 상대 선출이 함께 바뀐다) ② 랭크 AI 단계별로 선출 계산을 달리 하는 설정이 있는지 ③ 상대 선출은 비공개라 화면 칩은 없다(5.4 E3 결정 그대로).
- **검증**: `tsc -b`·`oxlint`·`build`·`test:ai`·`sim:ai`(엔진 무변경 해시 `regress`), 화면 확인은 사용자에게 위임 — `fixedPicks`가 있는 샘플을 상대로 불러 대전을 시작한 뒤 상대 선출 3마리에 고정 마리가 모두 들어 있는지.

### G1 저장 데이터 백업/복원 + 영구 저장 요청 (2026-10-29 사용자 추가)
- **문제**: 파티·프리셋·내 샘플은 전부 브라우저 `localStorage`에만 있다(`src/lib/storage.ts`). 2026-10-29 크롬 캐시를 지우면서 저장해 둔 파티와 샘플이 모두 사라졌고 복구할 수 없다. 브라우저마다 저장소가 따로라 같은 데이터를 다른 브라우저에서 쓸 수도 없다. 지금 내보내기·가져오기는 "내 샘플"에만 있다(`SamplePartiesModal`, `mySamples.ts`의 `exportMySamples`·`parseMySamples`). 파티 프리셋·슬롯 프리셋에는 없다.
- **방향**: **A 통합 백업/복원 + B 영구 저장 요청**을 한 항목으로 한다(서버 없음, 의존성 추가 없음).
  - **A**: 아래 범위의 데이터를 JSON 한 파일로 내보내고 같은 파일을 가져와 복원한다. 파일 형식은 `kind`·`version`을 둔 단일 JSON(내 샘플 내보내기와 같은 방식). 가져오기는 **믿을 수 없는 입력**이므로 기존 검증(`cleanSlot`·`parseMySamples`)과 크기 상한(`MAX_IMPORT_BYTES`)을 재사용하고, 틀린 항목은 건너뛰고 몇 개를 건너뛰었는지 알려 준다.
  - **B**: `navigator.storage.persist()`를 요청해 용량 부족으로 인한 자동 삭제를 줄인다. 사용자가 직접 지우는 것까지 막는다는 보장은 없고 브라우저마다 동작이 다르므로 **A가 본체**이고 B는 보조다. 결과는 화면에 띄우지 않는다.
- **백업 범위(사용자 결정, 2026-10-29)**: ① 저장한 포켓몬 샘플 ② 저장한 파티. **이것만** 넣는다. 랭크·프런티어 기록, 대전 영상, AI 학습 기억, 작업 중 파티 자동저장은 넣지 않는다.
- **저장소 대응(착수 전 확인)**: 사용자가 말한 두 가지를 코드 저장소에 대응시키면 ② 저장한 파티 = `party-presets`(이름 붙인 파티), ① 저장한 포켓몬 샘플 = `slot-presets`(이름 붙인 포켓몬 빌드 1마리) 또는 `my-samples`(내 샘플 6마리 파티) 중 하나다. 어느 쪽인지 확정되기 전까지 **세 저장소를 모두** 범위에 둔다(셋 다 같은 모양의 목록이라 비용이 작다). 확정되면 불필요한 쪽을 뺀다.
- **미결정**: ① 가져오기 방식 — 기존 목록에 더하기(제안: id는 새로 매겨 충돌 방지, 이름 중복은 표시) vs 덮어쓰기 ② 버튼 위치 — 사이드 메뉴·각 모달·전용 설정 중 어디에 둘지 ③ 기존 내 샘플 내보내기·가져오기를 통합 버튼으로 옮길지, 모달의 버튼을 유지하고 통합 버튼을 더할지 ④ 백업을 잊지 않게 하는 안내(마지막 백업 시각 표시 등)를 넣을지.
- **원칙**: 새 UI는 기존 앱 스타일·CSS 변수에 맞추고 **호버에 의존하지 않는다**(모바일 터치 대응). 가져오기는 `party.v1`(작업 중 파티)을 건드리지 않고, 사용자에게 저장소를 지우거나 덮어쓰라고 안내하지 않는다.
- **검증**: `tsc -b`·`oxlint`·`build`·`test:ai`(`battle-ai-scenarios.mjs`의 V3 내보내기·가져오기 시나리오를 통합 형식으로 확장 — 왕복 동일성, 잘못된 파일 거부, 크기 상한)·`validate:data`. 화면 확인은 사용자에게 위임 — 내보내기 → 가져오기 왕복, 다른 브라우저에서 복원, 잘못된 파일 거부 메시지. 네이티브 `confirm/prompt`를 새로 쓰지 않는다.
