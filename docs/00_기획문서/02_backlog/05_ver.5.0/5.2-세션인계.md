회사 PC는 RAM 8GB(여유 약 1~2GB)라 측정처럼 메모리를 많이 쓰는 작업을 돌리면 백그라운드 명령이 메모리 부족으로 종료된다(5.0, 5.1 A2, 5.2 C1 단계 4에서 반복). **사용자 결정(2026-10-23): 모든 측정은 집 PC(i9·16코어·RAM 32GB)에서 한다.** 회사 PC는 코드·데이터·문서 작업과 가벼운 검증(`validate:data`·`test:ai`·`test:rank-ai`·`tsc -b`·`oxlint`·`build`)만 한다.
새 세션은 **아래 "시작 프롬프트"를 그대로 붙여 넣으면** 된다. 작업이 진행되면 "현재 상태"를 갱신하고 `docs:` 커밋으로 `dev`에 push한다(CLAUDE.md — 인계 문서는 편집 후 곧바로 커밋).

## 새 PC에서 처음 할 일

1. 클론이 없으면 `git clone https://github.com/Erensia/poke-builder.git`, 있으면 `git fetch origin` 후 `git checkout dev && git pull --ff-only origin dev`.
   `git log --oneline -5`에 `feat: 기초 샘플 파티 2개 추가 — 사이코·일렉트릭 필드, 기초샘플 18개·전체 53개 풀 (5.2 SP)`(`1a7194c`)·`feat: 기초 샘플 파티 6개 추가 — 기초샘플 16개·전체 51개 풀 (5.2 SP)`(`b27a912`)와 `feat: 샘플 45개 등급 갱신 — 249쌍 증분 측정과 등급 히스테리시스 (5.2 C1·C4) (#331)`(`5650dd0`)가 보여야 한다.
   **`git pull`은 측정을 시작하기 전에만 한다.** 측정이 도는 동안에는 `pull`·`checkout`·`merge`로 `src/`를 바꾸지 않는다 — 측정 프로세스가 `src/lib`·`src/data`를 읽으므로 도중에 바뀌면 결과가 섞인다.
2. `npm install` → `npx tsc -b` · `npx oxlint` · `npm run validate:data` · `npm run test:rank-ai`가 통과하는지 확인(Node 22+ 권장).
3. 측정 전 체크: 여유 메모리(12병렬 ≈ 5.4GB), 개발 서버(`npm run dev`)·무거운 앱 종료, `git status`가 깨끗한지(`scripts/sample-party-pairs.json`에 이전 측정의 미커밋 수정이 없어야 한다).

## 작업 규칙 (CLAUDE.md가 우선, 요약)

- 브랜치 흐름 `dev` → 항목 브랜치 → PR(커밋 1개, squash) → `dev` → `main`(merge commit, PR 제목 `ver5.2`). **코드를 고칠 때만** 적용. `docs/**`만 고치면 브랜치·PR 없이 `dev`에 바로 커밋·push.
- 커밋 메시지는 한국어. 수정 요청이 오면 새 커밋을 얹지 말고 `git commit --amend` + `git push --force-with-lease`. `git add`는 **파일을 지정**한다. PowerShell에서 `git commit -F -`로 파이프하면 제목 앞에 BOM이 붙으니 메시지를 파일로 쓰고 `-F <파일>`을 쓴다.
- PR은 사용자 승인 뒤 `gh pr merge <번호> --squash`로 머지하고, **정리(`git branch -D` + `git push origin --delete`)는 반드시 `gh pr view <번호> --json state`가 `MERGED`일 때만** 한다.
- 샘플 파티 추가(SP): `dev`에 커밋·push. `dev`가 `main`보다 앞서 있으면(미배포 작업이 쌓인 동안) **`dev`에만** 반영하고 `main`은 `ver5.2` 릴리스 때 함께 나간다. 지금도 `main..dev`에 #331·기초샘플 8개·문서가 있다.
- 측정 중에는 `src/`를 수정하지 않는다. 메모리 부족으로 백그라운드가 종료되면 다시 시작하지 말고 사용자에게 보고한다.
- 브라우저가 필요한 확인은 사용자에게 위임한다. `champions-party-sim.party.v1`·`...party-presets.v1`을 지우거나 덮어쓰라고 안내하지 않는다.

## 집 PC 측정 순서

**의존**: M2·M3은 등급 풀(`samplePartyTiers.json`)로 상대를 고르므로 **M1이 끝나 등급이 확정된 뒤에** 잰다. M4·M5는 등급과 무관하다(PR #332가 `dev`에 머지된 뒤에 M5). 측정은 CPU·메모리를 나눠 쓰니 동시에 돌리지 않는다.

### M1 기초샘플 8개 등급 증분 측정 (C1)
```
node scripts/rank-party-tiers.mjs 10 --jobs 14 --new tb-mega-offense,tb-sword-dance,tb-malice-cycle,tb-counter,tb-mega-balance,tb-grassy,tb-psychic-field,tb-electric-field --write > tiers.out
```
- 한 줄로 입력한다(bash의 `\` 줄 이음은 PowerShell에서 깨진다). `tiers.out`은 저장소 루트에 생기는 출력 파일이니 **커밋하지 않는다**(`git add`는 파일 지정).
- 시작 로그에 `측정할 쌍 388개 (전체 1378쌍, 저장된 표 990쌍)`가 나와야 한다. 7,760판 — 12코어 실측 약 1.65판/초면 약 1시간 20분, 16코어는 더 빠르다. 조각(20쌍)마다 저장되니 중단돼도 같은 명령으로 이어진다(시드·AI 파라미터는 표와 같아야 한다).
- `--new`는 이번에 처음 재는 기초 8개만 적는다(심화 20~25는 #331에서 확정됐다). 마진은 판수에서 ±2SE로 계산된다(`tiers.out` 첫 줄).
- 끝나면 `tiers.out`의 `(유지 — 순수 3등분이면 …)` 줄과 신규 8개 등급을 확인하고 `npm run test:rank-ai`·`npm run validate:data`. `samplePartyTiers.json`에서 값이 바뀐 키가 신규 8개와 `유지`로 표시된 이동뿐인지 `git diff`로 본다.
- 브랜치 `feat/5.2-tb-tiers` → 승률표·등급 파일만 커밋 → PR(커밋 1개).

### M2 몬스터볼 랜덤 구축 상대 약화 (C3)
- 현재 `src/lib/battle/ai/rankProfile.ts`의 `RANDOM_RATE.monster`가 1이고 하등급 샘플보다 약 6%p 강하다(5.1 A3: 하 56.3% · 중 50.0% · 상 52.9%). 제안은 `1 → 0.7`.
- 재측정은 `5.1-backlog.md` A3 절의 재현 명령(`RANDOM_TIER=하|중|상 PAIRS="<등급 샘플 인덱스>-0,…" node scripts/battle-ai-sim.mjs partyvs 30 '{}'`, 등급별로 `qWins/(pWins+qWins)` 합산)을 **M1 이후의 등급 표 기준으로** 한다. 수용 기준(몬스터볼이 하등급 샘플과 몇 %p 안인가)은 측정 전에 사용자와 정한다.

### M3 A4 사다리 재측정 (C2)
```
node scripts/rank-ladder.mjs 200 --jobs 14
```
- 러너는 PR #334(`rank-ladder.mjs`, 시뮬레이터 `rank:N` 파라미터)다. 기본 단계 0,1,2,3,6(몬스터·슈퍼·하이퍼·마스터볼 4·마스터볼 1=앱 AI) 인접 4쌍 × 쌍당 200시드(400판)를 샘플 풀에서 재고, 쌍별 승률(무승부 제외)·55~65% 합격 여부·단조 증가 여부를 출력한다. 회사 PC 스모크: 단일 프로세스로 앱 AI 쌍이 판당 약 3.5초라 집 PC 14병렬이면 전체가 10~15분 안팎일 것으로 본다(추정).
- 5.1 A4 값(P1/P0 82.0%·P2/P1 67.0%·P3/P2 61.8%·P4/P3 62.7%)과 비교한다. 단, A4의 단계 정의(5.0 결론의 5단 JSON)와 이 러너의 `RANK_AI_PROFILES`가 정확히 같은지는 확인하지 못했으니 숫자가 조금 다를 수 있다. 학습 단계(3~5)의 λ는 `LEARN=1`+대전 간 누적이 필요해 이 러너는 재지 않는다. 풀이 53개이고 상 풀이 18개 이상으로 커졌다는 점을 같이 본다.
- 선택 항목이다. M1·M2 결과를 보고 할지 정한다.

### M5 고정 선출 대 AI 선출 (C5-B)
```
npm run bench -- toggle '{}' --on '{"kind":"fixed"}' --greedy 0 --status 0 --h2h 0 --select 150 --pool picks --jobs 14
```
- A = 작성자 고정 선출(`fixedPicks`를 포함한 조합에서 AI가 나머지를 고름), B = AI 선출(`{}`). 풀은 `fixedPicks`가 있는 샘플 8곳뿐이라 대진이 같은 쌍의 반복이다. 600판 오차는 약 ±4%p이니 A가 B보다 앞서는지·비슷한지만 본다(작성자 선출이 AI 선출보다 약하면 AI 선출 판단이 낫다는 뜻).
- 결과(`aWins`·`bWins`·`selectMsA/B`)를 `5.2-backlog.md` C5에 기록한다.

## 회사 PC에서 이어갈 수 있는 작업

- 선출 미리 채우기 앱 기능(샘플을 불러오면 선출 화면에 `fixedPicks`를 미리 표시, AI 상대일 때 작성자 선출 사용)은 별도 UI가 필요해 보류 중이다(`5.2-backlog.md` C5). 사용자가 원하면 설계부터.
- 샘플 txt가 오면 SP: `node scripts/add-sample.mjs <txt> --id <id> --style <성향> [--name --desc] [--fix] [--dry]`로 변환·검증·임시 등급·README 샘플 수까지 처리한다. 오타는 제안만 하고 `--fix`일 때 후보가 하나뿐인 것만 교정한다. 이름·성향·설명은 사람이 정하고, 이력 문구("5.2에서 …개 추가")와 백로그 SP 기록은 손으로 고친다. `npm run test:sample`로 스크립트를 검증한다.
- "5.2 마무리" 절(`5.2-backlog.md`)은 초안이다. 집 PC 측정이 끝나면 [ ] 칸을 채워 릴리스 때 쓴다.
- 위 어디서든 문서·백로그 정리, 가벼운 검증.
- 측정(M1~M4)과 `npm run bench`·`sim:ai` 대량 실행은 하지 않는다.

## 알아 둘 것

- 회사 PC에서 50쌍 조각(프로세스 1개, 힙 512MB, 낮은 우선순위)은 약 22분이고 1회 종료를 겪었다. 기록은 `5.1-A2-측정로그.md`와 `5.2-backlog.md` C1.
- `.git/index.lock`이 0바이트로 남으면 git·Obsidian 프로세스가 없는지 확인한 뒤 지운다(5.2 C1에서 한 번 발생).
- Git Bash가 간헐적으로 `add_item ... failed`로 죽으면 PowerShell로 같은 명령을 실행한다.
- **Windows PowerShell 5.1은 인자 안의 큰따옴표를 벗긴다.** JSON 인자는 `'{\"kind\":\"fixed\"}'`처럼 `\"`로 이스케이프하거나(`'{}'`는 그대로) Git Bash에서 실행한다. 위 M4·M5 명령은 bash 기준 표기다.
