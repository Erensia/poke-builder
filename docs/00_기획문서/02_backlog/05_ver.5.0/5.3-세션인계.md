1. `git fetch origin` 후 `git switch dev && git merge --ff-only origin/dev`. `git log --oneline -5`에 `data: 샘플 26~30 승률 쌍 275개 측정 결과 추가 — 표 1,653쌍(58개 전수) (5.3 D3) (#340)`(`767fc98`)와 `feat: 등급 측정의 새 파티 자동 판별 — 표 파일 tiered 기록 (5.3 D5) (#339)`(`63fd2cc`)·`feat: 샘플 파티 27 추가와 픽시 학습셋 달빛 보정 — 전체 58개 풀 (5.3 D1) (#338)`(`3b5a98e`)가 보여야 한다.
   **`git pull`은 측정을 시작하기 전에만 한다.** 측정이 도는 동안에는 `pull`·`checkout`·`merge`로 `src/`를 바꾸지 않는다.
2. `npm install` → `npx tsc -b` · `npx oxlint` · `npm run validate:data` · `npm run test:rank-ai`가 통과하는지 확인.
3. 측정 전 체크: 여유 메모리, 개발 서버·무거운 앱 종료, `git status`가 깨끗한지.

## 작업 규칙 (CLAUDE.md가 우선, 요약)

- 브랜치 흐름 `dev` → 항목 브랜치 → PR(커밋 1개, squash) → `dev` → `main`(merge commit, PR 제목 `ver5.3`). **코드·데이터를 고칠 때만** 적용. `docs/**`만 고치면 브랜치·PR 없이 `dev`에 바로 커밋·push.
- 커밋 메시지는 한국어. 수정 요청이 오면 새 커밋을 얹지 말고 `git commit --amend` + `git push --force-with-lease`. `git add`는 **파일을 지정**한다. PowerShell에서 `git commit -F -` 파이프는 BOM이 붙으니 메시지를 파일로 쓰고 `-F <파일>`.
- PR 머지 뒤 정리(`git branch -D` + `git push origin --delete`)는 `gh pr view <번호> --json state`가 `MERGED`일 때만 한다.
- **`main`보다 앞서 있는지는 `git fetch` 뒤 `origin/main..origin/dev`로 센다**(로컬 `main`은 오래돼 있다 — 5.2 릴리스 뒤 25커밋 앞선 것으로 오판한 적 있음). 지금 `origin/main..origin/dev`에는 5.3 작업(#338·#339·#340 등)이 쌓여 있어 **새 샘플 추가는 `dev`에만** 반영하고 `main`은 `ver5.3` 릴리스 때 함께 나간다. (샘플 추가만 있을 때는 사용자가 `main` 머지까지 허용했다 — 2026-10-26.)
- 측정 명령은 시드 수 `10`을 먼저 적는다(`--jobs 1`처럼 숫자 옵션만 쓰면 시드 수로 읽혀 "저장된 표는 시드 10…" 오류). 측정 중에는 `src/`를 수정하지 않는다. 메모리 부족으로 백그라운드가 종료되면 다시 시작하지 말고 보고.
- `.git/index.lock`이 0바이트로 남으면(Obsidian 실행 중) git 프로세스가 없는지 확인하고 지운다. 작업 복사본의 JSON은 CRLF(index는 LF)다.
- 브라우저가 필요한 확인은 사용자에게 위임. `champions-party-sim.party.v1`·`...party-presets.v1`을 지우거나 덮어쓰라고 안내하지 않는다.
