2026-10-22 오후, 퇴근(17:30) 전에 회사 PC에서 **프로세스 1개**로 단계를 늘려 가며 측정한 기록이다. 쌍은 순서대로(`rank-party-tiers.mjs`와 같은 `i<j` 순) 재고, 단계가 끝날 때마다 표를 `wip/a2-pairs` 브랜치에 저장하고 이 문서에 쓴다. 전체는 **샘플 39개 = 741쌍**(쌍당 시드 10 = 20판, 총 14,820판, 탐색 끈 기본 AI `{}`).

## 집 PC에서 이어하기

1. `git fetch origin && git checkout dev && git pull --ff-only origin dev` (측정 시작 **전에만**).
2. 부분 표를 가져온다(작업 트리에만, 스테이징 없이): `git restore --source=origin/wip/a2-pairs --worktree -- scripts/sample-party-pairs.json` → 아래 "저장된 쌍"의 쌍 수가 들어 있어야 한다(`grep -c '|' scripts/sample-party-pairs.json`).
3. 남은 쌍만 측정: `node scripts/rank-party-tiers.mjs 10 --jobs 12 > tiers.out` (표에 있는 쌍은 건너뛴다. 시드·`--params`가 표와 다르면 거부된다). 이후 순서는 `5.1-세션인계.md`의 "1. A2 데이터 측정".
4. 끝난 뒤 `wip/a2-pairs` 브랜치는 로컬·원격 모두 삭제한다.

- **결정성 확인(단계 1 뒤)**: 처음 2쌍(`real-sand-tar|real-sun-zard`, `real-rain-pelipper|real-sun-zard`)을 새 프로세스로 다시 재면 표와 **완전히 같다**(승패·a편 승 모두). 조각 크기와 무관하게 결과가 같다는 뜻이다.
- **판단(단계 1)**: 메모리는 힙 상한 안에서 안정적이고 결과 품질도 정상이라 단계 2(100쌍)로 올렸다. 속도는 예상(1.0초/판)보다 느렸는데 사용자 작업과 CPU를 나눠 쓴 영향으로 본다. 조각을 키워도 시작 비용(약 9초)이 조각당 2% 미만이라 속도 이득은 거의 없고, 크기를 정하는 기준은 메모리 안정성과 중단 때 잃는 양이다.

- **판단(단계 2)**: 시간·메모리·품질 모두 단계 1과 같은 수준으로 일정(1.40초/판, 메모리 누수 없음, a편 승률 49.7%, 무승부 0.3%)해서 단계 3으로 올렸다. 단계 3은 남은 시간(17:10까지 약 62분)에 맞춰 150쌍 대신 **120쌍**(2,400판, 예상 56~60분)으로 정했다. 시스템 여유 최저가 190~220MB로 계속 빠듯하니 사용자 앱을 줄이면 더 안전하다.

- **단계 3 중단(16:08 시작 → 약 4분 뒤 16:11 종료)**: 시스템 메모리 부족으로 Claude Code가 백그라운드 명령을 종료했다(`reaper`). 그 시각 사용자 앱(`streem` 629MB·Chrome 474MB·**Obsidian 371MB, 15:41 시작**)이 떠 있어 프로세스 없이도 여유가 약 950MB였고, 측정 프로세스(약 600MB)가 더해지면 여유가 300MB 아래로 내려갔다. 단계 3은 결과가 저장되기 전에 끊겨 **표는 150쌍 그대로**이고 잃은 것은 약 4분이다. 지시대로 다시 시작하지 않았다.
- **교훈**: 이 PC에서 프로세스 1개(최대 약 600MB)는 여유 메모리가 약 1GB 아래일 때 위험하다. 단계 1·2는 사용자 앱이 적을 때(여유 최저 191~221MB까지 내려가도 종료되지 않음) 버텼으나, 앱이 더 늘어난 순간 종료됐다. 조각이 클수록 한 번 종료될 때 잃는 양이 커지므로(120쌍 = 약 56분), 이 PC에서 다시 한다면 **30~50쌍 조각**이 적절하다.
- **최종 상태(2026-10-22 17:10, 회사 PC 작업 종료)**: 저장된 쌍 **250 / 741**(33.7%), 남은 쌍 **491**(9,820판). `wip/a2-pairs`에 250쌍 표가 있다. 집 PC 12코어(5.0 실측 약 1.65판/초)로는 남은 분량에 **약 1.7시간**(코어가 더 많거나 빠르면 그만큼 줄어든다). 단계 5는 17:30 전에 끝낼 수 없어 시작하지 않았다.
- **이 PC 로컬 상태**: 작업 트리에 추적되지 않는 `scripts/sample-party-pairs.json`(250쌍)이 남아 있다 — 커밋하지 않는다(`git add`는 파일 지정). 측정 프로세스는 모두 종료했고 실행 중인 것은 없다.
- 참고: `git status`에 `docs/데이터변경이력.md`·`docs/00_기획문서/02_backlog/04_ver.4.0/README.md`가 수정된 것으로 보이나 내용은 HEAD와 같다(diff 없음). 문서 폴더를 연 Obsidian이 다시 저장한 줄바꿈·수정 시각 차이로 보이며 커밋하지 않는다.

- **판단(단계 3 재시도)**: 사용자가 "50쌍씩 단계별로 더"를 요청해 Obsidian이 닫혀 여유가 1.8GB로 회복된 16:23에 50쌍으로 다시 시작했다. 시간(1.37초/판)·품질(a편 49.0%)은 일정하고 메모리는 완만히 늘었지만(+2.7MB/분) 힙 상한 안이다. 17:10까지 남은 시간에 맞춰 단계 4도 50쌍(예상 22~25분)으로 갔다.
