# ver.5.0 코드 전체 리팩토링 설계 (2026-10-21 작성 · **2026-10-22 실행 완료** — 결과는 `5.0-backlog.md` "리팩토링 결과")

CLAUDE.md 규칙: 버전의 앞자리가 바뀌는 업데이트(4.x → 5.0)가 끝나면 `ponytail` 스킬로 코드 전체 리팩토링 → **엔진 로직 테스트 → 기능 테스트**. 4.0 때의 방식(`../04_ver.4.0/4.0-backlog.md` "전체 리팩토링")을 그대로 잇는다. 이 문서는 **설계만**이고 코드는 바꾸지 않았다.

## 1. 원칙
- **동작 불변**: 리팩토링 PR은 화면·엔진·AI 동작을 바꾸지 않는다. 해시·출력이 기준값과 같아야 통과.
- `ponytail`: 삭제 > 재사용 > 표준 > 최소 코드. 추상화를 더하는 리팩토링은 하지 않는다(중복 제거·분할·삭제만).
- 기능 작업이 **전부 끝난 시점의 `dev`** 기준으로 시작한다(4.0과 같은 순서 — 아래 3번).
- 4.0 "제외 확정"(칩/알약 9종 공용화 · 리팩토링 잔여 한계 · 배틀비디오 비율 표기 등)과 `4.1-backlog.md`의 제외 목록은 **그대로 승계**하고 재론하지 않는다.

## 2. 현황 (2026-10-21, 5.0 `dev` = `cbe23d4`)
- 규모: `src` ts/tsx 약 39,990줄, `scripts` 약 5,980줄. 5.0이 만든 변화는 32개 파일 +1,654 / −100줄(4.1 종료 대비).
- 큰 파일: `mirroredEffects.ts` 1,789 · `DefenseInferencePanel.tsx` 1,506 · `ai/evaluator.ts` 1,434 · `preHitEffects.ts` 1,288 · `matchupEvaluator.ts` 1,165 · `state.ts` 1,150 · `hitResolution.ts` 1,135 · `resolveAction.ts` 1,075 · `ActionEffectLines.tsx` 1,015 · `finishTurn.ts` 1,004 · `BattleLogPage.tsx` 997. 대부분 4.0에서 거대 함수를 단계로 쪼갠 뒤의 파일이라 **파일 크기보다 함수 크기**로 본다.
- 파일 밖에서 안 쓰이는 `export`: **7개**(전부 타입). 4.0에서 91개를 정리한 뒤라 거의 없다 — 효용 낮음.
- 5.0 기준값은 이미 고정돼 있다: `bash docs/00_기획문서/02_backlog/05_ver.5.0/verify-kit/verify.sh`가 14항목 전부 PASS(AI 출력·엔진 해시가 4.0 기준과 동일 — 앱 AI 경로를 안 바꿨기 때문). 따라서 기준 재기록은 필요 없고 `baseline/`을 그대로 쓴다.

## 3. 순서
1. (선행) 사용자 브라우저 일괄 검증(#311~#315 미확인분·모바일 폭) → 문제 수정 PR → 5.0 마무리 한계 정리(`5.0-backlog.md` "5.0 마무리" 갱신).
2. `main` 머지 직전 브랜치 `ver5.0-final`을 `dev`에서 분기(4.0과 같다). 이 브랜치에서 낸 PR이 마지막 PR이고, 항목마다 PR 1개(커밋 1개, squash).
3. **`ponytail-audit`를 다시 돌려** 최신 수치를 받고 사용자가 범위를 고른다(아래 4번이 후보 초안).
4. 항목별 리팩토링 PR → 각 PR마다 5번 검증 세트 전부 통과.
5. 엔진 로직 테스트(검증 세트) → **기능 테스트**(사용자 화면 확인: 배틀타워·랭크배틀·프런티어·역산·스피드 조정·모바일 폭).
6. `dev` → `main` PR 제목 `ver5.0`(merge commit). 머지 뒤 Vercel Production 배포 sha 확인(4.0 때 누락 전력).

## 6. 화면 확인(사용자 위임) — 기능 테스트 체크리스트 초안
- 배틀타워: 파티 편성 → 선출 → 대전 → 결과, AI 상대, 학습 칩 `🧠 AI 학습 N판`
