# ver.6.0 코드 전체 리팩토링 설계 (2026-10-29 작성 · **설계만, 코드는 아직 바꾸지 않았다**)

CLAUDE.md 규칙: 버전의 앞자리가 바뀌는 업데이트(5.x → 6.0)가 끝나면 `ponytail` 스킬로 코드 전체 리팩토링 → **엔진 로직 테스트 → 기능 테스트**. 5.0 때의 방식(`../05_ver.5.0/5.0-리팩토링설계.md`)을 그대로 잇는다. 6.0의 기능 작업(K1~K3, 클라우드 동기화)은 모두 끝났고 `dev`에 있다.

## 1. 원칙
- **동작 불변**: 리팩토링 PR은 화면·엔진·AI·동기화 동작을 바꾸지 않는다. 해시·출력이 기준값과 같아야 통과.
- `ponytail`: 삭제 > 재사용 > 표준 > 최소 코드. 추상화를 더하는 리팩토링은 하지 않는다(중복 제거·분할·삭제만).
- 기능 작업이 **전부 끝난 시점의 `dev`** 기준으로 시작한다. 항목마다 브랜치 → PR 1개(커밋 1개) → `dev` squash.
- 4.0·5.0의 "제외 확정"(칩/알약 9종 공용화, 4.0 잔여 한계 등)은 **그대로 승계**하고 재론하지 않는다.

## 2. 현황 (2026-10-29, `dev` = `f1d0604`) — `ponytail-audit` 실측
- 규모: `src` 41,021줄(5.0 설계 때 39,990줄, +1,031) · `scripts` 6,548줄(+568) · 파일 193개. 의존성은 `react`·`react-dom`·`firebase`(지연 로딩) 셋뿐이라 **뺄 의존성 없음**.

- 120줄 넘는 함수·컴포넌트: `ActionEffectLines` 997 · `BattleBoard` 720(안의 익명 함수 510·235) · `useBattleLogSession` 578 · `MatchupSlotCard` 393 · `ActionMainLine` 384 · `useDefenseInferenceState` 310 · `applyEffectMove` 276 · `BattleSetupCard` 251 · `PartySlotCard` 234 · `defineAbilityHitEffect` 235 · `collectResult` 234 · `triggerAbilityHitEffect` 232.

- **솔직한 결론**: 진짜 삭제로 줄어드는 양은 약 50줄뿐이다. 나머지는 큰 컴포넌트·훅을 나누는 **이동**이라 줄 수는 그대로이고 가치는 읽기 쉬움뿐이다. 4.0에서 거대 함수를 이미 쪼갠 뒤라 5.0 때보다 효용이 더 낮다.

## 4. 순서
1. 집 PC 첫 로그인 확인(순서서 "1-5b")과 기능 테스트 일부. 문제가 나오면 6.1로 넘길지 6.0에서 고칠지 그때 정한다.
2. 범위를 정한다(위 표). 항목마다 PR 1개.
3. 각 PR마다 5번 검증 세트 통과 → 마지막에 기능 테스트(6번).
4. `dev` → `main` PR 제목 `ver6.0`(merge commit). 머지 뒤 Vercel Production 배포 sha가 `main`인지 확인.

## 5. 검증 세트 (PR마다)
- **R-1처럼 엔진을 안 건드리는 PR**: `npx tsc -b` · `npx oxlint` · `npm run build` · `npm run test:ai` · `npm run test:sync` · `npm run test:rules`(Java 21 이상). 이 PC에서 가능.
- **엔진·AI 경로를 건드릴 수 있는 PR(R-2~R-6)**: 위에 더해 `bash docs/00_기획문서/02_backlog/05_ver.5.0/verify-kit/verify.sh`(14항목: AI 출력·엔진 해시·계산 함수 차분 해시 등, 약 3.5분). 기준(`baseline/`)은 5.0 그대로 쓴다 — 6.0은 엔진을 바꾸지 않았다. 랭크 코드를 건드리면 `test:rank`·`test:rank-ai`도.
- **`verify.sh`는 노드 프로세스 10개를 동시에 돌려 이 PC(RAM 7.7GB, 여유 약 0.5GB)에서는 메모리 부족으로 종료될 수 있다.** 집 PC에서 돌린다(5.x 측정 정책과 같다). 종료되면 다시 시작하지 말고 보고한다.
- 결과 파일이 달라지면 **리팩토링 버그**로 보고 원인부터 찾는다(기준을 고치지 않는다). `verify-work/`는 커밋하지 않고 삭제.

## 6. 기능 테스트(사용자 화면 확인) 체크리스트 초안
- **클라우드 동기화(6.0)**: 집 PC 첫 로그인(백업 파일 저장 → 주 계정 로그인 → 올라감) → 회사 PC 로그인(받아 옴) → 파티 저장 후 다른 기기에서 "지금 동기화" → 로그아웃 후 목록 유지
- 배틀타워: 파티 편성 → 선출 → 대전 → 결과, AI 상대, `🧠 AI 학습 N판`
- 랭크배틀: 시작 → 대전 → 이력·게이지 · 배틀 프런티어: 연승·상대 고정
- 역산·스피드 조정·매치업 탭 한 바퀴, 모바일 폭(약 390px)에서 백업 모달·랭크 프로필
- 네이티브 `confirm/prompt`를 쓰는 버튼(파티·슬롯 프리셋, 배틀비디오)은 자동화로 누르지 않고 코드 리뷰로 대체. `champions-party-sim.party.v1`·`party-presets.v1`은 지우거나 덮어쓰라고 안내하지 않는다.
