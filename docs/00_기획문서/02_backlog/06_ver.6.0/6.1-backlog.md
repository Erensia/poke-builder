# ver.6.1 백로그

**작성 중**(2026-10-29) — 집 PC 확인에서 문제가 없어 **B(리팩토링 버전)로 확정**했다. 할 항목(L1~L5 중 무엇을 할지)은 사용자가 고른다. 6.0(`6.0-backlog.md`, 릴리스 PR `ver6.0`)은 클라우드 백업(K)만 담았다. 이전 버전: `6.0-backlog.md`("6.0 마무리"에 한계 전체).

6.1은 마이너 버전이라 **전체 리팩토링은 하지 않는다**(아래 R-2~R-6은 고른 항목만). 항목별 브랜치 → PR 1개(커밋 1개) → `dev` squash, 마지막에 `dev` → `main` PR 제목 `ver6.1`(merge commit). 측정·엔진 전체 검증(`verify.sh`)은 **집 PC**.

## 출발 상태 (2026-10-29)
- `dev` == `main` (`ver6.0` 릴리스 후). 엔진·AI·데이터는 5.5와 같다. 샘플 58개.
- 이후 `dev`에만: PR #353 `npm audit` high 취약점 7건 해결(vite 8.3.5, source-map-js 1.2.2, `overrides`로 `@grpc/grpc-js` ^1.14.6 — firebase 13.1.0 최신판도 `~1.9`에 묶여 있어서). `main`에는 `ver6.1` 때 함께 나간다.

## 분기 — 집 PC 확인 결과: **문제 없음 → B**
확인 절차는 `6.0-backlog.md` "집 PC 첫 로그인 절차"와 집 PC용 순서서(`firebase-환경설정-순서서.md.local`, git 밖).

- **결과(2026-10-29, 사용자)**: 로컬(`localhost`)과 웹(Production) 양쪽에서 동기화에 문제가 없었다. 6.0 미수정 한계 중 "집 PC 실사용 확인 전"과 "Production 주소 로그인 미확인"은 이것으로 해소됐다. 모바일 폭 확인 여부는 따로 듣지 못했다.
- A(수정 버전, L0)는 하지 않는다. 6.1은 **B — 리팩토링 버전**으로 아래 L1~L5 중 사용자가 고른 만큼 한다.
