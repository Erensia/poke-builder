## ①-2 결정 대기

### C4 항목 단위 병합 (보류 권장)
현재는 **목록 단위** — 양쪽이 바뀌면 "클라우드 내용으로 바꾸기 / 이 기기 내용으로 올리기"를 고른다. 항목 단위로 합치려면 필요한 것:
1. 항목마다 `updatedAt`(현재 이름 변경은 `savedAt`을 바꾸지 않는다) — 목록 JSON 형식이 바뀌어 기존 클라우드 데이터 마이그레이션과 키 순서 재고정이 필요하다.
2. 삭제 표시(tombstone) `{id, deletedAt}` — 없으면 "다른 기기에서 지운 것"과 "내가 새로 만든 것"을 구분하지 못한다. 쌓이는 표시를 정리하는 규칙도 필요하다.
3. 병합 규칙 — 같은 id를 양쪽에서 수정했을 때(최신 우선), 한쪽 삭제·한쪽 수정일 때의 정책.
4. `firestore.rules`의 필드 모양·크기 검증 수정과 콘솔 재게시, `test:sync`·`test:rules` 대폭 확장.
- 얻는 것: 두 기기에서 따로 추가한 항목이 한쪽에 의해 대체되는 일이 사라지고 충돌 선택 창이 거의 안 뜬다. 지금도 확인 창이 있어 데이터를 **모르는 새 잃지는 않는다**. C1(충돌 알림)으로 놓치는 문제가 풀리면 효용이 더 줄어든다.

### G1 앱의 3선출 난이도 구분
- 지금 랭크 AI 단계(몬스터·슈퍼·하이퍼·마스터볼 4~1·챔피언)는 **실수율·탐색 끄기 / 학습 사용률 λ / 상대 파티 등급** 세 가지로만 갈리고, **선출은 모든 단계가 최선**이다(`chooseAiSelection`에 단계 파라미터를 안 넘기고 온도 0.05). 샘플 상대는 `fixedPicks`(사람이 고른 선출)까지 항상 쓴다.
- 영향 크기 근거: AI 선출 대 무작위 3마리가 600판 62.3%(2.2 B5 기준값). 즉 선출 하나가 승률 약 12%p. 이미 실수율로 약해진 P0~P1에서는 영향이 작고, 사다리 인접 격차가 합격선을 넘는 구간(P1/P0 79.6%·P2/P1 70.5%·P3/P2 70.7%)의 **간격을 줄이는 미세 조정 수단**으로 쓸 만하다. 수치는 아직 없다 — 5.1~5.4에서 `selectvs` 약화 조건이 계속 미측정이다.
- AI 작업이라 G3 측정 결과가 먼저 필요하다.

### G2 선출 화면 컬럼 폭
5.4 E3에서 **큰 문제는 해결**했다(안내 줄 제거 → 칩, 컬럼을 `max-content`로). 남은 것은 한쪽에만 긴 이름이 있을 때 좌우 컬럼 폭이 **조금** 다른 것뿐이다(같은 폭으로 맞추려면 grid 구조 변경). 외형만의 문제라 **삭제 후보**.
