# 6.3 G4 — 챔피언 AI 강화 설계 (초안, 2026-10-30)

상태: **설계 초안 — 실험 순서·허용 범위는 사용자 확정 대기.** 코드는 아직 없다. 6.3 백로그 G4의 "별도 설계가 필요하다, 설계 문서부터"를 이 문서로 시작한다.
이전 시도(5.0 R3 "앱 AI보다 강한 수단 탐색")는 모두 폐기됐다. 이번에는 **같은 계산을 더 많이 하는 방향을 버리고** 폐기 원인에서 병목을 다시 찾는다.

## 1. 목표와 합격 기준

챔피언(마스터볼 레이팅 2500 이상)이 지금은 마스터볼 1과 같은 AI(앱 AI)이고, 차별은 최상 파티 풀뿐이다. 앱 AI보다 **실제로 강한** 단계를 만든다.

| 기준 | 값 |
|---|---|
| 강도 | 챔피언 후보 대 앱 AI `h2h` **55% 이상**, 400판 이상(z ≥ 1.6). 사다리 합격선과 같은 선출 포함 조건(`SELECT=1`)에서도 유지 |
| 시간 | 판단 평균 ≤ **1초**(앱 AI 0.23초의 약 4배), 최대 ≤ 5초(사용자 결정 2026-10-31). Worker에서 돌고 지금은 2초 안에 답이 없으면 지금 AI로 폴백하는 장치(`aiClient.ts`)가 있어 챔피언은 5초로 늘려야 한다 |
| 회귀 | 앱 AI·하위 단계의 `verify.sh` 출력 불변(챔피언 전용 옵션은 기본 끔), 새 `test:ai` 시나리오 |
| 번들 | 모델 파일을 쓰면 200KB 이내, Worker 로드 시 한 번만 읽기 |

## 2. 지금 AI 구조 (요약)

```
선택지 점수(HP 교환식 §4) ─ 상위 3개 ─▶ 탐색 오라클(search.ts) ─▶ 최종 선택
                                      후보 × 상대 응수(상위 3) × 시드 1~4개를 runTurn으로 한 턴만 돌림
                                      값 = Σ 상대응수 가중치 × 평균_시드[ 그 턴 판세 변화 + 잎 평가 ]
상대 응수 가중치 = 상대 모델 ver2(한 단계 추론) × 사용자 학습 메모리(종별 기술·교체·변화기 배율)
잎 평가(fast)  = createPartyModel(6×6 대면표) + partyValueAfterTurn(이어지는 대면의 미니맥스)
```

실측 비용(이 PC, 2026-10-30, 3마리 파티 샘플 쌍):

| 항목 | 시간 |
|---|---|
| 엔진 `runTurn` 한 턴 | **0.29 ms** |
| 판단 — 기능 끔(`OFF`) | 3.7 ms |
| 판단 — 탐색 없는 기본 AI | 34 ms |
| 판단 — 앱 AI(오라클 켬) | **226 ms** |

엔진은 거의 공짜이고 시간은 전부 **AI 판단(대면표·잎 평가)**에서 쓴다. 이전 프로파일: 잎 평가 `partyValueAfterTurn` 57%(대면표 계산 21% 포함).

## 3. 과거 시도와 폐기 원인

| 시도 | 결과 | 읽을 점 |
|---|---|---|
| 탐색 오라클 도입(2.0) | 현재 AI 대비 **약 56%**(약 2.3σ) — 앱 기본 | 롤아웃으로 실제 엔진 규칙을 보는 것은 **효과가 있다** |
| 탐색 예산·폭 확대(`budget`·`topK`·`seeds`, c9) | 50.6% | 같은 계산을 더 해도 **평평하다** — 병목은 폭이 아니다 |
| 상시 `depth 2`(c8) | **55.7%**, 판단 1.7초(약 7배) | **깊이만** 효과가 있었다. 비용이 문제 |
| 후반 한정 `depth 2` | 49.8~50.5% | 이득은 초반~중반 국면에서 나오는데 거기가 시간 대부분 |
| 평가식 파라미터 튜닝(2.0 3단계) | 평평(개별 이득은 우연, 조합은 −) | 현재값은 평평한 최적점 근처 |
| 3선출 개선(2.1 A-3·A-2) | 48.8~53.4% | 선출 평가는 이미 무작위 대비 62%, 승패는 대전 중 판단이 좌우 |
| 챔피언 카운터 픽 | 효과 없음(±3.4%p) | 파티 대면표 점수가 실제 승패를 잘 예측하지 못한다 |
| 선출 약화로 사다리 간격 조정(6.3 G1) | 불가 | (이번 버전) |

**공통 교훈** — ① 같은 구조 안의 폭·예산·파라미터·선출은 전부 평평하다. ② 깊이는 효과가 있었지만(55.7%) 잎 평가가 비싸서 시간이 7배가 됐다. ③ 대면표 점수가 실제 승패 예측에 약하다(카운터 픽 실패의 해석). → **병목은 "잎 평가의 정확도·비용"과 "한 분포에 대한 기대값 최적화"** 쪽일 가능성이 크다.

## 4. 병목 가설

| # | 가설 | 근거 |
|---|---|---|
| H1 | 잎 평가(대면표)가 정확하지 않고 비싸다 | 카운터 픽 실패, 깊이 2에서만 이득(더 정확한 값을 보니까), 시간의 57%가 잎 평가 |
| H2 | 상대 응수를 **하나의 예측 분포**로 보고 기대값만 최대화한다. 동시 수 게임(교체/유지, 방어, 랭크업)에서 상대가 예측을 넘어서면 약하다 | 응수는 상위 3개 + 가중치, 최악 경우·균형 전략 개념이 오라클에 없다 |
| H3 | 후보 가지치기(상위 3개, 평가식 점수 기준)가 좋은 선택지를 버린다 | 오라클이 43% 턴에서 평가식과 다르게 고르고 이긴다 → 평가식이 틀리는 곳이 많다 |
| H4 | 호라이즌이 한 턴이다 | 깊이 2만 효과 |

## 5. 새 방향 후보

### 방향 A — 학습된 가치 함수를 잎 평가로 (H1·H4)
자기대전 데이터로 "이 state에서 내 편이 이길 확률"을 학습하고, 오라클의 잎 평가를 대체·보정한다.
- 데이터: AI끼리 대전의 **매 턴 시작 state 특징 → 최종 승패**. 이 PC에서 앱 AI 자기대전은 약 4천 판/시간(한 판 ≈12초, 14코어) ≈ 11만 state/시간. 탐색 없는 기본 AI는 10배 이상 빠르다.
- 특징: 파티별 HP 비율·상태이상·랭크·벽/날씨/필드/설치물, 선후공 관계, 마릿수, **기존 대면표 값(`partyValueAfterTurn`)을 특징 하나로 포함**(기존 정보를 잃지 않는다).
- 모델: 로지스틱 회귀 → 필요하면 작은 MLP. 순수 TS로 학습·추론(파이썬 불필요).
- 이점: 모델이 대면표 전체 재계산보다 훨씬 싸면 같은 시간에 **깊이 2**를 돌릴 수 있다 — 효과가 있었지만 비싸서 버린 방향을 되살린다.
- 위험: 자기대전 분포(앱 AI끼리) 밖에서 틀릴 수 있음, 이득이 작을 수 있음 → **먼저 예측 정확도로 판정**(게이트 1).
- 비용: 데이터 수집 스크립트·학습 스크립트·특징 추출·`search.ts` 잎 연결·모델 JSON.

### 방향 B — 동시 수 게임으로 풀기 (H2)
오라클이 이미 가진 행렬 `M[내 후보][상대 응수]`(롤아웃 값)로 기대값 대신 **강건한 선택**을 한다.
- 1차(싸다): 값 = (1−ρ)·기대값 + ρ·최악 응수 값. ρ 스윕(0.25·0.5·1).
- 2차: 상대 응수를 3개로 자르지 않고(교체·방어 포함) 행렬을 풀어 **혼합 전략**(최대최소/후회 매칭)으로 고르고, 사용자 학습 분포가 있으면 그 분포 쪽으로 기울인다(착취 + 안전).
- 이점: 구현이 오라클 안 몇십 줄, 비용은 거의 없음. 예측 가능한 AI가 아니게 되어 **사람이 패턴을 파악해 이기는 것**을 막는다(앱 AI 대 앱 AI h2h에 그 이득이 다 드러나지는 않는다).
- 위험: 앱 AI가 같은 모델을 쓰므로 h2h 이득이 작을 수 있다 → 실제 사람 효과는 측정이 어렵다.

### 방향 C — 모호한 턴에만 깊게 (H4, 비용 절감)
상위 두 후보의 값 차이가 작고(`budgetMargin` 안) 판이 갈리는 국면(양쪽 남은 마릿수 합이 많고 선택지가 교체·랭크업을 포함)에서만 `depth 2`를 켠다. 후반 한정 깊이(49.8~50.5%)와 달리 **초중반의 모호한 턴**을 겨냥한다. 방향 A의 싼 잎 평가가 있으면 선택 없이 상시 깊이 2도 가능.

### 방향 E — 선출 개인화 예측 (사용자 제안 2026-10-31)
챔피언 AI가 사용자의 선출을 **직접 보지 않고**, 사용자의 파티 구성과 과거 선출 기록을 대조해 가장 가능성 높은 3선출을 예상한 뒤 그에 맞춰 자기 선출을 고른다.
- 예전 A-3(상대 선출 예측, 48.8~51.8%)은 기록 없이 평가식으로만 예측했다. 이번에는 **개인 선출 기록**(파티 구성별로 어떤 3마리를 골랐는지)을 쓴다 — 사람은 선출에 습관이 강해 예측이 맞을 가능성이 있다.
- 필요: 사용자 선출 기록 저장(`ai-memory`에 선출 항목 추가 또는 별도 키, 클라우드 동기화 대상 포함), 예측 모델(파티 구성 해시 → 선출 빈도, 없으면 평가식 폴백), `chooseAiSelection`에 상대 선출 가중치 연결(A-3 코드가 브랜치에 있다).
- 측정: 선출 습관이 있는 스타일 봇(항상 같은 3마리·같은 선봉)에 대해 켬 대 끔. 사람 효과는 측정이 어렵다. 우선순위는 낮고 방향 D·B·A 결과 뒤.

### 방향 D — 상한 측정(헤드룸)
"시간 무제한 슈퍼 챔피언"(`depth 2`·`budget` 96·`seeds` 8·`leaf` precise)을 만들어 앱 AI와 붙인다. 실험용이고 제품화하지 않는다.
- ≥ 60%: 계산 증가가 강도로 이어진다 → 방향 A·C(비용을 낮추는 쪽)에 투자 가치가 크다.
- ≤ 53%: 이 구조의 탐색이 포화 → 방향 B(게임 이론)나 평가 개선으로.
- 비용: 한 판 약 5분 → 100시드(200판) × 14코어 ≈ 1~3시간. 가장 먼저 해 볼 만한 "어디에 쓸지 정하는 실험".

## 6. 권장 순서

1. **Stage 0 — 방향 D(상한 측정) + 방향 B 1차(강건 혼합)**: 둘 다 코드가 작다. 결과로 A·C·B 2차 중 어디에 시간을 쓸지 정한다.
2. **Stage 1 — 방향 A 데이터·정확도 게이트**: 자기대전 state 수집 → 현재 잎 평가 값 단독 대 학습 모델의 승패 예측(로그 손실·AUC, 보류 대전으로 검증). 학습이 의미 있게 낫지 않으면(로그 손실 개선 < 3%) 폐기.
3. **Stage 2 — 통합**: 게이트 통과 시 `search.leaf: "learned"`로 연결하고 같은 시간 예산에서 깊이 1 대 깊이 2, 앱 AI 대 h2h 400판.
4. **Stage 3 — 챔피언 프로필**: `RANK_AI_PROFILES[7]`에 챔피언 전용 옵션 연결(기본 끔 유지), `test:ai` 시나리오, `verify-kit` 기준값 갱신, 집 PC `verify.sh` 전체, 사다리 7번 쌍(챔피언 대 마스터볼 1) 측정.

각 단계의 폐기 기준은 합격 기준(§1)과 위 게이트다. 폐기해도 실험 결과는 이 문서에 남기고 코드는 넣지 않는다(5.0 R3 방식).

## 7. 사용자 결정이 필요한 것

결정 완료(사용자, 2026-10-31):
1. **시간 예산**: 판단 평균 1초, 최대 5초까지 허용.
2. **선출 정보**: 사용자의 3선출을 직접 보는 안은 쓰지 않는다(숨은 정보). 대신 **방향 E** — 파티 구성과 과거 기록으로 선출을 예측해 맞춰 구성하는 안으로 한다.
3. **모델 파일**: 학습된 가중치 JSON을 번들에 넣어도 된다.
4. **측정**: 방향 D를 병렬 6개 이하로 돌려 본다(파일럿 후 본 측정 시간을 정한다).

## 8. 하지 않는 것 (재론하지 않는다)

- 탐색 폭·예산·시드 확대, 후반 한정 깊이, 평가식 파라미터 미세 튜닝, 선출 개선, 카운터 픽 — 전부 평평하거나 효과 없음으로 측정됐다.
- 하위 단계(P0~P6)의 강도 변경 — 6.3 A2에서 확정.

## 9. Stage 0 결과 — 방향 D 상한 측정 (2026-10-31)

대 상대는 앱 AI(`APP`: 탐색 fast·topK 3·응수 3·budget 24 + 상대 모델 ver2). 조건: 샘플 파티 무작위 3마리(선출 없음), 좌우 교대, 병렬 9개(CPU 약 70%).

| 후보 | 판수 | 전적 | 승률 | 판단 시간(병렬 부하 포함) |
|---|---|---|---|---|
| 슈퍼 챔피언 — `depth 2`·seeds 6·topK 5·응수 4·budget 0 (파일럿) | 48 | 27:21 | 56.3% | — |
| **슈퍼 챔피언** (본 측정, 57분) | 300 | **174:126** | **58.0%** (z 2.8) | 평균 3.6초 · 최대 41초 |
| **c8 = `depth 2` + 앱 AI 제품 설정** (13분) | 400 | **217:179** (무 4) | **54.8%** (z 1.9) | 평균 **628ms** · 최대 7.4초 |

유휴 단독 실행 첫 턴(가장 비싼 구간) 판단 시간: 앱 AI 248ms · c8 974ms · 슈퍼 8.8초.

**해석**
- 계산을 늘리면 **실제로 강해진다**(58%, 유의). 이전 `budget` 확대(50.6%)와 달리 깊이를 쓴 경우다. 판정선(§5 방향 D): 53~60% — 깊이 쪽에 투자 가치는 있다.
- 슈퍼 챔피언이 c8보다 약 3%p 강한 것은 시드·후보 폭을 키운 몫이지만 시간이 9배라 제품화 대상이 아니다. **이득의 대부분은 깊이 2에서 나온다.**
- **c8은 시간 예산(평균 1초, 최대 5초) 안에 들어온다.** 이전에 "앱 AI의 2배 이내" 기준으로 폐기했던 구성이다. 54.8%(z 1.9)로 합격선 55%에 아주 조금 못 미치지만 오차(±4.9%p) 안이다. 두 번의 c8 측정(55.7% 202판 · 54.8% 400판)이 일치한다.
- **걸림돌**: 병렬 부하 포함 최대 7.4초 — 5초를 넘는다. 단독 실행의 최대는 더 짧겠지만 확인이 필요하다. `aiClient.ts`의 2초 폴백을 챔피언만 5초로 늘리고, 깊이 2를 쓰는 턴에 시간 안전장치(남은 시간이 부족하면 깊이 1로)를 둔다.

**다음 판단(미실행)** — ① c8을 챔피언 후보 v0으로 두고 약간의 개선(예: `topK` 4·`budget` 36·`seeds` 늘리기를 한 번에 하나씩)으로 55%를 넘기고 시간을 줄이는 길, ② 방향 A(학습된 가치 함수)로 잎 평가를 싸게 해 같은 시간에 슈퍼 챔피언 수준(58%)을 노리는 길. ①이 싸고 빠르며 ②는 크지만 상한이 더 높다. 둘은 겹치지 않는다(①로 v0 확정 → ②는 그 뒤 개선).

## 10. 챔피언 v0 채택과 다음 단계 (2026-10-31)

- 개선 후보 4개(대 앱 AI 400판씩): 후보 4개·예산 36 **54.4%** · 예산 48 **54.5%** · 응수 4개·예산 36 **55.2%** · 후보 2개·예산 16 **51.1%**. c8(54.8%)과 같거나 낮다 → **c8이 이 구조의 평평한 지점**. 후보 3개는 필요하고 더 넓혀도 이득이 없다.
