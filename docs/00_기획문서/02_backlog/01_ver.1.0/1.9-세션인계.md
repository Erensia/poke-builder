## 작업 규칙 (사용자 확정)

- 기획 문서보다 **코드가 우선** — 코드를 먼저 확인한다. 설계가 필요한 건 설계안을 먼저 제안하고 합의 후 구현.
- 항목마다 dev에서 브랜치 → PR을 dev로 **squash 머지**(PR 1개 = 커밋 1개). 머지한 브랜치는 삭제(원격 자동 삭제 켜짐).
  dev → main은 **ver.1.9 끝에 merge commit**으로(사용자 확인 후). **dev가 삭제되지 않게 주의(사용자 당부)** — PR 머지 시 원격 브랜치
  자동 삭제가 켜져 있으므로 PR 대신 로컬에서 `git merge --no-ff dev` 후 main 푸시. 막히면 PR 머지 직후 같은 커밋으로 dev 재푸시해 복구, 머지 후 원격 dev 존재 확인.
- 기획 문서만 바꾸는 변경은 dev에 직접 커밋. 기능 작업 중 발견한 버그는 그 기능 커밋에 포함.
- 머지 때 README 최신화. 커밋 메시지 끝에 Co-Authored-By / Claude-Session 줄.
- 커밋 전 `npm run lint` + tsc(`npx tsc -b`) + `npm run test:ai`.
- **엔진 변경**: `node scripts/battle-ai-sim.mjs regress 300` 해시를 전후 비교해 `battle-ai-decision-layer.md` §12에 기록.
  데이터·엔진 변경이 섞이면 "이전 데이터 + 새 코드" 해시를 따로.
- **AI 튜닝 판정**: 그리디 승률 + h2h. 표준 5종(그리디 800 켬/끔, STATUS=1 그리디 400 켬/끔, STATUS=1 h2h 200 켬 대 끔)을
  **`npm run bench`로 시드 구간 조각(기본 50)으로 나눠 CPU 코어 수(4)만큼 병렬**로 돌리고 합산한다(사용자 결정 2026-09-28 — 이전 "5개 병렬"
  대체, 조각 합은 한 번에 돌린 결과와 판 단위로 같음):
  `npm run bench -- toggle '{끔 파라미터}' [--root <체크아웃>]`, 이전 AI와 비교(정확도 수정)는 `npm run bench -- compare <이전 체크아웃>`.
  벤치 도중 작업 트리를 바꿀 거면 `git worktree`로 벤치 전용 체크아웃을 만들어 `--root`로 넘긴다(실행기·시뮬레이터 스크립트도 복사본을 쓰면 안전).
- 벤치가 도는 동안 다음 항목을 이전 브랜치 끝에서 따서 진행, 앞 PR이 squash 머지되면 `git rebase --onto origin/dev <이전 끝> <브랜치>`.
  다음 항목 사전 조사를 미리 해 두고, 결정할 점은 바로 보고.
- AI 동작이 바뀌는 정확도 수정(튜닝이 아닌 것)은 이전 AI와 `OPP_ROOT` h2h(+ 필요하면 그리디)로 오차 안인지 확인해 기록.
- 화면 확인이 필요 없는 데이터·엔진 PR은 검증 후 바로 squash 머지, 화면 변경 PR은 Vercel 미리보기 주소를 드리고 사용자 확인 후 머지.
- **브라우저 화면 검증은 사용자에게 맡긴다**(claude-in-chrome 직접 사용 금지). 부탁 전에 해당 작업 브랜치를 원격에 올려 두고
  사용자에게 PC에서 전환 방법을 안내. 테스트 중 localStorage `champions-party-sim.party.v1`(파티 자동저장)은 절대 지우지 말 것.
- 한국어로 답한다(사용자는 영어가 어렵다).
