## E1. AI 교체 왕복

3.2 백로그 "E1" 메모(2026-10-09)에서 옮겨 온 내용이다.

- **증상**: 배틀 프런티어에서 상대 `tb-snow`(맘모꾸리·툰베어·글레이시아)가 내 블래키(속임수·하품·달빛·바크아웃, 먹다남은음식) 앞에서 15턴 중 11턴을 교체로 보냄. 맘모꾸리/툰베어 ↔ 글레이시아를 오감.
- **재현**: 같은 파티·앱 AI 설정(`APP_DECISION_PARAMS`)으로 블래키가 변화기·바크아웃만 쓰게 하면 12~14턴 중 5~6회 교체. 로그의 11/15는 못 맞췄다(차이 원인 미확인). 하품을 빼도 6/12라 하품은 보조 원인. 재현 스크립트는 저장소에 없다(Vite `ssrLoadModule`로 `createBattleState` → `chooseAiAction` → `runTurn` 루프, 블래키 행동은 고정 순서) — 착수 때 `battle-ai-scenarios.mjs`의 시나리오로 새로 만든다.
- **원인(메커니즘)**
  1. 블래키 회복량(먹다남은음식 1/6 + 달빛)이 상대 공격 데미지 이상이면 `turnRates.ts:343`이 처치 턴 수 c를 `Infinity`로 둔다. 바크아웃으로 특공이 떨어진 글레이시아는 공격기 4개가 모두 c=∞ → 점수가 전부 같다(−2.01).
  2. 새로 나올 포켓몬은 능력치 하락이 초기화돼 있어 교체 점수(−1.22)가 더 낫다 → 교체. 그런데 맘모꾸리·툰베어는 속임수(상대 공격 능력치로 계산)에 약해 버티는 턴 수 d≈2.2·1.8이라 −0.8~−1.1, 능력치가 멀쩡한 글레이시아(d≈4.6, −0.23)가 낫다 → 다시 교체. 반복.
  3. 변화기 턴(달빛·하품·바크아웃)은 상대에게 손해가 아니라서 교체의 "턴 손실"이 비용으로 안 느껴진다.
  4. 왕복 끊기(`levelOne.ts:97`)는 직전 턴에 **양쪽이 모두** 교체했을 때만 작동 — 내가 제자리에 있으면 안 걸린다. "방금 들어온/나간 포켓몬" 제한은 없다.
  5. 탐색 오라클(`PRODUCT_SEARCH_PARAMS`, depth 1)은 한 수 앞만 봐서 왕복을 못 본다. 오라클 유무로 교체 수는 거의 같았다(6 vs 5).
- **평가식의 한계 정리**
  - 스냅샷 평가라 **이력이 없다**(히스테리시스 없음): 지난 턴에 같은 이유로 교체했다는 사실이 점수에 안 들어온다.
  - **c=∞가 점수를 뭉갠다**: "이길 수 없음"이면 공격기끼리 구분이 사라지고, 교체와는 "얼마나 덜 지느냐"만 비교한다. 어느 선택지도 이길 수 없을 때 "가장 덜 나쁜 것"이 곧 교체가 된다.
  - **교체의 이득만 계산**: 능력치 하락·랭크 초기화(`partyEval.ts` 물러났다 다시 나오는 포켓몬 규칙)와 새 포켓몬의 HP는 이득으로 잡히는데, "교체를 반복해도 상황이 그대로"라는 비용은 없다.
  - **승리 경로 탐색이 없다**: 유일하게 가능성 있는 수(툰베어 인파이트로 약점 공략, 로그 턴 7에서 75% 깎음)를 의도적으로 노리지 않는다. 그 경로의 점수가 속임수 위험(d≈1.8) 때문에 낮을 뿐이다.
  - 상대(사용자)가 변화기만 쓰는 **교착**을 별도 상태로 인식하지 못한다.
- **수정 방향 후보** (효용·위험 순; 하나씩 벤치로 측정)

  | 안 | 내용 | 장점 | 위험·비용 |
  |---|---|---|---|
  | A | **교체 히스테리시스**: 직전 턴에 교체해 들어온 포켓몬을 다시 빼거나, 직전에 나간 포켓몬으로 되돌아가는 교체에 마진(점수 차 ≥ m)을 요구 | 작다(`decision.ts` 동률 처리 근처 + 직전 교체 기록). 왕복 직접 차단 | 정말 필요한 즉시 교체(약점 맞교체)를 막을 수 있음 → 마진을 "교체 쪽이 확정 처치 회피일 때"는 면제 |
  | B | **교착 판정**: 내 공격기가 전부 c=∞이고 상대 지난 턴이 변화기면, "새로 나온 포켓몬의 초기화 이득"을 교체 점수에서 제한 | 원인 2를 직접 겨냥 | 판정 기준 설계 필요(c=∞ 전부 / 데미지 0) |
  | C | **교체 비용 상향**: `switchLostTurns` 1 → 상황별(상대가 변화기 계열이면 가산) | 파라미터만 만짐, 3단계 튜닝 노브가 이미 있음 | 전반적으로 교체가 줄어 `style switcher` 봇 상대 등 기존 벤치 하락 가능 |
  | D | **오라클 depth 2 / 교체 왕복 롤아웃** | 근본적(2턴 뒤 같은 상황으로 돌아옴을 봄) | 시간 한도(평균 3초·최대 5초) 초과 위험이 큼 — 비추천 |
  | E | **승리 경로 선호**: 유일한 약점 공략 기술이 있으면(c 유한 & 상성 우위) 지는 대면 점수에 가산 | 로그 턴 7처럼 시도하게 함 | 다른 대면 판단에 영향이 커 회귀 범위 넓음 — 후순위 |

  - **추천**: A(마진) 단독 먼저 → 부족하면 B 추가. C·D·E는 A·B로 부족할 때만.
- **검증 계획**: ①재현 시나리오를 `battle-ai-scenarios.mjs`에 추가(회복형 상대 앞 교체 횟수 ≤ N). ②`sim:ai` 회귀: 판당 교체 수·h2h 승률(`greedy`·`style`·`h2h`)이 기존(h2h 202:185 등 2.0 기준)보다 떨어지지 않는지. ③`regress` 해시 동일 여부(AI 변경이라 해시는 영향 없어야 함). ④ 시간 측정. 과거 교체 왕복 대응(2.0 1-C 왕복 끊기 ①)이 같은 계열 문제이므로 `2.0-backlog.md` 1-C 결과를 먼저 참고한다.
- **주의(코드 수정 규칙)**: AI 변경은 `ponytail` 스킬로 작성하고, 브랜치 흐름은 `dev` → feature → PR(커밋 1개) → `dev`. 브라우저가 필요한 확인(프런티어 실전)은 사용자에게 위임한다.
