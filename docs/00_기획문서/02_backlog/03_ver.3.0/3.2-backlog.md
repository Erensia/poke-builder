## 항목 메모

### V1. 속보 선후공 반영
- 현재: 스피드 역산의 속도 보정 특성 후보에서 속보를 뺀다(`speedInference.ts` 주석). 엔진 `state.ts`는 상태이상일 때 ×1.5이고 마비 반감을 무시한다(`types/ability.ts`에 속보 필드가 이미 정의됨).
- 할 일: `evaluateSpeedMatchup`의 가정(마비 등)에 상태이상일 때 속보 배율을 엔진과 같은 순서로 추가 → 스피드 역산 행 조건의 특성 후보에 속보 포함 → 결정력 화면(매치업 페이지) 선후공 표시도 같은 함수를 쓰므로 함께 맞춰진다.
- 검증: `test:inference`에 속보 왕복·손계산 추가, `test:damage`·`test:ai` 회귀. 화면은 사용자 위임(조건 영역 문구).

### V2. 역산 관측 입력 보존
- 확인 먼저: `DefenseInferencePanel.tsx`는 `localStorage`를 쓰지 않는다. 같은 화면 안 탭 전환에서 상태가 유지되는지·새로고침 때만 날아가는지 확인해 범위를 정한다.
- 방향(안): 상대 포켓몬·관측 행·행별 조건·가정 전체를 새 localStorage 키 하나로 자동 저장(파티·프리셋 키는 건드리지 않는다). 지우기 버튼 하나.
- 주의: 데이터 변경으로 포켓몬·기술 id가 사라져도 앱이 깨지지 않게, 불러올 때 존재하지 않는 id는 걸러낸다(3.1 `isUsableSample`과 같은 방어).

### V3. 내 샘플 백업·공유
- 내보내기(JSON 파일 저장) + 가져오기(파일 선택, 검증 후 병합) 한 쌍. 3.1에서 "내보내기만 있으면 일반 사용자에겐 쓸 곳이 없다"고 뺐으므로 **반드시 한 쌍**으로 한다.
- 가져오기는 신뢰하지 않는 입력이다 — `SamplePartyPreset` 모양 검증·id 충돌 처리·깨진 항목 건너뛰기. 마스터 승격(개발자)은 지금처럼 콘솔 한 줄 또는 이 파일을 Claude가 읽는 흐름을 유지.
- 선택: 같은 틀을 파티 프리셋 백업에도 쓸 수 있는지 확인(범위 밖이면 기록만).

### V4. 다단히트 역산 (선택)
- 다단히트는 타별로 난수가 독립이라 합계 데미지의 가능 집합이 16단계보다 훨씬 넓다. 타 수가 정해진 기술(2~3타 고정)부터 시작하는 안.
- 효용이 작거나 계산이 느려지면 폐기해도 되는 스파이크 성격.

### V5. 포인트 예산·결합 개선 (선택)
- 공격·특공·스피드를 모두 관측한 경우 방어 쪽 **하한**을 쓴다(지금은 상한과 스피드 최솟값만).
- 결합 되풀이가 최대 3번이라 수렴 보장이 없다 — 변화 없을 때까지 돌리되 계산 시간(현재 평균 ~380ms·최대 ~700ms)이 한도를 넘지 않는지 측정.
