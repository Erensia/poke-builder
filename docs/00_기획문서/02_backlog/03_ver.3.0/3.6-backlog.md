## 항목 메모

### T2. 스피드 표 재설계 (계획만 — 세부는 착수 때 토의)
- **목적(사용자)**: 내가 주려는 노력치의 스피드 실수치로 **어떤 포켓몬을 추월하고 어떤 포켓몬은 못 하는지** 알아보기 쉽게. 역산과 연계하지 않는다.
- **현재 코드**: `lib/speedTable.ts`(`speedNeighbors` — 폼마다 가장 가까운 경우 하나, 위아래 5줄 이상, 항상 빠름/갈림/항상 느림 개수)·`SpeedTablePanel.tsx`. 줄 보기는 정확한 경계 확인용으로 남긴다.
- **상대 단계(확정, 2026-10-14)**: 일반 개념 그대로 — **최속**(스피드↑ 보정 · 32pt) · **준속**(보정 없음 · 32pt) · **무투자**(보정 없음 · 0pt) + **최저속**(스피드↓ 보정 · 0pt, 트릭룸용). 값이 하나씩이라 추월 / 동속 / 못 추월이 정확히 갈린다.
- **준준속 폐기(사용자)**: 사용자가 만든 개념(조정 수치 묶음)이었으나, 스피드↑ 31pt가 보정 없음 32pt보다 빨라 준속을 가로지르고(종족값 100: 최속 167 · 준속 152 · 준준속 121~166 · 무투자 120) 서열이 안 된다. 보정 없음 1~31pt만으로 줄이면 서열은 깔끔하나 범위가 넓어 쓸모가 없다. 조정 수치는 "상대가 가진 값"이 아니라 "내가 고르는 값"이므로 아래 조정 기능으로 푼다.
- **근거(샘플 35개 210슬롯 집계)**: 스피드↑32 82 · 보정없음32 31 · 보정없음0 49 · 스피드↓0 14 · 스피드↓32 2 · 중간 값 32(그중 1~4pt가 20 — 예산 잔여로 보임, 8pt 이상 의도 조정은 12). 최저속(↓0)이 의도 조정(12)보다 흔해 단계에 넣었다.
- **조정 기능(T2에 포함)**: ①내 종의 포인트 0~32(성격은 현재 선택 유지)에 따른 스피드 값과, 추월 대상이 늘어나는 지점 — 예: "8pt부터 ○○ 무투자를 추월" ②상대 포켓몬을 하나 고르면 최속·준속·무투자(·최저속)를 각각 추월하는 **최소 포인트**(불가능하면 그렇게 표시). 예: 누리레느로 아머까오를 넘으려면 몇 pt인지. `formRows`·`speedValue`로 계산 가능.
- **안(제안)**: 상대 단계 선택 버튼 → 그 가정에서 추월 / 동속 / 못 추월 폼을 스프라이트 묶음으로 + 단계별 개수 요약. 조정 기능은 아래 별도 영역(또는 접이식).
- **착수 때 정할 것**: ①선택 버튼 방식인지 단계를 한 화면에 펼칠지 ②조정 기능의 배치(같은 탭 아래 영역 vs 서브 탭) ③상대 쪽 배율(구애스카프 ×1.5·순풍 ×2) 가정 토글 — 기본은 후속 ④기존 줄 보기와의 배치 ⑤목표 포켓몬 선택 UI(`PokemonPickerModal` 재사용 가능한지).
- **검증(예상)**: 단계 값·최소 포인트 계산은 `speedTable.ts`에서 하므로 `test:inference`(기존 `speedValue` 대조)에 단계 값·최소 포인트(경계 ±1 대조)를 보태 스크립트로 직접, 화면은 사용자 위임.

### I1. 역산 기능 최적화·기능 개선 (계획만 — 후보를 모아 둔 것, 착수 때 사용자와 고른다)
- **현황**: `lib/defenseInference.ts` 701줄 · `attackInference.ts` 438줄 · `speedInference.ts` 290줄 · `combinedInference.ts` 161줄 · `DefenseInferencePanel.tsx` 1,408줄 · 검증 `scripts/defense-inference-check.mjs`(`npm run test:inference`).
- **최적화 후보**: 결합 계산 시간(방어·공격 평균 ~450ms·최대 ~700ms, 3쪽 최대 ~690ms — 3.1 측정)을 줄일 수 있는지 프로파일 → 입력할 때마다 도는지·메모 가능한지. 결과 동일 원칙(P1처럼 `test:inference` 왕복 결과 동일 확인).
- **정확도 후보**: ①포인트 예산 — 방어·공격 쪽 하한은 공격·특공·스피드를 다 관측했을 때만 정해져 쓰지 않음 ②결합 되풀이 최대 3번이라 수렴 보장 없음 ③메가 관측이 하나라도 있으면 도구 가정이 전부 꺼짐(L1-c는 제외 확정) ④V5-b(하한 효과 확대, 낮음).
- **기능 후보**: ①미지원 기술 확대 — V4-b(멀티스케일·섀도실드 + 다단히트, 가변 타수), 고정 데미지·자이로볼/일렉트릭볼·쓰러진 공격(정보가 없거나 모델이 달라 어려움) ②관측 입력 사용성(`DefenseInferencePanel` 1,408줄 — 입력·결과 영역 정리).
- **착수 때 정할 것**: 위 후보 중 무엇을 이번에 할지 / 시험적 기능이므로 "기능 개선"의 우선순위를 실제 사용 불편(사용자 체감)에 둘지 / 파일 분리는 하지 않음(리팩토링은 4.0).
