## 항목 메모

### T2. 스피드 표 재설계 (계획만 — 세부는 착수 때 토의)
- **목적(사용자)**: 내가 주려는 노력치의 스피드 실수치로 **어떤 포켓몬을 추월하고 어떤 포켓몬은 못 하는지** 알아보기 쉽게. 역산과 연계하지 않는다.
- **현재 코드(완료 후)**: `lib/speedTable.ts`(`SPEED_TIERS`·`tierRow`·`speedOutlook`·`minPointsToPass`·`speedBreakpoints`)·`SpeedTablePanel.tsx`. 기존 실수치 줄 보기(`speedNeighbors`)는 화면이 가로로 길어져 삭제했다.
- **상대 단계(확정, 2026-10-14)**: 일반 개념 그대로 — **최속**(스피드↑ 보정 · 32pt) · **준속**(보정 없음 · 32pt) · **무투자**(보정 없음 · 0pt) + **최저속**(스피드↓ 보정 · 0pt, 트릭룸용). 값이 하나씩이라 추월 / 동속 / 못 추월이 정확히 갈린다.
- **준준속 폐기(사용자)**: 사용자가 만든 개념(조정 수치 묶음)이었으나, 스피드↑ 31pt가 보정 없음 32pt보다 빨라 준속을 가로지르고(종족값 100: 최속 167 · 준속 152 · 준준속 121~166 · 무투자 120) 서열이 안 된다. 보정 없음 1~31pt만으로 줄이면 서열은 깔끔하나 범위가 넓어 쓸모가 없다. 조정 수치는 "상대가 가진 값"이 아니라 "내가 고르는 값"이므로 아래 조정 기능으로 푼다.
- **근거(샘플 35개 210슬롯 집계)**: 스피드↑32 82 · 보정없음32 31 · 보정없음0 49 · 스피드↓0 14 · 스피드↓32 2 · 중간 값 32(그중 1~4pt가 20 — 예산 잔여로 보임, 8pt 이상 의도 조정은 12). 최저속(↓0)이 의도 조정(12)보다 흔해 단계에 넣었다.
- **조정 기능(T2에 포함)**: ①내 종의 포인트 0~32(성격은 현재 선택 유지)에 따른 스피드 값과, 추월 대상이 늘어나는 지점 — 예: "8pt부터 ○○ 무투자를 추월" ②상대 포켓몬을 하나 고르면 최속·준속·무투자(·최저속)를 각각 추월하는 **최소 포인트**(불가능하면 그렇게 표시). 예: 누리레느로 아머까오를 넘으려면 몇 pt인지. `formRows`·`speedValue`로 계산 가능.
- **구현 결과(사용자 확정)**: 단계 4개를 한 화면에 펼쳐 추월 / 동속 / 못 추월 폼을 스프라이트로(추월은 접이식) + 개수 요약. 포인트 조정은 같은 탭 아래 영역, **목표 포켓몬 고르기는 내 포켓몬 카드 아래(왼쪽 열)**, 순풍은 카드 상태이상 아래 `있음` 토글 버튼, 구역마다 접기/펼치기, 모바일(≤760px)은 오른쪽 영역 폭을 왼쪽 열과 같게(최대 320px). 칩 설명 박스는 유리 패널 모양으로 맞춤.
- **남은 것(후속 후보)**: 상대 쪽 배율(구애스카프 ×1.5·순풍 ×2) 가정 토글 — 지금은 표 아래 안내 문구로만 알린다.
- **검증(완료)**: `test:inference`에 단계 값(`computeRealStats` 대조 344폼×4)·추월 분류·최소 포인트(경계 ±1)·포인트 지점 전수 대조를 추가(ALL PASS), `tsc -b`·`oxlint`·`build`·`test:damage`·`validate:data` 통과. 화면(PC·모바일)은 사용자 확인 완료.
