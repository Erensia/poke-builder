## 3.5 한계 메모 (출처)

- **M1·U1-b**: 길게 눌러 끌기 로직은 `hooks/useLongPressDrag.ts`(300ms, 10px 이동 취소, `touchmove` 차단, 타깃에 `is-drag-over` 직접 부착, 터치 주 입력 기기에서 HTML5 드래그 끔, 직후 click 삼키기). `useSlotSwapDnd`(결정력·내구력)·`PartySlotCard`(파티 편성 슬롯·기술 칸 `MovePip`, `data-move-pip="슬롯-칸"`, 모듈 변수 `draggedMovePip`)가 쓴다. 다른 슬롯과의 기술 교환은 막아 두었고, 빈 칸은 끌 수 없고 놓을 곳으로만 쓴다.
- **S1**: `.picker-search`를 `PokemonPickerModal`·`MovePickerModal`·`ItemPickerModal`이 쓴다. 하단 sticky → 맨 위로 옮긴 것이라 ver.1.6 §1-1(엄지 접근성)·§2-1(스크롤에 따라오기)과의 균형을 화면에서 봐야 한다.
- **T1·H1·V4-b·V5-b·E1**: `3.4-backlog.md`·`3.3-backlog.md`의 출처 메모 참고.

## 메모

- 마이너 버전이라 전체 리팩토링은 하지 않는다. 3.x → 4.0 때 `ponytail` 전체 리팩토링 → 엔진·기능 테스트.
- 코드 항목은 항목별 브랜치 → PR 1개(커밋 1개) → `dev` squash. 화면 확인이 필요한 항목은 로컬 브랜치를 먼저 전환해 두고 사용자에게 체크리스트로 위임한다.
- dev → main 버전 업데이트 PR 제목은 `ver<버전>`(예: `ver3.6`)으로 통일한다.
