## 항목 메모

### T1-b. 스피드 역산 겹쳐 보기 (계획만 — 세부는 착수 때 토의)
- **하려는 것**: 스피드 표 탭(`SpeedTablePanel.tsx`·`lib/speedTable.ts`)에 상대 스피드 역산의 후보 범위를 겹쳐 그려 "이 상대는 표의 어느 라인인가"를 보여준다.
- **현재 코드**: 역산 결과는 `DefenseInferencePanel.tsx`(1,408줄) 안에서만 계산된다(`lib/speedInference.ts`). 표 탭과 공유하려면 상태를 위로 올려야 한다(`MatchupPage`/`useMatchup`). 폼마다 가까운 경우 하나만 올리는 표 방식은 유지.
- **흡수한 한계(스피드 역산)**: ①동속은 랜덤이라 가능도 ½로만 취급 → 표에서 동속 라인을 어떻게 표시할지 ②관측을 8번 모아도 실수치 폭이 평균 35 남음(1회 50.6 → 3회 45.0 → 8회 35.5, 내 속도에서 먼 상대일수록 정보가 적음) → 후보 폭이 넓을 때 "정보 부족" 안내를 같이 보여줄지 ③속보(상태이상 ×1.5)는 선후공 판정에 있음(3.2 V1). 계산 자체를 바꾸는 게 아니라 **표시·안내로 풀 수 있는지**를 먼저 본다.

### I1. 역산 기능 최적화·기능 개선 (계획만 — 후보를 모아 둔 것, 착수 때 사용자와 고른다)
- **현황**: `lib/defenseInference.ts` 701줄 · `attackInference.ts` 438줄 · `speedInference.ts` 290줄 · `combinedInference.ts` 161줄 · `DefenseInferencePanel.tsx` 1,408줄 · 검증 `scripts/defense-inference-check.mjs`(`npm run test:inference`).
- **최적화 후보**: 결합 계산 시간(방어·공격 평균 ~450ms·최대 ~700ms, 3쪽 최대 ~690ms — 3.1 측정)을 줄일 수 있는지 프로파일 → 입력할 때마다 도는지·메모 가능한지. 결과 동일 원칙(P1처럼 `test:inference` 왕복 결과 동일 확인).
- **정확도 후보**: ①포인트 예산 — 방어·공격 쪽 하한은 공격·특공·스피드를 다 관측했을 때만 정해져 쓰지 않음 ②결합 되풀이 최대 3번이라 수렴 보장 없음 ③메가 관측이 하나라도 있으면 도구 가정이 전부 꺼짐(L1-c는 제외 확정) ④V5-b(하한 효과 확대, 낮음).
- **기능 후보**: ①미지원 기술 확대 — V4-b(멀티스케일·섀도실드 + 다단히트, 가변 타수), 고정 데미지·자이로볼/일렉트릭볼·쓰러진 공격(정보가 없거나 모델이 달라 어려움) ②T1-b와의 연동(결과를 다른 탭에서 쓰기) ③관측 입력 사용성(`DefenseInferencePanel` 1,408줄 — 입력·결과 영역 정리).
- **착수 때 정할 것**: 위 후보 중 무엇을 이번에 할지 / 시험적 기능이므로 "기능 개선"의 우선순위를 실제 사용 불편(사용자 체감)에 둘지 / 파일 분리는 하지 않음(리팩토링은 4.0).
