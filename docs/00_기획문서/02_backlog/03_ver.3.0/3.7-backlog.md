## 항목 메모

### H1-b. HP 눈금 강조 확대 + 패널 고정 영역 (계획만 — 세부는 착수 때 토의)
- **현재**: 포인트 편집 모달(`PointsEditorModal`)의 슬라이더 아래 눈금 띠(`MarkStrip`, 로직 `lib/hpMagic.ts`). 강조(★·노란색)는 슬롯의 도구·기술 중 먹다남은음식 16n+15 · 자뭉열매·대타출동 4n+3 · 생명의구슬 10n+9뿐. 눈금/띠를 누르면(클릭·탭) 설명 패널이 열려 아래 줄이 밀린다(호버는 반짝여서 뺐다).
- **강조 확대(슬롯 정보로 자동 판정, 사용자 입력 없음)**:
  - 도구: 독독구슬·화염구슬·검은진흙 → 16n+15(맹독·화상·독 타입 회복 ⌊HP/16⌋).
  - 타입: 스텔스록 배율은 바위 상성으로 정해진다 — 4배 약점 홀수(⌊HP/2⌋) · 약점 4n+3 · 등배 8n+7 · 반감 16n+15.
  - 기술: 배북·저주(고스트) 등 HP 절반 소모 기술 → 홀수.
  - 조건이 겹칠 때 우선순위는 3.4 H1 절(16n+15가 8n+7·4n+3·홀수를 포함, 생명의구슬 10n+9와의 동시 충족 조건)을 따른다.
- **패널 위치**: 슬라이더 아래에 패널 높이를 미리 확보한 고정 영역을 두고, 비어 있을 때는 "눈금을 눌러 설명 보기" 안내. 호버 대신 클릭 유지. CSS 위주. 모바일에서 문장이 길면 영역 안에서 스크롤.
- **검증**: 판정 로직은 `test:inference`의 `hpMagic` 전수 검사에 케이스 추가, 화면(PC·모바일)은 사용자 위임(로컬 브랜치 먼저 전환).

### A4. 노력치 역산(방어) 관측에 턴 종료 효과 반영 (계획만 — 세부는 착수 때 토의)
- **현재 구조**: `defenseInference.ts`의 `candidateLikelihood`가 후보(최대 HP)마다 정확한 HP(`h`)를 관측 사이로 이어 가며, 관측마다 `before`/`after` 화면 %(`displayPercent`)를 맞춘다. 주석에 "관측 사이 회복 없음 가정". 공격 역산(`attackInference.ts`)은 내 HP 수치를 직접 입력하는 방식이라 대상 아님.
- **하려는 것**: 관측 행에 "이 관측(맞은 뒤) 턴 종료 효과"를 고르게 하고, 후보 HP마다 변화량을 계산해 `h2 → h2 ± 변화량`(0~최대 HP로 자름)을 `after` 판정 전에 끼운다. 변화량: 먹다남은음식 +⌊HP/16⌋ · 독 −⌊HP/8⌋ · 화상·모래바람 −⌊HP/16⌋ · 맹독 −⌊HP/16⌋×경과 턴 · 씨뿌리기 −⌊HP/8⌋ · 그래스필드 +⌊HP/16⌋ 등(`lib/hpMagic.ts`의 효과표와 맞춘다). 상대 도구를 먹다남은음식으로 가정했다면 기본값 자동 채움을 검토.
- **이번에 하지 않는 것**: 자뭉열매처럼 HP 절반 이하에서 조건부로 발동하는 효과(분기 필요) · 공격 역산 쪽.
- **비용·위험**: 계산 시간은 거의 늘지 않는다(후보당 연산 한 줄). 결과가 바뀌는 변경이므로 효과를 지정하지 않은 기존 시나리오의 결합 결과 해시(`10040ffa0108c9a3`)는 그대로여야 한다 — 이것이 회귀 기준. 효과를 지정한 새 시나리오는 왕복(알려진 SP로 관측을 만들어 역산해 진짜 배분이 후보에 있는지) 검증.
- **UI**: `DefenseInferencePanel.tsx` 관측 행(`ObservationRow`, `lib/inferenceDraft.ts` 임시 저장에 필드 추가). 

### A3. 내구 조정 탭 (계획만 — 세부는 착수 때 토의)
- **위치**: 계산 기능 메뉴의 새 탭 **내구 조정**(결정력 계산 · 노력치 역산 · 스피드 조정 · 내구 조정). 구조는 스피드 조정 탭과 같게(왼쪽 내 포켓몬 카드, 오른쪽 조정 영역, 구역 접기/펼치기).
- **하려는 것**: 내 포켓몬 + 가정 공격자(포켓몬·기술·성격·SP·도구) + 날씨·필드·벽 조건에서 "최대 난수로 맞아도 생존"(그 밖에 난수 n% 생존 등은 착수 때 사용자와 정함)을 만족하는 HP·방어(또는 특방) 포인트 조합. 총 SP가 적은 순 곡선/표로 보여주고, H1의 HP 마법 수치(16n+15 등) 지점을 표시한다.
- **구현 방향**: 기존 데미지 계산(`matchupEvaluator`/`evaluator` 데미지 경로)을 재사용, HP 0~32 × 방어 0~32 격자(1,089칸)를 훑는다. 내 포켓몬 카드·날씨·필드 배경은 스피드 조정 탭의 패턴을 재사용.
- **착수 때 정할 것**: 생존 목표 종류(확정/난수 n%) · 가정 공격자 입력 방식(기존 상대 선택 UI 재사용 여부) · 결과 표시(곡선 vs 표) · 여러 공격 동시 버티기(이번 범위에서는 제외 추천).
- **검증**: 경계 검사(찾은 최소 포인트 −1이면 생존 실패, 그 포인트면 성공)와 `computeRealStats`·데미지 계산 대조를 `test:inference` 또는 `test:damage`에 추가. 화면은 사용자 위임.
