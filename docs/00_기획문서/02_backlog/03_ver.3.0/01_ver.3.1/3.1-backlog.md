## C2. 상대 노력치 역산 2차 — 결정 사항(2026-10-07)

- **"흔한 배분 가중"은 하지 않는다.** 극보정을 주된 사전 가정으로 쓰면 역산하는 의미가 없어진다(극보정이 아닌 배분을 잡아내는 게 가치). 내구 지수는 이미 사전 가정 없이 좁게 나온다. 대신 **C2-a**로 극보정 칸을 표시만 한다 — 극보정 후보가 하나도 안 남으면 "일반적이지 않은 배분"이라는 정보가 된다.
- **포인트 합계 66은 항상 다 쓴다고 본다(사용자 결정).** 66을 다 안 쓴 상대는 없다고 보므로 "다 썼다고 가정" **옵션은 만들지 않는다** — 합계 66 고정이 기본 제약이다.
- **C2-b 공격 역산이 본론**이다. 상대가 내게 준 데미지는 정확한 HP 수치라, 내가 입힌 %(정수 반올림)보다 훨씬 좁게 나온다.
  - 입력: 상대 기술·급소 여부·받은 데미지(내 HP 수치). 내 방어·HP·성격은 알고 있어 변수는 상대 공격(특공) 포인트·성격·난수 16단계.
  - **성격 공유**: 공격 역산이 걸러낸 성격 후보를 방어 역산에도 쓴다(성격은 한 값).
  - **포인트 예산**: 합계 66 고정이므로, 공격·특공·스피드 포인트를 알면 HP+방어+특방의 합이 정확히 정해진다. 그래서 **공격·특공·스피드를 다 알아야 예산이 의미를 갖는다** → C2-b와 C2-c를 따로 떼지 않고 한 묶음으로 설계하는 안.
  - 계산 구조(안): 관측은 성격이 정해지면 쪽별로 독립이라, 성격별로 각 쪽(방어·공격·스피드)의 가능 집합을 따로 구한 뒤 합계 66 조건으로 합친다(후보를 한 번에 6차원으로 세지 않는다).
- **도구·특성 보정**: 구애머리띠는 포켓몬 챔피언스에 없어서 대상이 아니다. 생명의구슬처럼 한두 턴이 지나면 알 수 있는 도구는 지금 방어 쪽 "상대 도구 가정"처럼 **사용자가 가정으로 입력**한다 — 알게 된 시점에 가정을 바꿔 다시 계산하면 되므로 "첫 턴은 제외하고 두 번째 턴부터 반영" 같은 별도 규칙은 두지 않는다. 공격 보정 특성(천하장사류 등)도 같은 방식.
- **스피드 역산**: 선후공은 "이 값보다 빠르다/느리다"라는 부등식이라 구간이 나온다. 스피드에도 포인트를 배분했을 수 있어 스피드 포인트·성격(스피드 보정)이 변수다. 스카프·순풍·마비 같은 변수는 가정 입력으로 처리한다.

## S2. 내 샘플 프로토타입 — 스파이크 (정의 초안, 확정 아님)

**배경(2026-10-07 논의)**: 샘플 파티를 지금은 사용자가 txt를 만들고 Claude가 읽어 `samplePartyPresets.json`에 넣는다. 앱 안에서 만들 수 있으면 더 편할 것 같지만 "어떻게 좋은 방식으로 구현할지"가 정해지지 않아서, **정의를 먼저 적고 로컬 브랜치에서 한 번 구현해 본 뒤 판단**한다.

**핵심 제약**: 브라우저 앱이라 화면에서 `src/data/*.json`(마스터)을 고칠 수 없다 — 인앱으로 추가한 샘플은 어떻게 해도 **localStorage 사용자 데이터**다. 마스터는 읽기 전용으로 두고, 마스터로 올리는 길은 "내보내기 JSON → Claude가 읽어 데이터에 반영"(지금 txt 방식과 같은 흐름).

**정의 초안(프로토타입 최소 범위)**
1. 현재 파티를 **이름·분류(기초샘플/심화샘플)·성향 라벨·설명**과 함께 "내 샘플"로 저장(새 localStorage 키, 파티·프리셋 키는 건드리지 않음).
2. 샘플 파티 모달에 **"내 샘플" 탭** — 불러오기·삭제(·이름 변경).
3. **JSON 내보내기**(파일 저장 또는 복사). 형식은 마스터 `SamplePartyPreset`과 같게.
- 이번 시험에서 **제외**: JSON 가져오기, 프런티어 상대 풀에 포함(샘플 id 기준 기록·풀 크기 의미가 바뀜 — 필요해지면 옵션으로 따로).
- 기존 **파티 프리셋**(이름 붙여 저장·불러오기)과 겹친다 — 차이는 분류·설명·샘플 모달 노출·마스터로 내보내기.

**성공 기준(셋 다 "예"여야 채택)**
1. txt를 만드는 것보다 샘플 하나를 만드는 게 **실제로 빠르고 편하다**(사용자 체감).
2. 내보낸 JSON을 마스터에 **문제없이 반영**할 수 있다(`npm run validate:data` 통과).
3. 파티 프리셋과 **역할이 헷갈리지 않는다**.

**운영 규칙**

## C2-b 설계 확정 (사용자, 2026-10-07)

- **입력**: 관측 행의 종류를 고른다 — "내가 입힌 데미지"(기존, 상대 HP %) / **"내가 받은 데미지"**(새). 같은 역산 탭·같은 상대 포켓몬·성격 공유를 쓴다. 결과도 하나로 합쳐 보여 준다.
- **받은 데미지 행**: 상대가 쓴 기술(상대 포켓몬의 습득 기술에서 고름)·급소 여부·**내 HP 수치 "맞기 전 → 맞은 뒤"**(게임 화면의 숫자 그대로, 기존 % 행과 같은 형태). 같은 턴의 턴 종료 효과(먹다남은음식·독 등)가 섞이지 않게, 맞은 직후 HP를 넣는다고 안내한다.
- **계산**: 내 포켓몬(방어자)은 능력·특성·도구·랭크를 알고 있어, 변수는 상대의 공격(물리면 공격, 특수면 특공) 포인트·성격·난수 16단계뿐이다 — 정수 데미지 공식(`damageFormula`)으로 후보(포인트 0~32 × 성격 보정 3종)마다 데미지 16단계를 만들어 받은 데미지와 맞는지 본다. 방어 역산의 가능도 가중 방식과 같은 틀.
- **공격 보정 가정**: 방어 역산의 "상대 특성·도구 가정"처럼 **가정 입력(기본 없음)** — 공격 보정 후보(생명의구슬·달인의띠·타입 강화 도구, 테크니션·맹화류 등)를 목록에서 고르고, 알게 되면 바꿔 다시 계산한다. 후보별 확률 합산은 하지 않는다. 상대 공격 랭크·벽·날씨·필드도 방어 역산과 같은 입력을 쓴다.
- **포인트 예산(합계 66)이 주는 정보의 한계**: 관측하지 않은 스탯(예: 물리 어태커의 특공)이 남은 포인트를 흡수할 수 있어서, **상한(HP+방어+특방 ≤ 66 − 공격 − 특공 − 스피드, 모르는 스탯은 최소 0)은 항상 유효**하지만 **하한은 공격·특공·스피드를 다 관측했을 때만** 정해진다. 공격·스피드를 더 관측할수록 내구 범위가 좁아지는 구조 — 성격 공유가 가장 큰 이득이다.

## C2-c 설계 확정 (사용자, 2026-10-08)

- **관측**: "이번 턴 누가 먼저 움직였나"(우선도가 같은 기술끼리). 내가 먼저 → 상대 실효 스피드 ≤ 내 실효 스피드, 상대가 먼저 → ≥. 동속은 랜덤이라 어느 쪽이든 가능(가능도 ½). 결과는 숫자가 아니라 부등식이라 한 번의 관측은 "이 값보다 빠르다/느리다"만 알려 주고, 조건이 다른 관측을 모을수록 구간이 좁아진다.
- **입력**: 관측 행 종류에 "선후공"을 추가(세 번째 종류). 행에서는 **누가 먼저**만 고른다.
- **조건은 행별**(사용자 결정): 트릭룸·내 쪽 순풍·상대 쪽 순풍·내 마비·상대 마비·상대 스피드 랭크·상대 속도 보정 도구(구애스카프·검은철구)·특성(엽록소·쓱쓱·모래헤치기·눈치우기·곡예·서핑테일·시간벌기) 가정을 행마다 따로 저장한다. 내 스피드 랭크·특성·도구는 내 포켓몬 카드 값을 그대로 쓰고, 날씨·필드는 위쪽 선택기를 쓴다.
- **계산**: 기존 `evaluateSpeedMatchup`(선후공 판정)을 재사용한다 — 순풍(×2)·서핑테일(필드)이 빠져 있어 옵션으로 추가한다(엔진 `computeTurnOrderSpeed`와 같은 곱셈 순서). 후보(스피드 포인트 0~32 × 스피드 보정 묶음 ↑/↓/없음)마다 모든 관측의 선후공이 맞는지 본다.
- **결합(PR5-b)**: 성격 공유에 스피드 보정이 들어가고, 포인트 예산에는 스피드 최소가 반영된다. 속보(상태이상 시 스피드 ×1.5)는 아직 선후공 판정에 없어 후보에서 뺀다.

1. **화면**: 관측 행 종류에 "선후공"(세 번째) — 행에는 "누가 먼저"(내가 먼저/상대가 먼저)만. **조건은 행별**: 트릭룸·내/상대 순풍·내/상대 마비·상대 스피드 랭크·상대 속도 보정 도구(`SPEED_ITEM_CANDIDATES`)·특성(`SPEED_ABILITY_CANDIDATES`)·곡예 발동 후 — 행 아래 접이식 "조건" 영역(칸이 많아 화면이 복잡해지는 걸 피함). 내 스피드 랭크·특성·도구는 내 카드, 날씨·필드는 위쪽 선택기. 새 행은 직전 행의 조건을 이어받는다. 메가 전/후 선택은 다른 행 종류와 같다.
2. **결과**: 스피드 포인트 범위·가능도 중심 구간·실수치 범위·스피드 보정(↑/↓/없음) 묶음 가능도. **안내 문구**: 선후공은 상대 속도가 내 속도 근처일 때만 정보가 크고(측정: 실수치 폭 1회 50.6 → 3회 45.0 → 8회 35.5), 조건(내 순풍·상대 랭크 등)을 바꿔 가며 모을수록 좁아진다.
3. **결합(`combinedInference.ts` 확장)**: ① 성격 공유에 스피드 보정이 들어가 방어·공격·스피드 세 쪽의 가능한 성격 교집합을 쓴다(`SpeedInferenceInput.natureIds`). ② 포인트 예산에 스피드 **하한**을 쓴다 — 추월했다는 관측은 "이 포인트 이상"이라는 하한만 주고(내가 먼저면 상한), 하한은 **남은 성격 후보를 모두 고려한 최솟값**을 쓴다(성격 후보가 줄수록 하한이 올라간다: 예) 내 망나뇽 132를 한카리아스(종족값 102)가 추월 → 스피드↑ 0 / 무보정 10 / 스피드↓ 25). 방어 쪽 상한 = 66 − 공격·특공 최소 − 스피드 최소, 공격 쪽 상한 = 66 − 방어 최소 − 스피드 최소, 스피드 쪽 `maxPoints` = 66 − 방어·공격 최소. 되풀이는 지금처럼 바뀌지 않을 때까지(최대 3번).
4. **효과**: "내가 먼저" 관측은 스피드↑ 성격을 배제할 수 있고(예: 134 > 132), 종족값이 낮은 상대가 추월했다면 하한이 커서 다른 쪽 포인트 상한을 크게 줄인다.
5. **검증**: `test:inference`에 결합 왕복(세 쪽 진짜 배분이 남고 후보가 늘지 않음) 추가. 역산 탭 화면은 사용자 위임.
