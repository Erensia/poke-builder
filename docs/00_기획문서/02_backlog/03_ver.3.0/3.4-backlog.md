## 항목 메모

### T1. 스피드 실수치 표 (계획만 — 세부는 착수 때 토의)
- **하려는 것**: 현재 로스터(`pokemon.json`) 포켓몬들이 가질 수 있는 **모든 스피드 실수치**를 최고값부터 최저값까지 내림차순 표로 만든다. 사용자가 포켓몬을 고르면 그 포켓몬의 스피드 실수치가 표의 어느 위치(순위·구간)인지 표시한다.
- **재료(이미 있는 것)**: 종족값(`baseStats.spe`, 메가폼 포함) · 실능치 계산 `statCalculator.ts`의 `computeRealStats` · 성격 배율 `natureMult("spe", …)`(스피드 ↑·무보정·↓ 3종) · 속도 보정(구애스카프 ×1.5 등 `speedMultiplier` 도구, `speedInference.ts`의 `SPEED_ITEM_CANDIDATES`) · 랭크·상태이상 배율 `computeEffectiveSpeed`·`computeStatusSpeedMultiplier`.
- **착수 때 정할 것**: ①"경우의 수"의 축 — 스피드 포인트(0~32) × 성격 3종까지만 볼지, 도구·특성·랭크·순풍 같은 배율까지 넣을지 ②같은 실수치를 가진 포켓몬 묶기(동속) ③메가폼을 별도 항목으로 볼지 ④표 크기(319종 × 포인트 × 성격 → 수천 행)에 맞는 화면(가상 스크롤·필터) ⑤선택한 포켓몬 표시 방식(내 포켓몬 슬롯/도감 선택 연동·스크롤 위치·강조) ⑥화면 위치(결정력·내구력 페이지의 새 탭 vs 도감 vs 별도 페이지) ⑦역산 결과(스피드 역산 후보 범위)를 표에 겹쳐 보여줄지.
- **검증(예상)**: 계산은 `test:inference`·`test:damage` 류 스크립트로 직접(정렬·동속·경계값), 화면은 사용자 위임.

### H1. 포인트 분배 시 특수 HP 표시 (계획만 — 기준 표 수령 대기)
- **하려는 것**: 능력 포인트(SP)를 나눌 때 HP 실수치가 "특수한 값"에 도달하면 그 자리에 별도 표시를 한다. 특수한 값의 목록과 최적 분배 기준은 사용자가 준 표를 따른다.
- **전제(사용자 전달, 포챔스 기준)**: Lv50 고정 · 개체값 31 고정 · 노력치 대신 능력 포인트(SP) · **1 SP = 실수치 1**. 도입부만 받았고 기준·표 본문은 아직 없다 → **표를 받으면 이 절에 그대로 옮긴다.**
- **착수 때 정할 것**: ①기준 표 확정(HP 외 능력치에도 적용할지) ②표시 위치(`PartyEditor` 포인트 분배 UI, 결정력·내구력 페이지 슬롯 카드 등) ③표시 형태(배지·색·툴팁) ④현재 HP 계산(`computeRealStats`)과 기준값의 일치 확인 ⑤종족값·특성·도구에 따라 기준이 달라지는지.
- **검증(예상)**: 기준값 판정 함수는 스크립트로 직접(경계값), 화면은 사용자 위임.

## 3.3 한계 항목 — 출처 메모

3.3 백로그 "3.3 마무리"에서 옮겨 온 내용. 착수 때 해당 항목 절을 `3.3-backlog.md`("E1 결과" 등)와 함께 읽는다.

- **E1-b**: 반복 교체 14회 남음(21 → 14, 마진 1 이상은 14로 같음). 교착 판정은 "내 공격기 전부 c=∞"뿐이라 상대가 변화기만 쓰는지는 보지 않는다(이력 없음). 후속안: 3.3 백로그 C(교체 비용 상향)·E(승리 경로 선호). 벤치(`greedy`·`style`·`h2h`)·`regress` 해시·시간 측정 필수.
- **U1-b**: HTML5 드래그앤드롭(`useSlotSwapDnd.ts`)은 터치에서 동작하지 않는다. 계산·역산 두 탭 모두 해당.
- **V4-b**: 멀티스케일·섀도실드 + 다단히트(첫 타만 줄어듦)는 오류로 안내 중. 급소 표시는 모든 타에 같이 적용. 타수가 가변인 위력·최대 타수 기술.
- **V5-b**: 포인트 하한이 걸리는 경우가 5/177. 새 실측 사례가 있을 때 효과 확인.
