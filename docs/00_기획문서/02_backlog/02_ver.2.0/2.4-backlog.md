## B1. 일렉트로빔 대전 로그 문구 수정

- 사용자 요청(2026-10-05): 일렉트로빔은 날씨가 비가 아닐 때 2턴을 쓰는 차지형 기술이다. 1턴째에 에너지를 모으며 자신의 특수공격이 1랭크 오른다.
- 현상: **특수공격이 오르는 1턴째의 로그가 출력되지 않고**, 능력치 스테이터스에만 반영된다. 로그 양을 줄이는 방법이긴 하나 진행된 턴의 내용 전달이 부족하다.
- 목표 출력(대전 로그):

  ```
  1턴째(사용한 턴)
  (포켓몬 이름)은(는) 전기를 모았다!
  (포켓몬 이름)의 특수공격이 올랐다!
  2턴째(사용한 다음 턴)
  (포켓몬 이름)의 일렉트로빔! — 데미지 xxx(퍼센트)
  ```

- 구현 지침: 문구의 **은(는) 조사는 기존 조사 처리 코드(`eunNeun` 등)를 재사용해 자동 선택**한다.
- 착수 시 확인: 날씨가 비일 때(1턴 발사)는 기존 동작 유지, 차지 문구가 다른 차지형 기술(솔라빔 등)의 1턴째 로그와 같은 경로를 쓰는지, 일렉트로빔 외 "차지 1턴째에 능력치가 오르는" 다른 기술에도 같은 로그 공백이 있는지 함께 점검.

## B2. 프리즈드라이 상성 버그 수정

- 사용자 보고(2026-10-05): 물/풀·물/비행·물/땅·물/드래곤 상대에게 프리즈드라이가 4배여야 하는데 2배만 들어가는 것 같다. 본가 상성: 2배 — 물·드래곤·땅·비행·풀 / 반감 — 강철·불꽃·얼음 / 나머지 1배.
- 확인(2026-10-05, 엔진 실행으로 재현): **상대에 물타입이 있으면 상성 전체를 2배로 고정**한다. 물이 아닌 다른 타입의 상성은 곱하지 않는다.

  | 상대 타입 | 엔진 | 본가 기준 |
  |---|---|---|
  | 물 | 2배 | 2배 |
  | 물/풀·물/비행·물/땅·물/드래곤 | 2배 | **4배** |
  | 물/불꽃·물/얼음·물/강철 | 2배 | **1배** |
  | 물/독·물/에스퍼 | 2배 | 2배 |

  물이 아닌 상대(풀 2배, 드래곤/땅 4배 등)는 정상.
- 원인: `src/lib/moveContext.ts`의 `typeEffectivenessOverride`가 `defenderTypes.includes(물)`이면 `effectiveness`(2)를 **전체 배율로 대체**한다. 데이터(`moves.json`의 `overridesTypeEffectivenessFor: { type: "물", effectiveness: 2 }`)는 "물타입 칸을 2배로 친다"는 뜻이라 그대로 두면 된다.
- 수정 방향: 상대 타입별로 곱하되 `overridesTypeEffectivenessFor.type`에 해당하는 칸만 `effectiveness`로 치환하고 나머지 타입은 타입표대로 곱한다. 면역 우선(저수 등 `absorbedByDefenderAbility`·`grantsImmunity`) 가드는 유지. 이 필드를 쓰는 곳이 `moveContext.ts` 한 곳뿐이라 배틀·결정력·AI가 같이 바로잡힐 것으로 보이나 착수 시 확인.
- 검증 방법: 위 표를 재현 스크립트로 돌려 전 케이스 일치 확인(+ `test:ai`).

## X1. [상시 수정] 상대 실능치 역산 검증·수정

- 사용자 보고(2026-10-02): **방어력 계수 측정 결과가 이래저래 실제와 다르다.** 기능을 더 확장(C2)하기 전에 정확도부터 검증해야 한다. 사용자가 몇 번 더 써 보며 검수하고, 그 결과를 이 항목에 쌓아 고친다.
- **상시 수정 항목**: 한 버전에서 끝내지 않고 **다음 버전 백로그에도 계속 올린다**(검증·수정이 끝났다고 사용자가 판단할 때까지).
- 진행 방식(안):
  1. 사용자가 어긋난 사례를 모은다 — 내 포켓몬·기술·급소 여부·상대 포켓몬·화면 % 전/후·결과(범위가 어떻게 나왔는지 / 실제 알고 있던 배분).
  2. 같은 상황을 엔진 공식·화면 수치와 대조해 원인을 가른다: 입력 문제(급소·날씨·필드·랭크·벽 누락) / 가정 문제(%올림, 한 번만 내림, 열매·특성) / 공식 차이.
  3. 고친 뒤 `defense-inference-check.mjs`(공식 대조·왕복)에 사례를 회귀 케이스로 추가.
- **알려진 가정(검증 대상)**: 역산의 화면 % **올림 가정**(`displayPercent` 한 곳)은 실사용 관측으로 확인 대기. 이 앱의 데미지 공식은 보정 곱 뒤 **한 번만 내림** — 챔피언스 실제 방식은 미확인. 어긋남의 1순위 용의자.
- 검증 기준선: 현재 `test:inference` — 공식 대조 1200건, 왕복 126/126, 메가 왕복 49/49 통과(코드상 일관성은 맞고, 실제 게임과의 차이는 이 검증으로 못 잡음).

## L1~L7. 이전 버전에서 넘어온 한계·가정

각 항목은 사용자가 필요하다고 할 때 착수한다. 자세한 맥락은 `2.2-backlog.md`(L1~L5)·`2.3-backlog.md`(L6·L7) 마무리 절 참고.

- **L1 C3**: 메가 전 반감 열매 가정과 메가진화 후 관측 사이의 전환(관측 도중 메가) 미지원.
- **L2 F1**: 적응력(자속 2배)·스킨 계열 특성과 리베로•변환자재 토글 조합 미확인.
- **L3 E1**: 위기회피 발동 피격에서 못 나갈 때(예비 없음·봉인) 열매가 정상 발동한다는 부분은 가정.
- **L4 B2**: 선출 매 판 재선택, 새로고침 시 진행 소실, 상대 수동 변경 시 결과 라벨 불일치, AI 대 AI 자동 연속 대전 없음.
- **L5 B6**: 보충 사실을 화면에 알리지 않음.
- **L6 2.3 B2**: 상대 정보 숨김(도구·실능치·파티 트래커)이 전부 `aiSide` 단일 값(어느 한쪽이 AI인지)을 전제로 분기한다. L4의 AI 대 AI 연속 대전이 생기면 "상대"가 모호해지므로 이 숨김 로직을 재검토해야 한다.
- **L7 2.3 B4**: 탈 발동 상대에게 유턴류를 써도 교체되도록 고쳤지만(PR #213), 대타에 막힌 유턴류 등 "데미지는 막히나 명중은 한" 다른 경우는 코드 읽기로만 확인했었다. **확인 완료(2026-10-05, 사용자): 대타를 쓴 상대에게 유턴을 써도 교체 UI가 정상 동작한다.** 더 할 일 없음.
