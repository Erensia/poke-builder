# ver.8.1 백로그

**초안(2026-11-10) — 범위는 사용자가 항목마다 확정한다.** 8.1은 **일반 버전**이다: 8.0 F1 점검에서 나온 체감 불편 3건(슬라이더·프리셋 모션·모바일 세로 배치)과 그동안 미뤄 온 UI·접근성 한계를 풀고, 8.3(AI·엔진 전용)이 쓸 규칙 조사·측정을 미리 해 둔다. 항목은 `8.0-backlog.md`의 "8.1 후보"(U1~U5·S1·S2)를 옮겨 오고 8.0 F1 결과(U6~U8)를 더했다. 번호는 `8.0-backlog.md` 한계 총괄표와 이어지도록 그대로 쓴다.

### U6 결과 (2026-11-10, #452)
- **8.0 회귀가 아니다**: 슬라이더 경로 파일(`PointsEditorModal`·`useParty`·`storage`·`App`·`PartyPage`)은 7.7 대비 변경 0건이었다. 7.7 이전부터 있던 구조다.
- **주원인 — 막대 `transition`**: `.points-slider-fill { transition: width 0.08s linear }`가 값이 바뀔 때마다 목표 위치를 80ms 늦게 쫓아와 막대가 마우스보다 느려 보였다. 개발 서버·프로덕션·배포본 모두 같았고, 제거 뒤 사용자가 "확실히 나아졌다"고 확인했다.
- **부원인 — 헛 상태 갱신**: `setAbilityPointOnSlot`이 값이 그대로여도 새 객체를 돌려줘 `pointermove`마다 `setSlots`·전체 리렌더·`localStorage` 저장이 반복됐다(드래그 1회 251회 → 32회). 값이 그대로면 같은 참조를 돌려주도록 고쳤다(`stepAbilityPointOnSlot`과 동일).
- **얻은 규칙**: ① 처음엔 `transition 0.08s`를 "작다"고 넘기고 렌더 비용부터 의심했다 — **환경(개발·프로덕션·배포본)을 가리지 않고 똑같이 느리면 렌더 비용이 아니라 CSS 시각 지연부터 본다.** ② 코드로 지목한 원인은 사용자 화면에서 확인될 때까지 확정하지 않는다(이번에도 첫 수정만으로는 체감이 안 달라졌다). ③ 서버 렌더링으로 렌더 비용을 재려던 시도는 `CloudBackup`의 `useSyncExternalStore`(서버 스냅샷 없음) 때문에 막혔다 — 이 앱의 컴포넌트는 `renderToString`으로 바로 재지 못한다.
- **하지 않은 것**: 파티 저장 디바운스, `startTransition`으로 파티 갱신 미루기 — 원인이 `transition`으로 확인돼 불필요. 다시 느려지면 그때 렌더 비용을 계측한다.

### U6 설계 — 먼저 진단, 그다음 수정 (진행 전 계획, 위 "U6 결과"가 최종)
코드 확인(2026-11-10): 슬라이더(`PointsEditorModal.tsx`의 `PointsSlider`)는 `pointermove`마다 `onSet`을 불러 파티 상태를 바꾸고, `useParty`의 effect가 슬롯이 바뀔 때마다 `saveParty`로 `localStorage`에 **동기 저장**한다(`useParty.ts:21`). 채움 막대는 `transition: width 0.08s linear`(`PointsEditorModal.css:129`).
1. **8.0 변경인지 가른다**(사용자): 배포본(7.7 시점 Vercel 주소)과 로컬 8.0 두 창에서 같은 슬롯·같은 드래그를 해 보고 똑같이 느린지 본다. 7.7에서도 같으면 리팩토링 탓이 아니다(8.0은 `PointsEditorModal`·`useParty`를 건드리지 않았다).
2. **원인 확정**(사용자 Chrome Performance 녹화 또는 Claude가 `console.time` 임시 계측 코드를 줘서 값만 보고): 후보는 ① 저장(직렬화 + `setItem`) ② 파티 전체 재렌더·재계산(6슬롯 실수치·계산 탭 공유 상태) ③ `transition`.
3. **수정안(원인에 따라 하나만)**: 드래그 중에는 슬라이더 값을 컴포넌트 로컬로 두고 `pointerup`(또는 `requestAnimationFrame`당 1회)에만 파티 상태에 반영 / 파티 저장을 디바운스하되 **`pagehide`·`visibilitychange`에서 반드시 플러시**(사용자가 파티 자동저장을 두 번 잃은 이력이 있다 — 새로고침·탭 닫기 직전 유실이 없어야 한다). 저장 키·형식은 불변.
4. **완료 기준**: 같은 드래그의 체감이 7.7 이하, 새로고침 뒤 마지막 값이 남아 있음.

### U7 선택지 — 사용자 결정
`usePop`(`src/hooks/usePop.ts`, 6.5 M1 D)이 슬롯의 포켓몬 ID를 이전 값과 비교해 **바뀐 카드에만** `card-pop`을 붙인다. 같은 포켓몬이 같은 칸에 다시 들어오면 모션이 없다.
- **A. 현행 유지** — 비교 방식이 "무엇이 바뀌었는지"를 보여 주는 의도. 코드 변경 0, 문서에 의도를 남기고 닫는다.
- **B. 불러오기 때만 6칸 전부 팝**(권장 후보) — 프리셋을 불러왔다는 신호가 한눈에 보인다. 신호(예: 불러오기 횟수 카운터)를 `usePop`에 값으로 넘겨 키를 바꾸는 방식이 가장 작다. 동작 줄이기에서는 생략(기존 규칙).
- **C. 모션 없이 즉시 교체** — 불러오기만 조용히. 다른 편집(포켓몬 고르기)의 모션과 일관성이 깨진다.
