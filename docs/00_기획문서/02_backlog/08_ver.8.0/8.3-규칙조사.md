# ver.8.3 규칙 조사 (8.1 S1)

**작성 2026-11-10(초안) — 읽기 전용 문서다. 코드는 바꾸지 않았다.** 8.3(AI·엔진 전용)은 항목마다 **본가 규칙을 먼저 확정**하고 시작한다. 이 문서는 8.3 후보마다 ① 지금 엔진이 어떻게 동작하는지(코드 위치) ② 자료로 확인한 내용(신뢰도 표시) ③ 사용자가 확정해 줄 질문을 모아 둔 것이다.

## 이 문서를 쓰는 법
- **질문(Q)마다 사용자가 한 줄로 답하면** 그 답을 "확정" 칸에 옮기고 8.3 백로그의 해당 항목 사양으로 쓴다. 모르면 "본가 그대로"나 "현재 유지"라고만 해도 된다.
- 신뢰도 표시: **[데이터]** 이 앱의 `src/data` 원문 · **[코드]** 현재 엔진을 읽어 확인 · **[재현]** 엔진을 직접 돌려 확인 · **[자료]** 웹 검색 요약(Bulbapedia·Smogon 등, 세대별로 다를 수 있음) · **[기억]** 모델 기억이라 검증 안 됨.
- **한계**: 규칙의 기준은 **포켓몬 챔피언스**(이 앱이 시뮬레이션하는 게임)인데, 챔피언스 전용 기술 페이지(`pokemon-zone.com/champions/...`)는 자동 접근이 막혀(403) 읽지 못했다. Bulbapedia 본문도 검색 발췌만 읽었다. 그래서 **본가(주로 9세대) 규칙이 챔피언스에 그대로 적용되는지는 사용자 확인이 필요**하다.

## R1. 돌림노래
- **[데이터]** "노래로 상대를 공격한다. 함께 돌림노래를 하면 계속해서 쓸 수 있고 위력도 2배로 올라간다." 위력 60.
- **현재 엔진 [코드]** `preHitEffects.ts:903` — **직전 턴에도 같은 포켓몬이 썼으면** 위력을 2배씩 올린다(60→120→상한 200). `echoStreak`에 "마지막으로 쓴 턴·연속 횟수"를 저장. **같은 턴에 상대(또는 다른 포켓몬)가 먼저 쓴 돌림노래는 세지 않는다.** AI도 연쇄를 평가에 넣지 않는다(6.3).
- **자료 [자료]** Bulbapedia(Round) 발췌: "같은 턴에 먼저 쓴 돌림노래가 있으면 뒤의 돌림노래는 위력이 60→120이 되고, 속도와 무관하게 먼저 쓴 직후에 행동한다." 설명은 주로 아군(더블)을 예로 든다. **싱글에서 상대의 돌림노래가 포함되는지는 발췌에서 확정하지 못했다.** 같은 포켓몬이 연속 턴에 써서 2배가 된다는 설명은 발췌에 **없다** → 현재 엔진 방식이 본가 규칙이 아닐 가능성이 크다. (Showdown 구현은 "다른 포켓몬 누구든 먼저 쓴 돌림노래"를 기준으로 한다고 기억하지만 **[기억]**이다.)
- **질문**
  - Q1-1. 챔피언스 싱글 대전에서 **상대(AI)도 같은 턴에 돌림노래를 쓰면** 뒤에 쓴 쪽 위력이 2배가 되나?
  - Q1-2. 그렇다면 현재의 "연속 턴 사용" 방식은 **없애도** 되나?
  - Q1-3. 뒤에 쓴 쪽이 **행동 순서도 앞당겨지나**(속도 무시), 아니면 위력만 2배인가? (순서까지 구현하면 `runTurn` 행동 순서 결정에 손을 대야 해서 범위가 커진다.)
- **8.3 영향**: 엔진(위력·필요 시 순서) + AI 평가(연쇄 반영) → `verify-kit` 기준값 갱신.

## R2. 사이코노이즈(회복 봉인)·지옥찌르기
- **[데이터]** 사이코노이즈(에스퍼 특수 75): "불쾌한 음파를 상대에게 날려서 공격한다. **2턴 동안 상대는 기술이나 특성 또는 지니고 있는 도구로 HP를 회복할 수 없다.**" `healBlock` 상태 2턴을 건다. 지옥찌르기(악 물리 80): "2턴 동안 소리 기술을 낼 수 없다." `throatChop` 상태. 회복봉인이라는 기술 자체는 데이터에 **없다**(상태는 사이코노이즈만 건다).
- **현재 엔진 [코드]** `healBlock`이 막는 것: 회복 **기술** 사용(`preHitEffects.ts:377`), 그래스필드 회복·먹다남은음식(`finishTurn.ts:62·72`)·날씨 회복 특성(`:97`)·뿌리박기·아쿠아링 회복(`:152`)·씨뿌리기 흡수(`:182`). 카운터는 턴 종료마다 줄어 0에서 해제(`:241`). **막지 않는 것(6.3 문서)**: **나무열매 회복**. 지옥찌르기는 소리 기술 사용을 막는다(`preHitEffects.ts:378`) — 자료와 일치.
- **자료 [자료]** Psychic Noise: 2턴, **재사용해도 지속 시간이 갱신되지 않는다**, 추가 효과라 인분(Shield Dust)이 막고 우격다짐(Sheer Force)이 억제한다. Throat Chop: 소리 기술 2턴 봉인(회복과 무관). Heal Block(4세대): 먹다남은음식·검은진흙·조개껍질방울을 막고 **회복 나무열매는 먹지 않는다** — 이후 세대는 확인 못 함.
- **질문**
  - Q2-1. 이 앱 문구가 "도구로도 회복 못 한다"인데, **HP 회복 나무열매(오랭·자뭉 등)와 조개껍질방울**도 막아야 하나? (지금은 먹다남은음식만 막고 열매는 못 막는다.)
  - Q2-2. **흡수 기술**(기가드레인 등)의 회복은 막나? (코드 미확인 — 8.3 착수 때 확인)
  - Q2-3. 사이코노이즈를 봉인 중에 다시 맞히면 **지속 시간이 갱신되지 않는** 규칙을 넣나? (지금 동작은 코드 미확인)
  - Q2-4. AI 평가에 이 봉인을 반영할지(회복 기술·열매에 의존하는 상대에게 가치가 있고, 지옥찌르기는 소리 기술 보유 상대에게 가치가 있다)? 지금은 "걸린 뒤 못 쓰는 기술만 피한다".
- **8.3 영향**: 엔진(열매 소비 분기)·AI 평가.

## R3. 미래예지
- **[데이터]** 에스퍼 특수 120. "기술을 사용한 2턴 뒤에 상대에게 염동력의 덩어리를 보내어 공격한다. 방어 계열 기술을 무시한다."
- **현재 엔진 [코드]** `finishTurn.ts:220 applyFutureSight` — 쓴 시점의 `realStats`·`types`·`stages`를 **스냅샷**으로 저장(`side.futureSight`), 카운터 0이 되는 턴 종료에 **그 자리의 포켓몬**을 타격한다. 방어·대타 무시, 타입 상성만 적용, 특성·도구 보정 없음. 그 자리가 기절해 있으면 무효. 턴 종료 처리 안의 위치는 먹다남은음식·날씨 회복 뒤, 씨뿌리기 앞(`:789`). AI는 모으기와 같은 비용으로 센다.
- **자료 [자료]** Bulbapedia(Future Sight) 발췌: 방어류·버티기에 영향받지 않는다. **데미지는 선택한 시점이 아니라 맞는 시점에 계산**하며 사용자의 특공과 대상의 특방을 그때 값으로 쓴다. 사용자가 필드에 없으면 **특성·도구는 적용되지 않는다**(엔진과 일치). 생명의구슬 적용은 자료가 엇갈린다. **대타·매직가드와의 상호작용, "언제 맞는가"는 자료에서도 미확정**이라고 표기돼 있다.
- **질문**
  - Q3-1. 계산 시점: **쓴 시점 스냅샷**(현재 엔진)과 **맞는 시점의 능력치**(자료 쪽) 중 챔피언스는 어느 쪽인가? (예: 쓴 뒤 칼춤·교체가 있으면 결과가 달라진다.)
  - Q3-2. 대타 뒤에 있는 상대는 정말 무시하고 맞히나?(현재 무시)
  - Q3-3. 맞는 시점에 상대의 랭크·날씨·필드·도구는 반영되나? (현재: 상대 랭크는 맞는 시점 `fighter.stages`, 날씨·필드·도구는 미반영)
  - Q3-4. 턴 종료 처리 안의 위치(R6 순서 정리와 함께 확정).
- **8.3 영향**: 엔진(계산 시점)·AI 평가·시나리오.

## R6. 턴 종료 순서 — 희망사항·먹다남은음식·미래예지
- **현재 엔진 [코드]** `finishTurn.ts:785~` 포켓몬마다 순서대로: 멸망의노래 → 특성 면역 해제 → 필드 회복 → **먹다남은음식** → 날씨 회복 특성 → 날씨 피해 특성 → 뿌리박기·아쿠아링 → **미래예지** → 씨뿌리기 → 저주 → 속박 → 소금절이 → 물엿범벅 → 문어굳히기 → **희망사항** → 봉인 상태 카운트 → 졸음 → 모래바람 피해 → 상태이상 틱. 즉 **희망사항이 먹다남은음식보다 뒤**다.
- **사용자 제보 [7.4 조사]** 블래키가 희망사항을 쓴 다음 턴 끝에 먹다남은음식으로 HP가 가득 찬 뒤 희망사항이 회복 0이 되어 로그 줄도 안 남았다. 사용자 선호: **희망사항을 먹다남은음식보다 먼저, 회복 0이어도 로그 한 줄.**
- **자료 [자료]** 목록마다 달라 정확한 위치는 미확정: Smogon의 7세대 개정 목록은 **미래공격(미래예지·파멸의소원) → 희망사항** 순이고(3·4번째), 4세대 목록은 희망사항이 날씨 메시지·먹다남은음식보다 앞이다. **두 목록 모두 희망사항이 먹다남은음식보다 앞**이다. 미래예지와 먹다남은음식의 상대 순서는 세대별로 다르다. 9세대(챔피언스 기준) 정확한 목록은 확인하지 못했다.
- **질문**
  - Q6-1. 희망사항을 **먹다남은음식 바로 앞**(필드 회복 다음)으로 올리는 최소 변경으로 충분한가, 더 앞(날씨 메시지·미래예지 앞)까지 올리나?
  - Q6-2. 미래예지도 먹다남은음식보다 앞당기나? (자료상 7세대 목록은 미래공격이 먼저)
  - Q6-3. 회복이 0이어도 남길 **로그 문구**("희망사항이 이루어졌지만 회복할 HP가 없었다" 등)를 정해 주면 좋다.
  - Q6-4. 순서 변경이 엔진 출력 전체에 영향을 줄 수 있으니(`regress` 해시 변경), 한 PR에서 순서만 바꾸고 기준값을 갱신하는 방식으로 진행해도 되나?
- **8.3 영향**: 엔진(턴 종료 순서)·로그 문구 → 기준값 갱신.

## R7. 방어류 연속 사용·마지막 행동 실패 범위
- **현재 엔진 [코드]** `mirroredEffects.ts:1656~` `protectAndFieldSetup`: `protectEffect`가 있는 **모든 기술**(방어·판별·킹실드·버티기·패스트가드·길동무 등)이 `protectStreak` **하나를 공유**하고, 성공 확률은 (1/3)^연속 횟수다. **내가 이번 턴 마지막에 행동하면 방어·판별·킹실드(`block`)만 실패**하고 연속 횟수가 0으로 돌아간다(7.3 B2, 사용자 확정). 버티기·길동무·패스트가드는 이 실패에서 **제외**(사용자 결정 2026-11-05).
