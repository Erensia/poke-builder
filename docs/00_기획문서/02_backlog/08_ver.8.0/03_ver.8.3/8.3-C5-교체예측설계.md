## 0. 요약

- **지금 AI가 상대 교체를 보는 곳**: ① 탐색(`search.ts`)은 상대 행동 후보에 교체를 `opponentSwitchWeight`(0.5)로 섞고 롤아웃이 엔진 `runTurn`을 그대로 돌리므로 **앱 AI(`APP_DECISION_PARAMS`, 탐색 켬)는 교체 턴을 이미 반영**한다. ② 상대 모델이 켜진 프로필은 `attachSwitchRead`가 교체 확률 q ≥ 0.3일 때 공격기 점수를 들어올 포켓몬 기준과 섞는다(교체 읽기).
- **안 보는 곳**: 탐색이 꺼진 기본 AI의 방어류 평가(`evaluateProtectMove`)는 상대 행동 혼합이 **기술만**(`opponentActionMix`)이고 교체가 없다. 8.3 A5 이후 "상대가 교체한 턴에 내가 마지막이라 방어가 실패"가 엔진 규칙이므로(7.3 B2 + A5), 이 평가는 상대가 교체할 확률만큼 방어를 **과대평가**한다.
- **7.3 측정(보류 근거)**: 방어류 `block` 사용 중 같은 턴에 상대가 교체해 실패한 비율 — 기본 AI 300판 80회 중 15회(18.8%, 전체 5,421턴의 0.3%), 앱 AI 40판 32회 중 4회(12.5%, 전체 803턴의 0.5%). 판당 0.1회 수준.
- **제안**: 코드 착수 전에 **M0 측정으로 현재 손해를 다시 잰다**(A5로 방어 규칙이 바뀌었고 기준 출력도 여러 번 바뀌었다). 손해가 측정 오차 안이면 **측정 근거를 적고 C5를 폐기한다.** 의미 있는 손해가 나오면 §3의 최소 수정 하나만 한다. **M0 대상은 상대 모델 켬 + 탐색 끔 프로필뿐이다**(검수 반영).

## 2. 규칙 근거

- 상대가 교체한 턴 방어류 실패(마지막에 행동하면 실패)는 이미 엔진 규칙이다(7.3 B2, 8.3 A5 — Showdown 대조 완료). C5는 **규칙을 바꾸지 않고 AI의 평가만** 맞춘다. 따라서 Showdown 검수 대상이 아니다.
- 상대 교체 확률 q의 출처: 상대 모델이 켜진 프로필은 `levelOneDistribution`이 이미 `dist.switchProb`를 낸다(탐색·교체 읽기가 쓰는 값). **새 모델을 만들지 않는다.** 상대 모델이 꺼진 프로필은 q를 알 수 없다 → §7 Q2.

## 3. 설계 (M0가 진행 판정일 때만)

1. `protectValue`(`decision.ts:535`)를 `(1 − q) · [성공확률 · success + (1 − 성공확률) · fail] + q · 0`으로 바꾼다. q = 상대가 이번 턴 교체할 확률(`dist.switchProb`). 교체 턴은 방어가 실패하지만 **맞지 않으므로** 값 0의 별도 갈래이고, 기존 `fail`(맞는 대면)에 섞지 않는다. q를 그대로 곱한다(임계 없음, Q6).
2. `OpponentThreat`에 `switchProb` 한 필드를 더하고 `chooseAiAction`의 `withThreatOverride` 자리에서 채운다(없으면 0 = 현행). `ProtectEvaluation`에 이 값을 실어 `protectValue`가 읽는다.
3. **적용 그룹: `block`(방어·판별·킹실드류)·`priorityGuard`(패스트가드)·`endure`(버티기). 길동무(`destinyBond`)·`punish`가 아닌 길동무는 제외** — Showdown에 마지막-행동 실패 검사가 없어 교체 턴에도 성공하고 예약이 남는다. (`punish`는 `block`과 같은 검사를 쓰므로 포함, 구현 때 `protectGroupOf`로 확인.)
4. 탐색 경로(`searchDecide`)는 이미 교체를 섞으므로 **건드리지 않는다**(이중 반영 방지 — 시험 C5-d).
5. **속박·교체 후보 없음은 코드 변경 없음**(Q5): q가 이미 0이 된다. 시험만 추가.
6. 와이드가드는 없다(싱글배틀).
