## 3. 엔진 설계

### 3-1. 타입 (`src/types/battle.ts`)

```ts
/** 교체로 등장한 포켓몬에게 발동한 설치물(8.3 B2) — 문구(entryMessages)와 별개로 화면 연출이 읽는 구조화 정보. 문구가 나오는 때와 1:1이다 */
export type EntryHazardTrigger = "stealthRock" | "spikes" | "toxicSpikes" | "stickyWeb" | "toxicSpikesAbsorbed";
```

`SwitchLogEntry`에 `hazardTriggers?: EntryHazardTrigger[]` 추가(발동이 하나도 없으면 키 없음). `entryMessages` 주석에 "설치물 발동은 `hazardTriggers`에도 있다"를 덧붙인다. `ApplySwitchOutcome`(`switching.ts:564`)에도 `hazardTriggers: EntryHazardTrigger[]`를 추가한다(이쪽은 항상 배열 — 아래 3-4의 도우미가 키 생략을 맡는다).

### 3-2. 발생 지점 (`switching.ts` `applyEntryHazardsOnSwitchIn`)

반환형을 `void` → `EntryHazardTrigger[]`로 바꾸고, `const hits: EntryHazardTrigger[] = []`를 만든 뒤 **각 `log.push` 바로 옆에서** 하나씩 `hits.push`한다. 대응표(현행 문구 조각 → 이벤트):

| `log.push` 위치 | 문구 | 이벤트 | 옛 화면 판별 |
|---|---|---|---|
| `:157` 독타입 등장 | `…독압정을 흡수했다!` | `toxicSpikesAbsorbed` | `includes("독압정을 흡수")` → "독압정 제거!" 팝업 |
| `:164` 스텔스록 | `뾰족한 바위가 …덮쳤다! (n 데미지)` | `stealthRock` | `HAZARD_TRIGGERS` "뾰족한 바위" |
| `:175` 압정뿌리기 | `…압정에 상처를 입었다! (n 데미지)` | `spikes` | "압정에 상처" |
| `:188~192` 독압정 | `…몸에 독이 퍼졌다!` / `…몸에 맹독이 퍼졌다!` | `toxicSpikes` | "몸에 독이 퍼졌다"·"몸에 맹독이 퍼졌다" |
| `:199` 끈적끈적네트 | `…끈적끈적네트에 걸려 스피드가 떨어졌다!` | `stickyWeb` | "끈적끈적네트에 걸려" |

세 곳의 조기 반환(`isFainted(self)` 시작·스텔스록 뒤·압정 뒤)은 `return hits`로 바꾼다. 조건·순서·문구·상태 변경 코드는 한 줄도 건드리지 않는다.

### 3-3. 전달 길 (반환값)

- `runEntryEffects`(`:540`): `const hits = applyEntryHazardsOnSwitchIn(...)`로 받아 마지막에 `return hits`(나머지 4단계는 그대로).
- `performSwitch`(`:376`): 반환형 `void` → `EntryHazardTrigger[]`. 조기 반환(`:385`)은 `[]`, 끝은 `return deferEntry ? [] : runEntryEffects(state, key, log)`. 다른 호출자(`applySwitch` 외)가 반환값을 무시해도 동작은 같다.
- `runTurn.ts:655`(동시 교체 2단계)는 `runEntryEffects`의 반환값을 받아 해당 교체 기록에 채운다(3-4).

### 3-4. 교체 기록을 만드는 5곳

공통 도우미 한 줄(`switching.ts`에 두고 내보낸다): `const hazardField = (hits: EntryHazardTrigger[]) => (hits.length ? { hazardTriggers: hits } : {})` — 비었을 때 키를 두지 않기(Q3)를 한 곳에 모은다.

| 곳 | 바꾸는 법 |
|---|---|
| ① `runTurn.ts:150` 일반 교체 | `const hits = performSwitch(...)` → 기록에 `...hazardField(hits)` |
| ② `runTurn.ts:595` `performChoice` | 반환형을 `string[] \| undefined` → **`SwitchLogEntry \| undefined`**로. 비지연이면 `performSwitch` 반환값을 `...hazardField(hits)`로 기록에 넣는다. `executeChoices`(`:635`)는 `entry.entryMessages`를 `msgs` 대신 쓰고, 동시 교체 2단계에서 `const hits = runEntryEffects(ctx.state, key, entry.entryMessages); if (hits.length) entry.hazardTriggers = hits` |
| ③ `switching.ts:578` `forceRandomSwitch` | ①과 같다 |
| ④ `applySwitch`(`:614`) | `const hazardTriggers = performSwitch(...)` → 결과 객체에 `hazardTriggers`(항상 배열). 화면 `useBattleLogSession.ts:284~291`이 `forcedSwitchLogEntry`로 넘기고, `forcedSwitchLogEntry`(`battleSessionHelpers.ts:97`)가 `...hazardField(applied.hazardTriggers)`로 합성 카드에 넣는다. `Pick<ReturnType<typeof applySwitch>, …>`에 `"hazardTriggers"`를 더한다 |
| ⑤ `battle-ai-sim.mjs:274` | `uiLog` 수동 조립에 `hazardTriggers: applied.hazardTriggers` 한 줄(시험 도구의 `logidx` 점검이 쓰는 로그가 화면 로그와 같은 모양을 유지하게 — 점검 로직 자체는 안 바뀜) |

AI 코드(`levelOne.ts:94`·`search.ts:194`)는 `applySwitch(...).nextState`만 쓰므로 영향 없다.

## 4. 화면 설계

- `turnFxSchedule.ts:65`: `messages: sw.entryMessages` → `hazards: sw.hazardTriggers ?? []`(반환 객체는 별도 타입 없이 추론되므로 타입 수정은 없다).
- `useTurnFx.ts:113`: `hazardHit(sw.side, sw.hazards, …)`.
- `turnFxPrimitives.ts`: `HAZARD_TRIGGERS`(문구 표)와 `:211`의 `includes("독압정을 흡수")`를 지운다. `hazardHit(who, hits, delay)`는 이벤트마다 같은 연출을 낸다 — `stealthRock`→`HAZARD.stealth`, `spikes`→`HAZARD.spikes`, `toxicSpikes`→`HAZARD.toxic`, `stickyWeb`→`HAZARD.web`(번쩍임 0.6·흔들림 4·이름 팝업, **기존과 같은 값**), `toxicSpikesAbsorbed`→"독압정 제거!" 팝업(기존과 같은 값·색). 이벤트→`HAZARD` 키 매핑은 4줄 객체 하나. 같은 종류가 두 번 들어와도 한 번만 연출하던 기존 동작(`Set`)은 이벤트가 종류당 최대 한 번이라 필요 없다.
- 연출의 타이밍·모양·색·팝업 문구는 **바꾸지 않는다.** UI 신기능(데미지 팝업 등)도 넣지 않는다.
- 로그 줄(`SwitchLines.tsx`·`EndOfTurnLines.tsx`)은 `entryMessages`를 그대로 그린다 — 변경 없음.

- **문구 판별과 필드의 일치**: `regress 200`(과 가능하면 20000)의 모든 교체 기록(`trace`·`uiLog`)에서, **옛 판별**(`HAZARD_TRIGGERS`+`"독압정을 흡수"`로 `entryMessages` 검색)의 결과 집합과 `hazardTriggers` 집합이 **전부 같은지**. 불일치 0이면 연출이 바뀌지 않는다는 증거다. 표본에 설치물이 거의 없으면 설치기를 가진 파티로 늘려 돌린다.
- 기존 시험 전체(`npm run test:ai`) ALL PASS, `npx tsc -b`·`npx oxlint`·`npm run build`.

## 6. 해시·검증 예상

**예상: 필드를 더하는 것만으로 `regress 200`·`regress 20000` 해시가 바뀔 수 있다**(C6 — `trace` JSON에 `hazardTriggers`가 들어가므로, 표본 안에 설치물 발동 교체가 있으면 바뀐다). 안 바뀌면 그 표본에 발동이 없었다는 뜻이다. `greedy120`·`status60`·`h2h40`·`ai60`·`test:inference` 결합·차분 해시는 `TurnResult` 전체를 해시하지 않으므로 **불변 예상**이다. **A4·A5 때 해시 불변 예상이 두 번 틀렸으므로(인계 교훈) 단계별로 측정하고 예상을 믿지 않는다.**
