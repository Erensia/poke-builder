# 8.3 C4 — 랜덤 구축 `MAX_MEGAS` 2 휴리스틱 설계서

**작성 2026-11-13(집 PC).** 출발점: `dev` `ef8e0b6`. 근거: `5.1-backlog.md` A3("`MAX_MEGAS` 2 유지", 이유만 적고 상한 자체는 안 쟀음), `8.0-backlog.md` 이월, 코드 `src/lib/randomSlotParty.ts`·`ai/rankProfile.ts`(`pickRankOpponent`). 코드 변경 없는 판정 항목이다. CLAUDE.md "버전 작업 절차 2단계"에 따라 **이 문서를 커밋하고 사용자 검수(§4)를 받아 확정**한다.

## 1. 무엇을 정하는가
랜덤 구축(① 랭크 AI 상대 — 등급 샘플 슬롯 풀에서 6마리, ② 사용자 "랜덤 구축" — 저장 슬롯 + 샘플 보충)은 메가진화 포켓몬을 **최대 2마리**로 제한한다. 이는 파티 규칙(메가 수 제한 없음)이 아니라 생성 휴리스틱이다. 5.1에서는 "배틀에서 메가는 편당 한 번이라 세 번째는 선택지일 뿐"이라는 이유로 유지했다. **상한이 실제로 얼마나 걸리고 어떤 분포를 만드는지는 재지 않았다.** 이번에 재서 유지·변경·폐지를 정한다.

## 2. 측정 (2026-11-13, 일회용 스크립트 — 커밋하지 않고 삭제)
등급 구분 없이 샘플 파티 68개의 슬롯 408개(메가 슬롯 99개)를 한 풀로 두고, 같은 규칙(중복 포켓몬·도구 금지)·같은 셔플로 **상한 없음 대 상한 2**를 2만 번씩 비교했다.

| 항목 | 값 |
|---|---|
| 샘플 파티의 메가 수 분포(68개) | 0마리 9 · 1마리 21 · **2마리 36** · 3마리 2 · 4마리 이상 **0** |
| 상한 없는 랜덤 구축의 메가 수 분포 | 0:10.3% · 1:32.9% · 2:36.2% · **3+:20.6%**(3:16.7%, 4:3.6%, 5:0.3%) |
| 상한이 결과를 바꾼 구축 비율 | **20.5%** |
| 상한 2 랜덤 구축의 메가 수 분포 | 0:10% · 1:33% · 2:57% |

해석: 샘플 파티(사람이 만든 파티)는 메가 3마리가 3%(2/68), 4마리 이상이 0이다. 상한을 없애면 랜덤 구축의 **5분의 1이 메가 3마리 이상**이 되어 샘플과 동떨어진다. 상한 2의 분포(0·1·2 = 10·33·57%)는 샘플(13·31·53% + 3마리 3%)과 거의 같다.

## 3. 제안
- **`MAX_MEGAS` 2 유지**(코드 변경 없음). 근거: 상한이 5분의 1의 구축에서 실제로 걸리고, 걸린 결과가 샘플 분포에 가장 가깝다. 상한을 3으로 올리면 3마리 구축이 약 17%로 샘플(3%)의 5배가 된다.
- 상한을 규칙에 맞춰 없애는 안은 **버린다**: 랜덤 구축 난이도(5.1 A3: 하 56.3·중 50.0·상 52.9%, 샘플 평균 수준)를 건드리고 메가 편중 파티가 늘어난다. 난이도를 다시 재야 하는 비용이 크다.
- 이로써 사용자 화면 안내("메가진화 포켓몬은 최대 2마리", 5.0 #317)·`randomSlotParty.ts` 주석("규칙 위반이 아닌 생성 휴리스틱")도 **그대로 맞다.**
- 한계: 측정은 등급 구분 없는 전체 풀이다(등급별 풀은 슬롯 수가 달라 비율이 조금 다를 수 있으나 결론은 같다고 본다). 상한의 승률 영향은 재지 않았다(분포 근거로 충분하다고 판단 — 승률이 필요하면 `partyvs`로 별도 측정).
