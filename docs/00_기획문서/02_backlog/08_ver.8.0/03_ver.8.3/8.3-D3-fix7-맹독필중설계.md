## 1. 무엇이 틀렸나
| 항목 | Showdown(champions) | 엔진 현재 |
|---|---|---|
| 독 타입이 쓰는 맹독 | 필중(명중 판정·회피 랭크·반짝가루 등 전부 무시) | 명중 90에 랭크·보정이 그대로 걸려 최대 10% 빗나감 |
- 근거 확인: `hitChance.ts`·`preHitEffects.ts`에 독 타입·맹독 연계 분기 없음(grep). 사용자 사례가 필요한 값 규칙은 아니고 소스 명시 규칙(본가 6세대 이후 동일).

## 2. 고칠 것
- `src/lib/battle/hitChance.ts` `computeBattleHitChance`의 필중 분기 묶음(`alwaysHits`·`lockOn`…) 옆에 한 줄: `move.id === "맹독" && attacker.types.includes("독")`이면 `null`. 사용자 타입은 **현재 타입**(`attacker.types`, 변경·추가 반영)을 쓴다 — Showdown `hasType`과 같다.
- 평가기·AI(`moveDamage.ts:287`·`evaluator.ts:641`·`finishTurn.ts:270`)는 같은 함수를 호출하므로 자동 반영.
- **이번에 하지 않는 것**: 무적 상태(땅파기·날기 등) 대상 통과 — 싱글에서 맹독이 반무적 상태에 쓰이는 경우가 드물고 E2 2차(반무적 규칙 표)에서 한꺼번에 다룬다.

## 3. 규칙
- 필중이면 `null`(기존 규약: "반드시 맞으면 null"). 일격필살·방어 판정 등 다른 단계는 영향 없음.
- 독 타입이 아니면 현행 그대로(명중 90, 랭크·보정 적용). 메가진화로 독 타입이 생기거나 사라져도 `attacker.types`가 현재 값이라 따라간다.

## 4. 영향 범위
- 기준 출력: 독 타입 맹독 사용 판의 명중 판정 → `regress`·`greedy`·`h2h`·`ai` 해시 변동 예상(맹독 + 독 타입 샘플 수는 구현 전에 `samplePartyPresets.json`에서 센다 — 0이면 h2h·ai는 불변일 수 있음).
- 화면: 배틀 로그에서 맹독이 빗나가는 일이 독 타입에게는 사라진다.
