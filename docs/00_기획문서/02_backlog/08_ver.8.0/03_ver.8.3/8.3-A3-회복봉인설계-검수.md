## 2. 불일치·누락

### 2-1. 흡수 기술은 "회복 0"이 아니라 "사용 불가"다 (이전 검수 정정)
- [소스] champions에서 흡수 기술 전부가 `flags.heal: 1`이다(기가드레인·드레인펀치·흡혈·우드혼·드레인키스·파라볼라차지·비터블레이드·말차갓챠 등, `drain` 있고 `heal` 없는 기술은 0개). healblock `onDisableMove`/`onBeforeMove`/`onModifyMove`가 `heal` 플래그로 판정하므로 회복 기술과 똑같이 막힌다.
- [실행] 봉인 직후 request: `[["gigadrain",true],["drainpunch",true],["splash",false]]`(disabled). 같은 턴에 먼저 기가드레인을 고른 뒤 봉인되면:
  ```
  |-start|p2a: Venusaur|move: Heal Block
  |cant|p2a: Venusaur|move: Heal Block|Giga Drain
  ```
- 정정: 규칙조사 검수 §3 R2와 사양서 검수 §4의 "흡수 기술은 `battle.heal()` 단계에서 차단"은 **부정확**했다. `battle.heal()` 차단은 사실이지만 그 전에 기술 자체가 `cant`로 끝난다. 설계서 §2·§0의 "검수 ✅"는 이 오류를 이어받은 것이다.
- 설계 영향: `isHealingMove`(`preHitEffects.ts:377`)에 `drainFraction > 0`을 더한다. moves.json에 `heal` 플래그가 있다면 열거 대신 플래그 하나로 판정하는 편이 짧고 누락이 없다(힐링위시·회복파동·부활의기도·생명의물방울도 `heal` 플래그 — 엔진 지원 여부 확인).
  - `usageConditions.ts`가 같은 판정을 쓰면 AI(자기 선택지·상대 사용 확률)도 자동으로 맞춰진다.
  - `hitResolution.ts:966` 흡수 회복 가드는 호출 기술 경로 대비로 남겨도 된다(Showdown도 `onModifyMove`에서 호출된 회복 기술을 `cant` 처리).
- 시험: **R2-b 기대값 교체** — "봉인 중 기가드레인 → 선택 불가, 강제 시 `cant`, 데미지 없음". 조개껍질방울·먹다남은음식은 회복 0 그대로.

### 2-2. 열매를 먹게 하는 기술 4종: "안 먹힘"이 아니라 "먹히고 회복 0"
- [소스] 네 경로 모두 `TryEatItem`을 거치지 않는다.
  - 벌레먹기/쪼아대기·던지기: `singleEvent('Eat', item, …)` 직접 호출
  - 볼주머니(기술)·다과회: `pokemon.eatItem(true)` — `force`라 `TryEatItem` 생략
  - 열매 효과의 회복은 `this.heal()` → `TryHeal`에서 0으로 막힘
- [실행]
  - 봉인된 쪽이 볼주머니(기술): `-boost def 2` → `-enditem Sitrus Berry [eat]`, **회복 줄 없음**
  - 봉인된 쪽이 벌레먹기: `-enditem p1a Sitrus Berry [from] stealeat [move] Bug Bite`, **회복 줄 없음**(상대 열매도 사라짐)
- 설계 영향: Q1의 "확인 결과가 '안 먹힘'이면 가드 추가"는 전제가 틀렸다. 맞는 동작은 **소비는 그대로, 회복만 0**이다. 현재 엔진(회복 적용)도, 설계의 대안(안 먹힘)도 모두 다르다.
- 구현 권장(§3 참조): 회복을 공통 함수 한 곳에서 막으면 이 네 경로는 **추가 코드 없이** 맞는다. 그래서 같은 PR에 넣는 비용이 거의 없다.

### 2-3. 되새김질: 결과는 같지만 해제 턴에는 회복된다
- [소스] cudchew `onResidualOrder: 28` → `singleEvent('Eat')` 직접 호출(`TryEatItem` 없음). 봉인 중이면 `-activate`·`-enditem [eat]` 로그가 나오고 회복만 0, `effectState.berry`는 삭제(소멸). healblock 해제는 order 20이라 **해제 턴에는 봉인이 먼저 풀리고 되새김질이 회복한다.**
- [실행]
  - 2턴째에 봉인(되새김질 시점에 봉인 유지): `-activate Cud Chew` → `-enditem Sitrus Berry [eat]`, 회복 없음, 이후 재발동 없음 → 설계 ④와 결과 일치
  - 1턴째 열매 섭취 직후 봉인(2턴 종료가 봉인 해제 턴 = 되새김질 턴): `-end Heal Block` → `-activate Cud Chew` → `-heal 423/444` → **회복됨**
- 설계 영향: `applyCudChew`가 A1 순서에서 `tickBlockVolatiles`(④ 끝) **뒤**에 있는지 확인한다. 앞에 있으면 해제 턴 결과가 Showdown과 달라진다. 수확(harvest, order 28)도 같은 위치 관계다.
- 표현: "먹지 않는다"보다 "**발동하지만 회복 0, 대기 소멸**"이 정확하다(로그를 남길지는 UI 결정).

### 2-4. 지옥찌르기는 시작·해제 모두 표시 없음
- [소스] throatchop `onStart`/`onEnd`가 `'[silent]'` → 클라이언트에 문구가 나오지 않는다. healblock `onEnd`는 `-end … move: Heal Block`(문구 표시).
- [실행] `|-end|p2a: Snorlax|Throat Chop|[silent]`
- 권장: `volatileEnded`는 `"healBlock"`만 둔다(타입도 한 값). 지옥찌르기 해제 줄을 넣는다면 "Showdown에 없는 UI 결정"으로 설계서에 명시한다.

### 2-5. 재생력은 봉인돼도 회복한다
- [소스] regenerator `onSwitchOut`이 `pokemon.heal()`(Pokemon 메서드)을 쓴다 — `battle.heal()`과 달리 `TryHeal`을 거치지 않는다. 아픔나누기도 `sethp`라 봉인 무관(`heal` 플래그 없음).
- [실행] 봉인 중 야도란 교체 → 재등장 시 `230/331 → 331/331`
- 설계 영향: §1의 "특성 등 모든 HP 회복 봉인"에 **예외(재생력, 아픔나누기)**를 명시한다. 회복 가드를 공통 함수에 둘 경우 이 둘은 가드를 거치지 않게 한다.

## 3. 구현 단순화 권장
Showdown은 막는 지점이 두 곳뿐이다.
1. `battle.heal()` → `TryHeal`: 모든 HP 회복(기술·흡수·도구·특성·열매 효과·볼주머니·되새김질)
2. 자동 발동 열매의 `TryEatItem`: 소비 여부(봉인 중이면 안 먹고 보존)

poke-builder에 공통 회복 함수가 있다면, 설계 §3-1 ①~④를 지점별 가드 대신 **(가) 공통 회복 함수에 `healBlock`이면 0 한 줄 + (나) `triggerBerryHeals`·`applyBerryHpThresholdHeal` 열매 분기의 보존 가드**로 줄일 수 있다. 그러면 볼주머니·흡수 특성·되새김질·열매 기술 4종(§2-2)이 전부 따라온다. 공통 함수가 없으면 설계대로 지점별로 넣되 §2-2의 네 경로를 "소비 + 회복 0"으로 추가한다.
