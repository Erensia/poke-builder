## 버전 규칙
- 항목마다 **설계서를 먼저 써서 커밋**한 뒤 구현한다(`CLAUDE.md` "버전 작업 절차" 2-1). 설계서는 이 폴더에 둔다(`8.3-<항목>-설계.md`).
- 코드는 **항목당 PR 1개**(커밋 1개, squash 머지). 기준값이 바뀌는 PR은 같은 PR에서 `update-baseline.sh`로 갱신한다.
- 시나리오는 **먼저 실패 → 수정 후 통과**를 확인한다(`8.3-시나리오사양서.md` "순서와 기준값").
- 작업 중 **그 작업과 관련 없는 수정**이 나오면 바로 고치지 않고 이 문서의 "8.3 마무리"에 한계·후속조치로 적는다(`CLAUDE.md` 2-3).
- 문서만 고치면 브랜치·PR 없이 `dev`에 `docs:` 커밋.

- **[해소 2026-11-12 A4-b #487] 정상 공격 경로의 위급할때·레드카드 불일치 3가지**(설계서 Q11, 탈출버튼·우격다짐 포함해 정렬 완료; 아래는 고치기 전 상태 기록): ① `defenderExitPause`(`runTurn.ts:453~459`)가 도망봉인·`isForcedSwitchBlocked`면 위급할때를 막는다 — Showdown은 `canSwitch`만 봐서 그림자밟기·뿌리박기에도 교체된다 ② `applyRedCard`(`:388~394`)가 `damage > 0`·`hitNegatedByAbilityName`을 보아 탈이 벗겨지는 적중에는 발동하지 않는다 — Showdown은 "맞았는가"로 판정해 발동 ③ 레드카드가 `isForcedSwitchBlocked`를 카드 소모 **전에** 봐서 뿌리박기·흡반이면 카드가 보존된다 — Showdown은 카드가 소모되고 교체만 안 된다. - 피격 측·사용자 측 부가 효과(스태미나, 자기과신 랭크 변화)는 상태만 바뀌고 로그 줄이 없다(Q6, UI 결정). 생명의구슬 반동이 빗나감·무효에도 생기는 것은 Showdown 동작을 따랐고 본가와 같은지는 미확인(Q8).
