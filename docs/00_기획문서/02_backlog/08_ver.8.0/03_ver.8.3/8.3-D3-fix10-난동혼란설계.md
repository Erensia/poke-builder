## 0. 사전 확인 — 사용자 인게임 사례(2026-11-18)
- **2턴짜리 역린은 2턴째에 상대가 페어리 타입이라 무효여도 혼란에 걸린다.**
- 혼란에 걸리지 않는 경우는 **3턴짜리가 중간인 2턴째에 무효로 풀린 때**뿐이다(3턴째에 풀리면 걸린다 — Showdown 규칙 표).
- 즉 "예정된 마지막 턴에 끊기면 혼란, 그 전에 끊기면 없음"이다. Showdown 소스와 정확히 같다(검수 `E2-대조-검수.md` §2-1).

## 1. 무엇이 틀렸나
| 예정 지속 | 끊긴 시점 | 본가·Showdown | 엔진 현재 |
|---|---|---|---|
| 2턴 | 2턴째(예정 마지막 턴) | **혼란** | 없음 |
| 3턴 | 2턴째(중간) | 없음 | 없음 |
| 3턴 | 3턴째(예정 마지막 턴) | **혼란** | 없음 |
| 2·3턴 | 1턴째 빗나감·무효 | 상태가 안 걸림 → 없음 | 없음 |
엔진 `updateRampage`(`rampage.ts:43~72`)는 `disrupted(action)`(행동불능·빗나감·방어·타입 무효·특성 면역)이면 **언제든** `endRampage`만 하고 반환한다. 파일 머리 주석("도중에 끊기면(… 마지막 턴 포함) 혼란 없이 끝난다")과 1.9 백로그 5번 D가 이 동작의 근거였다.

## 2. 고칠 것
`updateRampage`의 끊김 분기에서 **이 턴이 예정 마지막 턴이었으면** 정상 종료와 같은 혼란 처리를 한다.
- 예정 마지막 턴 판정: **`entry.turnsRemaining === 1`**. (시작 때 `total`을 2·3·(소란피기 3)으로 정하고 `turnsRemaining = total − 1`을 저장하므로, 이어 쓰는 턴에서 값이 1이면 이 턴이 마지막이다. 3턴짜리의 2턴째는 값이 2라 해당 안 됨.) 1턴째에 끊기면 `entry`가 아직 없어(`!entry`) 기존대로 아무 일도 없다.
- 혼란 부여 조건은 **정상 종료와 같다**: 종류가 역린류(`kind === "confuse"`), 쓰러지지 않았음, 이미 혼란이 아님, 혼란 면역 특성(`immuneToConfusion`, 마이페이스류)이 아님. 소란피기(`uproar`)는 끊겨도 혼란 없음.
- 중복을 피하려고 정상 종료 쪽의 "혼란 걸기" 6줄을 작은 함수(`confuseAfterRampage(fighter, action, random)`)로 뽑아 두 분기가 함께 쓴다. 이 함수는 `action.rampageConfused = true`도 남긴다(로그 "○○는 지쳐서 혼란에 빠졌다!"가 `ActionEffectLines.tsx:177`에서 이미 그려진다).
- `action.rampageEnded`는 지금처럼 정상 종료에서만 세운다(소란피기 종료 문구에만 쓰인다 — 끊김 분기는 그대로 세우지 않는다).
```ts
if (isFainted(fighter) || disrupted(action)) {
  const wasFinalTurn = entry?.turnsRemaining === 1;   // 예정 마지막 턴이었나
  if (entry) endRampage(fighter);
  if (wasFinalTurn && !isFainted(fighter) && kind === "confuse") confuseAfterRampage(fighter, action, random);
  return;
}
```
(실제 구현은 ponytail 규칙대로 최소 diff. 위는 형태 설명.)

**2-1. 필수 보정(검수 §2) — 턴 종료에 잠들어 있으면 혼란 없이 해제**
Showdown `lockedmove.onResidual`은 `target.status === 'slp'`이면 **`onEnd`를 부르지 않고** 상태를 지운다("don't lock, and bypass confusion for calming"). 이 콜백은 **그 턴에 `duration`이 만료되지 않을 때만**(= 그 턴에 난동 기술이 **명중한** 턴) 실행된다. 그래서 수면은 두 갈래다.
| 경우 | Showdown | 위 §2만 적용한 엔진 | 현행 엔진 |
|---|---|---|---|
| **A.** 명중한 턴 **안에서** 잠듦 → 다음 턴 행동불능(느린 상대의 수면 기술, 그 턴 종료의 하품) | **혼란 없음**(턴 종료에 조용히 해제) | 다음 턴이 예정 마지막 턴이면 **혼란 ✗(새 오류)** | 없음 ✓ |
| **B.** 예정 마지막 턴에 **움직이기 전** 잠듦(빠른 상대의 수면 기술) | 혼란(잠든 채 혼란) | 혼란 ✓ | 없음 ✗ |
- B는 §2의 끊김 분기가 이미 해결한다. A를 지키려면 **턴 종료 처리에서 수면 부여(하품) 뒤에** 한 줄이 필요하다: 난동 중(`entry` 있음)이고 `fighter.status.condition === "sleep"`이면 **혼란 없이** `endRampage`. 턴 종료까지 `entry`가 남아 있는 경우는 "이번 턴에 명중했고 아직 마지막 턴이 아님"뿐이라(끊김·마지막 턴은 `updateRampage`가 이미 해제) 소스의 "만료되지 않는 턴"과 정확히 같다.
- 위치: `finishTurn.ts`의 ④ 개별 효과 단계, **`applyDrowsySleepOnset(ctx)` 바로 뒤**(하품 `onResidualOrder: 23`이 `lockedmove`(순서 없음 = 맨 뒤)보다 먼저라는 소스 순서와 같다). 앞에 두면 하품으로 잠든 경우를 놓친다 → 호출 줄 위에 이 순서를 주석으로 적는다. 구현은 `rampage.ts`에 작은 함수 `calmRampageIfAsleep(fighter)`를 두고 내보내 `finishTurn.ts`에서 부른다(`endRampage`는 비공개 유지).
- 예: 3턴짜리 역린, 2턴째 명중, 그 턴 종료에 하품으로 잠듦 → Showdown은 혼란 없음. §2만 적용하면 3턴째 행동불능에서 혼란을 건다(오류) → 이 한 줄이 막는다.

**2-2. 미스트필드(사용자 결정 2026-11-18 — 이번 PR에 포함)**
Showdown 미스트필드는 땅에 있는 포켓몬의 `confusion`을 출처와 무관하게 막으므로 **난동 끝 혼란도 걸리지 않는다**(champions 습득 24종). 엔진에는 `isConfusionBlockedByField(field, grounded)`(`fieldEffects.ts:60`)가 있다. `confuseAfterRampage`(정상 종료와 예정 마지막 턴 끊김이 함께 쓰는 함수) 맨 앞에 `isConfusionBlockedByField(state.field, isGrounded(state, fighter, abilityOf(fighter)))`이면 부여하지 않는 검사를 넣는다(`updateRampage`가 `state`를 이미 받으므로 인자 전달만 추가, `isGrounded`는 `battle/grounding.ts`). 혼란이 막히면 `rampageConfused`도 세우지 않는다. 이 변경으로 정상 종료 쪽도 함께 바뀐다(미스트필드 위 난동 판의 해시가 달라진다 — 사용자 지적대로 AI 측정 해시도 변동 대상).

## 3. 규칙(소스·인게임 대조)
- Showdown `lockedmove.onEnd`는 `trueDuration ≤ 1`일 때만 혼란을 건다(= 예정 마지막 턴에 끝났을 때). 끊김 경로 `onAfterMove`(빗나감·무효·방어 포함)에서도 종료되며 이때 `trueDuration`이 위 표와 같다.
- **행동불능 경로**: 마비·풀죽음·얼음·혼란 자해는 `BeforeMove` 실패 → 턴 종료 `duration` 만료 → `end`가 불려 **마지막 턴이면 혼란**(소스 확정 — 검수 §5 Q1, 실측을 기다리지 않고 진행). **수면은 두 갈래**다(위 2-1): 예정 마지막 턴에 움직이기 전 잠들면 혼란(B), 명중한 턴 안에서 잠들어 다음 턴 행동불능이면 혼란 없음(A). 이전 검수 회신(`E2-대조-검수.md` §2-1)의 "수면도 같은 만료 경로"는 **B만 맞다** — fix-10 검수 문서로 정정됐다. 사용자 인게임 확인은 무효·빗나감 계열이다.
- 이미 혼란이면 새로 걸지 않는다(Showdown `addVolatile` 실패와 같음).

## 5. 영향·측정
- 난동 기술(역린·꽃잎댄스·난동부리기·대격분)이 든 판에서만 바뀐다. `regress`의 무작위 빌드에 섞이므로 `regress 200`·`regress 20000`이 바뀔 수 있고, `greedy`·`status60`·`h2h`·`ai60`도 확인한다. **측정 시작 전에 "명령·예상 종료 시간"을 먼저 보고한다**(약 3분: `regress 200`·`regress 20000`·`STATUS=1 greedy 60`, 마지막에 `SERIAL=1 verify.sh` 약 8분). `test:inference` 결합 해시는 불변이어야 한다.
- **AI**: `ai/evaluator.ts:1008`·`ai/opponentMoveModel.ts:54`는 난동의 "끝나면 혼란" 비용만 본다. 끊겨도 마지막 턴이면 혼란이 걸리게 되므로 AI의 비용 추정은 조금 낙관적이 된다 — 이 PR에서는 건드리지 않는다(알려진 한계로 기록).
- **화면**: 끊긴 턴에 "지쳐서 혼란에 빠졌다!" 줄이 나온다(기존 줄 재사용). 무효 문구 뒤에 이어지는 위치가 어색하지 않은지 사용자 화면 확인(역린 2턴짜리 + 상대 페어리). 브라우저 검증은 사용자에게 위임한다.
