## 2. 수정필요·결정필요 상세

### 2-1. E7-01 독압정 흡수는 접지일 때만
- **차이**: 엔진은 독 타입이면 접지와 상관없이 독압정을 흡수한다. Showdown은 비접지(풍선·부유·중력 없는 비행·전자부유 등)면 **아무 일도 일어나지 않고 설치물이 남는다.**
- **로스터에서 걸리는 경우**: 독 타입 중 비행/부유는 없고(`pokemon.json` 독 타입 22종), 풍선(출전 가능)을 든 독 타입·전자부유가 현실적인 경우다. `[측정]` 독압정+독 타입 등장 144회 중 **비접지는 2회**(0.001%).
- **구현**: `applyEntryHazardsOnSwitchIn`의 접지 판정(`isGrounded(state, self, selfAbility)`)을 맨 앞에서 한 번 구하고, 독압정 흡수 조건에 `selfGrounded &&`를 넣는다. 흡수 문구·트리거(`toxicSpikesAbsorbed`)는 접지일 때만. 압정·독압정 중독·끈적끈적네트의 접지 판정은 이미 `selfGrounded`를 쓴다.
- **시험**: 풍선을 든 아보크 + 독압정 → 흡수 안 됨·설치물 남음·중독 안 됨 / 접지 독 타입(독/땅·일반 독 타입) → 흡수(회귀) / 중력으로 접지가 되면 비행형도 흡수(있으면).

### 2-2. E7-02·E7-10 끈적끈적네트·위협과 능력치 하락 방지 특성
- **차이 ①(문구)**: Showdown은 접지면 `-activate`(발동 문구)를 **항상** 낸다. 엔진은 랭크가 실제로 바뀔 때만 문구·`stickyWeb` 트리거를 낸다(이미 −6이거나 하락이 막히면 아무 줄도 없다).
- **차이 ②(결함)**: 클리어바디(`blocksOpponentStatDropsForStats`)·플라워베일(풀 타입 아군)이 있어도 설치물·위협의 −1이 그대로 들어간다. 기술 경로(`hitResolution.ts` 615행·`mirroredEffects.ts` 334행)·문어굳히기·시럽(`finishTurn.ts`)은 `statDropBlockStatsOf`를 쓰는데 **등장 경로(`applyEntryHazardsOnSwitchIn`·`applyIntimidateWithReaction`)에는 빠져 있다.** `[측정]` 끈적끈적네트 접지 등장 263회 중 하락 방지 특성 보유 **1회** — 로스터에서 드물지만 틀린 규칙이다.
- **구현**:
  - 끈적끈적네트: 접지면 발동 트리거(`stickyWeb`)와 발동 문구를 **항상** 낸다. 랭크 −1은 `statDropBlockStatsOf(self, ability)?.includes("spe")`이면 막고(심술꾸러기 `contraryDelta`는 지금처럼 적용), 막힌 경우 문구는 "…끈적끈적네트에 걸렸지만 {특성}으로 스피드가 떨어지지 않았다!"(성공 문구 "…걸려 스피드가 떨어졌다!"는 그대로). 이미 −6이라 변화가 없는 경우도 같은 방식(걸렸지만 더 떨어지지 않는다).
  - 위협: `applyIntimidateWithReaction`에서 정신력류(`immuneToIntimidate`)·파수견 처리 다음에 `statDropBlockStatsOf(opponent)`를 검사해 막으면 문구 `{상대}의 {특성}! 위협에 능력이 떨어지지 않았다!`를 내고 **주눅(`raisesStatWhenIntimidated`)도 발동시키지 않고** 돌아온다(Showdown은 하락이 막히면 주눅의 `onAfterBoost`가 안 돈다).
- **같은 PR 제안**: 두 경로가 같은 헬퍼를 쓰고 시험이 겹친다. 위협은 E8 영역이지만 한 번에 고친다(E8 문서에는 "E7에서 처리"로 표기).
- **시험**: 클리어바디 메타그로스 + 끈적끈적네트 → 랭크 0·문구 / 클리어바디 상대 + 위협 → 공격 랭크 0·주눅 보유 상대는 속도도 안 오름 / 일반 포켓몬 → 기존 문구·−1(회귀) / 이미 −6 → 문구만.

### 2-3. E7-03·E7-04 등장 효과 순서 재배치
- **Showdown 순서**(한 번의 `fieldEvent('SwitchIn')`, 같은 포켓몬이라 스피드 동일): `order → priority → speed → subOrder`. 우선도 0: **치유소원(자리 sub 3) → 설치물(편 sub 4) → 등장 특성(sub 7) → 도구 시동(풍선 등, sub 8)**, 그 뒤 **우선도 −1: 시드류·의태**, **우선도 −2: 기분파·플라워기프트 등**. (+1·+2 우선도의 긴장감·서투름·중화가스는 설치물 앞이지만 설치물 결과와 무관 — E7-19.)
- **엔진 현재**: `performSwitch`가 기분파·의태 폼을 먼저 맞춘 뒤 `runEntryEffects` = 설치물 → 등장 특성 → 시드 → 풍선 → 치유소원.
- **새 순서**: `runEntryEffects` = ① 치유소원 ② 설치물 ③ 등장 특성 ④ 풍선 안내 ⑤ 시드 ⑥ 의태 ⑦ 기분파. `performSwitch` 앞부분의 `applyForecastForm`·`applyMimicryForm` 호출은 삭제하고 ⑥·⑦로 옮긴다(`deferEntry`로 교체와 등장을 나눠 부르는 A7 경로도 `runEntryEffects`를 거치므로 같은 순서). 킬가르도 실드폼 복귀는 지금대로 교체 직후(Showdown `stancechange`는 행동 시).
- **치유소원 소모 조건**: `healingWishPending`은 `(HP < 최대HP) || 상태이상`일 때만 회복하고 소모한다 — 그렇지 않으면 남아 다음 교체 때 다시 본다(`[실행]` 확인). 회복은 설치물 **전**이므로 회복 → 스텔스록 피해 → 독압정 중독 순서가 된다.
- **AI 영향**: `calcEntryHazardDamage`(교체 후보 피해 예측)는 후보의 현재 타입(교체 때 base로 되돌려 둔 값)으로 계산하므로 새 순서와 일치한다(캐스퐁은 교체 대기 중 노말). 치유소원 대기 편에서 설치물 피해 뒤 회복한다고 보던 AI 평가가 있으면 구현 첫 단계에서 `trail callers`로 확인한다.
- **빈도**: 치유소원 대기 중 등장 169회(0.085%, 이 중 설치물이 있는 경우만 결과가 달라짐), 기분파+스텔스록·압정 21회(0.01%).
- **시험**: 체력 30·독 상태 + 스텔스록·독압정 + 치유소원 → 회복 후 스텔스록 피해·독 상태(Showdown과 같은 HP) / 회복 불필요 등장 → 치유소원 남음 / 캐스퐁 쾌청 + 스텔스록 → 피해 노말 기준·폼은 피해 뒤 불꽃 / 날씨 없음(회귀) / 시드: 일렉트릭메이커 + 시드 같은 포켓몬(회귀).

### 2-4. E7-05·E7-06 교체 소정정
- **분노의주먹 카운터**: `performSwitch`의 초기화 목록에 `outgoing.timesHitByMoves = undefined`를 추가한다(`state.ts` 필드 주석·`switching.ts` 489행 주석 정정). 교체 후 다시 나온 포켓몬은 0부터 센다. 카운트 조건(Showdown은 데미지가 숫자일 때 타수만큼, 엔진은 실제 HP 피해가 있을 때 타마다)은 **E10에 넘긴다**.
- **도주**: 도주 특성 데이터에 `ignoresSwitchTrapping: true`(필드명은 구현 때 기존 `escapesTrapping`과 맞춰 결정)를 달고 `isTrappedFromSwitching`·`trappedByOpposingAbility` 맨 앞에서 보유자면 `false`로 돌린다(도구 `escapesTrapping`과 같은 자리). 로스터 보유종은 폭슬라이뿐이라 영향은 매우 작지만 데이터에 설명만 있고 효과가 없는 상태라 정정한다. AI(교체 가능 판정)도 같은 함수를 써서 따라온다. **E8의 "도주" 항목은 E7에서 처리했다**고 기록한다.
- **시험**: 분노의주먹 사용자가 맞은 뒤 교체했다 돌아오면 카운터 0 / 도주 보유자가 검은눈빛·속박 상태에서 교체 가능 / 일반 포켓몬은 여전히 불가(회귀).

### 2-5. E7-07 설치물 발동 순서(F6①) — 결정필요
- **차이**: Showdown은 설치한 순서대로 처리하고, 엔진은 고정 순서(독압정 흡수 → 스텔스록 → 압정 → 독압정 중독 → 네트)다.
- **결과가 달라지는 장면**: ① **로그 줄 순서**(설치 순서 vs 고정 순서) ② 설치물에서 기절하면 **그 뒤 설치물은 처리되지 않으므로**, 스텔스록을 독압정보다 먼저 깔아 독 타입이 스텔스록에서 쓰러지면 **독압정이 필드에 남는다**(`[실행]` 확인: 독압정 남음 / 반대 순서는 제거). 엔진은 항상 흡수가 먼저라 독압정이 사라진다. ③ 기절 전 중독·랭크 하락은 기절한 포켓몬이라 관측되지 않는다.
- **빈도**: 설치물 2종 이상 등장 **170회(0.085%)**, 그중 독 타입이 독압정을 흡수하는 등장 5회(0.0025%), 독압정+독 타입+스텔스록 3회. 결과가 실제로 갈리는 판은 사실상 없다(기준 출력에도 거의 안 보임).
- **구현 규모**: 중간. `HazardState`에 설치 순서(`placedOrder: ("stealthRock"|"spikes"|"toxicSpikes"|"stickyWeb")[]`, 처음 설치할 때 추가·제거될 때 삭제)를 두고 `cloneSide`·고속스핀·제거 기술 경로를 맞춘 뒤 `applyEntryHazardsOnSwitchIn`을 순서대로 도는 핸들러 표로 바꾼다(독압정 핸들러 안에서 접지→독 타입 흡수→강철→중독 순). 저장된 옛 로그·`regress` 해시에는 줄 순서가 바뀐 판만 영향.
- **옵션**: **(가)** 이번 D3에서 한다(Showdown 규칙 일치, 영향은 로그 줄·극히 드문 잔존 설치물). **(나)** 9.0 이후로 미룬다. **권고: (나)** — 결과가 갈리는 판이 0.0025% 수준이고 `HazardState` 구조 변경(저장 데이터 호환)이 따른다. 단 E7-01·02가 같은 함수를 고치므로 **구현을 표 구조로 짜 두면 (가)로 갈 때 순서 키만 추가하면 된다**(E7-01 구현 시 이를 염두에 둔다).
