## 2. 불일치·보완

### 2-1. 탈출버튼은 탈이 벗겨지는 적중에도 발동한다 (V1 → Q14 변경)
- [소스] champions `ejectbutton.onAfterMoveSecondary` 조건: `source !== target && target.hp && move.category !== 'Status' && !move.flags['futuremove']`, 그 뒤 `canSwitch`·`forceSwitchFlag`·`beingCalledBack`·`isSkyDropped`·`commanding`·다른 활성의 `switchFlag`. **데미지량 검사가 없다.** 레드카드와 같은 `AfterMoveSecondary` 이벤트라 "피격 대상이었는가"로 판정된다.
- [실행] 사이코키네시스 → 따라큐(탈, 탈출버튼):
  ```
  |-activate|p2a: Mimikyu|ability: Disguise
  |-damage|p2a: Mimikyu|130/130
  |-damage|p2a: Mimikyu|114/130|[from] pokemon: Mimikyu-Busted
  |-enditem|p2a: Mimikyu|Eject Button        ← 발동, switch 요청
  ```
- 설계 영향:
  - §3-1 4의 "`action.damage > 0`은 그대로 둔다"를 **삭제**하고, 레드카드(§3-1 2)와 같은 "본체에 닿았는가" 조건 목록(`hit`·비상태·`!blockedReason`·면역 아님·방어/대타 막힘 아님·`!hitSubstitute`·흡수 특성 아님·`!sheerForceAbilityName`)을 쓴다. 홀더 생존(`target.hp`)은 유지.
  - Q14를 "Showdown 확인 — 탈에도 발동"으로 고친다. §5 V1 표 갱신.
  - 시험 N-5에 행 추가: **N-5b 탈출버튼 + 탈(데미지 0) → 발동·버튼 소모·교체창.**
  - 비용: 레드카드 조건을 이미 다시 쓰므로 같은 목록 재사용. 호출처가 둘(레드카드·탈출버튼)이 되므로 §3-1 서두의 "공용 함수로 뽑지 않는다" 판단은 그대로 둬도 되지만, 같은 파일 안의 `isBodyHit(action)` 같은 지역 함수 하나는 중복 제거 이득이 있다(선택).

### 2-2. 레드카드로 끌려 나가면 생명의구슬 반동이 없다 (V4 → R3-t7 교체, §3-2 ③ 보완)
- [소스] `lifeorb.onAfterMoveSecondarySelf` 조건에 **`!source.forceSwitchFlag`**가 있다. 레드카드는 그보다 먼저 도는 `AfterMoveSecondary`에서 `useItem` → `DragOut` 성공 시 `source.forceSwitchFlag = true`를 세운다.
  - 미래예지: `futuremove.onEnd`가 `trySpreadMoveHit`(레드카드 포함) **다음에** 생명의구슬을 직접 부르므로 같은 조건이 걸린다.
  - 정상 공격: `AfterMoveSecondary`(레드카드) → `AfterMoveSecondarySelf`(생명의구슬) 순서라 똑같다.
  - 뿌리박기·흡반이면 `DragOut`이 실패해 `forceSwitchFlag`가 서지 않으므로 **카드는 소모되고 반동도 받는다**.
- [실행]
  | 경로 | 조건 | 결과 |
  |---|---|---|
  | 정상 | 알라카잠(생명의구슬) 사이코키네시스 → 잠만보(레드카드) | `-enditem Red Card` → `drag Chansey`, **반동 없음** |
  | 정상 | 같은 조건 + 알라카잠 뿌리박기 | `-enditem` → `-activate Ingrain` → **반동 117/130** |
  | 미래예지 | 알라카잠(생명의구슬, HP 5) → 잠만보(레드카드) | `-enditem` → `drag Chansey`, **반동 없음**(V4 시나리오 재현 불가) |
  | 미래예지 | 같은 조건 + 알라카잠 뿌리박기 | `-enditem` → `-activate Ingrain` → **반동으로 기절** → 기절 교체 |
- 설계 영향:
  - §3-2 ③: "생명의구슬 반동 처리(`:293~306`)는 그대로 둔다"를 고친다. **레드카드 판정을 반동보다 먼저** 하고, "카드 소모 && 사용자가 `!isForcedSwitchBlocked`"(= 끌려 나갈 예정)이면 반동을 건너뛴다. 레드카드 판정이 사용자 생존(`source.hp`)을 보므로 순서가 바뀌면 반동 기절 때 카드가 보존되는 차이도 생긴다.
  - 1차 검수 §2-5의 "빗나감·무효에도 반동"은 그대로 유효하다(그 경우 레드카드가 돌지 않으므로 충돌 없음).
  - §3-1 정상 경로: `applyRedCard`가 끌어낼 때 같은 행동의 생명의구슬 반동이 이미 적용되고 있는지 구현 첫 단계에서 확인한다. 적용 중이면 Showdown과 다르므로 ⑥-d에 한 줄(반동 건너뛰기)을 더하고 해시 영향은 단계 ①에 포함한다.
  - 시험 교체:
    | # | 입력 | 기대 |
    |---|---|---|
    | R3-t7a | 사용자 생명의구슬(필드, 예비 있음) + 대상 레드카드 | 카드 소모, **반동 없음**, 턴 종료에 사용자 교체 |
    | R3-t7b | R3-t7a + 사용자 뿌리박기, 반동으로 쓰러질 HP | 카드 소모, **반동으로 기절**, 교체 없음 → 기절 교체 |
    | N-7 | 정상 공격: 생명의구슬 공격자 vs 레드카드 / + 공격자 뿌리박기 | 반동 없음·교체 / 반동 있음·교체 없음 |
  - §5 V4 행을 "확인 — 끌려 나가면 반동 없음, 반동 기절은 교체가 막힐 때만"으로 고친다.

### 2-3. 교체 시점 근거 (C2·V2·V3 보충)
- [소스] `runAction`의 순서: `case 'residual'`(잔류 전체 = 미래예지 order 3 ~ 필드·스크린 만료) → **phazing**(`forceSwitchFlag && hp`면 `dragIn`) → `resolveFaints` → 교체 요청. 레드카드 `drag`는 필드 카운트다운보다 늦고 기절 처리보다 이르다.
  - 사용자가 같은 잔류 안에서 나중에(독 등) 쓰러지면 `pokemon.hp` 검사로 `drag`가 없다 → §3-2 ④ "사용자가 살아 있고" 조건과 일치.
- [실행] V2: 3턴 종료에 리린보(그래스메이커)가 `drag` → `-fieldstart Grassy Terrain` → 4~8턴 종료 회복 5회 → 8턴 종료 `-fieldend`. **5턴 유지.**
- [실행] V3: 3턴 종료에 번치코(가속)가 `drag` → 4턴 종료 `Speed Boost spe +1`. `activeTurns`가 다음 턴 시작에 1이 되기 때문(기절 교체와 같다).
- 설계 영향: 없음. §5 V2·V3를 "확인됨"으로 고친다. 시험 R3-t8 기대값(5턴) 그대로.

### 2-4. 우격다짐 (N-6 확인, 구현 메모)
- [소스] `spreadMoveHit` 끝: `if (!suppressingSecondaries())` 안에서만 `AfterMoveSecondary`(레드카드·탈출버튼)와 `EmergencyExit`를 돈다. `suppressingSecondaries = activeMove.hasSheerForce && activePokemon.hasAbility('sheerforce')`.
- [실행] 니드킹(우격다짐):
  | 기술 | 레드카드 | 탈출버튼 | 위기회피(51% → 45%) |
  |---|---|---|---|
  | 독침(추가효과 있음) | 미발동·보존 | 미발동·보존 | 미발동 |
  | 지진(추가효과 없음) | 발동·`drag` | 발동·교체 | 발동 |
- 구현 메모: `action.sheerForceAbilityName`이 **"우격다짐이 실제로 적용된 행동"(기술에 추가효과가 있어 위력이 오른 경우)에만** 채워지는지 확인한다. 특성 보유만으로 채워진다면 지진 같은 기술에서 세 효과가 잘못 막힌다. N-6의 "추가효과 없는 기술이면 정상 발동" 행이 이 확인을 겸한다.
