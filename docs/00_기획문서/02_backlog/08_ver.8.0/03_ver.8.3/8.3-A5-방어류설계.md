## 1. 확정된 규칙 (R7, Showdown 소스·실측)

출처: `8.3-규칙조사.md` R7 최신 확정, `8.3-규칙조사-검수.md` §2, `8.3-시나리오사양서-검수.md` R7-a~g. 근거 코드: `endure.onPrepareHit: !!queue.willAct() && runEvent('StallMove')`, `quickguard/wideguard.onTry: !!queue.willAct()` + `onHitSide: source.addVolatile('stall')`, `destinybond.onPrepareHit: !pokemon.removeVolatile('destinybond')`, `stall` 조건(`duration: 2`, `onRestart: counter *= 3`).

1. **방어·판별·킹실드·니들가드·토치카·버티기**: 이번 턴 **마지막에 행동하면 실패**한다. 실패하면 `protectStreak`은 **0으로 초기화**된다. 마지막이 아니면 (1/3)^`protectStreak` 확률로 성공하고, 성공하면 `protectStreak + 1`. (버티기가 새로 이 묶음에 들어온다.)
2. **패스트가드(와이드가드)**: **연속 사용 확률 판정이 없다**(streak가 몇이든 굴리지 않는다). 단 **마지막에 행동하면 실패**한다(streak 0으로). 성공하면 `protectStreak + 1`이라 **다음 방어류의 성공 확률이 1/3 → 1/9…로 깎인다**.
3. **길동무**: `protectStreak`을 읽지도 쓰지도 않는 **독립 규칙**이다. **직전 행동이 성공한 길동무이고 그 예약이 아직 남아 있으면 이번 길동무는 100% 실패**한다. 예약이 풀리는 경우 — 다른 기술을 쓴 행동, 행동불능(마비·풀죽음 등)이 된 행동, 교체, 길동무 실패 — 뒤의 길동무는 성공한다(성공/실패가 번갈아 나온다). "마지막 행동이면 실패"는 길동무에 **없다**(7.3 B2 결과 유지).

"마지막에 행동한다"의 정의는 지금 엔진 그대로다 — `movesSecond`(이번 턴 행동 순서가 두 번째) 또는 상대가 이번 턴 교체했다(`defenderMove.id === SWITCH_PASS_MOVE_ID`). Showdown의 `queue.willAct()`(큐에 남은 move/switch 행동이 있는가)와 싱글에서 같다: 내가 첫째면 상대 행동이 남아 있고, 상대가 교체했으면 교체는 행동 전에 이미 끝나 있다.

## 2. 지금 엔진이 하는 일 (`mirroredEffects.ts:1674~1718`)

```
if (protectEffect && !bounceActive) {
  streak = attacker.protectStreak ?? 0
  lastToAct = protectEffect === "block" && (movesSecond || defenderMove === 교체)     // ← block만
  rollPassed = !lastToAct && random() < (1/3)^streak                                  // ← 모든 갈래가 굴림
  if (!rollPassed) { protectStreak = 0; protectFailed = true }
  else { protectStreak = streak + 1; ... 길동무면 destinyBondArmed = true / 아니면 activeProtect 설정 }
} else if (!bounceActive) protectStreak = 0
```

실패 시 `protectFailed`만 서고 `protectStanceEntered`는 서지 않아 화면은 "○○의 △△는 실패했다!"를 낸다(C7). 성공 시 `block`·`blockPriority`만 `protectStanceEntered`를 세운다. 이 동작은 모두 유지한다.

## 3. 설계

### 3-1. 방어류 갈래 정리 — 버티기·패스트가드 (`protectAndFieldSetup`)
길동무를 먼저 별도 갈래로 떼고(§3-2), 남은 `block`·`blockPriority`·`endure`를 한 갈래로 처리한다. **바깥 구조 `if (protectEffect && !bounceActive) { … } else if (!bounceActive) { protectStreak = 0 }`는 그대로 둔다**(매직미러 반사 중이면 이 블록 전체를 건너뛴다 — 아래 의사코드는 `if (protectEffect && !bounceActive)` 안쪽이다) **[검수 §2-5]**.

```
const effect = c.effectiveMove.protectEffect
if (effect === "destinyBond") { …§3-2… }
else if (effect) {
  const streak = attacker.protectStreak ?? 0
  const lastToAct = c.movesSecond || c.defenderMove.id === SWITCH_PASS_MOVE_ID      // block 한정을 풀어 전부
  // 패스트가드는 연속 사용 굴림이 없다 — 마지막 행동만 아니면 성공
  // [검수 §2-4] 연속 횟수 상한: Showdown stall counterMax 729 = 3^6 → 6연속 이후 확률은 1/729에서 멈춘다
  const rollPassed = !lastToAct && (effect === "blockPriority" || c.random() < Math.pow(1 / 3, Math.min(streak, 6)))
  …이하 지금과 같음(실패면 streak 0·protectFailed, 성공이면 streak + 1·activeProtect 설정)…
}
```

- **난수 사용 순서**: `lastToAct`면 굴리지 않는다(지금 `block`과 같음 — Showdown도 `willAct()`가 거짓이면 `runEvent('StallMove')`를 부르지 않는다). 패스트가드는 **마지막이 아니어도 굴리지 않는다**(C3). 두 변화 모두 이후 난수열을 밀어 `regress` 해시가 바뀔 수 있다 — 단계 ①에서 따로 잰다.
- `protectStanceEntered`·`targetedSelf`(패스트가드는 상대 기술 `priority > 0`일 때만 막는다)·`activeProtect` 설정은 **건드리지 않는다**.
- 버티기 실패는 `activeProtect`가 서지 않으므로 이번 턴 상대 공격에 대한 HP 1 버팀이 없다. `hitResolution.ts:347` 주석("방어류 공용 성공 확률로 이미 발동 여부가 갈렸으니")은 그대로 맞다.

### 3-1b. 행동하지 못한 턴의 카운터 만료 **[검수 §2-3]**
`resolveAction`(`resolveAction.ts:961~962`)에서 `resolvePreHitEffects`가 `defenderKey`가 없는 결과(= 일찍 반환한 `ActionLogEntry`)를 돌려주는 갈래에 한 줄을 넣는다.
```
const pre = resolvePreHitEffects(…)
if (!("defenderKey" in pre)) { c.state[c.actorKey].protectStreak = 0; return pre }   // 방어류를 성공하지 못한 턴 → stall 만료
```
- 이 갈래는 방어류 갈래(거울 단계)에 닿지 못한 **모든** 행동을 한 번에 덮는다: 마비 행동불능·수면·얼음·풀죽음·혼란 자해·도발/기술봉인 등 사용 불가·차지 1턴째·명중 실패 등. 방어류 자신이 조기 반환하는 경우(도발로 방어 사용 불가)도 Showdown에서 `stall`이 갱신되지 않아 만료되므로 같은 0이다.
- 교체는 `performSwitch`(`switching.ts:453`)가 이미 `undefined`로 만든다(R7-k는 회귀 시험). 매직미러 반사 구간은 `bounceActive`로 거울 단계를 건너뛰고 행동자 자신의 카운터는 그대로 두는 기존 동작을 유지한다(조기 반환 갈래가 아니므로 영향 없음).
- 영향: `regress` 무작위 빌드에서 방어류를 쓰는 포켓몬이 행동불능이 된 다음 턴의 방어 성공률이 오른다. 단계 ①에 포함해 해시를 잰다.
- 한계: 한쪽이 턴 시작 전부터 쓰러져 있어 `runActionPhase`가 행동 루프를 끊는 경우(`runTurn.ts:514`) 살아 있는 쪽은 `resolveAction`을 거치지 않아 카운터가 남는다. 그 턴이 끝나면 쓰러진 쪽 교체가 이어져 상대가 새로 나오는 경우라 실전 영향이 거의 없어 이번에는 두지 않는다.

### 3-2. 길동무 분리
**(가) 직전 상태 전달.** `resolveAction`이 `resolvePreHitEffects`를 부르기 **전에** `c.destinyBondWasArmed = state[actorKey].destinyBondArmed === true`를 기록하고, 거울 단계 입력(`resolveMirroredMoveEffects`, `resolveAction.ts:277`)과 `MirroredMoveEffectsInput`·`MirroredCtx`(`mirroredEffects.ts:24·57`)·초기화(`:1783~`)에 `destinyBondWasArmed` 필드를 한 줄씩 추가한다. **`preHitEffects.ts:1294`의 "행동 시작 때 무조건 지움"은 바꾸지 않는다**(R7-g의 "행동불능 뒤엔 성공"이 이 동작에서 그대로 나온다). 영속 상태 필드는 늘리지 않는다.

**(나) 길동무 갈래.**
```
if (effect === "destinyBond") {
  // 길동무는 방어류 연속 사용 카운터를 읽지도 올리지도 않는다. 직전 성공이 아직 예약 중이면 이번엔 100% 실패.
  // 호출 기술(잠꼬대·따라하기 등)로 나온 길동무는 Showdown에서 호출한 기술의 beforeMove가 예약을 먼저 풀어 성공하므로 c.move(고른 기술)로 구분한다.
  c.attacker.protectStreak = 0                                   // Q18
  if (c.move.protectEffect === "destinyBond" && c.destinyBondWasArmed) c.protectFailed = true
  else { c.attacker.destinyBondArmed = true; c.protectSucceeded = true }
}
```
- 실패해도 `destinyBondArmed`는 이미 `false`다(행동 시작 때 지워짐) — Showdown이 실패하면서 `removeVolatile`로 예약을 푸는 것과 같다. 그래서 R7-f(성공 → 실패 → **3턴째 성공**)가 자연히 나온다.
- 길동무 발동(`hitResolution.ts:448 checkDestinyBond`)은 바꾸지 않는다.

### 3-3. AI (`ai/protectMoves.ts`, `ai/evaluator.ts:517`)
- `protectSuccessChance(streak)`를 **그룹별로** 만든다: `block`·`punish`·`endure` = (1/3)^min(`protectStreak`, 6) **[검수 §2-4 — 엔진과 같은 상한]** / `priorityGuard`(패스트가드) = **1** / `destinyBond` = **예약이 남아 있으면 0, 아니면 1**(`state[key].destinyBondArmed`). 시그니처는 `(fighter, group)`로 바꾸고 호출은 `evaluator.ts:517` 한 곳뿐이다.
