## 2. 영향 범위 (구현 전에 알아 둘 것)

접촉 여부는 아래를 바꾼다. 데이터만 바꿔도 해시가 변할 수 있는 이유다.

| 영역 | 바뀌는 동작 |
|---|---|
| 접촉 반응 특성(까칠한피부·정전기·불꽃몸·독가시·미라·미끈미끈 등 설명문에 "접촉"이 든 특성 18종) | 불새·트림·대격분·바늘미사일은 **반응이 없어지고**, 지구던지기는 **반응이 생긴다** |
| 울퉁불퉁멧(도구) | 같음 |
| 원격(`movesIgnoreContact`) | 지구던지기가 접촉이 되면 원격 보유자에게는 접촉 반응이 없는 쪽으로 처리됨 |
| **관통드릴·보이지않는주먹** | 접촉기만 방어류를 뚫는다 → **불새·대격분·바늘미사일·트림은 이제 방어에 막히고**, **지구던지기는 뚫는다**(고정 데미지 기술이 뚫는 경우의 데미지 규칙은 시험으로 현재 동작 고정) |
| 복슬복슬 | 접촉기 데미지 절반이 되는 쪽이 지구던지기로 바뀜(복슬복슬 본문 확인) |
| 파동의방호 | 접촉 기술 데미지 절반 — 같은 이유 |
| AI(`moveDamage.ts:231`) | 접촉 반응 예상 손실이 같은 방향으로 바뀜 |

## 3. 검증 도구 보강 (같은 PR, 재발 방지)

- **K5 점검**: `scripts/move-effect-audit.mjs`(B3, `validate:data`에서 실행)에 "`tags`의 접촉/비접촉 ↔ `makesContact` 일치" 한 줄을 더한다. 지금 어긋난 기술이 트림·불새·지구던지기(위 3개)와 **날개치기**(`makesContact` 없음, 미사용 데이터)뿐이라 이 PR이 끝나면 통과한다.
- 날개치기는 `makesContact: true`를 채운다(미사용 데이터라 동작 영향 없음, K5 통과용). → 질문 Q3.
- Showdown과의 대조는 E0 도구가 이미 한다(`D3-검수자료/zz-d3-data-diff.mjs.txt`) — 구현 후 `contact` 불일치가 0이어야 한다.
