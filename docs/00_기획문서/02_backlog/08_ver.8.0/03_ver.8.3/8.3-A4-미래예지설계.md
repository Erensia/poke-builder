## 1. 확정된 규칙 (사용자 2026-11-10, 검수로 보정)
- **맞는 시점에 계산한다**: 그 순간의 스탯·랭크·날씨·필드·도구를 전부 반영(규칙조사 Q3-1·Q3-3). 사용자·대상 모두.
- **대타가 있으면 대타가 대신 맞는다**(Q3-2). 대타 HP가 줄고 본체는 그대로.
- **사용자 쪽 스탯은 슬롯의 현재 포켓몬이 아니라 미래예지를 쓴 원래 포켓몬**. 교체로 내려갔어도 그 포켓몬의 능력치, 랭크는 교체로 초기화된 값(R3-e).
- **적중은 일반 공격과 같은 판정을 거친다**: 명중·회피, 무적 은신(빗나감), 급소, 타입 면역. 방어만 무시하고 버티기는 적용된다.
- 같은 자리에 이미 대기 중이면 실패(R3-f), 적중 시점에 대상이 기절해 있으면 맞지 않음(R3-g), 순서는 A1 ③ 단계(R3-d).
- AI: 6.3 문서의 한계 "스냅샷·방어/대타 무시·특성/도구 보정 없음"을 해소한다.

## 3. 새 규칙과 구현
### 3-1. 엔진
1. **예약 구조를 줄인다**(`state.ts:399`): `futureSight?: { turnsRemaining: number; move: Move; sourceIndex: number }`. `realStats`·`types`·`stages`를 지운다. 사용자는 **상대 편의 `party[sourceIndex]`** 객체를 직접 참조한다. 교체 시 랭크·타입·특성·대타·방어 상태의 복원이 이미 `performSwitch`(`switching.ts:430~455`)에서 이뤄지므로 별도 처리 없이 R3-e의 "랭크는 초기화된 값"이 성립한다. 상태 복제(`state.ts:1139`)는 `{ ...side.futureSight }` 한 줄로 단순해진다(파티가 같이 복제되므로 인덱스가 유효). 설치부(`preHitEffects.ts:491`)는 `sourceIndex: sideOf(c.state, c.actorKey).activeIndex`만 저장한다.
   - **"필드에 있음" 판정** `srcOnField = sideOf(opp).activeIndex === sourceIndex && !isFainted(src)`. 교체로 내려갔다가 **적중 전에 다시 나온 경우는 필드에 있음**이다(Showdown은 같은 객체의 `isActive`를 본다, R3-v).
2. **적중부는 정상 공격의 피격 파이프라인을 재사용한다**: `applyFutureSight`의 `computeDamage` 직접 호출을 `resolveHitAndApplyDamage`(`hitResolution.ts:1030`) 호출로 바꾼다. 데미지 계산(`resolveHit`: 날씨·필드·스크린·열매 반감·도구·급소·16단계 난수)·대타 흡수·기합의띠/옹골참·**버티기**·피격 특성·탈이 한꺼번에 따라온다. 입력(`HitResolutionInput`)은 `resolveAction.ts:1016`의 호출과 1:1로 맞추되 다음과 같이 채운다(구현 첫 단계에서 항목 전부를 정상 호출과 대조하고, 달라지는 것은 이 표에 한 줄 추가한다).

   - 빗나가거나(`hit` 거짓) 은신 중이면 **파이프라인을 호출하지 않는다**(정상 경로도 사전 단계에서 빗나감 결과를 돌려준다 — `resolveAction.ts:962` 부근, 구현 첫 단계에서 대조). 대상이 기절해 있으면 지금처럼 소멸(호출·반동 모두 없음). 사용자 `party[sourceIndex]`가 기절해 있어도 호출한다(⑧).
   - 구조 변경은 **입력을 만드는 지역 헬퍼 1개**(`finishTurn.ts` 안)와 파이프라인의 `delayedHit` 분기 3곳이다. 새 파일·새 추상화 없음. `finishTurn.ts`는 `runTurn.ts`만 import하고 `hitResolution.ts`·`switching.ts`는 `finishTurn`·`resolveAction`·`runTurn`을 import하지 않아 새 import에 순환이 없다(확인 완료). `// ponytail: 에스퍼 전용이라 흡수 특성(마중물류) 판정은 생략 — 타입이 다른 지연 공격기가 생기면 preHitEffects의 흡수 판정을 헬퍼로 뽑아 재사용`. `// ponytail: 노멀스킨은 보유 종이 없어 생략(미래예지 26종 중 0종) — 보유 종이 생기면 onEnd처럼 type만 노말로 바꾼다(×1.2 없음)`.
3. **명중 굴림**: 헬퍼가 `hit = evadedByCharge ? false : hitChance === null ? true : random() < hitChance`로 정한다(`rollHit`과 같은 구조, `lockOn`·`glaiveRush`·매직미러 분기는 미래예지와 무관해 생략). 빗나가면 데미지·피격 효과 없이 §3-1 ⑤의 반동만 처리하고 `futureSightMiss`를 남긴다.
4. **로그**(`EndOfTurnLogEntry`, 선택 필드만 추가 — 옛 대전 영상 로그에도 안전):
   - `futureSightMoveName` 줄은 그대로 쓰되 `damage`는 **본체가 실제로 잃은 HP**(`hpBefore − currentHp`)로 채운다. 대타가 맞으면 0.
   - 새 필드: `futureSightMiss?: true`("빗나갔다!"), `futureSightCritical?: true`("급소에 맞았다!"), `futureSightSubstitute?: "hit" | "broke"`("대타가 대신 맞았다!"·"대타가 쓰러졌다!"), `futureSightImmune?: true`("효과가 없었다"). 타입 상성의 "굉장했다/별로였다" 문구는 이번에 넣지 않는다(턴 종료 줄은 지금도 상성 문구가 없다).
   - UI는 `EndOfTurnLines.tsx:78`의 분기 한 곳과 반동 줄 분기 하나를 고친다. 연출(`useTurnFx`)은 건드리지 않는다.
5. **사용자 측 효과는 헬퍼가 직접 처리한다**(파이프라인 밖, `srcOnField`일 때만):
   - **생명의구슬 반동**: `attackerItem?.selfRecoilFractionOfMaxHp && !attackerAbility?.negatesIndirectDamage`이면 `floor(maxHp × 비율)`만큼 사용자 HP를 깎는다. **적중 결과와 무관**하게 — 빗나감·무효(타입 면역)·대타 적중에도 생긴다. 대상이 적중 전에 이미 기절해 불발이면 없다. 반동 줄 `{ actor: 사용자 쪽 키, damage, remainingHp, fainted, itemRecoilItemName }`을 남긴다. 같은 뜻의 필드 `itemRecoilItemName`이 `ActionResult`(`types/battle.ts:256`)에는 있고 `EndOfTurnLogEntry`에는 없어 **같은 이름의 선택 필드를 추가**한다(수치는 `damage`에 담는다). 파이프라인의 반동 분기는 `delayedHit`로 꺼져 있으므로 이중 적용이 없다.
   - **쓰러뜨린 뒤 발동하는 특성**: 대상이 이 적중으로 쓰러졌으면(`damage > 0 && isFainted(defender)`) `attackerAbility.boostsStatOnKo`(자기과신)·`boostsHighestStatOnKo`(천정부지)를 적용한다. 이 두 블록은 파이프라인이 아니라 `resolveAction.ts:623~632`(`applyKnockoutAbilities`)에 있어 자동으로 따라오지 않는다 → 헬퍼에 같은 6줄을 둔다(중복이 신경 쓰이면 구현 때 작은 공용 함수로 뽑는다). 교체돼 있으면 미발동. 변한 랭크는 파티 트래커로 보이고 로그 줄은 만들지 않는다(Q6).
   - 반동으로 사용자가 쓰러지는 경우의 기절·승패 처리는 턴 종료 공통 처리(⑤ 뒤)를 따른다 — 시나리오 R3-p로 확인한다.
6. **방어 측 반응의 현황(검수 §2-6 대조)**: 탈출버튼·레드카드·위급할때는 파이프라인이 아니라 `runTurn.ts`의 행동 후 처리(`applyRedCard` 370행, 탈출버튼 466행, 위급할때 454행)에 있고 행동(`ActionLogEntry`) 기준으로 돈다. 미래예지 적중은 `finishTurn.ts`에서 일어나 이 처리를 **지나지 않는다**.

   위급할때·레드카드는 알면서 두는 한계로 백로그 후속 후보에 올린다(Q9).
7. **설치부 로그·실패 규칙은 그대로**: "미래를 내다보았다!"(`futureSightSet`)·"그러나 실패했다!"(`futureSightFailed`).
