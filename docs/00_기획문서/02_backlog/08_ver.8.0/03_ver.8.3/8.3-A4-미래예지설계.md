## 1. 확정된 규칙 (사용자 2026-11-10, 검수로 보정)
- **맞는 시점에 계산한다**: 그 순간의 스탯·랭크·날씨·필드·도구를 전부 반영(규칙조사 Q3-1·Q3-3). 사용자·대상 모두.
- **대타가 있으면 대타가 대신 맞는다**(Q3-2). 대타 HP가 줄고 본체는 그대로.
- **사용자 쪽 스탯은 슬롯의 현재 포켓몬이 아니라 미래예지를 쓴 원래 포켓몬**. 교체로 내려갔어도 그 포켓몬의 능력치, 랭크는 교체로 초기화된 값(R3-e).
- 같은 자리에 이미 대기 중이면 실패(R3-f), 적중 시점에 대상이 기절해 있으면 맞지 않음(R3-g), 순서는 A1 ③ 단계(R3-d).
- AI: 6.3 문서의 한계 "스냅샷·방어/대타 무시·특성/도구 보정 없음"을 해소한다.

## 3. 새 규칙과 구현
### 3-1. 엔진
1. **예약 구조를 줄인다**(`state.ts:399`): `futureSight?: { turnsRemaining: number; move: Move; sourceIndex: number }`. `realStats`·`types`·`stages`를 지운다. 사용자는 **상대 편의 `party[sourceIndex]`** 객체를 직접 참조한다. 교체 시 랭크·타입·특성·대타·방어 상태의 복원이 이미 `performSwitch`(`switching.ts:430~455`)에서 이뤄지므로 별도 처리 없이 R3-e의 "랭크는 초기화된 값"이 성립한다. 상태 복제(`state.ts:1139`)는 `{ ...side.futureSight }` 한 줄로 단순해진다(파티가 같이 복제되므로 인덱스가 유효).
   - 설치부(`preHitEffects.ts:491`)는 `sourceIndex: sideOf(c.state, c.actorKey).activeIndex`만 저장한다.
2. **적중부는 정상 공격의 피격 파이프라인을 재사용한다**: `applyFutureSight`의 `computeDamage` 직접 호출을 `resolveHitAndApplyDamage`(`hitResolution.ts:1030`) 호출로 바꾼다. 이 함수가 데미지 계산(`resolveHit`: 날씨·필드·스크린·열매 반감·도구·급소·16단계 난수)·대타 흡수·기합의띠/옹골참·피격 특성·탈을 모두 처리한다. 입력(`HitResolutionInput`)은 `resolveAction.ts:1016`의 호출과 1:1로 맞추되 다음과 같이 채운다(구현 첫 단계에서 항목 전부를 정상 호출과 대조하고, 달라지는 것은 이 표에 한 줄 추가한다).

   | 입력 | 값 |
   |---|---|
   | `attacker` | `opponent 편 party[sourceIndex]` |
   | `attackerAbility`·`attackerItem` | 사용자가 **필드에 있고 살아 있을 때만** `abilityOf`·`effectiveHeldItem(…, state)`, 아니면 `undefined` (§0 ①) |
   | `defender`·`defenderAbility`·`defenderItem` | `state[key]`(적중 시점의 활성). 특성은 `resolveEffectiveDefenderAbility`(틀깨기는 사용자가 필드에 있을 때만 성립) |
   | `move`·`effectiveMove`·`typeEffectiveness`·`abilityOffense/statOffense/abilityDefense/finalDefense/stabMultiplier` | `resolveMoveContext(attackerAbility, move, defender.types, defenderAbility, { weather, defenderItem, defenderGrounded, attackerHpFraction, defenderHpIsFull, defenderHasStatusCondition, field })` — `preHitEffects.ts:707`과 같은 호출. 상성 0이면 데미지 0 |
   | `ownMoveTypeBoostMultiplier`·`rivalryMultiplier` | 정상 공격과 같은 식(`preHitEffects.ts:971·974`) |
   | `gemMultiplier` | 1 (보석은 사용 시점에 소비되는 효과) |
   | `blockedByProtect`·`unseenFistPiercing`·`evadedByCharge`·`defenderHideType` | `false`·`false`·`false`·`undefined`. **호출 전에 `defender.activeProtect = undefined`로 비운다** — 방어·버티기를 제거하는 Showdown과 같게(§0 ⑥, 버티기도 무시) |
   | `blockedBySubstitute` | `defender.substituteHp !== undefined && !attackerAbility?.bypassesScreensAndSubstitute` (틈새포착은 사용자가 필드에 있을 때만, §0 ②). 소리·저주 예외는 미래예지와 무관 |
   | `defenderBerriesBlocked` | `!!attackerAbility?.preventsOpponentBerries` (`preHitEffects.ts:143`과 같게) |
   | `hitChance` | `null`(판정 없음, Q4) |
   | `sheerForceAbilityName` | `undefined` |

   - 구조 변경은 **입력을 만드는 지역 헬퍼 1개**(`finishTurn.ts` 안, 약 30줄)뿐이다. 새 파일·새 추상화 없음. `// ponytail: 에스퍼 전용이라 흡수 특성(마중물류) 판정은 생략 — 타입이 다른 지연 공격기가 생기면 preHitEffects의 흡수 판정을 헬퍼로 뽑아 재사용`.
   - 대상이 기절해 있으면 지금처럼 소멸(호출하지 않음). 사용자 `party[sourceIndex]`가 기절해 있어도 호출한다(§0 ⑧).
   - **순환 import 없음(확인 완료)**: `finishTurn.ts`는 `runTurn.ts`만 import하고, `hitResolution.ts`·`switching.ts`는 `finishTurn`·`resolveAction`·`runTurn`을 import하지 않는다. `finishTurn.ts`가 `hitResolution.ts`를 새로 import해도 안전하다.
3. **로그**(`EndOfTurnLogEntry`, 선택 필드만 추가 — 옛 대전 영상 로그에도 안전):
   - `futureSightMoveName` 줄은 그대로 쓰되 `damage`는 **본체가 실제로 잃은 HP**(`hpBefore − currentHp`)로 채운다. 대타가 맞으면 0.
   - 새 필드: `futureSightCritical?: true`("급소에 맞았다!"), `futureSightSubstitute?: "hit" | "broke"`("대타가 대신 맞았다!"·"대타가 쓰러졌다!"), `futureSightImmune?: true`("효과가 없었다"). 타입 상성의 "굉장했다/별로였다" 문구는 이번에 넣지 않는다(턴 종료 줄은 지금도 상성 문구가 없다).
   - **생명의구슬 반동**(사용자가 필드에 있을 때, §0 ⑦): 파이프라인이 반동을 자동으로 적용하므로 로그가 필요하다. 사용자 편 줄 `{ actor: 사용자 쪽 키, damage, remainingHp, fainted, itemRecoilItemName }`을 추가한다. 같은 뜻의 필드 `itemRecoilDamage`·`itemRecoilItemName`이 `ActionResult`(`types/battle.ts:256`)에는 있고 `EndOfTurnLogEntry`에는 없으므로, 후자에 **같은 이름의 선택 필드 `itemRecoilItemName`을 추가**한다(데미지 수치는 `damage`에 담는다).
   - UI는 `EndOfTurnLines.tsx:78`의 분기 한 곳과 반동 줄 분기 하나를 고친다. 연출(`useTurnFx`)은 건드리지 않는다.
   - 사용자가 반동으로 쓰러지는 경우의 기절·승패 처리는 턴 종료 공통 처리(⑤ 뒤)를 따른다 — 구현 때 시나리오 R3-p로 확인한다.
4. **피격 측 부가 효과는 로그를 남기지 않는다**: 약점보험·스태미나 등이 발동하면 상태(랭크·도구 소모)는 정상적으로 바뀌지만 턴 종료 줄에는 표시되지 않는다. 파티 트래커·랭크 표시로는 보인다. 알면서 두는 한계로 백로그에 적는다(Q6).
5. **설치부 로그·실패 규칙은 그대로**: "미래를 내다보았다!"(`futureSightSet`)·"그러나 실패했다!"(`futureSightFailed`).

### 3-2. AI
새 코드가 없다. 엔진 변경은 `runTurn` 탐색에 자동 반영된다(`futureSight`를 읽는 AI 코드가 없으므로 구조 변경으로 깨지는 곳도 없다). `withTurnCost`의 2턴 비용 계산은 지금의 상태 기준으로 데미지를 추정하는 것이어서 "맞는 시점 계산"과 방향이 같다. 대타나 교체를 예측해 미래예지의 가치를 바꾸는 것은 이번에 하지 않는다.

## 4. 이 PR에 넣지 않는 것
- **파멸의소원**: 데이터에 없다. 예약 구조가 `move`를 들고 있어 기술이 추가되면 코드 변경 없이 같은 경로를 탄다(타입이 달라 흡수 특성이 걸리는 경우만 3-1 ②의 ponytail 주석 참고).
- 피격 측 부가 효과 로그(3-1 ④), 타입 상성 문구, 연출 변경.
- AI의 대타·교체 예측과 미래예지 가치 재평가.
- 사람 UI의 미래예지 상태 표시(예: "미래예지 대기 중" 배지) — UI 변경이라 8.4 후보에 적는다.

## 5. 결정·해석 (기본값으로 진행. 이견 있으면 알려 주세요)
- **Q1. 정상 공격의 피격 파이프라인을 재사용한다.** 사용자 확정("계산을 맞는 시점에 처리하기 때문이다")과 §0 ⑥(방어 측 효과 전부 정상 적용)을 가장 적은 코드로 맞춘다. 대안인 "데미지 공식만 직접 호출 + 배율 보강"은 `resolveHit`의 배율 로직(약 60줄)을 한 번 더 복제해 두 곳을 유지해야 하고 급소·버티기·탈을 따로 넣어야 한다. 비용은 입력 조립 약 30줄과 §3-1 ④의 로그 한계다.
- **Q2. 사용자가 필드에 없으면 특성·도구는 적용하지 않는다**(§0 ① `[기억]`). 능력치·타입은 그 포켓몬의 현재 값. 검수 결과가 다르면 입력 표 한 줄만 바뀐다.
- **Q3. 급소와 16단계 난수를 쓴다**(정상 공격과 같은 `resolveHit`). 지금의 연속 난수에서 바뀌므로 RNG 소비 순서가 달라진다(§6).
- **Q4. 적중 시 명중 판정은 하지 않는다**(현재 유지). Showdown이 판정한다고 확인되면 `hitChance`에 `computeBattleHitChance`(`hitChance.ts:32`)를 넣고 빗나감 줄을 추가한다.
- **Q5. 은신 중인 대상도 맞는다**(현재 유지). 빗나간다고 확인되면 `evadedByCharge`·`defenderHideType`을 정상 경로와 같게 채운다.
- **Q6. 피격 측 부가 효과의 로그는 이번에 만들지 않는다.** 상태는 맞게 바뀌고 표시만 빠진다. 필요하면 후속 항목으로 올린다.
- **Q7. 사용자가 기절한 채로도 맞는다**(현재 엔진과 같고 §0 ⑧). 이때 특성·도구는 적용하지 않는다(Q2).
- **Q8. 생명의구슬 반동 줄을 만든다**(§0 ⑦). 파이프라인이 자동으로 적용하므로 보이지 않는 HP 변화를 만들지 않는다.

## 6. 위험과 영향
- **기준 출력**: 미래예지를 쓰는 샘플 파티가 **0건**이라 `regress 200`·`regress 20000`·`greedy120`·`status60`·`h2h40`·`ai60`은 **바뀌지 않을 가능성이 높다**(구현 후 실측). 바뀌면 원인은 이 항목 하나다. **바뀌면 안 되는 것**: `test:inference` 결합 해시 `10040ffa0108c9a3`·계산 함수 차분 해시 — 역산은 미래예지를 보지 않는다.
- **A3와 분리**: 출발 기준값 `f5855868…`에서 이번 변화의 원인은 미래예지 하나여야 한다.
- **기존 시나리오 2개 수정**: `17-ver83.mjs`의 R6-d(49행)·R6-j(111행)가 `futureSight`를 옛 구조(`realStats`·`types`·`stages`)로 직접 만든다 → `sourceIndex`로 바꾼다. `15-ver63.mjs` B2는 실제 기술을 쓰므로 그대로 통과해야 한다(회귀).
- **저장 데이터**: 진행 중 `BattleState`는 저장하지 않는다(`useBattleAi.ts`의 localStorage는 AI 학습 기록). 저장된 대전 영상은 로그만 담고, 새 로그 필드는 모두 선택 필드다.
- **화면**: 턴 종료 줄에 "급소에 맞았다!"·"대타가 대신 맞았다!"·"효과가 없었다"·반동 줄이 추가될 수 있다 — 화면 확인 대상(미래예지 대전 + 대타 대상).
