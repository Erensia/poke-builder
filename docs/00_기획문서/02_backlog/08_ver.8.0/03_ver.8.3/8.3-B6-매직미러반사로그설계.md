## 2. 규칙 확인

반사의 **규칙**은 바꾸지 않는다. 다만 **표시 순서와 문구**가 포챔스·Showdown과 어긋나지 않는지 검수가 필요하다(V1~V3). 제가 아는 Showdown 로그는 `-ability`(특성 표시) 다음에 방어측이 쓴 `|move|…|[from]ability: Magic Bounce` 줄이 나오는 순서라 위 3줄 구성과 같은 모양이지만, 포챔스 한국어 실제 문구(특히 "되받아쳤다"류 추가 줄 유무)는 확인하지 못했다.

## 3. 화면 설계

### 3-1. 줄 구성과 변경 전·후

반사 행동(`action.bouncedMoveName`)일 때 `BattleTurnLog`가 `ActionMainLine`+`ActionEffectLines` 대신 새 `ActionLines`를 그린다(§3-3). 예시(킬라플로르가 매직미러 브리무음에게 스텔스록):

```
변경 전  킬라플로르의 스텔스록 — 브리무음의 매직미러! 기술이 되돌아왔다! · 뾰족한 바위가 되돌아와 시전자 쪽 필드에 깔렸다!
변경 후  킬라플로르의 스텔스록
         브리무음의 매직미러!                                   (is-muted)
         브리무음의 스텔스록 · 상대 편 필드에 뾰족한 바위가 깔렸다!
```

| 반사된 기술 | 변경 전 | 변경 후 |
|---|---|---|
| 압정뿌리기·독압정·끈적끈적네트 | `… 기술이 되돌아왔다! · 상대 편 필드에 …`(**시전자 쪽인데 "상대 편"으로 오표기**) | 3줄 구성, `브리무음의 압정뿌리기 · 상대 편 필드에 압정이 흩뿌려졌다!`(반사한 쪽 기준이라 맞다) |
| 상태이상(도깨비불 등) | 머리 줄에 인라인, 효과 줄 `킬라플로르는 화상을 입었다!` | 3줄 구성, 효과 줄 **같음** |
| 랭크 하락 | 효과 줄 대상 = 시전자(`actorName` 분기) | 효과 줄 대상 = 시전자(뒤집힌 `defenderName`) — **같음** |
| 하품 | `킬라플로르의 졸음을 유도했다!` | `상대 킬라플로르의 졸음을 유도했다!` — **"상대" 접두가 붙는다**(비반사와 같은 문구, V4) |
| 앙코르 | `킬라플로르의 앙코르!` / `킬라플로르는 앙코르를 받았다!` | `브리무음의 앙코르!` / `킬라플로르는 앙코르를 받았다!` — **첫 줄 주어가 사용자로** |

### 3-2. 보기용 사본 `reflectedView`

```ts
/** 매직미러 반사(8.3 B6): 엔진이 반사 구간을 "방어측이 되받아쳐 쓴 것"으로 처리하므로 줄도 그렇게 읽는다 — 이름과 체력 표기 편을 맞바꾼 사본 */
function reflectedView<P extends { action: ActionLogEntry; actorName: string; defenderName: string }>(p: P): P {
  const { bouncedMoveName: _b, bouncedByAbilityName: _a, copycatCalledMoveName: _c, sleepTalkCalledMoveName: _s, ...rest } = p.action;
  return { ...p, actorName: p.defenderName, defenderName: p.actorName, action: { ...rest, actor: opponentKey(p.action.actor) } };
}
```
- `bouncedMoveName`을 사본에서 지워 **효과 줄의 기존 반사 분기가 걸리지 않게** 한다(분기 자체도 지운다 — 이중 안전). 지우는 곳 6개: `actionMainLineParts.tsx:55~57`(인라인 문구)·`:112~117`(스텔스록 분기), `ActionEffectLines.tsx:164~169`·`:297~310`·`:315~317`·`:914`(`bounced ? actorName : defenderName` 4곳 — 뒤집힌 이름이면 `defenderName`이 곧 시전자).
- `actor`를 뒤집으면 `useActionHp`의 편 기준(C6)이 반사한 쪽을 사용자로 읽어 체력 표기가 엔진 모델과 맞는다. `SelfSwitchAfterMoveLines`·`ForcedOpponentSwitchLines`·`RedCardSwitchLines`(`BattleTurnLog.tsx:143~154`)는 **원래 `action.actor`를 그대로** 쓴다(원 행동 기준).

### 3-3. 새 컴포넌트 `ActionLines` (`ActionMainLine.tsx`에 함께 둔다)

```tsx
export function ActionLines(props) {            // props: action·actorName·defenderName·headDamage·headDamagePercent·percentOnly
  if (!props.action.bouncedMoveName) return <><ActionMainLine {...props} /><ActionEffectLines {...props} /></>;
  const r = reflectedView(props);
  return (<>
    <div className="battle-turn-line"><MoveUseLabel action={props.action} actorName={props.actorName} /></div>      {/* ① 원래 시전자의 기술 줄 (흉내쟁이·잠꼬대 표기 포함) */}
    <div className="battle-turn-line is-muted">{props.defenderName}의 {props.action.bouncedByAbilityName}!</div>   {/* ② 특성 안내 */}
    <ActionMainLine {...r} /><ActionEffectLines {...r} />                                                         {/* ③ 반사한 쪽이 쓴 줄 + 효과 줄 */}
  </>);
}
```
- `MoveUseLabel`은 머리 줄의 흉내쟁이 줄·`{시전자}의 {기술}`·잠꼬대 표기를 **함수로 뽑아** 머리 줄과 ①이 함께 쓴다(코드 복사 방지). 비반사 행동은 지금과 **바이트 단위로 같은 출력**이어야 한다(시험 B6-n).
- `BattleTurnLog.tsx:131~141`의 두 컴포넌트 호출을 `ActionLines` 하나로 바꾼다(`HpFormatContext.Provider`는 그대로 감싼다).
- 파일: `ActionMainLine.tsx`(`ActionLines`·`reflectedView`), `actionMainLineParts.tsx`(분기 삭제·`MoveUseLabel`), `ActionEffectLines.tsx`(분기 삭제), `BattleTurnLog.tsx`(호출 교체). **엔진·타입·연출·데이터는 안 건드린다.**

## 6. 해시·검증 예상

**기준 출력 전부 불변**(엔진·데이터·AI 변경이 없다 — `src/components/**`만 바뀐다). 따라서 `verify-kit` 기준값은 갱신하지 않는다. 그래도 **A4·A5·B2에서 "불변 예상"이 틀린 적이 있어** 구현 뒤 `regress 200`(약 1분)로 `04ba3f40…`을 확인하고, 전체 `SERIAL=1 verify.sh`는 PR 전에 한 번 돌린다(약 8분). **측정 예정(시작 전 보고)**: `test:ai`(약 1분) · `regress 200` · 필요 시 `verify.sh` 14항목(약 8분). 메모리 압박(2.4GB 여유)이 있으니 `verify.sh` 중에는 개발 서버·다른 작업을 띄우지 않는다.

## 7. 구현 순서와 PR

브랜치 `feature/8.3-b6-magic-mirror-log`(`dev`에서), 커밋 1개, 항목 PR 1개. 순서: 시나리오 먼저(실패 확인, 특히 B6-g~l의 **실제 오표기 출력 확인** — 설계서 §3-1의 "오표기될 수 있다"를 사실로 바꾼다) → 분기 삭제·`MoveUseLabel` 추출·`reflectedView`·`ActionLines` → `BattleTurnLog` 호출 교체 → `tsc`·`oxlint`·`build`·`test:ai` → 해시 확인 → **화면 확인(사용자 위임)** → PR → 확인 후 squash 머지·브랜치 정리.

**화면 확인 체크리스트(구현 뒤 안내)**: 매직미러 포켓몬(브리무음)을 상대로 — ① 스텔스록: 3줄(`시전자의 스텔스록` / `브리무음의 매직미러!` / `브리무음의 스텔스록 · 상대 편 필드에 …`) ② 압정뿌리기·독압정·끈적끈적네트: 같은 3줄, "상대 편"이 맞는 쪽 ③ 도깨비불·하품·앙코르: 3줄과 효과 줄 대상 ④ 일반(비반사) 행동 줄이 이전과 같다 ⑤ 저장해 둔 옛 영상을 재생해도 새 3줄로 보인다 ⑥ AI 상대전에서 반사한 쪽이 AI일 때 체력 표기가 이상하지 않다(퍼센트/실수치).

## 9. 알면서 두는 것 (백로그 한계로 옮길 후보)

- **카드 연출**: 특성 배너 표시·방어측이 기술을 쓰는 듯한 모션은 8.4(UI/UX) 후보다. 지금 `useTurnFx`는 시전자 카드에 연출한다.
- **반사 범위 차이(V3)**: 엔진이 Showdown보다 넓게 반사하는 기술이 있을 수 있다 — 규칙 차이라 조사·정렬은 별도 항목(F8 후보).
- 효과 줄 전체를 "필드 단위"로 다시 모델링하지 않는다. 이름 맞바꿈은 `defenderName`을 쓰는 줄이 **반사 구간에서 기록된 필드**라는 가정에 기대는데(C5), 반사 구간 **밖**에서 `actor` 기준으로 기록된 필드가 반사 행동에 섞이면 틀릴 수 있다. 시험 B6-m·g~l이 확인한 범위 밖의 조합은 화면 확인에서 걸러진다.
- 체력 표기(C6)는 AI 상대전에서 반사한 쪽이 AI일 때의 퍼센트/실수치를 맞추기 위해 `actor`를 뒤집는다. 반사 행동에 체력 수치가 나오는 기술(아픔나누기류)이 드물어 실제 화면 확인 대상(§7 ⑥)이다.
- 효과 줄의 주어 첫 줄 `앙코르!`·`졸음을 유도했다!` 같은 기존 중복·문체는 건드리지 않는다.
