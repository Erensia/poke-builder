## 2. 고칠 것

### 2-1. 4096 연산 도구 (`src/lib/damageFormula.ts`)
- `modify4096(value, numerator)` = `tr((tr(value × numerator) + 2047) / 4096)` — **배율은 4096분율 정수(numerator)로 직접 받는다**(§9-1). 소수 배율에서 분자를 만드는 `q4096(m, stage)`는 데이터 소수(1.3·1.2 …)를 분자로 바꾸는 입구 한 곳에만 둔다.
- `chain4096(...factors)` = 인자를 차례로 `((prev×next)+2048)>>12`로 곱한 소수(4096분율) 반환. 인자가 1이면 건너뛴다.
- **부동소수점 보정**: 정수 분자를 쓰는 곳은 보정이 필요 없다. 소수 입구 `q4096`만 `m×4096`이 정수에 1e-6 이내면 반올림(예: `1/(4/3)=0.7500000000000001`), 아니면 내림.
- `roundHalfDown`은 B9(방어 관통 ×0.25)·다른 호출처가 쓰므로 **남긴다**(`modify4096`이 `roundHalfDown`과 같은 값을 내는 경우는 4096분율이 정확히 표현될 때뿐).

### 2-2. `integerHitDamage` (`damageFormula.ts`)
| 단계 | 현재 | 변경 |
|---|---|---|
| 위력 | `max(1, roundHalfDown(power × baseMultiplier))` | `max(1, modify4096(power, baseMultiplier))` |
| 방어 스탯(두꺼운지방 등) | `fl(fl(def×랭크) × bulkMultiplier)` | `modify4096(fl(def×랭크), bulkMultiplier)` — 1.5·0.5·2는 값이 같고 1.5 외 배율만 달라질 수 있다 |
| 날씨 | `roundHalfDown(d × w)` | `modify4096(d, w)` |
| 급소 | `fl(d × crit)` | **변경 없음**(`crit`는 1.5 고정 — 스나이퍼 2.25는 §2-4) |
| 자속 | `roundHalfDown(d × stab)` | `modify4096(d, stab)` |
| 상성 | `fl(d × te)` | 변경 없음 |
| **화상(신규)** | (최종 보정에 포함) | 상성 직후 `burnMultiplier`(신규 필드, 기본 1)가 1이 아니면 `modify4096(d, burn)` |
| 최종 보정 | `roundHalfDown(d × final × firstHit)` | `modify4096(d, chain4096(final, firstHit))` |

- `DamageParts`에 `burnMultiplier?: number`를 추가한다(생략 시 1). `hitsToKill.ts`·`moveDamage.ts`·`koChanceByUses` 등 `DamageParts`를 그대로 넘기는 곳은 자동으로 따라온다(필드 하나가 늘 뿐).

### 2-3. 배율을 모으는 곳을 `chain4096`으로 (곱 → 체인)
배율이 **같은 Showdown 이벤트**에 속하는 것끼리만 체인으로 묶는다.

| 단계(이벤트) | 묶는 곳 | 구성 요소 |
|---|---|---|
| 위력(`BasePower`) | `battlePower.ts` `computeDamage`의 `baseMultiplier: abilityMultiplier × itemMultiplier × fieldMultiplier` | 특성·도구·필드·젬·열거 안 된 곱 |
| 최종(`ModifyDamage`) | `hitResolution.ts:287`, `matchupEvaluator.ts:687` | 공격측 도구(`itemFinalMultiplier`), 방어측 특성(멀티스케일 등)·반감 열매·벽·대검돌격, 스나이퍼(§2-4) |
| 첫 타 전용 | `firstHitFinalMultiplier` | 최종 체인의 마지막 항으로 이어 붙인다(Showdown은 같은 `ModifyDamage` 체인) |

- **방어측 배율은 지금 "내구 배율(÷)" 꼴**(`finalDefenseMultiplier 2` = 절반)이다. 체인에는 **데미지 배율(×)** 로 넣어야 하므로 사이트에서 `1/x`를 구해 `q` 보정을 거친 뒤 넣는다(멀티스케일·복슬복슬 2 → 0.5, 하드록 4/3 → 0.75, 반감 열매 2 → 0.5, 벽 2 → 0.5 — 모두 4096분율로 정확히 표현됨).
- **순서**: Showdown `chain`은 순서에 따라 반올림이 다를 수 있고 순서는 핸들러 우선도·속도로 정해진다. 엔진은 **고정 순서**(공격측 도구 → 스나이퍼 → 방어측 특성 → 열매 → 벽)를 쓴다. 한계는 §7.
- 공격·방어 **스탯** 체인(`ModifyAtk`·`ModifyDef`)은 이번에 **건드리지 않는다**(1.5배는 현행과 같은 값, 그 외는 E1 2차에서 개별 확인).

### 2-4. 화상·스나이퍼 분리
- **화상**: `hitResolution.ts:198`의 `burnMultiplier`를 `finalMultiplier` 곱에서 빼서 `DamageParts.burnMultiplier`로 넘긴다. 평가기·역산은 `finalOffenseMultiplier: burnDamageMultiplier(…)`로 같은 값을 넘기는 곳이 5곳(`matchupAssumptions.ts:29`·`attackInference.ts:285,307`·`defenseInference.ts:476`·시험 ⑩)이라, **이 옵션의 의미를 "화상"으로 한정**하고 `matchupEvaluator`가 `burnMultiplier`로 옮기게 한다(옵션 이름은 유지 — 호출처 변경 최소). 다른 용도로 `finalOffenseMultiplier`를 쓰는 곳이 없음은 구현 전 grep으로 재확인.
- **스나이퍼**: 급소 배율은 항상 1.5(`CRITICAL_DAMAGE_MULTIPLIER`)로 두고, 스나이퍼(`critDamageMultiplier` 2.25)일 때 급소 타에서 **최종 체인에 ×1.5를 추가**한다. `Ability.critDamageMultiplier` 필드는 의미가 "급소 타 최종 배율 1.5"로 바뀌므로 **필드를 `critFinalMultiplier`(값 1.5)로 이름·값 변경**(`abilities.json` 1건, 데이터 변경 이력 항목 추가). 사용처: `battlePower.ts:376,418,451`·`hitResolution.ts:291`·`matchupEvaluator.ts:585,912`. `critMultiplier` 자체는 그대로 1.5.

## 3. 규칙(Showdown 소스 대조, 엔진 기존 동작)
- 체인 곱: `((prev4096 × next4096) + 2048) >> 12`, 인자 양자화 `tr(x × 4096)`. 최종 적용은 `modify`: `tr((tr(value × m4096) + 2047) / 4096)`.
- 화상 `modify(d, 0.5)`는 상성 뒤·`ModifyDamage` 앞. 근성 특성과 객기(facade, gen6+)는 화상 감소에서 제외된다(현행 `ignoresBurnAttackPenalty`가 같은 조건인지 시험 1에서 확인).
- 스나이퍼는 `ModifyDamage` 이벤트 핸들러라 체인 안에 들어간다.
- **바뀌지 않는 것**: 기본 데미지·급소(내림)·난수·상성·최소 1·방어 관통 ×0.25(B9)·고정 데미지·일격기.

## 7. 위험·한계
- **사례 40건이 구별력이 없음**(§0): 4096 체인이 본가와 일치한다는 직접 증거는 소스(Showdown = 본가 모방)뿐이다. 외부 계산기 조합 사례 1건이 있으면 확정(Q1).
- **체인 순서**: Showdown은 핸들러 우선도·속도순, 엔진은 고정 순서. 반올림 차이는 1 이하·드문 조합에 한정되며 한계로 기록한다.
- **내구 배율(÷) → 데미지 배율(×) 변환**의 부동소수점: `q` 보정 + 시험 1·4가 지킨다.
- 위력 체인에서 **열거 안 된 곱**(근거 없는 특성·도구를 위력에 묶어 둔 것, `damageFormula.ts` 머리 주석)도 체인에 같이 들어간다 — 사례가 생기면 단계를 옮기는 기존 방침 유지.
- 평가기·역산도 같은 함수를 쓰므로 한 번에 따라가지만, 화면 수치가 바뀐다는 사실을 릴리스 노트(`README` 최신화 때)에 한 줄 적는다.
