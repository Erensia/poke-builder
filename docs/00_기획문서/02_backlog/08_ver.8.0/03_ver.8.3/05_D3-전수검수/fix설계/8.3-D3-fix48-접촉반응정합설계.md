- **E8-26 원인**: `abilities.json`의 `hitTrigger.on`을 정한 Phase 5가 "정전기·불꽃몸 = 물리 접촉을 받으면"으로 읽었다(`types/ability.ts` 87행 주석). Showdown은 `onDamagingHit`에서 `checkMoveMakesContact`만 본다(카테고리 조건 없음). `physicalContact`를 쓰는 특성은 **정전기·불꽃몸·독가시 3종뿐**이고 코드 사용처는 `abilityHitTriggers.ts` 매처 하나(스크립트·화면 사용 없음).
- **E8-27 원인**: `hitResolution.ts` 634행 블록(`disablesAttackerMove`)이 PP만 0으로 만든다. 이미 있는 사슬묶기 경로(`mirroredEffects.ts` `setsDisable`, `inflictVolatile(…,"disable",…)`, 지속 `DISABLE_DURATION = 4` = Showdown 5에서 "아직 안 움직임 −1", 아로마베일 `blocksMentalMoves`, 멘탈허브 `getMentalHerbCureResult`)를 쓰면 지속·치료·면역이 한 번에 맞는다. 기술 선택 차단은 `volatile.active.disable`을 보는 기존 경로(`battleRules.ts`·`moveRestrictionKind`)가 사슬묶기와 똑같이 처리한다. **봉인 대상은 호출한 기술이어야 하는데** 선택한 기술은 `resolveAction`의 입력 `move`(`resolveAction.ts` 951행)에만 남고 `c.move`는 `pre.move`(호출된 기술)로 덮이므로(985행 부근) 타 처리에는 선택한 기술이 전달되지 않는다 — 배선이 필요하다(§2-2).
- **E8-28 원인**: 드레인만 타 처리 뒤에 있다. 드레인 기술 8종(기가드레인·드레인펀치·드레인키스·원념의칼·흡혈·파라볼라차지·우드혼·휘적휘적포)은 **기술 데이터상 단발·비고정**(`maxHits`·`fixedDamage` 없음)이지만, **부자유친은 엔진에도 구현돼 있어**(`abilities.json` `followUpHitPowerMultiplier: 0.25`, `hitResolution.ts` 883~905행 `followUpHitDamage` 분기) 단발 드레인이 실전에서 **2타**가 된다. 후속 타는 첫 타 직후 같은 컨텍스트로 위력 ×0.25(반올림)를 한 번 더 날리고 그 타도 접촉 반응·울퉁불퉁멧을 거친다 — 드레인이 이 타들의 피해로 **타마다** 일어나야 한다.

## 2. 변경

### 2-1. E8-26 — 데이터 3건 + 사용되지 않는 값 정리 (① 단계)
1. `src/data/abilities.json`: 독가시·정전기·불꽃몸의 `hitTrigger.on`을 `"physicalContact"` → `"contact"`. **줄 단위 치환**(재직렬화 금지, 작업 복사본 CRLF). `npm run validate:data`.
2. `src/lib/abilityHitTriggers.ts`·`src/types/ability.ts`: 이제 아무 데이터도 쓰지 않는 `"physicalContact"`(유니언 값·`case`·주석)을 **지운다**(`grep`으로 사용처 0 확인 후).
3. `docs/데이터변경이력.md`에 한 항목(특성 3건, 기술·포켓몬 수치 불변).
- **AI**: `hitTriggerMatchesMove`는 AI(`moveDamage.ts` 접촉 데미지 추정)도 쓴다 — 매처 동작은 `contact`가 이미 있어 변경 없음.
- **영향**: 정전기·독가시가 특수 접촉기(4종)에도 확률 30%로 발동 — 샘플 도달 작음, `regress` 변동은 무작위 빌드에서 4종 기술과 3종 특성이 만나는 장면에 한한다. **방진패드**는 챔피언스 합법 도구 166종에 없다(검수 확인: 방진패드를 지니면 무발동은 Showdown 쪽 사실이고 엔진에는 도구가 없어 해당 없음).

### 2-2. E8-27 — 저주받은바디를 4턴 봉인(사슬묶기 경로)으로, 봉인 대상은 호출한 기술 (② 단계)
**배선(A-2)**: `resolveAction.ts`에서 **입력으로 들어온 기술**(`move` 인자, 잠꼬대·따라하기 호출 전)의 id를 `c.selectedMoveId`로 보관해 `HitResolutionInput`·`HitCtx`에 `selectedMoveId: string`·`selectedMoveName`(로그용)으로 넘긴다(호출 기술이 없으면 `c.move`와 같다). `hitResolution.ts` 634행 PP 0 블록을 아래로 교체한다(조건 순서는 Showdown `cursedbody`·`disable.onStart`):
- 발동 자격: 현행 `!c.delayedHit`(미래예지 등은 무발동, Showdown `futuremove`)을 **유지**하고, `remainingPp[c.selectedMoveId] !== undefined`(발버둥은 PP 기록이 없어 자연히 제외 = Showdown `struggle`)로 바꾼다. 따라하기가 기술칸에 없는 기술을 불러도 선택한 기술인 따라하기가 기준이라 발동한다. 추가로
  - **`remainingPp[c.selectedMoveId] > 0`**(마지막 PP를 쓴 직후면 `onStart`가 실패 — 이 시점은 PP가 이미 1 깎인 뒤다, 호출 기술에서는 **호출한 기술의 슬롯**이 기준이다. 잠꼬대 PP가 0이면 무발동),
  - **`!hasVolatile(attacker.volatile, "disable")`**(이미 봉인 중이면 무발동, 기존 봉인 유지),
  - **`!c.attackerAbility?.blocksMentalMoves`**(아로마베일 — 사슬묶기·헤롱헤롱바디와 같은 플래그, Showdown은 무음 차단).
- 부여: `attacker.volatile = inflictVolatile(attacker.volatile, "disable", c.random, c.selectedMoveId)` — **지속 보정 0**(`targetAlreadyActedAdjust`는 쓰지 않는다: 저주받은바디는 공격측이 지금 움직이는 중이라 Showdown이 "아직 안 움직임"과 같게 `duration--` 처리하므로 기본값 4가 정확하다).
- 멘탈허브: `getMentalHerbCureResult(c.attackerItem, c.attacker.itemConsumed ?? false)`이면 방금 건 `disable`을 지우고 도구를 소모(`consumeItem`)하며 `c.statusCureBerryItemName`을 채우고 로그 필드(`abilityDisabledMoveName`·`ev.disabledMoveName`)를 비운다 — 헤롱헤롱바디 분기(`hitResolution.ts` 556~565행)와 **같은 패턴**이다(같은 6줄 복제를 3번째로 늘리지 않도록 구현 때 공용 소함수로 묶을지 판단한다).
- 로그: 기존 필드(`abilityDisabledMoveName`·`abilityDisableAbilityName`)를 그대로 쓰되 **이름은 선택한 기술**(`c.selectedMoveName`)로 바꾼다 — **새 문구·UI 없음**. 이후 그 기술을 고르면 기존 사슬묶기 경로가 `moveRestrictionKind: "disable"`로 막는다.
- **부자유친 × 저주받은바디**(검수 확인, 추가 작업 없음): 1타에 봉인되면 2타는 "이미 봉인 중"으로 무발동(Showdown 786행) — 위 조건으로 자연히 맞다.
- **AI**: `disablesAttackerMove`를 읽는 곳은 엔진뿐(AI 모델링 없음). 선택 차단은 기존 `disable` 처리가 맡아 변경 없음.
- **영향**: 팬텀·포트데스(샘플 5슬롯)에게 맞은 공격측이 4턴 뒤 그 기술을 되찾는다 — 지금은 영구 봉인이라 `regress`가 가장 의미 있게 바뀔 단계다.
- **난수 소비 위치(검수 B-4, 참고)**: Showdown은 "이미 봉인 중"만 난수 **전**에 거르고 아로마베일·PP 0·멘탈허브는 난수 **후**에 걸린다. 엔진 난수열은 Showdown과 별개라 정합성 영향은 없고 해시에만 영향이 있다 — 확률 굴림(`c.random() >= chance`)은 현행 위치(자격 판정 전)를 유지한다.

### 2-3. E8-28 — 드레인 회복(해감액 포함)을 접촉 반응 앞으로, 타마다 (③ 단계)
- `applyRecoilAndDrain`의 **흡수기 블록**(`hitResolution.ts` 967~985행, 해감액 포함)을 함수 `applyDrainHeal(c)`로 빼고 **`applyDamageToDefender`·`applyEndurance` 직후, `triggerAbilityHitEffect` 직전**에 호출한다. `applyRecoilAndDrain`에서는 지운다. 조건·식은 **그대로**(`drainFraction`·큰뿌리·회복봉인·해감액·`reverseDrainHealsToDamage`).
- **타별 피해 기준(A-1)**: 한 행동에서 여러 번 호출되므로 호출 사이의 **실제 피해 증가분**으로 계산한다 — `c.drainAccountedDamage`(이미 드레인에 반영한 `actualDamageDealt` 누계)를 두고 `applyDrainHeal`이 `c.actualDamageDealt − c.drainAccountedDamage`를 그 타 피해로 쓴 뒤 누계를 갱신한다. 호출 위치(각각 그 타의 `applyEndurance` 직후·반응 직전): ① 고정 데미지 분기 ② 단발 분기 ③ **다단 루프 안**(타마다) ④ **부자유친 후속 타 분기**(`followUpHitDamage`). 드레인 기술이 다단·고정인 경우는 데이터에 없지만 같은 함수를 부르는 자리라 일관되게 맞는다. **회복량은 타마다 `floor(그 타 피해 × 비율)`을 계산해 더한다**(Showdown은 타마다 `Math.round` — 식은 바꾸지 않으므로 타별 내림의 합이 합계 내림과 1 HP 정도 다를 수 있다, 새 기준에 포함).
- **공격측 기절 시 중단(설계서 초안에 없던 것, 검수 시험 22 요구, 같은 원인)**: 1타 반응(까칠한피부·유폭·울퉁불퉁멧 등)으로 **공격측이 쓰러지면 그 뒤 타는 나가지 않는다**(Showdown `!pokemon.hp && targets.length === 1` → 루프 종료). 엔진은 ⓐ 부자유친 후속 타 분기 조건에 `!isFainted(c.attacker)`를 더하고 ⓑ 다단 루프의 중단 조건(`isFainted(c.defender) || c.substituteBroke`)에 `isFainted(c.attacker)`를 더한다. 부자유친이 아닌 일반 다단(씨기관총 등) × 접촉 반응으로 공격측이 죽는 장면도 같이 맞는다.
- **반응의 범위(B-2)**: 드레인은 **모든 `DamagingHit`보다 앞**이다. 엔진의 반응은 두 군데뿐이다 — 특성(`triggerAbilityHitEffect`: 까칠한피부·미끈미끈·헤롱헤롱바디·정전기·유폭·내용물분출·매지션 등)과 **울퉁불퉁멧**(`applyContactItemRecoil`, 모든 호출 자리에서 `triggerAbilityHitEffect` 바로 뒤에 호출됨). 둘 다 새 드레인 호출 뒤이므로 순서가 자동으로 맞고, **자보열매·령열매는 엔진에 없다**(`items.json` 확인)라 해당 없음. 구현 때 다른 `onDamagingHit`형 경로가 없는지 `grep`으로 한 번 더 확인한다.
- 반동 → 생명의구슬 → 조개껍질방울은 **현행 순서 그대로**(Showdown도 반응 뒤 — 검수 실행: 드레인 → 까칠한피부 → 생명의구슬)이므로 건드리지 않는다. 시험 17로 고정.
- **AI**: 기대 손실 추정(`moveDamage.ts` 242행)은 순서와 무관한 기댓값 합산이라 변경 없음.
- **영향**: 흡수기 16슬롯 × 접촉 반응 71슬롯. 풀피에서 쓰는 드레인은 회복이 사라지고(상한), 낮은 HP에서는 회복이 먼저라 반응으로 쓰러지는지 판정이 바뀐다. 부자유친 후속 타 중단·다단 루프 중단은 `regress` 무작위 빌드에서만 나타난다. 해시 변동이 세 단계 중 가장 클 수 있다.
- **분리(이번에 안 함)**: 드레인 양이 Showdown 세대 5+는 **`Math.round`(최소 보정 없음, 0 가능)** 인데 엔진은 `Math.floor` — E10 후보로 이미 기록됨(fix-32). 순서·타 단위만 바꿔야 단계별 해시 원인이 "드레인 위치" 하나로 분리된다(검수 B-1: 초안의 "최소 1"은 세대 4 이하의 `clampIntRange`와 혼동한 문구였다).

## 4. 알면서 둔 것
- **E8-29**(미끈미끈 × 미러아머 공격자의 반사)는 **이번에 안 한다**(기록만). 합법 조합(미끈미끈 보유 × 미러아머 공격자)이 실제로 있는지 먼저 확인하고 E8-b 이후에 판단한다. 코드 주석("대상 조합이 없어 생략")은 그대로 둔다.

- **흡수 + 기합의띠**: `applyEndurance`가 HP를 1로 되돌릴 때 `actualDamageDealt`를 줄이지 않아 드레인이 막기 전 피해로 계산된다(기존 한계, 이번 범위 밖).
