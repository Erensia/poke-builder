## 0. 한 줄 요약
`checkUsageGates`(`preHitEffects.ts` 280행)의 "대상이 쓰러졌고 살아 있는 대상이 필요한 기술이면 실패" 한 줄이 Showdown과 다른 장면 5가지를 고친다. 게이트 한 줄 수준이라 한 PR로 묶고, 판정 순서(f)는 범위가 커서 **분리를 권고**한다.

## 1. 현행과 목표
현행: `isFainted(c.defender) && needsLivingTarget(c.move)` → `blocked("usageCondition")`. 자기 대상·필드 기술은 통과.

| # | 장면 | Showdown | 엔진 현행 | 이 PR의 변경 |
|---|---|---|---|---|
| a | 고스트 저주 | `-fail`, HP 그대로 | 성공 처리, 사용자 HP 절반 소비 | 사용자가 고스트 타입인 `setsCurse`는 게이트에서 실패(HP 소비 전). 비고스트 저주(능력 변화)는 자기 대상이라 그대로 성공 |
| b | 록온 | `-fail` | 성공(자기 대상 volatile) | `lockOn`을 거는 기술도 게이트 실패 |
| c | 문어굳히기 | `-fail` | `hit=true`, 효과만 `!isFainted` 가드로 없음(로그 문구만 다름) | 게이트 실패로 통일(문구 "그러나 실패했다!") |
| d | 미래예지·파괴예지 | **성공**(쓰러진 자리에 예약, 2턴 뒤 그 자리 대체가 맞음) | 실패 | `delayedAttackTurns` 기술은 게이트 예외 |
| e | 대폭발·자폭 | `-fail`이지만 **사용자 기절** | 실패, 사용자 생존 | 실패 처리하되 `selfFaints`면 사용자 HP 0(마지막 1마리면 승패가 달라짐) |

구현 위치는 전부 `checkUsageGates` 280행 한 곳(+ e의 사용자 기절 반영). `needsLivingTarget`은 `moveContext.ts`(흡수 판정)도 쓰므로 **함수는 건드리지 않고** 게이트 쪽에서 조건을 덧붙인다.

## 2. 구현 때 프로브로 확정할 것 (검수 확인 요청)
1. c: 현행 `hit=true`가 되는 경로(`isOpponentTargetingMove`가 이미 true로 보일 텐데 왜 게이트를 통과하는지) — 프로브로 확인 후 설계서 §9에 기록. 게이트를 통과하는 이유가 다른 곳에 있으면 그곳을 고친다.
2. d: 예약이 쓰러진 자리의 `sideOf(defenderKey).futureSight`에 들어가는지, 2턴 뒤 그 슬롯 대체에게 맞는지(`finishTurn`). 쓰러진 슬롯이 대체로 교체된 뒤에도 `sourceIndex`가 유효한지.
3. e: 실패 결과에 `selfFainted`를 어떻게 실을지(`blocked` 반환 경로가 사용자 기절을 로그·`runTurn` 후속 처리(교체 요구·승패)에 전달하는지). 안 되면 `blocked` 호출 전에 `c.attacker.currentHp = 0`만 두고 `selfFainted` 필드를 맞춘다.

## 3. 시험 (먼저 쓰고 현행에서 실패 확인) — 파일 `87-ver83-d3fix56.mjs`
fix-55 시험(86번) 방식: 교체 직후 설치물로 쓰러진 상대에게 뒤 행동을 맞춘다.
1. a: 고스트 저주 → 실패, 사용자 HP 불변. 비고스트 저주 → 성공(회귀).
2. b: 록온 → 실패, `lockOn` 없음.
3. c: 문어굳히기 → 실패 로그, 상태 불변.
4. d: 미래예지 → 예약 성공, 2턴 뒤 새 슬롯에 적중.
5. e: 대폭발·자폭 → 실패 + 사용자 HP 0. 사용자가 마지막 1마리면 상대 승.
6. 회귀: 자기 대상·필드 기술(칼춤·스텔스록)은 그대로 성공, 일반 공격은 그대로 실패.
