### 1-1. 지역 함수 `noTargetGate(c)` (R6)
```ts
function noTargetGate(c: PreHitCtx) {
  if (isFainted(c.defender) && !c.move.delayedAttackTurns && !(c.move.chargeTurn && !c.releasingCharge) &&
      (needsLivingTarget(c.move) || (c.move.setsCurse && c.attacker.types.includes("고스트")) ||
       c.move.inflictsVolatile?.some((v) => v.volatile === "lockOn") || c.move.octolock)) {
    if (c.move.selfFaints && !c.attackerAbility?.preventsSelfFaintMoves) c.attacker.currentHp = 0;
    return { value: c.blocked("usageCondition") };
  }
}
```
(검수 부록 임시 패치에 R-g 예외를 더한 형태. 구현 때 실제 필드명으로 확정.) `needsLivingTarget`은 `moveContext.ts` 102행(타입 흡수 판정)도 쓰고, "살아 있는 대상이 필요한 기술"이라는 의미를 유지해야 하므로 **함수는 건드리지 않고** 게이트 쪽에서 조건을 덧붙인다(검수 동의). a의 타입은 "기술을 고른 시점의 타입"이라 Showdown(`PrepareHit` 뒤 변환자재·리베로)과 일치한다.

## 2. 확정된 사항 (검수 프로브로 닫힌 것)
1. c: 위 표의 원인(`octolock`만 있는 데이터). 다른 곳을 고칠 필요 없음.
2. d: 예약·착탄·`sourceIndex` 모두 문제 없음(임시 패치로 2턴 뒤 `party[2]`가 33 데미지 맞음). "이미 예약이 있으면 실패"는 유지.
3. e: 새 필드 불필요. `blocked()`(213행)가 `selfFainted: isFainted(c.attacker)`(232행)를 호출 시점 HP로 정하고, `forcedSwitch`·`winner`는 `finishTurn`이 파티 상태로 계산한다(예비가 있으면 `forced={a,b}`, 마지막 1마리면 `winner=a`). 엔진은 280행이 345행(습기)보다 앞이라 습기 예외를 조건에 넣어야 한다.
4. R-i 호출 기술 영향: `resolveAction.ts` 676행 주석("쓰러진 상대를 노리는 기술은 preHitEffects에서 실패해 데미지가 0")의 전제가 이 경로에서 깨져 있었다 — 이 수정으로 전제가 맞게 된다(주석 문구는 확인만).

## 3. 시험 (먼저 쓰고 현행에서 실패 확인) — 파일 `87-ver83-d3fix56.mjs`

1. a: 고스트 저주 → 실패, 사용자 HP 불변. 비고스트 저주 → 성공(공·방 +1, 스피드 −1).
2. b: 록온 → 실패, `lockOn` 없음.

6. 회귀: 칼춤·스텔스록 성공, 일반 공격(누르기) 실패, 철제광선 실패·반동 없음.
