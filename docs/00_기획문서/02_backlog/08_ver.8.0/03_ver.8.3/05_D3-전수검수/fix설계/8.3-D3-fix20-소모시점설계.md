## 1. 무엇이 다른가
엔진은 걸린 포켓몬이 **행동할 때**(`preHitEffects.ts` `checkActionBlockers` 2-0절)마다 `consumeVolatileTurn`으로 줄인다. 수면·얼음·마비·풀죽음·혼란 자해 등으로 이 판정 앞에서 막힌 턴은 줄지 않는다. Showdown은 턴 종료에 줄어 그런 턴도 지속에서 빠진다.
막히는 **행동 수**는 평소(걸린 포켓몬이 매 턴 행동)에는 같다. **예외(검수 §2-1)**: 턴 시작에 교체로 들어온 대상에 건 도발은 Showdown에서 `activeTurns = 0`이라 +1이 없어 **3행동 → 2행동**이 된다(Showdown과 일치하는 방향의 변경, 해시 변동 원인 후보):
| | 엔진 | Showdown(걸리는 시점별) |
|---|---|---|
| 도발 | 3 | 대상이 아직 안 움직임 → 3(걸린 턴 포함 3행동) / 이미 움직임 → 4(다음 턴부터 3행동) |
| 앙코르 | 3 | 같음(3 / 4) |
| 사슬묶기 | 4 | 대상이 아직 안 움직임 → 4 / 이미 움직임 → 5 — 막는 행동 4번 |
따라서 **부여 시점 보정과 턴 종료 소모를 한 묶음으로** 옮겨야 평소 값이 유지된다.

## 2. 고칠 것
1. **부여 시점 보정**(`mirroredEffects.ts`): 도발(`inflictVolatile`, 약 860·862행의 일반 경로)·앙코르(약 1650행)·사슬묶기(`setDisabledMoveName` 계열)에 부여 때의 "대상이 이미 움직였는가"를 넘겨 지속 턴을 정한다. **판정 기준(검수 §2-1 필수): `c.movesSecond`(공격측이 후공인가)가 아니라 "대상(현재 활성 개체)이 이번 턴 필드에 있었고 그 행동 차례가 이미 지났다(수면·마비·풀죽음 등으로 막혔어도 포함)"**. `movesSecond`로 대신하면 U턴·볼트체인지·퀵턴·막말내뱉기로 먼저 빠지고 새로 나온 대상에 도발이 한 행동 더 걸린다(Showdown `activeTurns = 0`이라 +1 없음). 도발의 +1은 여기에 "이번 턴 입장이 아님"을 더한 조건이고, 앙코르·사슬묶기는 교체 입장 직후 `lastMove`가 없어 실패한다(엔진이 교체 시 마지막 기술을 지우는지 구현 첫 단계에서 확인, 다르면 E10). 이전에는 `c.movesSecond`로 적었으나 그 정의가 U턴 뒤·턴 시작 교체 입장 대상에 어긋나므로 구현 첫 단계에서 "대상 자신의 행동 차례 경과" 신호(행동 큐 또는 이번 턴 행동 여부)가 엔진에 있는지 읽고, 없으면 최소한의 표지를 추가한다. `inflictVolatile`에 선택 인자 `durationAdjust`(도발·앙코르: 이미 움직였으면 +1, 사슬묶기: 아직이면 −1)를 추가하는 최소 변경. 기본 지속은 도발 3·앙코르 3·**사슬묶기 5**(Showdown 기준 — 기존 4는 "아직 안 움직임 −1"을 미리 반영한 값이므로 새 기준 5에서 보정한다).
   - **저주받은바디 경로(검수 §2-2 필수)**: 저주받은바디(팬텀·눈여아 숨겨진 특성·드래펄트 — 챔피언스 합법)로 걸린 사슬묶기는 **기술을 쓰는 중인 공격자**가 묶이는 경우라 −1 → 4이고, 그 턴 행동은 이미 끝났으므로 턴 종료 3 → **다음 3행동만 막힌다.** 엔진이 저주받은바디를 구현했다면 그 경로의 `setDisabledMoveName` 호출에 −1을 넘긴다("공격측 후공 = 이미 움직임" 규칙을 그대로 적용하면 +0이 되어 4행동이 된다). 미구현이면 E8 백로그.
2. **소모를 턴 종료로**: `finishTurn.ts` `tickBlockVolatiles`(회복봉인·목조르기를 이미 "턴 종료마다 줄고 걸린 턴도 센다"로 처리)의 대상 목록에 `taunt`·`disable`·`encore`를 더한다. `checkActionBlockers` 2-0절의 `consumeVolatileTurn` 호출 3곳(도발·사슬묶기·앙코르)은 **삭제** — 검사(`hasVolatile`·막힘 판정)는 그대로 둔다.
   - **앙코르 PP 0 조기 해제(권고, 검수 §2-3)**: `encore.onResidual`(순서 16)은 앙코르 기술 PP가 0이면 턴 종료에 즉시 해제한다. 소모를 `tickBlockVolatiles`로 옮기는 김에 같은 자리에서 처리하면 한 줄이다. 엔진이 이미 다른 곳에서 처리하면 변경 불필요 — 구현 첫 단계 grep. 없으면 E10 백로그.
3. **끝나는 시점**: 마지막 턴 종료에 0이 되어 해제되므로 그 턴의 행동은 여전히 막힌다(Showdown과 같음).
4. **AI**: `ai/`에서 도발·앙코르·사슬묶기의 `turnsRemaining`을 읽는 곳이 있으면(없다는 grep 결과를 구현 첫 단계에서 재확인) "남은 틱 수"가 곧 "남은 막히는 행동 수"이므로 의미가 같아 변경 불필요. 읽는 곳이 있으면 같은 PR에서 맞춘다.
5. **하지 않는 것**: 트집(지속 없음)·봉인·검은눈빛은 소모 없음 — 변경 없음. 앙코르 불가 기술 19종·`mefirst` 예외는 E10.

## 3. 영향·측정
막히는 행동 수는 평소 같고, 걸린 포켓몬이 걸린 동안 행동하지 못하는 턴(수면·마비·풀죽음)이 있을 때와 걸린 뒤 같은 턴에 해제되는 시점에서만 변한다. 해시는 거의 불변일 것이나 변동 가능 — `regress 200`·`regress 20000`·`STATUS=1 greedy 60`(약 3분) 뒤 `SERIAL=1 verify.sh`. **불변이어야 하는 것**: `test:inference` 결합·차분 해시.
