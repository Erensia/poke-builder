## 1. 무엇이 다른가
- 열탕(물): `moves.json`에 `curesStatus: { target: "opponent", status: "freeze" }`가 있어 얼음 상대를 해동한다 ✓.
- **열사의대지(땅)**: 같은 표시가 없다. 자기 해동(`thawsUserOnUse`)만 있어서, 얼음 상대에게 맞춰도 얼음이 풀리지 않는다.

## 2. 고칠 것
`src/data/moves.json` 열사의대지(5373행 근처)에 열탕과 같은 `"curesStatus": { "target": "opponent", "status": "freeze" }` 추가.
**가드(Q2 확정)**: `mirroredEffects.ts` `healAndThaw`의 ① `curesStatus` 중 대상이 상대(`target: "opponent"`)인 해동 ② 불꽃 타입 데미지 기술의 얼음 해동에 **"실제로 맞았을 때만"** 조건을 건다 — `c.hit && !c.blockedByProtect && !c.hitSubstitute && c.damage > 0`(같은 파일 `damagingMoveLanded`는 대타 적중을 맞음으로 세므로 **그 함수를 쓰지 말고** 대타를 따로 제외한다). Showdown: 대타 뒤는 `afterMoveSecondaryEvent` 대상에서 빠지고(champions `scripts.ts` 350·575), 불꽃 해동은 `onDamagingHit`(피해를 입혔을 때)이라 대타·무효 모두 해당 없다. **자기 대상 `curesStatus`(물거품아리아류의 자기 치료 등)와 파티 치료는 건드리지 않는다.** 구현 첫 단계: 시험 7·8을 먼저 돌려 현행에서 실패하는지(= 가드 부재) 확인하고, 이미 앞단에서 걸러져 통과하면 코드 가드는 넣지 않고 시험만 남긴다.
- 순서가 Showdown과 같다: 엔진은 `inflictStatuses`(화상 30% 시도 — 얼음이라 실패) → `healAndThaw`(해동) 순이고, Showdown도 화상은 부가효과, 해동은 `onAfterMoveSecondary`라 부가효과 뒤다. 결과적으로 **얼음 상대는 화상이 안 걸리고 풀리기만 한다.**
- 로그: 열탕과 같은 `curedStatus` 경로라 같은 문구가 나온다(새 문구 없음).
- 열사의대지의 효과 문구(`effect`) 대조(B3 방식): 이미 "30% 화상"만 적혀 있으면 문구는 그대로 둔다. 열탕 문구도 해동은 적지 않았으므로 일관된다.

## 3. 영향·측정
샘플 파티 30여 개 중 열사의대지 보유 0건. 랜덤 파티·AI 시뮬은 학습 기술을 쓰므로 변동 가능성은 낮지만 0은 아니다 — `regress 200`·`regress 20000`·`STATUS=1 greedy 60`(약 3분, `SERIAL=1`)으로 확인하고 불변이면 `verify.sh`는 마지막에 한 번(약 8분). 시작 전에 명령·예상 시간 보고.

## 4. 시험 `46-ver83-d3fix15.mjs`
1. 열사의대지 → 얼음 상대: 명중 뒤 상대 상태 없음, 로그 `curedStatus` = 얼음(현행 실패).
2. 같은 상황에서 화상은 걸리지 않는다(얼음이라 부가효과 실패, 순서 확인) — 상대가 해동된 뒤 같은 기술 재사용 시 화상 30%는 정상(기존 동작).
3. 열탕과 같은 결과(대조군, 현행도 통과).
4. 얼음이 아닌 상대(수면·마비·없음)에는 영향 없음 — `curesStatus.status`가 `freeze`로 한정.
5. 무효 타입에는 해동 없음: 열사의대지가 안 먹히는 상대(비행·부유 등)는 명중 전에 막히므로 얼음 유지(현행 규칙 유지 확인 — 같은 `curesStatus` 경로가 열탕과 같은 위치에서 실행됨).
6. 데이터 검사: `curesStatus` 보유 기술 중 `status: "freeze"` 대상은 열탕·열사의대지 둘.
7. **대타 뒤 얼음 상대**: 열탕·열사의대지·불꽃 기술이 대타를 맞히면 얼음이 유지된다(Showdown). 현행에서 해동되면 실패 → §6 Q2.
8. **빗나감·방어**: 빗나가거나 방어된 열탕·열사의대지는 얼음을 풀지 않는다. **불꽃 타입 데미지 기술의 빗나감·방어도 같이 넣는다**(가드는 해동 두 갈래 — 열탕류·불꽃 — 모두에 들어가므로 둘 다 고정; 검수 권고).
9. **사용자 자기 해동(①)**: 얼음 상태의 사용자가 열사의대지를 쓰면 카운트 판정 없이 녹고 기술이 나간다(현행 통과 예상 — `thawsUserOnUse` 이미 있음). **얼어 있던 사용자는 기술이 빗나가거나 방어돼도 녹는다**(Showdown: 사용자 해동은 명중·방어 판정보다 먼저 — 새 가드가 자기 해동 경로까지 막지 않는지 확인; 검수 권고).
10. **우격다짐 + 열사의대지(필수, 검수)**: 우격다짐 강철톤이 얼음 상대에게 열사의대지 → **상대는 녹고, 화상은 걸리지 않고(우격다짐이 부가 화상을 지움), 위력 ×1.3**. champions `hitStepMoveHitLoop`는 `afterMoveSecondaryEvent`를 `suppressingSecondaries()` 검사 없이 불러 해동이 남는다. 가드에 우격다짐 조건을 섞지 않는다. 현행 엔진에서 `healAndThaw`가 우격다짐 판정과 묶여 해동이 빠지면 실패 → Q2 범위 안에서 같은 PR로 고친다.
11. (선택) **틈새포착(대타 무시) + 열사의대지/열탕**: 대타가 있어도 상대가 녹는다 — 가드가 지나치게 막지 않는지 확인.

## 6. 위험·한계·질문
- **대타(소스로 판정됨)**: 대타에 맞으면 Showdown은 해동하지 않는다(§7). 따라서 "열탕과 같은 동작" 기준만으로는 부족하다 — **엔진의 `healAndThaw` 해동 두 갈래(`curesStatus`·불꽃 타입)에는 `hitSubstitute`·`hit` 가드가 보이지 않는다**(같은 파일의 다른 부가효과는 `!c.hitSubstitute`를 확인한다). 이 가드가 파이프라인 앞쪽에서 이미 걸러지는지 구현 첫 단계에서 시험(대타 뒤 얼음 상대에 열탕·열사의대지·불꽃 기술, 빗나감)으로 확인한다. **걸러지지 않으면 열사의대지만이 아니라 열탕·불꽃 해동까지 같은 가드를 넣어야 하므로 이 PR의 범위가 코드 변경으로 커진다** — 그 경우 사용자에게 보고하고 범위를 정한다(Q2).
- **Q2 확정(사용자 2026-11-19)**: 같은 PR에서 고친다. 해동 규칙 한 덩어리이고 해시 변동은 거의 없을 것으로 본다(대타 뒤 얼음 상대는 드물다) — 측정으로 확인. 가드를 넣으면 불꽃 기술이 얼음 상대의 대타를 맞힌 경우도 얼음이 유지되는 쪽으로 바뀐다.
- **Q1**: 이 항목을 fix-14에 합칠까? — 권고: 따로. 데이터 한 줄이라 PR이 가볍고, 해시 원인이 분리된다.

## 7. 사전 검수 메모 (2026-11-19, `8.3-D3-fix14-맹독설계-검수.md` §5 — 정식 검수 아님)
- 해동은 **두 가지**다: ① 사용자가 얼어 있어도 기술을 쓰며 녹는다(`frz.onBeforeMove`·`onModifyMove`의 `defrost`), ② 맞은 상대가 녹는다(`frz.onAfterMoveSecondary`의 `thawsTarget`). `curesStatus` 한 줄은 ②다. **①은 엔진에 이미 있다**(`thawsUserOnUse` — 열사의대지·열탕 포함, 시험 9로 고정).
- **대타 뒤 얼음 상대는 녹지 않는다**: 대타에 맞으면 `spreadMoveHit`(champions `scripts.ts` 350)이 대상을 `null`로 바꾸고 `afterMoveSecondaryEvent`는 `null`을 걸러낸 대상에게만 돈다(575). §6의 "알면서 둔 것"은 소스로 판정됐다.
- 참고: champions `hitStepMoveHitLoop`는 `afterMoveSecondaryEvent`를 `suppressingSecondaries()`(우격다짐) 검사 없이 부른다. **필수로 올림(검수 §2-1)**: 강철톤은 숨겨진 특성이 우격다짐이고 챔피언스에서 열사의대지를 배우는 합법 조합이다 → 시험 10.
