- 결론: **조건부 승인(보정 1건 필수).** 빗나감·무효·방어·마비·풀죽음·얼음은 설계서 규칙(`turnsRemaining === 1`이면 혼란)이 소스와 같다. **수면은 갈래가 둘**이고, 설계서대로만 고치면 현재 맞고 있던 수면 경우가 새로 틀어진다(§2). 턴 종료 처리 한 줄로 해결된다.

## 1. 일치 확인

`lockedmove` 동작을 소스 그대로 옮긴 상태 기계로 재현했다(§7 스크립트).

| 경우 | 소스 | 설계서 |
|---|---|---|
| 2턴짜리, 2턴째 빗나감·무효·방어 | 혼란 | 혼란 ✅ |
| 3턴짜리, 2턴째 빗나감 | 없음 | 없음 ✅ |
| 3턴짜리, 3턴째 빗나감 | 혼란 | 혼란 ✅ |
| 2턴짜리, 2턴째 마비·풀죽음·얼음(`BeforeMove` 실패) | 혼란(턴 종료 만료 → `end`) | 혼란 ✅ |
| 1턴째 실패 | 상태 없음 | 없음 ✅ |
| 정상 종료 | 혼란 | 혼란 ✅ |

- `turnsRemaining === 1` 판정: 소스의 "해제 시 `trueDuration ≤ 1`"과 같은 분기다. ✅ 단, 이 값이 **끊김 분기에 들어오기 전에 감소되지 않는지**를 시험 3(3턴짜리 3턴째)이 확인한다.
- 이미 혼란·마이페이스: `addVolatile('confusion')` 실패와 같다. ✅
- 소란피기: 별도 볼라틸(`uproar`)이라 혼란 없음. ✅

## 2. ⚠️ 보정 — 수면은 두 갈래

`lockedmove.onResidual`:

```ts
onResidual(target) {
  if (target.status === 'slp') {
    // don't lock, and bypass confusion for calming
    delete target.volatiles['lockedmove'];   // onEnd를 부르지 않는다 → 혼란 없음
  }
  this.effectState.trueDuration--;
},
```

이 콜백은 **그 턴에 `duration`이 만료되지 않을 때만** 실행된다(만료되면 `end`가 먼저 불리고 콜백은 건너뜀). 만료되지 않는 턴 = 그 턴에 난동 기술이 **명중한** 턴이다(시작 또는 `onRestart`로 `duration = 2`).

| 경우 | 소스 | 설계서대로 고친 엔진 | 현행 엔진 |
|---|---|---|---|
| A. 명중한 턴 **안에서** 잠듦 → 다음 턴 행동불능 (느린 상대의 수면 기술, 그 턴 종료의 하품 — 하품 23이 `lockedmove`(순서 없음 = 맨 뒤)보다 먼저) | **혼란 없음**(턴 종료에 조용히 해제) | 다음 턴이 예정 마지막 턴이면 **혼란 ✗** | 없음 ✅ |
| B. 예정 마지막 턴에 **움직이기 전** 잠듦 (빠른 상대의 수면 기술) | 혼란(잠든 채 혼란) | 혼란 ✅ | 없음 ✗ |

- 예: 3턴짜리 역린, 2턴째 명중, 그 턴 종료에 하품으로 잠듦 → 소스는 혼란 없음. 설계서안은 3턴째 행동불능에서 혼란을 건다.
- 하품·수면 기술은 출전 빈도가 낮지 않아 A는 실전에서 나온다.
- 이전 회신(`8.3-D3-E2-대조-검수.md` §2-1)의 "수면은 같은 만료 경로"는 **B만 맞다.** 이 문서로 보정한다.

### 2-1. 조치(권고안)

턴 종료 처리의 **마지막 쪽**(하품 등 수면 부여 뒤)에 한 줄:

```ts
// lockedmove.onResidual: 명중한 턴 종료에 잠들어 있으면 혼란 없이 해제(Showdown "calming")
if (entry && fighter.status === 'sleep') endRampage(fighter);   // 혼란 처리 없음
```

- 턴 종료까지 `entry`가 남아 있는 경우는 "이번 턴에 명중했고 아직 마지막 턴이 아님"뿐이다(끊김·마지막 턴은 `updateRampage`가 이미 해제). 이것이 소스의 "만료되지 않는 턴"과 정확히 같다.
- B는 `updateRampage` 끊김 분기에서 이미 처리되므로 이 줄과 겹치지 않는다.
- 위치가 하품 처리보다 앞이면 A의 하품 경우를 놓친다 → 순서를 주석에 적는다.

## 3. 범위 밖 확인 요청 — 미스트필드

- 소스 `mistyterrain.onTryAddVolatile`은 땅에 있는 포켓몬의 `confusion`을 **출처와 무관하게 막는다** → 미스트필드 위에서는 난동 끝 혼란도 걸리지 않는다. champions 습득 24종.
- 설계서의 `confuseAfterRampage`는 정상 종료 쪽 코드를 그대로 뽑는 것이므로, 정상 종료가 이미 미스트필드를 보고 있으면 문제없다. 보고 있지 않다면 **이번 PR이 만든 차이가 아니므로** 백로그(E-영역 후보)로 둔다. 구현 때 확인해 결과만 알려 주면 판정한다.

```js
function run(total, turns){            // turns: [행동('hit'|'miss'|'cant'), 턴종료에 잠들어 있음]
  let v=null, conf=false; const end=()=>{ if(v.td<=1) conf=true; v=null; };
  for (const [act, slp] of turns){
    if (!v && act==='hit') v={td:total,dur:2}; else if (v && act==='hit' && v.td>=2) v.dur=2;
    if (v && act!=='cant' && v.dur===1) end();                                    // onAfterMove
    if (v){ v.dur--; if (!v.dur) end(); else if (slp) v=null; else v.td--; }     // Residual
    if (!v) break;
  }
  return conf;
}
// run(2,[['hit',1],['cant',0]]) → false   (시험 13)
// run(3,[['hit',0],['hit',1],['cant',0]]) → false   (시험 14)
```
