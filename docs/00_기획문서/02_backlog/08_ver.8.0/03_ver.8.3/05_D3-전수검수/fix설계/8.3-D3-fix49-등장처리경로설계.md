## 2. 변경

### 2-1. ① 위협·하양허브 (E8-30·31·36)
**a. E8-30 대타** — `applyIntimidateWithReaction` 맨 앞(면역 특성 검사보다 앞)에 `opponent.substituteHp !== undefined`이면 로그 한 줄(`〈위협 보유자〉의 〈위협〉! 하지만 〈상대〉에게는 효과가 없었다!` — 새 문구, 문자열 로그)을 남기고 `return`. 반응 특성·미러아머·하양허브는 이 함수의 후속이거나 묶음 끝 호출이라 자동 미발동(검수 H6·H7 일치: 허브 미소모·오기 미발동). 시작·교체·메가·트레이스 복사(②) 모두 이 함수를 지난다.
**b. E8-31 배짱** — `abilities.json` 배짱에 `"immuneToIntimidate": true`(줄 단위 치환, CRLF). 설명 문구에 "위협에 영향을 받지 않는다" 추가(`docs/데이터변경이력.md`). 로그는 정신력류와 같은 기존 분기. 소비처는 `switching.ts` 140행 하나.
**c. E8-36 하양허브 — 등장 묶음 끝 1회(R1)** — 공용 소함수 `finishEntryBundle(state, log)`를 `switching.ts`에 둔다. 내용은 **순서대로** ① `retryWaitingTrace`(②에서 추가, R3 — 하양허브보다 **앞**) ② 양쪽 활성 포켓몬의 하양허브 반응(`shouldTriggerWhiteHerb`·`clampStagesToNonNegative`·`consumeItem`). 호출 지점(**설치물 단계 뒤 별도 호출은 두지 않는다**):
- **단일 등장**(자발 교체·단독 강제 교체·기절 대체 하나·U턴류): `runEntryEffects` 끝(⑦ 기분파 뒤)에서 호출. `runEntryEffects`에 선택 인자 `{ endsBundle = true }`를 더한다.
- **유턴류 동시 교체 묶음**(엔진 §0-E): `executeChoices` ② 루프가 `runEntryEffects(…, { endsBundle: false })`로 각 등장을 돌고, **루프가 끝난 뒤 한 번** `finishEntryBundle`을 부른다(문구는 마지막 등장 기록의 `entryMessages`에 push). 자발 동시 교체(양쪽 `switch`)는 행동마다 따로 `performSwitch` → 단일 등장 두 번이라 Showdown D1과 같다. **기절 후 교체는 `applySwitch` 한쪽씩 → 단일 등장 두 번**이라 D2와 달라진다(§4).
- **메가진화**: `applyMegaEvolution`에서 `applyEntryAbilityOnSwitchIn`·시드 뒤 호출.
- **배틀 시작**: `createBattleState`에서 양쪽 등장 효과·시드 뒤 호출(시작 문구는 `entryAnnouncements`).
- 문구는 행동 로그와 같은 `〈이름〉의 〈도구〉(으)로 떨어진 능력을 원래대로 되돌렸다!`(`ActionEffectLines.tsx` 1031행). 곡예가 소모로 켜지면 "스피드가 2배로 올랐다!" 한 줄(`triggerTerrainSeeds`와 같은 방식, D3-fix-9). 서투름·매직룸이면 불발(`effectiveHeldItem`).
- 기존 `mirroredEffects.ts` 후처리(행동 끝)는 그대로 — 등장에서 이미 복구돼 있으면 `shouldTriggerWhiteHerb`가 거짓이라 겹치지 않는다.

### 2-2. ② 트레이스 (E8-34·35, R2·R3)
**a. 교체·메가(`applyEntryAbilityOnSwitchIn`)** — 복사(`setEffectiveAbility`) 직후 **같은 함수를 한 번 더 호출**한다(`notrace` 특성만 복사되므로 재귀 1단계에서 끝). 복사 전 단계(배리어프리·틀깨기·일루전·총대장)는 트레이스에 해당 플래그가 없어 중복이 없다.
**b. 시작 — 복사를 날씨 판정 전에 확정(R2)** — 초안의 "복사 뒤 날씨 덮어쓰기"는 폐기. `resolveEntryWeather`에서 각 쪽의 **날씨 설정 특성**을 `weatherSetterOf(fighter, opponent)`로 구한다: 자기 특성이 `setsWeather`면 그것, 아니면 자기가 트레이스이고 상대 특성이 복사 가능(`!isUncopyableAbility`)하며 `setsWeather`면 **상대의 그 특성**(트레이스 쪽도 같은 날씨의 설정자로 취급). 이어서 기존 알고리즘(양쪽 설정자면 시작 순서로 먼저 처리한 쪽이 주인·바위는 각자 자기 도구, 같은 날씨면 첫 쪽만 발동)을 그대로 쓰되 순서 비교는 공용 `startOrder()`를 쓴다(TW1 8·TW2 5·TW3 5). 로그의 날씨 줄 이름은 설정자 특성(복사한 쪽도 복사한 특성 이름). 이후 `resolveEntryAbilityEffects` 루프의 트레이스 복사는 날씨를 다시 건드리지 않는다.
  - **필드**는 루프가 시작 순서이고 복사 자리에서 복사한 특성의 본문을 재호출하므로 자동 일치(TW4 + 필드연장 변형 1건으로 확인). 루프 본문은 지역 함수 `applyAbilityEntry(entry, ability)`로 빼서 복사 직후 복사한 특성으로 한 번 더 호출한다(위협·감미로운꿀·필드·괴짜·안내류가 같은 본문).
  - **`startOrder()`의 ② 시점 구현**: ②에서는 지금의 `a.spe >= b.spe`(원시)를 함수로 빼기만 한다(**순서 비교 로직은 ④에서 교체**) — ②의 해시 원인이 "트레이스"만이 되도록.
**c. E8-35 대기 재시도(R3)** — `retryWaitingTrace(state, log)`: 활성 포켓몬 중 **유효 특성이 아직 `copiesOpponentAbilityOnEntry`(대기 중)**이고 살아 있으면 복사를 다시 시도(성공하면 위 a의 재호출로 효과 발동). **`finishEntryBundle` 안에서 하양허브보다 먼저** 호출한다 — 호출 지점은 §2-1-c의 네 곳이 그대로 겹친다(교체·묶음·메가·시작). 그래야 TRW1처럼 복사한 위협으로 떨어진 상대의 하양허브가 같은 처리 안에서 복구된다.
- **기록만(사용자 결정)**: 등장 외 경로(고민씨·심플빔·동료만들기·스킬스왑·역할 등 챔피언스 합법 특성 변경 기술, 미라·향기의잔향·떠도는영혼)로 상대 특성이 "복사 불가 → 가능"으로 바뀌는 경우의 재시도는 미지원. 행동 끝 공통 후처리(`mirroredEffects`)에 재시도를 넣으려면 행동 로그에 등장 문구를 담을 새 필드·화면 변경이 필요해 비용이 크고, 대기 중 트레이스와 겹쳐야 해서 도달이 극히 낮다(§4).

`applyMegaEvolution`에서 메가폼으로 바꿀 때 `fighter.proteanActivatedSinceSwitchIn = undefined`(특성이 같든 다르든). 한 줄.

### 2-4. ④ 시작 등장 순서 — 동률 무작위(E8-37) + 스피드 보정(E8-39, R4)
- **범위**: 턴 행동·교체·메가 선언 순서의 동률은 이미 난수(`orderBySpeed`). 남은 a 고정은 **배틀 시작뿐**(`resolveEntryWeather`·`resolveEntryAbilityEffects`). 한 번 정한 순서를 두 함수가 **공용 `startOrder()`로 공유**한다(Showdown은 한 큐를 한 번 정렬).
- **스피드 보정(R4)**: 비교 값을 원시 `realStats.spe`에서 `computeSpeedWithEffects({ realSpe: spe, stage: 0, ability: undefined, item: startItemOf(fighter)(서투름·매직룸 반영), status: null, weather: undefined, field: undefined, unburdenActive: false, tailwind: false })`로 바꾼다 — **구애스카프 ×1.5·검은철구 ×0.5**만 실질적으로 작동하고(시작엔 날씨·상태·필드·순풍·랭크가 없다), 반올림은 턴 순서 계산(D3-fix-11)과 같은 함수라 일치한다(검수 §5-2). 구조 변경 없음.
- **난수 주입**: `createBattleState(init, random?)`. `random`이 있으면 **보정 스피드가 같을 때만** 소비하고 **없으면 a 먼저**(결정론 유지). 호출처: `battle-ai-sim.mjs` 237·566·571·631·641·657·659행(sim의 `rng` 전달 — 동률이 아니면 난수를 안 써 **동률 없는 판의 난수열은 그대로**), 화면 `battleSessionHelpers.ts` 22행 `createStateFromParties`(실제 대전 시작에만 `Math.random`, AI 선출 계산은 전달 안 함), `damage-formula-check.mjs`·`rank-ai-check.mjs`는 그대로.
- **지연 결정**: 동률 판정은 "순서가 필요한 순간"에만 한 번 굴린다(`resolveEntryAbilityEffects`의 조기 반환 뒤, `resolveEntryWeather`는 양쪽 다 날씨 설정자일 때). `startOrder()`가 결과를 캐시해 날씨·특성이 같은 결과를 쓴다.

### 2-5. ⑤ 감미로운꿀 교체·메가 등장 + 1회·대타 면역·심술꾸러기 (E8-38)

- **D2 기절 동시 교체 묶음(후보 E8-40)**: Showdown은 양쪽이 동시에 기절한 뒤의 두 등장을 한 `runSwitch`로 묶어 하양허브 1회로 네트·위협 하락을 함께 복구하지만, 엔진은 `applySwitch`를 편마다 따로 불러(화면·시뮬레이터·AI 탐색) 첫 쪽 등장 끝에서 허브가 먼저 소모돼 둘째 쪽 위협 −1이 남는다. 같은 판에서 양쪽이 동시에 기절 + 네트 + 허브 + 위협이 겹쳐야 나타나 도달이 극히 낮고, 고치려면 화면·시뮬레이터·탐색의 교체 확정 흐름(두 편의 교체를 모은 뒤 함께 등장)을 바꿔야 한다. 이번엔 안 한다(후속 후보).
