## 2. 변경

### 2-1. ① 위협 묶음 (E8-30·31·36) — `applyIntimidateWithReaction` 한 곳 + 데이터 1줄 + 등장 처리 끝의 하양허브 반응
**a. E8-30 대타** — `applyIntimidateWithReaction` 맨 앞(면역 특성 검사보다 앞)에 `opponent.substituteHp !== undefined`이면 로그 한 줄(`〈위협 보유자〉의 〈위협〉! 하지만 〈상대〉에게는 효과가 없었다!` — 새 문구, 화면 연출은 문자열 로그라 영향 없음)을 남기고 `return`. 반응 특성·미러아머·하양허브는 이 함수 안의 후속이라 **자동으로 미발동**이다. 시작·교체·메가·트레이스 복사(②)가 모두 이 함수를 지나므로 한 곳 수정으로 전부 맞는다. 시작 장면에는 대타가 없어 무관.
**b. E8-31 배짱** — `abilities.json` 배짱에 `"immuneToIntimidate": true` 한 줄(줄 단위 치환, 작업 복사본 CRLF). 설명 문구에 "위협에 영향을 받지 않는다"를 더한다(`docs/데이터변경이력.md`). 로그는 정신력류와 같은 기존 분기(`… ${oppAbility.name} 때문에 효과가 없었다!`). 이 플래그의 소비처는 `switching.ts` 140행 하나(AI·평가기 사용 없음 — `grep` 확인).
**c. E8-36 하양허브 즉시 복구(§0-A)** — 공용 소함수 `restoreLoweredStatsWithWhiteHerb(fighter, ability, log)`를 `switching.ts`에 두고(판정은 기존 `shouldTriggerWhiteHerb`·`clampStagesToNonNegative`, 소모는 `consumeItem`), 등장 처리의 **하락이 일어날 수 있는 지점 뒤**에서 양쪽 활성 포켓몬에 대해 부른다:
- 교체·메가: `applyEntryAbilityOnSwitchIn` 끝(위협·감미로운꿀 뒤)에서 `self`와 `opponent` 둘 다 — 위협을 받는 쪽이 하양허브 보유자다. `runEntryEffects`의 설치물 단계(끈적끈적네트 스피드 −1) 뒤에도 `incoming`에 한 번(Showdown은 하락 직후라 설치물이 먼저고 등장 특성 위협이 다음 — 같은 함수 두 번 불러도 소모는 1회라 안전).
- 시작: `resolveEntryAbilityEffects` 루프에서 위협 호출 직후 `opponent`(위협을 받은 쪽)에 대해 부른다. 양쪽이 모두 위협일 때도 각자 상대에게서 한 번씩만 받으므로(하양허브는 받는 쪽 기준) 허브 보유자만 복구·소모되고 허브가 없는 쪽의 −1은 남는다(시험 9, 구현 전 Showdown 실행으로 확인).
- 로그 문구는 행동 로그와 같은 `〈이름〉의 〈도구〉(으)로 떨어진 능력을 원래대로 되돌렸다!`(`ActionEffectLines.tsx` 1031행)를 문자열로 낸다. 곡예가 소모로 켜지면 `triggerTerrainSeeds`와 같은 방식으로 "스피드가 2배로 올랐다!" 한 줄(8.3 D3-fix-9, 이 경로는 resolveAction 전후 비교가 못 잡는다).
- **서투름·매직룸이면 불발**(`effectiveHeldItem`): 시작에는 매직룸이 없고 서투름은 `ability.disablesOwnItemEffects`로 거른다.
- **원인 분리**: 기존 `mirroredEffects.ts` 후처리(행동 끝)는 그대로 둔다 — 등장에서 이미 복구돼 있으면 `shouldTriggerWhiteHerb`가 거짓이라 겹치지 않는다. 다른 반응(필드 시드)은 이미 등장 처리에 있다.
- **영향**: 하양허브 보유자가 위협을 받는 장면의 첫 행동 피해(0 vs −1 공격)가 바뀐다 — 샘플 하양허브 3슬롯이 매번 해당.

### 2-2. ② 트레이스 묶음 (E8-34·35)
**a. 교체·메가(`applyEntryAbilityOnSwitchIn`)** — 복사(`setEffectiveAbility`) 직후 **같은 함수를 한 번 더 호출**해 복사한 특성으로 등장 효과를 돌린다(`notrace` 특성만 복사되므로 재귀는 1단계에서 끝난다 — `isUncopyableAbility`). 이미 메가진화 경로가 이 함수를 재사용하므로 가장 작은 수정이다. 복사 전 단계(배리어프리·틀깨기·일루전·총대장)는 트레이스 자신에게는 해당 플래그가 없어 중복 발동이 없다.
**b. 시작(`resolveEntryAbilityEffects`)** — 루프 본문을 지역 함수 `applyAbilityEntry(entry, ability)`로 빼서 **복사 직후 복사한 특성으로 한 번 더 호출**한다(위협·감미로운꿀·필드·괴짜·안내류가 모두 같은 본문). **날씨**는 `resolveEntryWeather`가 앞서 따로 끝내므로(§0-C) 루프에서 복사한 특성이 `setsWeather`면 `{ weather, weatherTurnsRemaining }` 덮어쓰기 값을 함께 돌려주고 `createBattleState`가 `state.weather`에 반영한다(이미 같은 날씨면 갱신·문구 없음 — 기존 규칙). 지속은 복사한 쪽의 유효 도구 바위만 본다(8.3 D3-fix-26과 같은 `weatherRockBonusOfItem`). **구현 때 이 날씨 덮어쓰기가 `resolveEntryWeather`와 순서 의존(양쪽 날씨·트레이스 동시)에서 Showdown과 같은지 `[실행]` 대조한다**(TR1c 장면 추가).
**c. E8-35 대기 재시도** — 소함수 `retryWaitingTrace(state, log)`: 활성 포켓몬 중 **유효 특성이 아직 `copiesOpponentAbilityOnEntry`(대기 중 = 복사 전)**이고 살아 있으면 복사를 다시 시도한다(성공하면 위 a의 재호출로 효과 발동). 호출 지점은 **상대 쪽의 등장·특성 변화 뒤**: `runEntryEffects` 끝, `applyMegaEvolution` 끝, (시작은 루프 안에서 둘의 순서로 이미 처리). Showdown의 매 갱신 재시도를 이 세 지점으로 근사한다 — 특성이 도중에 바뀌는 다른 경로(변신·위액·스킬스왑류)는 이번에 안 건드린다(샘플 도달 0, §4). `seek`가 거짓인 경우(상대 `noability`·특성보호막)는 챔피언스 합법 도구에 특성보호막이 없어(`items.json` 확인) 무시.
- **영향**: 위협을 복사한 트레이스가 상대 공격을 내린다(상대 위협에 한함, 샘플 가디안·후딘 3슬롯). 복사한 날씨·필드 특성이 실제로 깔린다.

### 2-3. ③ 변환자재·리베로 메가 (E8-33)
`applyMegaEvolution`에서 메가폼으로 바꿀 때 `fighter.proteanActivatedSinceSwitchIn = undefined`(특성이 같든 다르든 — Showdown `setAbility`가 `abilityState`를 새로 만든다, 검수서 §3-4 "같은 특성 메가 재발동 명시"와 일치). 한 줄.

### 2-4. ④ 시작 등장 순서의 동률 무작위 (E8-37)
- **범위**: 턴 행동·교체·메가 선언 순서는 이미 `orderBySpeed`가 동률을 난수로 정한다(E3-13·16). **남은 a 고정은 배틀 시작뿐**(`resolveEntryWeather` 838행·`resolveEntryAbilityEffects` 961행의 `aFighter.realStats.spe >= bFighter.realStats.spe`). 한 번 정한 결과를 **두 함수가 공유**해야 날씨·위협이 같은 순서로 처리된다(Showdown은 한 큐를 한 번 정렬).
- **난수 주입**: `createBattleState(init)`에 난수가 없다. 두 번째 인자 `random?: () => number`를 더해 **있으면 동률일 때만 소비**하고 **없으면 지금처럼 a 먼저**(결정론 유지 — 화면 밖 호출·검증 스크립트가 영향받지 않는다). 호출처: `battle-ai-sim.mjs` 237·566·571·631·641·657·659행(sim의 `rng`를 전달 — 동률이 아니면 난수를 안 써서 **동률 없는 판의 난수열은 그대로**라 해시 변동이 동률 장면에만 한정된다), 화면 `battleSessionHelpers.ts` 22행 `createStateFromParties`(실제 대전 시작에만 `Math.random` 전달, AI 선출 계산은 전달 안 함), `damage-formula-check.mjs`·`rank-ai-check.mjs`는 그대로(난수 없음).
- **지연 결정**: 동률 판정은 "이 순서가 필요한 순간"에만 한 번 굴린다(양쪽이 모두 순서가 의미 있는 등장 특성을 가졌을 때 — `resolveEntryAbilityEffects`의 조기 반환 뒤, `resolveEntryWeather`는 양쪽 다 날씨 특성일 때). 공용 클로저 `startOrder()`가 결과를 캐시한다.
- **알려진 한계(기록만, §5-2)**: 시작 순서는 `realStats.spe` 원시값이라 구애스카프·마비·순풍·곡예 등 **스피드 보정을 안 본다**(Showdown은 보정된 `getActionSpeed`). 예: 스카프 보유 리드가 원시 스피드가 낮아도 먼저 등장. 상태 없이(`createBattleState` 도중) 보정 스피드를 쓰려면 구조를 바꿔야 해서 이번에 안 한다.

### 2-5. (결정 시) ⑤ 감미로운꿀 교체·메가 등장 + 1회·대타 면역 (E8-38)
- `applyEntryAbilityOnSwitchIn`에 `lowersOpponentEvasionOnEntry`를 추가: `fighter.syrupTriggered`(새 선택 필드, **교체로 물러나도 초기화 안 함** — Showdown 배틀 1회)가 없을 때만 발동하고 세운다. 상대 `substituteHp`가 있으면 `-immune`(변화 없음·문구 한 줄), 아니면 회피율 −1(`contraryDelta` 존중, 기존 시작 경로 본문과 같은 처리). 시작 경로의 같은 본문에도 `syrupTriggered`를 세운다(리드가 나갔다 돌아올 때 재발동 방지).
- 시작 경로는 같은 본문을 **소함수로 빼 공유**한다(위협과 같은 방식). 대타는 시작에 없으나 같은 함수라 일관.
