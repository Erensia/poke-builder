## 0. 한 줄 요약
Showdown 변덕쟁이는 **올릴 후보 = 5종 중 `boosts < 6`**, **내릴 후보 = 5종 중 `boosts > −6` 이고 올린 능력치가 아닌 것**으로 먼저 거른 뒤 각각 `sample`한다(명중·회피 제외). 엔진은 5종에서 먼저 뽑고 `applyStageDelta`가 상한에서 흡수해, +6인 능력치를 뽑으면 **올릴 몫이 사라진다.** 후보를 거른 뒤 뽑도록 고친다.

## 1. 문제
### 1-1. 규칙 (Showdown 2702~2730행)
1. 올림: `stats` = 명중·회피 제외, `boosts[s] < 6`인 것. 비어 있지 않으면 `sample` → `+2`.
2. 내림: `stats` = 명중·회피 제외, `boosts[s] > −6 && s !== 올린 능력치`인 것. 비어 있지 않으면 `sample` → `−1`.
3. `this.boost(boost, pokemon, pokemon)` 한 번(둘 다 같은 호출). 후보가 비면 `sample`을 부르지 않는다(난수 소비 없음).
4. 올릴 후보가 있으면 반드시 +2가 들어가고, 내릴 후보가 있으면 반드시 −1이 들어간다.

### 1-2. 엔진 현행 (`finishTurn.ts` `applyMoodyRandomStages`, 699~716행)
`raised` = 5종 균등 → `lowered` = 나머지 4종 균등 → 둘 다 `applyStageDelta`(상한·하한에서 흡수). 난수는 항상 2회 소비.
- 차이 ①: +6인 능력치를 뽑으면 +2가 사라진다(Showdown은 다른 능력치를 올린다).
- 차이 ②: −6인 능력치를 뽑으면 −1이 사라진다.
- 차이 ③: 5종이 전부 +6이면 Showdown은 올림 없음·내림만, 엔진은 +6 흡수·내림 정상(결과는 같으나 난수 소비가 다르다).
- 차이 ④(로그): 한쪽 후보가 비는 경우를 문구가 처리하지 못한다(`moodyRaisedStat && moodyLoweredStat` 둘 다 있어야 줄이 나온다).
- 반전(Contrary): 후보 거름은 **원래 랭크 기준**이고 델타만 뒤집힌다(Showdown `boost()` 안에서 반전) — 엔진의 `contraryDelta` 위치가 같아 유지.

### 1-3. 도달
샘플 변덕쟁이 보유자가 있는 파티에서 랭크 +6/−6에 닿으려면 칼춤·배북 등과 오래 버텨야 하나, 랜덤 빌드(regress)·랭크전에서 도달 가능(빈도는 §7에서 측정). 수정 근거는 "규칙이 다르다"(전수 검수 방침).

## 2. 변경
- `applyMoodyRandomStages`: 후보를 거른다.
```
const up = BATTLE_STAT_KEYS.filter((s) => fighter.stages[s] < 6);
const raised = up.length ? up[Math.floor(random() * up.length)] : undefined;
const down = BATTLE_STAT_KEYS.filter((s) => s !== raised && fighter.stages[s] > -6);
const lowered = down.length ? down[Math.floor(random() * down.length)] : undefined;
```
- 적용: `raised`가 있으면 `+2`, `lowered`가 있으면 `−1`(둘 다 `contraryDelta`). 둘 다 없으면 로그 엔트리를 만들지 않는다.
- 로그: `moodyRaisedStat`·`moodyLoweredStat`은 이미 선택 필드. `EndOfTurnLines.tsx` 174행 조건을 "하나라도 있으면"으로 넓히고 문구를 3종으로 나눈다:
  - 둘 다: 기존 "{이름}의 {특성}! {올림}이 크게 올라가고 {내림}이 떨어졌다!"
  - 올림만: "{이름}의 {특성}! {올림}이 크게 올라갔다!"
  - 내림만: "{이름}의 {특성}! {내림}이 떨어졌다!"
- 영향 파일: `finishTurn.ts`, `EndOfTurnLines.tsx`(AI 코드는 변덕쟁이를 읽지 않는다 — 구현 때 `grep moodyRandomStages` 확인).

## 4. 영향·예측
- 해시: **변덕쟁이 보유자가 ±6 랭크에 닿은 판**에서만 바뀐다 → 변동 매우 작거나 없을 수 있다. 구현 직전 일회용 계측(`globalThis` 카운터)으로 `regress 20000`의 발생 횟수(올림 상한 흡수·내림 하한 흡수·후보 전멸)를 잰다. 불변이면 그 사실을 보고하고 시험으로 규칙을 지킨다.
- 난수 소비: 후보가 비면 난수를 부르지 않으므로 이후 난수열이 달라진다(해시 변동 요인에 포함).
- 저장된 영상: 새 필드 없음(선택 필드 조합만 확대).

## 5. 알면서 둔 것 / 범위 밖
- Showdown은 능력치 변화마다 줄을 따로 내지만(`-boost`·`-unboost`) 엔진은 한 줄로 합친다 — 기존 방침 유지.
- **반전(Contrary) 보유자의 문구**: 현행 문구는 "크게 올라가고 … 떨어졌다!" 고정이라 반전이면 방향이 거짓이 된다(기존 문제, 이 PR 범위 밖). 검수에서 같이 고칠지 정한다 — 권고: 별도 로그 정합 항목(E8-48과 같은 PR).
- 올릴 후보가 있어도 `applyStageDelta`의 상한 클램프(+6)는 +5→+6 같은 경우 +1만 올린다(Showdown과 같다).
