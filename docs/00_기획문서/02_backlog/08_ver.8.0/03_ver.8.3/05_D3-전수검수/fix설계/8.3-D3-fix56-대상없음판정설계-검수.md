## 2. 포인트별 상세

### 2-1. a 고스트 저주
- 조건은 `c.move.setsCurse && c.attacker.types.includes("고스트")`이다. `preHitEffects.ts` 165행, `mirroredEffects.ts` 1510행과 같은 식을 쓴다.
- 타입 기준 시점도 맞다. Showdown에서 변환자재·리베로는 `PrepareHit`(`[notarget]` 뒤)에 발동한다. 엔진의 `recordUsageEffects`도 게이트 뒤다. 그래서 게이트가 보는 타입은 "기술을 고른 시점의 타입"이 되며, 둘이 일치한다.

### 2-2. b 록온
- 조건은 `c.move.inflictsVolatile?.some((v) => v.volatile === "lockOn")`이다. 엔진 데이터에서 해당하는 기술은 록온 하나뿐이다(실측).
- **정정**: 검수 요청의 "마인드리더 같은 비슷한 기술"은 엔진 데이터에 없다(Showdown Champions 모드에서도 `Past`). 시험·설계서에서는 록온만 다룬다.

### 2-3. c 문어굳히기 — §2-1 원인 확정
- 데이터는 `{ category: "status", octolock: true }`뿐이다. `inflictsVolatile`·`statChanges`가 없다.
- 그래서 `isOpponentTargetingMove`(`fieldEffects.ts` 77행)가 **false**이고, `needsLivingTarget`도 false가 되어 게이트를 통과한다.
- 그 뒤 `rollHit`에서 `hit=true`가 나고, 효과는 `mirroredEffects.ts` 1085~1092행의 `!isFainted(c.defender)` 가드에 막힌다.
- 다른 곳을 고칠 필요는 없다. 게이트 조건에 `c.move.octolock`만 더한다. 임시 패치로 `blockedReason=usageCondition`이 확인됐다.
- 설계서 §2-1의 "`isOpponentTargetingMove`가 이미 true로 보일 텐데"는 사실과 반대다. 구현 때 프로브로 확인할 항목에서 **확정 사항**으로 바꿔 적는다.

### 2-4. d 미래예지
- Showdown은 `getMoveTargets`(`pokemon.ts` 859행)에서 `futuremove`만 쓰러진 대상을 남긴다. 예약은 슬롯 조건이라 그 자리의 다음 포켓몬이 맞는다.
- 엔진은 게이트 예외(`!c.move.delayedAttackTurns`)만 두면, 547행 경로가 `sideOf(defenderKey).futureSight`에 예약한다.
  - 예약값은 `turnsRemaining: 3`이고, 턴 끝에 2가 된다.
  - `finishTurn.applyFutureSight`는 착탄 시점의 활성 포켓몬(`fighter`)을 때린다. 그래서 대체에게 맞는다(실측 +2턴 33 데미지).
- §2-2의 "`sourceIndex` 유효성": `sourceIndex`는 **사용자(b) 편**의 `activeIndex`다. 쓰러진 a 편 슬롯의 교체와는 관계가 없어 유효하다. Showdown도 사용자가 교체된 뒤에 착탄한다(d').
- "이미 예약이 있으면 실패"는 그대로 유지된다.
- **정정**: 파괴예지는 엔진 데이터에 없다. 설계서 §1 표의 "미래예지·파괴예지"는 "미래예지(파괴예지는 데이터 없음)"로 고치고, 시험 4는 미래예지만으로 둔다.

### 2-5. e 대폭발류 — §2-3 경로
- Showdown 순서: 1차 대상 확인 → `TryMove`(습기) → **564행 기절** → 573행 `[notarget]` `-fail`. 로그는 `-fail` 다음에 `faint`가 나온다.
- 엔진: `c.blocked()`(213행)는 **호출하는 시점에** `selfFainted: isFainted(c.attacker)`(232행)를 계산한다. 따라서 `blocked` 호출 직전에 `c.attacker.currentHp = 0`만 두면 `selfFainted`가 자동으로 true가 된다. 새 필드는 필요 없다.
- `forcedSwitch`와 `winner`는 `finishTurn`이 파티 상태로 계산한다. 그래서 실측에서 예비가 있으면 `forced={a,b}`, 마지막 1마리면 `winner=a`가 나왔다. §2-3의 "안 되면…" 대안은 불필요하다.
- **R5(필수)**: 습기 예외.
  - 사용자 자신이 습기면 Showdown은 `TryMove`에서 막아 **기절하지 않는다**.
  - 쓰러진 대상의 습기는 발동하지 않으므로 사용자가 기절한다.
  - 엔진은 280행(대상 없음)이 345행(습기)보다 앞에 있다. 그래서 기절 조건은 `c.move.selfFaints && !c.attackerAbility?.preventsSelfFaintMoves`로 둔다. 이 조건이면 h1·h2 모두 Showdown과 같다(실측).

## 3. 엔진 쪽 판단

### 3-1. 게이트에 덧붙이는 방식 — 동의 + 지역 함수화 권고
- `needsLivingTarget` 안에 넣지 않는 것이 맞다. 다른 사용처는 `moveContext.ts` 102행(타입 흡수 특성) 하나다.
- 현재 흡수 특성 중 고스트·노말·격투·에스퍼 타입을 흡수하는 것이 없어서, 함수 안에 넣어도 당장 결과는 같다.
- 그래도 이 함수는 "살아 있는 대상이 필요한 기술"이라는 의미를 갖는다. d(미래예지 예외)를 함수 안에 넣으면 이 의미가 깨진다. 게이트 쪽에 두는 것이 안전하다.
- R-i 때문에 같은 판정을 두 곳(280행, 호출 기술 확정 뒤)에서 쓴다. 조건과 e의 기절 처리를 **지역 함수 하나**(예: `noTargetGate(c)`)로 뽑는다. 이 방식이 두 줄을 복사하는 것보다 작다.

### 3-2. R-i(필수) — 잠꼬대·흉내쟁이가 부른 공격
- 280행 게이트는 `c.move`가 잠꼬대(자기 대상)일 때 한 번만 돈다. 이후 599행·608행에서 부른 기술로 바뀌면 다시 확인하지 않는다.
- 실측(현행, 잠든 b가 잠꼬대 사용):

  | 부른 기술 | 엔진 현행 | Showdown |
  |---|---|---|
  | 누르기 | `hit=true` **데미지 100**, `fainted: true`, 쓰러진 대상의 **까칠한피부가 사용자에게 29** | `-fail` |
  | 기가드레인 | 데미지 21, `fainted: true` | `-fail` |
  | 이판사판태클 / 생명의구슬 | 데미지, 까칠한피부 29 | `-fail` |
  | 대폭발 | 데미지 294 + 사용자 기절 | `-fail` + 사용자 기절 |

- 쓰러진 포켓몬의 특성이 발동하고, 기절 표시가 한 번 더 나온다. fix-55 검수 R2에서 고친 `resolveAction.ts` 676행 주석의 전제("쓰러진 상대를 노리는 기술은 preHitEffects에서 실패해 데미지가 0")도 이 경로에서는 깨진다.
- 수정: 흉내쟁이 블록 끝(608행 `c.move = copied` 다음)에서, 호출이 있었으면 같은 지역 함수를 한 번 더 부른다. 임시 패치 결과 네 장면 모두 실패하고, 데미지·까칠한피부가 없어졌다. 대폭발은 사용자만 기절했다.
- 로그: `blocked()` 결과에 `sleepTalkCalledMoveName`·`copycatCalledMoveName`이 실리지 않는다. 그래서 로그가 "잠꼬대 → 그러나 실패했다!"가 되어 부른 기술 이름이 빠진다. Showdown은 부른 기술의 `move` 줄을 낸 뒤 `-fail`을 낸다. `extra`로 두 이름을 넘긴다.
- 빈도: 잠꼬대는 fix-55 이후 노출이 늘어나는 같은 장면에서 일어난다. 게이트 두 줄 수준이라 **이 fix에 포함**할 것을 권고한다.

### 3-3. R-g(사용자 결정) — 차지 기술의 준비 턴
- Showdown은 차지 기술의 `TryMove`(550행)가 1차 대상 확인 뒤, 2차 `[notarget]`보다 **앞**에 있다. 그래서 준비 턴이 그대로 성공한다.

  | 장면 | Showdown 실측 | 엔진 현행 |
  |---|---|---|
  | 솔라빔·공중날기 | `-prepare` → 다음 턴 `[from] lockedmove`로 **대체 C를 때린다** | 실패(준비 없음) |
  | 메테오빔 | `-prepare` + 특공 +1 → 다음 턴 대체를 때린다 | 실패, 랭크 변화 없음 |
  | 일렉트로빔 **비** | 특공 +1 → `-fail` | 실패, 랭크 변화 없음 |
  | 솔라빔 **쾌청** | `-fail`(준비 생략 → 대상 없음) | 실패 ✔ |
  | (2턴째 발사 시점에 대상이 쓰러짐) | `-fail` | 실패 ✔(`releasingCharge` 경로) |

- 엔진 대상: 솔라빔·다이빙·고스트다이브·구멍파기·공중날기·뛰어오르기·메테오빔·솔라블레이드·일렉트로빔·불새(10종). 브리두라스(일렉트로빔)가 도감에 있어 실전에서 일어날 수 있다. 엔진에 파워풀허브는 없다.
- 수정안(프로브 미실시):
  1. 게이트 예외에 `c.move.chargeTurn && !c.releasingCharge`를 더한다.
  2. `handleChargeAndCopyMoves`에서 준비를 생략하는 분기(`skipsCharge`)로 곧장 발사할 때는, `chargeStatChanges`를 적용한 **뒤에** 지역 함수를 부른다.
  - 이렇게 하면 표의 5장면이 모두 맞는다.
- 선택지:
  - **(가) fix-56에 포함(권고)**: 같은 게이트·같은 시험 파일이고, R-i와 같은 지역 함수를 쓴다.
  - **(나) 별도 fix**: fix-59(f) 앞에 하나 더 둔다.
