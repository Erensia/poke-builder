## 2. 원인 (코드 읽기)
- **E8-18**: 정화의소금 `immuneToStatuses`에 `badly-poisoned` 누락(`isImmuneToStatus`는 `includes(status)`).
- **E8-24**: `mirroredEffects.ts` `inflictStatuses`가 `isImmuneToStatus`(특성·타입)·`isStatusBlockedByField`·신비의부적·쾌청 얼음에서 **`continue`로 조용히 넘어간다**(신비의부적은 틈새포착도 안 본다). 화면 줄은 `statusInflictFailed` 하나. 선례: `volatileBlockedByAbility`(마이페이스 혼란 등).
- **E8-19**: 졸음 부여(`mirroredEffects.ts` ~804행)는 "이미 상태이상/졸음"과 일렉트릭필드(접지)만 막고, 2턴 뒤 `finishTurn.ts` 500행이 면역·필드·**신비의부적**을 한꺼번에 본다.
- **E8-20**: 잠자기(`mirroredEffects.ts` ~1173행 `restSleep`)는 무조건 `currentHp = maxHp` + `inflictRestSleep()`. 수면 면역은 턴 끝 치료(`finishTurn.ts` 630행, **`immuneToStatuses` 전부를 치료**)에서만 나타난다. 이 치료 루프와 `abilityChange.ts` 33행(특성 획득 시 치료)은 **Showdown에 `onUpdate`가 없는 정화의소금·스위트베일까지 치료**한다(R4).
- **리프가드**: 동작 플래그 없음. `statusImmunitiesOf(fighter, ability)`는 날씨를 받지 않는다(호출 지점 약 20곳).

## 3. 변경
### 3-0. 데이터 (`abilities.json`·`types/ability.ts`) + `docs/데이터변경이력.md`
1. **E8-18**: 정화의소금 `immuneToStatuses`에 `"badly-poisoned"` 추가(면역 특성 9종 전수 대조 완료 — 독 계열은 이 한 건).
2. **R4**: `Ability.noCureOnAcquire?: boolean`(특성을 얻어도 기존 상태이상을 치료하지 않음)을 **정화의소금·스위트베일**에 표시한다(Showdown `onUpdate` 없음, 실행 확인 D 표). 치료 루프 두 곳(`finishTurn.ts` 630행·`abilityChange.ts` 33행)이 이 표시가 있으면 건너뛴다. 나머지(불면·의기양양·유연·수포·면역·마그마의무장·열교환)는 Showdown `onUpdate`가 있어 그대로.
3. **리프가드**: `Ability.blocksStatusesInSun?: boolean`을 리프가드에 표시한다(쾌청일 때 모든 주 상태이상·하품 면역). 날씨 판정은 엔진의 `activeWeather(state)`(구름몸 등 날씨 무효 특성 반영 — Showdown `effectiveWeather`와 같음)를 쓴다. **치료는 없다**(Showdown도 걸리는 것만 막음, 쾌청이 시작돼도 기존 상태이상은 유지).

### 3-1. 공용 판정 — 상태이상이 걸리지 않는 사유 (`src/lib/battle/state.ts`)
```ts
export interface StatusBlockContext { weather?: Weather; self?: boolean }   // self: 자기 자신이 대상(잠자기 — 플라워베일·신비의부적 제외)
/** 특성(+풀 타입 플라워베일, 쾌청의 리프가드)이 이 상태이상을 막는가. 소란피기는 제외한 순수 특성 면역 */
export function abilityBlocksStatus(fighter, ability, status, ctx?: StatusBlockContext): boolean
/** 이 상태이상이 걸리지 않는 사유 — 특성(이름) 또는 그 밖(타입·필드·신비의부적·쾌청 얼음·소란) */
export type StatusBlock = { kind: "ability"; abilityName: string } | { kind: "other" };
export function statusBlockReason(state, side, fighter, ability, status, opts: {
  attackerBypassesPoisonTypeImmunity?: boolean; attackerBypassesScreens?: boolean; self?: boolean; skipSafeguard?: boolean; skipSleepTriggerOnly?: boolean }): StatusBlock | undefined
```
- `statusBlockReason`은 `inflictStatuses`의 기존 `continue` 네 개(① 특성·타입 면역 ② 필드 ③ 신비의부적 ④ 쾌청 얼음)를 **같은 순서로** 한 곳에 모아 사유를 돌려준다. 신비의부적은 **공격측이 틈새포착(`bypassesScreensAndSubstitute`)이면 통과**(N1·Showdown `safeguard.infiltrates`)하고, `self`면(잠자기) 보지 않는다. 플라워베일은 `self`면 막지 않는다(N2·Showdown `target !== source`).
- **틀깨기(N1)**: 호출부가 이미 틀깨기로 무시된 방어측 특성(없음)을 넘기므로 사유가 나오지 않는다. 시험 22로 고정.
- `statusImmunitiesOf`(특성+플라워베일+소란)는 기존 호출 지점을 위해 남기되 **날씨 선택 인자**를 받아(`statusImmunitiesOf(fighter, ability, weather?)`) 리프가드가 쾌청에 전체 면역 목록을 돌려준다. 날씨를 안 넘기면 리프가드는 꺼진 채(= 특성 획득 치료 루프 등 기존 경로 불변).

### 3-2. E8-24 — 면역 로그 (`mirroredEffects.ts`·`resolveAction.ts`·`types/battle.ts`·`ActionEffectLines.tsx`)
- `inflictStatuses`: 상태이상 **전용 변화기**(`category === "status"`, `effect.chance === undefined`)가 `statusBlockReason`으로 막히면 `c.statusBlocked = { status, kind, abilityName? }`를 채운다(첫 상태이상 하나 — `break` 규칙 동일). 데미지 기술의 부가·확률 효과는 조용히 둔다. `ActionLogEntry.statusBlocked?: { status; kind: "ability" | "other"; abilityName?: string; self?: boolean }`.
- **기존 문구 재사용**: `ability` → `{방어측}의 {특성명}! {상태 라벨}에 걸리지 않는다!`(`volatileBlockedByAbility`·방음·방탄 줄과 같은 형태). `other` → `{방어측}에게는 효과가 없는 것 같다…`(`ohkoImmune`과 같은 문구). 신비의부적·미스트필드·일렉트릭필드·쾌청 얼음·소란피기·타입 면역을 이 한 줄로 합친다(§5). 상태 라벨은 `STATUS_LABELS`; 어색하면 구현 때 문장 틀(`…되지 않는다!`)을 한 번에 맞춘다(시험은 필드 존재만 고정).
- 반사(매직미러) 경로는 `reflectedView`가 방어측=사용자 사본으로 그려 이름이 맞는다(fix-45 방식). `moveFailure.ts`는 구현 때 `statusInflictFailed` 처리 방식을 먼저 확인하고 `statusBlocked`를 같은 방식으로 넣는다.

### 3-3. E8-19 — 하품: 즉시 막는 것과 2턴 뒤 막는 것을 가른다 (R3)
Showdown 구분(검수 §4)을 그대로 따른다.

| 시점 | 막는 것 |
|---|---|
| **하품 사용 시(즉시, 졸음 안 걸림)** | 이미 상태이상·졸음, **특성**(불면·의기양양·정화의소금·스위트베일·**리프가드+쾌청**·풀 타입 플라워베일), 일렉트릭필드(접지, fix-31 기존), **신비의부적(공격측이 틈새포착이면 통과)** |

- AI: `statusMoveEffects.ts` 하품 실패 판정(528행)은 이미 면역·필드·신비의부적을 "실패"로 보므로 의미가 맞아졌다(변경 없음, 리프가드는 날씨 인자 전달). `opponentMoveModel.ts` 143행 빠른 판정은 같은 즉시 차단 집합(특성·신비의부적·일렉트릭필드)을 본다.

### 3-4. E8-20 — 잠자기가 실패하는 조건 (R1·R2)
잠자기를 쓰는 쪽(자기 자신)은 아래 중 하나면 **회복도 수면도 치료도 없이 실패**한다(Showdown `Rest.onTry` → `setStatus` 순):
0. **이미 수면**(잠꼬대 경유) — **R2**. 엔진의 잠꼬대는 잠자기를 고를 수 있으므로(제외 목록에 없음) 이 한 줄이 필요하다.
1. **HP 가득**(`currentHp === maxHp`) — 상태이상이 있어도 실패.
2. **수면 면역 특성**(`abilityBlocksStatus(self, …, "sleep", { self: true, weather })` — 불면·의기양양·스위트베일·정화의소금·**리프가드+쾌청**; 플라워베일은 자기 자신이라 제외 — N2) → `statusBlocked { kind: "ability", self: true }`.
3. **일렉트릭필드 또는 미스트필드 + 접지**(R1: `isStatusBlockedByField(field, "sleep", grounded)`), **소란피기 중**(`sleepBlockedByUproar`) → `statusInflictFailed`("그러나 실패했다!").
- 신비의부적은 자기 자신을 막지 않는다. 실패 때 기존 상태이상은 치료하지 않는다. 열매 상호작용은 성공 경로에서만 그대로.
- AI: `opponentMoveModel.ts` `isPointlessNow`의 잠자기 예외(`!(restSleep && 상태이상)`)를 없애 **풀피면 무의미**로, `evaluator.ts` 1135행 잠자기 평가는 위 0~3이면 후보에서 제외한다. 엔진·AI 공용 판정 `restFails(state, key)`를 `statusMoveEffects.ts`에 둔다.

### 3-5. 리프가드 (`state.ts`·호출 지점)
- 3-0·3-1의 데이터·함수로 쾌청의 리프가드가 **모든 주 상태이상(상대발·반사·특성 발동·열매·독압정·불꽃 구슬류 등 날씨를 넘기는 경로)** 과 **하품·잠자기**를 막는다. 날씨를 넘기는 호출 지점: `mirroredEffects.ts`(593·630·659·679·700·716행)·`hitResolution.ts`(502·517)·`preHitEffects.ts`(1263)·`switching.ts`(260 독압정)·`fling.ts`(28)·`finishTurn.ts`(500 졸음 트리거)·AI(`partyEval.ts` 134, `statusMoveEffects.ts` 322·533·945). 치료 경로(`abilityChange.ts` 33·`finishTurn.ts` 630)는 날씨를 넘기지 않는다.

## 5. 알면서 둔 것
- **면역 문구 합치기**: 신비의부적·필드·소란·쾌청 얼음·타입 면역을 "효과가 없는 것 같다…" 한 줄로 합친다. Showdown은 `-activate … Safeguard`·터레인별 문구를 따로 낸다 — 새 문구·UI를 만들지 않는 방침.
- **정화의소금 잠자기 문구**: Showdown은 특성 문구 없이 `-fail`이지만(잠자기에 `status` 필드가 없어서) 엔진은 Q1 방침대로 특성 줄을 낸다.
- **플라워베일 vs 자기 부여 상태이상(화염구슬·독독구슬)**: Showdown은 `target !== source`라 통과, 엔진 `statusImmunitiesOf`는 막는다. 풀 타입 플라워베일 보유자가 도달 불가에 가까워 기록만(**E8-25 후보**).
- **틀깨기 + 열교환**: Showdown은 "화상 → 즉시 치료"(`onUpdate`), 엔진은 턴 끝 치료라 화상 데미지가 한 번 들어갈 수 있다. 합법 조합(틀깨기+도깨비불)이 없어 기록만.
- **`moveFailure` 확장**이 "직전 기술 실패"류 효과에 닿는지는 구현 때 확인한다.
- E8-18②(정화의소금 ±1 반올림)는 ② 배율 묶음. E8-21·22는 fix-47.
