## 1. 반사 집합·근거 (일치)

| 항목 | Showdown | 설계서 |
|---|---|---|

| 세 기술 플래그 | 울부짖기 `reflectable·sound·bypasssub`, 날려버리기 `reflectable·bypasssub·wind`, 뒤집어엎기 `protect·reflectable`(**bypasssub 없음**) | 반사 대상에 추가 |

## 3. §2-2·§2-3 판정 (일치)

- **대상 키 일반화**: Showdown `forceSwitch`는 "기술의 대상"을 끌어낸다. 반사된 기술의 대상은 원래 사용자이므로 `bouncedMoveName ? key : opponentKey(key)`는 정확하다.
- **가드 조건**: Showdown `forceSwitch`는 `target.hp > 0 && source.hp > 0 && canSwitch(target.side)` 후 `DragOut` 이벤트(흡반·번견·뿌리박기)로 막는다. 설계서의 `hasLivingReserve`·`isForcedSwitchBlocked`·기절 가드를 대상 키 기준으로 옮기는 것과 같다.
- **`isForcedSwitchBlocked` 두 번째 인자**: 반사 시 `source`는 매직미러 쪽이다. 매직미러 보유자는 틀깨기를 동시에 가질 수 없으므로 흡반·번견은 항상 유효 — 설계서 서술과 같다.
- **반환값 false**: 방어측(매직미러 쪽)은 끌려 나가지 않으므로 맞다. 변화기라 위기회피·탈출버튼은 어차피 평가되지 않는다.
- **드래곤테일·배대뒤치기**: `reflectable` 없음 — 영향 없음(시험 9 일치).
- **뒤집어엎기 자동 적용(§2-3)**: 반사 구간에서 사용자에게 적용된다는 설계는 Showdown 결과(장면 7)와 같다. 단 아래 R1의 대타 조건이 반사 구간에서도 지켜지는지가 확인 포인트다.

## 4. 시험 보강

### R1. 대타 조건 (시험 11·12 신규)
- Showdown `substitute.onTryPrimaryHit`: `bypasssub`가 없는 변화기는 `getDamage`가 없어 `-fail`. 반사된 기술도 **원래 사용자의 대타**에 대해 같은 판정을 받는다.
- **시험 11**: 사용자가 대타 뒤에서 뒤집어엎기 → 반사 → **실패, 사용자 랭크 그대로**(장면 8).
- **시험 12**: 사용자가 대타 뒤에서 날려버리기 → 반사 → **끌려 나감**(장면 10).
- 엔진의 반사 구간이 "사용자 대타"를 보는지 먼저 확인한다. 기존 반사(전기자석파 등 `bypasssub` 없는 상태이상기)에서 이미 처리돼 있으면 시험만 추가, 아니면 이 PR 범위로 같이 고친다(기존 반사기에도 같은 차이가 있다는 뜻이므로 별도 항목으로 분리하는 것도 가능 — 결과를 보고 판단).

### R2. 기존 시험 확장
- **시험 5**: 흡반에 더해 **번견**(마피티프는 champions에서 울부짖기 습득 → 도달 가능)과 **뿌리박기**를 추가한다. 세 경우 모두 반사돼도 교체 없음(장면 3·6).
- **시험 3**: 사용자 랭크가 전부 0이면 반사된 뒤집어엎기는 **실패**(장면 9). 양쪽에 랭크가 있는 현재 장면만으로는 "사용자 쪽에만 적용"을 보지만 실패 분기는 보지 않는다.
- 예비 없음(시험 5 전반부)의 Showdown 로그는 `-fail`이다. 엔진 로그 문구는 기존 실패 문구 재사용으로 충분(§6-3 시험 대체와 같은 취지).

## 5. Q1(결정 필요): 반사된 울부짖기 vs 사용자 방음

- Showdown: 방음 `onTryHit`은 `target !== source && flags.sound`면 `-immune`. 반사된 울부짖기의 `target`은 원래 사용자, `source`는 매직미러 쪽이므로 **사용자의 방음이 막는다**(장면 2).
- 설계서는 "극히 드문 조합"으로 백로그에 두었지만 champions 스캔 결과 **도달 가능**하다.
  - 방음 + 울부짖기 습득: **짜랑고우거(Kommo-o)·바리톱스(Bastiodon)**
  - 매직미러: 에브이·브리무음·메가 픽시·메가 깜까미·메가 앱솔
- 이 PR 전후 비교: 전에는 "매직미러 쪽이 끌려 나감", 후에는 "방음 사용자가 끌려 나감" — **둘 다 Showdown(아무도 안 나감)과 다르다**. 이 PR이 경로를 새로 열기 때문에 함께 닫는 편이 깔끔하다.
- **권고**: 이번 PR에 포함. `forceTargetSwitch`의 반사 분기에서 `move.sound && 사용자 특성 === 방음`이면 교체하지 않고 방음 무효 로그(기존 문구) — 가드 1개 + 시험 1건. 측정 해시 원인 분리에도 문제 없다(같은 "반사된 강제 교체" 범주).
- 대안: 백로그 유지. 이 경우 §5에 "도달 가능(2종 × 5종)"으로 고쳐 적는다.
