## 3. 변경

### 3-1. 데이터 — 면제 79종 표시 (규칙이 아니라 데이터로)
**선택**: `Move`에 `pressureExempt?: true`를 **면제 79종에만** 붙인다(이진 표시, 511종 전수 대상 필드보다 작고 `mustpressure` 4종은 표시 없음으로 자연히 −2).
- **왜 규칙이 아닌가**: 엔진에는 "자기 대상인가"를 판별할 일관된 필드가 없다(`statChanges[].target`·`setsScreen`·`protectEffect` 등이 기술마다 흩어져 있고 회복·대타출동·아쿠아링·미스트는 필드가 제각각). 규칙 함수로 추정하면 누락이 조용히 틀린 −2로 남는다 — 데이터 79건 + **Showdown 대조 검증**이 더 안전하다(accuracy > 기존 구현).
- **목록 생성·검증**: 영문→한글 매핑은 D3 E0에서 쓴 `zz-d3-data-diff.mjs.txt`의 PokeAPI CSV 매핑(`API_DIR`)을 쓴다 — **이 PC에는 CSV가 없어 설계 단계에서는 영문 분류까지만 확정**했고, 구현 때 집 PC 또는 사용자가 CSV를 받아 매핑한 목록을 **이 설계서 부록과 대조**한다. 구현 시험이 `scripts/battle-ai-scenarios/…`에서 `moves.json`의 `pressureExempt` 집합이 Showdown 대상 분류(영문 목록을 시험에 박는다)와 **같은 79종**인지 검사한다(매핑은 일회용 스크립트가 만들고 시험에는 한글 id 목록을 고정).
- **수정 방식**: 줄 단위 삽입(재직렬화 금지, 작업 복사본 CRLF — fix-48 교훈: `sed -i` 대신 node 스크립트), `npm run validate:data`, `docs/데이터변경이력.md` 항목(79종 이름 포함).

### 3-2. 엔진 — `payMovePp`(`preHitEffects.ts` 192행) 한 곳
- 프레셔 블록 조건에 `!c.move.pressureExempt`를 더한다(`extraPpCostWhenTargeted` 값 1은 그대로). 주석 정정("자기 대상 변화기도 포함 — 본가 규칙"을 지우고 Showdown 규칙·`mustpressure`·예외를 적는다).
- **잠꼬대·흉내쟁이**: 프레셔 차감은 `payMovePp`(167행 부근)에서 호출 **전**에 일어나 호출된 기술을 모른다(호출은 565·587행). 두 선택지 — **(가) 권고**: 호출 기술이 정해진 뒤(`c.move`가 덮인 직후)로 **호출 계열 기술에 한해** 프레셔 차감을 옮기고 호출된 기술의 `pressureExempt`로 판정, 슬롯은 호출한 기술(`c.pre`의 입력 기술)에서 차감. (나) 알면서 둠: 잠꼬대·흉내쟁이는 자기 대상이라 면제되어 호출 기술이 상대 대상이어도 프레셔 −1이 빠진다. 샘플은 **둘 다 0건**이라 (나)도 실영향은 작지만 규칙 정확성상 (가)를 권고한다(작업량: 차감 코드를 소함수로 빼 두 곳에서 호출).
- 기존 예외 유지: 차지 기술 2턴째(`releasingCharge`)·난동 이어 쓰기·반동 턴은 PP 자체를 안 쓰므로 프레셔도 없다(`payMovePp`의 조건 그대로, Showdown은 연속 사용 때 `useMove`의 `sourceEffect` 조건과 같은 결과 — 구현 때 `[실행]` 대조).
- **PP 하한**: `Math.max(0, …)` 그대로. 과사열매(`restoresPpOnZero`)는 차감 후 정확히 0이 되는 순간에만(기존 규칙 불변, 프레셔 차감으로 0이 돼도 같은 판정).
- **로그**: `pressureExtraPpAbilityName`은 "추가로 차감됐을 때만" 채워져 화면 문구가 자연히 줄어든다(자기 대상 기술에는 더 안 나옴) — 문구·UI 변경 없음.
- **AI**: `extraPpCostWhenTargeted`·`pressureExtraPp…`를 읽는 곳은 엔진뿐이다(AI·평가기 사용 `grep` 0건) — 변경 없음.
