## 4. Q1(확정): champions 탈출버튼은 공격자 유턴 교체를 취소하지 않는다

| | 기본 `data/items.ts` 1692행 | champions `items.ts` 262행 |
|---|---|---|
| 탈출버튼 발동 후 | `if (target.useItem()) source.switchFlag = false;` → **공격자의 유턴·볼트체인지·퀵턴 교체 취소** | 해당 줄 삭제 → **공격자도 교체 유지(양쪽 교체)** |

- 유턴의 `source.switchFlag = move.id`는 `runMoveEffects`(`battle-actions.ts` 1372행)에서 **`AfterMoveSecondary`보다 먼저** 설정된다. 탈출버튼의 "누가 이미 `switchFlag === true`면 중단" 검사는 문자열(`'uturn'`)을 걸러내지 않으므로 탈출버튼은 발동하고, champions에서는 공격자 교체도 남는다.
- 위기회피의 같은 변경(교체 플래그 정리 루프 삭제)은 E8 R2에서 지적돼 엔진이 이미 일치(시험 24번 A7-3)한다고 설계서가 적었다. **탈출버튼 쪽은 설계서에 언급이 없다.**
- 우격다짐과는 무관한 별개 차이다.

### 확정된 처리 (사용자 결정 2026-11-24, 권고안)
1. Claude Code에서 엔진 동작을 먼저 확인한다(유턴·볼트체인지·퀵턴 사용자 → 탈출버튼 보유자, 교체 가능한 후보가 양쪽에 있는 장면).
2. **엔진이 이미 양쪽 교체면**: 일치. fix-43 `74-ver83-d3fix43.mjs`에 **시험 10번**(양쪽 교체, 탈출버튼 소모)으로 고정만 추가한다.
3. **엔진이 공격자 교체를 취소하면**: 수정필요. **E9 별도 항목 fix-44**로 등록하고 fix-43 PR에는 넣지 않는다.
   - 이유: 설계서 §4 측정은 `regress` 해시 변동을 "우격다짐 × 세 효과" 조합으로 설명하는 구조다. 유턴 × 탈출버튼 변경이 같은 PR에 섞이면 해시 변동의 원인을 나눌 수 없다.

## 5. 시험 보강

### R1. 시험 7(탈출버튼 + 위기회피 동시 보유)
- Showdown 순서: `AfterMoveSecondary`(탈출버튼, `switchFlag = true`) → `EmergencyExit`(위기회피는 `target.switchFlag`면 return). 기대값 "탈출버튼만"은 맞다.
- 단 위기회피는 **HP가 절반 위 → 절반 이하로 넘어갈 때만** 발동한다. HP 구간을 맞추지 않으면 탈출버튼이 없어도 위기회피가 안 걸려 시험이 공허하게 통과한다.
- **수정**: 공격 전 HP > 50%, 공격 후 ≤ 50%(생존)로 맞추고, 같은 장면에서 도구만 뺀 대조(위기회피 발동)를 함께 둔다. 탈출버튼과 레드카드는 한 포켓몬이 동시에 가질 수 없으므로 "판정 순서 탈출버튼 → 레드카드 → 위기회피"는 엔진 내부 순서 설명으로만 남긴다.

### R2. 시험 5(추가효과 제거 회귀)
- 독찌르기 독 확률은 30%라 난수를 고정하지 않으면 우격다짐 처리가 깨져도 70% 확률로 통과한다.
- **수정**: 추가효과 판정이 반드시 걸리는 난수로 고정하고, 같은 난수에서 일반 특성 대조군은 독이 걸리는 것을 확인한다.
