## 2. 지적 사항

### 2-1. [중요] 반전(Contrary)과 변덕쟁이는 함께 있을 수 없음 → 시험 #8 삭제, 미결 1 종결
- 반전은 **특성**입니다(Showdown 678행 `contrary.onChangeBoost`). 포켓몬은 특성을 하나만 가지므로 변덕쟁이 보유자는 반전일 수 없습니다. 스킬스왑 등으로 특성이 바뀌면 그 순간 변덕쟁이가 아니게 됩니다.
- 따라서:
  - 시험 #8(반전 + atk +6)은 정상 상태로는 만들 수 없는 장면입니다 → **삭제** 권고. 강제로 상태를 만들어 시험하면 존재하지 않는 동작을 고정하게 됩니다.
  - §5 "반전 보유자의 문구"와 §6 미결 1은 **도달 불가로 종결** 권고. E8-48로 넘길 필요가 없습니다.
  - §1-2 마지막 줄(반전 설명)은 "반전은 특성이라 변덕쟁이와 공존 불가 — `contraryDelta` 호출은 해가 없으므로 그대로 둠"으로 바꾸는 것을 권고합니다.
- 구현 때 확인할 것: 엔진 `contraryDelta`가 무엇을 보고 뒤집는지(`ability === 'contrary'`만 보는지) `grep`. 특성 외의 다른 경로(예: 내부 플래그)가 있다면 그때만 다시 검토합니다.

### 2-2. [중요] 난수 소비 횟수를 시험으로 고정
- §1-1-3("후보가 비면 난수 소비 없음")이 해시 변동의 원인인데, 시험이 `() => 0`만 쓰면 호출 횟수 차이를 잡지 못합니다.
- 권고: 호출 횟수를 세는 난수(`let n = 0; const random = () => (n++, 0);`)를 써서 다음을 단언합니다.

| # | 장면 | 난수 호출 횟수(기대) | 현행 |
|---|---|---|---|
| 4 | 5종 전부 +6 | **1** | 2 |
| 5 | def·spa·spd·spe −6, atk 0 | **1** | 2 |
| 7 | 5종 전부 −6 | **1** | 2 |
| 1 | 전부 0 | 2 | 2 |

→ #4·#5·#7은 결과뿐 아니라 **호출 횟수로도 현행에서 실패**하게 됩니다.

### 2-3. [경미] "둘 다 없음"은 일어날 수 없음
- 올릴 후보가 비면 5종이 모두 +6이므로 내릴 후보는 반드시 5종 전부입니다. 반대로 내릴 후보가 비면 올릴 후보는 반드시 있습니다.
- §2의 "둘 다 없으면 로그 엔트리를 만들지 않는다"는 방어 코드로 두어도 되지만, 설계서에 "도달 불가(방어용)"라고 적어 두기를 권고합니다. 시험은 필요 없습니다.

### 2-4. [확인] 상대의 미러허브·편승(Opportunist)
- Showdown 미러허브(`items.ts` 4174행 `onFoeAfterBoost`)는 상대가 실제로 올린 양을 복사합니다. 현행 엔진은 +6 능력치를 뽑으면 +2가 흡수되어 복사할 것이 없고, 수정 후에는 다른 능력치가 실제로 +2 올라 복사 대상이 됩니다.
- 엔진에 미러허브/편승이 구현되어 있고 변덕쟁이 경로에도 연결되어 있다면 해시 변동 요인이 하나 더 생깁니다. 구현 때 `grep mirrorHerb|opportunist`로 확인하고, 구현이 없으면 "해당 없음"으로 기록하면 됩니다(이 PR 범위의 수정은 필요 없음).
