## 2. R1(필수 수정): 대타 무시 기준은 "소리"가 아니라 `bypasssub`

### Showdown
- `substitute.condition.onTryPrimaryHit`: `if (target === source || move.flags['bypasssub'] || move.infiltrates) return;` — 판단 기준은 **`bypasssub` 플래그**다. 소리 기술은 전부 `bypasssub`를 갖고 있어 "소리 = 대타 무시"처럼 보일 뿐이다.
- champions 합법 기술 중 **소리가 아니면서 `bypasssub`인 반사 가능 기술**:

| 기술 | 습득 종 수 | 비고 |
|---|---|---|
| 날려버리기 | 19 | 강제 교체 — 엔진 게이트 없음(설계서 B1) |
| 도발 | 137 | 행동방해 |
| 앙코르 | 79 | 행동방해 |
| 트집 | 67 | 행동방해 |
| 사슬묶기 | 45 | 행동방해 |
| 헤롱헤롱 | 282 | 행동방해(성별) |
| 원한 | 91 | PP 감소 |
| 안개제거 | 29 | 회피 하락 + 장판 제거 |

- `[실행]`: 도발·트집·사슬묶기를 매직미러에 쓰고 **사용자가 대타 뒤** → 반사돼 **사용자에게 걸린다**(대타 유지). 직접 대타 뒤 상대에게 써도 걸린다(대조).
  - 주의: 앙코르는 반사 시 `-fail`이 나오지만 이는 대타 때문이 아니라 사용자의 마지막 기술이 앙코르 자신(`failencore`)이라서다. 시험 장면으로 쓰지 말 것.

### 엔진 영향
- §3-3은 "이후 `!c.opponentEffectsBlocked`로 게이트된 기존 블록(랭크 하락·상태이상·**행동방해**·뒤집어엎기 등)"이 대타를 존중한다고 적었다. `substituteBlocksMove`가 소리만 빼면 **반사된 도발·트집·사슬묶기·헤롱헤롱·원한·안개제거가 사용자 대타에 막힌다** — 현행(버그 덕에 우연히 일치)보다 **나빠진다**.
- 같은 함수가 624행(직접 사용)도 대신하므로, **직접 쓴 도발 등이 대상 대타에 막히고 있다면 그것도 기존 어긋남**이다. 엔진에 이미 별도 예외가 있는지 구현 전에 확인해야 한다.

### 권고
1. `substituteBlocksMove`의 제외 조건을 **`bypasssub`에 해당하는 데이터**로 바꾼다. 엔진 기술 데이터에 이에 해당하는 필드가 있으면 그것을, 없으면 "소리 분류 ∪ 위 8종" 집합을 쓴다. 고스트 저주는 Showdown에서도 `bypasssub`라 같은 집합에 들어간다.
2. 구현 전 확인: 엔진이 **직접 쓴 도발 등**을 대타 뒤 상대에게 어떻게 처리하는지. 이미 통과시키고 있으면 그 예외를 공용 함수로 옮기면 되고, 막고 있으면 공용 함수가 직접 사용 경로도 함께 고치게 된다 — 이 경우 해시 원인이 하나 더 생기므로 §7 단계 측정에 "직접 사용 bypasssub" 단계를 추가하거나 별도 항목(E8-15 후보)으로 분리할지 사용자 결정이 필요하다.
3. 시험 14(공용 함수 단위)에 **도발+대타 → false** 를 추가한다.

## 4. R3: §3-2 Showdown 순서 근거 (소스 확인)

| 판정 | Showdown 위치 | 우선도/단계 |
|---|---|---|

- 황금몸·방음·방탄이 매직미러와 한 포켓몬에 공존할 수 없다는 서술도 맞다(특성 1개).

## 5. Q1(결정 필요): 반사 후 사용자 쪽의 "대타 외" 면역

### Showdown
- 반사는 `useMove(newMove, 반사한 쪽, {target: 원래 사용자})`로 **기술을 새로 쓴다**. 따라서 원래 사용자에 대해 TryHit(황금몸·방음·초식 등)·가루 면역·대타가 **모두 다시 판정**된다.
- `[실행]`:

| 장면 | Showdown |
|---|---|
| 이상해꽃(풀) 수면가루 → 에브이 | 반사 → `-immune|p1a: Venusaur` |
| 짜랑고우거(방음) 싫은소리 | 반사 → `-immune … Soundproof` |
| 타부자고(황금몸) 이상한빛 | 반사 → `-immune … Good as Gold` |
| 고고트(초식) 씨뿌리기 | 반사 → `-boost atk 1`(흡수) |

- champions 도달 가능 조합(스캔): 풀 타입 + 반사 가능 가루기 **23**, 방음 + 반사 가능 소리기 **7**(바리톱스·짜랑고우거), 황금몸 + 반사기 **2**(타부자고 이상한빛·금속음), 초식 + 풀 반사기 **2**(고고트 씨뿌리기·고민씨). 방진·방진고글은 champions에 해당 조합/아이템이 없다.

### 엔진
- 설계서 §2의 원인 서술대로라면 반사 구간 시작 후 `opponentEffectsBlocked`는 입력값(false) 그대로이고 **맞바뀐 방어측을 대타 외 기준으로도 다시 보지 않는다**. fix-44에서 반사된 울부짖기 × 방음 가드를 넣었다면 그 경로만 처리돼 있을 수 있다. 상태이상 쪽(풀 타입 가루, 황금몸)이 다른 곳에서 막히는지는 엔진 코드 확인이 필요하다.

### 선택지
- **A(권고)**: §3-3을 "대타만 다시 판정"에서 **"맞바뀐 방어측에 대해 `checkDefenderImmunities`의 방어측 차단 집합(황금몸·가루 면역·방음·방탄·초식·대타)을 다시 계산"**으로 넓힌다. 같은 자리·같은 규칙(반사 = 새로 쓰기)이라 근본 원인 하나로 닫히고, 공용 함수를 하나 더 늘리는 대신 기존 판정을 재사용하면 된다. 해시 원인은 §7 단계 측정에 단계 하나를 추가해 분리한다.
- **B**: 이번 PR은 대타만. 나머지는 E8-16(후보)으로 백로그하고 §5 "알면서 둔 것"에 도달 가능(34조합)으로 기록.
- 어느 쪽이든 **S1**: §3-3의 대입은 `c.opponentEffectsBlocked = …`(덮어쓰기)가 아니라 기존 값과 **누적(`||`)** 하는 형태로 둔다. fix-44에서 반사 구간에 다른 차단을 넣었다면 덮어쓰기가 그것을 지운다.

## 6. 그 밖의 항목 (일치)

- **§3-2 `c.blockedBySubstitute = false`**: 반사 성립 시 변화기라 데미지 경로 no-op이라는 판단 맞음. 양쪽 대타(C2)는 수정 후 "반사 → 사용자 대타 `-fail`"로 Showdown 로그 경로와 같아진다.
- **§3-3 C3**: 맞바뀐 뒤 `attackerAbility`는 반사한 쪽 특성(매직미러)이므로 틈새포착이 끼어들 수 없다. Showdown도 `move.infiltrates`는 기술 사용자(반사한 쪽) 기준.
- **§3-4 로그**: 주체 일치(§1). 뒤집어엎기 문구 미출력은 기존 한계로 두는 판단 동의.
- **§3-5 AI**: `effectMoveFails`·`opponentMoveModel`이 매직미러 상대 변화기를 이미 무의미로 보므로 변경 불필요 — 동의. 단 R1을 공용 함수로 바꿔 직접 사용 경로가 바뀌면 AI의 "대타 뒤 상대에게 도발 무의미" 판단이 있는지 함께 확인한다.
- **§5 가루 면역 순서**: 매직미러 5종에 풀 타입 없음 — 스캔 확인, 도달 불가 맞음.
- **§6 사용자 결정(한 PR·기존 문구)**: 검수 의견 없음. §7 측정 계획 승인(R1·Q1 결과에 따라 단계 추가).
