## 1. 문제 — 세 겹으로 어긋난다
Showdown의 순서는 **방어류(`onTryHit` 3) → 매직미러(1) → 황금몸·방음·방탄(0) → 가루 면역(`hitStepTryImmunity`) → 대타(`spreadMoveHit` 0단계, 뒤 단계)** 이다(R3 정정: 매직미러 우선도는 1, 2는 매직코트). 반사는 기술을 **반사한 쪽이 원래 사용자에게 새로 쓰는 것**이라 **원래 사용자에 대한 면역·대타가 전부 다시 판정**된다. 엔진은 대타를 반사 **앞**에서 한 번, 반사하는 쪽 기준으로만 본다.

**`[실행]`** Hippowdon(사용자) → Espeon(매직미러), 대타는 `addVolatile('substitute')`.

## 2. 원인 (코드 읽기)
`src/lib/battle/preHitEffects.ts` `checkDefenderImmunities`:
```ts
c.blockedBySubstitute = defender.substituteHp !== undefined && !소리 && !(저주·고스트) && !attackerAbility.bypassesScreensAndSubstitute;   // 624행
c.opponentEffectsBlocked = 황금몸 || c.blockedBySubstitute || 방어 || 가루면역 || 방음 || 방탄;                                          // 668행
c.bouncedByMagicMirror   = !c.opponentEffectsBlocked && 매직미러 && isMagicBounceReflectable(move);                                  // 681행
```
- **R1**: 대타 무시를 "소리 분류"로만 판정한다. Showdown은 `move.flags['bypasssub']`이고 소리 기술은 전부 그 플래그를 가질 뿐이다. 비소리 `bypasssub` 28종(§3-0)은 대타에 막히지 않아야 하는데 엔진은 막는다(D1).
- **E8-14**: `bouncedByMagicMirror`가 `opponentEffectsBlocked`에 든 **반사하는 쪽 대타**로 막힌다.
- **E8-13·Q1**: `mirroredEffects.ts` 반사 구간 시작(바인딩 맞바꿈)에서 `c.opponentEffectsBlocked`는 입력값(반사 성립 조건상 false) 그대로라, **맞바뀐 방어측(원래 사용자)의 대타·황금몸·가루 면역·방음·방탄을 다시 보지 않는다.**
- 로그: 막힘 문구 필드(`blockedBySubstituteMoveName`·`soundproofBlockedByAbilityName` 등)가 반사하는 쪽 판정에서만 만들어진다.

## 3. 변경
### 3-0. 데이터 — `bypassesSubstitute` (R1, 덤프 전수 추출)
- `src/types/move.ts`에 `bypassesSubstitute?: boolean`(옆 `bypassesProtect`와 같은 결). Showdown `bypasssub`이면서 **소리가 아닌** 기술(champions 합법 28종)에 `true`를 둔다 — **소리 기술은 소리 분류가 이미 같은 일을 하므로 따로 표시하지 않는다**.
- 대상 28종(덤프 `legal` ∩ `flags.bypasssub` ∖ `flags.sound`, 엔진 이름): 당신먼저·아로마미스트·헤롱헤롱·코칭·저주·안개제거·길동무·사슬묶기·앙코르·페어리록·가드스왑·흑안개·도우미·봉인·지휘(=Showdown `instruct`)·생명의물방울·자기장조작·파워스왑·자기암시·미러타입·역할·스킬스왑·스피드스왑·원한·도발·다과회·트집·날려버리기. 전부 엔진에 존재한다. 대타 판정에 실제로 작용하는 것은 상대를 겨냥하는 도발·트집·사슬묶기·앙코르·헤롱헤롱·원한·안개제거·흑안개·스왑·복사 계열이고 나머지(자기·필드·아군 대상)는 정확성을 위한 표시다.
- 데이터 변경 절차: `moves.json`은 작업 복사본 CRLF(인덱스 LF)라 줄 단위 삽입으로 편집하고 `npm run validate:data`를 돌리며 `docs/데이터변경이력.md`에 한 줄 적는다. 추출 스크립트는 `D3-검수자료/zz-fix45-bypasssub.mjs.txt`로 보관한다.

### 3-1. 공용 함수 (`preHitEffects.ts`)
```ts
/** 대타가 이 기술의 상대 방향 효과를 막는가 — Showdown `bypasssub`: 소리 기술·`bypassesSubstitute` 기술·틈새포착은 대타를 무시한다. */
export function substituteBlocksMove(move: Move, user: BattleFighterState, userAbility: Ability | undefined, target: BattleFighterState): boolean {
  return target.substituteHp !== undefined && !(move.classification ?? []).includes("소리") &&
    !move.bypassesSubstitute && !userAbility?.bypassesScreensAndSubstitute;
}   // 고스트 저주의 기존 예외는 저주의 bypassesSubstitute로 흡수된다
```
- **직접 사용 경로(624행)가 이 함수를 쓰도록 바꾼다** → D1이 닫힌다.

```ts
/** 방어측이 이 기술의 상대 방향 효과를 막는 사유 — 황금몸·대타·가루 면역·방음·방탄. 방어류·상성 면역은 호출부(직접 사용 경로 전용). */
export function opponentEffectBlockers(move, user, userAbility, target, targetAbility): {
  goldBodyAbilityName?: string; substitute: boolean; powder: boolean; soundproofAbilityName?: string; bulletproofAbilityName?: string; any: boolean;
}
```
- `checkDefenderImmunities`의 황금몸·대타·가루·방음·방탄 판정(617~667행)을 이 함수로 옮겨 **직접 사용 경로와 반사 구간이 같은 규칙을 쓴다**(Q1을 위한 공용화). 방어류(`activeProtect`)·`respectsTypeImmunity`는 기존 위치에 둔다.

### 3-2. E8-14 — 반사하는 쪽 대타는 반사를 막지 않는다 (`checkDefenderImmunities`)
```ts
const blockedOtherThanSubstitute = 황금몸 || 방어 || 가루면역 || 방음 || 방탄;
c.opponentEffectsBlocked = blockedOtherThanSubstitute || c.blockedBySubstitute;
c.bouncedByMagicMirror = !blockedOtherThanSubstitute && 매직미러 && isMagicBounceReflectable(move);
if (c.bouncedByMagicMirror) { c.blockedBySubstitute = false; c.opponentEffectsBlocked = false; }
```
- **순서 근거(R3, 소스 확인)**: 방어류(`onTryHit` 3) → 매직미러(1) → 황금몸·방음·방탄(0, 매직미러와 한 포켓몬에 공존 불가) → 가루 면역(`hitStepTryImmunity`, TryHit 다음 단계) → 대타(`spreadMoveHit` "0. check for substitute", TryHit·면역·명중 단계를 **모두 지난 뒤** 별도 단계). 대타는 우선도 비교 대상이 아니다. 따라서 방어를 `blockedOtherThanSubstitute`에 두는 것이 맞다. 가루 면역이 반사보다 뒤인 점은 매직미러 5종에 풀 타입이 없어 도달 불가(§5).

### 3-3. E8-13 + Q1 — 반사 구간에서 원래 사용자(맞바뀐 방어측)의 차단을 다시 판정한다 (`mirroredEffects.ts`)
반사 구간 시작, 바인딩을 맞바꾼 직후:
```ts
const b = opponentEffectBlockers(c.move, c.attacker, c.attackerAbility, c.defender, c.defenderAbility);   // 맞바뀐 뒤 attacker = 반사한 쪽, defender = 원래 사용자
c.opponentEffectsBlocked ||= b.any;                                                                       // S1: 덮어쓰기(=)가 아니라 누적
c.bounceUserBlock = b;                                                                                    // 로그용(§3-4)
```
- `c.attackerAbility`는 맞바뀐 뒤 **반사한 쪽의 특성**이라 사용자의 틈새포착이 끼어들 수 없다(C3). 사용자의 방음·황금몸은 사용자 특성 그대로 읽는다(Showdown도 반사된 기술은 새 `useMove`).
- 이후 `!c.opponentEffectsBlocked`로 게이트된 기존 블록(랭크 하락·상태이상·행동방해·뒤집어엎기 등)이 사용자의 대타·면역을 존중한다. 게이트 없는 블록은 그대로다 — 스텔스록(B2)·강제 교체(B1: `forceTargetSwitch`의 방음 가드는 fix-44에서 이미 처리).
- 도발·트집 등은 `bypassesSubstitute`라 사용자 대타에 막히지 않는다(D2).

### 3-4. 로그 (`resolveAction.ts`) — 기존 문구 재사용
- `finalizeAction`: `blockedBySubstituteMoveName = (c.blockedBySubstitute || bounceUserBlock.substitute) && !c.hitSubstitute && isOpponentTargetingMove(c.effectiveMove) ? name : undefined`.
- 반사 중 새로 막힌 사유는 기존 필드에 채운다: `soundproofBlockedByAbilityName`·`bulletproofBlockedByAbilityName`·`goodAsGoldBlockedByAbilityName`(`c.blockedByGoodAsGold` 대신 반사 값)·`powderBlockedMoveName`. 반사 줄은 `reflectedView`가 방어측=사용자인 사본으로 그리므로 문구가 "(사용자)의 방음!"·"(반사한 쪽)의 …는 실패했다!" 순으로 Showdown `-immune`/`-fail` 주체와 맞는다. 새 문구·UI 변경 없음.
- 뒤집어엎기는 `isOpponentTargetingMove`가 아니라 직접 사용 때도 대타 막힘 문구가 없다(기존 한계, §5).

### 3-5. AI — 같은 공용 함수로 통일 (초안 "AI 무변경" 철회)

## 5. 알면서 둔 것
- **초식 흡수(E8-16으로 분리)**: 반사된 풀 변화기를 사용자의 초식이 흡수(능력치 +1)하는 2조합(고고트 씨뿌리기·고민씨)은 "막는다"가 아니라 흡수 경로(`abilityAbsorb`)라 로그·효과가 따로 필요하다. 이 PR에서는 제외하고 `8.3-D3-E8-검수.md`에 E8-16으로 기록한다.
- **상성 면역(전기자석파 등 `respectsTypeImmunity`)**: 반사 후 사용자의 타입 면역(땅 타입 사용자의 전기자석파)은 `typeEffectiveness`(원래 방어측 기준)로 이미 계산돼 다시 보지 않는다. 땅 타입 사용자가 전기자석파를 매직미러에 쓰는 도달 가능성이 낮아 기록만 한다(**E8-17 후보**).
- **가루 면역 ↔ 반사 순서**: Showdown은 반사가 풀 타입 가루 면역보다 먼저지만 매직미러 5종에 풀 타입이 없어 도달 불가. 코드는 현행 순서 유지.
- **직접 쓴 뒤집어엎기·강제 교체의 대타**: 뒤집어엎기는 `opponentEffectsBlocked`로 이미 대타에 막히고(일치), 날려버리기·울부짖기는 대타 게이트가 없어 `bypasssub`와 일치. 다만 뒤집어엎기는 막힘 문구가 없다(UI 한계).
- **반사된 기술의 PP·실패 판정(`moveFailure`)**은 현행대로. 새로 채우는 방음·황금몸·가루 필드는 `moveFailure`·`rampage`가 이미 읽는다.
- **시험 8의 틈새포착 하마돈**은 합법 조합이 아니다(Showdown 스크립트도 동일). 엔진 시험이라 무방.
