## 0. 한 줄 요약
오기·승기는 **상대(또는 상대 쪽 효과)가 낸 능력치 하락**에만, **떨어진 능력치 하나마다 1회씩** 발동한다. 엔진은 ① 자기 기술의 반동 하락에도 발동하고(E8-42) ② 한 기술이 여러 능력치를 내려도 1회만, ③ 명중·회피 하락·접촉 반응 하락(미끈미끈)·턴 끝 지속 하락(문어굳히기·시럽봄)에는 발동하지 않고 ④ 기절한 보유자에게도 발동한다(E8-43). 한 함수로 모아 호출 지점마다 같은 규칙을 쓰게 한다.

## 1. 문제

### 1-1. 규칙 (Showdown 965a535, champions 변경 없음)
- `defiant`/`competitive.onAfterEachBoost(boost, target, source, effect)`(`data/abilities.ts` 645·901행): `if (!source || target.isAlly(source)) return;` — **출처가 없거나 자기 자신·아군이면 무발동**. 능력치가 `boost[i] < 0`으로 실제 하락한 경우에만 `this.boost({atk|spa: 2}, target, target, null, false, true)`.
- `AfterEachBoost`는 `boost()`가 **능력치 하나씩** 처리할 때마다 불려서 **한 기술이 능력치 둘을 내리면 2회**(간지르기 오기 atk +3)다. 하락 판정은 클램프된 값이라 이미 −6이면 발동하지 않는다. **명중률·회피율도 능력치**다(진흙뿌리기·달콤한향기 발동).
- 출처가 상대인 하락은 전부 포함: 변화기·데미지 기술의 부가 하락·위협·끈적끈적네트·**접촉 반응 하락(미끈미끈)**·**미러아머 반사(출처 = 반사한 상대)**·**턴 끝 지속 하락(문어굳히기 `boost(…, source)`·시럽봄)**. 자기 하락(엄청난힘·용성군·껍질깨기·약한갑옷)은 무발동.

## 2. 변경

### 2-1. 공용 함수 두 개 (한 곳)
`state.ts`(랭크 도우미들이 사는 곳)에 둔다. 소비처가 `mirroredEffects.ts`·`switching.ts`·`finishTurn.ts` 셋이라 한 파일에서 내보낸다.
1. `countLoweredStats(before, after, accBefore?, accAfter?)` — 5종 랭크 + 명중·회피 가운데 **`after < before`인 능력치의 수**를 돌려준다(클램프로 변화 없으면 0).
2. `applyOwnStatDropReaction(fighter, lowered)` — 보유자가 `boostsStatOnOwnStatDrop`이고 **기절하지 않았고** `lowered > 0`이면 `{stat, delta}`를 **`lowered`번** `applyStageDelta`(+6 클램프)로 올린다. 올라간 값이 있으면(`stages[stat]` 변화) 로그 한 줄(`switching.ts`의 기존 문구 재사용 — 호출처가 문구를 갖는 경우만).
→ 기존 `applyCompetitiveBoost`(기술 경로)·`reactToOwnStatDrop`(`switching.ts`)은 이 둘을 부르도록 바꾼다.

### 2-2. 호출 지점별 규칙
| 지점 | 세는 것 | 변경 |
|---|---|---|
| 기술 경로 **방어측** | `defenderStagesBeforeMoveChange` → 반사·차단·명중회피 변화 **뒤** 최종값(상대 기술이 낸 하락만 — 방어측 자기 변화는 없다) + 명중·회피 | 호출을 명중·회피 변화 처리(`opportunistAndAccuracyChanges`, 460~476행) **뒤**로 옮긴다 |
| 기술 경로 **공격측** | **자기 기술 변화를 뺀** 하락: 새 스냅샷 `attackerStagesAfterOwnChange`(`applyStatChanges`가 자기 변화를 적용한 직후)를 기준으로 → 미러아머 반사로 내려간 것 + **접촉 반응 하락**(`hitResolution.ts`가 이미 모으는 `abilityLoweredAttackerStats`의 능력치 수) | 새 필드 1개 + 접촉 반응 수 읽기 |
| `switching.ts` 위협·끈적끈적네트·미러아머 반사 | 한 건의 하락 → 1 | `reactToOwnStatDrop` → 공용 함수 |
| `finishTurn.ts` 문어굳히기·시럽봄 | 실제로 내려간 능력치 수(문어굳히기 최대 2, 시럽봄 1) | 하락 적용 직후 공용 함수 호출 + 로그 필드 필요 시 기존 `octolockDrop`·`syrupCoatDrop`에 올림 정보는 **추가하지 않고** 랭크만 올린다(문구는 기존 EOT 항목이 이미 있어 별도 줄 필요하면 §6 결정) |
- **하지 않는 것**: Showdown은 하락 **즉시** 상승(능력치마다)이고 엔진은 효과 처리가 끝난 **뒤**에 한 번에 올린다 — 클램프가 걸리지 않는 한 최종 랭크가 같다(+6 근처에서만 순서 차이가 있을 수 있고 §5에 기록).

### 2-3. 주석 정정
`mirroredEffects.ts` 365행 "자기 기술로 자기 스탯을 내렸든(공격측)…" 주석을 새 규칙으로 바꾼다(Showdown `target.isAlly(source)`). `abilities.json`의 오기·승기 설명은 "상대에게 능력치를 떨어뜨리는 공격을 받으면" 류인지 구현 때 확인(아니면 문구 정정을 같은 PR에).

## 4. 영향·예측
- 해시: 랜덤 빌드에서 오기·승기 보유자가 **자기 반동 기술**(엄청난힘·용성군·오버히트·인파이트 등)을 쓰는 판 + 다중 하락·명중회피·미끈미끈·문어굳히기·시럽봄을 만나는 판에서 바뀐다. 샘플 슬롯: 승기 엠페르트 3·오기 대도각참 1 — 자기 하락 기술 없음, 미끈미끈(히스이미끄래곤 1)과의 조합은 있음. 빈도는 구현 직전에 일회용 스크립트로 잰다(출처별로 센다).
- AI: 평가기는 `boostsStatOnOwnStatDrop`을 읽는지 구현 때 grep(`ai/` 하위)로 확인 — 읽으면 같은 규칙으로 맞춘다.
