## 1. 소스 동작 요약

```ts
unburden: {
  onAfterUseItem(item, pokemon) { if (pokemon !== this.effectState.target) return; pokemon.addVolatile('unburden'); },
  onTakeItem(item, pokemon) { pokemon.addVolatile('unburden'); },
  onEnd(pokemon) { pokemon.removeVolatile('unburden'); },
  condition: { onModifySpe(spe, pokemon) { if (!pokemon.item && !pokemon.ignoringAbility()) return this.chainModify(2); } },
}
```

- 켜짐: `eatItem`·`useItem`의 `AfterUseItem`(열매·소모 도구·레드카드·풍선·던지기), `takeItem`의 `TakeItem`(떨구기·도둑질·탐내다·트릭/바꿔치기·벌레먹기·쪼아대기·불사르기·부식가스).
- ×2 조건: **지금 도구 없음(`!pokemon.item`) + 특성 무시 상태 아님.** 매직룸·서투름은 `item`을 지우지 않으므로 ×2 유지.
- 꺼짐: 특성 `End`(교체 `switchIn` 120행이 복사 131행보다 먼저 → 바톤터치로 넘어가지 않음, `setAbility` 전부, `skillSwap`, 위액 `onStart`).
- `setItem`(도구를 받는 쪽)은 곡예와 무관. 되찾아도 다시 켜지지 않는다(`onStart` 없음).
- 곡예 활성화 자체를 알리는 프로토콜 메시지는 소스에 없다.

### 2-1. 트릭 맞교환(양쪽 모두 도구 보유) — 결과 동일 확인

소스는 `takeItem`으로 일단 볼라틸을 달고(새 도구가 있어 ×1), 엔진은 전후 비교가 "있다 → 있다"라 켜지 않는다. 이후 그 도구를 잃는 경로는 엔진에서도 모두 켜지므로(소모 = `consumeItem`, 비소모 = 행동 안 전후 비교) **결과는 같다.** 별도 처리 불필요.

### 2-2. Q2 근거 보강

Showdown에는 곡예 활성화 문구가 아예 없다. 기존 로그 줄은 엔진 고유 안내이므로, 턴 종료·행동 뒤 소모에서 새 줄을 만들지 않아도 소스와 어긋나지 않는다.

## 3. 보완·확인

### 3-1. ⚠️ 남의 열매를 먹는 경로 — 확인 요청

- 벌레먹기·쪼아대기: 먹는 쪽은 `singleEvent('Eat')`·`runEvent('EatItem')`만 부르고 **`AfterUseItem`이 없다** → 먹는 쪽 곡예는 켜지지 않는다. 열매를 잃는 쪽(대상)만 `takeItem`으로 켜진다.
- 던지기(열매): 맞은 쪽은 `Eat`만 부른다 → 맞은 쪽 곡예 켜지지 않음. 던진 쪽은 `AfterUseItem`으로 켜짐.
- **위험:** 엔진이 이 "먹는 효과"를 `consumeItem(먹는 쪽)`으로 처리하고 있다면, 3-2 이후 **먹는 쪽 플래그가 켜진다.** 먹는 쪽이 도구가 없던 곡예 보유자면 ×2가 잘못 생긴다(현행에는 없던 오류).
- 조치: `consumeItem` 호출 24곳 중 "자기 도구가 아닌 것을 먹는" 호출이 있는지 구현 전에 확인한다. 있으면 그 호출은 `consumeItem`을 쓰지 않거나, 플래그를 켜지 않는 인자를 둔다. 시험 16·17 추가(§4).

### 3-2. 같은 특성으로 바뀌는 경우 — 알면서 두는 차이

- 소스는 `setAbility`·`skillSwap`에서 **새 특성과 무관하게** 이전 특성 `End`를 부른다. 9세대 스킬스왑은 같은 특성끼리도 성공한다(`gen <= 5`만 실패). 즉 곡예 ↔ 곡예 스킬스왑이면 양쪽 모두 해제된다.
- 설계서는 "새 특성이 다르면" 해제한다 → 이 경우만 다르다.
- 판단: 곡예 보유자끼리 대면 + 스킬스왑 사용이 필요해 빈도가 사실상 0이다. 반대로 무조건 해제로 바꾸면, 엔진에 "같은 특성 재대입"(예: 폼 처리 중 갱신)이 있을 때 오히려 틀릴 위험이 있다. **설계서 조건 유지**를 권고하고 §7에 한 줄 기록한다.

### 3-3. 메가진화 시험(11번) 도달성

나무킹의 메가스톤은 빼앗기지 않으므로 메가진화 시점에 곡예 플래그가 켜져 있을 수 없다. 시험은 상태를 직접 대입해 헬퍼 동작만 확인하는 것으로 충분하다(실전 경로 시험 불필요).

### 3-4. 도구를 되받는 경로 보충(시험표)

설계서 §4의 "도구를 받음"에 **리사이클·수확·줍기**류도 같은 규칙(×1)이다. 엔진이 구현한 것만 시험 3에 표본으로 넣는다(선택).
