## 1. 포인트 1 — 면제 79종 (`[실행]` 515종 전수)

### 1-1. 분류 집계 (설계서 §2 표와 같은 값)
`normal 349 · self 61 · all 18 · allAdjacentFoes 23 · allAdjacent 16 · any 16 · allySide 8 · randomNormal 6 · adjacentAlly 4 · scripted 4 · allies 2 · adjacentAllyOrSelf 2 · allyTeam 1 · self+mustpressure 1(봉인) · foeSide+mustpressure 3 · foeSide 1(끈적끈적네트)` = 515. 부록 A 79종은 모두 챔피언스 합법이다.

### 1-2. 실측과 설계 분류 대조
- **일치 513종**: 기본 PP 감소는 515종 모두 1이고, 추가 차감이 부록 A의 0/1 분류와 같다.
- 특히 물어본 두 기술:
  - **봉인**: 대상은 `self`지만 `mustpressure`라 `pressureTargets = foes()` → **−2** 확인
  - **끈적끈적네트**: `foeSide`는 `pressureTargets = []`이고 `mustpressure`가 없어 **−1** 확인(같은 상대 진영 설치기인 압정뿌리기·스텔스록·독압정은 −2)
- **어긋남 2종**:

| 기술 | Showdown 정적 분류 | 실측 | 원인 | 처리 |
|---|---|---|---|---|
| **저주** | `normal`(→ 설계 −2) | **비고스트 사용자 −1 / 고스트 사용자 −2** | `curse.onModifyMove`가 비고스트면 `move.target = 'self'`로 바꾸고, 이 값이 `getMoveTargets`에 들어간다 | **R1** |
| 발버둥 | `randomNormal` | 추가 0(PP 슬롯 없음) | 발버둥은 PP를 쓰지 않는다 | 엔진에 없음 — 무관 |

### 1-3. R1(수정 요청) — 저주는 사용자 타입 규칙으로
- 비고스트 저주(잠만보 등)는 흔한 기술이다. 고정 데이터로 면제하면 고스트 저주가, 면제하지 않으면 비고스트 저주가 틀린다.
- **권고**: 저주에는 `pressureExempt`를 붙이지 않고, `payMovePp`의 프레셔 조건에 "저주이고 사용자가 고스트 타입이 아니면 면제"를 더한다. 타입 판정은 **엔진의 저주 효과 분기(고스트/비고스트)가 쓰는 판정과 같은 함수**를 써서 두 곳이 어긋나지 않게 한다. Showdown은 `ModifyMove` 시점의 `hasType('Ghost')`이므로 변환자재·리베로로 타입이 바뀌는 순서는 엔진의 저주 효과 판정 순서를 그대로 따른다.
- 시험 추가: 비고스트 저주 −1 / 고스트 저주 −2.

## 2. 포인트 2 — 데이터 방식 vs 규칙 함수

**데이터 방식(`pressureExempt`)을 승인한다.** 판단 근거:
1. 결정 기준이 Showdown의 **기술별 `target` 값**이라 본질이 데이터다. 엔진에는 이 값에 대응하는 필드가 없고, 효과 필드(`statChanges[].target`·`setsScreen`·`protectEffect` …)로 거꾸로 추정하면 끈적끈적네트(상대 진영인데 면제)·봉인(자기 대상인데 비면제)·치유소원·꼬리자르기·배턴터치·날따름 같은 예외를 규칙에 하나하나 넣어야 한다. 이 경우 누락이 생겨도 조용히 −2로 남는다(설계서 §3-1의 지적이 맞다).
2. 데이터는 이번 검수의 515종 전수 실측과 1:1로 대조할 수 있다. 시험 10이 그 대조를 고정한다.
3. 예외는 **저주 하나**만 규칙으로 둔다(R1). 사용자 타입에 따라 대상이 바뀌는 다른 합법 기술은 없다. `onModifyMove`로 `target`을 바꾸는 나머지 2건(와이드포스 `expandingforce`·테라클러스터 `terastarstorm`의 `allAdjacentFoes` 전환)은 상대 대상끼리의 전환이라 결과가 같다.

## 5. 추가 확인

### R2(확인 요청) — 틀깨기는 프레셔를 무시하지 않는다
- `[실행]` 틀깨기 철구룡(박치기) vs 프레셔 → **−2**, 테라볼트도 −2, 틀깨기 칼춤 −1. 프레셔는 `flags: {}`(`breakable` 없음)라 특성 무시의 대상이 아니다.
- 설계서 §5는 "틀깨기·위액은 기존 `c.defenderAbility` 판정 그대로"라고 했다. **`c.defenderAbility`가 공격자의 틀깨기를 반영해 null을 돌려주는 구조라면 현행 엔진은 틀깨기 공격자의 프레셔 차감을 빠뜨린다.** 구현 착수 때 `c.defenderAbility`의 출처를 확인해 주기 바란다. 틀깨기를 반영하는 값이면 프레셔 판정에는 틀깨기를 반영하지 않는 유효 특성(위액 억제만 반영)을 쓴다. 시험 추가: 틀깨기 공격자 박치기 −2.

### R3(확정) — 연속 사용 예외 `[실행]`
설계서 §3-2가 "구현 때 대조"로 남긴 항목을 실측했다. 턴별 PP 감소(프레셔 / 대조):

| 기술 | 프레셔 | 대조 |
|---|---|---|
| 역린(난동) 3턴 | 2, 0, 0 | 1, 0, 0 |
| 솔라빔(차지) 2턴 | 2, 0 | 1, 0 |
| 구르기 3턴 | 2, 0, 0 | 1, 0, 0 |
| 파괴광선 + 반동 턴 | 2, 0 | 1, 0 |
| 소란 3턴 | 2, 0, 0 | 1, 0, 0 |
| 풀죽음으로 행동 불능 | 0 | — |

→ 첫 턴에만 −2이고, 이어 쓰는 턴·차지 2턴째·반동 턴·행동 불능에는 프레셔를 포함해 차감이 없다. 설계서의 "기존 예외 유지"와 같다. 시험 9에 구르기·소란을 더하면 된다(엔진에 해당 기술이 있으면).

### 문서 정합 — AI PP 예측
E8 검수 §13-2는 fix-50 범위에 "AI PP 예측"을 넣었고, 설계서 §3-2는 "AI·평가기 사용 `grep` 0건 → 변경 없음"이라고 적었다. 결론이 "변경 없음"이면 §13-2 쪽에 그렇게 정리해 두는 것으로 충분하다. 다만 AI가 상대나 자신의 PP를 **기술 PP 소모 함수로 예측하는 경로**가 있다면(프레셔 블록을 직접 읽지 않아도 `payMovePp`를 거친다면) 자동으로 따라오는지 한 번 확인해 두는 편이 좋다.
