## 2. E3-01 스피드 정수 절삭 — 결정필요(권고: 따라간다)

### 2-1. 소스

```ts
// sim/pokemon.ts getStat
stat = boost >= 0 ? Math.floor(stat * boostTable[boost]) : Math.floor(stat / boostTable[-boost]);
stat = this.battle.runEvent('ModifySpe', this, null, null, stat);   // 체인 → modify 1회
if (statName === 'spe' && stat > 10000 && !this.battle.format.battle?.trunc) stat = 10000;
// data/conditions.ts par (champions 재정의는 onBeforeMove 1/8뿐, onModifySpe는 기본 그대로)
onModifySpePriority: -101,
onModifySpe(spe, pokemon) { spe = this.finalModify(spe); if (!pokemon.hasAbility('quickfeet')) spe = Math.floor(spe * 50 / 100); return spe; }
// champions getActionSpeed: getStat('spe') → 트릭룸이면 -speed (trunc 없음)
```

문서 §2의 단계(랭크 `floor` → 체인 `modify` → 마비 `floor` → 상한)와 같다. 대상 보정(스카프 1.5·철구 0.5·순풍·날씨 특성·서핑테일·곡예 2·속보 1.5)은 모두 정확한 분율이라 **체인 순서와 무관**하다. 차이는 오직 절삭 위치에서 생긴다.

### 2-2. `[계산]` 독립 재현

스크립트를 그대로 돌리지 않고 Python(정확 유리수 + 정수 파이프라인)으로 다시 짜서 같은 입력(스탯 60~200 × 보정 10종 × 랭크 −2~+2, 49,702,500쌍)을 비교했다.

| 항목 | 문서 | 재현 |
|---|---|---|
| Showdown 동속 / 엔진 동속 | 0.319% / 0.145% | 0.319% / 0.145% |
| 판정이 다른 쌍 | 0.23% | 0.229% |
| SD 동속·엔진 확정 / 엔진 동속·SD 확정 / 뒤집힘 | 0.196 / 0.023 / 0.010% | 0.196 / 0.023 / 0.010% |
| 보정·랭크 없음 | 19,881쌍 100% 일치 | 일치 |
| 검은철구 60·61 → 30·30 / 랭크 −1 60·61 → 40·40 | ✅ | ✅ |
| 뒤집힘 예: 60(−1) vs 스카프+마비 107(−2) → 엔진 40.000 < 40.125, SD 40 > 39 | ✅ | ✅ |
| 엔진 동속·SD 확정 예: "60(−1) vs **스카프** 80(−1)" | — | ❌ 스카프만이면 엔진 80.0·SD 79다. 문서 수치(엔진 40.0 = 40.0, SD 40 vs 39)는 **스카프+마비 80(−1)** 의 값이다 → 문구 정정 |

### 2-3. 결정 의견

- **따라간다에 동의.** E2-01(명중) 결정과 같은 근거다(본가·Showdown 모두 정수 파이프라인, 사용자 지침 "정확성 > 기존 구현").
- 구현 메모
  1. 마비는 **체인의 일부가 아니라 체인 뒤 `floor(×50/100)`** 이다. `chain4096`에 0.5로 넣으면 `modify` 반올림(0.5는 내림)과 `floor`가 홀수에서 같아 보이지만, 체인 안에 다른 배율이 있을 때 값이 달라진다(예: 스카프+마비 107(−2) → 체인 안 39 / 체인 뒤 39는 같으나, 순풍+마비처럼 `modify` 결과가 홀수가 되는 경우를 시험으로 고정). 단계를 문서 그대로 분리한다.
  2. 속보는 마비 `floor`를 건너뛰고 체인에 1.5를 넣는다(문서 E3-10과 같음).
  3. 상한 10000은 도달 불가(§E3-06)라 넣지 않아도 결과는 같다. 넣는다면 한 줄.
  4. 이 함수 하나를 순서 판정·AI(`ai/speed.ts`)·매치업(`matchupEvaluator.ts`)·E3-15 위력 계산이 함께 쓴다(별도 구현을 두지 않는다 — 문서 §5 옛 메모와 같음).
  5. 노력치 역산(`speedInference.ts`)과의 연결은 문서 §2 "확인 필요"대로 설계서에서 호출 그래프로 확인한다. 역산이 "보정 반영 스피드 → 실능"을 거꾸로 푼다면 정수 절삭 때문에 **역산 결과가 범위**가 될 수 있다(소수 곱이면 한 점).

### 3-2. b: 켜는 경로

- 소스: `eatItem`(`pokemon.ts:1827`)·`useItem`(`:1867`)이 `AfterUseItem`을 부르고, `takeItem`이 `TakeItem`을 부른다 → 곡예 `onAfterUseItem`·`onTakeItem`이 상태를 단다. 레드카드는 `target.useItem(source)`(방어측), 탈출버튼은 `target.useItem()`(방어측) — 문서와 같다.
- **표 보정**

| 경로 | 검수 |
|---|---|
| 턴 종료 HP 임계 열매 | ✅ 실재 경로. 시나리오는 **독 타입이 아닌 곡예 포켓몬**으로 쓴다(포푸니크는 독 타입이라 독 피해 예시가 성립하지 않는다 — 루차불·레파르다스 등) |
| 미래예지 + 레드카드 | ✅ Showdown도 발동한다(`futuremove` 조건은 탈출버튼 champions 재정의에만 있고 레드카드에는 없음). 단 `source.isActive`가 필요 — 미래예지 사용자가 교체됐으면 레드카드가 소모되지 않는다. 엔진 `finishTurn.ts:324`가 이 조건을 갖는지 함께 본다 |

### 3-3. c: 특성이 바뀌면 효과가 사라진다

- 소스: 곡예 `onEnd`가 상태를 지우고, **다시 특성을 얻어도 상태를 새로 달지 않는다**(곡예에는 `onStart`가 없다). 즉 "한 번 잃으면 그 교체 동안 ×1 고정"이다.
- **위액은 `[실행]` 없이 확정**: `gastroacid` 조건 `onStart`가 `singleEvent('End', 특성)`을 호출한다 → 곡예 상태 제거. 문서 §2 괄호의 "특성 억제류는 `[실행]`으로 확인"은 소스로 닫는다. 화학변화가스는 출전 보유자 0이라 해당 없음.
- 출전 가능 경로(곡예 쪽이 맞는 경우): 스킬스왑 45 · 고민씨 11 · 동료만들기 10 · 심플빔 3 · 위액 6종 습득, 특성 **미라**(데스니칸 — 접촉 시 교체)·**떠도는영혼**(데스버드). 루차불(접촉기 위주)과 미라는 실전에서 만날 수 있는 조합이다. 메가진화로 특성이 바뀌는 나무킹은 메가스톤을 잃을 수 없어 해당 없음.
- **조치안 의견**: 문서 ①(`특성이 곡예 && 플래그 && 도구 없음`)은 특성을 **되찾는 경우**(스킬스왑 두 번 등) Showdown과 달라진다(Showdown ×1, ① ×2). 권고는 **특성 변경 지점에서 플래그를 지우는 방식**이다. 지점이 7곳(`hitResolution.ts:660·672`, `mirroredEffects.ts` 5곳, 변신 2곳)이므로, `effectiveAbilityId`를 바꾸는 헬퍼 하나를 만들고 그 안에서 지우는 형태가 Showdown의 `End` 이벤트와 구조가 같다. 헬퍼를 만들기 어렵다면 ①을 쓰고 "되찾는 경우 차이"를 설계서에 알려진 차이로 적는다(빈도 매우 낮음). 두 방식 모두 ①의 `도구 없음` 판정(a)은 그대로 필요하다.
- "곡예를 새로 받은 쪽은 ×1"은 소스와 같다(새 보유자에게 상태가 없음).

## 4. E3-15 자이로볼·일렉트릭볼 — 수정필요

- 소스 확인: `gyroball` `floor(25 × 대상.getStat('spe') / 사용자.getStat('spe')) + 1`(무한대면 1, 상한 150), `electroball` `floor(사용자 / 대상)` → `[40,60,80,120,150][min(비, 4)]`(무한대면 0). `getStat('spe')`는 랭크 + `ModifySpe` 전부(순풍·날씨 특성·곡예·서핑테일·스카프·철구·마비)를 포함하고 트릭룸은 포함하지 않는다 → 문서와 같다. champions 재정의 없음.
- 조치안(§2-3의 정수 함수 하나를 공유) 동의. **E3-01 뒤**에 하는 것이 자연스럽다 — E3-01 전에 하면 위력 입력이 소수 스피드가 되어 한 번 더 바뀐다.
- 예상값(시험용): 스피드 100 vs 50에서 자이로볼(느린 쪽 사용) 51 → 순풍 받은 상대면 101, 일렉트릭볼(빠른 쪽 사용) 80 → 순풍이면 150.

## 5. 그 밖

### 5-1. E3-08 손톱·퀵드로 — 소스로 확정
- `FractionalPriority`는 `runEvent(…, 0)`(`battle-queue.ts:249`)로 시작한다. 퀵드로(`onFractionalPriorityPriority: -1`)가 손톱(`-2`)보다 먼저 돈다 → 퀵드로 30% 성공 시 전달값 0.1이라 손톱은 굴리지 않고, 실패 시 손톱 20%. 합계 0.3 + 0.7×0.2 = **44%**. 문서 서술과 같다. `[실행]` 3번은 생략해도 된다.

### 5-2. E3-12 재정렬 — 순서 영향 없음, 참고 1건
- 문서 판정(싱글은 남는 기술이 하나라 재정렬 무영향)에 동의한다.
- 참고: gen8+ 재정렬은 스피드뿐 아니라 **우선도도 다시 계산**하고(`getActionSpeed(action)` → `ModifyPriority` 재실행) 그 값을 `action.move.priority`에 넣는다. 이 값은 사이코필드·여왕의위엄·테일아머의 "선제기 차단"(`move.priority > 0.1`) 판정에 쓰인다. 예: 풀피 파이어로(질풍날개)가 더 빠른 선제기에 먼저 맞으면 Showdown에서는 자기 차례에 우선도가 0으로 다시 계산되어 차단되지 않는다. 엔진은 턴 시작 값이라면 차단한다. 순서(E3)가 아니라 차단 판정 문제이고 빈도가 매우 낮아 **E8(특성) 2차 후보로 넘긴다**(출전: 파이어로·여왕형 특성 마더캔디·테일아머 키키링크·사이코메이커 에스퍼제비 2종).

### 5-3. E3-13 메가진화 로그 순서 — 보충
- Showdown 메가진화 행동의 `speed`도 `getActionSpeed()`(champions: 트릭룸이면 부호 반전)라 **트릭룸에서는 느린 쪽이 먼저 진화**한다. 8.4 로그 후보에 이 한 줄을 함께 적는다.

### 5-4. E3-14 시간벌기 + 손톱 — 소스로 확정
- 시간벌기 `onFractionalPriority: -0.1`은 상수라 우선도 0(기본)으로 **먼저** 실행되어 전달값 −0.1, 이어서 손톱이 `priority <= 0`을 만족해 굴리고 성공하면 0.1로 **덮어쓴다**. 문서 서술과 같다. 시간벌기 출전 보유자는 깜까미 1종(메가진화하면 매직미러로 바뀜). 개선권장 유지.

```python
# E3-01 독립 재현 (python3 -I, numpy) — 49,702,500쌍, 정확 유리수로 엔진 측 계산
import numpy as np; from fractions import Fraction as F
BT=[1,1.5,2,2.5,3,3.5,4]
def chain(ms):
    p=4096
    for m in ms: p=(p*int(m*4096)+2048)>>12
    return p
modify=lambda v,n:(int(v*n)+2047)//4096
def sd(s,g,ms,par):
    s=int(s*BT[g]) if g>=0 else int(s/BT[-g])
    if ms: s=modify(s,chain(ms))
    if par: s=s*50//100
    return min(s,10000)
def eng(s,g,ms,par):
    m=F(1)
    for x in ms: m*=F(x).limit_denominator(4)
    return s*m*(F(1,2) if par else 1)*(F(2+g,2) if g>=0 else F(2,2-g))
MS=[([],0),([1.5],0),([0.5],0),([2],0),([2],0),([],1),([1.5,2],0),([1.5],1),([2],1),([1.5],0)]
K=[(s,g,i) for s in range(60,201) for g in(-2,-1,0,1,2) for i in range(10)]
A=np.array([sd(s,g,*MS[i]) for s,g,i in K]); E=np.array([int(eng(s,g,*MS[i])*840) for s,g,i in K])
r1=np.sign(A[:,None]-A[None,:]); r2=np.sign(E[:,None]-E[None,:])
print((r1==0).mean(),(r2==0).mean(),(r1!=r2).mean(),((r1==0)&(r2!=0)).mean(),((r2==0)&(r1!=0)).mean(),((r1*r2)<0).mean())
# → 0.00319 0.00145 0.00229 0.00196 0.00023 0.00010
```
