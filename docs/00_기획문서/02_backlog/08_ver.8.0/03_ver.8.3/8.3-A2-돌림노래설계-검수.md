## 2. 불일치

### 2-1. 2배는 "포켓몬"이 아니라 "뒤에 대기 중인 행동"에 붙는다
- [소스] `round.onTry`가 큐에서 `action.move.id === 'round'`인 행동을 찾아 `queue.prioritizeAction(action, move)` → `action.sourceEffect = round`. `basePowerCallback`은 `move.sourceEffect === 'round'`만 본다. 앞선 포켓몬이 그 뒤 필드에 남아 있는지는 보지 않는다.
- [실행] 선공 쥬피썬더 돌림노래 → 후공 잠만보(레드카드) 피격, 쥬피썬더 강제 교체(럭키 등장) → 잠만보 돌림노래:
  ```
  |-enditem|p2a: Snorlax|Red Card|[of] p1a: Jolteon
  |drag|p1a: Chansey|...
  |move|p2a: Snorlax|Round|p1a: Chansey|[from] move: Round
  |debug|BP doubled
  ```
- 설계 영향: `c.defender.echoTurn` + `switching.ts`의 초기화로는 이 경우 2배가 아니게 된다. 싱글에서 같은 턴 "선행 사용 후 교체"가 생기는 경로는 레드카드(champions에 존재)뿐이다.
- 수정안(코드도 줄어듦): 마커를 포켓몬이 아닌 **배틀 상태 한 칸**(`state.echoTurn?: number`, 이번 턴에 돌림노래가 `onTry` 지점에 도달한 턴 번호)으로 둔다. 싱글에서는 한 포켓몬이 한 턴에 자기 행동으로 돌림노래를 두 번 쓸 수 없으므로 "이번 턴에 이미 기록됨 = 상대가 먼저 씀"이다. `switching.ts` 초기화와 포켓몬 필드는 필요 없어진다.
- R1-h 기대값 교체: "선행 상대가 레드카드로 강제 교체된 뒤 내 돌림노래 → **2배**".

### 2-2. 뒤쪽이 호출 기술로 나온 돌림노래면 2배가 아니다(앞쪽은 호출이어도 유발함)
- [소스] 큐 검색 조건이 `action.move.id === 'round'` → 이번 턴 **선택한 행동이 돌림노래**여야 당겨진다. 잠꼬대·따라하기 등으로 나온 돌림노래는 `sourceEffect`가 그 기술이라 2배 아님. 반면 앞쪽은 호출된 돌림노래여도 `onTry`가 실행되므로 상대의 돌림노래를 2배로 만든다.
- [실행]
  - 선공 돌림노래 → 후공 잠듦+잠꼬대→돌림노래: `[from] move: Sleep Talk`, `BP doubled` 없음(1배)
  - 선공 잠듦+잠꼬대→돌림노래 → 후공 돌림노래: `[from] move: Round`, `BP doubled`(2배)
- 설계 영향: `c.defender.echoTurn === turnNumber`만 보면 첫 번째 경우도 2배가 된다. 잠꼬대·따라하기(둘 다 champions에 존재)를 엔진이 지원한다면 2배 조건에 "이번 기술이 호출된 기술이 아님(이번 턴 선택한 기술 그대로)"을 더한다. 지원하지 않으면 해당 없음(설계서에 한 줄 명시).

## 4. 참고(범위 밖, 확인만 권장)
- round 플래그는 `sound`·`bypasssub`(대타 무시). poke-builder 데이터·엔진이 소리 기술의 대타 무시를 처리하는지 확인. 지옥찌르기의 소리 기술 봉인은 `BeforeMove` 단계 → 행동 불능과 같이 "사용 안 함"(설계의 `checkActionBlockers` 위치와 맞으면 됨).
