## 2. 불일치의 원인 (소스)

### 2-1. 탈출버튼이 유턴에 발동하는 이유 (V5 / R3)
- [소스] champions `ejectbutton.onAfterMoveSecondary` (`data/mods/champions/items.ts:262`): 다른 활성에 대해 **`pokemon.switchFlag === true`**인지 검사한다.
- 그런데 유턴·볼트체인지는 `source.switchFlag = move.id`, 즉 **문자열 `'uturn'`**을 넣는다(`sim/battle-actions.ts:1366~1368`). 문자열은 `=== true`가 아니므로 이 검사에 걸리지 않는다. 이 조건이 막는 것은 다른 탈출 효과가 `switchFlag = true`를 세운 경우뿐이다.
- 그래서 탈출버튼은 **발동한다.** 기본 9세대 규칙(`data/items.ts:1692`)에는 발동 직후 `source.switchFlag = false`(공격자의 유턴 취소)가 있지만, **champions는 이 줄이 없다.** 결과적으로 양쪽 모두 교체한다.
- [실행] 아래 표 S3. 기본 규칙(`gen9customgame`)에서는 탈출버튼이 발동하고 유턴 사용자는 교체하지 않았다 — A4-b 검수 때 쓴 포맷으로 보면 "유턴이 취소되는" 것처럼 보일 수 있으니 주의.
- 같은 이유로 A4-b 검수 §2-1의 인용(조건 목록)은 문장 자체는 정확하지만, **"유턴 사용자가 대기 중이면 막힌다"는 해석은 틀렸다.** 설계서 §1·§0 C1의 "탈출버튼 도구 유지"도 현재 엔진이 틀린 동작임을 뜻한다(우연히 같은 결과가 아니라 **둘 다 Showdown과 다르다**).

### 2-2. 위기회피가 유턴을 취소하지 않는 이유 (V2 / R2)
- [소스] 기본 규칙의 `emergencyexit.onEmergencyExit`(`data/abilities.ts:1250`)에는 모든 활성의 `switchFlag`를 지우는 반복문이 있어 유턴을 취소한다. 그러나 **champions는 이 특성을 다시 정의하며 그 반복문을 뺐다**(`data/mods/champions/abilities.ts:28`, 웨이크아웃 `:103`도 동일). 즉 `target.switchFlag = true`만 세운다.
- [실행] S4: 위기회피가 발동했는데 유턴 사용자(`p1`)와 홀더(`p2`) **둘 다 교체 요청**이 열린다. 같은 상황을 기본 규칙에서 돌리면 `p1`의 요청이 없다(설계서 R2의 가정은 기본 규칙에 해당).
- 위기회피는 유턴이 정해둔 플래그 위에서 홀더 플래그만 추가하므로, 홀더의 교체 가능 여부(`canSwitch`)·`forceSwitchFlag`·`switchFlag`만 본다. 공격자 편 상태는 보지 않는다.

### 2-3. 레드카드가 유턴을 취소하는 이유 (V1 / R1)
- [소스] 레드카드는 `source.forceSwitchFlag = true`만 세우고 `switchFlag`는 건드리지 않는다. 유턴의 `switchFlag = 'uturn'`은 그대로 남지만, 행동이 끝난 뒤 phazing(`sim/battle.ts:2866~2872`)에서 `dragIn`이 공격자를 무작위 예비로 **바꿔 버린다.** 새로 나온 포켓몬은 `switchFlag = false`이므로 교체 요청이 만들어지지 않는다.
- 결론이 설계서 R1과 같으나 **메커니즘은 "플래그 취소"가 아니라 "플래그를 가진 포켓몬이 사라짐"**이다. 구현 시 `ctx.didSwitch` 가드(§3 4번)로 같은 효과를 내는 것은 문제없다.

### 2-4. 호출 순서 (참고)
유턴 명중 시 한 행동 안에서 일어나는 일(소스 + 실행 일치):
1. 데미지 → 유턴 사용자에 `switchFlag = 'uturn'`
2. `AfterMoveSecondary` — **탈출버튼(우선도 2) → 레드카드(우선도 0)**. 홀더는 도구를 하나만 가지므로 둘이 겹치지는 않는다.
3. `EmergencyExit` (위기회피)
4. 행동 종료 후 phazing — 레드카드 `drag` 실행
5. 교체 요청 — `switchFlag`가 서 있는 쪽 전부(양쪽 동시 가능)

## 3. 새로 생기는 상황: 동시 교체

탈출버튼·위기회피 × 유턴에서 **양쪽 모두 교체 요청**이 열린다.

- [실행] S3(탈출버튼)·S4(위기회피): `p1.forceSwitch=[true]`, `p2.forceSwitch=[true]`로 요청이 동시에 열린다.
- **교체 실행 순서는 교체해 나가는 포켓몬의 스피드가 빠른 쪽이 먼저**다. 유턴 사용자가 빠르면 유턴 쪽이 먼저(`|switch|p1a ... [from] U-turn`), 홀더가 빠르면 홀더 쪽이 먼저 나온다(S3b·S4b). 동속은 확인하지 않았다(필요하면 추가 실측).
- 설계 영향:
  - 설계서 C5 "방어측 pause를 이미 지원한다"는 **한 번에 한 쪽만 멈추는 흐름**이다. 이번 규칙에서는 공격자와 방어측이 한 행동에서 둘 다 대기해야 하므로, `pendingPivot`이 두 슬롯을 갖거나 연속 pause 두 번으로 처리해야 한다. 연속 pause로 가면 **선택은 어느 순서든 상관없지만 실행(로그) 순서는 위 스피드 규칙**을 따라야 한다.
  - 한 쪽의 선택이 상대의 선택을 보고 바뀔 수 있는지(정보 노출)는 UI 결정이다. Showdown은 동시 선택이다.
  - 교체 후 등장 특성(위협 등)의 발동 순서는 이 스피드 순서의 영향을 받는다.

## 5. 수정 권장 — 엔진(§3)

설계서의 "새 순서"에서 바뀌는 부분:

| 단계 | 설계서 | 수정 |
|---|---|---|
| 1 `applyRedCard` | 공격자가 끌려 나가면 `didSwitch=true` | 변경 없음 |
| 3 `emergencyExitPause` | **발동하면 유턴 자체 교체를 평가하지 않음(R2)** | 취소하지 않는다. 유턴 pause와 **함께** 대기 |
| 4 `selfSwitchPause` | `didSwitch`면 건너뜀 | 변경 없음 (레드카드 취소 R1) |
| 5 `ejectButtonPause` | 유턴 pause가 반환되면 도달하지 않음 | **도달해야 한다.** 유턴이 pause여도 탈출버튼은 평가되어 방어측도 대기 |

- 현재 엔진은 `selfSwitchPause`가 값을 돌려주면 즉시 반환하므로(C1), 위기회피·탈출버튼이 **아예 평가되지 않는다.** 이것이 지금 Showdown과 어긋나는 부분이고, 수정 후에는 "유턴 pause를 만든 뒤에도 방어측 효과를 평가해 pause를 하나 더 붙이는" 구조가 필요하다.
- 함수를 위기회피/탈출버튼으로 쪼개는 것은 그대로 유효하다. 다만 호출 순서의 핵심 제약이 바뀐다: **"레드카드만 유턴을 취소한다."**

| S8 | 유턴 → 레드카드, 공격자 편 예비 없음 | 레드카드 미발동, 도구 유지, 교체 없음 |
| S9 | 불릿펀치(일반 공격) → 레드카드 | `-enditem` → `drag` (A4-b 회귀) |
| S10 | 유턴 → 탈출버튼, **홀더 편** 예비 없음 | 미발동, 도구 유지. p1만 교체 요청 |
| S11 | 유턴 → 탈출버튼 + 위기회피 홀더 | `-enditem Eject Button`만 출력, 위기회피 로그 없음. p1·p2 둘 다 교체 요청 |
| 비교 | 기본 규칙(`gen9customgame`)에서 S3·S4 | S3: 탈출버튼 발동, **p1 교체 요청 없음**. S4: 위기회피 발동, **p1 교체 요청 없음** |

## 8. 문서 정합성(사소)
- §0 C1 마지막 문장 "탈출버튼이 유턴에 맞은 턴에는 무시된다"와 §1 첫 항목은 "이것은 우연히 같다"가 아니라 **현재 엔진이 Showdown과 다른 동작**이라고 고쳐야 한다.
- §10 "취소된 교체에 대한 로그 안내는 만들지 않는다(V2로 확인)"는 R1의 레드카드에만 해당한다. S1에서 `drag` 뒤에 유턴 교체 줄이 없다. 위기회피에서는 취소가 없으므로 이 항목은 R1 설명으로 옮긴다.
- §8 해시: 위기회피·탈출버튼 홀더 상대 유턴이 이제 **교체가 한 번 더 일어나는** 판이 되므로 영향이 레드카드만의 경우보다 넓다(해시가 변할 확률이 올라감). 단계 ① 분할만은 그대로 출력 불변이어야 한다.
- A4-b 검수 §1 "탈출버튼 … 다른 활성의 `switchFlag`가 true면 발동하지 않음" 해석은 유턴 상황에서는 틀렸다. 이 문서 §2-1로 정정한다.
