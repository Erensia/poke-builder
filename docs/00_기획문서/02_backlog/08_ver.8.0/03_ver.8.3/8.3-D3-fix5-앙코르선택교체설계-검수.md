## 2. Showdown 동작

### 2-1. Q1 champions 재정의와 기본 9세대의 차이

```ts
// 기본 9세대 data/moves.ts encore.condition
onStart(target) { ...; if (!this.queue.willMove(target)) this.effectState.duration!++; }
onOverrideAction(pokemon, target, move) { if (move.id !== this.effectState.move) return this.effectState.move; }
// runMove: OverrideAction은 PP 차감 전에 실행된다. 바뀐 기술에도 원래 선택의 priority를 덮어쓴다
```

| 차이 | 기본 9세대 | champions | 싱글 결과 |
|---|---|---|---|
| 교체 시점 | 실행 직전(`runMove`) | 걸리는 순간(`changeAction`) | 같다(사이에 다른 행동이 없다) |
| 우선도 | 원래 선택의 우선도 유지 | `insertChoice`로 다시 정렬 | 같다(남은 행동이 대상 하나뿐) |
| 멘탈허브 | `onUpdate`로 앙코르가 바로 치료됨 → 덮어쓰기 없음 | `!hasItem('mentalherb')`로 직접 제외 | 같다(선택 기술 그대로, 앙코르 해제) |

- 설계서 해석(§2 "결과가 같다", §4 "순서 유지")은 맞다. 엔진은 멘탈허브를 걸리는 순간에 치료·소모하므로 Showdown과 같은 결과가 나온다.

### 2-2. Q2 교체 제외 대상 — 결과가 같은 이유

```ts
// sim/battle-queue.ts
willMove(pokemon) { if (pokemon.fainted) return null;
  for (const action of this.list) if (action.choice === 'move' && action.pokemon === pokemon) return action; }
```

| 상대 상태 | Showdown 동작 | 엔진(설계서) | 결과 |
|---|---|---|---|
| 교체 선택 | `willMove`가 null → `duration++`. 교체는 기술보다 먼저 처리되므로 앙코르는 사실상 새로 나온 포켓몬이 맞는다(직전 기술이 없으면 실패) | `didSwitch` 건너뜀 | 같다 |
| 충전 2턴째·난동 | 잠긴 기술 = `lastMove`(준비 턴에도 `moveUsed` 실행) → `action.moveid === move.id` → 교체 없음 | `forcedLockedAction` 건너뜀 | 같다 |
| **반동** | 행동 기술 id는 `'recharge'`이고 `lastMove`는 파괴광선이라 서로 다르다 → **교체가 실행된다** → 그러나 `runMove`의 `BeforeMove`에서 `mustrecharge`(우선 11)가 막는다("반동으로 움직일 수 없다") | 건너뜀 | **같다**(어느 쪽이든 반동으로 움직이지 못함, PP 소모 없음) |
| 쓰러짐 | `willMove`가 null | `isFainted` 건너뜀 | 같다 |

- 설계서 Q2의 근거 "`willMove` 기준"은 반동의 경우에는 정확하지 않다. 설계서 §4 주석을 "반동은 Showdown도 교체하지만 `mustrecharge`가 행동을 막아 결과가 같다"로 보정한다.

### 2-3. Q4 PP

- champions: 교체된 행동은 앙코르 기술로 `runMove`된다 → 잠금이 없으면 `deductPP(앙코르 기술)`. 원래 고른 기술의 PP는 그대로다.
- 기본 9세대: `OverrideAction` → `baseMove`가 바뀐 뒤 `deductPP(baseMove)`. 결과는 같다.
- 엔진의 기존 동작("고른 기술 PP 소모 + 행동 실패")은 두 버전 모두와 다르다. 이번 수정으로 Showdown과 같아진다.

### 2-4. ⚠️ 지속 턴 — Showdown은 턴 단위로 차감한다

```ts
// sim/battle.ts (Residual 이벤트)
if (eventid === 'Residual' && handler.end && handler.state?.duration) { handler.state.duration--; ... }
// encore: duration 3. 상대가 이미 행동한 뒤 걸리면 duration++(=4)
```
- Showdown은 **턴이 끝날 때마다** 1을 차감한다. 상대가 그 턴에 행동했는지는 따지지 않는다.
- 엔진은 설계서 §3·§4에 따르면 **상대가 행동할 때마다** 1을 차감한다.
- 두 방식은 상대가 매 턴 정상적으로 행동하면 같다(설계서 §4의 설명). 그러나 **상대가 행동하지 못한 턴**에서는 다르다.

| 상대가 그 턴에 | Showdown | 엔진(행동 단위로 가정) |
|---|---|---|
| 마비로 못 움직임 / 풀죽음 / 잠듦 / 혼란 자해 | 1 차감 | 차감 위치가 이 판정보다 뒤라면 차감 안 함 → 앙코르가 길어짐 |
| 반동 턴(앙코르가 반동 턴에 걸린 경우) | 1 차감 | 반동이 "행동"으로 집계되는지에 따라 다름 |

- 이것은 **이번 PR 전부터 있던 차이**다. 이번 범위 밖으로 두고 **E-영역 후보**로 올린다. 엔진의 차감 위치(`preHitEffects.ts:386` 주변이 마비·풀죽음·잠듦 판정보다 앞인지 뒤인지)를 먼저 확인한다.
- 설계서 §6 "지속 턴" 사례는 **정상 행동 경로**(매 턴 앙코르 기술 실행)로만 기대값을 정한다. 행동하지 못한 턴이 끼는 경우는 시험으로 고정하지 않는다.

## 3. 엔진 설계 확인

### 3-1. `overrideEncoredPending` 구현 확인

- `ctx.order.indexOf(opp) < ctx.actionIdx`: `resolveAction` 직후에 `actionIdx`가 **현재 행동자의 인덱스인지, 이미 1을 더한 값인지**에 따라 경계가 달라진다. 1을 더한 값이라면 `<=`가 아니라 `<`가 맞다. 반대의 경우 상대가 이미 행동했는데 다시 교체 대상이 될 수 있다. §6 "후공" 시험이 이 경계를 잡으므로 반드시 둔다.
- 매직미러·매직코트로 앙코르가 반사되면 앙코르는 사용자 자신(이미 행동함)에게 걸린다. 함수는 `opp`만 보므로 영향이 없다. Showdown도 `willMove`가 null이므로 `duration++`만 한다. 결과가 같다.
- `preHitEffects.ts:386`의 안전망을 남기는 판단에 동의한다. Showdown에서는 `onDisableMove`가 선택 단계에서 막는 경로에 해당한다.

### 3-2. Q5 `failencore` — champions에서 해당하는 기술

- champions에서 사용할 수 있는 `failencore` 기술: **흉내쟁이·앙코르·잠꼬대·변신**(4개).
- 직전 기술이 이 4개 중 하나이거나 PP가 0이면 Showdown에서는 앙코르가 실패한다.
- 잠꼬대(습득 257종)는 실전 빈도가 높다. E-영역 후보로 올릴 때 우선순위를 높게 둔다.
