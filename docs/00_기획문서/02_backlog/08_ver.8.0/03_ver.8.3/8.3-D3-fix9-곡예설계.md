## 3. 고칠 것
**3-1. 판정(a)** — `computeTurnOrderSpeed`: `(fighter.unburdenActive && !fighter.currentItemId ? 2 : 1)`. 도구 유무는 `effectiveHeldItem`(서투름·매직룸이면 없는 취급)이 아니라 **`currentItemId` 그대로** 본다(Showdown `!pokemon.item` — 매직룸·서투름이어도 도구는 "있다"). 플래그 자체는 지우지 않는다(Showdown의 "다시 잃으면 즉시 복귀"와 같다).
**3-2. 켜기(b)** — 소모의 단일 입구인 `consumeItem`에서 켠다: 소모 대상이 곡예 특성(`abilityOf(fighter)?.doublesSpeedOnItemLoss`)이고 아직 꺼져 있으면 `unburdenActive = true`. 이러면 앞으로 소모 경로가 늘어도 빠지지 않는다(경로별 보완 안 함). 기존 두 곳은 다음처럼 바뀐다.
  - `applyKnockoutAbilities`: 비소모 제거(떨구기·빼앗김·트릭·부식가스)를 위한 전후 비교는 **그대로 둔다.** 다만 로그(`unburden*AbilityName`)를 "이번 행동에서 새로 켜졌는가"로 내려면 행동 시작 때 플래그도 저장해야 한다(소모는 `consumeItem`이 먼저 켜므로 `!unburdenActive` 가드가 로그를 삼킨다). → `ActionCtx`·`PreHitCtx`에 `attackerUnburdenBeforeAction`·`defenderUnburdenBeforeAction`(boolean)을 `…ItemIdBeforeAction` 옆에 추가(`preHitEffects.ts:44~45·151~152`, `resolveAction.ts:46~47·989`, 전달 객체 `preHitEffects.ts:1267`). 로그 조건: `!플래그_전 && 플래그_후`(둘 다 곡예 보유일 때).
  - `triggerTerrainSeeds`: `const had = fighter.unburdenActive` → `consumeItem` → `ability.doublesSpeedOnItemLoss && !had`이면 같은 문구. 중복 코드는 이것으로 사라진다.
  - **턴 종료·행동 뒤·등장 중 소모로 켜질 때는 새 로그 줄을 만들지 않는다**(기본안, Q2). 효과는 카드 태그와 순서에 나타난다. 새 필드를 `TurnResult`에 넣으면 `regress` 해시와 저장된 영상 호환이 따라 바뀌므로(7.4·8.3 B2 교훈) 필요하면 따로 설계한다.
**3-3. 끄기(c)** — `state.ts`에 헬퍼 `setEffectiveAbility(fighter, abilityId: string | null)`을 두고, 그 안에서 `effectiveAbilityId`를 쓴 뒤 **이전 특성이 곡예(`doublesSpeedOnItemLoss`)였고 새 특성이 다르면 `unburdenActive = undefined`**. 새 특성이 곡예여도 켜지 않는다(Showdown: 곡예에는 `onStart`가 없고 상태는 도구를 잃는 사건에서만 달린다). 위 §2의 쓰는 곳을 모두 이 헬퍼로 바꾼다(트레이스류는 곡예 보유자가 아니라 사실상 무동작이지만 일관성을 위해 포함). AI 시뮬레이션 6줄(`ai/statusMoveEffects.ts`)도 포함 — 복제 상태에 낡은 플래그가 남지 않게 한다. `abilitySuppressed`(위액)는 헬퍼가 `null`로 쓸 때 곡예가 해제되므로 별도 처리가 필요 없다.
**3-4. 화면** — `BattleFighterCard.tsx:134` 태그 조건을 `fighter.unburdenActive && !fighter.currentItemId`로(실제 ×2인 동안만 표시). 매치업 화면은 사용자 토글이라 변경 없음.
**3-5. 하지 않는 것** — 플래그 이름·구조 변경, 매치업 토글, AI의 곡예 평가(AI가 곡예 상태를 읽는 곳은 `computeTurnOrderSpeed` 한 곳이라 자동 반영), 하양허브 등장 중 경로(§7).

## 7. 위험·알면서 두는 것·확인 필요
- **하양허브 등장 중 경로**: `shouldTriggerWhiteHerb`의 호출처가 행동 안(`mirroredEffects.ts:379·384`)뿐이라 위협 등으로 등장 중에 랭크가 내려가도 하양허브가 발동하지 않을 수 있다. 곡예 이전에 **하양허브 자체의 E9 도구 배선 항목**이다. 시험에서는 현황만 확인하고(실패해도 이 PR에서 고치지 않음) 결과를 백로그에 적는다.

- 해시 변동 범위: 곡예 보유 빌드가 턴 종료 열매·레드카드·도구 되받기를 만나는 판. `regress`의 무작위 빌드에서 바뀔 가능성이 있다(예: B2·A4 때 "샘플 0개여도 해시가 바뀜"). 바뀌면 `update-baseline.sh`로 갱신하고 원인을 a·b·c로 분리한 표를 보고한다.
