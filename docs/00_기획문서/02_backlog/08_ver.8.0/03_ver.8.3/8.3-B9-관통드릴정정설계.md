## 3. 설계

### 3-1. 엔진
- **`hitResolution.ts`**:
  - `:251~253`의 `contactIgnoresDefenseBoost`와 `:259~262`의 `defenderStagesForDamage` 분기를 삭제하고, `:288`의 `defenderStages`는 `baseDefenderStages`를 그대로 받게 한다(변수명 정리).
  - **`contactDefenseStat`(`:249`)는 지우지 않는다**(C3 — `:293` 날씨 방어 배율이 쓴다). 이름을 `defenseStat`로 바꾸고 주석에서 "관통드릴" 언급을 없앤다.
  - `:306~312`의 "최소 데미지 보장" 블록을 삭제한다.
  - `:314~315`: `if (c.unseenFistPiercing) hitDamage = Math.floor(hitDamage * 0.25);` → 원데미지가 양수이면 `Math.max(1, Math.floor(hitDamage * 0.25))`(Q5, V8 결과에 따라). 주석을 "보이지않는주먹·관통드릴"로.
- **`preHitEffects.ts`**: 코드 변경 없음(관통드릴이 `contactBypassesProtectAtQuarterDamage`를 가지면 `:622`가 그대로 동작). 주석 `:617~621`·`:1231`만 "보이지않는주먹·관통드릴"로. **V3가 "관통드릴은 접촉 반응 없음"이면** `:1232` 조건에 `&& !(c.unseenFistPiercing && c.attackerAbility?.…)` 한 줄을 더한다(Q4 필드).
- **`ability.ts`**: 옛 필드(`contactIgnoresDefenseBoostAndGuaranteesMinDamageFraction`, `:474~478`)와 주석 삭제, `:794~`의 보이지않는주먹 주석에 "관통드릴도 사용"을 덧붙인다.
- `damagingMoveLanded`·벽 파괴·설치물 제거(B7·B8)는 코드 변경 없이 `blockedByProtect = false` 덕에 자동으로 맞아진다(시험으로 고정).

### 3-2. 데이터
`abilities.json`(LF, 키 순서·들여쓰기 유지): 관통드릴 레코드에서 `contactIgnoresDefenseBoostAndGuaranteesMinDamageFraction: 0.25`를 **지우고** `contactBypassesProtectAtQuarterDamage: true`를 넣는다. 설명문은 Q8(기본안: 그대로). `validate:data`·`move-effect-audit`는 특성 필드를 대조하지 않으므로 영향 없음(구현 때 실행으로 확인). `docs/데이터변경이력.md`에 항목 추가(같은 PR).

### 3-3. 로그·화면
변경 없음(Q7). 방어한 상대에게 몰드류-메가의 접촉기가 들어가면 "방어로 막혔다" 줄 대신 일반 데미지 줄이 나온다(보이지않는주먹과 같음).
