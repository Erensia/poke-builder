## 2. 데이터

### 2-1. 불새 정의와 파워풀허브

```ts
// data/moves.ts
skyattack: {
  accuracy: 90, basePower: 140, pp: 5, critRatio: 2,
  flags: { charge: 1, protect: 1, mirror: 1, distance: 1, metronome: 1, nosleeptalk: 1, failinstruct: 1 },
  onTryMove(attacker, defender, move) {
    if (attacker.removeVolatile(move.id)) return;           // 2턴째: 발동
    this.add('-prepare', attacker, move.name);
    if (!this.runEvent('ChargeMove', attacker, defender, move)) return;  // 파워풀허브만 이 이벤트를 쓴다
    attacker.addVolatile('twoturnmove', defender);
    return null;                                            // 1턴째: 준비만
  },
  secondary: { chance: 30, volatileStatus: 'flinch' },
}
// data/mods/champions/items.ts:706
powerherb: { inherit: true, isNonstandard: "Past" },
```

- 불새 정의는 champions에서 재정의되지 않는다. 기본 정의를 그대로 쓴다.
- 날씨 생략(일렉트로빔·솔라빔), 능력치 상승(메테오빔·일렉트로빔), 준비 중 숨기(공중날기류) 같은 처리가 **없다**. 따라서 `chargeSkipWeather`·`chargeHideType`·`chargeStatChanges`를 넣지 않는 판단은 맞다.
- `onChargeMove` 핸들러는 기본 데이터에서 파워풀허브 하나뿐이다. 파워풀허브는 champions에서 **목록에서 빠진 것이 아니라 `Past`로 지정**되어 있다. 원인과 결과: 덤프가 `Past` 도구를 걸러 냈기 때문에 "없다"로 보인 것이다. 사용할 수 없다는 결론은 같으므로 설계서 §2의 문구만 "`Past`(사용 불가)"로 바꾼다.

### 2-2. 충전·반동 기술 집합

| 구분 | Showdown 기본 전체 | champions 사용 가능 | 비고 |
|---|---|---|---|
| `flags.charge` | 17개 | **10개**: bounce·dig·dive·electroshot·fly·meteorbeam·phantomforce·**skyattack**·solarbeam·solarblade | Past 7개: freezeshock·geomancy·iceburn·razorwind·shadowforce·skullbash·skydrop |
| `flags.recharge` | 10개 | **6개**: blastburn·frenzyplant·gigaimpact·hydrocannon·hyperbeam·rockwrecker | `meteorassault`는 Past인데 champions `learnsets.ts`에 습득 종 1개가 남아 있다 |

- 설계서 §1과 §5 데이터 시험의 "충전 10개"는 정확하다.
- "반동 7개는 엔진과 일치"는 엔진에 `meteorassault`가 들어 있다는 뜻으로 보인다. 이 기술은 champions에서 `Past`다. 이번 범위에는 영향이 없으므로 E0 참고 사항으로만 남긴다.

## 3. 규칙 대조(설계서 §3)

### 3-1. PP

```ts
// sim/battle-actions.ts runMove
const lockedMove = pokemon.getLockedMove();
if (!lockedMove) { if (!pokemon.deductPP(baseMove, ...)) ... }   // 1턴째: 잠금이 없으므로 PP 1 소모
// 2턴째: twoturnmove.onLockMove → 'skyattack' → 잠금 상태이므로 PP를 깎지 않는다
pokemon.moveUsed(move, targetLoc);   // 1턴째에도 lastMove = 불새
```
- 설계서와 같다. 덧붙여 **준비 턴에도 `lastMove`가 불새로 기록된다.** 이 점은 fix5의 앙코르 판정에 영향을 준다(fix5 검수 §3-3).

### 3-2. Q2 방어

- `useMoveInner`의 `TryMove`(battle-actions.ts:550)는 명중 단계인 `trySpreadMoveHit`(:582)보다 **먼저** 실행된다. 1턴째에는 `onTryMove`가 `null`을 반환하므로 방어 판정 단계까지 가지 않는다. 그래서 준비 턴의 상대 방어는 아무 영향이 없다.
- 2턴째에는 `onTryMove`가 `twoturnmove`를 지운 뒤 일반 명중 단계로 들어간다. 이때 방어에 막히면 **충전은 그대로 소모**되고, 다음 턴에는 기술을 자유롭게 고를 수 있다.
- → 설계서 판단과 같다. §5 방어 시험에 "막힌 뒤 다음 턴은 자유 선택(잠금 해제)" 확인을 넣을 것을 권고한다.

### 3-3. ❌ Q3 흉내쟁이 — Showdown은 충전 기술을 막지 않는다

```ts
copycat: { onHit(pokemon) {
  let move = this.lastMove;
  if (move.flags['failcopycat'] || move.isZ || move.isMax) return false;   // charge는 검사하지 않는다
  this.actions.useMove(move.id, pokemon);
}}
// sleeptalk과 비교: if (move.flags['nosleeptalk'] || move.flags['charge'] || ...) → 잠꼬대만 charge를 막는다
```
- 불새를 포함한 충전 기술 10개 중 `failcopycat`을 가진 것은 없다. 그래서 Showdown에서는 흉내쟁이가 불새를 부르면 **1턴째 준비가 시작되고, 다음 턴에 불새가 발동한다.**
- 흉내쟁이는 champions에서 사용할 수 있다(습득 26종). 따라서 엔진의 "흉내쟁이에서 `chargeTurn` 기술 제외"(`preHitEffects.ts:1351`)는 실전에서 나올 수 있는 **Showdown과의 차이**다.
- 설계서 판단대로 이번 PR 범위 밖으로 두고, **E-영역 후보로 확정**한다.
- 참고로 지시(instruct)는 불새의 `failinstruct` 때문에 실패하는 것이 맞다(champions 습득 1종).

### 3-4. ➕ 발동 턴에 행동하지 못하는 경우

```ts
// data/conditions.ts twoturnmove
onMoveAborted(pokemon) { pokemon.removeVolatile('twoturnmove'); }
```
- 2턴째에 `BeforeMove`가 실패하면 충전이 해제된다. 실패하는 경우는 풀죽음, 마비로 못 움직임, 잠듦(하품), 혼란 자해 등이다. 다음 턴에는 기술을 자유롭게 고를 수 있고 불새 PP는 1회분만 소모된 상태다.
- 이것은 기존 충전 기술과 같은 경로다. 다만 불새는 이번에 처음 2턴 기술이 되므로, 시험 사례를 1건 두면 안전망이 된다.
  - 예: 2턴째에 상대가 더 빠른 풀죽음 기술로 먼저 맞힌다 → 불새가 나가지 않고 준비가 해제된다 → 다음 턴은 자유 선택.

## 4. 시험 보완(설계서 §5에 추가 권고)

| 대상 | 사례 | 기대(Showdown) |
|---|---|---|
| 방어 | 2턴째에 방어로 막힘 → 다음 턴 | 잠금 해제, 다른 기술 선택 가능. 불새 PP는 1회분만 소모 |
| 발동 중단 | 2턴째에 풀죽음(또는 마비로 못 움직임) | 불새 미발동, 준비 해제, 다음 턴 자유 선택 |
| (기록만) 흉내쟁이 | 상대가 직전에 불새를 쓴 뒤 흉내쟁이 | Showdown: 불새 준비 시작. 엔진: 제외 → **E-영역 후보**. 이번 PR에서는 현재 동작을 고정하지 않는다 |
