# 8.3 시나리오 사양서 검수 결과 (Showdown 대조)

- 대상: `8.3-시나리오사양서.md` (2026-11-10 작성, R6-c 2026-11-11 개정본)
- 기준: smogon/pokemon-showdown `965a535`, mod `champions`, 싱글(`gen9championsbssregmc`) — **poke-builder는 더블 미지원**
- 검수일: 2026-11-12. 상충 항목은 `sim-check.js` 실측으로 확인함

## 1. 기대값 수정 필수 (Showdown과 상충)

| # | 현재 기대 | 수정 기대 | 근거 |
|---|---|---|---|
| R7-d | 버티기를 그 턴 마지막에 사용 → 기술 **성공** | 그 턴 마지막에 사용하면 **실패**(방어·판별·킹실드와 같은 조건). 실패하면 stall 카운터 증가 없음 | `data/moves.ts` endure `onPrepareHit: !!this.queue.willAct() && runEvent('StallMove')`. 실측: 상대 Protect(+4)가 먼저 행동한 뒤 Endure를 쓰면 `-fail` |
| R8-a | 폴터가이스트(상대 도구 없음) 실패 → 폼 불변(실드) | **블레이드폼으로 폼체인지한 뒤** 실패. 폼 변경 이벤트·로그 발생 | `data/abilities.ts` stancechange는 `onModifyMove`에서 폼을 바꾸고, poltergeist의 도구 확인(`onTry`)은 그 뒤에 실행됨. 실측 로그: `-formechange Aegislash-Blade` → `move Poltergeist` → `-fail` |

원인: 기술 처리 단계의 순서 때문이다. 순서는 `BeforeMove`(행동 불가 판정) → `ModifyMove`(배틀스위치) → `onTry`/`onPrepareHit`(성공 판정)이다. 그래서 "기술을 냈지만 실패"한 경우에도 배틀스위치는 이미 적용된 상태가 된다. 행동 자체가 불가능한 경우(R8-b)는 ModifyMove까지 가지 않으므로 폼이 그대로다.

## 2. 표현·범위 수정

| # | 수정안 | 근거 |
|---|---|---|
| R1-d | "싱글 한정: 우선도 0, 순서 불변"으로 명시. 더블에서는 뒤 사용자가 앞당겨지지만 미지원이므로 구현 불필요 | `round.onTry` → `queue.prioritizeAction` |
| R7-c | "자신은 항상 성공" 대신 다음으로 수정: "연속 사용 확률 판정은 없음. **단, 그 턴 마지막 행동이면 실패.** 성공하면 stall 카운터를 ×3 누적하므로 다음 방어 성공률은 1/3, 연속하면 1/9…" | quickguard/wideguard `onTry: !!this.queue.willAct()`, `onHitSide: source.addVolatile('stall')`, conditions `stall.onRestart: counter *= 3` |
| R6-b | 로그 "희망사항이 이루어졌지만 회복할 HP가 없었다"는 **poke-builder의 UI 결정**으로 명시. Showdown은 HP가 가득 차 있으면 로그를 남기지 않음(실측으로 확인) | wish `onEnd`: `if (damage)`일 때만 `-heal` |
| R6-d | "설치된 순서대로" 대신 "**미래예지 → 희망사항 고정 순서**"로 수정. 싱글에서는 지연 턴 차이(2턴/1턴) 때문에 결과가 같지만, 근거는 우선순위 값이다 | futuremove `onResidualOrder: 3`, wish `onResidualOrder: 4` |

## 4. 정합 확인 (수정 불필요)

- R1-a·b·c: `basePowerCallback`에서 앞의 돌림노래가 당긴 행동만 2배이고, 연속 사용 보너스는 없음
- R2-a·b·c: 회복 열매(오랭·자뭉·피자 계열·베리주스·의문열매)는 모두 TryHeal 검사를 거침. 먹다남은음식·조개껍질방울·흡수 기술은 `battle.heal()` 단계에서 차단됨. 사이코노이즈를 재사용하면 `onRestart`에서 갱신하지 않고 대미지만 들어감
- R3-a·b·c·d: 적중 시점에 `trySpreadMoveHit`을 실행함. `bypasssub`가 없으므로 대타가 맞음
- R6-a·c: 날씨(필드 1) → 미래예지 3 → 희망사항 4 → 먹다남은음식 5.4 → 씨뿌리기 8 → 독 9 → 화상 10
- R7-a·b: 길동무는 stall 카운터를 건드리지 않음
- R8-b·c·d
- R4·R5: 변경 범위가 아님
- R2-d·R7-e(AI): Showdown에 대응하는 로직이 없어 검수 범위 밖
