## 1. 문제
상태이상을 **걸 수 없을 때**의 처리가 엔진 여러 곳에서 Showdown과 다르다. 같은 "상태이상 면역 판정"이라 한 묶음으로 본다.

|---|---|---|---|

## 2. 원인 (코드 읽기)
- **E8-18**: `src/data/abilities.json` 정화의소금 `immuneToStatuses: ["burn","freeze","paralysis","poison","sleep"]` — `isImmuneToStatus`는 `includes(status)`만 보므로 `"badly-poisoned"`가 없으면 통과(면역 특성만 `["poison","badly-poisoned"]`). 특성 획득 시 치료(`finishTurn.ts` 630행)도 같은 목록이라 맹독은 안 낫는다.
- **E8-24**: `mirroredEffects.ts` `inflictStatuses`가 `isImmuneToStatus`(특성·타입)·`isStatusBlockedByField`(필드)·신비의부적·쾌청 얼음에서 **`continue`로 조용히 넘어간다.** 화면은 `statusInflictFailed`("이미 걸려 있음") 한 줄뿐(`ActionEffectLines.tsx` 192행). 데미지 기술의 부가 상태이상은 본가도 조용하므로 **상태이상 전용 변화기(확정 효과, `chance` 미지정)** 만 사유를 낸다. 엔진에는 같은 형태의 선례가 있다 — `volatileBlockedByAbility`(마이페이스 혼란 등, "X의 마이페이스! 혼란에 걸리지 않는다!").
- **E8-19**: 하품 졸음 부여(`mirroredEffects.ts` ~804행)는 "이미 상태이상/졸음"과 일렉트릭필드(접지)만 막는다. 잠듦 면역 특성은 2턴 뒤 `finishTurn.ts` 500행(`isImmuneToStatus("sleep", …)`)에서 무산시킨다.
- **E8-20**: 잠자기(`mirroredEffects.ts` ~1173행, `restSleep`)는 무조건 `currentHp = maxHp` + `inflictRestSleep()`이고 어떤 실패 판정도 없다. 수면 면역은 턴 끝 치료(`finishTurn.ts` 630행)에서만 나타난다. AI는 `opponentMoveModel.ts` `isPointlessNow` 124행이 "풀피 + 상태이상 있음"이면 잠자기를 의미 있다고 본다(Showdown은 풀피면 상태이상과 무관하게 실패).

## 3. 변경
### 3-1. E8-18 — 데이터 (`abilities.json`)
정화의소금 `immuneToStatuses`에 `"badly-poisoned"`를 더한다. **전수 점검**: 면역 특성 9종의 목록을 대조했다 — 독 계열은 면역(`poison`,`badly-poisoned`)과 정화의소금뿐이라 이 한 건이다. `docs/데이터변경이력.md`에 한 줄, `validate:data`.

### 3-2. 공용 판정 — 상태이상이 걸리지 않는 사유 (`src/lib/battle/state.ts` 근처, 신규 함수 2개)
```ts
/** 특성(+풀 타입 플라워베일)이 이 상태이상을 막는가 — 소란피기(`sleepBlockedByUproar`)는 제외한 순수 특성 면역 */
export function abilityBlocksStatus(fighter, ability, status): boolean
/** 이 상태이상이 걸리지 않는 사유(없으면 undefined) — 특성(이름)·그 밖(타입·필드·신비의부적·쾌청 얼음·소란피기) */
export type StatusBlock = { kind: "ability"; abilityName: string } | { kind: "other" };
export function statusBlockReason(state, side, fighter, ability, status, opts: { attackerBypassesPoisonTypeImmunity?: boolean }): StatusBlock | undefined
```
- `statusBlockReason`은 `inflictStatuses`의 기존 `continue` 조건 네 개를 **같은 순서·같은 의미로** 한 곳에 모은 것이다(리팩토링이 아니라 사유를 돌려주기 위한 이동): ① `isImmuneToStatus`(특성 → `ability`, 타입 → `other`) ② `isStatusBlockedByField` ③ 신비의부적 ④ 쾌청 + 얼음. 엔진 `inflictStatuses`·잠자기·AI가 같은 함수를 쓴다. `statusImmunitiesOf`(특성+플라워베일+소란)는 그대로 둔다.

### 3-3. E8-24 — 면역 로그 (엔진 `mirroredEffects.ts`·`resolveAction.ts`·`types/battle.ts`·`ActionEffectLines.tsx`)
- `inflictStatuses`: 상태이상 **전용 변화기**(`category === "status"`이고 `effect.chance === undefined`)가 `statusBlockReason`으로 막히면 `c.statusBlocked = { status, reason }`을 채운다(첫 상태이상 하나만 — `break` 규칙 동일). 데미지 기술의 부가 효과·확률 효과는 조용히 둔다. `ActionLogEntry.statusBlocked?: { status: StatusCondition; kind: "ability" | "other"; abilityName?: string; self?: boolean }` 추가.
- **기존 문구 재사용**(결정 2026-11-28, fix-45와 같은 방침 — 새 문구·새 UI 없음):
  - `kind: "ability"` → `{방어측}의 {특성명}! {상태 라벨}에 걸리지 않는다!` — `volatileBlockedByAbility` 줄(마이페이스 등)과 같은 형태. 열교환: "드닐레이브의 열교환! 화상에 걸리지 않는다!".
  - `kind: "other"`(타입·필드·신비의부적·쾌청 얼음·소란피기) → 기존 줄 `{방어측}에게는 효과가 없는 것 같다…`(`ohkoImmune`과 같은 문구). Showdown은 신비의부적·필드에서 별도 문구를 내지만 이번에는 **한 문구로 합친다**(§5 알면서 둔 것).
- 상태 라벨은 `STATUS_LABELS`(`battleLogLabels.ts`)를 쓴다. 잠듦·독·맹독 라벨이 "…에 걸리지 않는다" 문장에 어색하면 구현 때 문장 틀(`…되지 않는다!`)을 한 번에 맞춘다(시험은 필드 존재만 고정하고 문구는 화면에서 확인).
- 반사(매직미러) 경로: 반사된 줄은 `reflectedView`가 방어측=사용자인 사본으로 그리므로 별도 처리 없이 이름이 맞는다(fix-45에서 확인한 방식).
- `moveFailure.ts`: 이 필드가 서면 "기술이 실패한 행동"으로 본다(방음·황금몸·가루 면역과 같은 목록에 추가). 구현 때 `statusInflictFailed`가 그 목록에서 어떻게 다뤄지는지 먼저 확인하고 같은 방식으로 넣는다.

### 3-4. E8-19 — 하품을 잠듦 면역 특성이 즉시 막는다 (`mirroredEffects.ts` 졸음 부여부)
- 졸음 부여 직전, 대상이 `abilityBlocksStatus(target, ability, "sleep")`(불면·스위트베일·의기양양·정화의소금·풀 타입 플라워베일)이면 졸음을 걸지 않는다. 로그는 기존 `volatileBlockedByAbility { abilityName, volatile: "drowsy", self: false }`를 채운다(→ "X의 불면! 졸음에 걸리지 않는다!").
- **소란피기·타입·필드(일렉트릭필드 외)·신비의부적은 지금처럼 2턴 뒤 트리거에서 막는다**(Showdown도 하품 자체는 특성·일렉트릭필드만 즉시 막고 나머지는 잠듦 시도 때 막힘). 일렉트릭필드(접지)는 이미 즉시 막는다(8.3 fix-31).
- AI(`statusMoveEffects.ts` 528행 하품 실패 판정)는 이미 "잠듦 면역이면 실패"로 보므로 변경 없음. `opponentMoveModel.ts` 143행의 빠른 판정(`isPointlessNow`의 `yawn` — 상태이상·졸음만 봄)은 특성을 추가로 보게 한다(한 줄, `abilityBlocksStatus`).

### 3-5. E8-20 — 잠자기가 실패하는 조건 (`mirroredEffects.ts` 잠자기부)
잠자기를 쓰는 쪽(자기 자신)이 아래 중 하나면 **회복도 수면도 없이 실패**한다(Showdown `Rest.onTry` + `setStatus` 실패):
1. **HP가 가득**(`currentHp === maxHp`) — 상태이상이 있어도 실패.
2. **수면 면역 특성**(`abilityBlocksStatus(self, ability, "sleep")`) — `statusBlocked { kind: "ability", self: true }`("X의 불면! 잠듦에 걸리지 않는다!").
3. **일렉트릭필드 + 접지**, **소란피기 중**(`sleepBlockedByUproar`) — `statusInflictFailed`("그러나 실패했다!").
- 실패 때 **기존 상태이상은 치료하지 않는다**(`curedStatus` 없음). 리샘열매 등 열매 상호작용은 성공 경로에서만 그대로.
- 이미 잠든 채로는 행동하지 못하므로 "이미 수면" 판정은 추가하지 않는다(엔진은 수면 중 행동 불가가 먼저 막는다).
- AI: `opponentMoveModel.ts` `isPointlessNow`의 잠자기 예외(`!(move.restSleep && user.status.condition)`)를 **풀피면 상태이상과 무관하게 무의미**로 바꾸고, `evaluator.ts` 1135행의 잠자기 평가는 위 1~3 조건이면 후보에서 제외한다(공용 판정 `restFails(state, key)`를 `statusMoveEffects.ts`에 두고 엔진·AI가 같이 쓴다).

## 5. 알면서 둔 것
- **신비의부적·필드·소란피기·쾌청 얼음의 면역 문구를 "효과가 없는 것 같다…" 한 줄로 합친다.** Showdown은 `-activate … Safeguard`·터레인별 문구를 따로 낸다. 새 UI·새 문구를 만들지 않는 방침이라 구분 문구는 후속(필요 시).
- **데미지 기술의 부가 상태이상**(화염방사의 화상 확률 등)은 막혀도 조용하다(본가도 동일).
- **`moveFailure` 확장**(상태이상 면역 → 실패 행동 판정)이 분노의 걸음 같은 "직전 기술 실패" 효과에 닿는지는 구현 때 확인한다.
- E8-18②(정화의소금 고스트 반감의 ±1 반올림)는 ② 배율 묶음에서 12종 일괄 판정(이번에 건드리지 않는다).
- E8-21·22는 fix-47.
