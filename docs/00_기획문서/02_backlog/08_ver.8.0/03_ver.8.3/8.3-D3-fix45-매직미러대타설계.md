## 1. 문제 — 두 방향이 모두 어긋난다
Showdown의 순서는 **매직미러 반사(`onTryHit`, 우선도 2) → 반사된 기술이 원래 사용자에게 적용되며 사용자의 대타가 막음(`substitute.onTryPrimaryHit`)** 이다. 엔진은 대타 판정을 반사 **앞**에서 한 번만, 그것도 **반사하는 쪽(방어측)** 기준으로만 한다.

**`[실행]`** Hippowdon(사용자, p1) → Espeon(매직미러, p2). 대타는 `addVolatile('substitute')`로 세웠다.

- **E8-13**(A1~A3): 반사로 사용자에게 되돌아온 `bypasssub` 없는 효과가 사용자의 대타를 통과한다.
- **E8-14**(C1): 반사하는 쪽이 대타 뒤에 있으면 엔진은 그 대타가 기술을 막은 것으로 보고 **반사하지 않는다.** Showdown은 반사가 대타보다 먼저라 그대로 되돌린다. 매직미러 보유자 5종(에브이·브리무음·메가 픽시·메가 깜까미·메가 앱솔) × 대타를 쓰는 파티에서 도달 가능하다.
- 도달 가능성: 샘플에 매직미러 1파티, 대타 사용 파티 다수. `regress` 해시가 바뀐다.

## 2. 원인 (코드 읽기)
`src/lib/battle/preHitEffects.ts` `checkDefenderImmunities`:
```ts
c.blockedBySubstitute = c.defender.substituteHp !== undefined && !소리 && !(저주·고스트) && !c.attackerAbility?.bypassesScreensAndSubstitute;  // 624행
c.opponentEffectsBlocked = 황금몸 || c.blockedBySubstitute || 방어 || 가루면역 || 방음 || 방탄;                                          // 668행
c.bouncedByMagicMirror   = !c.opponentEffectsBlocked && 매직미러 && isMagicBounceReflectable(move);                                  // 681행
```
- **E8-14**: `bouncedByMagicMirror`가 `opponentEffectsBlocked`에 들어 있는 **`blockedBySubstitute`(반사하는 쪽 대타)** 로 막힌다.
- **E8-13**: `mirroredEffects.ts` 1875행 반사 구간 시작에서 공격·방어 바인딩을 맞바꾼 뒤, `c.opponentEffectsBlocked`는 **입력값(= 반사하는 쪽 기준 판정, 반사 성립 조건상 항상 false)** 그대로다. 맞바뀐 뒤의 방어측(= 원래 사용자)의 대타를 다시 보지 않아, 이후 `!c.opponentEffectsBlocked`로 게이트된 상태이상·랭크 하락·뒤집어엎기 등이 전부 통과한다.
- 로그: `blockedBySubstituteMoveName`(실패 문구)도 반사하는 쪽 판정(`c.blockedBySubstitute`)에서만 만들어져(`resolveAction.ts` 669행) 사용자 대타가 막아도 문구가 없다.

## 3. 변경
### 3-1. 대타 판정을 공용 함수로 (`preHitEffects.ts`)
624행의 인라인 식을 함수로 뽑아 두 곳(방어측 판정, 반사 구간 시작)이 같은 규칙을 쓰게 한다.
```ts
/** 대타가 이 기술의 상대 방향 효과를 막는가 — 소리 기술·틈새포착·고스트 저주는 대타를 무시한다. */
export function substituteBlocksMove(move: Move, user: BattleFighterState, userAbility: Ability | undefined, target: BattleFighterState): boolean {
  return target.substituteHp !== undefined && !(move.classification ?? []).includes("소리") &&
    !(move.setsCurse && user.types.includes("고스트")) && !userAbility?.bypassesScreensAndSubstitute;
}
```

### 3-2. E8-14 — 반사하는 쪽 대타는 반사를 막지 않는다 (`checkDefenderImmunities`)
```ts
const blockedOtherThanSubstitute = 황금몸 || 방어 || 가루면역 || 방음 || 방탄;
c.opponentEffectsBlocked = blockedOtherThanSubstitute || c.blockedBySubstitute;
c.bouncedByMagicMirror = !blockedOtherThanSubstitute && 매직미러 && isMagicBounceReflectable(move);
if (c.bouncedByMagicMirror) { c.blockedBySubstitute = false; c.opponentEffectsBlocked = false; }   // 반사하는 쪽 대타는 이 기술을 받지 않는다(받는 쪽은 §3-3이 다시 판정)
```
- 순서 근거: Showdown은 방어류(`onTryHit` 우선도 3)가 매직미러(2)보다 먼저라 방어를 `blockedOtherThanSubstitute`에 두는 것이 맞고, 방음·황금몸·방탄은 매직미러와 한 포켓몬이 가질 수 없어 어느 쪽이든 같다(검수에서 소스 확인 요청). 대타(`onTryPrimaryHit`)는 반사보다 **뒤**다. 가루 면역은 Showdown에서 반사보다 **뒤**지만(`hitStepTryImmunity`) 챔피언스 매직미러 5종에 풀 타입이 없어 도달 불가라 그대로 둔다(§5).
- `c.blockedBySubstitute = false`: 반사하는 쪽 대타가 데미지·로그(`blockedBySubstituteMoveName`)로 새지 않게 한다. 반사 성립 시 기술은 변화기(`isMagicBounceReflectable`은 `category === "status"`)라 `hitResolution`의 데미지 경로는 이미 no-op이다.

### 3-3. E8-13 — 반사 구간에서 사용자(맞바뀐 방어측)의 대타를 판정한다 (`mirroredEffects.ts`)
반사 구간 시작, 바인딩을 맞바꾼 직후:
```ts
c.opponentEffectsBlocked = substituteBlocksMove(c.move, c.attacker, c.attackerAbility, c.defender);   // 맞바뀐 뒤 attacker = 반사하는 쪽(기술 사용자 역), defender = 원래 사용자
c.bounceBlockedBySubstitute = c.opponentEffectsBlocked;                                              // 로그용
```
- 여기서 `c.attackerAbility`는 맞바뀐 뒤 **반사하는 쪽의 특성**이라 사용자의 틈새포착이 대타를 뚫지 못한다(장면 C3).
- 이후 `!c.opponentEffectsBlocked`로 게이트된 기존 블록(랭크 하락·상태이상·행동방해·뒤집어엎기 등)이 그대로 사용자 대타를 존중한다. **게이트가 없는 블록은 그대로 통과**한다 — 스텔스록(설치기, B2)·강제 교체(울부짖기·날려버리기, B1)가 이에 해당하며 Showdown과 같다(대타 무관).
- 소리 변화기(싫은소리·금속음 등, B3)는 `substituteBlocksMove`가 소리를 제외하므로 사용자 랭크가 그대로 내려간다(일치).
- 결과값 `bounceBlockedBySubstitute`를 `collectResult`에 추가해 `resolveAction.ts` `finalizeAction`이 문구를 만든다(§3-4).

### 3-4. 로그 (`resolveAction.ts` 669행)
```ts
c.blockedBySubstituteMoveName = (c.blockedBySubstitute || c.bounceBlockedBySubstitute) && !c.hitSubstitute && isOpponentTargetingMove(c.effectiveMove) ? c.effectiveMove.name : undefined;
```
- 반사 줄은 `reflectedView`로 방어측이 사용자인 사본에서 그려지므로 문구는 "(반사한 쪽 이름)의 독가루는 실패했다!"로 나온다 — Showdown `-fail`(Espeon)과 같은 주체다.
- `isOpponentTargetingMove`가 아닌 뒤집어엎기는 **직접 쓸 때도 이 문구가 없다**(기존 한계, §5). 반사 때도 같게 둔다.
- `blockedBySubstituteMoveName`을 읽는 곳(`runTurn.ts` 410·478행, `moveFailure.ts`)은 상태이상기·랭크 변화기에서 이 값이 서면 "이 기술은 상대에게 닿지 못했다"로 본다 — 반사돼도 같은 의미라 그대로 둔다(구현 때 `moveFailure` 쓰임을 한 번 더 확인).

### 3-5. AI
`effectMoveFails`(`statusMoveEffects.ts` 346행)는 `reflectsOpponentStatusMoves && isMagicBounceReflectable`이면 **무조건 실패 취급**하고, `opponentMoveModel.ts` 99행도 같다. 매직미러에게 쓰는 변화기를 이미 "무의미"로 보므로 **AI 변경 없음**. 이 PR의 `status60`·`greedy120` 변동은 엔진 결과 변화에서만 올 수 있다(없을 가능성이 높다).

## 5. 알면서 둔 것
- **가루 면역 ↔ 반사 순서**: Showdown은 반사가 풀 타입 가루 면역보다 먼저지만, 챔피언스 매직미러 보유자 5종에 풀 타입이 없어 도달 불가. 코드는 지금 순서(가루 면역이 반사보다 먼저)를 유지한다.
- **직접 쓴 뒤집어엎기·강제 교체의 대타**: 엔진은 직접 쓸 때 뒤집어엎기가 대타에 막히는 것을 `opponentEffectsBlocked`로 이미 처리한다(결과 일치). 다만 `isOpponentTargetingMove`가 아니라 **실패 문구는 안 나온다**(UI 한계, 기록만). 날려버리기·울부짖기가 직접 쓸 때 대타를 무시하는 것은 `bypasssub`와 같아 일치.
- **반사된 기술의 PP·실패 판정(`moveFailure`)**은 현행대로 둔다.
- 매직미러 + 사용자의 방어류·황금몸 조합은 도달 불가 또는 fix-44에서 기록됨.
