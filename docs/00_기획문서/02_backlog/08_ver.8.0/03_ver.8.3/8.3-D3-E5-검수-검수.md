## 2. 항목별 검수 의견

### 2-1. E5-15 벽 깨기 — 설계서 §2-4 해석 정정 (중요)
- 설계서는 "`TryHit`이 상성 무효·명중보다 앞(`battle-actions.ts:618~630`)"이라 빗나가도 깨진다고 읽었다. 그러나 그 단계(1번 `hitStepTryHitEvent`)는 `runEvent('TryHit')`로 **대상 쪽 핸들러(방어·매직미러·흡수 특성)**만 돈다. `runEvent`는 `onEffect`가 아니면 기술 자신의 `onTryHit`을 부르지 않는다.
- 깨트리기·사이코팽·레이징불의 `onTryHit`은 **히트 루프 안** `spreadMoveHit`의 `singleEvent('TryHit', moveData…)`(champions 재정의 `scripts.ts:332`)에서 실행된다. 순서: 무적 → 대상 TryHit(방어) → **상성 무효 → 명중** → … → 히트 루프(**기술 onTryHit = 벽 제거** → 대타 → 데미지).
- 결론(실측 ① 일치): **데미지 전 제거는 맞고, 방어·상성 무효·빗나감이면 벽 유지.** B8 규칙·시험(B8-g·j) 그대로 둔다.
- 설계 보강: 벽 제거 시점은 "명중·상성·방어 판정 통과 후, **대타 판정 전**"이다. 따라서 **대타를 때려도 벽은 깨진다** — fix-25 시험에 대타 케이스를 추가한다.
- fix-25는 `[실행]` 대기가 풀렸으므로 권고 순서에서 뒤로 미룰 이유가 없다.

### 2-2. E5-16 안개제거 — 사용자 의견 검토 (Q1)
- 사용자 의견: "상대 회피율 −1, 내 편과 상대 편 필드 효과(스텔스록·신비의부적·리플렉터 등)를 모두 지움."
- 실측 ②와 소스(`defog.onHit`): **대상 편** = 벽(리플렉터·빛의장막·오로라베일)·신비의부적·흰안개·설치물 제거 / **사용자 편** = **설치물만** 제거(`removeAll` 목록) / 필드 해제 / 날씨 유지 / 대상 회피 −1(대타가 있으면 회피 하락만 막히고 제거는 진행).
- 즉 **"양쪽 설치물 제거"까지는 사용자 의견이 맞고, "내 편 리플렉터·신비의부적도 제거"는 틀리다.** 본가(6세대 이후)도 Showdown과 같다.
- 엔진 현행(양쪽 벽·신비의부적 제거, 2.3 B3)은 이 오해에서 나온 결정으로 보인다. **권고: ①(Showdown에 맞춤, fix-29)**. 최종 결정은 사용자에게 다시 받는다.
- fix-29 시험에 추가: 대상이 매직미러면 반사되어 사용자 쪽이 "대상 편"이 됨(`reflectable`), 대타가 있는 대상.

### 2-3. E5-09 회복 반올림 — 신규 수정필요 (fix-30 제안)
- Showdown: `heal(modify(maxhp, factor))`, `modify`는 `tr((tr(v×m) + 2047) / 4096)`(사사오입이 아닌 **0.5 초과 올림**). 0.667 → 2732, 0.25 → 1024.
- 최대HP 1~500 전수 대조: **쾌청(×0.667) 167개 값에서 +1**(최대HP≡1 mod 3), **비·모래·눈(×0.25) 125개 값에서 +1**(최대HP≡3 mod 4), 날씨 없음(×0.5)은 차이 0. 실측 ⑪ 일치.
- 엔진 `computeWeatherHealFraction`의 `floor(maxHp × 2/3)`·`floor(maxHp/4)`는 약 1/3·1/4 확률로 1 적게 회복한다. 광합성·달빛·아침햇살 3기술 모두 해당.
- 설계: 회복량 = `modify(maxHp, 0.667 | 0.25 | 0.5)`(엔진에 4096 modify 헬퍼가 E1에서 있으면 재사용). 시험: 쾌청 154→103, 비 155→39, 없음 155→77. 같은 `modify` 회복을 쓰는 다른 기술(E10 범위)도 같은 헬퍼를 쓰는지 E10에서 확인.

### 2-4. [계산] 3건 처리
| # | 결과 |
|---|---|
| 1. 모래 바위 특방·눈 얼음 방어 ×1.5 | `modify(x, 1.5)` = `floor(1.5x)`가 1~999 전 범위에서 **차이 0**. 단, Showdown은 이 ×1.5를 **스탯 자체에 먼저(우선도 10)** 적용하고 다른 보정(돌격조끼 등)을 체인한다 — 엔진이 다른 보정과 한 체인으로 곱하면 순서 차이가 날 수 있으니 E1 체인 순서에서 확인 |
| 2. 회복 0.667 | §2-3 — **차이 있음** → fix-30 |
| 3. 필드 ×1.3 | `trunc(1.3×4096)` = **5324**, `round` = 5325. Showdown은 `[5325, 4096]`을 직접 쓴다. 엔진 `chain4096`이 1.3을 받아 버림 변환하면 틀린다 → Claude Code가 엔진 변환 방식 1줄 확인(버림이면 fix-23과 함께 `[5325,4096]` 명시) |
