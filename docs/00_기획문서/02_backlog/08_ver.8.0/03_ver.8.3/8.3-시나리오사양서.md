# ver.8.3 시나리오 사양서 (8.2 T3)

**작성 2026-11-10 — 문서만이다. 코드는 8.3에서 쓴다**(지금 `scripts/battle-ai-scenarios/`에 넣으면 현재 동작과 충돌해 실패한다). 근거는 `8.3-규칙조사.md`의 "확정" 칸(2026-11-10 사용자 답). 시나리오는 `scripts/battle-ai-scenarios/NN-*.mjs` 섹션 형식(`mon`·`est` 헬퍼, 결과 표에 `true/false`)으로 추가한다. 항목마다 **입력 상태 → 기대 결과**를 적고, "지금 동작"은 8.3 착수 전 실패를 확인하는 용도다.

**개정 2026-11-12 — Showdown 대조 검수 반영**(`8.3-시나리오사양서-검수.md` 1~3절: smogon/pokemon-showdown `965a535`, mod `champions`, 싱글 `gen9championsbssregmc`). 기대값을 고친 것은 R7-d·R8-a 2건, 표현·범위를 고친 것은 R1-d·R6-b·R6-d·R7-c 4건, 추가한 시나리오는 R2-e~g·R3-e~g·R7-f·g·R8-e·f 10건이다. 개정된 항목은 `(개정)`·`(추가)`로 표시한다. **poke-builder는 더블을 지원하지 않는다** — 더블 전용 동작은 구현하지 않는다. 사용자 원칙: 규칙이 Showdown과 다르면 정확한 쪽을 택한다(메모리 `accuracy-over-existing-implementation`). 이 개정으로 `8.3-규칙조사.md`의 일부 "확정" 칸(R7 버티기, R8 폴터가이스트, R3 사용자 스탯 해석)과 기대값이 달라지며, 규칙조사 문서는 별도 검수 결과를 받은 뒤 고친다.

## R3 미래예지
| # | 입력 | 기대 |
|---|---|---|
| R3-a | 쓴 뒤 칼춤·교체로 능력치 변화, 2턴 뒤 적중 | **맞는 시점의 스탯**으로 계산 |
| R3-b | 적중 시 대상 뒤에 대타 | 대타가 맞고 대타 HP 감소 |
| R3-c | 적중 시 날씨·필드·상대 도구·랭크 | 모두 적중 시점 값으로 반영 |
| R3-d | 순서 | R6 표의 ③ 단계(먹다남은음식보다 앞) |
| R3-e (추가) | 미래예지 사용자가 교체로 내려간 상태에서 적중 | 계산은 **원래 사용자 본인**의 능력치(랭크는 교체로 초기화된 값). 현재 그 슬롯에 있는 포켓몬의 능력치가 아님 (근거: futuremove `onEnd` — `trySpreadMoveHit([target], data.source, …)`) |
| R3-f (추가) | 같은 대상 슬롯에 미래예지가 대기 중인데 다시 사용 | 실패 (근거: futuremove `onRestart: return false`) |
| R3-g (추가) | 적중 시점에 대상이 기절해 있음 | 맞지 않음(로그 없음) (근거: futuremove `onEnd` — `target.fainted` → return) |

## R7 방어류·길동무
| # | 입력 | 기대 |
|---|---|---|
| R7-a | 길동무 성공 다음 턴 길동무 | 100% 실패, `protectStreak` 불변 |
| R7-b | 방어 성공 후 길동무 | 길동무 확률은 영향받지 않음(방어 카운터와 분리) |
| R7-c (개정) | 패스트가드·와이드가드 | 연속 사용 확률 판정은 **없음**. **단, 그 턴 마지막 행동이면 실패**(quickguard/wideguard `onTry: !!this.queue.willAct()`). 성공하면 stall 카운터를 ×3 누적(`onHitSide: source.addVolatile('stall')`, stall `onRestart: counter *= 3`)하므로 **다음 방어·판별 성공률은 1/3, 연속하면 1/9…** |
| R7-d (개정) | 버티기를 그 턴 마지막에 사용 | **실패**(방어·판별·킹실드와 같은 조건). 실패하면 stall 카운터 증가 없음 (근거: endure `onPrepareHit` — `!!this.queue.willAct() && runEvent('StallMove')`, 실측: 상대 Protect(+4)가 먼저 행동한 뒤 Endure를 쓰면 `-fail`). *이전 기대("마지막이어도 성공", 사용자 정정 2026-11-10)를 Showdown 실측으로 대체한다* |
| R7-e | AI `protectSuccessChance` | 위 규칙과 일치 |
| R7-f (추가) | 길동무 성공 → 다음 턴 실패 → 3턴째 길동무 | 3턴째는 **성공**(실패할 때 volatile이 제거됨) (근거: destinybond `onPrepareHit: !pokemon.removeVolatile('destinybond')`) |
| R7-g (추가) | 길동무 성공 → 다음 턴 행동 불가(마비 등) → 그다음 턴 길동무 | 성공 (근거: destinybond `onMoveAborted`에서 제거) |

## R8 킬가르도 배틀스위치
순서 원리(검수): 기술 처리 단계는 `BeforeMove`(행동 불가 판정) → `ModifyMove`(배틀스위치) → `onTry`/`onPrepareHit`(성공 판정) 순이다. 그래서 기술을 **냈지만 실패**해도 배틀스위치는 이미 적용된다. 행동 자체가 불가능한 경우(R8-b)는 `ModifyMove`까지 가지 못해 폼이 그대로다.

| # | 입력 | 기대 |
|---|---|---|
| R8-a (개정) | 폴터가이스트, 상대 도구 없음 | **블레이드폼으로 폼체인지한 뒤** 실패. 폼 변경 이벤트·로그 발생 (근거: stancechange는 `onModifyMove`에서 폼을 바꾸고 poltergeist의 도구 확인(`onTry`)은 그 뒤. 실측 로그: `-formechange Aegislash-Blade` → `move Poltergeist` → `-fail`). *이전 기대("폼 불변", 사용자 확정 2026-11-10)를 Showdown 실측으로 대체한다* |
| R8-b | 마비·풀죽음·수면·빙결·혼란 자해로 행동 못 함 | 폼 불변 (`BeforeMove`에서 막혀 `ModifyMove`에 가지 못함) |
| R8-c | 공격 기술 사용 | `turnResults`에 폼 변경 이벤트(실드→블레이드), 로그 "킬가르도는 블레이드폼으로 폼체인지했다!" |
| R8-d | 킹실드 사용 | 이벤트(블레이드→실드), 로그 "킬가르도는 실드폼으로 폼체인지했다!" |
| R8-e (추가) | 킹실드가 실패(연속 사용 판정 실패 또는 그 턴 마지막 행동)하는 경우 | 실패해도 **실드폼으로 폼체인지**함 (근거: R8-a와 같은 원리 — `ModifyMove`가 `onPrepareHit`보다 앞) |
| R8-f (추가) | 킹실드 외의 변화 기술 사용 | 폼 불변 (근거: stancechange — `move.category === 'Status' && move.id !== 'kingsshield'` → return) |
