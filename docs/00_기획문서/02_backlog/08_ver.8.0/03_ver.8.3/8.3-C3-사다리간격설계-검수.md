1. §0 원인에 **"사다리 측정의 정확한 50.0%는 학습 비활성 + 거울 시드의 결과일 가능성"** 을 적고 rank-ladder의 학습 동작을 확인한다(§2-2).

## 2. 상세 — 현황 해석

### 2-1. 수치 재계산 (✅)
Elo = 400·log10(p/(1−p)).

| 항목 | 설계서 | 재계산 |
|---|---|---|
| 62.2% / 64.4% / 64.8% / 59.5% / 53.3% | +86 / +103 / +107 / +67 / +23 | +86.5 / +103 / +106 / +67 / +23 ✅ |
| 55% / 53% 하한 | 35 / 21 Elo | 34.9 / 20.9 ✅ |
| 목표 P3 232(P2 대비 +43) | 56% | 56.1% ✅ |
| 목표 P4 272 / P5 312(각 +40) | 55.7% | 55.7% ✅ |
| P6/P5(+51) | 57.3% | 57.3% ✅ |
| 엄격·완화 여유 | 34 / 90 Elo | 34 / 90 ✅ |

- 상한 65%(≈108 Elo)는 목표 배치 어디서도 걸리지 않는다. 현행 P3/P2 64.8%는 상한 경계에 붙어 있었다 — 이번 조정으로 같이 해소된다.

### 2-2. "정확히 50.0%"가 두 번 나온 이유 ⚠️❓
- 600판에서 진짜 승률이 50%여도 점추정이 정확히 50.0%가 될 확률은 쌍마다 약 3% 정도다. 두 쌍이 동시에 정확히 50.0%인 것은 우연으로 보기 어렵다.
- 더 그럴듯한 설명: 시드 1개 = 좌우를 바꾼 2판이고 AI 판단이 시드에 대해 결정적이면, **동일한 AI 둘**은 좌우만 바뀐 거울상 대국을 두어 시드마다 1승 1패(또는 2무)가 된다 → 무승부 제외 승률이 구조적으로 정확히 50.0%다.
- 즉 사다리 측정(S2)에서 P3과 P4, P5와 P6은 **완전히 같은 AI로 동작**했을 가능성이 크다. 원인은 "학습 이득이 작아서"가 아니라 **사다리 측정에서 학습(λ)이 작동하지 않아서**(기억이 비어 있거나 학습을 끈 상태)일 수 있다. 학습을 켠 M2에서는 49.7%·50.3%로 정확히 50이 아니었다는 점도 이 해석과 맞다.
- 이번 설계의 결론(λ로는 격차를 못 만든다 → 다른 수단으로 약화)은 **그대로 유효하다.** M2에서도 학습 효과는 측정 오차 수준이었기 때문이다. 다만 다음 두 가지를 적어야 한다.
  1. §0 원인 서술: "사다리 측정에서는 λ가 작동하지 않아 두 쌍이 동일 AI였다(❓ 확인). 학습을 켠 M2에서도 λ 효과는 오차 수준이다."
  2. §7 한계: 튜닝은 학습이 없는 상태로 한다. 실제 앱(학습 켬)의 인접 승률은 M2처럼 ±2%p 정도 달라질 수 있다(M2의 P5/P4는 57.2%로 사다리보다 2.3%p 낮았다). 엄격 하한 근처 쌍은 확정 측정에서 **학습을 켠 조건으로도 한 번** 잰다(선택).
- 확인 방법: `rank-ladder.mjs`가 학습 기억을 판 사이에 넘기는지, `POOL=samples` 조건에서 λ가 실제 판단에 들어가는지 확인한다.

### 2-3. 여유 34 Elo의 오차 ⚠️
- 여유 = (P6 − P2) − 4 × 35. P6 − P2 = 174 Elo는 측정 4쌍(P3/P2 107 + P4/P3 0 + P5/P4 67 + P6/P5 0)의 합이다. 각 ±14 Elo(1σ)면 합의 오차는 √4 × 14 ≈ **±28 Elo**다. 진짜 여유는 대략 6~62 Elo 범위다.
- 여유가 한 자릿수라면 엄격 기준은 처음부터 불가능하고, 3라운드를 소모한 뒤에야 알게 된다.
- 권장: **튜닝 전에 현행 P6 대 P2를 직접 1회 측정**(예상 승률 약 73%)한다. 한 쌍이고 코드 변경이 없다. 이 값으로 여유를 확정하고:
  - 여유 ≥ 약 20 Elo → 엄격 목표로 진행
  - 여유 < 약 20 Elo → 처음부터 완화 기준으로 진행(Q1의 후퇴를 앞당김)
- 비전이성(§7 한계 2)이 있으면 직접 측정값과 합이 어긋날 수 있다. 그 자체가 유용한 정보다(배치 계산에 어느 쪽을 쓸지 결정할 근거).

## 3. 상세 — 튜닝 절차

### 3-1. 라운드 정의 ⚠️
- §4 순서(① P5 → ② P4 → ③ P3)는 앞 단계가 확정돼야 다음 단계를 맞출 수 있는 **직렬** 구조다. 상한 3라운드면 단계마다 정확히 1회이고 재시도가 없다. 한 단계라도 첫 격자에서 빗나가면 폐기된다.
- 권장(기준점 방식):
  - **라운드 1(배치)**: 모든 후보를 **고정 기준점 대비**로 병렬 측정한다. P3·P4 후보 → P2 대비, P5 후보 → P6 대비, 그리고 현행 P6 대 P2(§2-3). 각 후보의 Elo 위치가 한 번에 나온다(P4 후보는 P2 대비 약 60~62%로 측정 가능한 범위).
  - **라운드 2(확인)**: 위치로 고른 조합의 인접 4쌍을 직접 측정한다.
  - **라운드 3(보정)**: 빗나간 쌍만 한 번 보정. 이후 확정 측정(1,200판).
- 시간: 라운드 1은 후보 수가 많아(P3 3개·P4 2개·P5 3~5개 + 1쌍) 병렬로도 S2보다 길 수 있다. 측정 시작 전 보고(Q6)에 후보 수와 예상 시간을 적는다.
- 기준점 방식도 비전이성의 영향을 받는다. 그래서 라운드 2의 직접 측정이 최종 판단이다.

### 3-2. P3·P4 실수율 격자 (✅, 추가 1개)
- 기존 자료로 첫 추정을 할 수 있다: P1 → P2(실수율 0.4 → 0.12, margin 1e9)가 +103 Elo였다. 선형으로 보면 실수율 0.01당 약 3.7 Elo.
  - P3 −64 Elo → r3 ≈ 0.17, P4 −24 Elo → r4 ≈ 0.065
  - 격자 r3 {0.10, 0.20} → 약 −37 / −74, r4 {0.05, 0.10} → 약 −18 / −37. 목표를 감싼다 ✅
  - **r3 = 0.15를 추가**하면 첫 라운드 적중 가능성이 높아진다(비선형·상대 모델 유무 차이로 추정이 어긋날 수 있으므로 감싸는 격자 유지).
- **실수율 역전**: r3 ≈ 0.17이면 P3(마스터볼 4)이 P2(0.12)보다 **무작위 수를 더 자주** 둔다. 상대 모델로 보상받아 전체 강도는 높지만, 사용자는 "상위 단계가 더 엉뚱한 수를 둔다"고 느낄 수 있다(§7 한계 3의 구체적 사례).
  - 완화책: P3·P4는 `margin 0.5`(최선에 가까운 차선책만)를 쓴다. 실수가 "그럴듯한 실수"가 되어 역전의 체감이 줄어든다. 대신 같은 약화량에 더 큰 rate가 필요하므로 margin 0.5를 쓸 때는 rate 격자를 위로 넓힌다(예: 0.2~0.4).
  - 어느 쪽을 쓸지는 측정 전에 정해 격자 크기를 줄인다. 검수 의견: **margin 0.5 우선**(체감 일관성), 목표 약화량이 안 나오면 1e9.
  - ❓ `test:rank-ai`가 단계별 실수율 단조성(높은 단계 = 낮은 실수율)을 검사하는지 확인한다. 검사한다면 시험 기대값 갱신 범위에 포함된다(§5).

### 3-3. P5 탐색 약화 ⚠️
- 현행 P5/P4 = +67 Elo는 **탐색 유무만의 차이**다(§2-2에 따라 λ 차이는 0). 목표는 P5를 −51 Elo, 즉 탐색 이득을 약 16 Elo만 남기는 것이다. 탐색을 약 3/4 덜어내는 강한 약화다.
- `topK 3 → 2` 같은 한 단계 조정은 이득 일부만 줄일 가능성이 크다. 격자에 **강한 조합**을 넣는다(예: `budget 24 → 6~8`, `topK 2 + maxOpponentMoves 2`, `topK 1`이 실질적으로 탐색 끔인지 ❓).
- **탐색 없는 후퇴안(완화 기준용)**: P5 = 현행 P3·P4와 같은 AI(`MODEL_ONLY`, 실수 없음, λ 0.75)로 두면 위치는 296이다.
  - P6/P5 = +67 → 59.5%(이미 S2에서 측정된 값과 같은 조합), P5/P4 = 296 − 272 = +24 → 53.4%.
  - 완화 기준(≥53%)은 만족, 엄격은 불만족. P3은 210~251 범위면 된다.
  - **탐색 파라미터 튜닝이 필요 없어** 측정 부담이 가장 작다. Q2(코드 변경 없음)와도 맞다. 엄격 실패 시 후퇴안으로 설계서에 적어 둔다.
  - 단점: 마스터볼 2(P5)와 마스터볼 1(P6) 사이에 탐색 유무라는 "질적" 경계가 생긴다. 내부 정의라 UI 영향은 없다.

### 3-4. 판정식 ⚠️
- 600판의 1σ는 ±2.0%p, 95% 구간은 ±4%p다. 측정값 55%의 진짜 값은 51~59%일 수 있다. 확정 측정(1,200판)은 1σ ±1.4%p, 95% 구간 ±2.8%p.
- 측정 전에 판정식을 고정한다(사후 해석 방지, C2 계열과 같은 원칙).
  - **엄격 통과**: 확정 측정에서 인접 4쌍 모두 점추정 55~65%.
  - **완화 통과**: 인접 4쌍 모두 점추정 ≥ 53%, **그리고** 95% 구간 하한 > 50%(단조 증가를 통계적으로 확인).
  - 라운드 1·2(600판)는 조합 선택용이고 판정에 쓰지 않는다.
- 보고 항목에 **무승부율**을 추가한다. 무승부 제외 승률이라 무승부가 많은 쌍은 실제 표본이 줄어든다.

## 4. 상세 — 구현 위험

### 4-1. 공유 상수 변형 ❓
- P5를 `{ ...APP_DECISION_PARAMS, search: { ...APP_DECISION_PARAMS.search, topK: 2 } }`처럼 **중첩까지 복사**해야 한다. `search`를 얕게 공유한 채 값을 바꾸면 앱 AI(`APP_DECISION_PARAMS`)가 같이 바뀌어 §4 중단 조건 ②를 어기게 된다. P3·P4의 `MODEL_ONLY` 공유도 같다.
- 시험 추가 권장: `test:rank-ai`에서 랭크 정의 생성 뒤 `APP_DECISION_PARAMS`·`MODEL_ONLY`의 값이 원본과 같음(깊은 비교)을 확인한다. 가능하면 상수를 `Object.freeze`(중첩 포함)로 막는다.

### 4-2. 측정 도구 JSON 인자
- `battle-ai-sim.mjs`의 `parseParams`가 JSON을 받는다는 전제에 동의한다. ❓ `rank-ladder.mjs`가 그 경로를 그대로 쓰는지, 선출(`SELECT=1`) 단계도 같은 파라미터로 판단하는지 확인한다(선출 AI가 단계 정의와 별개라면 후보 비교에 영향이 없는지 함께 확인).
- 후보 파라미터 문자열은 측정 결과 `.txt`에 그대로 남겨 재현할 수 있게 한다.

## 6. 문서 정합성(사소)
- §0 "원인(코드)"의 "학습이 승률에 주는 이득이 작아 λ로는 강도 격차가 생기지 않는다" → §2-2에 따라 "사다리 측정에서는 λ가 작동하지 않았고(❓), 작동해도 이득이 작다"로 정리.
- §2 표 "제안 목표"에 각 단계의 **인접 쌍 기대 승률을 한 줄로**(P3/P2 56.1 · P4/P3 55.7 · P5/P4 55.7 · P6/P5 57.3) 모아 두면 라운드 판단이 쉽다.
- §4 "라운드마다 바뀐 단계가 낀 인접 쌍만 재측정"과 "순서 ①~④"가 기준점 방식으로 바뀌면 함께 고친다.
- §7 한계에 추가: 학습 없는 조건의 튜닝(§2-2), 여유 추정의 누적 오차(§2-3), 실수율 역전(§3-2).
