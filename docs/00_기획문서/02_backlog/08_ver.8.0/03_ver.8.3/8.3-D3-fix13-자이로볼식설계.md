# ver.8.3 D3-fix-13 — 자이로볼 위력식을 Showdown식으로 정정 (사용자 확정식 번복)

**상태**: 초안(2026-11-19, 사용자 검수 대기). 근거: `8.3-D3-fix12-자이로일렉트릭볼설계.md` §9 부록(두 식 비교)·검수 §1-1·§2-1, **사용자 결정(2026-11-19) Q1 → (나) Showdown식, Q2 별도 PR로 재설계**. 사용자 말: "Showdown 로직이 내가 직접 손으로 찾아본 것보다는 정확하겠지." 인게임 확인은 하지 않았다(§6 Q2).
**PR**: 1개·커밋 1개. **fix-12(스피드 입력 정정) 머지 뒤 착수** — 입력이 맞아진 뒤 식을 바꿔야 해시 원인이 분리된다.
**기준**: Showdown `965a535` `data/moves.ts` `gyroball.basePowerCallback`(8054~): `power = Math.floor(25 * target.getStat('spe') / pokemon.getStat('spe')) + 1; if (!isFinite(power)) power = 1; if (power > 150) power = 150`. Champions 모드 재정의 없음(덤프 `championsOverride: null`, `data/mods/champions/`에는 습득 목록만).

## 0. 번복의 성격
`phase7.5-plan.md:161`("사용자가 준 계산식은 이 프로젝트 기준 확정값이므로 본가와 달라도 이걸 따른다")로 확정된 자이로볼 식 `min(150, floor(25 × (상대/나 + 1)))`을 **사용자가 직접 번복**한다(D3의 "정확성 > 기존 구현" 원칙, 곡예·난동에 이은 세 번째 번복). `phase7.5-plan.md:161·167·270`과 `battlePower.ts:110` 주석은 과거 기록이라 문서는 고치지 않고 **이 설계서·백로그·코드 주석에 번복 이력**(날짜·근거)을 남긴다.

## 1. 무엇이 다른가
엔진 (가) `min(150, max(1, floor(25 × (t/p + 1))))`(내 스피드 0 이하면 150) vs Showdown (나) `min(150, floor(25 * t / p) + 1)`(내 스피드 0이면 1). 항상 (가)가 약 24 높다.
| 내 스피드 | 상대 스피드 | 현행 (가) | (나) |
|---|---|---|---|
| 50 | 100 | 75 | 51 |
| 100 | 100 | 50 | 26 |
| 100 | 50 | 37 | 13 |
| 100 | 200 | 75 | 51 |
| 30 | 150 | 150 | 126 |
| 150 | 30 | 30 | 6 |
| 200 | 60 | 32 | 8 |
(fix-12 검수 §1-1 재계산 일치.) 실능 스피드 31~213 전 쌍 33,489개 평균 +23.9, 상한 150에서만 같음(0.3%). 평균 위력: 내가 더 빠름 37.2 → 13.2, 비슷 49.7 → 25.7, 더 느림 63.7 → 39.7, 훨씬 느림 101.5 → 78.4.

## 2. 고칠 것
**2-1. 식 한 줄** — `battlePower.ts` `gyroBallPowerFromSpeeds(userSpeed, targetSpeed)`:
```ts
if (userSpeed <= 0) return 1;                                   // Showdown: !isFinite(power) → 1 (도달 불가 경계)
return Math.min(150, Math.floor((25 * targetSpeed) / userSpeed) + 1);   // 연산 순서는 소스와 같게 — 곱 먼저
```
**연산 순서가 중요하다(검수 §2-1)**: `25 * (t/p)`로 쓰면 31~213 전 쌍 중 13쌍이 틀린다(예: 상대 161·나 35 → 115, Showdown 116). 참조 구현(시험)도 같은 순서를 쓴다. 입력은 fix-12가 만든 정수 스피드(`computeTurnOrderSpeed`·`computeSpeedWithEffects`)다.
**2-2. 주석** — `battlePower.ts:110`의 "사용자 확정식" 주석을 새 식과 번복 이력("8.3 D3-fix-13, 2026-11-19: 사용자 결정으로 본가·Showdown식으로 정정. 이전 확정식 `25×(t/p+1)`은 phase7.5-plan.md:161")으로 바꾼다.
**2-3. 영향을 받는 호출처(코드 변경 없음, 식만 공유)** — 엔진 `preHitEffects.ts`(fix-12 후), 매치업 `matchupEvaluator.ts` 위력 분기, AI `ai/moveDamage.ts`, 공격·방어·결합 역산(`attackInference.ts:289`·`defenseInference.ts:494`·`combinedInference.ts:111`)은 모두 `gyroBallPowerFromSpeeds`를 거치므로 한 곳 수정으로 일괄 반영된다.
**2-4. 하지 않는 것** — 일렉트릭볼 식(Showdown과 동치, 검수 확인), 기술 설명문(`moves.json` effect "상대보다 스피드가 낮을수록 위력이 올라간다(최대 150)"는 (나)에서도 맞다), 입력 스피드(fix-12).

## 3. 영향·측정
- **해시 변동 예상(단계 하나, 예상은 자주 틀려 측정으로 확인)**: 자이로볼을 든 무작위 빌드가 있는 `regress`, AI가 자이로볼을 평가하는 `greedy120`·`status60`·`h2h40`·`ai60`, 공격·방어 역산 왕복 시험(`defense-inference-check/14-speed-power-foulplay-def.mjs`·`04-attack-roundtrip.mjs` — 양방향이 같은 식을 쓰므로 통과는 유지되고 결합 해시는 바뀔 수 있다), 차분 해시(매치업 무작위 대결에 자이로볼 포함).

- **측정(시작 전에 "명령·예상 시간"을 먼저 보고)**: ① `regress 200`·`regress 20000`·`STATUS=1 greedy 60`(약 3분) ② `defense-inference-check`(역산 결합 해시) ③ `SERIAL=1 verify.sh` 14항목(약 8분). 변경이 식 한 줄이라 단계 측정은 하나이고, 기준값은 `update-baseline.sh`로 갱신한다. 역산 결합 해시가 바뀌면 fix-11처럼 변경 전후를 비교해 보고한다.
