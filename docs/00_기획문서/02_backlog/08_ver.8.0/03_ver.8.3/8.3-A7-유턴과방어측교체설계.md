## 1. Showdown에서 이미 확인된 것 (앞선 검수 근거)

- **탈출버튼**: `onAfterMoveSecondary` 조건에 `canSwitch`·`forceSwitchFlag`·`beingCalledBack`·`isSkyDropped`·`commanding` 뒤에 **"다른 활성의 `switchFlag`가 true면 발동하지 않음"**이 있다(`8.3-A4b-턴종료교체설계-검수.md` §2-1이 인용한 소스). 유턴 사용자가 교체 대기 중이면 `switchFlag`가 서 있으므로 **탈출버튼은 발동하지 않고 도구도 남는다.** 이것은 C1의 현재 엔진 동작(도구 유지)과 우연히 같다.
- **레드카드 vs 위기회피 정산 순서**: 레드카드 → 위기회피(A4-b 2·3차 검수 실측).
- 레드카드는 발동 시 공격자의 생명의구슬 반동을 만들지 않는다(A4-b V4).

## 3. 엔진 설계 (`runTurn.ts`)

`runActionPhase`의 행동 뒤 처리 순서를 바꾼다. 지금은 `selfSwitchPause` → `applyRedCard` → `forceTargetSwitch` → `defenderExitPause`.

**새 순서:**
1. `applyRedCard` — 공격자가 끌려 나가면 `ctx.didSwitch[key] = true`.
2. `forceTargetSwitch` — 변화 없음(드래곤테일류는 `selfSwitchAfterDamage`와 한 기술에 같이 없으므로 순서 영향 없음).
3. **`emergencyExitPause`** (`defenderExitPause`의 위기회피 절반을 분리) — 발동하면 방어측 pause를 돌려주고, **이 행동의 유턴 자체 교체는 평가하지 않는다**(R2).
4. `selfSwitchPause` — **`ctx.didSwitch[key]`가 서 있으면(레드카드로 이미 교체) 유턴류 분기를 건너뛴다**(R1). 그 외 조건은 지금과 같다.
5. **`ejectButtonPause`** (`defenderExitPause`의 탈출버튼 절반) — 유턴 pause가 이미 반환됐으면 도달하지 않는다(R3, 소스 근거와 동일). 유턴류가 아닌 행동에는 지금과 같다.

변경은 `runTurn.ts`의 함수 분할과 호출 순서, `selfSwitchPause`의 가드 한 줄이 전부다. `resumeTurn`·UI·AI의 pause 처리는 바꾸지 않는다(C5). `defenderExitPause`를 둘로 쪼개는 외에 로직 변경은 없다.

## 4. 화면 (`BattleTurnLog` · `SwitchLines`)

- R1: 로그는 "유턴 데미지" → "레드카드 발동" → "강제 교체"만 나오고, 유턴의 자체 교체 줄("돌아와!")은 없다. 레드카드 교체 기록(`redCardItemName`)은 A4-b에서 이미 `afterMove && forced`로 렌더되므로 **새 UI는 필요 없다.**
- R2: 위기회피 pause 흐름은 이미 있다. 유턴 사용자의 자체 교체 줄이 없는 것만 달라진다.
- 연출 일정(`turnFxSchedule`)의 `swaps` 계산은 `afterMove`·`forced`·`redCardItemName` 조합을 이미 처리한다 — 레드카드가 유턴 행동 뒤에 오는 경우도 같은 필드라 변경 없음(구현 중 재생 확인).

## 5. AI

- 평가기가 유턴을 어떻게 취급하는지(`optionType: "pivot"`)는 건드리지 않는다. 다만 **이번 변경으로 유턴 결과가 바뀌는 상황**(레드카드·위기회피 홀더 상대)에서 평가기가 `runTurn` 시뮬레이션을 거치는지 확인하고, 거친다면 자동으로 따라가고 아니면 한계로 적는다. 구현 중 `ai/**`에서 `selfSwitchAfterDamage`·`pivot` 사용처를 확인한다.

## 8. 해시·검증 예상

레드카드·위기회피·탈출버튼 홀더에 유턴·볼트체인지가 명중하는 판이 `regress`에 섞일 때만 `regress` 해시가 변한다. 200판에는 드물어 불변일 수 있고 `regress 20000`에서 변할 가능성이 크다. `greedy120`·`h2h40`·`ai60`은 AI가 이 조합을 고르는 정도에 따라 달라질 수 있어 **측정한다.** 단계 측정은 ① 분할만(출력 불변 확인) → ② 순서 변경, 두 단계로 `regress 200`·`regress 20000`·`status60`만 따로 돌린다(약 3분). 기준값은 `SERIAL=1` 깨끗한 출력으로만 갱신한다.

## 10. 알면서 두는 것

- 위기회피 발동 뒤 유턴 사용자의 **취소된 교체**에 대한 로그 안내는 만들지 않는다(Showdown도 줄이 없다고 가정 — V2로 확인).
- 같은 턴 두 번째 행동자가 맞는 경우(양쪽이 유턴·레드카드)의 연쇄는 위 규칙을 행동마다 독립 적용하는 것으로 둔다.
- 방어측 효과 홀더가 유턴 사용자에게 **쓰러진 경우**(피격 기절)는 기존 조건(`!isFainted(holder)`)이 그대로 막는다.
