# ver.8.3 D3-fix-20 — 도발·앙코르·사슬묶기는 턴 종료에 줄어든다 (E4b-08)

**상태**: 초안(2026-11-19) — **사용자 검수 대기.** 근거: `8.3-D3-E4b-검수.md` E4b-07·08. 이 묶음에서 **가장 크다**(두 군데 + 부여 시점 보정).
**PR**: 1개·커밋 1개. 시험 `scripts/battle-ai-scenarios/51-ver83-d3fix20.mjs`. fix-16~19와 순서 무관.
**기준**: Showdown `965a535` `data/moves.ts`:
- `taunt.condition`: `duration: 3`, `onStart`: `target.activeTurns && !this.queue.willMove(target)`(= 대상이 **이미 움직였으면**) `duration++`, `onResidualOrder: 15`.
- `encore.condition`: `duration: 3`, `onStart`: `!this.queue.willMove(target)`이면 `duration++`, `onResidualOrder: 16`.
- `disable.condition`: `duration: 5`, `onStart`: `this.queue.willMove(pokemon)`(= 대상이 **아직 안 움직였으면**) `duration--`, `onResidualOrder: 17`.
- 지속은 **턴 종료 처리**에서 효과마다 `duration--`, 0이 되면 끝난다(`sim/battle.ts` `residualEvent`) — 걸린 포켓몬이 그 턴 행동을 했는지와 무관하다.

## 1. 무엇이 다른가
엔진은 걸린 포켓몬이 **행동할 때**(`preHitEffects.ts` `checkActionBlockers` 2-0절)마다 `consumeVolatileTurn`으로 줄인다. 수면·얼음·마비·풀죽음·혼란 자해 등으로 이 판정 앞에서 막힌 턴은 줄지 않는다. Showdown은 턴 종료에 줄어 그런 턴도 지속에서 빠진다.
막히는 **행동 수**는 평소(걸린 포켓몬이 매 턴 행동)에는 같다:
| | 엔진 | Showdown(걸리는 시점별) |
|---|---|---|
| 도발 | 3 | 대상이 아직 안 움직임 → 3(걸린 턴 포함 3행동) / 이미 움직임 → 4(다음 턴부터 3행동) |
| 앙코르 | 3 | 같음(3 / 4) |
| 사슬묶기 | 4 | 대상이 아직 안 움직임 → 4 / 이미 움직임 → 5 — 막는 행동 4번 |
따라서 **부여 시점 보정과 턴 종료 소모를 한 묶음으로** 옮겨야 평소 값이 유지된다.

## 2. 고칠 것
1. **부여 시점 보정**(`mirroredEffects.ts`): 도발(`inflictVolatile`, 약 860·862행의 일반 경로)·앙코르(약 1650행)·사슬묶기(`setDisabledMoveName` 계열)에 부여 때의 "대상이 이미 움직였는가"(`c.movesSecond` — 공격측이 후공이면 대상이 이미 움직임)를 넘겨 지속 턴을 정한다. `inflictVolatile`에 선택 인자 `durationAdjust`(도발·앙코르: 이미 움직였으면 +1, 사슬묶기: 아직이면 −1)를 추가하는 최소 변경. 기본 지속은 도발 3·앙코르 3·**사슬묶기 5**(Showdown 기준 — 기존 4는 "아직 안 움직임 −1"을 미리 반영한 값이므로 새 기준 5에서 보정한다).
2. **소모를 턴 종료로**: `finishTurn.ts` `tickBlockVolatiles`(회복봉인·목조르기를 이미 "턴 종료마다 줄고 걸린 턴도 센다"로 처리)의 대상 목록에 `taunt`·`disable`·`encore`를 더한다. `checkActionBlockers` 2-0절의 `consumeVolatileTurn` 호출 3곳(도발·사슬묶기·앙코르)은 **삭제** — 검사(`hasVolatile`·막힘 판정)는 그대로 둔다.
3. **끝나는 시점**: 마지막 턴 종료에 0이 되어 해제되므로 그 턴의 행동은 여전히 막힌다(Showdown과 같음).
4. **AI**: `ai/`에서 도발·앙코르·사슬묶기의 `turnsRemaining`을 읽는 곳이 있으면(없다는 grep 결과를 구현 첫 단계에서 재확인) "남은 틱 수"가 곧 "남은 막히는 행동 수"이므로 의미가 같아 변경 불필요. 읽는 곳이 있으면 같은 PR에서 맞춘다.
5. **하지 않는 것**: 트집(지속 없음)·봉인·검은눈빛은 소모 없음 — 변경 없음. 앙코르 불가 기술 19종·`mefirst` 예외는 E10.

## 3. 영향·측정
막히는 행동 수는 평소 같고, 걸린 포켓몬이 걸린 동안 행동하지 못하는 턴(수면·마비·풀죽음)이 있을 때와 걸린 뒤 같은 턴에 해제되는 시점에서만 변한다. 해시는 거의 불변일 것이나 변동 가능 — `regress 200`·`regress 20000`·`STATUS=1 greedy 60`(약 3분) 뒤 `SERIAL=1 verify.sh`. **불변이어야 하는 것**: `test:inference` 결합·차분 해시.

## 4. 시험 `51-ver83-d3fix20.mjs`
1. **평소 행동 수 불변**: 걸린 포켓몬이 매 턴 행동 가능하면 도발 3행동·앙코르 3행동·사슬묶기 4행동이 막힌다(현행도 통과 — 불변 확인). 부여가 선공이든 후공이든 같다.
2. **후공 보정**: 도발을 대상이 이미 움직인 뒤(후공)에 걸면 다음 턴부터 3행동이 막힌다(걸린 턴의 행동은 이미 끝남).
3. **수면 중 도발**: 대상이 이미 움직인 뒤(후공) 도발을 걸어 지속 4가 되고, 대상이 다음 3턴 연속 수면이면 턴 종료마다 줄어 수면이 끝나는 4번째 턴에는 **도발이 이미 해제**되어 변화기를 쓸 수 있다(현행은 수면 중 줄지 않아 깨어난 뒤에도 3행동 막힘 → 실패).
4. **풀죽음·마비로 못 움직인 턴**도 소모된다(현행은 소모 안 함 → 실패).
5. **앙코르**: 3(후공 4)행동 강제 후 해제, 수면 중에도 줄어든다.
6. **사슬묶기**: 선공(대상 미행동) 4행동·후공 4행동(막는 행동 수 불변), 수면 턴도 소모.
7. **해제 시점**: 마지막 턴에도 그 행동은 막히고 턴 종료에 해제된다(한 턴 일찍/늦게 풀리지 않음).
8. 교체하면 휘발성이 초기화되는 기존 동작 불변.

## 5. 화면 확인(사용자 수행)
도발을 건 뒤 상대가 3턴간 변화기를 못 쓰고 4번째 행동에 쓸 수 있는지(평소 행동 수 불변 확인). 수면·마비 겹침은 시험으로 대체.
