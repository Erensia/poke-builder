## 2. 보완

### 2-1. [필수] "대상이 이미 움직였는가"는 `c.movesSecond`가 아니라 **대상 포켓몬 자신의 이번 턴 행동 차례가 지났는가**로
Showdown `willMove(target)`은 "대상 자신의 행동이 큐에 남아 있는가"다. `c.movesSecond`(공격측이 후공)로 대신하면 아래가 어긋난다:

| 경우 | Showdown | `movesSecond` 대용 |
|---|---|---|
| ① 상대가 U턴·볼트체인지·퀵턴·막말내뱉기로 먼저 빠지고 새로 나온 포켓몬에 도발 | `activeTurns = 0` → +1 없음 → 지속 3 → **다음 2행동** | 공격측 후공 → +1 → 4 → 3행동 ❌ |
| ② 턴 시작에 교체로 들어온 포켓몬에 도발 | `activeTurns = 0`, 행동 없음 → 3 → **다음 2행동** | `movesSecond` 정의에 따라 갈림 — 명시 필요 |
| ③ 대상이 먼저 차례를 맞았으나 수면·마비·풀죽음 등으로 막힘 | 큐에서 빠짐 → 이미 움직인 것 → +1 | 같음(후공) ✅ |

- 판정 기준을 "대상(현재 활성 개체)이 이번 턴 필드에 있었고 그 행동 차례가 이미 지났다(막혔어도 포함)"로 적는다. 도발의 +1은 여기에 "이번 턴 입장이 아님"을 더한 것이다.
- ①·②에서 앙코르·사슬묶기는 `lastMove`가 없어 실패한다. 엔진이 교체 시 마지막 기술을 지우는지 함께 확인(다르면 E10).
- 이 차이로 ②의 **교체 직후 도발은 3행동 → 2행동으로 바뀐다**(Showdown과 일치하는 방향). §3 "막히는 행동 수는 평소 같다"에 이 예외를 적고, 해시 변동 원인 후보로 둔다.
- 시험 추가 9: 턴 시작 교체로 들어온 대상에 도발 → 다음 2행동만 막힘. 시험 추가 10: 상대 U턴 뒤 새로 나온 대상에 도발 → 다음 2행동.

### 2-2. [필수] 저주받은바디 사슬묶기 = 5 − 1 = 4 → 다음 3행동
- Showdown `disable.onStart`의 두 번째 조건(`pokemon === activePokemon && activeMove && !isExternal`)은 저주받은바디로 **기술을 쓰는 중인 공격자**가 묶이는 경우다 → −1 → 4. 그 턴 행동은 이미 끝났으므로 턴 종료 3 → **다음 3행동만 막힌다.**
- 저주받은바디 보유: 팬텀·눈여아(숨겨진 특성)·드래펄트 — 모두 챔피언스 합법.
- 엔진이 저주받은바디를 구현했다면 그 경로의 `setDisabledMoveName` 호출에 −1을 넘긴다("공격측 후공 = 이미 움직임" 규칙을 그대로 적용하면 +0이 되어 4행동이 된다). 미구현이면 E8 백로그.
- 시험 추가 11: 저주받은바디 발동 → 다음 3행동 막힘.

### 2-3. [권고] 앙코르 PP 0 조기 해제
`encore.onResidual`(순서 16)은 앙코르 기술 PP가 0이면 턴 종료에 즉시 해제한다. 소모를 `tickBlockVolatiles`로 옮기는 김에 같은 자리에서 처리하면 한 줄이다. 엔진이 이미 다른 곳에서 처리하면 변경 불필요 — 구현 첫 단계 grep. 없으면 E10 백로그.

### 2-4. [권고] 구현 순서 문구
§6 "시험 → 부여 보정 → 소모 이동"에서 부여 보정만 들어간 중간 상태는 행동 수가 틀린 상태다. 커밋은 1개이므로 문제없지만, 중간 확인은 시험 1·2·6 대신 "보정 + 이동 후" 기준으로 본다고 적는다.
