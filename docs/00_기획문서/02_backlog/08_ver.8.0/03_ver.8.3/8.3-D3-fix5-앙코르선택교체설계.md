## 2. Showdown champions 소스(앙코르 재정의)

`data/mods/champions/moves.ts`:
```ts
encore: { inherit: true, condition: { inherit: true,
  onStart(target) {
    let move = target.lastMove;
    if (!move || target.volatiles['dynamax']) return false;
    …
    if (move.isZ || move.isMax || move.flags['failencore'] || !moveSlot || moveSlot.pp <= 0) return false;  // 실패
    this.effectState.move = move.id;
    this.add('-start', target, 'Encore');
    const action = this.queue.willMove(target);
    if (!action) {
      this.effectState.duration!++;                       // 이미 행동한 뒤라면 지속 +1
    } else if (action.moveid !== move.id && !target.hasItem('mentalherb')) {
      this.queue.changeAction(target, { choice: 'move', moveid: move.id });   // ← 선택을 앙코르 기술로 교체
    }
  },
  onOverrideAction: undefined,   // 기본 9세대의 "실행 시점 교체"는 없앤다
}}
```
- **앙코르가 걸리는 순간** 상대가 이번 턴에 아직 *기술 행동*을 남겨 두었고(`willMove` — 교체 행동은 해당 없음) 그 기술이 앙코르 기술이 아니며 멘탈허브가 없으면, 남은 행동을 앙코르 기술로 **즉시 교체**한다. 이미 행동했거나 교체를 고른 쪽은 `duration++`만 한다.
- 기본 9세대 `onOverrideAction`(실행 시점에 `move.id !== effectState.move`이면 앙코르 기술 반환)과 **결과가 같다**: 앙코르 이후 이번 턴에 실행될 선택은 앙코르 기술이다. champions는 그 시점이 "걸리는 순간"으로 옮겨졌을 뿐이다.
- 멘탈허브: 엔진은 걸리는 순간 앙코르를 치료·소모하므로(`mirroredEffects.ts:1648`) 이후 상대에게 `encore` 상태가 남지 않아 **자연히 교체 대상에서 빠진다**(Showdown과 같은 결과).

## 3. 엔진 현재 동작

- `mirroredEffects.ts:1635-1655`: 앙코르가 명중하면 상대 `volatile.active.encore = { moveId: 상대 직전 기술, 지속 3 }`를 건다(실패 조건: 상대가 기술을 쓴 적 없음·이미 앙코르·멘탈 차단 특성).
- `preHitEffects.ts:386-388`: 행동 직전에 "고른 기술이 앙코르 기술이 아니면 `moveRestricted`(앙코르) **실패**"로 막는다. 지속 턴은 그 행동마다 1 소모. **PP는 이 판정보다 앞(`:161`)에서 이미 깎인다** — 즉 지금은 고른 쪽 기술의 PP만 소모되고 행동은 실패한다(본가와 다르다).
- 앙코르 **이후의 턴**은 화면 입력(`BattleFighterInput`)과 AI(`opponentMoveModel.ts:60`)가 앙코르 기술만 고르게 막으므로 문제가 없다. **걸린 그 턴에 상대가 이미 다른 기술을 골랐고 아직 안 움직인 경우**만 틀린다(앙코르 사용자가 선공일 때: 속도가 빠르거나 짓궂은마음처럼 우선도 +1).

## 4. 고칠 것

`runTurn.ts` 행동 루프에서, 각 `resolveAction` 직후(현재 행동자 `key`의 효과가 막 적용된 뒤) 상대의 남은 행동을 점검한다:

```ts
/** 앙코르(8.3 D3-fix-5, champions): 이번 턴 아직 행동하지 않은 상대의 선택 기술을 앙코르 기술로 바꾼다. */
function overrideEncoredPending(ctx, key) {
  const opp = opponentKey(key);
  const enc = ctx.state[opp].volatile.active.encore;
  if (!enc?.moveId || ctx.didSwitch[opp] || isFainted(ctx.state[opp])) return;
  if (ctx.order.indexOf(opp) < ctx.actionIdx) return;             // 이미 행동함(actionIdx는 루프에서 `i + 1`로 이미 증가한 값 — 현재 행동자 i는 상대 판정에서 빠진다. 검수 §3-1, `runTurn.ts` 루프 확인)
  if (ctx.moves[opp].id === enc.moveId) return;                    // 이미 앙코르 기술
  if (forcedLockedAction(ctx.state[opp])) return;                  // 충전 2턴째·난동·반동은 잠금(교체 불가)
  const move = getMove(enc.moveId);
  if (move) ctx.moves[opp] = move;
}
```

- **교체한 쪽**(`didSwitch`)은 이번 턴 행동하지 않으므로 건드리지 않는다(Showdown `willMove`가 교체 행동을 안 잡는 것과 같다).
- **반동 중인 상대**: 엔진은 `forcedLockedAction`으로 건너뛴다. Showdown은 반동 행동의 id(`recharge`)가 `lastMove`와 달라 **교체를 실제로 실행**하지만 `mustrecharge`(`BeforeMove`)가 행동을 막는다 — 결과가 같다(검수 §2-2).
- **충전 2턴째**: Showdown은 준비 턴에도 `lastMove`를 기록(`moveUsed`)하므로 앙코르 기술 = 불새이고 잠긴 행동과 같아 교체가 없다. 엔진도 `forcedLockedAction`이라 같다. 단 **불새가 충전 기술이 되는 fix4가 먼저 머지된 뒤**에야 이 경로가 불새에 적용된다(fix4 → fix5 순서의 이유).
- **행동 순서는 원래 선택 기준을 유지**한다. 앙코르를 건 시점에 남은 행동은 대상 한 개뿐이라 순서에 영향이 없다(Showdown `changeAction`의 재정렬도 결과가 같다).
- 교체 후 `preHitEffects.ts:386`은 `moveId === c.move.id`라 실패 판정에 걸리지 않는다. 그 판정은 호출 기술(잠꼬대 등)이 앙코르 기술과 어긋나는 경우의 안전망으로 **그대로 둔다**.
- **PP**: 교체된 기술(앙코르 기술)의 PP가 깎인다 — `resolveAction`이 `c.move` 기준이라 별도 코드가 없다. 고른 기술의 PP는 소모되지 않는다(본가와 같은 결과).
- **로그**: 본가는 "앙코르로 바뀌었다"는 별도 문구가 없다. 행동 로그에는 앙코르 기술이 그대로 찍힌다(추가 문구 없음 — Q3).
- 지속 턴 소모는 기존 그대로(상대의 **행동마다** 1). Showdown은 **턴이 끝날 때마다** 1을 차감하고 상대가 이미 행동한 뒤 걸리면 `duration++`한다. 상대가 매 턴 정상적으로 행동하면 둘은 같지만, **상대가 마비·풀죽음·잠듦·혼란 자해로 못 움직인 턴**에는 엔진이 차감하지 않아 앙코르가 길어진다(검수 §2-4). 이번 PR 이전부터 있던 차이라 **E-영역 후보**로 올리고 시험으로 고정하지 않는다.

## 5. 영향 범위

- **사용 포켓몬**: 앙코르 습득 54종, 샘플 파티에 17회 등장 → AI 대국에 앙코르가 나오는 경우가 많다. 앙코르가 선공으로 걸리는 대국에서만 결과가 바뀐다.
- **해시**: `regress 200/20000`(앙코르 포함 빌드가 섞임)이 바뀔 가능성이 높다. `greedy120`·`status60`·`h2h40`·`ai60`·`test:inference`·`matchup`은 샘플 대국·계산 함수라 영향 여부를 측정으로 확인한다(앙코르 샘플 파티가 있으면 샘플 대국도 바뀔 수 있음).
- **AI**: 앙코르 기술의 가치 평가는 "이후 턴의 상대 기술 제한"만 보고 **이번 턴 즉시 교체의 이득은 반영하지 않는다** — AI가 앙코르를 약간 과소평가하는 한계는 유지(범위 밖). `opponentMoveModel.ts:60`의 상대 모델은 영향 없음.
- **화면·로그**: 번치코 플레어드라이브 → 무릎차기로 나가므로 "앙코르 때문에 이 기술을 쓸 수 없다!" 로그가 이 상황에서는 사라진다(그 문구는 호출 기술이 어긋나는 드문 경우에만 남음).
