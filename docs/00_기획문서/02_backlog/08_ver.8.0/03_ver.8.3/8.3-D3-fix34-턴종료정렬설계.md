## 1. Showdown이 하는 일 (소스 직접 대조 + 검수 확인)

1. **한 목록**: `runAction('residual')`은 먼저 `updateSpeed()`로 살아 있는 활성 포켓몬의 스피드를 **다시 계산**(2854행, 트릭룸이면 `10000 − 스피드` — `pokemon.ts` 662~669행)하고, `fieldEvent('Residual')`이 필드·편·포켓몬의 residual 핸들러를 **전부 한 배열**에 모은다(484~533행). 목록은 시작 때 한 번 만들고, 도중에 생긴 효과는 그 턴에 처리하지 않는다.
2. **정렬**: `speedSort`의 비교(`comparePriority`, 409~416행)는 **`order` → `priority` → `speed` → `subOrder` → `effectOrder`**. `order`가 작은 효과가 먼저고, 같은 order 안에서는 **스피드가 빠른 포켓몬의 효과가 먼저**, subOrder는 "같은 스피드"인 항목 사이에서만 쓰인다(스피드가 다르면 빠른 포켓몬의 효과를 sub 순으로 전부 한 뒤 느린 포켓몬).
3. **동률은 묶음마다 난수**: `speedSort`는 비교값이 0인 항목 묶음마다 `prng.shuffle`한다(456~462행). 즉 **같은 (order, 스피드, subOrder)** 인 서로 다른 포켓몬끼리의 순서는 order·sub마다 **독립적으로** 정해진다(먹다남은음식 순서와 독 순서의 앞뒤가 서로 다를 수 있다).
4. **자리 효과(미래예지·희망사항)는 자리 주인의 스피드로 정렬된다**: `findPokemonEventHandlers`가 슬롯 조건을 `effectHolder: pokemon`으로 수집하고(1153~1165행), `resolvePriority`가 `handler.speed = pokemon.speed`를 채운다. sub는 자리 기본값 3. *(초안은 "스피드 없음 → 난수"로 잘못 적었다 — 검수 필수 1.)*
5. **subOrder 기본값**(`resolvePriority`, 효과가 직접 정하지 않은 경우): 상태·휘발성(Condition) 2, 자리 3, 편 4, 필드·날씨 5, 특성 7, 도구 8. 효과가 직접 정한 값: 그래스필드 5/2, **탈피·촉촉바디·힐러 5/3**, 먹다남은음식·검은진흙 5/4, 가속류·변덕쟁이·수확·되새김질 28/2, 화염구슬류 28/3.
6. **핸들러마다 정산**: 핸들러 하나를 실행할 때마다 `resolveFaints(); if (this.ended) return;`(572~573행). **기절한 포켓몬의 핸들러는 건너뛴다**(517~519행), 단 자리 효과는 건너뛰지 않는다. **예외 둘**: ① 지속 종료형(`duration--` 뒤 0이 되어 `end()`가 도는 핸들러 — 멸망의노래)은 `resolveFaints` 없이 `continue`한다(520~527행) ② 날씨는 핸들러 **1개**이고 그 안에서 `eachEvent('Weather')`가 포켓몬별로 돌린 뒤 정산을 **한 번** 한다 → 두 효과 모두 같은 그룹 안에서는 **양쪽이 함께 쓰러질 수 있다**.
7. **동시 전멸 승자**: `checkWin(faintData)`는 둘 다 `pokemonLeft`가 0이면 **마지막으로 정산된 기절 포켓몬의 편**이 이긴다(gen5+, 2660~2670행). 기절 큐는 효과가 일어난 순서이므로 느린 쪽이 마지막이고 **느린 쪽이 이긴다**.
8. **날씨**: order 1의 **필드 핸들러** 하나(`onFieldResidualOrder: 1`)가 `eachEvent('Weather')`로 포켓몬별 `onWeather`를 스피드순으로 돌린다. 한 포켓몬 안에서는 날씨 sub 5 < 특성 sub 7(모래 피해 → 젖은접시·건조피부). 한 포켓몬에 날씨 줄이 둘 이상 나오는 조합은 실제로 없다(모래바람과 겹치는 회복 특성이 없음).

**결과가 달라지는 구체적 사례**(Showdown ↔ 엔진):
- **A. 효과 간 끼어들기 — 결과가 갈리는 두 장면**(검수 필수 2). *(초안의 "먹다남은음식 ↔ 씨뿌리기 끼어들기로 흡수량이 달라진다"는 틀렸다 — 회복은 같은 최대 HP를 상한으로 더해지기만 해 순서가 바뀌어도 최종 HP가 같고, 줄마다 찍히는 회복량 분배만 달라진다. 포켓몬 사이에 HP가 오가는 턴 종료 효과는 씨뿌리기 하나뿐이다.)*
  1. **상호 씨뿌리기**: 둘 다 씨앗 상태, a가 느리고 HP가 최대의 1/8 미만. Showdown은 b의 씨뿌리기(8)가 먼저라 a가 흡수분을 회복한 뒤 자기 씨뿌리기 피해를 받아 **생존**. 현행은 a 효과를 먼저 처리해 a가 **기절**.
  2. **씨뿌리기 원천이 더 뒤 order에서 쓰러질 처지**: a(예비 있음)가 독·HP 1이고 b가 a의 씨앗 상태. Showdown은 씨뿌리기(8)→독(9)이라 a가 먼저 회복하고 독을 받아 **생존**. 현행은 a의 독으로 a가 먼저 기절하고 b의 씨뿌리기는 "원천 기절"로 피해·회복 모두 **불발**.
- **B. 서로 다른 order에서 쓰러짐**: a에 화상(10)·b에 독(9), 둘 다 HP 1 → Showdown은 독(9) 먼저 → b 기절 → 끝(a 승, a 화상 미처리). 엔진은 a 효과를 먼저 → a 화상으로 a 기절 → b 승. **승자가 반대.**
- **C. 같은 order, a가 느린 경우(PR #533 한계)**: 둘 다 독(9)으로 쓰러질 처지면 Showdown은 **빠른 쪽이 먼저 쓰러져** 진다. 엔진은 a가 먼저 처리돼 a가 진다 — a가 빠르면 같고 **a가 느리면 반대**.
- **D. 스피드는 턴 시작이 아니라 residual 직전 값**: 이번 턴 행동으로 랭크·마비가 바뀐 경우 순서도 바뀐다(`FinishCtx.speedA/B`는 턴 시작 값).

빈도(E6 문서 §3-1, 2만 판·60.9만 턴): 양쪽 모두 HP를 바꾸는 효과가 있는 턴 **1.90%**, 그중 누군가 기절하는 턴 **0.067%(409턴)** — 승패가 달라질 수 있는 상한. **로그 줄 순서는 양쪽 효과가 있는 턴(2.32%)마다 바뀌어** `regress` 해시는 전부 바뀐다.

## 4. 새 구조

### 4-1. 핸들러 표와 실행기

`finishTurn.ts`에 효과 하나 = 표 한 줄을 둔다(지금 `EOT_INDIVIDUAL_STEPS`의 확장):

```ts
interface EotHandler {
  order: number;          // Showdown onResidualOrder(§3)
  sub?: number;           // onResidualSubOrder, 없으면 0 — 같은 스피드 안에서만 비교된다
  slot?: true;            // 기절한 자리 주인도 처리(미래예지·희망사항). 정렬은 일반 효과와 같다(자리 주인 스피드)
  deferWipe?: true;       // 같은 order 그룹이 끝난 뒤 한 번 전멸을 판정(order 1 날씨·24 멸망의노래)
  orderOf?: (f: BattleFighterState) => number; // 목록을 만들 때 상태로 order가 갈리는 것(상태이상 9/10)
  run: (ctx: EndOfTurnFighterContext) => void;
}
```
- 표는 **모듈 상수**(`EOT_HANDLERS`). §3의 한 행이 한 줄이다.
- **실행기** `runEndOfTurnHandlers(c)`:
  1. **스피드**: 각 포켓몬의 `computeTurnOrderSpeed(c.state, fighter)`(residual 직전의 지금 값 — Showdown `updateSpeed`와 같다). 이 함수는 랭크·마비·스카프·순풍·날씨 특성만 쓰는 **순수 스피드**이고 선제공격손톱·퀵드로는 `quickFirstChances`로 따로 있어 residual용으로 그대로 쓴다(검수 권고 1, 코드 확인). 트릭룸이면 비교를 뒤집는다(느린 쪽 먼저).
  2. **정렬 키**: `(order, 스피드(트릭룸이면 역순), sub, 동률 순위, 표 위치)`. 같은 포켓몬 안에서는 표 위치(Q2: 고정), 서로 다른 포켓몬이 **스피드가 정확히 같으면** 동률 순위로 정한다(Q1 (가')).
  3. **동속 동전(Q1 (가'))**: 정렬 전에, 양쪽 포켓몬 모두 핸들러가 있고 스피드가 같은 **`(order, sub)` 묶음마다** `random() < 0.5`를 한 번 뽑아 그 묶음에서 a가 먼저인지 b가 먼저인지 정한다. 뽑는 순서는 `(order, sub)` 오름차순(재현성). 스피드가 다르거나 한쪽만 핸들러가 있으면 난수를 쓰지 않는다.
  4. **실행**: 정렬된 `(핸들러 × key)`를 차례로 — `slot`이 아니고 holder가 기절했으면 건너뛰고, 실행 직전에 `makeEotCtx`로 **컨텍스트를 새로 만들고**(Q3: 도구·HP·상대 기절 여부가 앞 핸들러 결과를 반영), 실행 뒤 전멸 판정(§4-5). 전멸이면 중단.
- `eachFighter`·③④⑤ 루프·`eotOrder()`는 **삭제**하고 이 실행기가 대신한다(S0~S2는 단계별로 임시 키를 쓴다, §7).
- **전멸 판정**(`endIfWiped`)은 이미 **양쪽 포켓몬 모두**를 본다 — 핸들러가 보유자가 아닌 쪽을 쓰러뜨려도(해감액 씨뿌리기·미래예지 반동) 놓치지 않는다(검수 권고 3, 코드 확인). 인자(`lastFainted`)는 동시 전멸의 승자를 고르는 용도뿐이다.

### 4-2. 상태에 따라 order가 갈리는 효과

### 4-3. 같은 포켓몬 안의 현재 순서 보존
같은 포켓몬 안에서 지금 순서(면역 해제 → 그래스필드 → 탈피 → 먹다남은음식 → 아쿠아링 → 뿌리박기 → 씨뿌리기 → 상태이상 → 저주 → 속박 → 소금절이 → 물엿범벅 → 문어굳히기 → 카운터 틱 → 졸음)는 §3의 `order/sub`로 **그대로 재현된다**. 표 안의 동률 쌍은 **표 위치**로 고정한다: 속박→소금절이, 물엿범벅→문어굳히기(Q2: Showdown은 난수지만 둘 다 같은 포켓몬에 대한 피해/랭크 변화라 결과가 같다).

### 4-4. 자리(편) 효과(미래예지·희망사항) 순서 *(초안 폐기 후 재작성)*
Showdown은 자리 효과를 **자리 주인 포켓몬의 효과**로 수집해(§1-4) 그 포켓몬의 스피드로 정렬한다. 따라서 **별도 난수·특별 규칙이 없다** — 미래예지(3)·희망사항(4)는 일반 핸들러와 같은 키로 정렬되고(스피드가 같으면 일반 동속 규칙 §4-1 3), `slot: true`는 "주인이 기절해도 건너뛰지 않음"만 뜻한다. 주인이 기절해 있으면 Showdown은 `updateSpeed`가 건너뛴 이전 스피드를 쓰지만 그 경우 미래예지(`target.fainted`면 불발)·희망사항(기절이면 회복 없음)이 효과가 없어 관측 차이는 불발 로그 줄의 위치뿐이라 현재 스피드를 그대로 써도 된다.

### 4-5. 전멸 판정 시점 — `deferWipe`와 F-4 블록 삭제 (Q5 확정)
- **일반 핸들러**: PR #533대로 핸들러 하나가 끝날 때마다 `endIfWiped`. 한 핸들러가 `key`의 포켓몬을 쓰러뜨린 뒤 상대까지 쓰러뜨리면(해감액 씨뿌리기) 상대가 마지막이므로 상대 편 승리(`opponentKey(key)`).
- **`deferWipe` 그룹(order 1·24)**: 같은 order의 핸들러가 모두 끝난 **뒤에 한 번** 전멸을 판정한다 — Showdown의 날씨 핸들러 1개·멸망의노래 지속 종료형(`resolveFaints` 없이 `continue`)과 같다. 실행기는 핸들러 앞뒤로 두 포켓몬의 기절 여부를 비교해 **그 그룹에서 마지막으로 쓰러진 포켓몬**을 기록하고, 그룹 끝에서 `endIfWiped(c, 마지막으로 쓰러진 쪽)`을 부른다. **양쪽 다 전멸이면 마지막으로 쓰러진 쪽(= 스피드가 느린 쪽, 동속이면 동전 결과)이 이긴다**(`checkWin`, §1-7). 한쪽만 전멸이면 상대가 이긴다. 예비가 있으면 둘 다 쓰러져도 승패 없이 강제 교체.
- **F-4 삭제**: 멸망의노래 동시 기절을 따로 정하던 블록(`decideWinnerAndForcedSwitch`의 `perishFaintedKeys.size === 2` 분기)과 `c.perishFaintedKeys`·`c.speedA/speedB`·`applyPerishSongCountdown`의 boolean 반환을 삭제한다. 승자 규칙이 정렬 순서와 `deferWipe`에서 자연히 나온다 — **현행 F-4의 표시(둘 다 쓰러짐·느린 쪽 승)와 Showdown 모두와 맞는다**. 동속일 때만 "a 고정" → "동전"으로 바뀐다(Q5).
- **날씨**: 같은 방식 — 두 포켓몬의 모래바람 피해가 다 들어간 뒤 한 번 판정. 둘 다 쓰러지면 느린 쪽 승, 느린 쪽의 피해·기절 줄도 남는다.
- order 28·29·30 핸들러는 HP를 깎지 않아 일반 규칙(핸들러 뒤 판정)이면 충분하다.

## 8. 위험·알면서 두는 것

1. **컨텍스트 재생성(Q3)**: S0에서 분리 — 승패·해시가 어긋나면 컨텍스트 재사용 변형으로 한 번 더 쪼갠다.
2. **난수 소비 변화**: 완전 동속 + 양쪽에 같은 (order, sub) 핸들러가 있을 때만 새 난수가 생긴다. 변덕쟁이·탈피 등 기존 난수를 쓰는 효과는 포켓몬 간 처리 순서가 바뀌어 **난수열의 소비 순서**도 바뀌므로 해당 턴의 결과가 달라질 수 있다(상한은 409턴과 별개로 "난수 효과가 양쪽에 동시에 있는 턴").
3. **`deferWipe`의 "마지막 기절" 추적**: 핸들러 앞뒤로 두 포켓몬의 기절 여부를 비교해 기록한다. 한 핸들러가 둘 다 쓰러뜨리면 보유자(key) → 상대 순으로 기록(상대가 마지막). 그룹에서 아무도 쓰러지지 않으면 판정 없음.
4. **면역 해제(4.5)·열매 재확인(30)·`tickBlockVolatiles` 15**는 엔진 배치를 숫자로 옮긴 값이다(소스 값이 아님) — 코드 주석에 명시. 검수가 관측 차이 없음을 확인했다.
5. **옛 저장 영상·화면**: 저장된 로그는 그대로 표시된다. `EndOfTurnLines`는 항목마다 독립 줄을 렌더하고, HP 막대 연출(`turnFxSchedule.hpSteps`·`useTurnFx`)은 `endOfTurn`을 앞에서부터 항목 하나씩 재생하며 항목의 `actor`·`remainingHp`로 그 포켓몬 HP를 갱신하므로 서로 다른 포켓몬의 줄이 섞여도 동작한다(코드 확인). 연출이 "포켓몬별로 묶여 있다"고 가정하지 않는지는 사용자 판단(시험으로 화면 확인 대체 가능)을 받는다.
6. **`[실행]` 대조 미완**: `D3-덤프파일/fix-34-run.js`(사례 B·C·상호 씨뿌리기·자리 효과 시드 20개·동속 묶음 독립성 시드 200개·동속 교차·모래/멸망 동시 기절)는 Showdown 빌드가 되는 PC에서 `node fix-34-run.js`로 돌려 결과를 검수 파일 §5에 반영한다. 소스 판정이 확정 수준이라 구현을 막지 않는다.
