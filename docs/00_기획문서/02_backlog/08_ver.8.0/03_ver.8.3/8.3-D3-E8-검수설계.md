# ver.8.3 D3-E8 — 특성 216종 전수 검수 설계서 (초안, 사용자 검수 대기)

**상태**: 초안 2026-11-26. 사용자 결정(Q1~Q4, §6) 뒤에 확정하고 §4 순서로 진행한다. 1차 결과(우선 대상 일부)는 `8.3-D3-E8-검수.md`, 대응표는 `D3-검수자료/E8-특성대응표.md`.
**기준**: Showdown `965a535`(`~/showdown-ref`) `data/abilities.ts` + `data/mods/champions/abilities.ts` + `sim/` 코어. 엔진 `src/data/abilities.json`(216) + 플래그를 읽는 코드.

## 1. 지금까지 알아낸 것 (대응표 작업 결과)
- **216/216 매핑, 미매핑 0건**(E0와 같은 방식). 엔진 216 = Showdown 출전 216.
- 마스터 설계서의 "champions 실질 변경 9종"은 **7종**이다 — `angershell`(분노의껍질)·`wimpout`(도망태세)은 출전 가능 216종에 없다. 나머지 7종(`auraguard`·`eelevate`·`firemane`·`dragonize`·`megasol`·`piercingdrill`·`spicyspray`)은 **출전 허용만 바뀐 신규 특성**이라 동작은 기본 데이터·`sim/` 코어에서 확인한다.
- 훅 기준 자동 묶음: **③ 무효·면역 48 · ① 피격 반응 32 · ④ 등장 31 · ⑤ 턴 종료·상태 28 · ② 배율 68 · ⑥ 개별 9**(합 216). 마스터 설계서의 "① 피격 접촉 22·② 배율 33"은 엔진 구현 수였고, Showdown 훅 기준으로는 위와 같다.
- **샘플 파티가 쓰는 특성은 84종**(70개 파티 기준). 묶음별: ③ 19 · ① 15 · ④ 16 · ⑤ 11 · ② 21 · ⑥ 2.
- 엔진 데이터에 **동작 플래그가 없는 17종**은 코드에서 이름 문자열로 직접 찾는다(목록은 대응표 머리말).
- 특성은 데이터 플래그(`exitsFieldAtHalfHp` 등)로 정의되고 코드에는 특성 이름이 없다 — 검색은 **플래그명**으로 한다.

## 3. 항목마다 보는 것 (체크 순서)
1. Showdown 훅이 **언제·누구에게** 걸리는가(우선도·`onSource*`/`onAlly*`/`onFoe*`/`onAny*` 구분, 틀깨기 무시 여부 `breakable`·`suppressWeather`).
2. 엔진에서 같은 시점·대상에 걸리는가(플래그를 읽는 코드 한 곳씩).
3. **특성 억제·변경·무시**: 가스누출·스킬스왑·틀깨기 계열에서 훅이 꺼지거나 무시되는가.
4. **수치 식**: 배율(4096 체인 `q()`)·내림/반올림·최소 1 — 한 번 `[실측]` 식 비교를 한다.
5. 로그 문구는 판정 대상이 아니다(결과 값이 같으면 문제없음, 결과가 같고 순서만 다르면 개선권장).
