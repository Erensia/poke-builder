## 2. 상세

### 2-1. V3 — 정답은 모두 "문구"

| 기술 | Showdown champions | 엔진 필드 | 판정 → 수정 |
|---|---|---|---|
| 아이언헤드 | `secondary: {chance: 20, volatileStatus: "flinch"}` — **champions가 20으로 재정의**(mods/champions/moves.ts:540). 본가 gen9는 30 | `chance: 30` | 필드가 본가 값 그대로인 stale. **`chance: 20`** |
| 양날박치기 | `recoil: [1, 2]`(champions 재정의 없음) | `recoilFraction: 0.3333` | 필드 오기. **`recoilFraction: 0.5`** |
| 찬물끼얹기 | `secondary: {chance: 100, boosts: {atk: -1}}`만 있음. 화상 없음 | `inflictsStatus: burn, chance: 30` | 복사 실수. **`inflictsStatus` 삭제** |

- 원인 → 영향: 세 건 모두 필드만 고치면 문구와 일치하고, 허용 목록은 설계서 §3-3의 의도된 3건(킹실드·끈적끈적네트·데코레이션)만 남는다.
- 해시: 아이언헤드(풀죽음 판정 기준값), 양날박치기(반동 피해량), 찬물끼얹기(**화상 판정 난수 1회가 사라져 이후 난수열이 밀림**)는 모두 `regress` 해시를 바꿀 수 있다. 설계서 §5 ②대로 한 건씩 원인을 분리해 측정한다. 찬물끼얹기가 가장 넓게 번질 가능성이 높다.

### 2-2. V2 — 턴수 대조표 (Showdown champions 기준 재확인, 전부 일치)

champions는 표에 나온 기술의 지속 턴을 재정의하지 않는다(재정의는 `syrupbomb` 명중 90, `sandstorm` PP 5, `snaptrap` 타입뿐). 표현 차이가 있는 항목만 적는다.

| 항목 | Showdown | 설계서 표 | 판정 |
|---|---|---|---|
| 속박 4~5턴 | `partiallytrapped.duration = random(5, 7)` — 건 턴을 포함한 카운트라 피해는 4~5회 | `4 + floor(random×2)` | ✅ |
| 시럽봄 3턴 | `condition.duration: 4`, 건 턴 포함 → 스피드 하락 3회 | `syrupCoat` 3 | ✅ (엔진 3이 "하락 횟수"인지 구현 때 한 번 확인) |
| 잠자기 정확히 2턴 | champions는 일반 수면을 `sample([2,3,3])`로 재정의했지만 잠자기는 `statusState.time = 3`을 직접 넣어 덮어씀 → 2턴 | 정확히 2턴 | ✅ |
| 그 밖(날씨·필드·룸·방벽·순풍·사슬묶기·도발·소란·멸망의노래·난동류·사이코노이즈·지옥찌르기) | 기본 9세대 값 그대로 | 표와 같음 | ✅ |

### 2-3. K1c 보강 (권장)
- 확정 효과는 Showdown도 `chance: 100`으로 적는다(찬물끼얹기 공격 −1, 킬러스핀 독, 고속스핀 스피드 +1). 엔진 데이터가 100%를 `chance: 100`으로 적는 경우가 있다면 K1c가 오탐을 낸다.
- 규칙에 **"`chance < 100`인 필드만 K1c 대상"**을 명시하고, 시험 B3-d2(`chance: 100` · 문구에 확률 없음 → 경고 없음)를 추가한다.

### 2-4. 참고 — 집게덫 타입 (B3 범위 밖)
- champions `snaptrap: { isNonstandard: null, type: "Steel" }` — 사용 가능해지면서 **강철 타입**으로 바뀌었다. 문구 ↔ 필드 대조로는 잡히지 않는 항목이므로 `moves.json`의 `type`을 별도로 확인하고, 다르면 데이터 수정 항목으로 넘긴다.

## 3. 추가 범위 — 킬러스핀 · 독치장 (V6)

킬러스핀을 배우는 포켓몬은 champions에서 **킬라플로르 하나**다(learnsets). 킬라플로르의 특성은 독치장·부식이므로 둘이 같은 배틀에 자주 만난다(미러전).

### 3-1. 데이터 대조 (설계서 §0에 수동 대조 행으로 추가)

| 항목 | Showdown 값 | 대조 방법 |
|---|---|---|
| 킬러스핀 기본 | 독 · 물리 · 위력 30 · 명중 100 · 대상 상대 전체(싱글에서는 상대 1) | 수동 |
| 킬러스핀 독 | `secondary: {chance: 100, status: "psn"}` | K1(§2-3 규칙 적용 시 경고 없음이 정상) |
| 킬러스핀 제거 대상 | 시전자 편의 **압정뿌리기·독압정·스텔스록·끈적끈적네트** + 시전자의 **씨뿌리기·속박** | 수동(키워드 ↔ 필드 존재 대조는 Q7로 범위 밖) |
| 우격다짐 시 제거 생략 | `!move.hasSheerForce` 조건 | **M-C에서 발생 불가**(킬라플로르에 우격다짐 없음) — 대조 제외 |
| 독치장 | 물리 기술에 **피격**되면, 공격자 편 독압정이 **2층 미만**일 때 `-activate` 후 1층 추가 | 수동 |

### 3-2. 엔진 처리 순서 시험 (새 시험 `MS-a~f`)

- [소스] 독치장은 `onDamagingHit`, 킬러스핀 제거는 `onAfterHit`(대타출동이면 `onAfterSubDamage`)다. Showdown `spreadMoveHit`은 **피해 → 부가효과(독) → DamagingHit → AfterHit** 순서로 돈다.
- [실행] 공격 = 킬라플로르(부식, 킬러스핀), 방어 = 킬라플로르(독치장) 기준 실측:

| # | 상황 | Showdown 로그(요지) | 엔진 기대 |
|---|---|---|---|
| MS-a | 기본 | `-damage` → `-status psn` → `-activate Toxic Debris` → `-sidestart p2 Toxic Spikes` → `-sideend p2 Toxic Spikes [from] Mortal Spin` | 독압정이 깔렸다가 같은 행동 안에서 지워지고, **턴 끝에 공격자 편 독압정 0층** |
| MS-b | 공격자 편 독압정 이미 2층 | `-activate` 없음 → `-sideend Toxic Spikes` | 독치장 미발동, 기존 2층 제거 |
| MS-c | 공격자 편 스텔스록 + 공격자 씨뿌리기 | 독치장 설치 → `-end Leech Seed` → `-sideend Toxic Spikes` → `-sideend Stealth Rock` | 제거 순서는 **설치 순서가 아니라 고정 목록 순서**(씨뿌리기 → 압정 → 독압정 → 스텔스록 → 네트) |
| MS-d | 방어측이 대타출동 | `-activate Substitute [damage]` → `-sideend Stealth Rock`. 독치장·독 없음 | 대타가 맞으면 **독치장 미발동, 제거는 발동** |
| MS-e | 강철 타입 대상 | `-immune`. 제거 없음(스텔스록 남음) | 무효면 제거도 없음 |
| MS-f | 독치장이 아닌 대상 | `-status psn` → `-sideend Spikes` | 제거만 |

- 이 순서는 데이터가 아니라 엔진 처리 순서이므로 `validate-data`가 아니라 **시나리오 시험**으로 둔다. 파일은 `27-ver83-b3.mjs`에 함께 넣거나 별도 파일로 둔다(러너가 디렉터리를 읽으므로 어느 쪽이든 된다).
- 화면 문구는 B2(설치물 이벤트)의 문구 표를 따른다. "독압정이 깔렸다 → 사라졌다"가 **두 줄 모두** 나와야 Showdown과 같다(이전 세션에서 포챔스 실제 화면도 같은 순서임을 사용자가 확인).

### 3-3. 측정 단계에 미치는 영향
- 엔진이 이미 이 순서라면 시험만 추가 → **단계 ① 안에서 불변**.
- 엔진 순서가 다르면(예: 제거를 피해 직후에 처리해 독치장 독압정이 남음) 엔진 수정이 되므로 B3 범위를 넘는다. 이 경우 **단계 ③으로 나누어 따로 측정**하거나 별도 백로그 항목으로 분리한다. 구현 전에 엔진의 킬러스핀·독치장 처리 위치부터 확인할 것.
