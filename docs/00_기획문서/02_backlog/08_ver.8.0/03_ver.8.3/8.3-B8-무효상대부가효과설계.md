## 3. 설계

### 3-1. 엔진 (`mirroredEffects.ts`)
- `inflictStatuses`(`:560~`): 주 상태이상 블록(`:580` `else if (!c.opponentEffectsBlocked && c.effectiveMove.inflictsStatus)`)과 페이탈클로 블록(`:609` 조건)에 `damagingMoveLanded(c)`를 `&&`로 더한다. 인분(`secondaryEffectsBlockedByAbility`) 분기는 그대로(무효 상대에게 인분 문구가 안 뜨게 하려면 이 분기도 `damagingMoveLanded(c)` 안쪽에 둔다 — 구현 때 시험으로 확인).
- `inflictsVolatile` 루프(`:755~`): 루프 진입 조건에 `damagingMoveLanded(c)`를 더한다(상대 대상·자기 대상 모두).
- **벽 파괴(단계 ④)**: `mirroredEffects.ts`의 `damagingMoveLanded`를 `export`하고, `resolveAction.ts:648`의 `if (c.effectiveMove.breaksScreensOnHit)`를 `if (c.effectiveMove.breaksScreensOnHit && damagingMoveLanded(c))`로 바꾼다(`c`는 `MirroredCtx`와 같은 문맥인지 구현 때 타입 확인 — 안 맞으면 필요한 필드만 받는 얇은 인자로 한다). 이 블록은 현재 명중·무효를 안 보므로 빗나감·방어에도 깨지는지 B8-j에서 같이 확인한다. 레이징불도 같은 필드를 쓰므로 자동으로 포함된다.
- **자폭류**: 게이트가 이 경로를 막지 않아야 한다. 시전자 기절은 `selfFaints`(`types/move.ts:125`)로 처리되고 부가효과 블록과 별개다 — B8-i로 대폭발 vs 고스트에서 시전자가 쓰러지는지 확인한다.
- 변화기는 `damagingMoveLanded`가 항상 true라 영향이 없다. 대타에 맞은 데미지 기술은 true지만 효과는 기존 `blockedBySubstitute` 규칙이 계속 막는다.
- **전기자석파(Q3)**: 새 필드 `Move.respectsTypeImmunity?: boolean`(주석: Showdown `ignoreImmunity: false`). 전처리 단계(`preHitEffects.ts`)에서 변화기가 이 필드를 갖고 방어측 상성 배율이 0이면 `c.opponentEffectsBlocked`에 포함한다(기존 변수 재사용 — 황금몸·방음 등과 같은 "효과 차단" 취급). 문구는 기존 "효과가 없는 듯하다…"를 쓴다.

### 3-2. 데이터
전기자석파 레코드에 `"respectsTypeImmunity": true` 추가(V4로 대상 확정 뒤). `data-allowlist`·B3 점검(`validate-data`)에는 영향 없음.

### 3-3. 로그·화면
변경 없음(C7). 효과가 안 걸리면 해당 효과 줄이 자연히 안 나온다.

## 8. 알면서 두는 것 (백로그 한계로 옮길 후보)

- **AI 평가**는 이번에 조사·수정하지 않는다(C8). 엔진이 바뀌어도 AI가 무효 상대에게 부가효과 가치를 어떻게 세는지는 별도 확인 사항이다.
- **상성 무효 외의 "기술 실패" 경로**(특성 흡수 — 번개 vs 피뢰침·부유 vs 땅 기술·탈 등)에서 부가효과가 안 걸리는지는 이 설계서의 점검 대상이 아니다. D3 점검표(상성 무효 항목) 밖이면 D3에서 별도로 본다.
- 점검은 **단일 타입 포켓몬 7종**을 상대로 했다. 이중 타입의 한쪽이 무효인 경우(예: 땅/비행)는 같은 배율 계산을 타므로 대표성이 있다고 보되 B8-a가 일부 이중 타입을 포함하는지는 구현 때 확인한다.
- 전수 점검 스크립트는 임시 파일이었고 B8-a 시험이 이를 대체한다.
- **역린 고정 도중 2턴째에 상대가 무효 타입으로 바뀌는 경우**(검수 §2-3): Showdown은 `lockedmove` 고정이 풀리고 남은 턴 수에 따라 혼란 여부가 갈린다(`conditions.ts` `onAfterMove`·`onEnd`). 실행으로 확인되지 않았고, 엔진은 `updateRampage`가 `disrupted`(타입 무효)면 혼란 없이 종료한다. 차이가 있을 수 있어 백로그 한계로만 둔다.
- **V3는 소스 판정이다**(위 검수 반영). 실행 실측이 나오면 이 문서와 B8-j를 다시 맞춘다.
- 검수가 `showdown-code-map.md` §4("champions 재정의 3개뿐")를 정정했다 — 이 저장소 밖 문서라 우리 쪽 조치는 없다.
