# ver.8.3 D3-fix-18 — 불굴의마음은 풀죽음으로 행동이 막힐 때만 발동 (E4b-05)

**상태**: **검수 반영 확정(2026-11-20)** — Opus 5.5 검수(`8.3-D3-fix18-불굴의마음설계-검수.md`: 조건부 승인, 필수 1·권고 1) 반영. 구현 대기. 근거: `8.3-D3-E4b-검수.md` E4b-05.
**PR**: 1개·커밋 1개. 시험 `scripts/battle-ai-scenarios/49-ver83-d3fix18.mjs`.
**기준**: Showdown `965a535` `data/abilities.ts` `steadfast`: `onFlinch(pokemon) { this.boost({ spe: 1 }); }`. `data/conditions.ts` `flinch.onBeforeMove`가 `this.add('cant', …)` 뒤 `this.runEvent('Flinch', pokemon)`을 부르고 `false`를 돌려준다 — 즉 `Flinch` 이벤트는 **풀죽음 상태의 포켓몬이 행동하려다 막힐 때만** 일어난다. `flinch`는 `onBeforeMovePriority: 8`이라 수면·얼음(10)이 먼저 판정되어, 수면·얼음으로 못 움직이는 포켓몬에게는 발동하지 않는다. 이미 움직인 포켓몬은 막힐 행동이 없다.

## 1. 무엇이 다른가
엔진은 풀죽음이 **걸리는 순간**(`mirroredEffects.ts:1099` — `inflictedVolatile === "flinch" && defenderAbility.boostsStatOnFlinch`) 즉시 올린다. 그 결과:
- 대상이 이미 움직인 뒤 걸린 풀죽음(아무 효과 없는 풀죽음)에도 속도가 오른다.
- 대상이 수면·얼음으로 어차피 못 움직이는 턴에도 오른다(재충전·게으름 턴도 마찬가지 — Showdown은 이들이 풀죽음보다 먼저 막는다).
- Showdown에서는 위 두 경우 모두 오르지 않는다.
- **정정(검수 §2-1, 필수)**: 초안은 "마비·혼란 자해 턴에도 오른다(Showdown은 안 오름)"라고 적었으나 **틀렸다.** Showdown에서 풀죽음(`onBeforeMovePriority` 8)은 혼란(3)·헤롱헤롱(2)·마비(1)보다 **먼저** 판정되므로, 풀죽음 + 혼란/마비인 불굴의마음 포켓몬은 **항상 속도 +1**이고 혼란 지속도 줄지 않으며 자해·마비 굴림도 없다. Showdown에서 오르지 않는 경우는 ① 이미 움직인 뒤 ② 수면·얼음(·재충전·게으름)으로 먼저 막힌 턴뿐이다. **구현자는 "혼란·마비면 발동 안 함" 가드를 넣지 않는다**(시험 7·9가 이를 고정).
같은 턴에 대상이 아직 움직이기 전이고 정상 행동 가능이면 두 구현이 같다(올라가는 시점이 행동 시도 시점 vs 부여 시점 — 같은 턴 안이라 관측 동일).

## 2. 고칠 것
1. `mirroredEffects.ts:1099` 풀죽음 부여 직후의 즉시 발동 블록을 **삭제**한다.
2. `preHitEffects.ts` `checkActionBlockers`의 풀죽음 판정(약 367~370행, `hasVolatile(attacker, "flinch")` → `consumeVolatileTurn` → `blocked("flinch")`)에서 막히는 순간 `c.attackerAbility?.boostsStatOnFlinch`가 있으면 같은 `applyStageDelta(c.attacker.stages, boost.stat, contraryDelta(c.attacker, boost.delta))`를 적용한다.
3. **로그 호환**: 현재 즉시 발동은 로그에 별도 줄을 남기지 않는다(필드 없음) — 이 PR도 새 필드를 만들지 않는다(사용자 결정 2026-11-18 "새 로그 줄·필드 추가 안 함"의 연장). 랭크 변화는 상태 스냅샷으로만 드러난다.
4. 수면·얼음 판정이 풀죽음보다 앞서므로 별도 가드 없이 자연스럽게 Showdown 순서가 된다. **재충전**(우선도 11)도 풀죽음보다 먼저 막아야 한다 — 엔진이 재충전을 `checkActionBlockers`의 풀죽음 판정 **뒤**에서 처리하면 잘못 오르므로 구현 첫 단계에서 재충전 처리 위치를 확인하고 시험 10으로 고정한다(검수 §2-2). 랭크 +6 상한은 `applyStageDelta`가 지키면 별도 처리 불필요(검수 §2-3, 참고).

## 3. 영향·측정
불굴의마음 보유 포켓몬이 풀죽음을 맞는 시뮬 한정(그중 이미 움직인 뒤·못 움직이는 턴만 변동). 해시는 불변 또는 아주 작은 변동 예상 — `regress 200`·`regress 20000`·`STATUS=1 greedy 60`(약 3분) 뒤 `SERIAL=1 verify.sh`. AI(`ai/`)가 불굴의마음을 풀죽음 기대값에 반영하는지(`boostsStatOnFlinch` grep) 구현 첫 단계에서 확인하고, 반영한다면 "막히는 경우만"으로 맞춘다.

## 4. 시험 `49-ver83-d3fix18.mjs`
풀죽음 100% 기술(예: 속여때리기류 — 구현 때 `moves.json`에서 `chance` 없는 flinch 기술을 고른다)과 불굴의마음 포켓몬을 쓴다.
1. **정상**: 공격측이 먼저 움직여 풀죽음을 걸면 대상(불굴의마음)은 그 턴 행동하지 못하고 속도 랭크 +1(현행도 통과 — 불변 확인).
2. **이미 움직인 뒤**: 공격측이 느려서 대상이 이미 움직인 뒤 풀죽음이 걸리면 **속도 랭크 변화 없음**(현행은 +1 → 실패).
3. **수면 대상**: 수면인 불굴의마음 포켓몬에게 풀죽음 → 랭크 변화 없음(현행 +1 → 실패).
4. **얼음 대상**: 같음(현행 +1 → 실패).
5. **풀죽음 면역 특성**(정신력 등) 대상: 부여 자체가 막혀 랭크 변화 없음(불변).
6. **다른 특성**(불굴의마음 아님): 풀죽음으로 막혀도 랭크 변화 없음(불변).
7. **마비 12.5% 행동 불능이 풀죽음보다 뒤**(fix-17 이후 순서): 풀죽음이 마비보다 먼저 막으므로 풀죽음 상태에서 속도 +1(순서 의존 — fix-17 머지 후 확인).
8. `contrary`(심술꾸러기) 포켓몬은 −1(기존 `contraryDelta` 유지).
9. **풀죽음 + 혼란(검수 §2-1)**: 풀죽음 상태의 혼란 불굴의마음 포켓몬 → 속도 +1, **혼란 지속 그대로**, 난수 0회(엔진 순서 ② 풀죽음 → ⑤ 혼란이라 현행 구조에서 통과 예상 — 불변 확인용).
10. **재충전 + 풀죽음(검수 §2-2)**: 재충전 턴(기가임팩트·파괴광선 뒤)인 불굴의마음 포켓몬에게 풀죽음 → 재충전이 먼저 막아 랭크 변화 없음. 루카리오·엘레이드·괴력몬 모두 챔피언스에서 이 기술들을 배운다(게으름은 동시 보유가 특성 교체로만 가능해 생략).
