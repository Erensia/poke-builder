## 1. 문제
Showdown(`gen9championsbssregmc`)의 매직미러는 `reflectable` 플래그가 붙은 변화기를 되돌린다. 엔진은 "상대를 향한 효과가 있는 변화기"(`isOpponentTargetingMove`) 또는 설치기(`setsHazard`)에서 `notReflectable` 8종을 뺀 집합으로 판정해, **`reflectable` 60종 중 세 기술이 빠진다**.

| 기술 | Showdown 실행 결과(하마돈이 에브이 매직미러에게) | 엔진 현행 |
|---|---|---|
| 날려버리기·울부짖기 | 반사 → **사용자(하마돈)가 예비 포켓몬으로 끌려 나감**. 에브이는 그대로 | 반사 안 됨 → 에브이가 끌려 나감 |
| 뒤집어엎기 | 반사 → **사용자의 랭크 변화가 뒤집힘** | 반사 안 됨 → 에브이의 랭크가 뒤집힘 |

**`[실측]`** 엔진 판정을 이식해 Showdown `reflectable` 집합과 비교: 엔진 56종 · Showdown 60종 · **엔진에만 0 · Showdown에만 4**(울부짖기·날려버리기·뒤집어엎기 + 버섯포자는 엔진 데이터에 없는 기술이라 제외, E0). 반대 방향(엔진이 더 반사)은 0건이라 이번에는 **추가만** 한다.
**도달 가능성**: 샘플 매직미러 1파티, 날려버리기 15·울부짖기 1파티. `regress` 해시가 바뀔 수 있다.

## 2. 변경
### 2-1. 반사 판정 공용 함수 (`src/lib/fieldEffects.ts`)
`isOpponentTargetingMove`에 세 기술을 넣지 **않는다** — 그 함수는 사이코필드 우선도 차단·방어(막힘) 판정에도 쓰여 동작이 같이 바뀐다(사이코필드가 울부짖기를 막는지는 Showdown에서도 따로 정해진다). 대신 신규 함수를 둔다.

```ts
/** 매직미러가 되돌릴 수 있는 변화기 — Showdown `reflectable` 플래그와 같은 집합(8.3 D3-fix-44). */
export function isMagicBounceReflectable(move: Move): boolean {
  return move.category === "status" && !move.notReflectable &&
    (isOpponentTargetingMove(move) || !!move.setsHazard || !!move.forcesTargetSwitch || !!move.invertsTargetStatStages);
}
```
사용처 세 곳을 이 함수로 바꾼다(AI와 엔진이 같은 판정을 쓰게):
1. `preHitEffects.ts` 681행 `bouncedByMagicMirror`(엔진 본체) — `category === "status"`·`!notReflectable`·`(isOpponentTargetingMove || setsHazard)` 조건 대체.
2. `ai/statusMoveEffects.ts` 348행(AI의 "무의미한 기술" 판정).
3. `ai/opponentMoveModel.ts` 99행(AI의 상대 기술 모델) — **이 곳은 현재 `isOpponentTargetingMove`만 보고 `blocksOpponentStatusMoveEffects`와 묶어서 판정**한다. 황금몸은 건드리지 않는다(Showdown 황금몸은 `target !== source`인 모든 변화기를 막아 강제 교체·뒤집어엎기도 막지만 이번 범위 밖 — §5). 반사 조건만 새 함수로 분리한다.

### 2-2. 반사된 강제 교체 (`runTurn.ts` `forceTargetSwitch`)
현재 `!action.bouncedMoveName`이 반사된 기술을 강제 교체에서 제외한다(주석 372·476행의 shortcut). 반사되면 **끌려 나가는 쪽이 사용자(key)**여야 한다.
- 대상 키 = `action.bouncedMoveName ? key : opponentKey(key)`로 일반화. 나머지 가드(`hasLivingReserve`·`isForcedSwitchBlocked`·기절·끌려 나온 쪽 `didSwitch`)는 대상 키 기준으로 그대로 적용한다. `isForcedSwitchBlocked(대상, 공격 특성)`의 두 번째 인자(틀깨기 무시 판단)는 **반사 시 기술을 쓴 쪽이 아니라 반사한 쪽**의 특성을 넘긴다(틀깨기가 매직미러를 무시하면 애초에 반사되지 않으므로 이 경로는 틀깨기가 아닌 경우뿐).
- **방음(Q1, 이번 PR에 포함)**: 반사된 강제 교체 분기에서 기술이 소리 기술(`classification`에 "소리")이고 **사용자(끌려 나갈 쪽)의 특성이 방음**이면 교체하지 않는다 — Showdown 방음 `onTryHit`은 반사된 울부짖기의 `target`(원래 사용자)를 막는다. 챔피언스에서 방음 + 울부짖기를 배우는 포켓몬은 짜랑고우거·바리톱스, 매직미러 보유자는 5종(에브이·브리무음·메가 픽시·메가 깜까미·메가 앱솔)이라 도달 가능하다. 수정 전(매직미러 쪽이 끌려 나감)·수정 후 가드 없음(방음 사용자가 끌려 나감) 모두 Showdown(아무도 안 나감)과 달라서 이 PR이 경로를 새로 여는 김에 함께 닫는다. 가드 1개 + 시험 13.
- 반환값(`oppForcedOut`)은 "방어측이 끌려 나갔는가"로 쓰이고(위기회피·탈출버튼 가드), 반사 시엔 방어측(매직미러 쪽)이 그대로이므로 **반사 시 false**를 반환한다(상태기라 어차피 위기회피·탈출버튼은 평가되지 않는다 — 안전).
- 데미지 기술 드래곤테일·배대뒤치기는 `category !== "status"`라 반사되지 않으므로 이 경로에 영향 없다.

### 2-3. 뒤집어엎기
`mirroredEffects.ts` 518행 `invertsTargetStatStages`는 반사 구간(공격/방어 바인딩이 맞바뀐 블록) 안에서 실행되므로 **반사 판정만 열리면 자동으로 사용자에게 적용**된다(스텔스록 설치와 같은 방식). 별도 수정 없음 — 시험으로 확인한다.

## 5. 알면서 둔 것
- **황금몸 ↔ 울부짖기·뒤집어엎기**: Showdown 황금몸은 `target !== source`인 모든 변화기를 막는다(강제 교체 기술 포함). 엔진 `blockedByGoodAsGold`는 `category === "status"`로 막아 이미 일치할 가능성이 높지만 이 PR에서 대조하지 않는다(E8-b).
- **반사된 울부짖기 vs 사용자 방음**은 §2-2에서 이번 PR에 포함(Q1). 방음 가드는 강제 교체 분기에만 둔다 — 반사 구간의 다른 소리 변화기(예: 노래 계열 `classification: 소리`의 상태이상기)의 방음 처리는 기존 반사기와 같은 한계로 **E8 백로그**.
- **황금몸·짓궂은마음 도달성(검수 S1)**: champions에서 세 기술을 배우는 황금몸·짓궂은마음 보유자가 없어 "반사된 기술이 사용자의 황금몸에 막힘"·짓궂은마음 우선도 무효 순서는 **도달 불가**로 기록만 한다.
- **막말내뱉기(`selfSwitchIfStatLowered`) 반사 shortcut**(`runTurn.ts` 372행)은 별개라 건드리지 않는다.
- E8-11·12(클리어바디 명중 하락·옹골참 자해)는 이번 PR과 무관(개선권장, 기록만).
