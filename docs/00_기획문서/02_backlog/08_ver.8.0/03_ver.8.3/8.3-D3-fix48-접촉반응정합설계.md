- **E8-26 원인**: `abilities.json`의 `hitTrigger.on`을 정한 Phase 5가 "정전기·불꽃몸 = 물리 접촉을 받으면"으로 읽었다(`types/ability.ts` 87행 주석). Showdown은 `onDamagingHit`에서 `checkMoveMakesContact`만 본다(카테고리 조건 없음). `physicalContact`를 쓰는 특성은 **정전기·불꽃몸·독가시 3종뿐**이고 코드 사용처는 `abilityHitTriggers.ts` 매처 하나(스크립트·화면 사용 없음).
- **E8-27 원인**: `hitResolution.ts` 634행 블록(`disablesAttackerMove`)이 PP만 0으로 만든다. 이미 있는 사슬묶기 경로(`mirroredEffects.ts` `setsDisable`, `inflictVolatile(…,"disable",…)`, 지속 `DISABLE_DURATION = 4` = Showdown 5에서 "아직 안 움직임 −1", 아로마베일 `blocksMentalMoves`, 멘탈허브 `getMentalHerbCureResult`)를 쓰면 지속·치료·면역이 한 번에 맞는다. 기술 선택 차단은 `volatile.active.disable`을 보는 기존 경로(`battleRules.ts`·`moveRestrictionKind`)가 사슬묶기와 똑같이 처리한다.
- **E8-28 원인**: 드레인만 타 처리 뒤에 있다. 드레인 기술 8종(기가드레인·드레인펀치·드레인키스·원념의칼·흡혈·파라볼라차지·우드혼·휘적휘적포)은 **전부 단발·비고정 데미지**(`maxHits`·`fixedDamage` 없음)다 — 순서를 옮길 곳은 단발 분기와 이번엔 쓰이지 않는 다단·고정 분기의 같은 자리다.

## 2. 변경

### 2-1. E8-26 — 데이터 3건 + 사용되지 않는 값 정리 (① 단계)
1. `src/data/abilities.json`: 독가시·정전기·불꽃몸의 `hitTrigger.on`을 `"physicalContact"` → `"contact"`. **줄 단위 치환**(재직렬화 금지, 작업 복사본 CRLF). `npm run validate:data`.
2. `src/lib/abilityHitTriggers.ts`·`src/types/ability.ts`: 이제 아무 데이터도 쓰지 않는 `"physicalContact"`(유니언 값·`case`·주석)을 **지운다**(`grep`으로 사용처 0 확인 후). 사용처가 늘 가능성(YAGNI)이 없다.
3. `docs/데이터변경이력.md`에 한 항목(특성 3건, 기술·포켓몬 수치 불변).
- **AI**: `hitTriggerMatchesMove`는 AI(`moveDamage.ts` 접촉 데미지 추정)도 쓴다 — 매처는 그대로라 변경 없음(`damagesAttackerFraction`은 까칠한피부 `contact`).
- **영향**: 정전기·독가시가 특수 접촉기(4종)에도 확률 30%로 발동 — 샘플 도달 작음, `regress` 변동은 무작위 빌드에서 4종 기술과 3종 특성이 만나는 장면에 한한다.

### 2-2. E8-27 — 저주받은바디를 4턴 봉인(사슬묶기 경로)으로 (② 단계, `hitResolution.ts` 634행 블록)
PP 0 블록을 아래로 교체한다(조건 순서는 Showdown `cursedbody`·`disable.onStart`):
- 발동 자격: 현행 `!c.delayedHit`(미래예지 등은 무발동, Showdown `futuremove`)·`remainingPp[c.move.id] !== undefined`(발버둥은 PP 기록이 없어 자연히 제외 = Showdown `struggle`)를 **유지**하고, 추가로
  - **`remainingPp[c.move.id] > 0`**(마지막 PP를 쓴 직후면 `onStart`가 실패 — 이 시점은 PP가 이미 1 깎인 뒤다),
  - **`!hasVolatile(attacker.volatile, "disable")`**(이미 봉인 중이면 무발동, 기존 봉인 유지),
  - **`!c.attackerAbility?.blocksMentalMoves`**(아로마베일 — 사슬묶기·헤롱헤롱바디와 같은 플래그, Showdown 실행 `G5` 0/60).
- 부여: `attacker.volatile = inflictVolatile(attacker.volatile, "disable", c.random, c.move.id)` — **지속 보정 0**(`targetAlreadyActedAdjust`는 쓰지 않는다: 저주받은바디는 공격측이 지금 움직이는 중이라 Showdown이 "아직 안 움직임"과 같게 `duration--` 처리하므로 기본값 4가 정확하다).
- 멘탈허브: `getMentalHerbCureResult(c.attackerItem, c.attacker.itemConsumed ?? false)`이면 방금 건 `disable`을 지우고 도구를 소모(`consumeItem`)하며 `c.statusCureBerryItemName`을 채우고 로그 필드(`abilityDisabledMoveName`·`ev.disabledMoveName`)를 비운다 — 헤롱헤롱바디 분기(`hitResolution.ts` 556~565행)와 **같은 패턴**이다(같은 6줄 복제를 3번째로 늘리지 않도록 구현 때 공용 소함수로 묶을지 판단한다).
- 로그: 기존 필드(`abilityDisabledMoveName`·`abilityDisableAbilityName`)를 그대로 쓴다 — **새 문구·UI 없음**. 이후 그 기술을 고르면 기존 사슬묶기 경로가 `moveRestrictionKind: "disable"`로 막는다.
- **AI**: `disablesAttackerMove`를 읽는 곳은 엔진뿐(AI 모델링 없음). 선택 차단은 기존 `disable` 처리가 맡아 변경 없음.
- **영향**: 팬텀·포트데스(샘플 5슬롯)에게 맞은 공격측이 4턴 뒤 그 기술을 되찾는다 — 지금은 영구 봉인이라 `regress`가 가장 의미 있게 바뀔 단계다.

### 2-3. E8-28 — 드레인 회복(해감액 포함)을 접촉 반응 앞으로 (③ 단계)
- `applyRecoilAndDrain`의 **흡수기 블록**(`hitResolution.ts` 967~985행, 해감액 포함)을 함수 `applyDrainHeal(c)`로 빼고, **타 처리 직후·`triggerAbilityHitEffect` 직전**(= `applyDamageToDefender`·`applyEndurance` 다음)에 호출한다 — 단발 분기(787~798행)와 고정·다단 분기의 같은 자리(다단은 루프 뒤). `applyRecoilAndDrain`에서는 지운다. 조건·식은 **그대로**(`actualDamageDealt > 0`·`drainFraction`·큰뿌리·회복봉인·해감액).
- 반동 → 생명의구슬 → 조개껍질방울은 **현행 순서 그대로**(Showdown도 반응 뒤: 반동은 모든 타 뒤, 아이템 효과는 `AfterMoveSecondarySelf`)이므로 건드리지 않는다. 시험 25로 고정.
- **AI**: 기대 손실 추정(`moveDamage.ts` 242행)은 순서와 무관한 기댓값 합산이라 변경 없음.
- **영향**: 흡수기 16슬롯 × 접촉 반응 71슬롯. 풀피에서 쓰는 드레인은 회복이 사라지고(상한), 낮은 HP에서는 회복이 먼저라 반응으로 쓰러지는지 판정이 바뀐다. 해시 변동이 세 단계 중 가장 클 수 있다.
- **분리(이번에 안 함)**: 드레인 양이 Showdown은 `Math.round`(최소 1)인데 엔진은 `Math.floor` — E10 후보로 이미 기록됨(fix-32). 순서만 옮기고 식은 건드리지 않아야 단계별 해시 원인이 순서 하나로 분리된다.
