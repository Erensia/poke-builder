## 0. 요약
- **지금 학습**: 상대(사용자)가 실제로 고른 행동을 "예측 합 대 실제 횟수"로 집계해(대전마다 ×0.99) 상대 행동 분포를 보정한다. 보정 대상은 ① 교체 확률(사전 0.15, 강도 10) ② 변화기 사용률(사전 1, 강도 10) ③ 종별 기술 습관(사전 1, 강도 2). 사용률 λ는 보정 배율에 거듭제곱(랭크 AI 마스터볼 단계 활용).
- **문제**: 승률로 보면 이득이 작다(60.5 → 63.0%, 오차 안). 그런데 승률 3%p는 수천 판이 있어야 구분되므로 **학습이 실제로 상대를 잘 맞히는지**와 **맞히는데 승률에 안 옮겨지는지**를 가르지 못한다.
- **제안**: 승률 대신 **상대 행동 예측 정확도(로그 손실)** 를 1차 지표로 쓴다. 판 하나에 수십 개 관측이 나와 수백 판으로 구분되고, 학습이 하는 일(상대 예측)을 직접 잰다. 여유(headroom)가 없으면 폐기한다.

## 1. 목표·측정·중단 조건
| 항목 | 내용 |
|---|---|
| 목표 | 학습된 보정이 상대 행동을 더 잘 맞히게 한다 → 같은 AI 단계에서 승률이 오른다. 단 **판단 시간·저장 크기·감쇠 구조는 안 바꾼다**(C2-b 소관) |
| 대상 상대 | `style` 모드 봇 3종(`STYLE=switcher\|setup\|noisy`)과 무작위 정책. 실제 사람은 잴 수 없으므로 "습관이 있는 상대"의 대용이다 |
| M0(측정 1: 현재 학습의 예측 곡선) | `LEARN=1`·`style` 봇 상대 각 300판(좌우 교대). 관측마다 **원래 추론 분포(보정 전)** 와 **보정 후 분포** 가 실제 행동에 준 확률을 기록해 판 번호 구간별(1~25·26~100·101~300) 평균 −log p를 낸다. 교체·변화기·기술 세 갈래를 따로 본다 |
| M0 판정 | 보정 후가 보정 전보다 손실이 **5% 이상 낮은 갈래**가 있고, 포화 학습기(같은 봇을 300판 먼저 학습한 기억으로 시작)와의 차가 **현재 학습기 손실의 5% 이상**이면 여유 있음(개선 후보 진행). 그렇지 않으면 폐기 |
| 개선 후보(M0가 진행 판정일 때만, 하나씩) | **H1** 사전 강도 조정(교체 10·변화기 10·기술 2 — 갈래별 손실 곡선에서 초반이 느리거나 과적합이면) · **H2** 감쇠(0.99/0.995) 재조정은 **C2-b 설계와 얽혀 제외**(§4) · **H3** 분포 온도(tau)를 상대별로 보정(상대가 예측보다 더 결정적/무작위일 때) |
| M1(구현 후) | 같은 시드 **짝 비교**: 변경 전후 AI 선택이 갈라진 판만 모아 승패 변화를 본다(C5 검수 방식). 판단 시간 +20% 미만 |
| 중단 | ① M0가 여유 없음 ② M1이 갈라진 판에서 순이득 없음 ③ 판단 시간 +20% 이상 |
| 불변 | 엔진 규칙·`test:inference` 결합 해시·계산 함수 차분 해시. **학습이 꺼진 출력**(`regress`·`greedy`·`status60`·`h2h40`)도 불변이어야 한다(학습은 `opponentMemory`를 넘길 때만 켜짐). `ai60`은 학습을 쓰는 프로필이 있으면 바뀔 수 있다 — 단계별 측정 |

## 2. 규칙 근거
규칙이 아니라 AI 추정 보정이다. Showdown 검수 대상 아님.

## 3. 설계 (M0가 진행 판정일 때만)
- H1·H3 중 M0 곡선이 가리키는 **하나만** 한 PR에 담는다. 각각 `opponentMemory.ts`의 상수·`calibrateDistribution`에 국한(예: 사전 강도를 갈래별로 조정, 온도 보정 한 항 추가).
- 사용자 저장 기억 형식(`OpponentMemory` version 1)은 **바꾸지 않는다**(바꾸면 C2-b와 함께). H3이 필드를 더하게 되면 설계서를 다시 열어 사용자와 정한다.
- 시험: `scripts/battle-ai-scenarios/`에 보정 배율 시험 추가(기존 `1-C` 시험 위치 확인 후) — 기록이 없을 때 교체 예측 15%만 믿는 동작 불변 등.

## 4. 범위 밖
- **C2-b 동기화 합치기**(감쇠 집계라 합칠 수 없음): 기기별 파티션 구조 등 클라우드 형식 변경이 필요해 따로 설계한다. 감쇠 상수(H2)는 이 설계와 얽혀 C2-b에서 함께 본다.
- 새 학습 대상(선출·리드 습관 등): 이번엔 하지 않는다(YAGNI, 측정 근거 없음).

## 5. 해시·검증 예상 (믿지 말고 단계마다 잰다)
- M0 측정용 스크립트는 일회용(`scripts/zz-*.mjs`, 커밋하지 않음). 구현이 진행되면 M1용 도구는 항목 PR에 포함하는 안을 사용자와 정한다.
- 측정 시작 전 "명령·예상 시간" 보고: M0 — 봇 3종 × 300판 + 무작위 + 포화 기준, 판당 약 1.2초(MODEL_ONLY, 2프로세스 병렬) → 약 25분 예상(실측 후 갱신).

## 6. 구현 순서·PR
M0 측정 → (여유 없음이면 백로그 C2-a에 근거를 적고 종료, 문서만) → (여유 있음이면) 시험 먼저 → H1 또는 H3 구현 → M1 → `SERIAL=1 verify.sh` → PR 1개(커밋 1개) → 머지. 화면 확인은 없음(AI 보정 수치만 바뀜). C2-b는 이 항목이 끝난 뒤 별도 설계서.

## 8. 알면서 두는 한계(예정)
- 봇은 사람과 습관 구조가 다르다. 사람에게서의 이득은 이 측정으로 보장되지 않는다.
- 학습은 AI가 마스터볼 이상 단계에서만 쓴다(랭크 정책). 하위 단계 승률에는 영향이 없다.
