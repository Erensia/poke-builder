# 8.3 B8 설계서(타입 무효 상대에게 부가효과가 적용되는 결함) 검수 결과 — Showdown 대조

- 기준: smogon/pokemon-showdown `965a535`(2026-11-10, B7 검수와 같은 커밋). 싱글 `gen9championsbssregmc`
- 방법: **[소스] 코드 확인만.** 이번 세션은 `npm ci`(빌드)가 권한 거부되어 실행 실측을 못 했다. 실행 근거는 B7 검수의 실측(Nuzzle vs Ground `-immune`, Mortal Spin vs Steel `-immune`)을 재사용한다. V3는 기본안을 뒤집는 판정이라 **구현 전에 실행 실측 1회를 권장**한다(§5)

## 1. 판정 요약

| 항목 | 판정 |
|---|---|
| V1 상성 무효 → 부가효과 전부 없음 | ✅ 기본안대로. 부가효과(`secondaries`)는 무효 판정 뒤 단계에서만 처리된다 |
| V2 파괴광선류 vs 고스트 → 재충전 | ✅ **안 함**(기본안대로). 자기 대상 효과(`self`)도 무효 판정 뒤 단계다 |
| **V3 깨트리기·사이코팽 vs 무효 상대 → 벽** | ❌ **기본안과 반대 — 벽이 깨지지 않는다.** 기술의 `onTryHit`는 1단계 `TryHit` 이벤트가 아니라 **상성 무효 판정 뒤**(`spreadMoveHit`)에서 실행된다. 엔진 현행 동작이 결함이며 B8에서 같이 고친다(§2-1) |
| V4 상성 무효가 적용되는 변화기 | ✅ **전기자석파 하나뿐**(`ignoreImmunity: false`인 변화기 전수 = 1). champions mod 재정의 없음 |
| V5 실패 반동(무릎차기·발꿈치찍기) | ✅ 상성 무효에서도 반동(`onMoveFail`)이 일어난다(기본안대로) |
| Q1·Q2 게이트(`damagingMoveLanded`) | ✅ 방향 동의. 단 **역린·난동·소란의 고정(lock) 자기 휘발**, **속이기**가 §0-1 목록에 없다 — 시험으로 확인 필요(§2-3) |
| Q3 전기자석파 필드 | ✅ 동의. 판정 타입은 **실효 타입**(타입 변경 특성 반영 뒤)을 쓸 것(§2-4) |

**결론: V3만 고치면 착수 가능.** 벽 파괴에도 같은 게이트를 걸고, B8-a 허용 예외에서 벽 파괴를 빼고, 자폭류(시전자 기절)를 허용 예외에 넣는다.

## 2. 상세

### 2-1. V3 — 벽 파괴는 상성 무효 판정 뒤다 (기본안 정정)

Showdown gen7+ 기술 처리 순서(`sim/battle-actions.ts` `trySpreadMoveHit`, `:612~640`):

| 단계 | 함수 | 내용 |
|---|---|---|
| 0 | `hitStepInvulnerabilityEvent` | 공중날기 등 |
| 1 | `hitStepTryHitEvent` | `runEvent('TryHit', …)` — **대상 쪽 핸들러**(방어·매직미러·축전 등) |
| 2 | `hitStepTypeImmunity` | **상성 무효** → `-immune`, 기술 종료 |
| 3 | `hitStepTryImmunity` | 가루 면역 등 |
| 4 | `hitStepAccuracy` | 명중 |
| 7 | `hitStepMoveHitLoop` → `spreadMoveHit` | **기술 자신의 `onTryHit`**(`singleEvent('TryHit', moveData, …)`, base `:1101` / champions `scripts.ts:332`) → 대타 → 데미지 → `self`(`:1153`) → `secondaries` |

- 원인: 1단계 `runEvent('TryHit')`는 `onEffect` 인자 없이 호출되어 **기술 자신의 핸들러를 포함하지 않는다**(`battle.ts` `runEvent`는 `onEffect`일 때만 `sourceEffect.on…`을 넣는다). 깨트리기·사이코팽(`data/moves.ts` `brickbreak`·`psychicfangs`, `onTryHit`에서 `removeSideCondition`)의 벽 제거는 7단계의 `singleEvent('TryHit')`에서 돈다.
- 영향: **고스트에게 깨트리기, 악에게 사이코팽 → `-immune`, 벽 유지.** 설계서 C6의 기억("1단계에서 처리해 무효 상대에게도 깬다")은 단계 1과 기술 자신의 `onTryHit`를 혼동한 것이다. 코드 주석 "will shatter screens through sub, before you hit"는 **대타보다 먼저**라는 뜻이다(대타 판정이 같은 함수에서 `onTryHit` 바로 뒤).
- 엔진에 필요한 것: 벽 파괴 블록에도 `damagingMoveLanded(c)`를 건다. 이 게이트로 Showdown과 맞는 경우:

| 상황 | Showdown | `damagingMoveLanded` |
|---|---|---|
| 무효 상대(고스트·악) | 안 깸 | false → 안 깸 ✅ |
| 대타에 맞음 | **깸**(`onTryHit`가 대타보다 앞) | true(대타 적중) → 깸 ✅ |
| 방어(Protect) | 안 깸(1단계에서 막힘) | false ✅ |
| 빗나감 | 안 깸(4단계) | false ✅ |
| 탈(Disguise) | 깸(탈은 데미지 단계) | true(이론 데미지 > 0, B7 §2-1) ✅ |

- 참고: 레이징불(`ragingbull`)도 같은 구조지만 champions 학습자가 켄타로스(팔데아) 계열뿐이다. 엔진 데이터에 있으면 같은 게이트를 쓴다.

### 2-2. V1·V2·V5 — 무효 판정 뒤에 오는 것 / 앞에 오는 것

| 효과 | 위치 | 무효 상대일 때 |
|---|---|---|
| 상태이상·풀죽음·혼란·회복봉인·도망 불가(`secondaries`, 그림자꿰매기 `secondary.onHit` 포함) | 7단계 `spreadMoveHit` 5번 | 없음 (V1) |
| 재충전·고정(`self.volatileStatus`: `mustrecharge`·`lockedmove`·`uproar`) | 7단계 `selfDrops` (champions `scripts.ts:384`도 같음) | 없음 (V2) |
| 페이탈클로 무작위 상태이상(champions 재정의, `secondary.onHit`) | 7단계 | 없음 |
| 실패 반동 `onMoveFail`(무릎차기 `baseMaxhp / 2`·발꿈치찍기) | `useMoveInner` `:591`, `trySpreadMoveHit`가 false면 호출 | **있음** (V5) |
| **자폭류 시전자 기절**(`selfdestruct: 'always'` — 대폭발·자폭·미스트버스트) | `useMoveInner` `:564`, **명중 판정 전** | **있음** — 대폭발 vs 고스트도 시전자 기절 |

- 자폭류는 설계서에 없다. champions 학습자가 있다(대폭발 8·자폭 23·미스트버스트 12종). 엔진이 이미 시전자를 기절시키는지 B8-i에서 확인하고, B8-a 허용 예외에 넣는다. B8 게이트가 이 경로를 막지 않도록 주의한다.

### 2-3. 목록(§0-1)에 없는 후보 — 시험 추가 권장

| 기술 | 상성 | Showdown | 왜 확인하나 |
|---|---|---|---|
| 역린(Dragon) vs 페어리 | 무효 | 고정(`lockedmove`) 안 걸림 | §0-1에 없음. 엔진이 고정을 `inflictsVolatile` 밖에서 처리하거나, B8-a 비교 항목에 고정 상태가 빠졌을 수 있다 |
| 난동·소란(Normal) vs 고스트 | 무효 | 고정·소란 안 걸림 | 같음 |
| 속이기(Normal) vs 고스트, **첫 턴** | 무효 | 풀죽음 없음 | §0-1 풀죽음 5종에 없음. 점검이 첫 턴 조건을 못 맞췄을 가능성 |
| 배짱(Scrappy) 시전자의 누르기·속이기 vs 고스트 | **무효 아님** | 마비·풀죽음 정상 | 대조(회귀). champions에 배짱 보유자 있음(캥카·메가이어롭·부란다 등). `damage > 0`이라 게이트 통과가 정상 |

- 역린 고정 **도중**에 상대가 페어리로 바뀌는 경우(2턴째 무효)는 Showdown에서 고정이 풀리고 남은 턴 수에 따라 혼란 여부가 갈린다(`conditions.ts` `lockedmove` `onAfterMove`·`onEnd`). 실행으로 확인하지 않았으므로 §8 한계 후보로만 둔다.

### 2-4. V4·Q3 — 전기자석파

- `data/moves.ts`에서 `ignoreImmunity`를 가진 기술은 bide·futuresight·nihillight·thousandarrows·thunderwave 5개이고, **변화기에서 `false`는 전기자석파뿐**이다. champions mod에는 `ignoreImmunity` 재정의가 없다. 변화기는 기본값이 `ignoreImmunity = (category === 'Status')`(`:717`)라 다른 변화기는 타입 무효를 무시한다.
- 무효 판정은 `runImmunity(move)` — 기술의 **현재 타입**으로 본다. champions에 노말스킨(Normalize)·과녁(Ring Target, Past)이 없어 지금은 차이가 없지만, 엔진은 원래 타입이 아니라 데미지 계산과 같은 **실효 타입·상성 함수**로 판정하는 것이 안전하다.
- 가루 면역·장난꾸러기 vs 악은 별도 단계(3단계)라 Q3 범위 밖이 맞다(엔진은 이미 가루 면역을 `opponentEffectsBlocked`에 둠).
- 문구: Showdown `-immune` = "효과가 없는 듯하다…" 계열. 설계 C7·Q3와 일치.

## 3. 설계서 반영 목록

1. **Q5·C6 정정**: 벽 파괴(깨트리기·사이코팽, 데이터에 있으면 레이징불)에 `damagingMoveLanded(c)`를 건다. 무효 상대는 벽 유지, 대타 적중은 깸
2. **B8-a 허용 예외**: ② 벽 파괴를 빼고, **자폭류 시전자 기절**을 넣는다
3. **B8-j 기대값 변경**: 깨트리기 vs 고스트 → **벽 유지**. 추가: 깨트리기 vs 대타 → 깸 / vs 방어 → 안 깸(회귀)
4. **B8-d 추가**: 역린 vs 페어리·난동·소란 vs 고스트 → 고정 없음(다음 턴 기술 자유 선택). B8-a 비교 항목에 고정 상태 포함 여부 확인
5. **B8-c 추가**: 속이기 vs 고스트(첫 턴) → 풀죽음 없음
6. **B8-e 추가**: 배짱 시전자 누르기 vs 고스트 → 마비(무효 아님)
7. **B8-i 추가**: 대폭발 vs 고스트 → 시전자 기절, 상대 변화 없음
8. Q3: 전기자석파 판정에 실효 타입 사용(V4 목록 = 전기자석파 1개 확정)
9. §5 측정 단계: 벽 파괴 게이트를 ②에 넣거나 ④로 분리(분리 권장 — 원인 분리 원칙)
10. §8 한계 후보: 역린 고정 도중 무효 상대(2턴째) 처리

## 4. 참고: 코드 맵 정정

`showdown-code-map.md` §4는 "champions 엔진 재정의는 3개뿐"이라고 적었지만 실제로는 `actions.spreadMoveHit`·`hitStepMoveHitLoop`·`modifyDamage`·`canMegaEvo`·`canTerastallize`, `pokemon.getActionSpeed`·`formeChange`·`clearVolatile`도 재정의한다. 이번 판정(무효 판정 순서)에는 영향이 없다(`trySpreadMoveHit`·`useMoveInner`는 재정의 없음). 코드 맵을 함께 고쳤다.
