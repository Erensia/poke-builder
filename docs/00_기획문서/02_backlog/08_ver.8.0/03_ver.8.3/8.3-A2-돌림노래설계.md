## 1. 확정된 규칙 (사용자 2026-11-10, 변경 없음)
- 싱글 기준 **같은 턴에 앞서 쓰인 돌림노래가 있으면(상대 포함) 뒤에 쓴 쪽 위력 2배**(60 → 120).
- 연속 턴 사용 방식(`echoStreak`)은 **삭제**. 연속된 턴에서 쓴다고 위력이 오르지 않는다.
- 우선도·행동 순서는 건드리지 않고 **위력만** 바꾼다.
- AI 평가에 같은 턴 선행 사용 여부를 반영한다.

## 2. 지금 엔진이 하는 일 (코드 확인)
- 데이터 `src/data/moves.json:347` — `돌림노래`: 노말·특수·위력 60·우선도 0, 플래그 **`doublesPowerPerConsecutiveUse: true`**(이 이름이 현재 규칙을 나타낸다). `src/types/move.ts:723`의 주석도 "직전 턴에도 쓰면 2배씩, 상한 200, 상대와의 연쇄는 세지 않고 자신의 연속 사용만 센다".
- 엔진 `src/lib/battle/preHitEffects.ts:903`(`applyConditionalPower` 끝) — 시전자의 `echoStreak = { turn, count }`를 보고 **직전 턴(turn − 1)에도 썼으면** `count + 1`, 위력 `min(200, 60 × 2^(count−1))`. 이번 사용을 `echoStreak`에 기록.
- 상태 `src/lib/battle/state.ts:322` `echoStreak?: { turn; count }`. 교체로 물러나면 `src/lib/battle/switching.ts:459`가 지운다. 이 세 곳과 데이터 플래그·타입이 전부다(다른 참조 없음).
- 이 위치는 사전 효과 파이프라인에서 **면역 판정(`checkDefenderImmunities`, 반환값으로 흐름을 끊지 않음) 뒤, 명중 판정(`rollHit`) 앞**이다. 그래서 풀죽음·마비·잠듦·얼음 등으로 막힌 행동(`checkActionBlockers`에서 반환)은 기록되지 않고, **빗나감·방어·면역은 기록된다** — §0 ④의 가정과 이미 같다.
- 엔진은 `resolvePreHitEffects(state, actorKey, move, random, movesSecond, defenderMove)`로 상대가 이번 턴 고른 기술(`defenderMove`)과 선후공(`movesSecond`)을 이미 알지만, 이 문제에는 쓰지 않는다. 실행 여부를 정확히 알려면 상대 쪽에 "이번 턴 실제로 썼다"는 기록이 필요하다(상대가 못 움직였거나 교체했으면 안 센다).
- **AI**(`src/lib/battle/ai/moveDamage.ts:350`~): 돌림노래는 기본 위력 60으로 평가한다(6.3의 한계 "돌림노래 연쇄 미집계"). 비슷한 선례: `눈사태`(이번 턴 먼저 맞았으면 2배)는 후공일 때 `1 + targetAttackChance`로 기대 위력을 섞는다(`avalancheMultiplier`).

## 3. 새 규칙과 구현

### 3-1. 엔진
1. `echoStreak?: { turn; count }` → **`echoTurn?: number`**(마지막으로 돌림노래를 쓴 턴 번호). `state.ts` 필드와 주석 교체, `switching.ts`의 초기화는 `echoTurn = undefined`로 이름만 바꾼다(물러난 포켓몬은 더 이상 "앞서 쓴 상대"가 아니다 — Showdown의 활성 포켓몬 기준과 같다).
2. `preHitEffects.ts:903` 블록을 다음 의미로 교체한다.
   ```
   if (플래그 && power !== null) {
     const echoed = c.defender.echoTurn === c.state.turnNumber;   // 이번 턴 앞서 쓴 상대의 돌림노래
     c.attacker.echoTurn = c.state.turnNumber;                    // 이번 사용 기록
     if (echoed) power ×= 2                                       // 60 → 120, 누적 없음
   }
   ```
   기록 위치(§2의 `checkActionBlockers` 뒤)는 그대로 둔다. 연속 사용 횟수·상한 200은 사라진다.
3. **플래그 이름 변경**: `doublesPowerPerConsecutiveUse` → **`doublesPowerAfterEchoThisTurn`**. 규칙이 "연속 사용"이 아니게 되므로 옛 이름은 오해를 부른다. 바꾸는 곳은 `moves.json`(1곳)·`move.ts`(타입+주석)·`preHitEffects.ts`뿐이다. `moves.json`은 데이터 파일이라 LF 줄바꿈을 확인하고(현재 CR 0개) 같은 PR에서 `docs/데이터변경이력.md`에 한 줄 기록한다(데이터 JSON 수정 절차 — 트레일 노트 5.3 D1). `validate:data`·`test:sample`로 확인한다.
4. 데이터 `effect` 문구("함께 돌림노래를 하면 … 위력도 2배로 올라간다")는 공식 설명이라 그대로 둔다.

### 3-2. AI 평가 (`moveDamage.ts`)
- 결정 시점에는 상대가 이번 턴 무엇을 고를지 모르므로 `눈사태`와 같은 방식으로 **기대 위력**을 섞는다: AI가 **후공**이고 방어측(상대)이 돌림노래를 쓸 수 있으면 `echoMultiplier = 1 + echoChance`, 아니면 1. `echoChance` = 상대가 이번 턴 돌림노래를 고를 확률.
- `echoChance` 추정: 상대의 사용 가능 공격기(`attackChanceOf` 가 쓰는 기술 집합) 안에 돌림노래가 있으면 `attackChanceOf(상대 → 나) ÷ (상대 사용 가능 공격기 수)`, 없으면 0. `// ponytail: 공격기 균등 분배 — opponentMoveModel의 데미지^sharpness 가중치로 바꿀 수 있으나 돌림노래 사용자가 흔치 않아 균등으로 둠. 측정에서 편향이 보이면 가중치로 교체`.
- `avalancheMultiplier` 옆에 `echoMultiplier`를 두고 `extraOffenseMultiplier`에 곱한다. 새 함수는 `echoChanceOf` 하나(`opponentMoveModel.ts`의 `attackChanceOf` 곁).
- **AI가 선공인 경우**: 상대가 이후에 쓰는 돌림노래가 2배가 되는 위협 증가는 평가에 넣지 않는다(알면서 둔 한계 — 위협 모델에 선행 사용 상태를 끼워야 해서 범위가 커진다). 후속 후보로 백로그에 적는다.
- 탐색(`runTurn` 시뮬레이션)은 엔진을 그대로 쓰므로 위 엔진 변경이 자동 반영된다. 손으로 쓴 기대 위력은 이 한 곳뿐이다.

## 4. 이 PR에 넣지 않는 것
- 행동 순서 앞당김(싱글에서 결과가 같고 사용자가 불필요하다고 확정), 더블 전용 처리.
- AI 선공 시 상대 위협 증가(위 한계).
- 돌림노래 외 "같은 턴 선행 사용" 기술(없음 — 이 플래그를 쓰는 기술은 돌림노래뿐).
- 매치업 화면(`evaluateSlotMatchup`)의 표시는 기본 위력 60 그대로다(같은 턴 선행 여부는 화면 계산에 없는 정보).

## 5. 결정·해석 (기본값으로 진행. 이견 있으면 알려 주세요)
- **Q1. "먼저 쓴" 기준 = 실행에 들어간 사용(§0 ④).** 못 움직인 행동은 안 센다(상대가 풀죽음·마비·잠듦·얼음·혼란 자해 등으로 못 썼으면 내 돌림노래는 60). 빗나감·방어·면역·대타는 쓴 것으로 센다. 상대가 쓰러진 뒤에도 마커는 남아 같은 턴 뒤에 쓰는 쪽은 2배다(쓰러진 쪽이 먼저 쓴 경우).
- **Q2. 마커는 포켓몬에 달고 교체하면 지운다.** 같은 턴에 상대가 쓴 뒤 교체로 물러났다가 다른 포켓몬이 나와 돌림노래를 쓰면 2배가 아니다(앞서 쓴 포켓몬이 더 이상 활성이 아님). 유턴류로 돌림노래를 쓴 직후 교체하는 경우는 없다(돌림노래에 교체 효과 없음).
- **Q3. 누적 없음.** 같은 턴에 셋 이상이 쓰는 더블 규칙은 해당 없고, 싱글은 최대 2배(120)다. 옛 상한 200은 사라진다.
- **Q4. 플래그 이름 변경**(§3-1 ③). 반대하면 이름은 두고 주석만 고친다(코드 3곳이 줄어든다).
- **Q5. AI 범위.** 후공일 때 기대 위력만 반영하고 선공일 때의 위협 증가는 후속으로 미룬다(§3-2).

## 6. 위험과 영향
- **기준 출력**: 돌림노래를 쓰는 AI 대전에서 위력이 달라진다 — 연속 턴 사용에서 오르던 120/200은 사라지고 서로 쓰는 턴에 120이 생긴다. `regress 200`·`regress 20000`·`greedy120`·`status60`·`h2h40`·`ai60`이 바뀔 수 있다. **바뀌면 안 되는 것**: `test:inference` 결합 해시 `10040ffa0108c9a3`·계산 함수 차분 해시(60만 건) — 역산은 데이터의 위력(60)을 쓰고 새 플래그를 보지 않는다. 이 둘이 바뀌면 PR 전에 원인을 찾는다.
- **A1과의 분리**: A1 머지 후 기준값(`regress 200` `3eb104fd…`)이 출발점이다. A2의 변화 원인은 돌림노래 하나여야 한다.
- 저장된 대전 영상은 로그를 그대로 담고 있어 영향 없다.
- 화면: 로그에 위력 표시가 따로 없어 UI 변경은 없다(턴 로그의 데미지 숫자만 달라짐). 화면 확인은 돌림노래 두 번 쓰는 대전에서 뒤에 쓴 쪽 데미지가 앞의 약 2배인지 보는 정도다.
