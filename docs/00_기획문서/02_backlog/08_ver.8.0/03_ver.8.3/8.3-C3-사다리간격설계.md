## 0. 요약
- **현황(S2, 선출 포함 사다리, 시드 300 = 600판)**: P4/P3 **50.0%** · P5/P4 **59.5%** · P6/P5 **50.0%** · P7/P6 **53.3%**. 학습을 켠 h2h(M2): P4 vs P3 49.7% · P5 vs P4 57.2% · P6 vs P5 50.3%.
- **원인(코드)**: P3·P4는 같은 AI(`MODEL_ONLY`: 상대 모델만)이고 학습 사용률 λ(0.25 / 0.5)만 다르다. P5·P6은 같은 AI(`APP_DECISION_PARAMS`: 탐색+상대 모델)이고 λ(0.75 / 1.0)만 다르다. **학습이 승률에 주는 이득이 작아**(C2-a: 결정 민감도 3~19%, C2-b2 M0b: 순이득 0 근처) λ로는 강도 격차가 생기지 않는다. 그래서 마스터볼 4·3, 2·1이 사실상 같은 강도이고 격차는 P5(탐색 켬) 한 곳에 몰려 있다.
- **제안**: 상위(P6·P7)와 하위(P0~P2)는 **건드리지 않고**, P3·P4·P5를 **약하게 만들어** 인접 격차를 벌린다. P3/P2에 여유가 있어(현재 64.8% ≈ 107 Elo, 하한 55% = 35 Elo) 하위를 건드리지 않고도 배치할 수 있다(§2). 약화 수단은 P3·P4 = 실수 모델(`mistake`), P5 = 탐색 약화(§3).
- **목표 기준**은 §8 Q1에서 정한다(엄격: 인접 55~65% / 완화: 단조 증가 + 인접 ≥ 53%). 엄격 기준은 가능하지만 여유가 34 Elo뿐이라 측정 오차(600판 ±2%p ≈ ±14 Elo) 안에서 빠듯하다.
- 폐기도 정당한 결과다: 라운드 상한(§4) 안에서 목표를 못 맞추면 현행 유지로 닫고 근거를 적는다.

## 1. 현행 사다리를 Elo로 보면
Elo = 400·log10(p/(1−p)). S2·6.3 A2 숫자로 누적하면(P0 = 0):

| 단계 | 정의(`rankProfile.ts`) | 인접 승률 | 인접 Elo | 누적 Elo |
|---|---|---|---|---|
| P0 | 실수율 0.5(확정 처치도 무시), 기능 끔 | — | — | 0 |
| P1 | 실수율 0.4, 기능 끔 | 62.2% | +86 | 86 |
| P2 | 실수율 0.12, 기능 끔 | 64.4% | +103 | 189 |
| P3 | 상대 모델 + λ 0.25 | 64.8% | +107 | 296 |
| P4 | 상대 모델 + λ 0.5 | **50.0%** | **0** | 296 |
| P5 | 앱 AI(탐색+모델) + λ 0.75 | 59.5% | +67 | 363 |
| P6 | 앱 AI + λ 1.0 | **50.0%** | **0** | 363 |
| P7 | 챔피언(탐색 깊이 2) | 53.3% | +23 | 386 |

- **마스터볼 4~1**(`masterBand`: 레이팅 1600/1900/2200)이 P3~P6에 대응한다. 4·3, 2·1이 같은 강도다.
- P7/P6은 C1(챔피언 AI 강화)의 대상이다. **C3는 P7을 건드리지 않는다.**

## 2. 목표 배치 (하위·상위 고정, 사이만 벌린다)
P6 = 363 고정, P2 = 189 고정. 인접 격차 하한(엄격 55% = 35 Elo, 완화 53% = 21 Elo):

| | 엄격(≥55%) 가능 범위 | 제안 목표(둘 다 만족하는 예) |
|---|---|---|
| P3 | ≥ P2 + 35 = 224 | **≈ 232**(P3/P2 56%, 현재보다 −64) |
| P4 | ≥ P3 + 35 | **≈ 272**(P4/P3 55.7%, 현재보다 −24) |
| P5 | ≥ P4 + 35, ≤ P6 − 35 | **≈ 312**(P5/P4 55.7%, P6/P5 57.3%, 현재보다 −51) |
| P6 | 363 고정 | 363 |

- 엄격 기준의 총 여유는 363 − (189 + 4×35) = **34 Elo**(절대 하한 배치에서 남는 값). 완화 기준이면 363 − (189 + 4×21) = 90 Elo로 훨씬 넉넉하다.
- **하위(P0~P2)를 건드리지 않는 이유**: 하위를 약하게 하면 아래로 연쇄해 P0(최약)를 넘어서 다 벌릴 수 없다(6.3 G1 교훈 — 위를 약화하면 맨 위와 벌어지고 아래를 약화하면 간격이 커져 불가). 대신 P3/P2에 이미 있는 슬랙(107 → 약 43~60 Elo)을 쓴다.

## 3. 약화 수단
| 단계 | 수단 | 근거·주의 |
|---|---|---|
| P3 | `mistake: { rate: r3, margin: m3 }`(탐색 없는 판단에서 최선 − margin 이내 차선책을 확률 rate로 균등 선택) | `applyMistake`(`index.ts`)는 `params.mistake && !params.search`일 때만 적용 → 탐색이 없는 P3·P4에 쓸 수 있다. P0~P2는 이 방식으로 조정했다(6.3 A2) |
| P4 | 같은 수단, 더 작은 `r4` | P3·P4가 같은 AI라 λ만 다르다 → P4 = P3 + 작은 약화 차이 |
| P5 | **탐색 약화**: `search.budget`·`topK`·`maxOpponentMoves` 중 하나를 줄인다(예: `topK 3 → 2`, `maxOpponentMoves 3 → 2`, `budget 24 → 12`) | 탐색이 있으면 `mistake`가 적용되지 않는다(`!params.search`). 대안으로 **`mistake`를 탐색 경로에도 적용하도록 코드를 바꾸는 것**이 있으나 엔진 판단 흐름을 건드리므로 먼저 파라미터 약화로 시도한다(§8 Q2) |
| λ(학습 사용률) | **유지** | λ는 강도 수단이 아니다(C2). 단 앱 UI("AI 학습" 표시)와 일치를 위해 단계별 λ 값은 그대로 둔다 |

- 약화량 ↔ Elo의 관계는 모른다 → **측정으로 교정**한다(§4). 후보 파라미터 격자(처음 시도): `r3 ∈ {0.10, 0.20}`, `r4 ∈ {0.05, 0.10}`, `margin`은 P0~P2와 같은 `1e9`(어떤 차선책이든) 또는 `0.5` 중 하나, P5 탐색 후보 3종.

## 4. 측정·튜닝 절차 (승률이 직접 지표)
- **도구**: `scripts/rank-ladder.mjs`(`POOL=samples`·`SELECT=1`, 시드 300 = 600판, 승률은 무승부 제외)를 쓴다. 기존 단계 정의로는 `--rungs`가 프로파일 인덱스라 **후보 프로파일을 `rank:N`으로 지정할 수 있어야** 한다 → 측정용으로 후보를 임시 인덱스(예: `rank:8,9,10`)나 환경변수 JSON 인자로 넘기는 작은 변경이 필요하다(구현 단계에서 `battle-ai-sim.mjs`의 `parseParams`가 이미 JSON 인자를 받으므로 JSON 인자 쪽으로 해결, 코드 변경 없음 예상).
- **라운드**: 라운드마다 바뀐 단계가 낀 **인접 쌍만** 재측정한다(P3 변경 → P3/P2·P4/P3, P4 변경 → P4/P3·P5/P4, P5 변경 → P5/P4·P6/P5). 쌍 하나 약 8분~30분(탐색이 있는 쌍이 느리다), 병렬(`--jobs 10`)로 라운드당 약 30분 예상(S2: 4쌍 합 31.3분).
- **순서(위에서 아래, 6.3 A2 방식)**: ① P5를 고정된 P6에 맞춘다(P6/P5 ≈ 56%) ② P4를 P5에 맞춘다(P5/P4 ≈ 56%) ③ P3을 P4에 맞춘다(P4/P3 ≈ 56%) ④ 마지막에 P3/P2·전체 인접 4쌍을 한 번에 재측정해 확정.
- **라운드 상한**: 3라운드(각 ≈ 30분, 총 약 1.5~2시간 + 확정 측정 30분). 3라운드 안에 목표 기준을 못 맞추면 **현행 유지로 폐기**하고 근거(Elo 배치·실패한 약화 수단)를 백로그에 남긴다.
- **중단 조건**: ① 약화가 P2/P3 이하의 인접(P3/P2 < 55%·완화 < 53%)을 깨면 그 후보는 버린다 ② P5 약화가 앱 판단 시간·동작을 바꾸면 안 된다(랭크 단계 전용 파라미터만 바꾼다 — `APP_DECISION_PARAMS` 자체는 불변).
- 측정 시작 전 "명령·예상 시간"을 보고한다(CLAUDE.md). 측정 중에는 `src/`를 바꾸지 않는다(프로세스가 모듈을 읽는다).

## 5. 불변·검증 예상
- 바꾸는 것은 `RANK_AI_PROFILES` 안의 P3·P4·P5 정의뿐이다. `verify.sh`가 `rank:` 단계를 쓰지 않는 것을 확인했다(`regress`·`greedy`·`status60`·`h2h40`·`ai60`은 별도 파라미터) → **14항목 불변 예상**. 해시가 바뀌면 원인을 표로 보고한다.
- `npm run test:rank-ai`(`scripts/rank-ai-check.mjs`)가 단계 정의·등급 정책을 확인하므로 변경 뒤 통과해야 하고, 필요하면 시험 기대값(실수율 등)을 갱신한다.
- 사용자 체감 영향: 마스터볼 4~2 구간 상대가 지금보다 **약해진다**(상위 P6·챔피언은 그대로). 승급(레이팅 상승)이 더 부드러워지는 대신 같은 레이팅에서 만나는 AI가 약해진다 — 사용자 결정(§8 Q3).
- 화면 확인은 없다(AI 강도만 바뀜, 로그·UI 불변). 선택적으로 사용자가 랭크 모드를 몇 판 해 보는 체감 확인.

## 6. 구현 순서·PR
측정(라운드) → 확정 파라미터를 `rankProfile.ts`에 반영(단계 주석의 측정 숫자 갱신) → `test:rank-ai`·`verify.sh` → PR 1개(커밋 1개) → 머지. 코드 변경은 정의 상수뿐이라 작다(`mistake` 값·탐색 파라미터). 측정 도구·표는 `docs/…/C3-측정도구/`에 `.txt`로 보관한다(C2 방식).

## 7. 알면서 두는 한계(예정)
- 600판 측정의 표준오차는 ±2%p(≈ ±14 Elo)라 엄격 55% 하한 근처의 판정은 불확실하다. 확정 측정은 시드를 늘려(예: 600시드 = 1,200판) 오차를 줄인다.
- 인접 단계끼리만 직접 쟀다. 먼 단계(예: P3 대 P6) 승률은 Elo 합과 어긋날 수 있다(비전이성) — 확정 측정에서 P3 대 P6도 한 번 잰다.
- 약화로 만든 강도 격차는 "실수하는 AI"의 격차다. 사용자가 느끼는 난이도(예: 약한 단계가 터무니없는 수를 둔다)가 달라질 수 있다 — 체감 확인.
- P7(챔피언) 간격(P7/P6 53.3%)은 C1 소관이다.
