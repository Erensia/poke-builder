## 2. 상세

### 2-1. 두 특성은 Showdown champions에서 같은 코드다 (Q1 근거)

```ts
// data/abilities.ts piercingdrill  /  data/mods/champions/abilities.ts unseenfist (같은 본문)
onHitProtect(source, target, move) {
  if (move.flags['contact']) {
    target.getMoveHitData(move).bypassProtect = this.effect;
    return false;
  }
},
```
- champions의 보이지않는주먹은 기본 9세대 구현(`onModifyMove`에서 `protect` 플래그 삭제 → 데미지 그대로)을 `onModifyMove: undefined`로 지우고 위 코드로 바꾼다.
- 원인 → 영향: 두 특성의 동작이 완전히 같으므로, **관통드릴 전용 필드는 어느 경우에도 필요 없다.** Q1처럼 한 필드를 두 특성이 같이 쓰는 것이 Showdown 구조와도 같다.

### 2-2. V3 — 뚫은 뒤 방어류 접촉 반응은 **발동하지 않는다** (두 특성 공통)

[소스] 방어류의 반응 코드는 모두 condition의 `onTryHit` 안에서 **`checkMoveBypassesProtect` 뒤**에 있다.

```ts
// spikyshield (킹실드·토치카·블로킹·실크트랩·불꽃의수호도 같은 구조)
onTryHit(target, source, move) {
  if (this.checkMoveBypassesProtect(move, source, target)) return;   // ← 뚫으면 여기서 끝
  ...
  if (this.checkMoveMakesContact(move, source, target)) {
    this.damage(source.baseMaxhp / 8, source, target);               // 반응(도달 안 함)
  }
  return this.NOT_FAIL;
},
onHit(target, source, move) {
  if (move.isZOrMaxPowered && this.checkMoveMakesContact(...)) {     // Z·다이맥스 전용
    this.damage(source.baseMaxhp / 8, source, target);
  }
},
```
- 뚫으면 `onTryHit`이 반응 전에 `return`한다. `onHit` 쪽 반응은 `isZOrMaxPowered`일 때만 실행된다. 그래서 특성으로 뚫으면 **킹실드 공격 −1·니들가드 1/8·토치카 독이 모두 없다.** champions mod는 이 condition들을 재정의하지 않는다(`conditions.ts`·`moves.ts`는 pp·사용 가능 여부만 바꿈).
- B7 검수 표의 "가시 반동 없음"이 맞았다. 보이지않는주먹도 같은 코드이므로 결과가 같다.
- 원인 → 영향: 엔진 `preHitEffects.ts:1231~1232`의 주석 "보이지않는주먹으로 뚫고 들어간 경우도 … 발동한다"는 Showdown과 반대다. Q4의 "다르면 전용 필드" 분기는 쓰지 않는다. 대신 **"같다, 다만 현행 엔진이 틀렸다"**이므로 `:1232` 조건에 `!c.unseenFistPiercing`를 넣어 **두 특성 모두 반응을 끈다.**
- 영향 범위: **보이지않는주먹(골루그-메가)의 현행 동작이 바뀐다.** Q9 단계 ③은 "필요할 때만"이 아니라 **필수 단계**이고, 골루그-메가가 등장하는 빌드에서 `regress`가 바뀔 수 있다. 원인을 분리하려면 단계 ③을 따로 측정한다.
- 반응 말고는 정상 명중이므로 그대로 적용되는 것: 방어 측 접촉 특성·도구(까칠한피부·울퉁불퉁멧 등), 부가효과, 자기 랭크 하락, 반동, 흡수. 반동·흡수는 줄어든 데미지 기준이다.

### 2-3. V2·V8 — ×0.25의 반올림 방식과 적용 위치

[소스] `champions/scripts.ts` `modifyDamage`:
```ts
baseDamage = this.battle.runEvent('ModifyDamage', ...);           // 생명의구슬·달인의띠·멀티스케일 등
if (bypassProtect) baseDamage = this.battle.modify(baseDamage, 0.25);
if (this.battle.gen !== 5 && !baseDamage) return 1;               // 최소 1
return tr(baseDamage, 16);
```
`modify`는 `tr((tr(value * 1024) + 2047) / 4096)`이다. 즉 **4096 반올림(0.5는 버림)**이고 `floor`가 아니다.

| 원데미지 x | x mod 4 | Showdown | 엔진 현행 `floor(x × 0.25)` |
|---|---|---|---|
| 100 | 0 | 25 | 25 |
| 101 | 1 | 25 | 25 |
| 102 | 2 | 25 (.5는 버림) | 25 |
| **103** | **3** | **26** | **25** ❌ |
| 1 / 2 / 3 | — | 1 / 1 / 1 (최소 1) | 0 / 0 / 0 ❌ |

- 원인 → 영향: 원데미지를 4로 나눈 나머지가 3인 경우(약 1/4 확률) 엔진이 1 작다. 보이지않는주먹 현행 코드에도 같은 오차가 있다.
- 권장(Q5 수정): `Math.max(1, <엔진의 4096 반올림 헬퍼>(hitDamage, 1024))`. 생명의구슬 같은 배율에 이미 쓰는 4096 헬퍼가 있으면 그것을 쓰고, 새로 만들지 않는다.
- **적용 위치**: Showdown은 ×0.25를 **최종 배율(생명의구슬 등 `ModifyDamage`) 뒤**, 최소 1 앞에 둔다. 엔진 `hitResolution.ts:314~315`가 생명의구슬·달인의띠·멀티스케일 배율 **뒤**에 있는지 확인이 필요하다. 앞에 있으면 반올림이 한 번 더 달라진다.
- V8 명중: hitStep 순서가 `TryHit(방어 판정) → TypeImmunity → TryImmunity → Accuracy`이다. 뚫기 판정 뒤에도 명중 판정을 정상으로 하므로 **빗나갈 수 있다**(기본안 맞음). 상성 무효도 뚫기 판정 뒤에 처리한다.

### 2-4. 신규 — 뿔드릴(일격기)은 ×0.25를 받지 않는다

- [소스] `getDamage`는 `if (move.ohko) return target.maxhp;`(그리고 `damageCallback`·고정 데미지)에서 **곧바로 값을 반환**한다. 그래서 `modifyDamage`의 ×0.25 단계에 도달하지 않는다. 한편 방어 판정(`checkMoveBypassesProtect`)은 그 전에 이미 끝났다.
- 결과: 메가 몰드류 뿔드릴(접촉, `ohko`) vs 방어 → **방어를 뚫고, 명중하면 일격 기절**이다. `-zbroken` 줄도 나오지 않는다.
- champions 몰드류 learnset에 `horndrill`이 있다(설계서 C9 목록에도 있음). 골루그는 접촉 일격기·고정 데미지 기술을 배우지 않는다.
- 엔진 확인: 일격기 데미지가 `hitDamage`로 흘러가 `:314`의 ×0.25를 받으면 **최대 HP의 1/4만 들어가는** 차이가 생긴다. 일격기를 ×0.25에서 제외하는 가드(또는 이미 다른 경로라는 확인)가 필요하다.
- 참고: 옹골참은 일격기 자체를 막는다(Showdown 일반 처리, 이번 범위와 무관).

### 2-6. Q8 설명문 (사용자 결정)

- 참고 사실: Showdown 영문 shortDesc는 "…ignore a target's protection and deal **1/4 the usual damage**"이다. 보이지않는주먹의 champions shortDesc도 같은 문장이다. 한국어 Showdown 텍스트는 두 특성 모두 미번역이다.
- 의견: `abilities.json` 문구의 출처가 **게임 원문으로 확인되면 ⓐ(그대로)**에 동의한다. 다만 "최소 1/4"는 엔진·Showdown 동작과 반대 방향으로 읽힌다. 출처가 확인되지 않으면 **ⓑ(동작에 맞게 고쳐 씀)**가 낫다. 보이지않는주먹 문구를 이미 동작에 맞게 써 두었다면 그쪽에 맞추는 것이 일관적이다.

## 3. 설계서 반영 목록

1. **Q4 → 확정**: 두 특성 모두 방어류 접촉 반응 **미발동**. `preHitEffects.ts:1232` 조건에 `!c.unseenFistPiercing`를 넣고 주석을 정정한다. 전용 필드(`skipsPiercedProtectContactEffects`)는 만들지 않는다
2. **Q9 단계 ③을 필수로**: 보이지않는주먹 동작이 바뀌므로 따로 측정한다(골루그-메가 등장 빌드에서 `regress`가 바뀔 수 있음)
3. **Q5 수정**: `Math.max(1, round4096(hitDamage × 1024/4096))`. 엔진의 기존 4096 헬퍼를 재사용한다. ×0.25가 생명의구슬 등 최종 배율 **뒤**에 오는지 확인
4. **뿔드릴**: 일격기(및 고정 데미지)는 ×0.25에서 제외. 방어 관통 자체는 적용
5. 시험 수정·추가:
   - **P-b**: 기대값 `floor(× 0.25)` → `max(1, 4096 반올림(× 0.25))`. **원데미지 mod 4 = 3**인 사례를 하나 고정한다(현행 엔진에서 실패해야 함)
   - **P-f**: 기대값 "반응 **없음**"(킹실드 공격 랭크 변화 없음, 니들가드 시전자 HP 그대로, 토치카 독 없음). 보이지않는주먹도 같다(P-n에 P-f 포함) — **구현 전 실패**
   - **P-p**: 원데미지 1~3 → 1
   - **P-q(신규)**: 관통드릴 + 뿔드릴 vs 방어, 명중 고정 → 대상 기절(1/4 아님)
   - **P-r(신규, 선택)**: 뚫은 접촉기 vs 까칠한피부 또는 울퉁불퉁멧 보유 대상 → 시전자 반동 **있음**(방어류 반응만 없고 일반 접촉 반응은 있음)
6. Q8: §2-6 의견 참고 후 사용자가 결정
7. C4 본문의 "방어류의 접촉 반응은 그대로 발동한다"는 엔진 현행 설명으로는 맞다. 다만 Showdown과 다르다는 메모를 단다

## 5. 후속 확정 (2026-11-13, 사용자 전달 — 설계서 `8.3-B9-관통드릴정정설계.md`가 이 내용을 반영한다)

위 §1~§3은 첫 검수 결과이고, 이후 사용자가 두 가지를 확정했다. **충돌하는 부분은 이 절이 우선한다.**

1. **Q8 설명문(확정)**: 두 특성 공용 — "접촉 기술을 사용하면 상대의 방어 효과를 무시하고 1/4의 데미지를 입힐 수 있다". `abilities.json` 두 특성의 설명문을 필드 교체와 같은 커밋에서 바꾼다. 설명문은 계산에 안 쓰여 `regress`는 불변. 원래 버그가 "방어 효과"를 방어 능력치로 읽은 데서 나왔으므로 필드 주석에 해당 기술 목록(방어·판별·킹실드·니들가드·토치카·패스트가드)을 적는다.
2. **V3 / Q4 (§1·§2-2·§3-1·§3-2를 정정)**: 사용자가 공식 정보를 따라 **뚫은 뒤 방어류의 접촉 반응은 발동한다**고 확정했다(킹실드 시전자 공격 −1·니들가드 시전자 최대 HP 1/8·토치카 시전자 독). Showdown은 반응이 없으므로 **이 한 조합에서만 Showdown과 다르게 간다.** 따라서 ① 엔진 `preHitEffects.ts:1232`는 바꾸지 않는다(보이지않는주먹은 지금도 발동, 관통드릴은 같은 필드로 자동 동일) ② 설계서의 Q4 전용 필드 분기와 Q9 단계 ③(접촉 반응 처리)은 불필요 ③ 시험 P-f 기대값은 "반응 발동"(관통드릴은 구현 전 방어에 막혀 실패, 보이지않는주먹은 현행 통과), P-k는 연속기의 반응 횟수를 현재 엔진 결과로 고정 ④ 이후 Showdown 대조에서 이 조합의 차이는 정상으로 처리한다.

남은 항목: Q5(4096 반올림·최소 1)와 뿔드릴(접촉 일격기) 지적은 그대로 유효하다. 뿔드릴은 엔진 코드 확인 결과 이미 고정 데미지 분기를 타서 ×0.25를 받지 않으므로 가드 없이 시험 P-q로 고정한다.
