## 0. 요약
- **현재 챔피언(P7) = 앱 AI(탐색 켬) + 탐색 깊이 2**(`CHAMPION_DECISION_PARAMS`, 제한 5초). 마스터볼 1(P6, 앱 AI)과 비교해 선출 포함 사다리 **53.3%**(S2, 600판), v0 채택 때 **52.9%**(800판), 선출 없는 h2h **54.4~55.2%**. 설계 합격선은 **55%**였고 사용자 결정으로 v0를 채택했다.
- **이미 평평하거나 폐기된 방향은 다시 하지 않는다**(G4 §8): 탐색 폭·예산·시드 확대(c9·c10 54.4~55.2%), 후반 한정 깊이(49.8~50.5%), 평가식 파라미터 튜닝, 선출 개선, 카운터 픽, **방향 A 학습된 가치 함수**(공정 기준 대비 +0.9%·−1.9%·−3.5%, 게이트 3% 미달).
- **상한은 확인되지 않았다**: 시간 무제한 "슈퍼 챔피언"(`depth 2`·seeds 6·topK 5·응수 4·`budget 0`)은 **58.0%**(300판)로 c8 54.8%(400판)보다 높지만 **차이 3.2%p는 통계적으로 약하다**(검수). 판단 평균 3.6초·최대 41초라 그대로는 못 쓴다. → 이번 C1의 첫 질문은 "**시간을 무제한으로 쓰면 정말 이득이 있는가**"이다(§3-0b).
- **제안(§3)**: ① Stage 0 기준선 → 슈퍼 챔피언 짝 비교 → (이득이 있을 때만) 2묶음 분해 ② Stage 1 방향 B 1차(강건 혼합, min은 확률 ≥ 0.1 응수에만) ③ Stage 2 방향 C(모호한 턴에만 무거운 설정, 슈퍼 비교에서 이득이 확인된 경우만) ④ 방향 E는 **이번엔 하지 않는다**. 각 단계는 **승률 게이트**를 못 넘으면 코드 없이 폐기한다.

## 2. 구조·병목 요약 (G4 §2~§4, 이번 세션 지식 반영)
```
선택지 점수(HP 교환식) ─ 상위 topK ─▶ searchDecide ─ 값 = Σ_j w_j × 평균_시드[ 그 턴(들) 판세 변화 + 잎 평가 ]
                                     (후보 × 상대 응수 j × 시드)  depth 2 = 두 턴을 현재 정책으로 롤아웃
```
- 후보별 값 행렬 `tallies[후보].sums[j]`(상대 응수 j마다 롤아웃 합)가 이미 있어서 **강건 값**(방향 B)과 **2차 패스**(방향 C)는 같은 구조 위에 얹는다.
- 비용은 엔진이 아니라 **판단**(대면표·잎 평가)에 있다. 현행 P7: 평균 628ms(병렬 부하 포함 측정), 단독 첫 턴 974ms.
- 앱 AI가 같은 모델을 쓰므로 **h2h 이득이 사람 상대 이득을 과소·과대평가할 수 있다**(G4 방향 B 위험). 이 지표로는 "AI를 더 강하게 만든 것"만 재고 사람 체감은 잴 수 없다.

## 3. 단계와 후보
### Stage 0 — 기준선·슈퍼 챔피언 짝 비교·(조건부) 분해 (코드 변경 없음, 약 3~4시간)
**0a. 기준선(선별, 시드 1~300)**: **현행 P7 대 P6**, 선출 포함, **600판**(약 25분) + **판단 시간**을 단독 1프로세스로 측정(평균·p95·최대·5초 폴백 비율). 이후 모든 후보의 짝 비교 기준이다. (`SearchResult.rollouts`는 진단 필드라 이 단계에서는 없이 잰다.)
**0b. 슈퍼 챔피언 짝 비교**: **슈퍼 챔피언(`depth 2`·seeds 6·topK 5·응수 4·`budget 0`) 대 P6**, 같은 시드(1~300) **600판**(약 2시간 — G4에서 300판이 57분). 짝 순이득과 f를 낸다. **판정**: 짝 순이득 < +1.0%p면 "시간을 무제한으로 써도 이득이 없다" → **분해(0c)와 Stage 2를 취소**한다(Stage 1은 별개로 진행).
**0c. (0b에서 이득이 확인된 경우만) 2묶음 분해**: c8에서 슈퍼 쪽으로 옮긴 후보 2개를 같은 시드 600판씩 짝 비교한다. **잎 묶음** = `leaf: "precise"` · **폭 묶음** = `seeds 6`·`topK 5`·`maxOpponentMoves 4`·`budget 0`. 어느 묶음이 이득의 절반 이상을 차지하는지와 그 **시간 비용**(단독 평균·p95·롤아웃 수)이 산출물이다. 한 묶음이 이득을 대부분 차지하면 그 묶음 안을 더 쪼갤지는 사용자와 정한다.

### Stage 1 — 방향 B 1차: 강건 혼합 (코드 몇 줄, 비용 거의 0)
- `searchDecide`의 `valueOf`를 `(1−ρ)·Σ w_j·v_j + ρ·min_{j: w_j ≥ 0.1} v_j`로 확장(`search.robust ρ`, 기본 0 = 현행). ρ ∈ {0.25, 0.5}. **min은 모델이 0.1 이상으로 예측한 응수에만** 적용한다(잡음 낀 값의 최솟값이 체계적으로 낮아지는 "분산 벌점"을 피함).
- **이 안은 "기대값과 최악값의 보간"이지 혼합 전략(내시 균형·후회 매칭)이 아니다.** 백로그의 "동시 수 강건 혼합"이 혼합 전략을 뜻했다면 그것은 다른 방향(G4 방향 B 2차)이라 이번 범위 밖이다.
- 앱 AI가 같은 모델이라 h2h 이득이 작을 수 있다 — **짝 비교 600판 선별**로 판단하고, 이득이 없으면 폐기(사람 효과는 측정 불가라 근거 없이 채택하지 않는다).
- 챔피언 전용(`CHAMPION_DECISION_PARAMS`)만 켠다. 시험: ρ = 0이 현행과 같다, ρ에 따라 값이 기대값과 최악 값 사이에서 보간된다, `w_j < 0.1`인 응수는 min에서 제외된다.

### Stage 2 — 방향 C: 모호한 턴에만 무거운 설정 (0b에서 이득이 확인된 경우만)
- Stage 0c에서 이득이 나온 묶음(`leaf precise` 또는 폭)을 **상위 두 후보의 값 차이가 작은 모호한 턴에만** 쓰고, 무거운 패스는 **상위 2~3개 후보**로 좁힌다. 평균 시간 = 가벼운 설정 비용 + (모호한 턴 비율 × 추가 비용). 모호한 턴 비율을 먼저 측정해 시간 예산을 계산한다. **후반 한정**(49.8~50.5%)이 아니라 **모호성 기준**이다.
- **측정 중에는 롤아웃 수 기준 예산**으로 제한한다(벽시계 제한은 병렬 부하에 따라 걸리는 빈도가 달라 승률이 흔들린다). **벽시계 제한은 앱 안전장치로만** 쓰고, 내부 마감은 5초 폴백(앱 AI로 떨어짐)보다 앞선 **3초**에 둔다.
- 슈퍼 비교(0b)에서 이득이 없거나 무거운 설정만 이득이면서 시간 예산 안에 못 넣으면 이 단계는 **취소**한다.

### 방향 E — 선출 개인화 예측: **이번엔 하지 않는다**
사용자 선출 기록 저장·동기화·형식 변경이 필요하고 봇(습관 상대)으로만 측정할 수 있으며, C2에서 "예측 개선이 승률로 옮겨지지 않는다"는 교훈이 반복됐다. 백로그 후속 후보로 남긴다.

## 4. 시험·검증
- **새 시험**(`scripts/battle-ai-scenarios/`): (Stage 1) `robust` 0 불변·보간·`w_j < 0.1` 응수 제외, (Stage 2) 모호성 판정 함수·가벼운/무거운 설정 선택·롤아웃 수 예산, (진단) `SearchResult.rollouts`가 판단을 바꾸지 않는다 → 구현 전에 먼저 쓰고 실패를 확인.
- **불변**: `CHAMPION_DECISION_PARAMS` 외 정의·앱 AI·P0~P6 불변을 `test:rank-ai`로 확인. `verify.sh` 14항목은 챔피언 전용 옵션이라 **불변 예상**(`ai60`이 챔피언을 쓰는지 확인 — 쓰면 바뀌는 해시를 단계별 보고).
- 기준값 갱신이 필요하면 `SERIAL=1` 깨끗한 출력에서만.

## 6. 알면서 두는 한계(예정)
- h2h는 **같은 모델끼리의 자기대전**이다. 이득이 사람 상대 강도로 옮겨진다는 보장이 없고, 강건 혼합(B)은 특히 사람 효과가 h2h에 안 드러난다.
- **합격 못 함이 곧 이득 없음은 아니다**: 실제 문턱이 +2.8%p라 작은 진짜 이득(+1~2%p)은 2,400판에서도 잡히지 않는다. 기본값은 폐기이고 이 한계를 백로그에 남긴다.
- 판단 시간은 PC 성능에 의존한다(집 PC 단독 측정 기준). 느린 기기에서는 5초 폴백이 더 자주 걸려 사실상 앱 AI로 떨어진다.
- 슈퍼 챔피언 +3.2%p는 300판 측정이라 불확실하다(0b에서 600판 짝 비교로 확인).

## 7. 사용자 결정 이력(재론하지 않음)
- 시간 예산: 판단 평균 1초·최대 5초(2026-10-31). 숨은 정보(사용자의 3선출)를 직접 보는 안은 쓰지 않는다. 모델 파일을 번들에 넣어도 되나(방향 A는 폐기). 하위 단계(P0~P6) 강도는 변경하지 않는다(C3에서 P3만 조정됨).
