## 2. 상세

### 2-1. Q2 무효 가드 — `데미지 > 0` 조건이 탈(Disguise)에서 어긋난다 (신규)

- [소스] 제거는 `onAfterHit`(대타면 `onAfterSubDamage`)다. 적중해서 방어·무효에 막히지 않으면 데미지가 0이어도 실행된다.
- [실행] 킬러스핀 vs **탈 상태의 몽마시**(챔피언스 사용 가능, `isNonstandard: null`):
  ```
  |-activate|p2a: Mimikyu|ability: Disguise
  |-damage|p2a: Mimikyu|130/130        ← 데미지 0
  |-status|p2a: Mimikyu|psn            ← 독도 걸림
  |-sideend|p1: Player 1|Stealth Rock|[from] move: Mortal Spin
  ```
  (참고: 같은 구조인 아이스페이스는 챔피언스 비사용 `Past`라 영향 없음. 실측에서도 제거 + 스피드 +1)
- 원인 → 영향: 설계 Q2는 `damagingMoveLanded`의 "데미지 > 0 또는 대타" 기준을 그대로 재사용한다. 이 기준은 **0 데미지 적중**(탈)을 "안 맞음"으로 본다 → 엔진은 제거하지 않고 Showdown은 제거한다. 몽마시는 고스트/페어리라 고속스핀(노말)은 상성 무효로 해당이 없고, **킬러스핀(독)만 걸린다**.
- 권장: 가드 조건을 **"명중 + 방어 안 됨 + 상성 무효 아님"**으로 정의한다(`데미지 > 0`을 쓰지 않는다). 탈이 데미지를 0으로 흡수하는 경로를 엔진이 어떻게 표시하는지(예: 흡수 플래그, 상성 값)를 구현 전에 확인하고, 그 경우도 "맞음"으로 센다.
- 영향 범위 주의: `applyStatChanges`의 같은 기준에도 같은 한계가 있을 수 있다(자기 랭크 상승 기술 vs 탈). 이번 B7에서 `damagingMoveLanded`를 공용 함수로 뽑으므로, **공용 함수를 고치면 `applyStatChanges` 동작도 같이 바뀐다.** 바꿀지 분리할지 PR에서 정한다(분리하려면 제거 블록 전용 조건을 따로 둔다).
- 시험 추가: **MS-h** 킬러스핀 vs 탈 몽마시 → 설치물 제거됨, `spinCleared` 있음.

### 2-2. V1 — 시전자가 쓰러졌을 때 (설계 기본안 보정)

- [소스] `onAfterHit`(일반 명중)에는 `pokemon.hp` 조건이 **없다**. `onAfterSubDamage`(대타 맞음)에만 `pokemon.hp &&`가 붙어 있다. 문구 설명("user has not fainted")과 코드가 다르다.
- [실행] 고속스핀 시전자 HP 1, 상대 까칠한피부(러프스킨) 가르가브:
  ```
  |-damage|p1a: Excadrill|0 fnt|[from] ability: Rough Skin
  |-sideend|p1: Player 1|Stealth Rock|[from] move: Rapid Spin
  |faint|p1a: Excadrill
  ```
  시전자가 쓰러졌는데도 스텔스록이 제거된다.
- 원인 → 영향: 접촉 반응(`onDamagingHit`)이 `onAfterHit`보다 먼저 돈다. 시전자가 쓰러진 뒤에 교체로 들어오는 다음 포켓몬은 **설치물 없이** 나온다.
- 시험 추가: **RS-d** 시전자 HP 1 + 러프스킨 상대 → 시전자 기절, 설치물 제거. 엔진이 접촉 반응 뒤 제거 블록을 건너뛰는지 확인한다. 대타 경로는 접촉 반응이 대타에 막히므로 시전자가 쓰러질 일이 사실상 없어 `pokemon.hp` 조건은 무시해도 된다.

### 2-3. V2 — 무효 상대

| 시험 | Showdown 로그 | 결과 |
|---|---|---|
| 킬러스핀 vs 강철(강철쟁이, 부식) | `-immune` | 설치물(스텔스록) 남음, 독 없음 |
| 킬러스핀 vs 강철(부식 아님) | `-immune` | 같음 |
| 고속스핀 vs 고스트(팬텀) | `-immune` | 설치물·씨뿌리기 남음, **스피드 +1도 없음** |
| 킬러스핀 vs 방어 | `-activate … Protect` | 제거 없음 |

- 설계 C6·RS-b·MS-e·MS-g와 일치한다. 부식은 상태이상 **변화기**에만 작용하며 데미지 기술의 무효 판정을 바꾸지 않는다.

### 2-4. V3 — 고속스핀은 접촉 기술

- [실행] `Dex.mod('champions').moves.get('rapidspin').flags = {contact:1, protect:1, mirror:1, metronome:1}`. 러프스킨 상대로 실제 반응 확인(§2-2 로그).
- 킬러스핀도 `contact: 1`이며 데이터는 이미 `true`다.
- 조치: 고속스핀 `makesContact: false → true`. 효과: 러프스킨·울퉁불퉁멧집·끈적끈적바디 등 접촉 특성과 도구 반응이 생긴다 → **단계 ①의 해시 변화 원인이 하나 더 늘어난다.** 데이터 변경이력에 같은 줄로 적고, 단계 ①을 "제거 필드"와 "접촉"으로 나눠 `regress 200`을 두 번 재면 원인 분리가 쉽다.

### 2-5. V4 — 문구

- Showdown에는 영문 설명만 있고(`rapidspin.desc`) 포챔스 한국어판 문구는 없다. 기본안(`…벗어났다!`·`…필드의 …이(가) 사라졌다!`)의 정확성은 검수 범위 밖이다. 사용자가 포챔스 화면에서 직접 확인해 상수 한 곳만 바꾸는 방식이 맞다.
- 속박 해제는 Showdown도 `-end … [partiallytrapped]` 줄을 낸다 → **속박 줄을 그리는 설계(Q3)가 맞다.**

### 2-6. V5 — B8 분리

- [실행] 찌릿찌릿(전기, 마비 100%) vs 땅 → `-immune`, 마비 없음. 킬러스핀 vs 강철도 같다. Showdown은 상성 무효이면 부가효과 전에 기술 전체가 실패한다. C7 결함은 실재한다.
- 판정: 분리에 동의한다(해시 영향이 넓고 원인이 B7과 다르다).
- D3 흡수 여부: **프로젝트 문서에서 D3의 정의를 찾지 못했다.** 권장은 "수정은 B8 독립 항목, D3가 Showdown 전수 시나리오 비교라면 B8 입력(상태이상·랭크·반동 등 부가효과 전체)을 D3 점검 항목에 넣는다"이다. 부가효과 종류가 상태이상 외에 풀죽음·랭크 변화·반동에도 걸리는지 같은 전수 확인이 필요해서다.

### 2-7. Q4 — 제거 줄 순서와 기타 로그

- Showdown 처리 순서: 씨뿌리기 → 압정뿌리기 → 독압정 → 스텔스록 → 끈적끈적네트 → 속박. **설계 Q4와 같다**(MS-c 실측 일치). 제거 대상에 `gmaxsteelsurge`가 있으나 게임에 없다.
- 참고(수정 불필요): 고속스핀의 **자기 스피드 +1 줄 위치**가 다르다. 일반 명중은 `+1 → 제거`, 대타 명중은 `제거 → +1`. 싱글 화면에서 줄 순서만 다르며 최종 상태는 같다.
- Q5(독치장 → 독 순서)와 V6: 같은 행동 안의 효과 줄이고 최종 상태가 같다 → 둔다. 이번 실측도 Showdown은 `피해 → 독 → 독치장 → 제거`.

## 3. 설계서 반영 목록

1. §3-2·Q2: 가드 조건을 "명중 + 방어 안 됨 + 상성 무효 아님"으로 바꾸고, 공용 함수 분리 시 `applyStatChanges` 영향 범위를 결정(§2-1)
2. §3-1·Q1·V3: 고속스핀 `makesContact: true` 확정, 단계 ①에서 접촉과 `hazardClear`를 나누어 측정(§2-4)
3. §4: 시험 **MS-h**(탈), **RS-d**(시전자 기절) 추가(§2-1·§2-2)
4. V1 기본안 정정: "시전자 쓰러지면 생략"은 대타 경로만. 일반 명중은 제거(§2-2)
5. V5·V6·V7·V4 답 기입(§1 표)
6. 백로그 B8에 입력 추가: 찌릿찌릿 vs 땅 `-immune`(부가효과 전수 확인 필요)
7. 데이터 값 수동 대조(설계서 미언급): 고속스핀 노말·물리·위력 50·명중 100·PP 20, 킬러스핀 독·물리·위력 30·명중 100·PP 15·상대 전체
