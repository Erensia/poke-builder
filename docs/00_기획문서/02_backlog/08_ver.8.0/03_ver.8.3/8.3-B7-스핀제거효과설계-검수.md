## 2. 상세

### 2-1. Q2 — 원안 가드가 탈(Disguise)도 맞게 처리한다 (1차 검수 정정)

- [실행] Showdown: Mortal Spin vs 따라큐(Mimikyu, 탈) → `-activate Disguise` · 데미지 0 · `-status psn` · `-sideend Stealth Rock`. **제거한다.** Flame Charge vs 탈도 `-boost spe 1`.
- [엔진] `damagingMoveLanded`가 보는 `c.damage`는 **이론 데미지**다(`hitResolution.ts:787` `c.damage = hitResult.damage`). 탈은 그 뒤 `applyDamageToDefender`(`:393`)에서 실제 HP 감소만 막는다. 그래서 탈에 맞으면 `c.damage > 0`이고 가드를 통과한다 → **Showdown과 같이 제거**. 상성 무효만 `c.damage = 0`이 된다(`:732` 등).
- 원인 → 영향: 1차 검수는 `c.damage`를 실제 감소량으로 오해해 "원안은 탈에서 제거하지 않는다"고 판정했다. 실제로는 원안이 맞다. `applyStatChanges`(Flame Charge vs 탈 +1)도 이미 Showdown과 같으므로 "공용 함수로 뽑으면 랭크 판정도 바뀐다"는 우려도 없다(동작 불변).
- 권장: 원안처럼 **`damagingMoveLanded(c)`를 공용 함수로 뽑아 두 곳이 같이 쓴다.** 1차 검수 뒤 설계서에 반영된 "명중 + 방어 안 됨 + 상성 무효 아님" 별도 조건(`69fc43d`)도 결과는 같지만 기준이 두 개가 된다. 원안으로 되돌리는 편이 짧고 어긋날 여지가 없다.
- 시험 **MS-h**(Mortal Spin vs 탈 따라큐 → 제거, `spinCleared` 있음)는 회귀 시험으로 유지한다.

| # | 상황 | Showdown | 엔진(코드 기준) |
|---|---|---|---|
| RS-d | 시전자 HP 1, Rough Skin | 반동으로 기절 → `-sideend` → `faint` | 접촉 반동은 `hitResolution`, 제거는 그 뒤 `resolveMirroredPhase`. 시전자 기절로 건너뛰는 분기 없음 → 제거 ✅ |
| — | 시전자 HP 1, Rocky Helmet | 같음(제거) | 같음 |
| — | 시전자 HP 1, Life Orb | 제거 → Life Orb 반동 기절 | 제거는 됨. 반동 줄 위치만 확인 |
| V7 | 상대 KO | 제거 | `c.hit` 참 → 제거 ✅ |
| **MS-d** | **대타가 미리 있음**(독치장 대상) | `-activate Substitute [damage]` → `-sideend`. 독·독치장 없음 | 설계 기대값과 같음 ✅ |

- 1차 검수의 MS-d 실측은 공격이 대타 설치보다 먼저 나가 **대타를 맞히지 않은** 기록이었다. 대타를 미리 건 상태로 다시 쟀고 설계 기대값이 맞다.

### 2-3. V3 — 고속스핀 접촉 수정과 관통드릴 (신규, B7 범위 밖)

- 고속스핀은 접촉 기술이다. 데이터를 `makesContact: true`로 고치면 Rough Skin·Rocky Helmet 등이 반응하고, 단계 ①의 해시 변화 원인이 하나 늘어난다. **단계 ①을 `hazardClear`와 접촉으로 나눠 `regress 200`을 두 번 재는 것**을 권장한다(설계서 `69fc43d`의 ①-a/①-b 분리와 같다).
- **관통드릴(Piercing Drill, 메가 몰드류)**: 고속스핀 학습 포켓몬 중 메가 몰드류만 이 특성을 가진다.

| | Showdown | 엔진 |
|---|---|---|
| 정의 | 접촉 기술이 **방어(Protect)류를 뚫고** 1/4 데미지(`onHitProtect` → `bypassProtect`, `-zbroken`) | 접촉 기술이 **상대 방어 랭크를 무시**하고 **최소 데미지 = 최대 HP 1/4** 보장(`contactIgnoresDefenseBoostAndGuaranteesMinDamageFraction`) |
| 고속스핀 vs Protect / Spiky Shield | 뚫음 → 1/4 데미지, 스피드 +1, **설치물 제거**, 가시 반동 없음 | `blockedByProtect` → 제거 없음 |

  - 원인 → 영향: 엔진은 설명문 "상대의 **방어** 효과를 무시"를 방어 능력치로 해석한 것으로 보인다. Showdown은 같은 문장을 **방어(기술)류 관통**으로 구현했다. 보이지않는주먹(`contactBypassesProtectAtQuarterDamage`, `preHitEffects.ts:623`)과 같은 구조다. 지금은 고속스핀이 비접촉이라 드러나지 않았지만, V3로 접촉이 되면 Showdown과 결과가 달라지는 경로가 생긴다.
  - 권장: B7에서는 고치지 않는다. **새 백로그 항목**(관통드릴 해석)으로 등록하고, 포챔스 실제 동작(방어를 뚫는지)을 사용자가 확인해 정한다. 고치게 되면 보이지않는주먹 필드를 재사용하면 된다.
- 우격다짐(Sheer Force): champions에서 고속스핀·킬러스핀을 배우는 포켓몬(메가 포함) 중 우격다짐은 없다. 특성 복사로 얻는 경우만 남으므로 §8 한계에 한 줄 적으면 충분하다(Showdown은 이 경우 제거와 스피드 +1이 모두 사라진다).

### 2-4. V2 — 무효 상대 + Corrosion

| 시험 | Showdown | 비고 |
|---|---|---|
| Mortal Spin(Corrosion) vs Steel(Corviknight) | `-immune`, 제거·독 없음 | 엔진은 제거(C6, 가드로 해결)·독(C7, B8) |
| Rapid Spin vs Ghost(Gengar, 따라큐) | `-immune`, 제거·씨뿌리기 해제·스피드 +1 없음 | 엔진 스피드 +1은 이미 막힘 |
| Mortal Spin vs Protect | 제거 없음 | 일치 |
| **Mortal Spin(Corrosion) vs Poison(Toxapex)** | 데미지 → **`-status psn`** → 제거 | 1차 검수의 "Corrosion은 변화기에만 작용"은 틀렸다. 데미지 기술 부가 독에도 적용된다. 엔진도 `mirroredEffects.ts:578`에서 같은 처리를 하므로 일치. Toxic Debris(Corrosion 아님) 사용자는 독이 안 걸린다 |

- 시험 추가(선택): **MS-i** Corrosion Mortal Spin vs Poison 타입 → 독 + 제거. B8 수정 시 Corrosion 경로가 깨지지 않는지 지키는 회귀 시험이 된다.

### 2-5. V5 — B8 분리와 D3

- [실행] Nuzzle(Electric, 마비 100%) vs Ground → `-immune`, 마비 없음. Showdown은 상성 무효면 부가효과 전에 기술이 끝난다. C7 결함은 실재한다.
- 분리에 동의한다. 원인(부가효과 단계에 "맞았을 때만" 가드 없음)이 B7 제거 블록과 같은 축이지만, 영향 범위(모든 데미지 기술의 상태이상·풀죽음 등)가 넓어 `regress` 변화 원인을 분리하기 어렵기 때문이다.
- D3: 이전 대화 기록상 **"8.3 작업을 모두 끝낸 뒤 마무리 직전에 하는 엔진 배선 전수검사"**로 보인다(추정). 그렇다면 **B8을 D3에 흡수하지 않는 것**을 권장한다. D3는 마지막 단계라 거기서 처음 고치면 수정과 재측정이 마무리 직전에 몰리기 때문이다. B8은 독립 항목으로 먼저 고치고, D3에는 "상성 무효 시 부가효과 전체(상태이상·혼란·풀죽음·랭크·반동·흡수)가 없는지" 점검 항목만 둔다. D3의 정의가 다르면 알려 주시기 바란다.

### 2-6. Q4·로그

- 제거 줄 순서: 씨뿌리기 → 압정뿌리기 → 독압정 → 스텔스록 → 끈적끈적네트 → 속박. 설계 Q4와 같다(`gmaxsteelsurge`는 게임에 없음).
- 속박 해제도 Showdown이 `-end … [partiallytrapped]` 줄을 낸다 → 줄을 그리는 설계가 맞다.
- 참고(수정 불필요): 고속스핀의 스피드 +1 줄은 일반 명중이면 제거 앞, 대타 명중이면 제거 뒤다.

## 3. 설계서 반영 목록

1. Q2: **원안 유지** — `damagingMoveLanded(c)` 공용 함수 재사용. `69fc43d`에서 바꾼 별도 조건은 근거(탈)가 철회되었으므로 원안으로 되돌리는 것을 권장(되돌리지 않아도 결과는 같음)
2. V3: 고속스핀 `makesContact: true`, 단계 ①을 ①-a(`hazardClear`)/①-b(접촉)로 측정
3. 시험: MS-h(탈) 유지, RS-d(시전자 기절) 유지, **MS-i(Corrosion vs Poison) 선택 추가**. MS-d 기대값은 원안 그대로
4. 백로그 신규: **관통드릴 해석 차이**(Showdown = 방어류 관통 1/4, 엔진 = 방어 랭크 무시 + 최소 1/4). 포챔스 실제 동작 확인 필요
5. §8 한계: 특성 복사로 얻은 우격다짐 + 고속스핀·킬러스핀은 Showdown에서 제거·스피드 +1 없음(엔진 spin 블록은 우격다짐을 보지 않음)
6. B8: 분리. D3에는 점검 항목만(§2-5)

## 4. 1차 검수(Sonnet판)와 달라진 점

| 1차 검수 내용 | 재검수 결과 |
|---|---|
| Q2 원안은 탈에서 제거하지 않는다(❌) | **철회.** 엔진 `c.damage`는 이론 데미지라 탈도 통과한다. 원안이 맞다 |
| 공용 함수화 시 `applyStatChanges` 동작이 바뀐다 | **철회.** 동작 불변 |
| Corrosion은 상태이상 변화기에만 작용한다 | **틀림.** 데미지 기술의 부가 독에도 작용한다(엔진도 그렇게 구현) |
| MS-d 실측(대타 없이 맞은 기록) | 측정 오류. 재측정 결과 설계 기대값이 맞다 |
| (없음) | **신규**: 관통드릴과 V3 상호작용, 우격다짐 학습자 없음 확인, D3 성격 추정 |
| 포켓몬 한국어 이름 오기 | 영문 기준으로 표기하고 확인된 한국어 이름만 병기 |
