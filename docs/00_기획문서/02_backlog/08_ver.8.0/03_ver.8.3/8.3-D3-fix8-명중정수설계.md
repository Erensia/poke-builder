## 0. 사전 확인(사용자 사례)
fix-6과 같은 규칙: **외부 계산기 사례가 없으면 소스 근거로 진행**하되 Q1에 한 건을 요청한다. 명중 판정은 사용자 사례 파일(`damage-formula-check`)에 없다(데미지 전용). 본가가 정수 절삭인지 직접 확인된 바는 없어 **Showdown 소스를 기준**으로 한다.

## 1. 무엇이 틀렸나(E2-01)
| 단계 | Showdown | 엔진 현재 |
|---|---|---|
| 보정(`ModifyAccuracy` 체인) | 각 배율을 4096분율로 양자화해 `chain`, 한 번 `modify` → **정수** | 소수 곱(`1.3 × 0.9 …`) |
| 랭크 | `trunc(acc × (3+b)/3)` 또는 `trunc(acc × 3/(3−b))` → **정수** | `(3+s)/3`·`3/(3+|s|)` 곱, 절삭 없음 |
| 판정 | `randomChance(acc, 100)` (정수 %) | `random() < 소수 확률` |
| 상한 | `accuracy`가 100 이상이면 항상 명중 | `min(1, …)` |
- E2 `[계산]`: 명중 50~100 × 랭크 −3~+3 × 보정 7종 425가지 중 142가지에서 엔진이 평균 0.46%p, 최대 1.5%p 높다. 보정·랭크가 없으면 같다.

## 2. 고칠 것
1. **순서**(Showdown): ① 보정 체인(광각렌즈·포커스렌즈·복안·반짝가루·모래숨기/눈숨기·의욕·갈지자걸음·중력)을 `chain4096`으로 묶어 `modify4096(명중, 체인)` → 정수 ② 랭크 `trunc` 적용 ③ 100을 넘으면 필중으로 취급(`min(100)`) ④ 판정 확률 = `정수/100`.
2. `src/lib/accuracyCrit.ts` `computeHitChance`: 시그니처에 **정수 모드** 추가(기본 켬). 명중 `null`(필중)은 그대로. 반환은 `정수/100`(0~1)로 유지해 호출처(`c.random() < hitChance`) 변경 없음.
3. `src/lib/battle/hitChance.ts`: 곱해 모으던 `accuracyExtraMultiplier`(도구·특성·중력)를 `chain4096` 인자 목록으로 변경. 값: 광각렌즈 1.1·포커스렌즈 1.2(후공)·복안 1.3·반짝가루 0.9·모래숨기/눈숨기 0.8·의욕 0.8·갈지자걸음 0.5·중력 5/3 — Showdown 4096 상수(4505·4915·5325·3686·3277·3277·0.5·6840)와 **같은 값을 `q()`가 만들도록** 소수 입력으로 넘긴다(상수표를 코드에 따로 두지 않는다 — fix-6 `q` 재사용. `1.1 → 4505`, `1.2 → 4915`, `1.3 → 5324`임에 주의, 아래 §6).
4. **트리플악셀·찍찍베기 2타째 이후**: champions는 소수 그대로(절삭 없음, 순서는 랭크 → 보정)다. 호출 인자 `integerAccuracy: false`로 `computeBattleHitChance`를 부르는 경로를 `hitResolution.ts:742` 쪽에 둔다(현재 첫 타 `c.hitChance`를 재사용 중).
5. 일격필살(30/20 고정)·필중(`null`)·날씨 명중 수치(폭풍 50 등)는 기존 분기 그대로(날씨 수치는 정수라 영향 없음).

## 3. 규칙(소스 대조)
- 명중 정수 = `modify(base, chain(보정…))` → `boost`(절삭) → `Accuracy` 이벤트(중력은 체인에 포함되므로 별도 없음) → `randomChance(acc, 100)`.
- 보정이 모두 없으면 **현행과 값이 같다**(명중 85 → 85%). 랭크 0·보정 0인 대부분의 판정은 불변.
- 4096 양자화 값은 Showdown 상수와 **1 단위로 다를 수 있다**: `q(1.3)=5324`인데 복안은 소스가 `5325`(`[5325, 4096]`). 소스 상수를 그대로 쓰는 편이 정확하다 → **명중 보정은 소수 대신 4096 분자를 쓰는 작은 표**(`ACCURACY_Q = {복안: 5325, 광각: 4505, …}`)로 둔다(1회성 예외, 근거 주석). 반짝가루 3686·0.9×4096=3686.4 → 같음.

## 4. 영향 범위
- 기준 출력: 보정·랭크가 걸린 명중 판정(랭크 변화 기술·렌즈류·복안·모래숨기·갈지자걸음·의욕·중력 사용 판) → `regress`·`greedy`·`h2h`·`ai` 해시 변동 예상, 승률 영향은 미미(최대 1.5%p 한 판정).
- 평가기·AI 기대 데미지(`moveDamage.ts`)가 명중 확률을 곱하므로 AI 선택이 경계에서 바뀔 수 있다 → `ai60`·`h2h40`로 확인.
- 화면: 명중 표시(배율 표시)가 소수 둘째 자리에서 달라질 수 있다.
