# ver.8.3 D3-fix-15 — 열사의대지가 얼음 상대를 해동 (E4a-06)

**상태**: 초안(2026-11-19) — **사용자 검수 대기.** 근거: `8.3-D3-E4a-검수.md` E4a-06(1차 문서의 "열탕도 빠짐"은 정정됨 — 열탕은 이미 맞다).
**PR**: 1개·커밋 1개. 데이터 한 줄 수정이라 fix-14와 순서는 무관하다(원인 분리를 위해 따로 측정). 시험 `scripts/battle-ai-scenarios/46-ver83-d3fix15.mjs`.
**기준**: Showdown `965a535` `data/moves.ts` `scorchingsands`: `thawsTarget: true`(+ `defrost` 플래그, 화상 30%). `data/conditions.ts` `frz.onAfterMoveSecondary`: `if (move.thawsTarget) target.cureStatus()`. 덤프의 `thawsTarget` 기술은 `scald`·`scorchingsands`·`matchagotcha` 3개이고, 엔진에 있는 것은 열탕·열사의대지 둘이다.

## 1. 무엇이 다른가
- 열탕(물): `moves.json`에 `curesStatus: { target: "opponent", status: "freeze" }`가 있어 얼음 상대를 해동한다 ✓.
- **열사의대지(땅)**: 같은 표시가 없다. 자기 해동(`thawsUserOnUse`)만 있어서, 얼음 상대에게 맞춰도 얼음이 풀리지 않는다.

## 2. 고칠 것
`src/data/moves.json` 열사의대지(5373행 근처)에 열탕과 같은 `"curesStatus": { "target": "opponent", "status": "freeze" }` 추가. **코드 변경 없음.**
- 순서가 Showdown과 같다: 엔진은 `inflictStatuses`(화상 30% 시도 — 얼음이라 실패) → `healAndThaw`(해동) 순이고, Showdown도 화상은 부가효과, 해동은 `onAfterMoveSecondary`라 부가효과 뒤다. 결과적으로 **얼음 상대는 화상이 안 걸리고 풀리기만 한다.**
- 로그: 열탕과 같은 `curedStatus` 경로라 같은 문구가 나온다(새 문구 없음).
- 열사의대지의 효과 문구(`effect`) 대조(B3 방식): 이미 "30% 화상"만 적혀 있으면 문구는 그대로 둔다. 열탕 문구도 해동은 적지 않았으므로 일관된다.

## 3. 영향·측정
샘플 파티 30여 개 중 열사의대지 보유 0건. 랜덤 파티·AI 시뮬은 학습 기술을 쓰므로 변동 가능성은 낮지만 0은 아니다 — `regress 200`·`regress 20000`·`STATUS=1 greedy 60`(약 3분, `SERIAL=1`)으로 확인하고 불변이면 `verify.sh`는 마지막에 한 번(약 8분). 시작 전에 명령·예상 시간 보고.

## 4. 시험 `46-ver83-d3fix15.mjs`
1. 열사의대지 → 얼음 상대: 명중 뒤 상대 상태 없음, 로그 `curedStatus` = 얼음(현행 실패).
2. 같은 상황에서 화상은 걸리지 않는다(얼음이라 부가효과 실패, 순서 확인) — 상대가 해동된 뒤 같은 기술 재사용 시 화상 30%는 정상(기존 동작).
3. 열탕과 같은 결과(대조군, 현행도 통과).
4. 얼음이 아닌 상대(수면·마비·없음)에는 영향 없음 — `curesStatus.status`가 `freeze`로 한정.
5. 무효 타입에는 해동 없음: 열사의대지가 안 먹히는 상대(비행·부유 등)는 명중 전에 막히므로 얼음 유지(현행 규칙 유지 확인 — 같은 `curesStatus` 경로가 열탕과 같은 위치에서 실행됨).
6. 데이터 검사: `curesStatus` 보유 기술 중 `status: "freeze"` 대상은 열탕·열사의대지 둘.

## 5. 화면 확인(사용자 수행)
얼음 상대에게 열사의대지를 쓰면 해동 로그가 나오는지. (얼음 상대를 만들기 어려우면 시험 결과로 대체 가능 — 요청 시 안내.)

## 6. 위험·한계·질문
- **무효·대타 위치**: Showdown `thawsTarget`은 `onAfterMoveSecondary`라 대타에 맞으면(대타가 피해를 대신 받음) 해동이 일어나는지가 Showdown 소스 해석에 걸린다(`target`이 대타 뒤 본체인지). 열탕도 같은 문제를 안고 있으므로 **열탕과 같은 동작으로 맞추는 것을 기준**으로 하고, 대타 케이스는 알면서 둔 것으로 기록한다(E10 후속).
