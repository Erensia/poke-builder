# 노력치 역산 — 현행 설계서 (8.2 기준)

**작성 2026-11-11.** 목적: 노력치 역산 페이지(`DefenseInferencePanel`)의 역산 기능이 **지금 어떻게 동작하는지** 한 문서로 모은다. 지금까지 설계가 2.1·3.1·3.3·3.6·8.2 백로그에 흩어져 있어 전체를 보며 재검토하기 어려웠다. 이 문서는 **현재 코드를 읽어 쓴 as-built 문서**이고, 재검토 쟁점은 §12, 버전 배치 의견은 §13에 있다. 근거 코드: `src/lib/{defenseInference,attackInference,speedInference,combinedInference,latentOpponent,candidateCards,inferenceDraft}.ts`(합 약 2,300줄)와 `src/components/{DefenseInference*,defenseInference*,useDefenseInferenceState}.*`.

## 1. 한 줄 요약
게임이 보여 주는 **정수 값**(상대 HP %, 내 HP, 선후공)을 **정수 데미지 공식**으로 거꾸로 풀어, 상대의 **HP·방어·특방·공격·특공·스피드 능력 포인트(0~32)와 성격 보정**이 될 수 있는 후보를 좁힌다. 정답 하나가 아니라 **가능한 범위와 가능도**를 낸다.

## 2. 입력 — 관측 줄 세 종류
한 화면에 상대 포켓몬 1체, 내 포켓몬 1체(능력·특성·도구·랭크를 전부 아는 쪽)가 있고, 관측을 **줄**로 쌓는다.
| 종류 | 사용자가 넣는 값 | 풀어내는 것 | 엔진 |
|---|---|---|---|
| 입힌 데미지(`dealt`) | 내가 쓴 기술, 상대 HP **%** 맞기 전→후 (+급소·타수·턴 종료 효과·메가폼) | 상대 **HP·방어·특방** + 성격 | 방어 역산 `defenseInference.ts` |
| 받은 데미지(`received`) | 상대가 쓴 기술, **내 HP 수치** 맞기 전→후 | 상대 **공격·특공** + 성격 | 공격 역산 `attackInference.ts` |
| 선후공(`speed`) | 이번 턴 누가 먼저 움직였나 + 그 턴 조건 | 상대 **스피드** + 성격 보정 | 스피드 역산 `speedInference.ts` |
공통 가정 입력: 상대 특성·도구(모르면 "없음"), 상대 랭크, 날씨·필드·벽, 내 상태이상, 화면 %를 ±1%까지 허용하는 "여유". 상대 실수치(스피드·공격)는 자이로볼·일렉트릭볼·속임수를 쓸 때만 **선택 입력**(비우면 평균).

## 3. 공통 모델
1. **후보 공간**: 능력 포인트 0~32 × 성격 보정 묶음. 성격 25개를 (이 역산이 읽는 두 스탯에서) ×0.9/×1/×1.1이 같은 것끼리 묶어 **대표 성격 하나로 계산**한다(`buildNatureCombos`, 최대 3×3=9묶음). 포인트 합계는 **66**(`MAX_ABILITY_POINTS_TOTAL`).
2. **관측 → 데미지 분포**: 관측 하나가 `RollSet = {values[], probs?[]}`(총 데미지 값의 확률분포)를 만든다. 단타는 난수 16단계(85~100%) 균등, 다단히트는 타별 독립 난수의 합성곱, **모르는 값 평균**은 후보별 분포의 가중 혼합, 셸암즈는 분류별 분포 선택. 값은 `evaluateSlotMatchup`이 만든 `DamageParts`(위력·결정력·보정 곱)와 정수 데미지 공식(`damageFormula.ts`)이 낸다 — **엔진·매치업·역산·AI가 같은 공식 한 곳을 공유**한다.
3. **가능도**: 후보 하나가 관측 전체를 설명할 확률. 균등(포인트·성격 묶음 모두) 사전 위에서 곱한다. 0이면 불가능. 결과는 "가능한 후보 수·범위"와 "가능도 가중 중심 구간(10%~90%)과 중앙값".
4. **화면 %**: `displayPercent` = 내림, 단 HP가 남아 있으면 최소 1%(사용자 실측 2026-10-05). 한 곳에서만 바꾼다.
5. **결과 형태**: 포인트 범위, 실수치 범위, 성격 묶음별 가능 여부·가중, 내구 지수(HP×방어)·메가 전후 비교(`FormView`), 극보정 후보 수, 후보 카드(§8).

## 4. 방어 역산 — 상대 HP·방어·특방
- 후보 = (HP 포인트 × 방어 포인트 × 특방 포인트 × 성격 묶음) ≈ 33³×9. 읽지 않는 스탯(예: 특수 관측이 없으면 특방)은 0으로 고정하고 포인트 하한을 낮춰 적용한다.
- 첫 관측의 "맞기 전 %"에 맞는 **실제 HP 값들을 균등**으로 보고, 관측마다 난수를 굴려 화면 %가 맞는 HP만 이어 간다(`candidateLikelihood` — HP 상태 분포를 전진). 이어지는 관측은 "맞기 전 %"가 직전 결과(+턴 종료 효과)와 맞는 HP만 남긴다.
- **턴 종료 효과**(먹다남은음식·그래스필드·독·맹독 n/16·씨뿌리기·저주·화상·모래바람)와 **자뭉열매**(맞은 직후 회복이 화면 %에 섞임)는 사용자가 줄마다 고른다. 안 고르면 관측 사이 회복 없음.
- **멀티스케일류**: 처음 맞는 한 방만 풀피 조건. 메가진화는 줄마다 폼을 고르고(되돌릴 수 없음), 메가 후 관측은 메가폼 특성·종족값, 메가스톤이라 도구 효과는 끈다.
- 상대 **특성·도구**는 사용자가 한 가지로 가정(모르면 없음). 후보 목록은 방어 보정이 있는 특성·반감 열매 등 데이터에서 걸러 낸다(`DEFENSE_ABILITY_CANDIDATES` 등).

## 5. 공격 역산 — 상대 공격·특공
- 받은 데미지는 **정확한 HP 수치**라 방어 역산보다 정밀하다. 후보 = (공격 포인트 × 특공 포인트 × 성격 묶음). 스탯 하나씩 `atkL[i]`·`spaL[j]`를 따로 구해 쌍 루프에서 곱한다(셸암즈만 쌍 가능도를 더 곱한다, §7).
- 쓰러진 공격(맞은 뒤 HP 0)은 "데미지 ≥ 맞기 전 HP" 부등식. 쓰러진 다단히트는 `P(n타 ≥ HP) − P(n−1타 ≥ HP)`.
- 상대 공격 랭크·화상(물리 ×0.5, 근성·객기 예외)·공격 보정 특성·도구는 가정으로 받는다.
- 내 포켓몬 쪽이 확정값이라 방어/특방·HP 후보는 없다.

## 6. 스피드 역산 — 상대 스피드
- 관측은 **부등식**: 내가 먼저 → 상대 실효 스피드 ≤ 내 실효 스피드, 상대가 먼저 → ≥ (트릭룸이면 반대). 완전 동속은 가능도 ½.
- 실효 스피드는 `evaluateSpeedMatchup`(엔진 `computeTurnOrderSpeed` 미러): 랭크·순풍·마비·스카프·속보·곡예·날씨/필드 속도 특성 등을 **줄마다** 고른 조건으로 반영.
- 후보 = (스피드 포인트 × 보정 묶음{↑/무/↓}). 특성·도구·랭크·순풍 같은 조건은 후보가 아니라 **줄마다 사용자가 고르는 입력**이다. 한 번의 관측은 "이 값보다 빠르다/느리다"만 알려 주고, 조건이 다른 관측을 모을수록 구간이 좁아진다(구조적 한계: 내 스피드에서 먼 상대일수록 정보가 적음).

## 8. 결과 표현
- **범위 막대**(포인트·실수치): 가능한 전체 + 가능도 가중 중심 80% + 중앙값. **내구 지수**(HP×방어/특방)는 HP·방어 조합의 곱이라 포인트 범위보다 좁다.
- **후보 카드**(`candidateCards.ts`, 3.6 I2): 수만 후보 중 정렬 기준별 상위 60개 — 남은 SP 순 / 가능도 순 / 관측이 데미지 범위 중앙에 가까운 순. 카드에 포인트·SP 여유·일치 난수·관측별 데미지 구간.
- **HP 최적 수치 눈금**(3.4 H1), **극보정 후보 수**(3.1 C2-a, 계산에는 반영 안 함), **메가 전·후 나란히 보기**(3.1 L1-b).
- **진단**: 관측마다 단독 가능 여부(`singleFeasible`)와 모순일 때 빼면 풀리는 관측(`culprits`), 입력 오류 사유(`observationErrors`). 결합 후에도 이 진단은 결합 전 기준으로 유지(다른 쪽 제약 때문에 "이 관측만으로도 안 맞아요"로 오해되지 않게).

## 9. 결합 (`inferCombined`)
세 역산은 같은 상대의 서로 다른 면이라 서로를 좁힌다. 한쪽만 있거나 한쪽이 모순/무효면 결합하지 않고 각자 보여 준다.
1. **성격 공유**: 성격은 한 값 — 각 쪽에서 가능한 성격의 **교집합**만 모든 쪽의 후보로 쓴다(`natureIds`).
2. **포인트 예산(상한)**: 합 66에서 다른 쪽이 최소로 써야 하는 포인트를 뺀 값이 이 쪽 합의 상한.
3. **포인트 하한**(3.3 V5): 합계 66은 항상 다 쓴다고 보고, 다른 쪽이 쓸 수 있는 최대치를 뺀 값이 하한(관측하지 않은 스탯은 스탯당 32까지 흡수 가능).
4. 1~3을 **고정점까지 되풀이**(안전 상한 64, `converged`). 방어 쪽은 가능도를 `LikelihoodCache`에 두고 되풀이 때 재사용.
5. 성격 가중은 각 쪽 묶음 가중(묶음 가중 ÷ 묶음 안 성격 수)의 **곱**(독립 가정).
6. **사전 패스**(8.2): 모르는 값 평균 기술이 있을 때만 선후공→공격→방어 순으로 범위를 구해 입력에 실어 준다. 되풀이 중에는 갱신하지 않는다.

## 10. 화면·상태 구조
`DefenseInferencePanel`(조립) ← `useDefenseInferenceState`(상태·입력 객체·결합 호출) ← `defenseInferenceCalc.ts`(입력 객체·줄 안내 문구를 만드는 순수 함수) · `defenseInferenceHelpers.ts` · `DefenseInferenceSections.tsx`(가정·관측 입력) · `DefenseInferenceViews.tsx`(결과 표시).
- 입력 객체는 `useDeferredValue`로 계산을 뒤따르게 해 입력이 막히지 않게 한다(물리+특수가 함께면 후보가 수십만).
- **초안 저장**: 관측 줄·가정이 `localStorage`(`saveMatchupDraft`)에 저장되고, `restoreInference`가 깨진 저장본을 기본값으로 복원(사라진 id는 비움, 줄 id는 1부터 재부여).
- 줄 종류를 바꾸면 고른 기술·값을 비운다. 새 줄은 직전 줄의 폼·선후공 조건을 이어받는다. "맞기 전 %"는 직전 맞은 뒤 값(+턴 종료 효과 예상치)으로 채운다.

## 12. 재검토 쟁점 (한계·가정 목록과 후보 질문)
**A. 사전분포** — 포인트·성격 묶음을 **균등**으로 본다. 실전 배분은 0·32(극단)에 몰리고 합 66을 거의 다 쓴다. 결합이 하한(합 66)을 반영하지만 단일 스탯 사전은 균등이다. 극보정 후보는 "표시만, 계산에 반영 안 함". → 사전을 바꾸면 모든 가능도 가중·카드 정렬이 바뀐다.
**B. 가정 입력이 많다** — 상대 특성·도구·랭크·상태이상·날씨를 사용자가 **한 가지로 고정**한다(모르면 "없음"). 이번에 스피드·공격에 도입한 "모르면 후보 평균"을 특성·도구에도 확장할지(후보 수 곱셈), 아니면 입력 UX를 줄일지.
**C. 결합의 근사** — 성격 가중 곱(독립 가정), 사전 범위 비갱신, 같은 숨은 값을 공유하는 관측들을 독립 평균(결과가 넓게 나옴). 정확한 결합은 세 역산을 하나의 후보 공간에서 **동시에** 푸는 것(비용 큼).
**D. 평가기 의존** — 역산은 `evaluateSlotMatchup`의 `DamageParts`에 의존한다. 평가기와 엔진의 규칙이 어긋나면(셸암즈 사례: 평가기는 결정력·물리 고정, 엔진은 데미지·동점 50%) **역산 정확도가 직접 흔들린다.** 평가기-엔진 규칙 일치 감사가 필요한지.
**E. 관측 모델** — 줄 단위 3종 + 턴 연속성은 "맞기 전 %" 연쇄뿐. 턴 단위(한 턴의 선후공+양쪽 데미지+종료 효과)로 묶는 입력 모델이 더 자연스러운지.
**F. 결과 표현** — 범위 막대+중앙값+후보 카드 60개. 사후분포 자체(히트맵·상관)나 "이 정도면 충분" 판단 도구가 필요한지. 현재 "상대 배분을 하나 고르기"는 카드 목록에 의존.
**G. 구조** — `defenseInference.ts`(약 1,000줄)가 공통(NatureGroup·Range·buildNatureCombos·WeightedValues·diagnose)과 방어 고유를 같이 갖고, `attackInference`·`speedInference`·`combinedInference`가 거기서 import한다. 공통 모듈 분리(`inferenceCore`)와 `candidateLikelihood` 계열 분리. 계산을 Web Worker로 빼는 안.
**H. 성능** — 후보 33³×9 ≈ 32만이 기본 비용. 회사 PC에서 잰 가장 무거운 사례도 1초 미만(셸암즈 방어 3관측 770ms, `8.2-I1-셸암즈설계.md` §9). 저사양·모바일 기기에서의 시간은 따로 재지 않았다.
**I. 시험 구조** — 결합 해시가 난수열에 묶여 새 기술을 후보에 못 섞는 제약, 모듈 번호 체계(기능 추가순).
**J. 알려진 미지원·한계** — 변화기, 가변 위력 일부(공격 역산), 스피드 역산의 동속 가능도 ½·관측 폭(구조적), 한 화면에 상대 1체만, 분류 비교에 도구·특성·날씨 배율을 넣지 않는 엔진의 셸암즈 규칙.
