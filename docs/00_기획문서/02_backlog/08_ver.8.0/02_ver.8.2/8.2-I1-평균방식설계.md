# 8.2 I1 후속 — 상대 실수치를 몰라도 되는 "평균 방식" 설계

**작성 2026-11-11 — 설계 문서. 구현 완료: PR #475(같은 날).** 구현하며 §2-1의 "위력 고정 사본"을 **"위력(데미지 조각)이 같은 후보를 접어 대표 스피드 하나만 남기는 방식"** 으로 바꿨다(특성 보정이 위력에 곱해지는 경우 위력을 다시 넣으면 이중 적용될 위험이 있어서). §6-①(사본 동치 시험)은 없어지고 "범위 하나 = 고정 입력" 시험(§6-③)이 그 역할을 한다. 전제: `8.2-I1-역산확장설계.md` §1·§2의 "상대 스피드·공격 실수치를 직접 입력"은 PR #473으로 구현됐다. 사용자 지적(2026-11-11): *실수치를 모르니까 알아내려는 페이지인데 실수치를 입력받아야 알 수 있다면 의도와 어긋난다.* 맞는 지적이라 입력을 **필수에서 선택(알면 고정)** 으로 내리고, 비워 두면 모르는 값을 **가능한 후보 전체로 평균 내서** 역산한다. 방침이 안 서면 노력치 역산 자체를 접는 것도 방안이라는 사용자 단서가 있어, 구현 전 비용을 먼저 잰다(§7).

## 1. 무엇을 모르는가 (잠재 변수)
| 상황 | 잠재 변수 | 데미지에 들어가는 길 |
|---|---|---|
| 내가 자이로볼·일렉트릭볼을 상대에게 (방어 역산) | 상대 스피드 `S` | 위력 `P = f(내 실효 스피드, S의 실효값)` → `DamageParts.hitPowers` |
| 상대가 내게 자이로볼·일렉트릭볼 (공격 역산) | 상대 스피드 `S` | 위력 `P`가 같은 식으로 달라진다 |
| 내가 상대에게 속임수 (방어 역산) | 상대 공격 `A` | 결정력(`parts.offense`)이 `A`로 달라진다 |
| 상대가 내게 속임수 (공격 역산) | 없음 | #472에서 이미 해결(내 공격·방어로 정해진다) |

## 2. 핵심 아이디어 — 데미지 분포를 후보로 섞는다
후보 하나의 가능도는 `candidateLikelihood(maxHp, rolls, obs, tol)`이 구하고, 관측 하나의 `rolls`는 **`RollSet = { values, probs? }` — 데미지 값의 확률분포**다(`damageFormula.ts:101`). 다단히트가 이미 `probs`를 쓰므로 가중 분포는 그대로 받는다.

따라서 잠재 변수 `S`(또는 `A`)가 여러 값 `s₁…sₙ`(가중치 `w₁…wₙ`, 합 1)일 수 있을 때 그 관측의 분포는

```
P(데미지 = d) = Σ wᵢ · P(데미지 = d | sᵢ)        (= 각 sᵢ의 RollSet을 w로 섞은 RollSet)
```

이다. **후보 루프·가능도 함수는 한 줄도 바꾸지 않고, 관측의 `rolls`를 섞는 쪽만 바꾼다.** 값은 같은 데미지끼리 합쳐 `values` 수를 줄인다(다단히트 합성곱과 같은 처리).

### 2-1. 위력으로 접기 (자이로볼·일렉트릭볼)
위력은 `f(…)`가 비율 식(자이로볼 `⌊25·상대/나⌋+1`, 상한 150; 일렉트릭볼 구간표)이라 서로 다른 `S`가 같은 `P`로 접힌다. 그래서 `S` 후보를 곧장 섞지 않고 **(위력 P → 가중치)** 로 먼저 접는다.
1. 후보 스피드 목록 `𝒮`을 만든다(§3).
2. `s ∈ 𝒮`마다 `evaluateSlotMatchup(..., { defenderRealStatsOverride: { spe: s } })`(공격 역산이면 `attackerRealStatsOverride`)의 `damageParts.hitPowers`를 읽어 위력을 얻는다. 평가기를 쓰므로 랭크·도구 배율 규칙을 따로 복제하지 않는다.
3. 위력별로 가중치를 합쳐 `{P, w}` 목록을 만든다(대개 수십 개 이하).
4. 방어 역산: 위력별 `parts` 대안(`alts`)을 들고 있다가 `rollsFor(i, 방어실수치)`에서 섞는다. 공격 역산: 위력별 **대표 스피드 하나**를 남기고, 후보 `(성격, 포인트)`마다 그 대표 스피드로 평가기를 불러 `RollSet`을 만들어 섞는다.

### 2-2. 공격 스탯으로 섞기 (속임수 방어 역산)
`A`는 `parts.offense`를 바꾸므로 위력처럼 접히지 않는다. 후보 `a ∈ 𝒜`마다 `defenderRealStatsOverride: { atk: a }`로 `parts`를 만들고(대개 최대 ~100개), 데미지 값이 같으면 분포에서 합친다. 방어 역산에서만 쓰며 `alts`는 `{parts, w}` 그대로다.

## 3. 후보 집합과 가중치
- 후보: 포인트 `0..32` × 성격 보정 `{×0.9, ×1.0, ×1.1}`로 만든 **서로 다른 실수치**. 종족값은 그 관측 시점 폼(메가면 메가폼)의 값.
- 가중치: (포인트, 보정) 조합마다 포인트는 균등, 보정은 **성격 수 비율 17 : 4 : 4**(무보정 17개, 스피드↑ 4개, ↓ 4개 성격). 같은 실수치로 모이는 조합은 가중치를 합친다.
- **사전 범위로 좁히기**: 같은 상대의 스피드(선후공 줄) 역산 결과 `realSpe`, 속임수는 받은 데미지(공격 역산) 결과 `realAtk`의 `[min,max]` 안의 후보만 쓴다(§4). 범위가 없으면 전체.
- 직접 입력(`opponentSpeed`·`opponentAttack`, #473)은 그대로 둔다. 있으면 후보 집합이 그 값 하나로 줄어 지금 동작과 **완전히 같다**(시험 §6-③).

## 4. 사전 범위를 어디서 구하나 (순환 방지)
화면 입력 → 결합 역산 → 결과가 다시 입력이 되면 순환이다. 그래서 **`inferCombined` 안의 "사전 패스"** 로 푼다.
```
speed0  = inferSpeed(speedInput)                       // 선후공 줄, 다른 입력에 의존 없음
attack0 = inferAttack(attackInput + speed0.realSpe)    // 받은 데미지 줄 (자이로볼이면 스피드 범위 사용)
defense = inferDefense(defenseInput + speed0.realSpe + attack0.realAtk)
```
- 사전 패스는 **관련 기술이 입력에 있을 때만** 돈다(`needsPrior`). 없으면 지금과 비트 단위로 같은 경로라 `test:inference` 결합 해시(`10040ffa0108c9a3`)가 그대로다.
- 사전 패스 결과가 `ok`가 아니면(모순·무효·관측 없음) 범위를 쓰지 않고 전체 후보로 간다.
- 결합 되풀이(성격 공유·포인트 예산)는 사전 범위를 **갱신하지 않는다.** 되풀이가 좁힌 결과를 쓰면 더 정확하지만 입력이 매 라운드 바뀌어 `LikelihoodCache`를 못 쓴다. 범위가 더 넓은 쪽(보수적)으로 틀릴 뿐 진짜 배분을 놓치지는 않는다.

## 5. API·화면
- `InferenceInput`/`AttackInferenceInput`: 새 필드 `opponentSpeedRange?: Range`, (방어) `opponentAttackRange?: Range`. 직접 입력 필드는 그대로.
- `inferenceUnsupportedReason(move)`·`attackInferenceUnsupportedReason(move)`에서 `known` 인자와 "입력해야 한다" 분기를 **지운다** — 속임수(방어)·자이로볼·일렉트릭볼은 입력 없이도 지원. (#473의 `known`은 이 후속에서 삭제 = 코드 줄어듦)
- 화면: "상대 실수치 입력" 칸을 **"알고 있으면 고정"** 으로 바꾼다(필수 문구 제거). 비어 있을 때 안내: "비워 두면 가능한 모든 값을 평균내요. 선후공(스피드)·받은 데미지(공격) 줄을 추가하면 그 범위 안에서만 계산해 더 좁아져요." 채우기 버튼은 유지(범위 가운데로 고정하는 용도).
- 가정 줄(결과 아래)에 "상대 스피드/공격: 직접 입력 N / 역산 범위 a~b 평균 / 전체 평균" 한 줄을 더한다.

## 6. 시험 (`scripts/defense-inference-check/14-…mjs` 확장 + 새 모듈 15)
기존 모듈은 이미 입력을 준다. 새 시험은 **입력 없이** 돌린다.
1. **위력 사본 동치**: 자이로볼/일렉트릭볼 `s`마다 스피드 덮어쓰기 경로의 `damageParts`와 위력 고정 사본의 `damageParts`가 같다(깊은 비교).
2. **왕복(핵심)**: 진짜 배분으로 관측을 만들고 **입력 없이** 역산해도 진짜 배분이 후보에 남는다(superset). 자이로볼·일렉트릭볼 공격/방어, 속임수 방어 각 40건.
3. **단일 후보 = 고정 입력**: `opponentSpeedRange: {min: s, max: s}` 결과가 `opponentSpeed: s` 결과와 JSON 동일(결과 객체 전체).
4. **정보량 단조**: 입력 없음 ⊇ 범위 ⊇ 고정 값 순으로 `feasible` 수가 줄거나 같다.
5. **사전 패스**: 선후공 줄을 넣으면 자이로볼 역산의 `feasible`이 줄거나 같다. 선후공이 모순이면 범위 없이 전체로 간다.
6. **해시 불변**: `test:inference` 결합 해시 `10040ffa0108c9a3`. 단 무작위 왕복 후보 필터(`defense-inference-check.mjs:44`)는 지원 기술이 늘어 속임수(방어)가 섞이므로 `!m.usesTargetAttackStat`을 더해 난수열을 지킨다(공격 쪽 필터에는 이미 있다).

## 7. 비용 측정 계획·중단 기준
- 비용이 느는 곳은 `candidateLikelihood` 안쪽 루프의 `values.length`(관측 하나의 데미지 값 수). 단일 난수는 16, 평균을 낸 관측은 ~수십~수백. 후보 수(HP×방어×특방×성격 묶음 ≈ 33³×9)는 그대로다.
- 측정: 기존 방어 역산 3관측 시나리오에서 한 관측만 자이로볼/속임수로 바꿔 `inferDefense`·`inferCombined` 시간을 입력 있음/없음/범위로 잰다. 결과는 아래 "측정"에 적는다.
- **중단 기준(제안)**: 화면에서 결과가 나오기까지 **입력 없음 기준 2초(회사 PC)** 를 넘으면 후보 수 줄이기(값 합치기 근사·추가 캐시)를 먼저 하고, 그래도 넘으면 이 방식은 접고 직접 입력만 남긴다. 노력치 역산 전체를 접는 판단은 이 결과와 별개로 사용자가 한다.

## 8. 알려진 한계(수용)
- **같은 잠재 변수를 공유하는 관측들**(자이로볼 두 번)은 관측마다 독립으로 평균 내므로 실제보다 **넓게** 나온다(superset, 진짜 배분은 놓치지 않는다). 정확히 하려면 잠재 값을 바깥 루프로 빼야 해 비용이 `n`배다.
- 성격은 다른 역산과 공유되지만 평균에서는 스피드/공격 성격 보정을 독립 사전(17:4:4)으로 본다. 결합 후 성격 후보가 좁혀져도 평균은 갱신하지 않는다.
- 포인트 사전은 균등이다(실전에서는 0·32에 몰리지만 `isExtremePoints` 같은 별도 가중과 섞지 않는다).
- 후보 스피드/공격에 실효 보정(스카프·순풍·마비 등 선후공 조건)은 반영하지 않는다 — 위력 식의 "실효 스피드"에서 도구·랭크는 평가기가 입력 슬롯 값으로 곱한다.
