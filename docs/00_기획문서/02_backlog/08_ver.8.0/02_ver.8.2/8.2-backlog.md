- **9.1~ = 노력치 역산 집중 작업.** 리팩토링이 끝난 뒤에 한다. 쟁점 A~J(`8.2-노력치역산-현행설계서.md` §12)를 **전부 확인·검수·검증하고, 그 결과로 작업 항목을 다시 뽑는다**(채택·폐기). 전수 검사와 갈아엎기는 이 단계다. 최악의 경우 역산 기능을 폐지하거나 더 이상 손보지 않기로 할 수 있다.
- **10.0 = 9.x에서 만든 역산 작업물의 리팩토링 메이저.**
- **9.3(AI·엔진 개선)은 스킵**한다 → 다음 AI 작업 후보는 **10.3**. `CLAUDE.md`의 "x.3에 AI 작업이 없으면 일반 버전으로 쓴다"로 가능해 규칙 변경은 필요 없다. 8.3은 그대로 AI·엔진 전용이다.
- **8.4 UI/UX 감사에서 역산 화면을 제외하지 않는다.** 갈아엎기 전에 지금 다듬을 수 있는 부분은 8.x에서 전부 다듬는다. 그 후보 배치는 현행 설계서 §13 원안(평가기-엔진 정합 D→8.3, 입력 UX·관측 모델·결과 표현 B·E·F→8.4 감사 안)을 참고한다.
- **착수 때 만들 것**: 9.0은 새 메이저라 `09_ver.9.0/` 폴더·`9.0-backlog.md`·폴더 `README.md`를 만들고 `CLAUDE.md` 폴더 목록과 루트 README 문서 절도 함께 갱신한다(첫 백로그 규칙). 9.1의 쟁점 검수에 쓸 모델은 사용자가 고려 중(Opus).
