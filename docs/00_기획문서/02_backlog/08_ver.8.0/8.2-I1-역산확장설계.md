# 8.2 I1 — 노력치 역산 남은 항목 설계

**작성 2026-11-10 — 설계 문서다. 구현은 사용자 결정 뒤.** 방침: 역산 미지원 5종을 모두 푼다(사용자 결정 2026-11-10). 공격 역산(받은 데미지)의 **고정 데미지·쓰러진 다단히트**는 구현을 마쳤다(PR #469). 이 문서는 남은 것을 다룬다. `test:inference` 결합 해시(`10040ffa0108c9a3`)는 그대로여야 하므로 새 시험은 맨 뒤 모듈(12~)에 더한다.

## 0. 용어
- **방어 역산** = 내가 상대를 때린 관측(%)으로 상대의 HP·방어·특방을 추정. **공격 역산** = 상대가 나를 때린 관측(HP)으로 상대의 공격·특공을 추정. 둘 다 `evaluateSlotMatchup`이 만든 `DamageParts`로 정수 데미지식(16단계 난수)을 돌려 후보(포인트×성격)의 가능도를 구한다.
- 지금 `evaluateSlotMatchup`은 자이로볼·일렉트릭볼·속임수·셸암즈를 **이미 계산한다**(`matchupEvaluator.ts:338~400`, 매치업 화면용). 역산이 못 쓰는 이유는 후보를 만들 때 **다른 쪽 스탯을 모르기 때문**이다.

## 1. 속임수 (Foul Play) — 공격 쉬움, 방어는 입력 필요
속임수는 **맞는 쪽의 공격 스탯**으로 데미지를 낸다.
| 방향 | 상황 | 설계 |
|---|---|---|
| 공격 역산 | 상대가 내게 속임수 | 데미지는 **내 공격·내 방어**로 정해져 전부 아는 값이다. 상대 공격 후보를 거르지 못하고(고정 데미지와 같은 위치) 관측이 맞는지만 확인한다 → 후보 전체 가능, 모순이면 `contradiction`. **작음(고정 데미지 구현 재사용)** |
| 방어 역산 | 내가 상대에게 속임수 | 데미지에 **상대의 공격(미지)과 방어(미지)**가 같이 든다. → 새 입력 **`opponentAttack`(상대 공격 실수치)**를 받아 `defenderRealStats.atk`로 덮어쓴다. 값은 사용자가 직접 넣거나, 같은 상대의 **공격 역산 결과 중앙값으로 채우기** 버튼 |

## 2. 자이로볼·일렉트릭볼 — 상대 스피드 입력 필요
위력이 **양측 실효 스피드 비율**로 정해진다(`gyroBallPowerFromSpeeds`). 역산하는 상대의 스피드를 모르면 위력이 안 정해진다.
- 새 입력 **`opponentSpeed`(상대 스피드 실수치)**를 방어·공격 역산 양쪽 입력에 선택 필드로 추가하고, 평가기에 `speedOverride` 옵션(상대 슬롯의 `spe` 실수치 덮어쓰기)을 넣는다. 내 쪽 스피드·랭크·도구는 지금처럼 슬롯에서 읽는다.
- 값 얻는 길: ① 직접 입력 ② 같은 상대의 **스피드 역산 결과 중앙값으로 채우기**(결합 역산이 이미 같은 상대의 스피드 결과를 가진다 — `combinedInference.ts`).
- 비어 있으면 지금처럼 "상대 스피드를 입력해 주세요" 안내로 막는다(오류 문구 변경).
- 스피드를 후보 축(공격×스피드, 33×33×성격)으로 넣는 방식은 **채택하지 않는다** — 후보가 크게 늘고 스피드 역산과 중복이다.

## 3. 셸암즈 — 물리/특수가 후보에 따라 갈린다
셸암즈는 **물리·특수 중 맞는 쪽 데미지가 더 큰 쪽**으로 나간다(평가기는 동점이면 물리로 확정하는 규칙을 이미 쓴다 — 같은 규칙 유지).
| 방향 | 설계 |
|---|---|
| 공격 역산 | 상대 공격(a)·특공(s)이 둘 다 미지. 관측 한 개가 **쌍 (a,s)의 함수**가 된다: 후보 (a,s)로 물리·특수 두 `DamageParts`를 내 방어·특방에 맞춰 계산하고 더 큰 쪽의 난수표로 가능도를 구한다. 현재 `runCandidates`는 쌍 루프(`a`×`s`)를 이미 돌아 쌍 가능도를 곱하므로, **쌍 단위 관측(`pairRolls`)을 가능도 곱에 하나 더 끼우면 된다**(`atkL[i]·spaL[j]·pairL(i,j)`). |
| 방어 역산 | 상대 방어(d)·특방(sp)이 미지. 후보가 `[hp, def, spd]` 3중 루프라 쌍 (d,sp)가 이미 같이 있다. 관측에 **물리/특수 두 `DamageParts`**를 들고, 후보마다 둘 다 계산해 큰 쪽 난수표를 쓴다(`rollsFor` 캐시 키를 두 스탯으로). |
- 어려움: **중간~큼**. 가능도 루프 두 곳이 건드려지고 성능(쌍×16×16) 확인이 필요하다. 시행 수가 늘어 `test:inference` 시간이 늘 수 있다.

## 4. 방어 역산의 고정 데미지·쓰러진 다단히트
- **고정 데미지**: 방어 역산 후보는 `defenseKey`(def/spd)로 방어 스탯을 고르는 구조라 **방어 무관 관측**이 없다. 관측에 `fixedDamage`를 두고 난수표를 `{values:[50]}`로 하되, 방어 축의 루프에서는 "방어 스탯을 쓰지 않는 관측"으로 분기해야 한다. 정보는 **HP만** 준다(맞은 % ↔ 50/maxHP) — 오히려 HP 후보를 좁히는 데 유용하다. 작음~중간.
- **쓰러진 다단히트**: `candidateLikelihood`는 "맞은 뒤 %"를 한 번에 판정한다. 정확히 하려면 **(n-1)타(안 쓰러짐, % 미공개)** + **마지막 한 타(0%)**를 순차 관측 두 개로 쪼개고, 앞 관측의 "맞은 뒤 %"를 **와일드카드**(아무 값)로 취급한다. `PreparedObservation`에 `unobserved`(앞 관측용) 표시를 두는 정도다. 중간.

## 5. 추천 순서와 규모
| 순서 | 항목 | 규모 | 비고 |
|---|---|---|---|
| 1 | 속임수 공격 역산 | 작음 | 구현 재사용, UI 영향 없음 |
| 2 | 자이로볼·일렉트릭볼(양방향) + 속임수 방어 | 중간 | `opponentSpeed`·`opponentAttack` 입력 UI(+ 중앙값 채우기 버튼), 평가기 덮어쓰기 옵션 |
| 3 | 방어 역산 고정 데미지·쓰러진 다단히트 | 중간 | `candidateLikelihood` 순차 관측 |
| 4 | 셸암즈(양방향) | 중간~큼 | 쌍 가능도 |
PR은 항목 묶음마다 하나씩(1 / 2 / 3 / 4). 시험은 기존 방식대로 **왕복**(진짜 배분으로 관측을 만들어 후보에 남는지)을 모듈 13~16에 더한다.

## 6. 결정할 것
1. **입력 방식**(§1·§2): 상대 스피드·공격 실수치를 **직접 입력 + 역산 결과 중앙값 채우기 버튼**으로 받는 데 동의하는가? (대안: 입력 없이 역산 결과의 범위 전체를 평균내 계산 — 부정확·복잡해 비추천)
2. 순서(§5)대로 진행해도 되는가. 4(셸암즈)는 규모가 커서 8.2에서 빼고 따로 둘 수도 있다.
3. 셸암즈 동점(물리=특수 데미지)은 평가기 규칙(물리)을 유지해도 되는가.
