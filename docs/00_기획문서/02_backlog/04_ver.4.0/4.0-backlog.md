# ver.4.0 백로그

3.7 마무리에서 넘어온 항목. 이전 버전: `../03_ver.3.0/3.7-backlog.md`(3.7 종료 — HP 눈금 강조 확대·패널 고정 영역, 방어 역산 턴 종료 효과, 내구 조정 탭).

**작업은 아직 시작하지 않았다.** 범위는 2026-10-15에 아래와 같이 확정했다(스피드 역산만 논의 대기).

## 진행 순서 (2026-10-15 확정)

4.0은 새 메이저 버전이라 CLAUDE.md 규칙대로 `ponytail` 코드 전체 리팩토링 → 엔진 로직 테스트·기능 테스트를 하지만, **기능 작업이 남아 있어 리팩토링과 디자인 검수는 가장 마지막으로 미룬다.**

1. **기능 작업**(아래 ① F1~F4, 필요하면 ② 논의 항목) — 항목별 브랜치 → PR 1개(커밋 1개) → `dev` squash.
2. **`main` 머지 직전 브랜치**(예: `ver4.0-final`, 착수 때 정한다)에서 **리팩토링 → 디자인 검수** 순서로 진행한다. 이 브랜치에서 낸 PR이 마지막 PR이다.
3. 리팩토링 후 **엔진 로직 테스트 → 기능 테스트**(사용자 화면 확인) → 4.0 마무리(미수정 한계 정리) → `dev` → `main` PR 제목 `ver4.0`.

- 리팩토링은 동작을 바꾸지 않아야 하므로, **기능 작업이 전부 끝난 시점의 `dev`로 기준값을 다시 기록한 뒤** 리팩토링에 들어간다(아래 "기준값" — 기능 작업이 역산 코드·AI를 건드리면 해시가 바뀔 수 있다).
- 디자인 검수는 화면만 바꾸고 엔진·AI 기준값을 건드리지 않으므로 리팩토링 PR과 따로 PR을 낸다. 리팩토링으로 컴포넌트를 나눈 뒤에 검수한다(나누기 전에 검수하면 CSS를 다시 옮겨야 한다).

## ① 기능 작업

### F1 모바일 폭 관측 행 정리 (노력치 역산 탭 방어 역산) — **완료**(PR #275, 2026-10-15)

- **증상**: 3.7 A4로 관측 행에 "턴 종료 효과"가 들어간 뒤, 모바일 폭(≤760px)에서 관측 행이 어중간하게 잘렸다(PC는 괜찮았음).
- **결과**: 사용자와 PC·모바일 화면을 여러 번 보며 범위가 넓어졌다 — 모바일 재배치뿐 아니라 PC·모바일 공통 정리까지 했다.
  - 모바일 행 구조: 종류·기술(50:50) / (타수·메가, 있을 때만) / HP 변화·급소 / 턴 종료 효과. `#번호`·✕·"가능"은 왼쪽 여백에 쌓고, 오류 문구는 길어서 행 아래 전 폭.
  - 공통: 순서 HP 변화 → 급소 → 가능/불가능 → ✕(오른쪽 위 고정). 턴 종료 효과는 접기를 없애 행 아래 한 줄로 상시 표시(체크해야 계산에 반영). 맹독은 풀다운 대신 "맹독" 알약 토글 + 1~15턴 스테퍼.
  - 이 패널의 체크박스 8곳을 전부 알약 토글(`.dinf-crit`·`.dinf-check`·`.dinf-endturn label` 공용 스타일)로 통일. 종류 선택 문구는 "입힌 데미지"/"받은 데미지".
  - 같이 고친 버그: select가 버튼·입력칸보다 커 보이던 높이 불일치(행 안 컨트롤 2rem 고정)와 그 뒤 글자 아래가 잘리던 문제(위아래 여백 제거), PC 긴 행의 ✕ 단독 줄바꿈(✕ 위치 고정).
- **디자인 검수에 넘길 것**: 알약 토글 통일은 노력치 역산 패널 안에서만 했다 — 다른 화면의 체크박스·풀다운 통일은 검수에서 본다. 모바일 왼쪽 여백(#·✕·가능)은 고정 위치값이라 행 높이가 크게 바뀌는 경우(오류 문구 줄바꿈 등)의 어긋남을 검수 때 다시 본다. 340px 미만 폭의 select 글자 잘림은 확인하지 못했다.
- 모바일 폭 화면 확인: HP 눈금 설명 패널(H1-b)·내구 조정 탭(A3)·관측 행(F1) 모두 완료.

### F2 방어 역산 턴 종료 효과(A4) 한계 해소 — **완료**(PR #276, 2026-10-15)

- **자뭉열매**: 관측 행 턴 종료 효과 목록에 "자뭉열매 발동" 토글 추가(마지막 줄에는 이것만 "맞은 직후 효과"로 표시). 엔진은 자뭉열매를 행동 직후에 먹어서 화면의 "맞은 뒤 %"에 회복이 이미 섞이므로, 켠 줄은 후보별로 맞은 뒤 HP ≤ 1/2일 때만 인정하고 회복(최대 HP÷4, 숙성 2배)을 더한 값으로 화면 %와 대조한다. 사용자가 "먹은 줄"을 직접 표시하는 방식이라 먹음 여부를 경로별로 추적하지 않아도 된다. 한 번만 가능(두 줄에 켜면 거부), 먹은 줄은 맞은 뒤 %가 맞기 전 %보다 커도 허용, 후보 카드 정렬용 손실에도 회복분 반영.
- **다음 줄 예상값**: 턴 종료 효과를 고르면 다음 줄 "맞기 전 %"를 맞은 뒤 %에 16분율 합(÷16, 반올림)을 더한 값으로 채운다(직접 고친 값은 유지, 실제 화면과 1쯤 어긋날 수 있어 안내 문구에 적음).
- **메가진화**: 어느 줄이든 메가 폼을 고르면 도구 효과(먹다남은음식·자뭉열매)는 메가스톤을 들고 있으므로 모든 줄에서 비활성·해제, 계산에서도 무시.
- **제외 확정**: 공격 역산 턴 종료 효과(내 HP는 맞은 직후 수치를 직접 읽음) · 내 쪽 자뭉열매 토글 · "상대 도구 가정이 먹다남은음식이면 자동 켜기"(상대 도구 가정 목록은 반감 열매뿐이라 해당 없음).
- **남은 것**: 오랭열매(고정 10 회복) 미지원 · 턴 종료 시점에 HP가 절반 이하가 되어 먹는 경우(독 등으로 하락)는 "맞은 직후 먹음"만 지원.
- 검증: `test:inference` 결합 결과 해시 기준값(`10040ffa0108c9a3`) 유지, 자뭉열매 왕복 40/40·열매를 빼면 40건 어긋남·메가 무시 검증을 `defense-inference-check.mjs`에 추가.

### F3 내구 조정 탭(A3) 한계 해소 — **완료**(PR #277, 2026-10-15)

- **여러 공격 동시 버티기**: 상대 카드에 기술 3칸(가로, 결정력 탭과 같은 기술 알약·다단히트 타수). 모두 맞고도 버티는 최소 HP·방어·특방 포인트 조합을 구한다 — 같은 방어 스탯을 읽는 공격끼리 합성곱해 두고(스탯 값별 캐시), 방어·특방 두 분포는 합산 확률을 이분 탐색으로 센다. 결과는 앞 HP보다 방어+특방 합이 줄어드는 지점만 남기고, 합이 같으면 버틸 확률이 높은 쪽. 4기술(다단히트 2개 포함) 약 4ms. 기술 칸은 슬롯의 `bulkMoves`에 저장(자동저장 유지), 이전의 단일 `moveId`는 첫 칸으로 읽는다.
- **조건부 위력·HP 비율 가정(작게 붙이기)**: 상대 카드에 HP 슬라이더(분화·해수스파우팅 등)·보복·눈사태·분함의발구르기·분풀이·승부굳히기 토글·HP 1/3 이하·리베로 가정을 연결하고, 결정력 탭 `assumeOptions`와 같은 옵션을 모든 기술에 넘긴다(가정은 모든 기술에 공통).
- **교체**: 내구 조정 탭에서도 내/상대 카드를 끌어서(터치는 길게 눌러) 교체. 교체하면 상대 기술 칸은 비운다. 상대 카드는 `role="attacker"`라 `swapRole="defender"`로 구분.
- **레이아웃(사용자 요청)**: PC는 카드 두 장 가로 배열, 생존 목표·결과 영역은 카드 폭과 같은 폭으로 아래에 배치(좁은 화면은 카드 한 장 폭).
- **공통 개선(같은 PR)**: 스크린을 헤더로 이동 — "내 쪽/상대 쪽 스크린" 선택기를 날씨·필드 옆에 두고 전 탭이 같이 쓴다(각 탭의 개별 벽 선택 삭제, 역산 저장본에서 벽 제거, 교체해도 스크린은 그 편에 남김). 날씨·필드·스크린의 "없음" 칩을 없애고 켠 칩 재클릭으로 해제. 모바일 탭 4개 균등 폭·띄어쓰기 줄바꿈. 스피드 조정 설명 문구 "분배" 삭제.
- **같이 고친 버그**: 카드 기술 칸을 공용 컴포넌트(`MoveSlot`)로 뺄 때 `.matchup-move-pip` 전체에 폭 100%·말줄임이 걸려 결정력 탭 기술 알약이 늘어난 CSS 회귀 — 내구 조정 전용 클래스(`.matchup-move-row`)로 한정.
- **남은 한계**: 도구 강탈 가정 지정 없음 · 가정(HP 비율·후공 등)이 모든 기술에 공통(기술별 따로 못 줌) · 내 나머지 포인트·성격·도구·특성은 고정하고 HP·방어·특방만 바꾼다(고정 해제는 포인트 합계 제약으로 설계가 커서 하지 않음) · 성묘·토해내기 가정(`graveVisit`·`stockpile`)은 이 탭에서 지정하지 않는다.
- **리팩토링에 넘길 것**: `BulkAdjustPanel`의 가정 옵션 구성이 `MatchupPage.assumeOptions`와 거의 같은 규칙을 한 번 더 적었다(공용 함수로 뽑으면 줄일 수 있다).
- 검증: `test:inference` 결합 해시 기준값 유지, 단일 공격 29건 대조 통과, 여러 공격 12건(방어·특방 혼합 8건) 확률 전수 곱·HP별 최소 합·전체 최소 합 전수 대조를 `defense-inference-check.mjs`에 추가.

### F4 AI 속도 추가 최적화 (P1-b) — **제외 확정**(2026-10-15, 프로파일링 결과 효용 없음)

3.x에서 보류한 항목이라 4.0에서 먼저 프로파일링(`--cpu-prof`)으로 이득을 재 본 뒤 정하기로 했다. 결과:

- **체감 지연이 없다**: `sim:ai ai 30`의 턴당 판단 시간 평균 18ms·최대 94ms. 그리디 80판 약 21~26초(같은 코드도 실행마다 ±20%).
- **시간 분포**(CPU 25.9초): 61%가 `partyRaceValue → fight → afterDuel/duel` 연쇄 탐색, 나머지 약 35%는 데미지·타수 분포 계산(3.0 P1에서 메모화 완료). 단일 함수 최대 자체 시간 5.9%(`afterDuel`) — 한 곳에 몰린 병목이 없다.
- **연쇄 탐색 규모**(그리디 80판): `partyRaceValue` 6,437회 → 탐색 상태 3,567,449개(호출당 약 550개), 메모 적중률 `afterDuel` 19%·`duel` 9%, 메모 키 평균 61자. 대부분이 처음 보는 상태라 되풀이 낭비가 아니라 실제 필요한 탐색이다.
- **시험**: `positionKey` 문자열을 더 싸게 만드는 시험본(출력 동일)을 번갈아 3회 측정 — 21.3초 대 21.5초, 21.3초 대 21.9초, 26.9초 대 26.1초로 노이즈(±2%) 안. 문자열 생성은 병목이 아니다.
- **남은 방법**: 메모 키를 숫자·중첩 Map으로 교체(추정 최대 5~8%, 키 충돌 시 결과가 바뀔 수 있어 해시 전수 검증 필요) · 상태 복사 줄이기(3~5%, 가독성 비용) · 탐색 상태 수 줄이기(결과가 바뀌어 "결과 불변" 조건과 충돌 — 불가). 모두 사용자 체감 이득이 없어 하지 않는다.
- 결론: 4.0에서 하지 않고 한계로 남긴다. 다시 올릴 때는 이 측정을 기준으로(메모 키 숫자화부터) 시작한다.

## ② 스피드 역산 — **한계로 확정**(2026-10-15)

- **동속 가능도 ½**: 실효 스피드가 정확히 같으면 선후공이 무작위라 어느 결과든 가능하다 — 그 후보를 탈락시키지 않고 가능도 ½로 반영한다. 게임 규칙(50%) 그대로라 버그가 아니라 정확한 모델이다.
- **관측 폭**: 관측은 부등식("이 값보다 빠르다/느리다")이라 한 번으로는 범위가 넓고, 랭크·순풍·스카프 등 조건이 다른 관측을 모을수록 좁아진다. 정보량 자체의 한계이며 역산 탭에 안내 문구가 있다.
- 검토한 대안(다음 관측 조건 제안 기능·구간 그래프)은 효용이 불확실하거나 정보량이 그대로라 하지 않는다.
