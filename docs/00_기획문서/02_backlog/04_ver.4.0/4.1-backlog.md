# ver.4.1 백로그

4.0 마무리에서 넘어온 미수정 한계 가운데 **실제로 고칠 것만** 추렸다. 이전 버전: `4.0-backlog.md`(4.0 종료 — 리팩토링·디자인 검수·AI 상대 HP 비율 표기).

범위는 2026-10-19에 사용자와 확정했다(같은 날 요청받은 배틀타워 랭크배틀 시스템은 규모가 커서 **전부 5.0 백로그로 옮겼다** → `../05_ver.5.0/5.0-backlog.md`). 4.1은 마이너 버전이라 전체 리팩토링은 하지 않는다. 코드를 고치므로 항목별 브랜치 → PR 1개(커밋 1개) → `dev` squash, 마지막에 `dev` → `main` PR 제목 `ver4.1`.

## ① 기능·개선 작업

### A1 AI 비율 표기(#292)의 같은 종 중복 버그

- **증상**: 상대 파티에 같은 종이 둘이면 턴 종료 줄·행동 줄의 `%` 변환이 뒤의 포켓몬 최대 HP를 쓴다. 두 마리의 노력치·성격이 다르면 최대 HP가 달라 `%`가 틀린다.
- **원인**: `battleLog/BattleBoard.tsx`의 `aiMaxHp`가 `Object.fromEntries(party.map(f => [f.slot.pokemonId, f.maxHp]))`로 종 id를 키로 삼아 같은 종이 덮어쓰인다. 변환 쪽(`BattleTurnLog.tsx`의 `fmtHp`·`hpAsPercent`, `turnLog/hpFormat.ts`의 `useActionHp`)도 종 id로 조회한다.
- **영향**: 배틀타워는 종 중복이 없어 지금은 안 드러난다. 프런티어·배틀 시뮬레이터에서 같은 종을 두 마리 낼 때만 해당.
- **방향**: 키를 종 id가 아닌 구분되는 값(슬롯 인덱스 등)으로 바꾼다. 로그 쪽이 `activePokemonIds`로 종 id만 갖고 있다면 거기서 무엇을 더 찍을 수 있는지 착수 때 읽어 정한다. **엔진 로그·해시는 불변이어야 한다**(표시 계층만 고친다).
- **검증**: 같은 종 두 마리 파티(최대 HP가 다르게)로 AI 배틀 → `%`가 각 개체 기준인지 사용자 화면 확인. 엔진 해시(`regress 200`) 불변.
- **함께 볼 것**: 볼주머니 회복은 공격자·방어자 합산이라 AI가 낀 행동이면 수치를 감춘다 — 이번에 바꿀 필요가 있는지 코드를 읽고 판단한다(필수 아님).

### A2 터치 영역 확장을 칩 공통 마커 클래스로 (4.0 D4 한계)

- **문제**: `index.css` 맨 아래 `@media (pointer: coarse)` 블록이 눌리는 영역을 넓힐 클래스를 **수동으로 나열**한다(30종). 새 칩·알약 클래스를 만들면 직접 목록에 추가해야 하고, 빠뜨려도 에러 없이 모바일 터치 영역만 조용히 작아진다. `overflow: hidden`인 `.party-move-pip`·`.dinf-stepper`는 `::after`가 잘려 확장하지 못했다.
- **방향(사용자 확정)**: 공통 마커 클래스를 하나 두고 그 클래스에만 확장 규칙을 건다. 새 컨트롤은 마커만 붙이면 된다. 목록 나열 방식은 폐기한다.
- **같이 해결되는 것**: 4.0 마무리의 "칩/알약 클래스 9종 공용화" 한계. 중복이던 두 쌍(`party-meta-pip`/`matchup-meta-pip`, `party-move-pip`/`matchup-move-pip`)이 목록 때문에 따로 관리되던 문제가 사라지므로 클래스 자체를 합치지 않는다(아래 제외 확정).
- **주의**:
  - 마커를 붙이는 TSX 변경이 30여 곳이라, 누락 확인용으로 `pointer: coarse` 대상이던 클래스 목록과 마커 부착 목록을 착수 때 대조한다.
  - 규칙은 `position: relative`를 덮어쓰므로 이미 `absolute`·`fixed`인 요소(모달 닫기 ✕ 등)에 걸리면 레이아웃이 깨진다. 마커 규칙은 `:where()`로 낮은 명시도로 걸거나, 기존 위치 지정이 있는 요소는 `::after`만 쓰는 방식을 검토한다.
  - `overflow: hidden` 두 곳은 래퍼를 두거나 패딩·`min-height`로 보완하는 방식 중 착수 때 택한다. 안 되면 한계로 남기고 이유를 적는다.
- **검증**: 모바일 폭(≤760px)에서 4.0 D4와 같은 화면들의 모양·배치 불변(눌리는 영역만 넓어짐), PC는 변화 없음. 사용자 화면 확인(개발자도구 모바일 에뮬레이션).

### A3 `prefers-reduced-motion` 대응 확대 (4.0 D4 한계)

- **현황**: 대응 블록이 `BattleLogPage.css`(3곳)·`InfoTooltip.css`(1곳) 두 파일뿐이다. `animation`·`transition` 선언은 9개 CSS 파일 27곳(`Sidebar.css` 8곳, `BattleLogPage.css` 10곳 등)에 있다.
- **방향**: 파일별로 움직임이 있는 선언을 훑어 `reduce`일 때 끄거나 즉시 전환으로 줄인다. 전역 한 줄(`* { animation: none; transition: none }`)로 일괄 끄는 방식은 상태 변화 피드백(HP바 등)까지 사라질 수 있어 먼저 대상 선언 목록을 만들고 정한다.
- **검증**: 시스템 "동작 줄이기" 설정 또는 개발자도구 렌더링 탭의 `prefers-reduced-motion: reduce` 에뮬레이션으로 사용자 화면 확인.

## ③ 이월된 미수정 한계 (그대로 이월)

- **5.0으로 옮긴 것(2026-10-19 사용자 결정)**: 배틀타워 랭크배틀 시스템(R1)과 랭크별 AI 성향 차등(R2). 규칙·결정 사항·논의 목록은 `../05_ver.5.0/5.0-backlog.md`에 있다.

- **노력치 역산 미지원 기술**: 고정 데미지 · 자이로볼/일렉트릭볼 · 속임수 · 셸암즈 · 쓰러진 다단히트. 요청이 올 때만 한다. 멀티스케일·섀도실드 + 다단히트(V4-b)는 이미 제외 확정이다.
- **스피드 역산**: 동속 가능도 ½·관측 폭은 정보량의 한계로 확정, **H1-c**는 원본에 기준이 없어 보류.
- **터치·모바일 실기기**: 기기별 길게 누르기·스크롤 상호작용의 실기기 전수 점검은 사용자 수행 항목이다(A2 끝난 뒤 실기기에서 확인해 주면 한계로 정리한다).
- **일괄 기능 체크리스트**: 계산 4개 탭·도감·파티·배틀 전 화면을 한꺼번에 도는 점검은 4.0에서 하지 않았다. 4.1 마지막에 A1~A3 화면 확인과 묶어 할지 마무리 때 정한다.
- **AI 비율 표기의 나머지**: 로그 문구에 HP 수치가 새로 생기면 `useActionHp`·`hpAsPercent` 대상에 추가해야 한다(규칙으로 유지).

## 제외 확정 (재론하지 않는다)

4.0 백로그의 제외 확정 목록 전부에 더해, 2026-10-19에 아래를 제외했다.

- **칩/알약 클래스 9종 공용화** — 실제 중복은 `party-meta-pip`/`matchup-meta-pip`, `party-move-pip`/`matchup-move-pip` 두 쌍뿐이고 나머지는 토글형·표시용·버튼형으로 쓰임새가 달라 합치면 modifier만 늘어난다. 두 쌍을 합쳐도 CSS 약 45줄이 줄 뿐이고 시각 회귀(핵심 화면 8곳, 해시로 검증 불가)·터치 목록 이름 누락 위험이 있다. 문제의 핵심이던 "터치 목록 수동 관리"는 A2로 푼다.
- **리팩토링 잔여 한계** — `applyEffectMove` 276줄(독립 케이스 77개의 평평한 switch, 호출처 `evaluator.ts` 1곳) · `defineAbilityHitEffect` 235줄 · `runCandidates` 215줄(defenseInference) · `computeSoloOffensePower` 180줄 · `useBattleLogSession` 훅 564줄 · 컨텍스트 필드 100개 넘는 단계(`MirroredCtx` 126개 등). 사용자 체감이 없고, 엔진·계산은 검증 세트로 회귀를 막을 수 있어도 변환 도구를 저장소에 남기지 않아 손 작업 비용이 크며, 훅·컨텍스트는 설계를 바꿔야 한다. **예외**: 해당 함수를 기능 변경으로 건드리는 PR이 생기면 그 PR 안에서만 같이 분할한다.
- **배틀비디오 다시보기의 AI 상대 비율 표기** — 어느 편이 AI인지 기록하려면 비디오 저장 형식을 바꿔야 하고 기존 저장분에는 적용되지 않는다. 비디오는 로그를 저장해 두는 기록 용도라 실수치 그대로 둔다. 양쪽을 직접 조작하는 대전도 실수치 그대로.
- **볼주머니 회복의 AI 합산 수치 표기** — A1 작업 중 코드를 읽고 필요하면 그때 판단(필수 항목 아님).
