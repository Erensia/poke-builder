## ① 기능·개선 작업

### A1 AI 비율 표기(#292)의 같은 종 중복 버그 — **완료**(PR #296)

- **증상·원인**: 상대 파티에 같은 종이 둘이면 턴 종료 줄·행동 줄의 `%` 변환이 뒤의 개체 최대 HP를 썼다. `BattleBoard`의 `aiMaxHp`가 종 id를 키로 삼아 같은 종이 덮어쓰였고, 로그에는 종 id뿐이라 개체를 가를 수 없었다.
- **수정**: 엔진 로그에 필드를 더하면 `regress` 해시(`TurnResult` 전체 JSON)가 바뀌므로 표시 계층에서 해결했다. `battleLogText.activeIndexTrace(log, side, partyIds)`가 교체 기록(`switches`)을 따라 AI 편의 활성 파티 인덱스를 복원하고, `BattleTurnLog`는 `aiMaxHp` 대신 `aiParty`(종 id·최대 HP)를 받아 파티 인덱스로 최대 HP를 찾는다(행동마다 `HpFormatContext`를 내림). 행동 도중 교체(유턴류·강제 교체·탈출버튼)는 원인이 필드로 안 가려져, 행동에 찍힌 종이 맞는 후보를 앞에서부터 고른다(교체 전후가 같은 종이면 앞의 것 — 그 한 행동의 최대 HP만 틀릴 수 있음).
- **검증 도구**: `sim:ai -- logidx`(환경변수 `PIVOT` / `POOL=samples` / `DUP=1` 조합) — 로그만으로 복원한 인덱스를 턴마다 실제 엔진 `activeIndex`와 대조, 불일치 0건. 처음 구현은 탈출버튼·위기회피 교체에서 207건이 잡혀 후보 선택 방식으로 고쳤다.
- **실질 영향**: 파티 편성에서 같은 포켓몬을 둘 편성할 수 없어 **실제 대전에서는 도달하지 않는 경로**였다(사용자 확인). 방어적 수정이다.

### A2 터치 영역 확장을 칩 공통 마커 클래스로 (4.0 D4 한계) — **완료**(PR #297, 후속 #298)

- **문제**: `index.css`의 `pointer: coarse` 블록이 30종 클래스를 손으로 나열해, 새 칩을 만들고 목록에 빠뜨려도 에러 없이 모바일 터치 영역만 조용히 작아졌다. `overflow: hidden`인 `.party-move-pip`·`.dinf-stepper`는 확장하지 못했다.
- **수정**: `:where(.tap-target, .tap-targets button)` 규칙 하나로 교체했다. 새 칩·알약·작은 버튼은 `className`에 `tap-target`, 같은 종류 버튼 묶음은 부모에 `tap-targets`를 붙인다. 기존 대상 91곳(TSX 27개 파일)에 마커를 붙였고, 옛 목록 클래스가 쓰인 줄 중 마커 없는 줄 0건으로 대조했다. `:where`라 명시도가 0이어서 `position: absolute/fixed` 요소는 자기 규칙이 이긴다.
- **overflow 두 곳도 확장**: `.party-move-pip`은 말줄임용 `overflow`를 안쪽 `<span class="party-move-pip-text">`로 옮기고(`min-width: 0`, 그리드 `minmax(0, 1fr)`), `.dinf-stepper`는 `overflow: hidden` 대신 양끝 버튼에 반경을 줬다. 사용자 요청으로 스테퍼 `line-height: 1.35`를 맞춰 맹독 알약(`.toggle-pill`)과 세로 크기를 같게 했다.
- **칩/알약 클래스 9종 공용화는 하지 않는다**(제외 확정): 터치 목록 수동 관리 문제가 마커로 풀려 합칠 이유가 사라졌다.
- **후속 버그(PR #298)**: 모바일에서 `has-tip` 버튼(무작위 샘플·랜덤 구축)을 누르면 툴팁이 버튼 줄을 덮고 오른쪽으로 잘렸다. 마커의 `::after { inset: -8px -2px }`가 `.has-tip::after`(툴팁)와 같은 요소를 겨냥해, 툴팁이 지정하지 않은 `top`·`right`가 새어 들어갔다. **4.0 D4의 수동 목록 때부터 있던 충돌**을 마커 방식이 이어받은 것이다(당시 충돌 점검을 클래스 이름 기준으로만 해 같은 요소의 다른 클래스를 놓쳤다). 마커를 `::before`로 옮겨 해결했다 — `::before`/`::after`를 쓰는 CSS 규칙 전체를 대조해 겹치는 요소가 없음을 확인했고, 요소가 이미 `::before`를 쓰면(`.speedtab-card`, `summary` 등) 마커를 쓰지 않는다는 규칙을 `index.css` 주석에 남겼다.

### A3 `prefers-reduced-motion` 대응 확대 (4.0 D4 한계) — **완료**(PR #300)

- **분류 결과**: 대응이 CSS 2개 파일뿐이었고 `transition`·`animation`은 9개 CSS 27곳에 있었다. 슬라이드·크기 변화(사이드바, HP바, 슬라이더)와 색·불투명도 페이드 모두 기능 필수가 아닌 연출이지만, 단계가 이어지는 전환(사이드바는 폭이 바뀐 뒤 글자가 지연 후 나타남)은 화면 구조를 맞추는 역할도 한다.
- **수정**: 파일마다 목록을 만드는 대신 `index.css`에 전역 reduce 규칙 한 블록을 둔다(새 `transition`·`animation`도 자동으로 걸림). 전환은 끄지 않고 `--reduced-transition`(0.08s)으로 짧게만 하고 딜레이는 그대로 둔다. 처음에는 0.01ms로 끄고 딜레이까지 지웠는데, 사이드바 단계 전환이 어색하고 모바일에서 깜빡여서 바꿨다. 키프레임·반복 애니메이션은 0.01ms 1회로 끝낸다. 끝 상태를 직접 정한 기존 reduce 블록(우승 글로우·AI 생각 중 점·툴팁)은 유지했다. 값(0.08s)은 사용자 화면 확인으로 정했고 변수 하나로 조절한다.
- **JS**: `MoveDexPage`의 `scrollIntoView({behavior: "smooth"})`는 CSS가 안 먹는 옵션이라 reduce면 `"auto"`로 바꿨다. `transitionend`·`animationend`에 의존하는 코드는 없다.

### A4 파티 편성 화면의 무작위 샘플·랜덤 구축 설명을 제목 옆 ⓘ 한 개로 (A2 후속에서 파생) — **완료**(PR #299)

- **배경**: #298에서 `.has-tip` 툴팁을 호버 기기 전용으로 바꾸자 모바일에서는 이 두 버튼의 설명이 아예 안 보였다. 버튼 줄(300px)이 버튼 4개로 꽉 차 버튼마다 ⓘ를 둘 수도 없었다.
- **수정**: "내 파티 / 상대 파티" 제목을 기존 공용 `InfoTooltip`으로 감싸 ⓘ 한 개에 두 설명을 합쳤다(PC는 제목·ⓘ 호버, 모바일은 ⓘ 탭). 랜덤 구축 설명은 그 버튼이 보일 때만 넣고 두 설명 사이는 줄바꿈한다(`InfoTooltip` 말풍선에 `white-space: pre-line`). `.has-tip` 방식(`data-tip` 2곳, CSS 약 45줄)을 삭제해 툴팁이 `InfoTooltip` 하나로 통일됐다.

**이번 작업에서 얻은 규칙(CSS)**

- 새 규칙이 `::before`/`::after`를 쓰면 **같은 요소의 다른 클래스**(예: `.has-tip`)가 쓰는 pseudo-element와 겹치는지 CSS 전체를 grep으로 확인한다. 이름이 같은 클래스만 보면 놓친다.
- 요소가 이미 `::before`를 쓰거나 `overflow: hidden`이면 터치 마커(`tap-target`)를 쓰지 않는다. 안쪽 글자 칸으로 `overflow`를 옮기는 식으로 우회한다.
- 모션은 전역 reduce 규칙 한 곳에서 조절하고, 끝 상태를 직접 정해야 하는 것만 각 CSS의 reduce 블록에서 따로 정한다. 지연(`transition-delay`)까지 지우면 순차 전환이 깨진다.
- 작업 중 발견한 것은 **현재 작업이 만든 회귀면 바로 고치고**, 현재 작업과 무관하면 이월 목록에 기록만 한다(사용자가 시키기 전에는 손대지 않는다).
