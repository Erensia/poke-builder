## ② 이관 (6.6에서 넘어옴)
### B1 → 7.3: 눈보라(눈)·번개(비) 날씨 필중 미구현
- **현상(6.6 읽기 전용 검토)**: `moves.json` 눈보라(`accuracy: 70`, effect "눈이 내리면 반드시 명중한다")·번개(70, "비가 내리면 반드시 명중한다")에는 날씨 필중을 나타내는 필드가 없고, `src/lib/battle/hitChance.ts` `computeBattleHitChance`에도 날씨 분기가 없다(필중은 노가드·록온·작아지기 vs 플라잉프레스뿐, 일격기는 고정 확률). 그래서 눈에서 눈보라, 비에서 번개가 70%로 굴려진다. 폭풍은 effect에 날씨 조항이 없어 데이터와 일치한다.
- **영향**: 명중 확률은 배틀 AI(`ai/evaluator.ts`·`ai/moveDamage.ts`)와 공유하므로 고치면 AI 평가도 바뀐다. `scripts/battle-ai-scenarios/03-engine-weather.mjs`에는 이 사례가 없다.
- **수정안(작음)**: `Move`에 "이 날씨면 필중" 필드(예: `alwaysHitsInWeather: WeatherKind`)를 추가하고 눈보라(눈)·번개(비) 데이터를 채운 뒤 `computeBattleHitChance`가 `activeWeather(state)`와 일치하면 `null`(필중)을 돌려준다. 날씨 무효화(에어로크 등)는 `activeWeather`가 이미 반영하는지 확인한다.
- **7.3 규칙**: 수정 뒤 `npm run sim:ai -- regress 200` 해시 비교 → `verify-kit` 기준값 갱신 → **집 PC에서 `verify.sh` 전체 통과**(`CLAUDE.md`). 7.3에서 폭풍(effect에 날씨 조항 없음)도 원본 규칙과 대조한다.

### B2 → 7.3: 상대가 교체한 턴의 방어·판별 실패 규칙 미구현 (2026-11-05, 프런티어 확인 중 발견)
- **규칙(사용자 확정, 2026-11-05)**: 상대가 **교체한 턴**에 방어를 쓰면 방어 사용 이펙트(태세 진입) 없이 **실패 처리**되고, **다음 턴 방어는 확정 성공**한다(연속 사용 카운터 0으로 복귀). **판별에도 같은 규칙**이 적용된다. 7.3에서 눈보라·번개(B1)와 **같이** 적용한다.
- **현상(읽기 전용 검토)**: `mirroredEffects.ts:1656~1712` `protectAndFieldSetup`은 행동 순서·상대 행동 유무를 보지 않는다. 굴림에 성공하면(`successChance = (1/3)^protectStreak`) "방어태세에 들어갔다!"를 내고 `protectStreak`를 **올린 뒤**, 상대가 자기를 겨냥하지 않았으면(`targetedSelf` 거짓 — 교체·자기 대상 기술) 문구만 "방어는 실패했다!"(`protectFailed`)로 바꾼다(2차 지시 §1 G의 "막을 게 없었다" 표기). 그래서 교체한 턴에 로그가 "방어태세에 들어갔다!" + "방어는 실패했다!"로 모순되고, 카운터가 올라가 **다음 턴은 확정 성공이 아니라 1/3 확률**이 된다(사용자 보고 로그: 턴 4 교체 → 턴 5 방어 실패).
- **영향**: 배틀 AI의 `ai/evaluator.ts:517` `protectSuccessChance(streak)`와 `ai/protectMoves.ts`가 같은 연속 사용 확률을 쓴다 → 고치면 AI 평가도 바뀐다. `switching.ts:453`은 교체해 나가는 쪽의 `protectStreak`을 지우므로(나가는 포켓몬 기준) 방어 쓴 쪽 카운터와 무관하다.
- **수정안(작음)**: `protectAndFieldSetup`에서 굴림 전에 "이번 턴 상대가 교체해서 내 뒤에 행동할 기술이 없는가"를 판정해, 해당하면 굴림·태세 진입 없이 실패(`protectFailed`만, 태세 문구 없음)로 처리하고 `protectStreak = 0`으로 둔다. 상대 행동(교체 여부)을 이 단계에 전달하는 입력이 필요하다.
- **7.3에서 사용자에게 확인할 것**: ① 같은 방어 계열(킹실드·버티기·패스트가드·와이드가드·길동무 등 `protectEffect` 보유 기술)에 어디까지 적용하는지 — 지금 확정된 것은 방어·판별뿐이다. ② 상대가 교체가 아니라 **이미 먼저 행동해서 내가 마지막**인 경우(원본 게임에는 "마지막이면 방어 실패" 조항이 있다는 검색 결과가 있으나 Bulbapedia 원문은 403으로 못 읽어 미확인)도 같은 실패로 볼지. ③ 표시 문구(교체 턴에 "방어는 실패했다!"만 보일지).
- **7.3 규칙**: 시나리오(`scripts/battle-ai-scenarios/`)에 교체 턴 방어 사례 추가, `npm run sim:ai -- regress 200` 해시 비교 → `verify-kit` 기준값 갱신 → 집 PC `verify.sh` 전체 통과.

### B3 → 7.3: 멀티스케일이 다단히트의 모든 타에 적용된다 (2026-11-05, 사용자 보고)
- **현상(사용자 로그)**: 풀피 멀티스케일 망나뇽에게 한카리아스의 스케일샷(3타) — 턴 2: 3타 모두 15.0%(반감), 다음 턴(HP 감소 뒤, 메가진화 후): 26.3/25.1/26.3%. **규칙**: 멀티스케일은 HP가 가득 찬 상태일 때만이라 **첫 타만 반감**되고 2·3타는 반감 없이(약 2배) 들어가야 한다.
- **재현(엔진 직접, 2026-11-05)**: 한카리아스(스케일샷) vs 풀피 망나뇽(멀티스케일) — 타별 데미지 12.1 / 13.6%, 12.6 / 12.1%, 13.6 / 12.1%(전 타 반감). 같은 상대의 HP를 1만 깎으면 24.2 / 27.3%, 25.3 / 24.2%, 27.3 / 24.2%(전 타 비반감). **수정 뒤 기대**: 첫 타 약 12~13%, 이후 타 약 24~27%.
- **원인**: `preHitEffects.ts:704~717`의 `resolveMoveContext`가 행동 **시작 시점**의 `defender.currentHp === maxHp`로 `finalDefenseMultiplier`(멀티스케일 ×2는 final 단계)를 한 번 계산하고, 다단히트 루프(`hitResolution.ts:745~770`)의 모든 `resolveHit`가 같은 값을 쓴다(`hitResolution.ts:280~287`). 타마다 풀피를 다시 보는 코드가 없다.
- **같은 한계가 세 곳**: ① 실전 엔진(위) ② AI 데미지 모델 `ai/moveDamage.ts:363`(`defenderHpIsFull: defenderHp === defender.maxHp`) — `DamageParts`에 "첫 타에만 곱하는 최종 보정" `firstHitFinalMultiplier`(반감 열매용, `damageFormula.ts:56`·`matchupEvaluator.ts:678`)가 이미 있는데 멀티스케일은 거기 실리지 않아 `rest`(2타 이후)에도 반감이 남는다 ③ 역산 `defenseInference.ts:428`·`attackInference.ts:264`는 "멀티스케일·섀도실드는 첫 타에만 듣는데 계산은 전 타에 곱하므로 다단히트에서는 뺀다 … 아직 지원하지 않아요"로 막아 둔 **알려진 한계**다(코드에 이미 적혀 있다).
- **영향 범위**: 데이터에서 `defenderHpIsFull` 조건을 쓰는 특성은 멀티스케일 **하나**(섀도실드·테라셸은 로스터에 없다). 이상한비늘(`defenderHasStatusCondition`)은 다단히트 도중 상태이상이 바뀌는 일이 거의 없다. 공격측 HP 조건(맹화 등 `attackerHpAtMostFraction`)은 접촉 반동 도구(`applyContactItemRecoil`이 타마다 실행)로 도중에 바뀔 수 있으나 극히 드문 경우라 7.3에서 확인만 한다. 옹골참·기합의띠는 타별 `applyEndurance(preHp)`라 이미 정상이다.
- **수정안(권장)**: 멀티스케일을 반감 열매와 같은 **`firstHitFinalMultiplier` 구조로 표현**해 엔진·AI·계산기·역산이 한 구조를 공유한다 — 엔진 `resolveHit`가 첫 타에만 곱하고, AI `rest`는 자연히 반감이 빠지며, 역산의 "지원하지 않아요" 제한을 풀 수 있다. (최소안: 엔진 루프에서 `i > 0`이면 `resolveAbilityDefense`를 현재 HP로 다시 계산 — 엔진만 고치고 AI·역산 한계는 남는다.)
- **7.3 규칙**: 시나리오(`scripts/battle-ai-scenarios/`)에 스케일샷 vs 멀티스케일(풀피/비풀피 타별 데미지)을 추가하고, `npm run sim:ai -- regress 200` 해시 비교 → `verify-kit` 기준값 갱신 → 집 PC `verify.sh` 전체 통과. 역산 제한을 풀면 `test:inference`에 다단히트 멀티스케일 사례를 더한다.
