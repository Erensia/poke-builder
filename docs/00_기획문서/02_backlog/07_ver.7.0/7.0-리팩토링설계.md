## 1. 원칙
- **동작 불변**: 화면·엔진·AI·동기화 동작을 바꾸지 않는다. 해시·출력이 기준값과 같아야 통과.
- `ponytail`: 삭제 > 재사용 > 표준 > 최소 코드. 추상화를 더하는 리팩토링은 하지 않는다(중복 제거·분할·삭제만).
- 기능 작업이 전부 끝난 시점의 `dev` 기준. 항목마다 브랜치 → PR 1개(커밋 1개) → `dev` squash. 머지 즉시 브랜치 로컬·원격 삭제.
- 4.0·5.0·6.0의 "제외 확정"은 승계한다(칩/알약 9종 공용화, 6.0 R-7 큰 엔진 함수 4개·`ActionEffectLines` 등).
- **보호 목록(건드리지 않는다)**: 서비스 워커(`scripts/sw.template.js`·`vite.config.ts`의 플러그인·`registerSw.ts`·`UpdateBar`), 클라우드에 저장되는 JSON 키 순서, `localStorage` 키 이름, 데이터 JSON 서식(CRLF·indent). 사용자 저장 데이터·오프라인 캐시·동기화가 깨질 수 있다.

## 4. 순서
1. 범위를 정한다(위 표). 항목마다 PR 1개.
2. 각 PR마다 5절 검증 세트 통과.
3. 마지막에 6절 기능 테스트(사용자 화면 확인) → 7.0 마무리 절.
4. `dev` → `main` PR 제목 `ver7.0`(merge commit). 머지 뒤 Vercel Production 배포 sha가 `main`인지 확인. 이 배포가 6.6 설치자의 탭에 새 버전 안내 바가 처음 뜰 수 있는 배포다.
5. 7.0 종료 시점의 `verify.sh` 출력(또는 엔진 무변경 근거)을 남긴다 — 7.3 B1의 "수정 전" 기준이다.

## 5. 검증 세트 (PR마다)
- **엔진을 안 건드리는 PR(R-1·R-3·R-4)**: `npx tsc -b` · `npx oxlint src scripts` · `npm run build` · `npm run test:ai` · `test:damage` · `test:inference` · `test:rank` · `test:rank-ai` · `test:sample` · `test:sync` · `test:rules`(Java 21 이상). 이 PC에서 가능. `git diff --name-only origin/main origin/dev`에 `src/lib/battle`이 없는지 확인한다.
- **엔진·AI 경로를 건드릴 수 있는 PR(R-2 등)**: 위에 더해 `bash docs/00_기획문서/02_backlog/05_ver.5.0/verify-kit/verify.sh`(14항목, 약 3.5분, 기준은 `baseline/` 그대로 — 6.x는 엔진을 바꾸지 않았다). 랭크 코드를 건드리면 `test:rank`·`test:rank-ai`.
- **`verify.sh`는 노드 프로세스 10개를 동시에 돌려 이 PC(RAM 7.7GB)에서는 메모리 부족으로 종료될 수 있다.** 집 PC에서 돌린다. 종료되면 다시 시작하지 말고 보고한다.
- 결과가 달라지면 **리팩토링 버그**로 보고 원인부터 찾는다(기준을 고치지 않는다). `verify-work/`는 커밋하지 않고 삭제.
