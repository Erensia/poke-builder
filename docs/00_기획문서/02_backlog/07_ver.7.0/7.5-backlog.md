## F1 토의 — 연출이 겹치는 원인과 방안
### 지금 상태(코드 확인)
- **AI 강제 교체는 바로 일어난다**: 턴 결과가 반영된 직후 `useBattleLogSession.ts`의 `useEffect`(AI 쪽 `pendingForcedSwitch`)가 사람 입력을 기다리지 않고 곧바로 `resolveForcedSwitch`를 불러, 새 포켓몬의 합성 로그 카드가 **같은 순간** 로그에 붙는다. 사람이 고르는 쪽은 사람이 누를 때까지 늦어져서 겹치지 않는다 — 랭크(AI 상대)에서만 두드러지는 이유.
- **새 로그 항목이 오면 앞 턴 재생이 반쯤 끊긴다**: `useTurnFx`는 로그가 바뀌면 이전 재생의 타이머를 걷고 `setView(null)`(남은 로그 줄을 한꺼번에 공개·HP를 실제 값으로)한다. 반면 이미 시작한 Web Animations(화상 입자·기절 가라앉음·먼지·팝업, 각 0.5~1.1초)는 **계속 재생된다**. 그 위에 새 카드의 들어오는 모션(`swapIn`, 0.42초)이 0초에 시작해 겹친다.
- **같은 턴 안에서도 겹친다**: 턴 종료 틱 연출(`statusFx` 화상 불씨 6개 0.8초·번쩍임·`-n%` 팝업)이 `endStart`에, 기절 연출(`faintFx` 가라앉음 0.5초·먼지 6개 0.7초·"기절!")이 `endStart + 250ms`에 걸려 같은 카드에서 동시에 돈다.

### 방안(토의)
1. **같은 카드 연출 간 최소 간격 규칙(작음)**: 틱 → 기절 사이를 벌린다(예: 기절 연출을 틱 입자가 끝나는 뒤 +400ms, 또는 틱으로 쓰러지는 경우 틱 입자를 줄이고 번쩍임·팝업만). 같은 턴 안의 겹침만 푼다.
2. **AI 강제 교체를 이전 연출이 끝난 뒤로 미룬다(작음~중간, 권장)**: 이전 턴 연출 길이(마지막 프레임 시각 + 기절·결과 여유)를 구해 AI 교체 `useEffect`를 그만큼 지연한다. 길이는 `useTurnFx`의 일정 계산을 순수 함수로 빼서(`turnFxDuration(turn)`) 세션에서도 쓰거나, 훅이 길이를 돌려주는 방식. 연출을 안 보는 환경(동작 줄이기)에서는 지연 0. 사람 쪽 교체는 영향 없음.
3. **재생 대기열(큼, 정석)**: 새 로그 항목은 이전 재생이 끝난 뒤에 시작하도록 `useTurnFx`가 항목별 구간을 큐로 관리하고, 그동안 카드가 이전 상태(`prev`)를 계속 보여 준다. 연출이 겹치는 모든 경우(유턴 부분→완성본, 연속 강제 교체 등)를 한 번에 해결하지만 UI 상태 지연이 필요해 변경이 크다.
4. **기존 재생을 끊지 않기(작음)**: 새 항목이 와도 `setView(null)`로 로그 줄을 한꺼번에 공개하지 않고 남은 일정이 끝나도록 둔다(방안 2·3과 함께 필요).
### F1 결정 (사용자 2026-11-06)
- **방안 1·2·3을 모두 한다**(4는 3의 일부). 제보 내용을 정확히 짚었다: **새 포켓몬의 들어오는 모션이 기절 연출 도중에 시작돼서, 이전 포켓몬의 배틀 데이터(입은 피해·상태이상 피해·기절, 메가진화도 마찬가지)에 해당하는 연출이 새 포켓몬의 카드 위에서 실행된다.** 연출이 붙는 곳이 포켓몬이 아니라 편의 카드(`.battle-fighter`)라서, 상태가 바뀌어 카드 내용이 새 포켓몬이 되면 이어서 재생 중인 연출이 그 위에 얹히는 것이다. 수동 대전에서는 겹침이 없었다(사람이 고르는 동안 시간이 지나서).
- **원하는 동작**: 새 포켓몬의 등장은 이전 포켓몬의 연출이 **전부 끝난 뒤**에 보인다(살짝 겹치는 것도 안 된다).
- **방식(3 = 재생 대기열의 설계 초안)**:
  - `useTurnFx`의 타이머를 effect 정리 함수(cleanup)가 아니라 ref에 둬서 새 로그 항목이 와도 앞 재생을 끊지 않는다(= 방안 4). 지금은 새 항목이 오면 타이머를 걷고 `setView(null)`로 로그 줄을 한꺼번에 공개한다.
  - 새 항목은 앞 재생이 끝나는 절대 시각(`busyUntil`) 이후에 시작하도록 대기시킨다. 대기 중 카드는 **앞 항목이 끝난 시점의 배틀 상태**(`prevState`)를 계속 보여 준다 — 기절한 이전 포켓몬이 연출을 끝까지 받고, 그 뒤 새 항목이 시작될 때 교체 모션(`swapIn`)으로 새 포켓몬이 나온다. 메가진화·유턴 중간 → 완성본 같은 연속 항목도 같은 방식으로 풀린다.
  - 대기 중인 새 항목의 로그 줄은 숨기고(`reveal.actions = 0`), HP·파티 트래커·로스터도 보여 주는 상태(prev)에 맞춘다.
- **방안 1(같은 카드 연출 간 간격)**: 틱 → 기절 사이를 벌린다(기절 연출을 틱 입자가 끝난 뒤로, 또는 틱으로 쓰러지는 경우 입자를 줄이고 번쩍임·팝업만).
- **방안 2(AI 강제 교체 지연)**: 이전 턴 연출 길이를 `startOf`·`gapMs`·`endStart` 계산을 순수 함수로 빼서(`turnFxDuration`) 구해 AI 교체를 그만큼 미룬다. 방안 3과 일부 겹치지만(3이 화면을, 2가 AI의 상태 변경 시점을 맞춘다) 둘 다 한다고 정했으니, 3을 한 뒤 2를 얹고 중복이 남으면 그때 줄인다. 동작 줄이기에서는 지연 0.
- **작업 순서**: ① 4+3(타이머 ref화·대기열·prev 유지) → ② 1 → ③ 2 → ④ 사용자 화면 확인(랭크 AI 대전: 화상 틱으로 기절 → AI 교체 / 메가진화 직후 기절 → 교체 / 유턴 중간 → 완성본 / 연속 강제 교체 / 양쪽 동시 기절).
- 검증: `regress 200` 해시 불변·`fxhp` 불일치 0·`tsc`·`oxlint`·`build`. 연출은 화면에서만 확인되므로 사용자 몫.

## F2 토의 — 강제 교체 로그 블록 정리
### 지금 상태(코드 확인)
- 기절 뒤 교체는 `forcedSwitchLogEntry`(`battleSessionHelpers.ts`)가 **합성 로그 카드**를 만든다: `actions`·`endOfTurn`이 비고 `switches`에 `fromIndex -1` 교체만 있다. `turnNumber`는 직전 턴과 같은 번호(상태의 턴 번호는 턴이 시작할 때 올라간다)라 화면에는 **"턴 N · 먼저 행동…" 카드 바로 위에 "턴 N · 교체" 카드**가 따로 쌓인다(`BattleTurnLog.tsx`의 `isForcedSwitchCard` 분기).
- 이 합성 카드는 `useTurnFx`가 "들어오는 모션만" 재생하는 별도 항목이기도 하고, `activeIndexTrace`·`sim:ai logidx` 검증이 이 카드를 전제한다. 저장된 배틀 비디오(다시보기)에도 이 형태로 들어 있다.

### 증거 로그 (사용자 2026-11-06, 양쪽이 같은 턴에 쓰러진 경우)
```
턴 4 · 교체           ← 가라! 번치코!
턴 4 · 교체           ← 가라! 하마돈!
턴 4 · 먼저 행동: 우리팀  ← 한카리아스의 지진 … 따라큐는 모래바람에 시달리고 있다! (남은 HP 0) · 기절! / 날씨: 앞으로 1턴 뒤 소멸
```
- 턴 로그는 **최신이 위**(`[...log].reverse()`)라서 같은 턴의 교체 카드(하마돈 → 번치코 순으로 나중에 생김)가 원인인 "턴 4 · 먼저 행동" 카드 **위에** 쌓인다. 위에서 아래로 읽으면 "가라! 번치코!" → "가라! 하마돈!" → 그 둘을 부른 행동·기절 순서가 되어 **인과가 뒤집힌다**. 사용자가 짚은 문제: "턴 4의 따라큐가 왜 기절하게 됐는지 이상해진다".
- 교체 줄에 팀 표시가 없어("가라! 하마돈!") 양쪽이 동시에 쓰러진 경우 누구의 교체인지 구분이 안 된다. 카드 안(행동 → 턴 종료 → 교체) 줄은 위에서 아래로 시간순이므로, 교체를 그 턴 카드 맨 아래로 묶으면(방안 A) 인과가 맞아지고, 팀 표시("우리팀 ▸ 가라! 하마돈!")를 줄에 붙일 수 있다.

### 방안
- **A. 렌더에서 묶기(권장)**: 로그 데이터(배열)는 그대로 두고 `BattleTurnLog`가 합성 카드를 **직전 턴 카드 안**으로 묶어, 그 카드 맨 아래에 얇은 구분선과 함께 "가라! X!" 블록으로 그린다. 한 턴의 이야기(행동 → 턴 종료 → 기절 → 교체)가 한 카드에 이어지고 번호 중복이 사라진다. 로그 형식·저장된 비디오·`activeIndexTrace`·`logidx` 검증에 영향이 없고 옛 배틀 비디오도 같은 모양으로 정리된다. 주의: 공개(`reveal`) 범위를 "최신 항목이 합성 카드일 때 앞 카드의 하위 블록"에 적용해야 하고, 연속 강제 교체·양쪽 동시 교체 표기가 필요하다.
- **B. 데이터 병합**: 합성 카드를 만들지 않고 직전 `TurnResult.switches`에 더한다. 엔진·세션·저장 형식·옛 비디오 호환·`activeIndexTrace`·`logidx`를 모두 고쳐야 해서 크고, 얻는 모양은 A와 거의 같다 → 비권장.
- **C. 겉모양만**: 별도 카드는 두고 제목을 없애 앞 카드에 붙은 얇은 줄로 스타일링. 가장 작지만 DOM이 분리돼 있고 공개 순서 처리가 어색하다.
- **의견**: A로 한다. F1(재생 대기열)이 `reveal`·`BattleTurnLog`의 공개 방식을 건드리니 **F1을 먼저 안정화한 뒤** 그 위에 얹는다.
### F2 결정 (사용자 2026-11-06) — **A안(렌더에서 묶기)으로 간다**
- **묶는 방식**: 로그 데이터는 그대로 두고 `BattleTurnLog`가 `fromIndex -1` 교체만 있는 합성 카드를 **직전 턴 카드 맨 아래**(카드 안은 위에서 아래로 시간순: 행동 → 턴 종료 → 기절 → 교체)로 묶어 그린다. 교체가 끝난 뒤의 합성 카드 제목("턴 N · 교체")은 사라진다.
- **표기 형식: 형식 1로 확정**(사용자 2026-11-06) — 구분선 + 팀 표시 줄만 두고 **"이어서 교체" 같은 소제목은 두지 않는다**(같은 턴 안에서 이어지는 교체이기 때문).

  등장 때 발동한 특성·설치물 문구(위협·스텔스록 등)는 각 팀 줄 밑에 흐린 글씨로 붙는다(지금 `PreMoveSwitchLines`와 같은 방식).
- **양쪽이 동시에 쓰러졌거나 연속으로 쓰러졌을 때(사용자)**: **먼저 쓰러진 쪽이 먼저 다음 포켓몬을 내보낸다.** 각 줄에 팀 표시를 붙이고 그 순서로 정렬한다.
  - 쓰러진 순서는 턴 카드의 기록에서 구한다: 행동 순서대로 `fainted`(맞은 쪽)·`selfFainted`(쓴 쪽), 그다음 턴 종료 항목 순서대로 `fainted`. **같은 행동에서 동시에 쓰러지면 맞은 쪽(상대)이 먼저, 쓴 쪽이 나중 — 확정**(사용자 2026-11-06, 실제 처리 순서와 같다): 자폭은 폭발 데미지를 입은 쪽 체력이 먼저 줄어들고, 반동기는 쓴 쪽이 상대에게 먼저 데미지를 주고 나서 반동을 입고, 길동무는 길동무를 쓴 쪽(= 공격을 맞은 쪽)이 맞고 쓰러진 뒤에 발동하므로 **세 경우 모두 같은 규칙**이다(길동무만 반대가 아니다 — 길동무를 쓴 쪽이 "맞은 쪽"이기 때문). 서로 다른 행동·턴 종료에서 쓰러지면 처리 순서(행동 순서 → 턴 종료 항목 배열 순서) 그대로.
  - **화면 정렬만이 아니라 처리 순서도 이 규칙을 따른다**: 두 편이 모두 교체를 기다릴 때 먼저 쓰러진 편의 교체를 먼저 처리한다(`useBattleLogSession`의 AI 자동 교체 `useEffect`는 상대가 먼저 쓰러졌고 아직 고르지 않았으면 기다린다). 등장 특성(위협·날씨·필드)이 먼저 나온 쪽 기준으로 이어지기 때문이다. 엔진은 안 건드리는 세션 로직이라 `verify.sh` 기준 출력은 불변(시뮬레이션 harness는 a→b 순서의 별도 정책을 쓴다).
  - 새 포켓몬이 설치물로 또 쓰러져 연속으로 교체하게 되면 같은 블록 안에 이어서 쓴다.
- **옛 배틀 비디오(사용자)**: 새 모양으로 전면 수정한다. A안은 **렌더에서 묶는 방식이라 저장된 비디오의 데이터를 바꾸지 않고도** 옛 비디오가 같은 모양으로 보인다(옛 비디오는 교체가 처리된 순서로 저장돼 있어도, 묶을 때 위 "쓰러진 순서"로 정렬해서 새 규칙과 같게 보인다). 데이터 이전(마이그레이션)은 필요 없다.
- **작업 시점**: 7.5 백로그가 확정되기 전이라 **착수하지 않는다**. 순서는 F1(재생 대기열) 뒤 F2.
