- **스타일**: 기존 파티 칩 바(`battle-party-chip-bar`/`battle-party-chip-fill`, 20% 이하 `is-danger`·50% 이하 `is-warn`)와 같은 색 단계·CSS 변수를 쓴다(새 UI는 기존 앱 스타일에 맞춘다, 호버 의존 금지). AI 카드는 이미 HP를 `%`로만 보여 주므로(실수치 비공개) 바도 비율만 드러낸다.
- **정할 것(착수 때 확인)**: "나온 적 있음"을 어떻게 아는가 — 현재 상태에는 그 플래그가 없다. ① 엔진 상태에 `hasAppeared`(리드는 시작부터, 교체·강제 교체로 나올 때 세움)를 추가(저장된 대전을 복원해도 유지되지만 `BattleFighterState`가 늘어남) ② 턴 로그(`switches`의 `toIndex`)와 시작 시 활성 인덱스에서 UI가 계산(엔진 불변, 이미 `activeIndexTrace`가 비슷한 되짚기를 한다). 추천은 ②(엔진 출력·해시 영향 없음). 기절한 뒤 교체되기 전 상태, 유턴 도중 교체(턴 중간 교체)도 "나왔다"에 포함되는지 확인.
- **2.3 B2의 "출전 여부 비공개"와의 관계**: 선출된 3마리를 처음부터 드러내지 않는 것이 원래 의도다. 나온 뒤에만 바가 생기므로 정보는 실제 대전에서 보이는 것 이상을 드러내지 않는다(기절 표시도 같은 원칙).
- **성격**: UI 변경이라 `verify.sh` 기준 출력은 안 바뀐다(②안 기준). 화면 확인이 필요하다 → `npm run dev` 서버로 사용자에게 맡긴다. 모바일 폭(스프라이트 6개 나열)에서도 바가 칩 폭 안에 들어가는지 확인한다.
