# ver.7.4 백로그

**초안(2026-11-05) — 7.4는 일반 버전이다.** `verify.sh` 기준 출력이 바뀌지 않는 작업(측정·기능·UI·클라우드·문서·샘플 데이터)만 한다. 엔진·AI(`src/lib/battle/**`)는 건드리지 않는다(`CLAUDE.md` "버전 구성" — AI 작업은 다음 메이저의 x.3). 확정된 범위는 **집 PC 복구 후 샘플 등급·선출 벤치 전수 재측정**(사용자 결정 2026-11-05: 7.3을 재측정 없이 릴리스하고 측정은 7.4에서 시작)뿐이고, 나머지는 후보다. 이전 버전: `7.3-backlog.md`(배틀 AI·엔진).

## 출발 상태 (7.3 종료 기준)
- 7.3(`ver7.3`)은 `main`에 배포된다. 7.3 변경: 눈보라·번개·폭풍 날씨 필중과 쾌청 명중률 · 방어류가 내가 마지막에 행동하면 실패 · 풀피 멀티스케일은 다단히트 첫 타만 반감(엔진·계산기·AI·역산) · 반동 기절 뒤 상대 행동 유지 · 턴 로그 "먼저 행동"을 우리팀/상대팀으로 · AI 대전 상대 파티 체력바.
- **기준 출력**(`verify-kit/baseline`): `regress 200` 해시 `a4f6ca69…`, `test:inference` 결합 해시 `10040ffa0108c9a3`. 7.4에서 엔진·AI를 안 바꾸니 그대로여야 한다.
- 샘플 64개, 등급(하 19·중 20·상 20·최상 5)과 선출 벤치(64개 풀 AI 55.9%)는 **6.6 시점 기준**이라 7.3의 엔진·AI 변경 뒤에는 낡았을 수 있다.
- 7.3 최종 `verify.sh`는 **회사 PC에서 직렬로** 통과시켰다(병렬 10개가 메모리로 안 돼서). 집 PC 복구 뒤 병렬 `verify.sh`가 같은 결과인지 확인한다(아래 T0).

### T0 집 PC 복구 확인 ✅
- 포맷 후 세팅: Git 2.56 · Node v26.13(npm 11.20) · gh 2.103 · Python 3.12 · VS 2022 Build Tools(C++, trail의 tree-sitter 빌드용). E: 드라이브라 `git config --global --add safe.directory E:/05_poke-builder`가 필요했다.
- `dev` `4b8eaba`(7.3 릴리스 직후)에서 `verify.sh` 병렬 **14항목 전부 통과**(19분 30초) — 회사 PC 직렬 결과와 같다. ai60 턴 시간 192ms(기준 24ms)는 아래 E코어 문제 + 병렬 경쟁 때문이고 판정에서 제외되는 값이다.
- **E코어 문제**: Windows 11이 백그라운드 node 프로세스를 효율 모드(EcoQoS)로 보고 E코어 4개(cpu12~15)에만 몰아, 16개 프로세스가 각 25%씩만 받았다(전체 CPU 25~30%). 전원 모드 "최고의 성능"·구성표 "고성능"으로는 안 풀렸고, 관리자 PowerShell에서 `powercfg /powerthrottling disable /path "C:\Program Files\nodejs\node.exe"`(목록에 `Never On`)로 풀렸다 — 돌던 프로세스에도 바로 적용돼 16코어 100%. 포맷·Node 경로 변경 시 다시 해야 한다. 위 T0 시간은 이 설정 **전** 값이다.
