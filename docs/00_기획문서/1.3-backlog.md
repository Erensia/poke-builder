# ver.1.3 백로그

## 0. 이 문서의 성격

`1.2-backlog.md`의 핵심(§1 이미지·아이콘 7항목·§2 M-C 데이터 편입·§3 UI 정리·§4-1 꼬리자르기)과

dev → main은 별도 PR #77) 남은 **탐색성 조사 1건**으로 시작한다.

1.2와 동일 — `dev`에서 항목별 브랜치 → PR로 `dev` 머지 → 주기적으로 `dev` → `main`. 엔진
로직은 테스트 러너가 없어 `npm run dev`로 띄운 Vite 페이지 컨텍스트에서 `sim.runTurn`/
`resumeTurn`을 직접 호출해 스모크 테스트한다(방법 상세는 별도 메모 참고).

## 1. 엔진 미배선 기술 전수 감사 (1.2에서 이관: 2026-09-11)

M-C 편입분(PR-C 트랙)과 별개로, 기존 `moves.json` 497→511건 중 `effect` 텍스트에는 부가효과가
적혀 있는데 엔진(`battleSimulator.ts`) 분기가 없는 기술이 더 있는지 감사한다. §4-2(배턴터치)·
§4-5(황금몸)·§4-6(자기 랭크 하락)이 전부 "데이터·인프라는 있는데 결과가 로그/판정에 안 실리는"
유형이었던 것과 같은 결의 버그가 더 있을 가능성이 있어 접수됨.

**방법**:
- `moves.json`에서 `effect`에 상태 변화·교체·필드·랭크·보호 등 키워드가 있는데 대응 스키마
  필드(`inflictsStatus`/`statChanges`/`setsField`/`selfSwitchAfterDamage`/… )가 비어 있는
  엔트리를 추출 → 스프레드시트로 "의도적 미배선(1v1 무의미)" vs "버그" 분류.
- 배턴터치·황금몸·골드러시처럼 "필드 있음 + 인프라 있음 + 결과 안 남" 유형을 우선 처리.
- 대상: `src/data/moves.json` 감사 리스트, `src/lib/battleSimulator.ts`, `src/components/BattleLogPage.tsx`

**상태**: 완료(감사, 2026-09-12). `moves.json` 511건 전체를 스키마 필드 사용 여부(엔진·UI 전체
grep) + `effect` 텍스트 키워드 대조 두 방식으로 교차검증. 결과는 아래 §1-1~§1-9로 개별
백로그 항목화(수정은 각 항목에서 별도 진행). 감사만으로 끝난 나머지는 분류만 남김:

- **이미 자체 문서화된 기존 갭(새 발견 아님)**: `G의힘`(중력 상태 자체 미구현 → 위력배율 상시
  미발동), `경혈찌르기`(랜덤 대상 선택 엔진 미배선), `페어리록`·`그림자꿰매기`·`배수의진`·
  `자기장조작`·`아로마미스트`·`데코레이션`(더블·교체 전용이라 1v1 스텁) — 전부 `effect`
  텍스트에 이미 "미구현/스텁"이라고 명시돼 있어 추가 조치 불필요.
- **사소한 문서 누락(기능 결함 아님)**: `코칭`(아군 대상 랭크업, 1v1엔 아군 없어 무의미)만
  다른 더블 전용 기술들과 달리 `effect`에 "1v1 무의미" 주석이 빠져 있음. 우선순위 낮음, 별도
  항목화하지 않고 필요 시 사소 수정으로 처리.

### §1-1. 퀵턴 — 데미지 후 교체 미작동

`유턴`·`볼트체인지`와 `effect` 텍스트가 완전히 동일한데 `selfSwitchAfterDamage` 필드만 빠져
있음(복붙 시 필드 누락 추정). 대상: `src/data/moves.json`, `src/lib/battleSimulator.ts`.
**상태**: 완료(2026-09-12) — `selfSwitchAfterDamage: true` 추가, 로컬 확인 대기.

### §1-2. 아이스스피너 — 필드 파괴 미반영

`effect`에 "회전 운동에 의해 필드가 파괴된다"고 명시했는데 `destroysField` 필드가 없음
(`아이언롤러`는 있음). 대상: `src/data/moves.json`. **상태**: 완료(2026-09-12) —
`destroysField: true` 추가(아이언롤러와 달리 필드 없어도 실패하지 않으므로 `usageCondition`은
추가하지 않음), 로컬 확인 대기.

### §1-3. 가드스왑 / 파워스왑 — 상대와 랭크 교환 기능 자체 미구현

방어·특수방어(가드스왑) / 공격·특수공격(파워스왑)의 능력 랭크를 상대와 맞바꾸는 기능이
스키마에 전혀 없음. `파워트릭`의 `swapsOwnStats`는 자기 스탯끼리 교환이라 다른 기능이라 재사용
불가 — 신규 필드 설계 필요. 대상: `src/types/move.ts`, `src/data/moves.json`,
`src/lib/battleSimulator.ts`. **상태**: 완료(2026-09-12). `Move.swapsStagesWithTarget:
BattleStatKey[]`를 신설해 명중 시 지정 스탯들의 랭크(stages)만 자신·상대끼리 맞바꾼다(실수치는
그대로 — `averagesDefensesWithTarget`/`swapsSpeedWithTarget`처럼 이미 -6~+6 범위라 클램프
불필요). 가드스왑엔 `["def","spd"]`, 파워스왑엔 `["atk","spa"]`를 지정. 로그엔
`swappedStagesMoveName` 필드 + "서로의 랭크 변화를 맞바꿨다!" 문구 추가(`BattleLogPage.tsx`).

### §1-4. 객기 — 자기 상태이상 시 위력 2배 미구현

자신이 독·마비·화상 상태일 때 위력이 2배가 되는 로직이 스키마에 전혀 없음. 대상:
`src/types/move.ts`, `src/data/moves.json`, `src/lib/battleSimulator.ts`(또는
`battlePower.ts`). **상태**: 완료(2026-09-12). 기존 `conditionalDoublePower` enum에
`"user-status-burn-poison-paralysis"` 값을 추가(신규 필드 대신 기존 축 재사용). 객기에 반영.
`battleSimulator`에선 실제 상태이상 추적으로 정확히 판정되지만, `matchupEvaluator`(결정력·
내구력 페이지)는 상태이상 개념 자체가 없는 1턴 스냅샷이라 §1-5와 함께 항상 미충족(기본 위력)으로
둠 — `ability.ts`의 `defenderHasStatusCondition` 정책과 동일.

### §1-5. 베놈쇼크 — 상대 독 상태 시 위력 2배 미구현

상대가 독 상태일 때 위력이 2배가 되는 로직 없음. §1-4와 유사한 "자기/상대 상태이상 조건부
위력 배율" 패턴이라 같이 설계하면 효율적. 대상: `src/types/move.ts`, `src/data/moves.json`,
`src/lib/battlePower.ts`. **상태**: 완료(2026-09-12). §1-4와 함께 `conditionalDoublePower`에
`"target-status-poisoned"`(독·맹독 둘 다 포함) 추가, 베놈쇼크에 반영. matchupEvaluator 정책은
§1-4와 동일(항상 미충족).

### §1-6. 솔라블레이드 — 충전 턴 미구현

`tags`에 "충전"만 있고 정작 `chargeTurn`/`chargeSkipWeather` 필드가 빠져 있어(`솔라빔`엔 있음)
현재 2턴 충전 없이 매턴 즉발로 나갈 가능성이 있음. 물리 버전 통째로 미작동 여부 확인 필요.
대상: `src/data/moves.json`. **상태**: 완료(2026-09-12). `솔라빔`과 동일하게 `chargeTurn: true`
+ `chargeSkipWeather: "쾌청"` 추가. 솔라빔과 달리 솔라블레이드는 effect 텍스트에 "다른 날씨엔
위력 절반" 조항이 없어(위력 감소 없이 2턴 충전만) 그대로 반영. 참고: 솔라빔 본인의 "다른 날씨엔
위력 절반" 부분은 조사 중 엔진에 실제로 구현돼 있지 않은 것을 발견했으나(chargeSkipWeather는
1턴 즉발 여부만 판정, 위력 감소 로직 없음) §1-6 범위 밖이라 이번엔 손대지 않음 — 별도 확인 필요.

### §1-7. 성장 — 쾌청 시 2랭크 상승 조건 미반영

`effect`에 "쾌청 상태일 때는 2랭크 올라간다"고 명시했는데 항상 +1/+1(`statChanges`)만
적용됨. 날씨 조건부 랭크 변화를 표현할 스키마 필드가 없어 신규 설계 필요. 대상:
`src/types/move.ts`, `src/data/moves.json`, `src/lib/battleSimulator.ts`. **상태**:
완료(2026-09-12). `StatChangeEffect`에 `requiresWeather?: WeatherKind` 추가(`userIsType`과
같은 축의 조건부 필드) — `applyMoveStatChanges`가 이미 항목별로 delta를 누적 적용하는 구조라,
성장의 `statChanges`를 "기본 +1×2개 + 쾌청 조건부 +1×2개"로 나눠 넣으면 쾌청일 때 자동으로
합산 +2가 된다. `battleSimulator.ts`(실전투)·`matchupEvaluator.ts`(결정력·내구력 페이지, 이
페이지는 날씨 선택 UI가 있어 실제로 조건 판정 가능) 양쪽 다 `activeWeather`/`effectiveWeather`를
새 `weather` 옵션으로 넘기도록 배선.

### §1-8. 패스트가드 / 와이드가드 — 보호 효과 자체 미구현

`protectEffect` 필드가 아예 없음. 더블 전용처럼 보이지만 "아군 전원"에 사용자 자신도 포함되므로
1v1에서도 "이번 턴 공격 막기"가 유의미함(다른 더블 전용 스텁들과 성격이 다름) — 확인 후 실제로
작동 안 하면 우선순위 있는 버그. 대상: `src/data/moves.json`, `src/lib/battleSimulator.ts`.

**상태**:
- **패스트가드 — 완료(2026-09-12)**. `protectEffect`에 `"blockPriority"` 신설(기존
  `"block"`/`"endure"`/`"destinyBond"`과 같은 축, `protectStreak` 연속성공 확률도 공유) — 상대
  기술의 `priority > 0`일 때만 막는다. 방어류 판정 지점(`blockedByProtect`·`unseenFistPiercing`)과
  로그용 성공/실패 판정(`targetedSelf`)까지 전부 갱신.
- **와이드가드 — 보류**. 본가에선 "스프레드(전체 대상) 기술만" 막고 단일대상 기술은 통과시키는데,
  이 프로젝트 데이터엔 "이 기술이 스프레드인지" 분류 자체가 없어(511개 전체에 새로 추가해야 함)
  구현하려면 큰 데이터 작업이 필요함. 사용자 판단으로 일단 미착수로 남기고 다음 항목으로 진행.

### §1-9. 신비의부적(세이프가드) — 상태이상 면역 미구현

5턴간 상태이상 면역 효과가 스키마에 없음. §1-8과 마찬가지로 1v1에서도 유의미한 경쟁적 기술인데
미구현 상태. 대상: `src/types/move.ts`, `src/data/moves.json`, `src/lib/battleSimulator.ts`.
**상태**: 미착수.

### §1-10. 솔라빔 — 쾌청 아닌 날씨에서 위력 절반 미구현 (신설: 2026-09-12, §1-6 작업 중 발견)

`effect`에 "다른 날씨에는 위력이 절반이 된다"고 명시했는데, 엔진의 `chargeSkipWeather`는 "쾌청이면
1턴 즉발"만 판정하고 위력 감소 로직은 없음 — 비/모래바람/싸라기눈 등에서 2턴 충전 후에도 위력이
그대로 나갈 가능성. 대상: `src/data/moves.json`, `src/lib/battleSimulator.ts`(또는
`battlePower.ts`). **상태**: 미착수.

## 2. 전체 페이지 로직 점검 — 동일 포켓몬 중복 배치 버그 (신설: 2026-09-11)

`src/components/PartyPresetsModal.tsx`

**상태**: 완료(2026-09-12). 실제로는 우회 경로가 두 곳이었음 — 원래 대상 목록에 없던
`SlotPresetsModal.tsx`(저장된 포켓몬 빌드 1마리를 슬롯에 불러오는 경로)도 함께 수정:

  슬롯에 이미 있는 포켓몬의 빌드는 "불러오기" 버튼을 비활성화하고 "다른 슬롯에 있음" 표시.
- `PartyPresetsModal`의 "불러오기"(전체 6슬롯 프리셋)에는 프리셋 자체 내부에 중복 포켓몬이
  있는지 검사하는 방어 로직 추가(이 기능 도입 전에 저장된 낡은 프리셋 대비) — 중복이 있으면
  경고와 함께 불러오기 차단.

## 4. 결정력 & 내구력 페이지 — 상대 미선택 시에도 위력 표시 (신설: 2026-09-11)

현재 상대 포켓몬을 선택해야만 기술의 결정력(위력)이 표시되는 것으로 보임. 상대를 선택하지
않은 상태에서도 기술 자체의 결정력은 표시하도록 바꾼다. 단, 상대와의 타입 상성에 따른 배율
반영(반감·효과 굉장함 등 보정된 결정력)은 상대가 없으므로 표시하지 않아도 된다 — 순수 기본
위력만 노출하면 됨.

**대상**: `src/components/MatchupPage.tsx`, `src/components/MatchupSlotCard.tsx`

**상태**: 완료(2026-09-12). 단순히 `move.power`(기본 위력 수치)만 노출하는 대신, 사용자 피드백에
따라 **실제로 계산한 결정력**을 보여주도록 구현 — `matchupEvaluator.ts`에 `evaluateSlotMatchup`과
같은 하위 재료(특성 배율·자속·가변 위력 해석·날씨볼·필드펄스)를 재사용하는
`computeSoloOffensePower`를 신설해, 상대 정보 없이도 낼 수 있는 값(자속·랭크·특성·도구·날씨·필드
전부 반영)만 계산하고 상대 타입 상성만 제외한다. `MatchupPage.tsx`가 상대 미선택일 때 이 값을
계산해 `MatchupSlotCard.tsx`에 새 prop(`soloOffensePower`)으로 넘긴다.
- 변화기: 기존과 동일하게 "변화기는 결정력이 없어요"
- 상대 실능치/몸무게가 있어야 뜻이 있는 기술(속임수의 `usesTargetAttackStat`, 자이로볼의
  `gyroBallPower`)은 `computeSoloOffensePower`가 null을 반환 → "결정력을 고정 수치로 표시할 수
  없어요"로 중립 안내(상대를 선택하면 보여준다고 잘못 약속하지 않음).
- 헤비봄버 등 몸무게 비율 기술은 상대 몸무게를 몰라 기존 "정보 부족" 기본값
  (`WEIGHT_MOVE_FALLBACK_POWER`)을 그대로 사용.

## 6. 배틀타워 페이지 — 배틀비디오 기능 신설 (신설: 2026-09-11)

배틀타워 페이지에 "배틀비디오" 기능을 추가한다.

- 대전이 끝날 때마다 그 시점의 배틀 로그를 저장한다. 최근 3개까지만 유지하고, 4번째가
  생기면 가장 오래된 로그를 삭제한다(FIFO).
- 저장은 기존 파티 샘플과 동일하게 브라우저(localStorage 등)에 한다.
- 배틀타워 페이지 안에 토글 버튼을 두어, 누르면 저장된 배틀비디오 목록을 볼 수 있게 한다.
- 배틀비디오는 포켓몬 UI(스프라이트·게이지 등) 없이, 배틀 종료 시점의 텍스트 로그만 그대로
  꺼내 보여주는 방식으로 충분함.

**대상**: `src/components/BattleLogPage.tsx`, (신규) 배틀비디오 저장용 localStorage 키 —
`champions-party-sim.party.v1`은 파티 자동저장용 키이므로 **절대 재사용/충돌하지 않도록**
별도 키를 사용할 것 ([[dont-clear-party-autosave]] 참고).

**상태**: 미착수.

## 7. 작업 순서

§1(엔진 미배선 감사) 완료(2026-09-12) — 결과 §1-1~§1-9로 항목화. 남은 작업 순서:

**§1-1 → §1-2 → §2 → §4 → §5 → §1-3 → §1-4 → §1-5 → §1-6 → §1-7 → §1-8 → §1-9 → §1-10 → §3 → §6**

(§1-10은 §1-6 작업 중 발견된 신규 항목 — 우선순위 낮음, §1-9 다음 §3 전에 끼워 넣음)

- **§1-1(퀵턴)·§1-2(아이스스피너)** 먼저: `moves.json` 필드 한 줄 채우면 되는 최소 규모 수정.
  감사 직후 바로 처리하는 게 자연스러움.
- **§2(파티 중복배치 버그)·§4(위력 상시표시)·§5(도감 정렬)**: 서로 파일이 안 겹치는 독립적인
  소규모 UI/로직 수정. §1류 데이터 수정과도 파일이 겹치지 않아 순서 상관없이 처리 가능.
- **§1-3~§1-7**: 신규 스키마 필드 설계가 필요한 기술 데이터/엔진 보강(가드스왑·파워스왑,
  객기, 베놈쇼크, 솔라블레이드, 성장). §1-4·§1-5는 "상태이상 조건부 위력 배율" 패턴이 같아
  묶어서 설계.
- **§1-8·§1-9**: 보호 계열(패스트가드·와이드가드)·상태이상 면역(신비의부적) — 1v1에서도
  유의미한 경쟁적 기술이라 우선순위가 있지만, 실제 영향도(현재 게임에 이 기술을 쓰는 포켓몬이
  얼마나 있는지) 확인 후 착수.
- **§3(D&D 순서변경 + 기술 필터)**: `PartyBoard.tsx`/`PartySlotCard.tsx`를 §2와 공유하므로 §2
  머지 후 진행(충돌 방지).
- **§6(배틀비디오 신설)** 마지막: 대상 파일(`BattleLogPage.tsx`)이 가장 크고 신규 기능+신규
  저장소 설계가 필요해 범위·리스크가 제일 큼.
