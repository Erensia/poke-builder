## 0. 이 문서의 성격

## 1. 엔진 미배선 기술 전수 감사 (1.2에서 이관: 2026-09-11)

M-C 편입분(PR-C 트랙)과 별개로, 기존 `moves.json` 497→511건 중 `effect` 텍스트에는 부가효과가
적혀 있는데 엔진(`battleSimulator.ts`) 분기가 없는 기술이 더 있는지 감사한다. §4-2(배턴터치)·
§4-5(황금몸)·§4-6(자기 랭크 하락)이 전부 "데이터·인프라는 있는데 결과가 로그/판정에 안 실리는"
유형이었던 것과 같은 결의 버그가 더 있을 가능성이 있어 접수됨.

**방법**:
- `moves.json`에서 `effect`에 상태 변화·교체·필드·랭크·보호 등 키워드가 있는데 대응 스키마
  필드(`inflictsStatus`/`statChanges`/`setsField`/`selfSwitchAfterDamage`/… )가 비어 있는
  엔트리를 추출 → 스프레드시트로 "의도적 미배선(1v1 무의미)" vs "버그" 분류.
- 배턴터치·황금몸·골드러시처럼 "필드 있음 + 인프라 있음 + 결과 안 남" 유형을 우선 처리.
- 대상: `src/data/moves.json` 감사 리스트, `src/lib/battleSimulator.ts`, `src/components/BattleLogPage.tsx`

**상태**: 완료(감사, 2026-09-12). `moves.json` 511건 전체를 스키마 필드 사용 여부(엔진·UI 전체
grep) + `effect` 텍스트 키워드 대조 두 방식으로 교차검증. 결과는 아래 §1-1~§1-9로 개별
백로그 항목화(수정은 각 항목에서 별도 진행). 감사만으로 끝난 나머지는 분류만 남김:

- **이미 자체 문서화된 기존 갭(새 발견 아님)**: `G의힘`(중력 상태 자체 미구현 → 위력배율 상시
  미발동), `경혈찌르기`(랜덤 대상 선택 엔진 미배선), `페어리록`·`그림자꿰매기`·`배수의진`·
  `자기장조작`·`아로마미스트`·`데코레이션`(더블·교체 전용이라 1v1 스텁) — 전부 `effect`
  텍스트에 이미 "미구현/스텁"이라고 명시돼 있어 추가 조치 불필요.
- **사소한 문서 누락(기능 결함 아님)**: `코칭`(아군 대상 랭크업, 1v1엔 아군 없어 무의미)만
  다른 더블 전용 기술들과 달리 `effect`에 "1v1 무의미" 주석이 빠져 있음. 우선순위 낮음, 별도
  항목화하지 않고 필요 시 사소 수정으로 처리.

---

### §1-1. 퀵턴 — 데미지 후 교체 미작동

`유턴`·`볼트체인지`와 `effect` 텍스트가 완전히 동일한데 `selfSwitchAfterDamage` 필드만 빠져
있음(복붙 시 필드 누락 추정). 대상: `src/data/moves.json`, `src/lib/battleSimulator.ts`.
**상태**: 미착수.

### §1-2. 아이스스피너 — 필드 파괴 미반영

`effect`에 "회전 운동에 의해 필드가 파괴된다"고 명시했는데 `destroysField` 필드가 없음
(`아이언롤러`는 있음). 대상: `src/data/moves.json`. **상태**: 미착수.

### §1-3. 가드스왑 / 파워스왑 — 상대와 랭크 교환 기능 자체 미구현

방어·특수방어(가드스왑) / 공격·특수공격(파워스왑)의 능력 랭크를 상대와 맞바꾸는 기능이
스키마에 전혀 없음. `파워트릭`의 `swapsOwnStats`는 자기 스탯끼리 교환이라 다른 기능이라 재사용
불가 — 신규 필드 설계 필요. 대상: `src/types/move.ts`, `src/data/moves.json`,
`src/lib/battleSimulator.ts`. **상태**: 미착수.

### §1-4. 객기 — 자기 상태이상 시 위력 2배 미구현

자신이 독·마비·화상 상태일 때 위력이 2배가 되는 로직이 스키마에 전혀 없음. 대상:
`src/types/move.ts`, `src/data/moves.json`, `src/lib/battleSimulator.ts`(또는
`battlePower.ts`). **상태**: 미착수.

### §1-5. 베놈쇼크 — 상대 독 상태 시 위력 2배 미구현

상대가 독 상태일 때 위력이 2배가 되는 로직 없음. §1-4와 유사한 "자기/상대 상태이상 조건부
위력 배율" 패턴이라 같이 설계하면 효율적. 대상: `src/types/move.ts`, `src/data/moves.json`,
`src/lib/battlePower.ts`. **상태**: 미착수.

### §1-6. 솔라블레이드 — 충전 턴 미구현

`tags`에 "충전"만 있고 정작 `chargeTurn`/`chargeSkipWeather` 필드가 빠져 있어(`솔라빔`엔 있음)
현재 2턴 충전 없이 매턴 즉발로 나갈 가능성이 있음. 물리 버전 통째로 미작동 여부 확인 필요.
대상: `src/data/moves.json`. **상태**: 미착수.

### §1-7. 성장 — 쾌청 시 2랭크 상승 조건 미반영

`effect`에 "쾌청 상태일 때는 2랭크 올라간다"고 명시했는데 항상 +1/+1(`statChanges`)만
적용됨. 날씨 조건부 랭크 변화를 표현할 스키마 필드가 없어 신규 설계 필요. 대상:
`src/types/move.ts`, `src/data/moves.json`, `src/lib/battleSimulator.ts`. **상태**: 미착수.

### §1-8. 패스트가드 / 와이드가드 — 보호 효과 자체 미구현

`protectEffect` 필드가 아예 없음. 더블 전용처럼 보이지만 "아군 전원"에 사용자 자신도 포함되므로
1v1에서도 "이번 턴 공격 막기"가 유의미함(다른 더블 전용 스텁들과 성격이 다름) — 확인 후 실제로
작동 안 하면 우선순위 있는 버그. 대상: `src/data/moves.json`, `src/lib/battleSimulator.ts`.
**상태**: 미착수.

### §1-9. 신비의부적(세이프가드) — 상태이상 면역 미구현

5턴간 상태이상 면역 효과가 스키마에 없음. §1-8과 마찬가지로 1v1에서도 유의미한 경쟁적 기술인데
미구현 상태. 대상: `src/types/move.ts`, `src/data/moves.json`, `src/lib/battleSimulator.ts`.
**상태**: 미착수.

## 6. 배틀타워 페이지 — 배틀비디오 기능 신설 (신설: 2026-09-11)

배틀타워 페이지에 "배틀비디오" 기능을 추가한다.

- 대전이 끝날 때마다 그 시점의 배틀 로그를 저장한다. 최근 3개까지만 유지하고, 4번째가
  생기면 가장 오래된 로그를 삭제한다(FIFO).
- 저장은 기존 파티 샘플과 동일하게 브라우저(localStorage 등)에 한다.
- 배틀타워 페이지 안에 토글 버튼을 두어, 누르면 저장된 배틀비디오 목록을 볼 수 있게 한다.
- 배틀비디오는 포켓몬 UI(스프라이트·게이지 등) 없이, 배틀 종료 시점의 텍스트 로그만 그대로
  꺼내 보여주는 방식으로 충분함.

**대상**: `src/components/BattleLogPage.tsx`, (신규) 배틀비디오 저장용 localStorage 키 —
`champions-party-sim.party.v1`은 파티 자동저장용 키이므로 **절대 재사용/충돌하지 않도록**
별도 키를 사용할 것 ([[dont-clear-party-autosave]] 참고).

**상태**: 미착수.

## 7. 작업 순서

§1(엔진 미배선 감사) 완료(2026-09-12) — 결과 §1-1~§1-9로 항목화. 남은 작업 순서:

**§1-1 → §1-2 → §2 → §4 → §5 → §1-3 → §1-4 → §1-5 → §1-6 → §1-7 → §1-8 → §1-9 → §3 → §6**

- **§1-1(퀵턴)·§1-2(아이스스피너)** 먼저: `moves.json` 필드 한 줄 채우면 되는 최소 규모 수정.
  감사 직후 바로 처리하는 게 자연스러움.
- **§2(파티 중복배치 버그)·§4(위력 상시표시)·§5(도감 정렬)**: 서로 파일이 안 겹치는 독립적인
  소규모 UI/로직 수정. §1류 데이터 수정과도 파일이 겹치지 않아 순서 상관없이 처리 가능.
- **§1-3~§1-7**: 신규 스키마 필드 설계가 필요한 기술 데이터/엔진 보강(가드스왑·파워스왑,
  객기, 베놈쇼크, 솔라블레이드, 성장). §1-4·§1-5는 "상태이상 조건부 위력 배율" 패턴이 같아
  묶어서 설계.
- **§1-8·§1-9**: 보호 계열(패스트가드·와이드가드)·상태이상 면역(신비의부적) — 1v1에서도
  유의미한 경쟁적 기술이라 우선순위가 있지만, 실제 영향도(현재 게임에 이 기술을 쓰는 포켓몬이
  얼마나 있는지) 확인 후 착수.
- **§3(D&D 순서변경 + 기술 필터)**: `PartyBoard.tsx`/`PartySlotCard.tsx`를 §2와 공유하므로 §2
  머지 후 진행(충돌 방지).
- **§6(배틀비디오 신설)** 마지막: 대상 파일(`BattleLogPage.tsx`)이 가장 크고 신규 기능+신규
  저장소 설계가 필요해 범위·리스크가 제일 큼.
