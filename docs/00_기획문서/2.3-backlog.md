## X1. [상시 수정] 상대 실능치 역산 검증·수정

- 사용자 보고(2026-10-02): **방어력 계수 측정 결과가 이래저래 실제와 다르다.** 기능을 더 확장(C2)하기 전에 정확도부터 검증해야 한다. 사용자가 몇 번 더 써 보며 검수하고, 그 결과를 이 항목에 쌓아 고친다.
- **상시 수정 항목**: 한 버전에서 끝내지 않고 **다음 버전 백로그에도 계속 올린다**(검증·수정이 끝났다고 사용자가 판단할 때까지).
- 진행 방식(안):
  1. 사용자가 어긋난 사례를 모은다 — 내 포켓몬·기술·급소 여부·상대 포켓몬·화면 % 전/후·결과(범위가 어떻게 나왔는지 / 실제 알고 있던 배분).
  2. 같은 상황을 엔진 공식·화면 수치와 대조해 원인을 가른다: 입력 문제(급소·날씨·필드·랭크·벽 누락) / 가정 문제(%올림, 한 번만 내림, 열매·특성) / 공식 차이.
  3. 고친 뒤 `defense-inference-check.mjs`(공식 대조·왕복)에 사례를 회귀 케이스로 추가.
- **알려진 가정(검증 대상)**: 역산의 화면 % **올림 가정**(`displayPercent` 한 곳)은 실사용 관측으로 확인 대기. 이 앱의 데미지 공식은 보정 곱 뒤 **한 번만 내림** — 챔피언스 실제 방식은 미확인. 어긋남의 1순위 용의자.
- 검증 기준선: 현재 `test:inference` — 공식 대조 1200건, 왕복 126/126, 메가 왕복 49/49 통과(코드상 일관성은 맞고, 실제 게임과의 차이는 이 검증으로 못 잡음).

## B1. 배턴터치 기술 로직 구현

- 사용자 보고(2026-10-02): 현재 배턴터치 사용 시 **교체 UI가 표시되지 않고 턴이 그대로 종료된다.** 수정 필요.
- 목표: 배턴터치 사용 직후 교체 선택 UI를 띄우고, 교체되어 들어오는 포켓몬이 배턴터치 효과(랭크 변화 등 인계 대상)를 받게 한다. 인계 범위는 착수 시 엔진 구현 현황을 보고 확정.
- 착수 시 확인: 유턴·볼트체인지 등 다른 자속 교체 기술의 교체 UI 흐름 재사용 가능 여부, 플레이어·AI 양쪽 동작.

## B2. 배틀타워 배틀 UI 수정

- 사용자 요청(2026-10-02): 배틀타워 배틀에서 다음과 같이 UI를 바꾼다.
  1. **상대 도구 이미지 제거**: 선출 화면부터 배틀 내내 **상대 포켓몬의** 도구 이미지를 표시하지 않는다. 내 포켓몬 도구는 그대로 표기한다.
  2. **상대 실능치 표기 제거**: 배틀 내내 **상대 포켓몬만** 실능치를 표시하지 않는다(내 포켓몬은 그대로).
  3. **상대 파티 6마리 이미지 나열**: 실능치를 뺀 그 열에 상대 파티 6마리의 이미지를 늘어놓는다.
- 확정 사항(사용자 답변, 2026-10-02):
  - 도구 이미지 제거 범위는 **선출 화면·배틀 판 양쪽의 상대 포켓몬에만** 한정한다.
  - 상대 6마리 이미지에서 **출전 여부는 표기하지 않는다. 기절 여부만 표기**한다.
  - 분기: 앱의 배틀 화면은 배틀타워(`BattleLogPage`) 하나뿐이라 따로 분기할 "일반 배틀"은 없다(결정력·내구력 화면은 대전이 아니라 영향 없음). 배틀타워 화면을 직접 고치면 된다.

## B3. 안개제거 로직·엔진 구현

- 사용자 보고(2026-10-02): 테스트 중 **안개제거의 효과가 발동되지 않는다.** B1(배턴터치)과 마찬가지로 **엔진 배선이 안 된 것으로 보인다.** 안개제거 효과를 구현한다.
- 사용자 추가 보고(2026-10-02): **회피율 −1랭크도 배틀 로그에 나오지 않았다.**
- 현황(코드 읽기로 확인, 실행 검증은 아직):
  - `moves.json`의 안개제거는 상대 회피율 −1(`statChanges`) 항목만 있고, 효과 설명에 있는 **리플렉터·빛의장막 등 필드 제거 처리는 데이터에도 엔진에도 없다**(분류 필드·전용 분기 없음).
  - 회피율 −1 **수치 자체는 적용되는 것으로 보인다** — `mirroredEffects.ts`의 `applyMoveAccuracyEvasionChanges`가 `defender.accuracyStages`에 반영하고 `hitChance.ts`가 회피 랭크를 읽는다. 다만 **로그 표시 경로가 없다.** 상대 랭크 하락 문구(`opponentStatDrops`, `BattleTurnLog.tsx`)가 `BattleStatKey`(5스탯)만 담아 명중률·회피율 변화는 수집되지 않는다. 그래서 효과가 있어도 로그엔 안 뜬다.
  - 확인 방법: 안개제거 사용 뒤 상대 `accuracyStages.evasion`이 −1이 되는지 엔진 스크립트로 검증(수치 미적용이면 원인은 다른 곳).
- 목표: ① 회피율 −1의 로그 문구 추가("상대의 회피율이 떨어졌다!" — 감미로운꿀 등장 문구와 같은 형식) ② 상대 쪽 벽·필드 효과 제거 구현. 제거 대상 범위(양쪽 진영의 스텔스록·압정 등 설치 기술, 안개·필드 포함 여부)는 챔피언스 실제 동작 기준으로 착수 시 확정.
- 같은 로그 공백이 다른 기술(명중률·회피율을 바꾸는 기술 전반)에도 있을 수 있어 착수 시 함께 점검.
- B1(배턴터치)과 같은 유형(기술 효과 엔진 미배선)이라 묶어 살피면 효율적이다.

## 2.2에서 넘어온 한계·가정 (L1~L5)

자세한 맥락은 `2.2-backlog.md` 마무리 절 참고. 각 항목은 사용자가 필요하다고 할 때 착수한다.
