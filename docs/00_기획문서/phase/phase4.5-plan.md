# Phase 4.5 기획 — 포켓몬 로스터 확장 & 사이드 메뉴 활성화 (종료됨)

> 이어서 읽기: [Phase 4 기획](phase4-plan.md) · 이어지는 문서: [Phase 5 기획](phase5-plan.md)
> Phase 4에서 계획했던 5개 항목(§2 명중률 배율·§4 트릭룸·§1 회복 엔진·§3 날씨 지속시간+스크린·§7 UI 정합성)을 전부 마쳤다([PR #2](https://github.com/Erensia/poke-builder/pull/2)). 이 문서는 사용자가 이번에 새로 요청한 두 항목(포켓몬 로스터 확장, 사이드 메뉴 활성화)과, Phase 4에서 스코프 밖으로 남긴 백로그(§5·§6·§8·§9)를 한데 정리한 것이다.
>
> **§1~§5 전부 완료 — Phase 4.5 종료.** 로스터 확장(23→37종), 사이드 메뉴(포켓몬 도감·기술표) 활성화, 필드 개별 기술 상호작용, 도구 개별 효과 8종, 변화기 effect 텍스트 보강, 날씨 특성 동시보유 규칙까지 모두 반영됐다. §5-2(해동 기술 잔여 6종)·§5-5(오로라베일)는 현재 로스터에 학습자가 없어 데이터 확정이 불가능한 상태라 "학습자가 로스터에 들어올 때 처리"로 보류했다 — 재작업이 필요한 게 아니라 지금 시점엔 대상이 없는 것뿐이라 별도 이월 항목으로 취급하지 않는다. 이후 대규모 신규 인프라가 필요한 작업(미구현 특성 60종, 상대 기술 선택을 제약하는 변화기 4종 등)은 [Phase 5 기획](phase5-plan.md)에서 이어간다.

## 0. 이 문서의 성격

새로 발견한 문제가 아니라 (1) 사용자가 이번에 직접 요청한 신규 작업 두 건과 (2) `phase4-plan.md`에 "우선순위 낮음"으로 남아있던 이월 항목을 재우선순위한 것. 이월 항목의 배경은 `phase4-plan.md`와 그 위 링크를 따라가면 된다.

## 1. 포켓몬 로스터 확장 (신규 요청)

현재 로스터는 23종. 구체적으로 몇 마리를 추가할지, 어떤 포켓몬을 넣을지는 작업하면서 사용자가 지정한다.

- **일렉트릭필드를 배우는 포켓몬 반영**: [phase4-plan.md §7](phase4-plan.md#7-ui-정합성-갭)에 남아있던 이월 항목 — Phase 3에서 일렉트릭필드 *기술* 데이터는 추가했지만 로스터 어떤 포켓몬의 `learnset`에도 넣지 않았다(그래스/미스트/사이코필드는 각각 6마리씩 확인된 것과 대비). 이번 로스터 확장에서 일렉트릭필드를 쓸 수 있는 포켓몬을 실제로 넣으면서 함께 해결한다.
- 새 포켓몬을 넣을 때마다 같이 확인할 것: 메가진화 여부/전용 스톤, `learnset`(신규 기술 포함 여부), 특성(숨겨진 특성 포함), 능력치, 그리고 §3(아래, 필드 개별 기술 상호작용)에 나오는 필드 전용 기술(그래스슬라이더·대지의파동 등)을 배우는지 — 이걸 로스터 추가 시점에 같이 체크해두면 §3 작업이 나중에 훨씬 수월해진다.

## 2. 사이드 메뉴 활성화 — 포켓몬 도감 / 기술표 (신규 요청)

[Sidebar.tsx](../src/components/Sidebar.tsx)의 `NAV_ITEMS`에 "포켓몬 도감"·"기술표"가 `view: null`로 박혀 있어 클릭해도 아무 반응이 없다(버튼 자체가 `disabled`). `AppView` 타입(`"party" | "matchup" | "battle-log"`)에 새 뷰가 아예 없어서 단순히 플래그를 켜는 게 아니라 페이지 컴포넌트를 새로 만들어야 하는 실제 기능 작업이다.

- **포켓몬 도감**: 로스터 전체를 훑어보는 조회 페이지. 타입·능력치·특성(숨겨진 특성 포함)·메가진화 폼·`learnset`을 한눈에 볼 수 있으면 됨
- **기술표**: 현재 335개 기술(§1 로스터 확장 이후 378개로 늘어남)을 타입·분류(물리/특수/변화)·위력·우선도 등으로 필터·정렬해서 보는 조회 페이지
- 둘 다 기존 데이터 조회 함수(`getPokemon`/`getMove` 등)만 있으면 되고 시뮬레이터 로직(`battleSimulator.ts` 등) 변경은 필요 없다 — 순수 조회/필터 UI라 리스크가 낮음
- `App.tsx`에 뷰 분기 추가, `Sidebar.tsx`의 `view: null` → 실제 뷰로 교체

## 3. 필드 개별 기술 상호작용 (Phase 4 §5 이월)

필드 기본 효과(위력 배율·상태이상 면역·우선도 차단·그래스 회복)는 Phase 3에서 끝냈지만, 개별 기술 특수 상호작용은 스코프 밖으로 남겼다: 그래스슬라이더(그래스필드에서 우선도 +1), 대지의파동(필드별 타입 변경+위력 2배), 아이언롤러(필드 파괴), 미스트버스트/와이드포스/라이징볼트(필드 조건부 위력 변화). 각 기술이 실제 로스터에 있는지부터 재확인 필요 — §1(로스터 확장)에서 새로 들어오는 포켓몬이 이 기술들을 배우는지 같이 체크하면 좋음.

## 4. 우선도·상태이상·기타 개별 도구 효과 (Phase 4 §6 이월)

도구표에서 각각 서로 다른 개별 메커니즘이 필요해 미뤄온 항목들 — 우선순위 낮음(도구 1개당 기술/상황 1개라 서로 재사용 가능한 부분이 적음):

|---|---|
| 하양허브 | 능력 하락을 원래대로 되돌림(1회용) |
| 구애스카프 | 스피드 1.5배 + "교체 전까지 같은 기술만" 제약 |

## 5. 외부 확인이 필요했던 항목 (Phase 4.5 마무리, 옛 §5·§6·§8 통합) — 완료

전부 "챔피언스 실제 데이터/규칙을 확인하면 바로 처리 가능한" 작업이라 한데 묶었다. 새 엔진 인프라가 필요한 게 아니라 기존 스키마(`Move`/`Item`)에 값만 채우거나, 기존 패턴(`Move.setsScreen`, `Item.screenDurationBonus` 등)을 그대로 재사용하는 수준.

### 5-1. ~~변화기 `effect` 텍스트 누락 (17개)~~ — 해결됨

`power: null`인 변화기 중 `effect: ""`로 비어있던 17개(대타출동, 생명의물방울, 꿀꺽, 물붓기, 도발, 신비의부적, 사슬묶기, 수면가루, 미러타입, 봉인, 부식가스, 아픔나누기, 최면술, 매직룸, 중력, 파워스왑, 전자부유) 모두 최신화된 Champions 기술표를 참고해 텍스트를 채웠다.

(참고: `effect: ""`인 기술은 78개가 더 있지만 나머지는 위력 있는 공격기라 "특별한 부가효과 없음"이 곧 정답인 경우가 대부분 — 진짜 문제는 변화기 17개뿐이었음)

**범위 구분(사용자 확인)**: 도발·사슬묶기·앙코르·헤롱헤롱처럼 상대의 기술 선택 자체를 제약하는 변화기는, 텍스트만 채우는 건 위 17개처럼 4.5 §5-1 범위지만, 그 제약을 실제로 전투 시뮬레이터가 강제하는 것(도발 사용 후 3턴간 변화기 선택 차단, 사슬묶기의 직전 기술 봉인, 앙코르의 상대 기술 고정, 헤롱헤롱의 확률부 행동불능 등)은 `구애스카프`의 UI 잠금 패턴보다 범위가 넓은 신규 인프라라 Phase 5로 넘긴다 — [phase5-plan.md §2](phase5-plan.md)에 새 항목으로 추가.

### 5-2. ~~해동 기술 7종 데이터 없음~~ — 부분 해결, 나머지는 보류

얼음 상태에서 쓰면 자동 해동되는 기술 10종 중 4종(불사르기·열사의대지·플레어드라이브·열탕, 전부 `thawsUserOnUse: true`)은 이제 데이터가 있다 — 열탕은 밀로틱 로스터 추가 때 같이 채워짐.

남은 6종(성스러운불꽃·스팀버스트·크로스플레임·화염바퀴·화염볼·휘적휘적포)은 현재 로스터 37종 중 배우는 포켓몬이 0마리라 §3·§4에서 적용한 것과 같은 원칙(실제 로스터 학습자가 있는 것만 데이터 보강)에 따라 보류한다. 학습자가 로스터에 들어오는 시점에 그때 스탯을 확인해서 추가.

### 5-3. ~~`Ability.setsWeather` 양쪽 동시 보유 시 우선권 규칙 미확인~~ — 해결됨

사용자 확인: "우선권"이 있는 게 아니라 둘 다 발동한다 — 스피드가 빠른 쪽의 특성이 먼저 발동하고, 날씨는 이미 걸려있어도 실패 없이 항상 덮어쓰는 규칙(기존 확인 사항)이라 나중에(=스피드가 느린 쪽이) 발동하는 쪽의 날씨가 최종적으로 남는다. `resolveEntryWeather`를 수정해 양쪽 다 특성을 보유했을 때 스피드 순서대로 두 줄 다 발동 로그를 남기고, 최종 날씨는 스피드가 느린 쪽 걸로 반영하도록 고쳤다.

### 5-4. ~~그라운드코트 실존 여부~~ — 해결됨

사용자 확인: 그라운드코트는 아직 포켓몬 챔피언스에 도입되지 않은 도구. `items.json`에 추가하지 않고 이 항목은 종료.

### 5-5. 오로라베일 데이터 없음 — 보류

`moves.json`에 데이터 자체가 없고 로스터 학습자도 0마리 — §5-2와 같은 이유로 보류. 학습자가 로스터에 들어오면 위력/명중/PP를 확인해서 리플렉터/빛의장막과 같은 방식(`Move.setsScreen`)으로 추가하되, 물리·특수를 동시에 반감시키고 날씨(눈)가 있어야 쓸 수 있는 예외 규칙은 §3에서 만든 필드 조건부 패턴(`usageCondition` 등)을 참고해 별도 처리.

(출처: [phase4-plan.md §8](phase4-plan.md#8-데이터-완성도), Phase 4 §3 작업 중 발견)

## 6. 설계 범위 밖 — 파티 단위 확장이 먼저 논의돼야 함 (Phase 4 §9 이월, 일부 Phase 5로 이동)

1v1 단일 대전 시뮬레이터라는 지금 설계 전제 자체를 안 건드리면 의미가 없는 항목만 남았다. 원래 여기 같이 있던 고스트다이브·잠꼬대는 1v1 범위 안에서도 독립적으로 구현 가능해서 [Phase 5 기획](phase5-plan.md)으로 옮겼다.

- **엔트리 해저드**(독압정 등): "교체" 개념이 없으면 무의미
- **집단구타**: 위력이 파티 전원의 공격 종족값 기반이라 파티 개념 필요

파티 배틀 확장을 언젠가 논의하게 되면 그때 같이 검토.
