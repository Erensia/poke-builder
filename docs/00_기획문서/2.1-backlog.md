## B. 샘플 파티 묶음 (토의)

배경: 2.0 실사용에서 "내 파티를 여러 상대와 굴려 보는" 용도로 쓰려는데, 상대 파티를 매번 직접 짜기가 번거롭다(사용자, 약 11판을
내 파티 ↔ 여러 파티로 돌려 봄).

제안:
- 앱에 **미리 짜 둔 파티 묶음**을 넣는다 — 성향별로 대면형·교체(사이클)형·날씨(비·쾌청·모래)·트릭룸·변화기(랭크업·상태이상) 등
  6~10개. 각 파티는 지금 파티 저장 형식(포켓몬·특성·도구·기술·성격·포인트) 그대로.
- 대전 설정 화면에서 AI 쪽 파티를 **샘플에서 고르기 / 무작위**로 불러온다. 내 저장 파티(`champions-party-sim.party.v1`)는 건드리지
  않는다(샘플은 읽기 전용 데이터, 불러와서 고치면 사본).
- "연속 대전" 흐름: 내 파티 고정, 상대만 샘플 순환 → 결과 요약(파티별 승패). AI 학습(1-C)은 샘플 상대와 싸워도 사람 행동만 배우므로 그대로.

착수 때 토의할 것(사용자 — 세부는 직접 할 때 정한다):
1. 샘플 수·구성(어떤 성향을 넣을지) — 사용자가 실전에서 자주 보는 파티 위주로 할지, 교과서적 아키타입 위주로 할지.
2. 누가 짜는가 — Claude가 초안(데이터 로스터 안의 포켓몬·기술로만) → 사용자 검수. 메타 반영 정도는 사용자 판단.
3. 연속 대전·결과 요약까지 2.1에 넣을지, 샘플 불러오기만 먼저 할지.
4. 벤치 재사용: 시뮬레이터(`battle-ai-sim.mjs`)의 파티 풀에도 같은 샘플을 쓰면 AI 벤치의 다양성도 늘어난다(부수 효과).

## C. 상대 실능치 역산 (토의)

배경: 실제 포챔스에서는 상대의 성격·능력 포인트를 알 수 없다. 내가 입힌 데미지(줄어든 HP %)로 상대의 내구 배분을 거꾸로 추정하고
싶다(사용자 제안). AI의 완전 정보 전제(2.0 합의)와는 별개 — **사용자용 도구**다.

가능성: 충분히 가능하고, 계산도 가볍다.
- 챔피언스 실수치는 `HP = 종족 + 75 + P`, 그 외 `(종족 + 20 + P) × 성격`(`statCalculator.ts`) — 레벨·개체값이 없어 미지수가 적다.
- 방어 쪽 미지수: HP 포인트 0~32 × 방어(또는 특방) 포인트 0~32 × 성격(↑·↓·무보정) = 약 3,300가지. 각각 `computeDamage`
  (`battlePower.ts`)로 난수 16단계를 돌려도 5만 번 — 브라우저에서 즉시.
- 관측과 맞는 조합만 남긴다: "화면 % 표시가 이 값이 되는 (배분, 난수)가 하나라도 있는가".

한계와 대응:
- **HP와 방어는 서로 바꿔 칠 수 있다** — 한 번의 물리 공격으로는 "HP×방어 곱"의 범위만 좁혀진다(난수 폭 약 15% 때문에 한 방으로는
  ±7% 정도). 물리·특수를 둘 다 맞히면 공통인 HP가 갈라지고, 여러 번 맞히면 교집합으로 좁혀진다. 합계 66 상한도 제약으로 쓴다.
- 그래서 결과는 "정답 하나"가 아니라 **가능한 배분 범위 + 흔한 배분 순위**로 보여 준다(예: "HP 32 · 방어 20~32 · 방어↑ 성격이면
  맞음", "HP 0 이면 불가능"). 흔한 배분(32·32·2 등)에 사전 가중치를 줘 순위를 매긴다.
- 전제가 어긋나면 틀린다: 급소, 도구(돌격조끼·진화의휘석 등), 특성(멀티스케일·복슬복슬 등), 랭크, 벽·날씨. 사용자가 아는 조건은
  입력(체크)하게 하고, "모르는 도구" 선택지는 후보별로 다시 풀어 "돌격조끼라면 이 배분" 식으로 나눠 보여 준다.
- 화면의 HP 표시 방식: 게임은 상대 HP를 **정수 %(100% ~ 0%)**로 보여 준다(사용자 확인) — 관측 1회 = "잃은 %가 이 정수"로 받고,
  게임의 % 반올림 방식(내림·반올림)은 구현 때 확인해 판정 폭에 넣는다.

확장(같은 틀로 가능):
- **공격 쪽 역산**: 상대가 나에게 준 데미지(내 HP는 정확한 숫자)로 상대 공격·특공 포인트·성격·화력 도구(구애·생명의구슬) 추정 — 방어
  쪽보다 정확하다(내 HP가 정수라서).
- **스피드 역산**: 누가 먼저 움직였는지로 상대 스피드 포인트·성격의 상한/하한(동속 가능성 포함).
- 한 대전의 관측을 모아 상대 포켓몬 하나의 추정 배분을 계속 좁혀 가는 "관측 기록" 화면.

합의(2026-09-30, 사용자):
1. HP 표시: 게임은 **정수 %, 100% ~ 0%**.
2. 위치: **계산기 화면의 새 탭**.
3. 1차 출력: **가능한 배분 범위**부터(관측과 맞는 HP·방어/특방 포인트·성격 조합의 범위). 흔한 배분 순위 매기기는 그 다음.

남은 것(착수 때 토의):
- 1차 범위를 방어 역산만으로 할지(제안), 공격·스피드 역산까지 넣을지.
- 게임 % 표시의 반올림 방식 확인(구현 전).
- 모르는 도구·특성을 어떻게 보여 줄지(후보별로 나눠 보이기 제안).
- 흔한 배분 사전값의 출처(고정 목록 / B의 샘플 파티 / 사용자 저장 파티) — 순위 매기기 단계에서.

### C 추가 합의 (2026-09-30, 사용자 — 착수 전 토의)

1. **1차 범위 = 방어 역산만.** 공격·스피드 역산은 이후 단계.
2. **% 반올림**: 사용자 관측 "HP 1 남아도 1%"로 **올림 가정을 기본**으로 하되, % 변환은 함수 한 곳으로 분리하고 "여유 있게 보기(±1%)"
   옵션을 둔다. 확정용 관측: 상대가 HP를 조금만 잃은 직후 100%가 남는지 99%로 내려가는지(올림이면 100% 유지) — 구현 중 사용자 확인.
3. **특성·도구는 UI 토글**(분류 안 함): 내구력에 영향을 주는 특성·도구만 후보로 노출(전수 조사는 설계 때). 토글을 켜면 결과에
   "특성 OO 가정"을 표시. 관측을 왜곡하는 것(옹골참·지구력·먹다남은음식·열매 회복)은 **2차**에서 "관측 사이 사건" 입력으로.
4. **관측 = 목록**: (내 기술, 맞기 전 %, 맞은 후 %)를 여러 개 입력. 관측 사이 상대 회복이 없다는 전제를 화면에 경고.

### C MVP 구현 기록 (2026-09-30)

- **정확한 공식**: 매치업 화면의 난수 % 표기(`damageRollPercents`)는 정수 내림·`+2`가 없는 연속값 근사라(예: 정수 61 vs 근사 59.4, 약 2.7% 차이) 1% 단위 관측에 쓰면 후보 판정이 어긋난다.
  그래서 `computeDamage`와 같은 정수 공식 `floor((floor(floor(22×위력×공격÷방어)÷50)+2) × 보정 × 난수 ÷ 방어배율)`을 쓴다.
  `evaluateSlotMatchup`이 `damageParts`(위력·공격항·자속/특성/도구/날씨/필드/급소 배율·방어 랭크·방어 관련 배율)를 함께 내주게 했다(동작 무변경).
  한계: 이 앱은 보정을 전부 곱한 뒤 한 번만 내림한다 — 챔피언스가 보정마다 내림하는지는 미확인(실제 관측과 어긋나면 "여유 있게 보기(±1%)"로 대응, 이후 보정).
- **`lib/defenseInference.ts`**: 후보 = HP·방어·특방 포인트(합 66 이하) × 성격 묶음(방어/특방 ↑·↓·무보정 조합). 후보마다 관측을 순서대로 재생(난수 16단계 전부)해
  화면 %(올림, `displayPercent` 한 곳)와 맞는 경우만 남긴다. 상대 특성·도구 가정(방어에 영향을 주는 것만 목록), 벽, 상대 방어/특방 랭크, 내 상태이상(화상)·랭크·급소 반영.
  관측 하나짜리 가능 여부 + 모순이면 "어느 관측을 빼면 풀리는지" 표시. 다단히트·고정 데미지·타입 면역 기술은 관측에서 거른다(사유 표시).
- **화면**: 결정력 & 내구력 화면 상단 탭 [결정력 계산 | 상대 실능치 역산]. 내 포켓몬 카드 재사용(기술 칸·도구 강탈/곡예 토글 숨김), 상대는 종·폼만, 가정·조건, 관측 목록(다음 줄 "전 %"는 이전 줄 "후 %"로 자동), 결과(범위 막대·성격 묶음·HP×방어 분포 표).
- **검증**: `npm run test:inference` — 엔진 `computeDamage` 대조 1200건 일치, 왕복(진짜 배분으로 관측 생성 → 역산에 진짜 배분이 남는지) 126/126, 평균 남은 후보 약 40%. 판단 시간: 물리 1건 ~20ms, 물리+특수 2건 ~0.3초, 3건(모순 시 원인 탐색 포함) ~0.9초 — 무거우면 Worker로.
- **UX 테스트에서 볼 것**: 관측 입력이 번거롭지 않은가 / 결과가 "쓸모 있게" 좁혀지는가 / 남은 후보 40%로 충분한가(HP×방어 곱만 좁혀지는 한계 — 물리·특수를 섞거나 여러 번 맞히면 좁아짐) / 게임 % 반올림(올림 가정) 실제 확인.
- **다음(2차)**: 공격·스피드 역산, 관측 사이 사건(회복·옹골참), 후보별 특성·도구 나눠 보기, 흔한 배분 순위, 결과를 결정력 탭 상대 슬롯으로 넘기기.
