## 4. 버그 수정 — 자기/아군/양쪽 편 대상 기술이 상대 방어류에 잘못 막힘 (신설: 2026-09-14, §3 스모크 테스트 중 발견)

`battleSimulator.ts`의 `blockedByProtect`가 "방어측"을 항상 상대 고정 기준으로 계산해서,
정작 상대를 겨냥하지 않는 기술(아군 대상·양쪽 편 대상)까지 상대가 방어류(방어·킹실드 등)를
쓴 턴엔 효과가 조용히 무산되고 있었다. 로그 문구("막혔다!")는 자기 대상 기술에 안 뜨도록
이미 처리돼 있었지만(§6.5-6-2 ⑦) **실제 효과 적용 자체**는 여전히 막히는 상태였음.

본가 규칙(Bulbapedia Protect 문서 — 자신 대상·자신+아군 대상·전체 대상 기술과 설치 기술은
방어류로 못 막는다)에 따라 대상 3개 기술을 확인·수정:

- **회생의기도**(`Move.revivesFaintedAlly`) — 아군 대상. 스모크 테스트로 재현 확인(상대가
  같은 턴 방어류를 쓰면 부활이 조용히 무산, 실패 안내도 안 뜸) 후 수정.
- **정리정돈**(`Move.hazardClear === "tidy"`) — 양쪽 편 전체 대상. 코드 검사로 발견,
  수정 후 스모크 테스트로 확인.
- **코트체인지**(`Move.swapsSideEffects`) — 양쪽 편 전체 대상. 코드 검사로 발견(처음엔 명중
  판정이 있어 상대 대상인가 의심했으나, 웹 검색으로 Bulbapedia에서 방어류에 안 막힘을
  확인), 수정 후 스모크 테스트로 확인.

**제외(의도적으로 안 고침)**: 고속스핀(`Move.hazardClear === "spin"`)은 상대 1마리를 직접
공격하는 데미지 기술이라 방어류에 막히면 부가효과(설치물 정리)도 함께 무산되는 게 본가
규칙과 일치한다 — 그대로 뒀고, 수정 후에도 여전히 막히는지 스모크 테스트로 회귀 확인.
칼춤·나쁜음모 같은 자기 대상 랭크업은 `statChanges`로 처리되는 별개 경로라 애초에
`blockedByProtect`를 안 써서 조사 대상이 아니었다(확인 안 함, 별도 버그 없어 보임).

**상태**: 완료(2026-09-14). `battleSimulator.ts`에서 세 기술의 효과 적용 조건에서
`!blockedByProtect`를 제거(정리정돈은 "spin"과 분기를 분리). 브라우저 Vite 페이지
컨텍스트에서 4가지 모두 확인: 회생의기도·정리정돈·코트체인지가 상대 방어류를 뚫고 정상
동작, 고속스핀은 여전히 막힘(회귀 없음).
