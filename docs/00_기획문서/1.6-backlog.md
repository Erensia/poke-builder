# ver.1.6 백로그

## 0. 이 문서의 성격

ver.1.5(코드 리팩토링, `dev_repactoring` 브랜치) 진행과 별개로, 사용자가 정리해 둔
`백로그1.6.txt`(모바일 UI/UX 문제 + 기능 버그·업데이트 목록)를 이 프로젝트의 백로그 문서
형식으로 옮겨 적은 것이다. **아직 코드 조사도 착수도 안 한 순수 계획 문서** — 각 항목의
"대상 파일" 추정은 실제 착수 시점에 코드를 먼저 읽고 검증할 것(이 프로젝트의 기존 원칙:
계획 문서보다 실제 코드가 우선 — ver.1.5 §7에서 계획을 코드 읽은 뒤 바꾼 전례 참고).

원본 텍스트의 UI 문구 변경 항목은 사용자가 준 문구를 한 글자도 안 바꾸고 그대로 옮겼다 —
구현 시에도 그 문구를 정확히 반영할 것(조사 표기 자동 매칭 등 부가 지시사항 포함).

ver.1.5는 `dev`에 완전히 들어갔고(PR #121), ver.1.6은 `dev` 기준으로 바로 시작한다.
브랜치는 섹션 단위 feature 브랜치(`fix/…`, `feat/…`) → PR 1커밋(squash)으로 `dev` 병합
(기존 [[pr-merge-workflow]] 유지). 검증은 항목 성격이 제각각이라(모바일 CSS/레이아웃 vs
엔진 로직 vs UI 문구 vs 배틀타워 컴포넌트) 트랙별로 다르게 설계했다 — 브라우저가 필요한
검증(모바일 뷰포트 스크린샷, 엔진 스모크테스트 콘솔 실행, 배틀타워 UI 조작)은 전부
[[delegate-browser-verification-to-user]]에 따라 사용자에게 위임한다.

트랙 구성(서로 성격이 달라 독립적으로 진행 가능):
- **트랙 D — 모바일 UI/UX** (§1~§2): 디자인 개편 + 5건의 모바일 레이아웃/상호작용 버그.
- **트랙 E — 엔진/UI 문구 버그 수정** (§3): 아이템 적용범위 버그 1건(§3-2), UI 문구 개선
  7건(§3-3). 원래 트랙 E에 있던 특성 로직 2건(위기회피·괴짜/변신)은 착수 전 검증에서
  정상 동작하는 것처럼 보여 §5(보류)로 이관했으나, 실제로는 UI 연동 버그들이 숨어
  있었음이 나중에 드러났다 — §5 참고.
- **트랙 F — 배틀타워 편성/선출 UI** (§4): 중복 방지·드래그앤드롭·UI 압축·프로필 이미지 4건.
- **§5**: 위기회피·괴짜/변신·메가스톤 특성 표기 — 최하단 우선순위로 미뤄뒀다가 착수해
  보니 사용자가 앱에서 직접 재현하며 진짜 버그를 여럿 찾아냄(교체 등장 미발동, 보드
  표시·기술배치·메가진화 이미지 미반영, 메가스톤 소지만으로 특성 고정 등). 전부 수정 완료.

**상태**: 전체 완료(§3-2 PR #122, §3-3·§3-4 PR #123, §4-1·§4-2·§4-4 PR #124, §4-3 PR #125,
§2-1~§2-5 PR #126, §5 PR #127, §1 PR #128, 모두 dev 병합). **ver.1.6 백로그 전체 종료**
(2026-09-17, dev==main 예정).

## 1. 모바일 UI 리디자인

### §1-1. 디자인 컨셉 결정 — 글래스모피즘 vs 뉴모피즘

전면 UI를 글래스모피즘(Glassmorphism) 또는 뉴모피즘(Neumorphism) 스타일로 개편한다.

- 두 디자인 중 이 프로젝트에 더 어울리는 쪽으로 전면 개편.
- **가능하다면** 두 디자인을 각각 브랜치로 구현해 실제로 비교해 볼 수 있게 준비할 것
  (사용자가 최종 선택할 수 있도록).
- 디자인 구현 시 기본 색상은 **현재 배경색을 기반**으로 파생시킬 것 — 색상 체계를 처음부터
  새로 정하지 않는다.

**대상**: 전역 스타일(색상/그림자/블러 등 디자인 토큰), 컴포넌트 다수. 착수 시 영향 범위
전수 조사 필요.

**추가 논의 예정**: §2-5(기술표 헤더 슬라이드 동기화) 작업 중 사용자가 제안 — 기술표
페이지를 지금의 표(가로 스크롤 필요) 대신 **카드형 UI**로 바꾸는 것도 이 전면 개편과 함께
검토하기로 함(가로 스크롤 자체가 모바일에 안 맞는 레이아웃이라, 카드형으로 가면 §2-5에서
고친 헤더 동기화 로직이 통째로 필요 없어짐 — 개편 착수 시 우선순위 논의).

**진행 경과**(브랜치 `feat/glassmorphism-tokens`):
- 디자인 컨셉은 논의 끝에 글래스모피즘으로 즉시 확정(브랜치 두 개로 비교 없이 바로 진행).
- **토큰 + 공통 컴포넌트**: `index.css`에 `--surface`/`--surface-2`를 반투명으로,
  `--glass-blur`/`--glass-border`/`--glass-focus-border`/`--glass-shadow` 신설. 배경에
  고정 blob 2개(라이트/다크 각각 색 다름)를 깔아 블러 패널이 비칠 대상 마련. 모달 패널,
  사이드바(데스크톱 레일 + 모바일 드로어)에 `backdrop-filter` 적용.
- **개별 페이지 확산**: 매치업/파티/도감(포켓몬·도구)/타입 매트릭스/배틀타워 주요 카드
  패널에 블러 적용(단, 표 셀·리스트 아이템처럼 수십~수백 개씩 반복되는 요소는 성능 때문에
  블러 없이 반투명 색상만 — 바깥 패널 하나에만 블러를 걸고 안쪽은 평면 색).
- **검색창 통일**: 포켓몬/기술/도구 선택 모달 + 파티 샘플/저장된 샘플 모달 + 포켓몬
  도감/도구 도감, 총 7곳의 검색창을 전부 **목록 하단 고정(sticky bottom) + 유리 블러**로
  통일(기존엔 일부는 상단 고정, 일부는 목록과 같이 흘렀음 — 통일감 없단 피드백으로 정리).
  포커스 테두리도 불투명 보라 → 반투명 보라(`--glass-focus-border`)로 완화.
- **스크롤바**: 전역으로 얇고 반투명한 보라색 커스텀 스크롤바 적용(브라우저 기본 스크롤바가
  유리 패널 위에서 튀어 보인다는 피드백).
- **특성 설명 정리**(디자인 개편과는 별개 피드백, 같은 세션에 처리): `abilities.json` 216개
  중 괄호로 묶인 부가 설명이 있던 항목 전부(42개) 괄호를 통째로 제거 — 시뮬레이터 구현
  메모든 실제 게임 규칙 설명이든 구분하지 않고 괄호가 있으면 무조건 삭제, 없으면 그대로
  (사용자가 명확히 정한 규칙 — "본가에서 찾은 대로 심플한 문장만 남긴다").
- **§1-1c 기술표 카드 전환**: `MoveDexPage` 표(그리드 행 + 헤더/본문 가로 스크롤 동기화 JS)를
  전부 걷어내고 카드 그리드로 교체(데스크톱도 카드로 통일 — 사용자 확정). 정렬은 열 헤더
  클릭 대신 드롭다운 + 방향 토글 버튼(`movedex-sort-bar`)으로 이동. §2-5에서 고쳤던
  `headRowRef`/`translateX` 스크롤 동기화 로직은 카드형에선 애초에 불필요해져 전부 삭제.
- **모바일 실기기 검증 중 추가로 발견·수정한 버그 4건**:
  1. 포켓몬/도구 도감 — `align-items:flex-start`가 데스크톱(가로 배치)에서 목록·상세 패널
     높이를 다르게 유지하려는 의도였는데, 모바일(세로 배치)에선 같은 속성이 교차축(가로)에
     적용돼 상세 패널이 목록 패널보다 좁게 쪼그라드는 버그 — 모바일 미디어쿼리에서만
     `align-items:stretch`로 되돌려 수정.
  2. 배경 유리 얼룩(`body::before/after`)이 뷰포트 모서리에 `position:fixed`로 고정돼
     있었는데, 세로로 아주 긴 모바일 화면에서는 얼룩이 화면 위쪽 절반도 못 덮어 중간~아래로
     스크롤하면 유리 효과가 아예 안 보였음 — 얼룩을 훨씬 크게 키우고(46/50→70vmax) `#root`에
     세 번째 얼룩을 추가해 뷰포트 중간대까지 커버.
  3. 이판사판태클(`moves.json`)에 `recoilFraction` 필드가 빠져 있어 반동 데미지가 아예
     적용 안 되던 버그 — 같은 1/3 반동 계열 기술들과 맞춰 추가.
  4. **오버킬 시 반동/흡수/조개껍질방울이 이론상 데미지로 부풀려지던 버그**(사용자가 메가
     보만다 이판사판태클 vs 메가이어롭으로 실전 발견) — `recoilFraction`/`drainFraction`/
     조개껍질방울/생명의구슬/매지션이 전부 `damage`(상대 HP를 넘겨도 그대로인 이론상 수치)를
     기준으로 계산되고 있었음. `defender.currentHp`를 직접 건드리는 모든 지점(일반 히트·
     대타·카운터류·죽기살기)에서 실제로 깎인 HP(`actualDamageDealt`)를 새로 추적해 전부 이
     값 기준으로 교체(`src/lib/battle/hitResolution.ts`).

**상태**: 완료. §1-1a~c + 위 4건 버그 전부 PR #128(`feat/glassmorphism-tokens`) 1커밋으로
`dev` 스쿼시 머지(2026-09-17). **이것으로 ver.1.6 백로그 전체 종료.**

## 2. 모바일 UX 개선

아이폰 15 프로 + 사파리 기준으로 발견된 문제들. 다른 기기/브라우저에서도 재현되는지는
착수 시 함께 확인.

### §2-1. 검색창(포켓몬/기술 검색)이 하단에 고정돼 매번 스크롤해야 함

포켓몬 검색·기술 검색 모달의 검색창 위치가 화면 하단에 고정되는 문제. 검색할 때마다
스크롤해야 해서 불편함. 화면 중앙에 플로팅으로 고정하는 방식이 가능한지 검토하고, 불가능하면
대안(예: 상단 고정, sticky positioning 방식 변경 등)을 찾을 것.

**대상**: `PokemonPickerModal`·`MovePickerModal` 등 피커 모달 계열(§9에서 보류된 "피커 모달
6종 통합"과 연결지어 검토하면 좋을 수 있음).

**상태**: 완료(PR #126, dev 병합). 원인은 검색창 자체가 아니라 팝업 전체가 결과 적을 때
화면 아래쪽에 작게 눌러앉는 것 — 모든 모달 공통으로 `Modal.css`에서 내용량과 무관하게
고정 height(85vh)로 뜨게 수정.

### §2-2. 능력 포인트 배분 창 — 배분 수치 미표시 + 위치 문제

- PC에서는 각 능력치에 배분된 포인트 수치가 보이는데, 모바일에서는 그 수치 UI 자체가
  안 보임(수치를 확인할 방법이 없음).
- 능력 포인트 배분 창이 화면 너무 하단에 표기됨(§2-1과 비슷한 결의 위치 문제).

**대상**: `PointsEditorModal`.

**상태**: 완료(PR #126, dev 병합). 모바일에서 `display:none`으로 배분 수치 입력창 자체를
숨기고 있던 게 원인 — 숨기지 않고 입력창을 줄여서 자리 확보. 팝업 위치 문제는 §2-1과
같은 원인(Modal.css 공통 수정)으로 같이 해결됨.

### §2-3. 매치업 페이지(결정력&내구력) — 스피드 결과 블록 가로폭 불일치

모바일 화면에서 매치업 페이지의 스피드 결과를 보여주는 블록의 가로폭이 포켓몬 상태창 UI의
너비보다 넓어서 비율이 이상해 보임.

**대상**: `MatchupPage.tsx` 계열.

**상태**: 완료(PR #126, dev 병합). 원인이 두 겹이었음 — (1) 폭 계산 기준이 실제 CSS와
안 맞았음(모바일은 `.matchup-slot`이 고정 280px가 아니라 `MatchupSlotCard.css`의 기존
규칙으로 `max-width:320px`, 데스크톱은 카드 2장 사이에 `.matchup-verdict-row`(130px)까지
있어서 실제 폭이 280+130+280+갭×2=722px), (2) 긴 판정 문구("⚡ 내 포켓몬이 먼저
움직여요")가 실능치 span과 한 줄에 같이 들어가려다 flex 최소폭 때문에 부모 max-width를
뚫고 넘침 — 판정 문구를 항상 자기 줄 전체(flex-basis:100%)로 분리해서 해결.

### §2-4. 포켓몬 도감 / 도구 도감 — 초기 화면(미선택 상태) 블록 비율 문제

포켓몬 도감 페이지, 도구 도감 페이지를 모바일에서 열었을 때, 아직 아무것도 선택되지 않은
초기 화면("포켓몬을 선택하세요" / "도구를 선택하세요" 문구가 표시되는 블록)이 옆의 리스트
블록보다 작아서 비율이 이상해 보임.

**대상**: 포켓몬 도감·도구 도감 페이지 컴포넌트(§9에서 보류된 "도감 페이지 2종 통합"과
같이 검토하면 좋을 수 있음).

**상태**: 완료(PR #126, dev 병합). 초기화면 블록에 최소 높이(리스트와 동일한 320px)를
주고 문구를 가운데 정렬.

### §2-5. 기술표 페이지 — 모바일에서 헤더 슬라이드 시 본문이 따라가지 않는 버그

아이폰 15 프로 사파리 기준, 기술표 페이지의 기술 상세표 상단 헤더는 [기술/타입/분류/접촉]과
[우선도/위력/명중률/PP] 두 그룹으로 나뉘어 슬라이드로 전환된다. 그런데 헤더를 슬라이드해도
그 아래 본문(기술 상세표)은 같이 슬라이드되지 않고 빈 공간만 표시됨 — 본문 내부를 직접

### §3-2. 그라운드코트 아이템 — 특성으로 펼쳐진 필드에는 효과 미적용

그라운드코트(필드 지속시간 연장 도구)가 **기술로 펼친 필드에는 적용**되지만(8턴 유지),

### §3-4. 필드 설치 특성/기술이 다른 필드를 덮어쓰지 못하는 버그

사용자가 §3-3 검증 중 실제 앱에서 발견 — 필드 설치 특성(사이코/그래스/일렉트릭메이커)과
필드 기술(그래스필드·사이코필드·일렉트릭필드·미스트필드)이, 이미 **다른** 종류의 필드가
깔려 있을 때도 실패함. 본가에선 날씨처럼 다른 필드가 새 필드로 덮어써져야 하는데, 이
프로젝트는 같은 필드든 다른 필드든 "이미 필드가 있으면 무조건 실패"로 막고 있었음.

원인 추적: `bb3787d`(ver.1.2 이전, "날씨/필드 시스템 추가") 커밋이 "필드 재설치 시
턴수가 갱신되던 버그"를 고치면서, 같은 필드 재설치만 막아야 할 걸 **모든** 필드 설치
시도를 막도록 과잉 수정한 것으로 보임.

**수정**: `mirroredEffects.ts`(기술 경로)·`state.ts`(배틀 시작 등장 특성)·
`switching.ts`(교체 등장 특성) 세 곳의 조건을 `if (기존 필드 존재)` →
`if (기존 필드 === 새 필드)`로 변경 — 같은 필드 재설치만 실패, 다른 필드는 덮어씀(날씨와
동일 동작). 실패 안내 문구도 "하지만 이미 다른 필드가 있어 실패했다!" →
"하지만 이미 같은 필드가 있어 실패했다!"로 정정.

**대상**: `src/lib/battle/mirroredEffects.ts`, `src/lib/battle/state.ts`,
`src/lib/battle/switching.ts`.

**상태**: 완료(PR #123, dev 병합). 필드 교체 시나리오(그래스→사이코→일렉트릭 순 덮어쓰기,
같은 필드 재시도 시 실패) 사용자 직접 확인 완료.

## 5. 보류 — 우선순위 최하단 (완료)

착수 전 엔진 스모크테스트로는 "이미 정상 동작"처럼 보였지만, 실제로 다른 트랙을 전부
끝내고 착수해 보니 **사용자가 직접 앱에서 재현하며 실제 버그를 여럿 더 찾아냈다** —
콘솔 스모크테스트만으론 못 잡는 UI/데이터 연동 문제들이었다. 아래는 최종적으로 확인·
수정된 전체 목록이다(PR #127, dev 병합).

### §5-1. 위기회피(Emergency Exit)

**실제 원인**: 엔진 로직(`resolveAction.ts`/`runTurn.ts`) 자체는 정상이었지만, 메가스톤을
지닌 포켓몬(예: 갑주무사+갑주무사나이트)의 **특성 선택 UI가 메가진화 여부와 무관하게
항상 메가폼 특성으로 고정**돼 있어서, 애초에 위기회피를 고를 방법이 없었다(§5-3 참고 —
같은 원인이라 §5-3에서 같이 수정).

**상태**: 완료. §5-3 수정으로 함께 해결.

### §5-2. 괴짜(메타몽)·변신 기술

사용자가 실제 배틀에서 검증하며 순서대로 발견한 버그 4건, 전부 수정:

1. **배틀 중 교체 등장 시 괴짜 미발동** — `state.ts`의 배틀 시작(리드) 전용 함수에만
   구현돼 있고 `switching.ts`의 교체 등장 처리(`applyEntryAbilityOnSwitchIn`)엔 아예
   빠져 있었음. 같은 로직 추가.
2. **변신해도 보드 표시가 안 바뀜** — 로그엔 "변신했다!"가 찍히는데 `BattleBoard`가
   이름/스프라이트/타입을 `fighter.slot.pokemonId`(원본 종) 기준으로만 계산해서 화면은
   그대로였음. `transformedIntoPokemonId` 필드를 신설해 스프라이트·타입 배지만 변신
   대상 모습으로(이름은 본가 규칙대로 원본 종 유지).
3. **변신해도 기술 버튼이 안 바뀜** — 기술 버튼 목록(`activeMoveIds`)이 배틀 시작 시점의
   정적 셋업 데이터만 읽고 있어서, 변신으로 실제 복제된 `fighter.remainingPp`를 반영 못
   했음(메타몽 자신의 "변신" 하나만 계속 뜸). 변신 상태면 `remainingPp`의 키를 쓰도록 수정.
4. **변신 대상이 메가진화 상태였으면 그 모습도 복제해야 함** — 안 되고 있었음.
   `transformedIntoMegaStone` 필드를 신설해 해당 메가폼 스프라이트로 표시.

원본 요청의 4줄 로그 문구("가라!/메타몽!/메타몽의 괴짜!/변신했다!")는 결국 스코프에서
빠짐 — 실제로 문제였던 건 문구가 아니라 위 UI/데이터 연동 쪽이었다.

**상태**: 완료.

### §5-3. (신규 발견) 메가스톤 소지만으로 특성이 메가폼 특성으로 고정되던 버그

§5-1을 조사하다 발견 — `getEffectiveAbilityId`가 "메가진화 **중**이면 특성 고정"이라는
본가 규칙을, "메가스톤을 **지니기만** 해도 고정"으로 잘못 일반화하고 있었다(실제
메가진화 선언 여부와 무관). 그래서 파티 샘플·배틀 시뮬레이션 양쪽에서 메가스톤을 든
포켓몬은 기본 특성을 아예 선택할 수 없었음(`AbilityPickerModal`이 선택지 자체를
잠가버림).

**수정**: `getEffectiveAbilityId`를 `slot.ability`를 그대로 돌려주는 형태로 단순화(결국
아무도 안 써서 함수 자체를 삭제하고 7개 호출부 정리) + `AbilityPickerModal`의 잠금
제거. 단, **매치업 페이지만은** 메가진화 전/후 결정력을 비교해봐야 하니
`includeMegaAbilityOption` prop으로 메가폼 특성을 "메가진화 시" 태그를 단 추가
선택지로 제공(강제 아님, 명시적으로 골라야 적용).

**대상**: `src/lib/pokemonForm.ts`, `src/components/AbilityPickerModal.tsx`,
`src/components/{BattleSetupCard,PartySlotCard,MatchupSlotCard,MatchupPage}.tsx`,
`src/lib/matchupEvaluator.ts`, `src/lib/battle/state.ts`.

**상태**: 완료.
