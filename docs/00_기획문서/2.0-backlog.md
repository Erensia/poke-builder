# ver.2.0 백로그 — AI 판단 강화 ver2

ver.1.9 판단 강화 ver1(6-1~6-4, §16 A1~A5)은 엔진 규칙과 AI 계산을 맞추는 정확도 수정이었고, 벤치는 전부 "오차 안"이었다
(규칙 맞추기는 승률로 드러나지 않을 만큼 수확이 줄었다). 지금까지 승률을 크게 올린 건 구조 변경 — 파티 단위 평가(229:167),
상대 교체 모델링(STATUS=1 213:184). 그래서 ver2는 **판단 구조**를 바꾼다. 근거는 `배틀AI 기획/battle-ai-decision-layer.md` §13·§16.

## 합의 (2026-09-29, 사용자)

- **턴당 판단 시간 한도: 최대 2초**(혼자 쓰는 단계라 1~2초 텀 허용).
- **완전 정보 전제 유지** — 사람보다 조금 더 어려워야 연습 상대로 가치가 있다.
- **순서: 0 → 1 → 2 → 3**(아래). 항목마다 dev에서 브랜치 → PR squash 머지(1.9와 같은 작업 규칙).
- **3선출 한계**(선출 계산의 상대 교체 끔, 선출 뒤 두 마리 순서)는 **ver2.0에 넣을지 따로 토의** — 토의 시기가 오면 Claude가 알린다
  (예정: 2단계 탐색 제품화 뒤 — 선출 계산도 탐색·새 상대 모델을 쓸 수 있는지가 그때 정해진다. 0단계 결과가 선출에 시사점을 주면 그때).
- 측정 원칙: 800판 h2h의 σ ≈ 14승이라 3% 이하 개선은 벤치로 못 가린다. ver2 항목은 예상 효과가 큰 것 위주, 작은 정확도 수정은
  시나리오(`npm run test:ai`)로 판정.

## 작업 순서

0. **탐색 오라클로 측정**(시뮬레이터 전용, 기본 끔 — 화면·기본 AI 무변화). 후보 행동마다 실제 `runTurn`으로 한 턴을 돌리고, 결과
   state를 지금 평가식으로 채점하는 느린 AI를 만들어 현재 AI와 h2h. 크게 이기면 2단계로 제품화할 가치, 차이가 없으면 평가식이 천장에
   가깝다는 뜻 → 1·3단계 비중을 키운다. 두 AI의 선택이 갈린 턴을 분류해 평가식의 약점 목록도 얻는다. 설계안: 아래 "0단계 설계안".
1. **상대 모델 ver2**: 상대 행동 확률을 고정 규칙(변화기 0.08, 공격기 데미지³ 비례, §2)에서 "상대도 같은 평가기로 판단"(한 단계
   추론) + 대전 중 관측한 선택으로 보정하는 쪽으로. 아래 "1단계 계획"(PR 3개).
2. **얕은 탐색 제품화**(0단계 결과가 좋을 때만): 상위 K개 후보만 롤아웃, 턴당 시간 예산(최대 2초), 필요하면 Web Worker.

## 1단계 계획 — 상대 모델 ver2 (2026-09-29 제안, 사용자 결정 반영)

지금 모델의 빈 곳: 상대의 **이번 턴 교체를 아예 안 봄**(§4-10은 다음 대면부터), 변화기 확률이 상황과 무관하게 0.08, 상대의 실제 성향을
안 씀. §2-2 보정(공격기 분배 다듬기)은 승률 오차 안이었으므로 "교체·변화기를 언제 쓰나"를 맞히는 쪽에서 이득을 노린다.

- **1-A 측정 도구 — 스타일 봇**(시뮬레이터 전용): 교체형(불리한 대면이면 자주 교체)·변화기형(랭크업·상태이상기 먼저)·무작위 섞음(지금
  AI에 차선책을 섞음 — 사람 실수 흉내). "상대도 나처럼 생각한다" 모델이 AI끼리만 유리해지는 거울 편향을 막는 판정 기준.
- **1-B 한 단계 추론(핵심)**: 상대 행동 확률 ∝ exp(상대 관점 평가 점수 / τ) — 교체·변화기 포함. 상대 쪽 평가는 지금 고정 모델(재귀
  한 단계). 적용 범위는 **지금 실제 대면의 이번 턴**(가상 대면·대면표는 고정 모델 유지 — 판단 시간). 고정 모델과 섞는 비율을
  파라미터로. 오라클 상대 응수·기습 성공 확률·방어류 시뮬레이션이 같은 분포를 쓴다.
  - **교체 읽기(사용자 결정 2026-09-29 — 넣음)**: 상대가 확률 q로 대기 j로 교체한다고 보면 내 공격기 점수를 (1−q) × 지금 상대 기준 +
    q × j 기준으로 섞어, 교체를 읽고 들어올 포켓몬을 노린다.
- **1-C 대전 중 관측 보정**: 상대가 고른 행동이 예측의 몇 순위였는지·교체·변화기 사용을 기록해 τ·교체 성향·변화기 성향을 베타 분포식으로
  보정. 엔진 state는 건드리지 않고 AI 메모리 객체를 `chooseAiAction` 옵션으로 넘긴다.
  - **학습 범위(사용자 결정 2026-09-29 — (나))**: 배틀타워에서 같은 사용자 상대로 **대전 간 누적 저장**(localStorage 새 키 — 파티
    자동저장 `champions-party-sim.party.v1`과 별도, 절대 건드리지 않음). 연습 상대가 사용자 습관을 점점 읽는다.
  - 저장은 원본 로그가 아니라 집계 통계만(전체 성향 + 사용자가 쓴 포켓몬별, 최근 100종 상한 — 최대 약 25KB). 사전값 = 가상 관측 10회.
  - **잊는 속도(사용자 결정 2026-09-29 — 최근 약 50판)**: 대전이 끝날 때마다 모든 횟수 × 0.98(유효 기억 1/(1−0.98) = 50판).
  - 화면 노출(초기화 버튼·습관 요약)은 UI 설계안 확인 후 결정.
- 판정: 스타일 봇 3종 + 그리디 + h2h(현재 AI 대비, STATUS=1·일반). 스타일 봇 상대로 오르고 나머지 오차 안이면 채택. 시나리오(교체 읽기·
  랭크업 타이밍) 추가, 판단 시간 기록(예상 +50~100ms).

## 0단계 설계안 (사용자 확인 2026-09-29 — 그대로 진행)

§4-4 방어류 한 턴 시뮬레이션(엔진 `runTurn` + 재평가)을 모든 선택지로 넓힌 것. 엔진이 처리하는 규칙(급소·추가효과·명중 분포, 상대
선공기, 다단히트 vs 띠·옹골참·탈, 포자·분노의경혈, 반동 뒤 쉬는 턴, 숨는 턴 회피 등 §16-2 한계 다수)이 자동으로 들어간다.

```
후보   = 지금 AI 옵션 전부(−∞ 제외). 하드 오버라이드(확정 처치)는 그대로 먼저.
상대   = 상대 행동 분포 — 상대 기술 사용 확률 모델(§2) + 상대 교체 모델(§4-10), 5% 미만 제외·최대 4~5개·재정규화
          (1단계에서 새 상대 모델로 바뀌면 오라클도 같이 좋아진다)
난수   = 시드 K개(기본 4) — 모든 후보가 같은 시드 묶음을 쓴다(공통 난수 — 후보끼리 비교 분산 감소)
for 후보 o, 상대 행동 (m, w), 시드 s:
    S1 = runTurn(state, o, m, rng(s))   # 유턴류 멈춤·기절 교체는 지금 AI의 교체 선택으로 이어서 진행
    값 = 그 턴 HP·마릿수 변화(판세 F 차이, §4-5) + 잎 평가(S1)
점수(o) = Σ_m w × 평균_s 값
잎 평가 = S1에서 AI 쪽 최선 옵션 점수(지금 평가식 그대로 — 정밀) / 대안: partyValueAfterTurn(대면표만 — 빠름). 둘 다 재서 비교.
깊이   = 1턴(기본). 변형: 2턴(두 번째 턴은 양쪽 모두 지금 AI 정책) — 1턴 대비 이득이 있는지 확인.
```

- 위치: `src/lib/battle/ai/search.ts`(2단계 제품화 때 그대로 쓰도록), `DecisionParams.search`로 켜고 끔(기본 끔 → regress·기본 AI 무변화).
- 측정: h2h 오라클 대 현재 AI(STATUS=1·일반 각 200~400판, 파티 좌우 교대) + 그리디, 턴당 판단 시간, 선택이 갈린 턴의 옵션 종류별
  분류(`DIAG=search`). 시간이 오래 걸리므로(턴당 수 초 예상) 벤치 조각 병렬(`npm run bench`)로.
- 판정: 오라클이 오차 밖으로 이기면 → 2단계(시간 예산 안으로 줄이기). 오차 안이면 → 선택이 갈린 턴 분류만 챙겨 1·3단계로.
