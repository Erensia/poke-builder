# Phase 6.5 기획 — 매치업 페이지 개선 및 로그 문구 정비

> 이어서 읽기: [Phase 6 기획](phase6-plan.md)
> Phase 6 §2-1 정비 후보 중 "매치업 페이지에 반영 안 된 축들"을 사용자와 논의하면서, 이 페이지 자체를 손보는 작업으로 범위가 커져 별도 페이즈로 분리했다(2026-08-26). 이후 Phase 6 §1-4(대전 로그 UI 문구 정비)도 착수 직전 사용자 재검토로 이 문서에 합류했다(2026-08-27, §4 참고) — 서로 직접 연관은 없지만 둘 다 "기존 걸 다듬는" 성격이라 같이 묶었다.

## 0. 배경

Phase 6에서 매치업 페이지(`MatchupPage.tsx`, `evaluateSlotMatchup`)에 반영 안 된 축 4개(매지션/곡예 도구 강탈, 곡예 스피드 2배, 고스트다이브 방어류 무시)를 발견했다. 이 프로젝트에는 페이지가 두 개 있다는 걸 먼저 정리해둔다:

- **대전 로그 페이지**(`BattleLogPage.tsx`, `runTurn`): 턴을 실제로 하나씩 진행시키는 배틀 시뮬레이터. 매 턴 상태(도구를 뺏겼는지, 직전에 무슨 기술을 썼는지 등)를 그대로 들고 가기 때문에 위 4개 효과가 이미 정상 반영돼 있다 — **손댈 것 없음**.
- **매치업 페이지**(`MatchupPage.tsx`, `evaluateSlotMatchup`): "결정력 vs 내구력" 한 방 비교 계산기. 턴 개념이 없는 스냅샷이라 "직전 턴에 뭘 했는지"에 의존하는 축이 반영될 자리가 없다.

**사용자 확인(2026-08-26)**: 매치업 페이지도 어디까지나 "1대1 포켓몬 대결"을 상정한 페이지이므로, 1대1 대결에서 실제로 반영돼야 하는 로직은 전부 반영돼야 한다는 게 사용자 의견 — 단, 이 축들은 "이전 턴에 뭘 가정하느냐"에 따라 결과가 달라지므로 **토글(켜고 끄기)로 사용자가 직접 가정을 선택**하는 방식으로 넣기로 확정했다.

## 1. 토글형 "이전 턴 가정" 4종

매치업 페이지 양쪽 슬롯에 각각 다음 토글을 추가한다(기본값은 전부 꺼짐 = 지금과 동일한 계산):

- **매지션/곡예로 상대 도구를 뺏었다고 가정** — 켜면 이 슬롯의 `item`을 없는 것으로 계산(또는 매지션/곡예 보유 슬롯이 상대 도구를 가져온 것으로 반영 — 세부 UX는 착수 시 결정).
- **곡예 발동 직후(스피드 2배)라고 가정** — 켜면 이 슬롯의 실효 스피드를 2배로 계산.
- **고스트다이브 2턴째(방어류 무시)라고 가정** — 켜면 이 슬롯이 상대의 방어/판별/버티기/킹실드를 무시하는 것으로 계산.

세부 구현 시 확인 필요: 토글이 "공격측/방어측 중 어느 슬롯"에 붙어야 하는지(효과별로 다름 — 예: 도구 강탈은 강탈한 쪽, 곡예 스피드는 곡예를 쓴 쪽 자신), 토글 간 상호 배제 필요 여부(예: 도구 강탈 토글을 켰는데 그 슬롯이 애초에 매지션/곡예 보유가 아니면 의미 없음 — UI에서 막을지 그냥 허용할지).

## 2. 스피드 비교 신설 (사용자 신규 요청, 2026-08-26)

매치업 페이지가 지금은 결정력·내구력만 비교하고(`computeOffensePower`, `computeBulkPower`, `evaluateMatchup`) 스피드는 아예 안 보여준다. 실제로 "누가 먼저 움직이는지"가 결정력/내구력만큼 중요한 축이라 스피드 비교를 신설한다.

- 최소 요구사항: 양쪽 슬롯의 실효 스피드(특성/도구/날씨/랭크 반영)를 계산해서 어느 쪽이 먼저 움직이는지 표시.
- 위 §1의 "곡예 스피드 2배" 토글과 자연히 연동돼야 한다(토글을 켠 슬롯의 스피드 계산에 2배가 반영된 상태로 비교).
- 세부 구현 시 확인 필요: 트릭룸 가정 토글도 같이 넣을지(스피드 역전), 마비로 인한 스피드 0.5배 가정도 넣을지 — 우선순위는 착수 시 사용자와 조율.
- **대안 검토 후 기각(2026-08-27)**: 사용자가 1차 정리 항목에서 "결정력&내구력 페이지와 같은 UI를 가진 완전히 별도의 새 페이지"로 다시 요청했으나, 재확인 결과 위 계획대로 **매치업 페이지 내 통합을 유지**하기로 확정 — 새 페이지 신설 없음.

## 4. 대전 로그 UI 문구 전면 정비 (Phase 6 §1-4에서 이월, 2026-08-27)

원래 Phase 6 §1-4로 편성돼 있던 항목인데, 착수 직전 사용자 재검토로 이 문서로 옮겨왔다. 매치업 페이지 개선과 직접 연관은 없지만, 두 작업 모두 "새 기능보다 기존 걸 다듬는" 성격이라 Phase 6.5에서 같이 다룬다.

Phase 5에서 특성/기술 로직을 워낙 많이(70종 넘게) 새로 붙이면서 `BattleLogPage.tsx`의 로그 문구가 그때그때 개별적으로 추가돼왔다 — 한 번에 모아서 톤·형식·정보량을 통일하는 리뷰가 필요하다.

- **지금 상태**: 로그 문구가 최소 6가지 서로 다른 패턴으로 흩어져 있다 — `STATUS_ONSET_TEXT`/`STATUS_TRIGGER_TEXT`/`STATUS_CURE_TEXT`(상태이상 3단계, 함수 맵), `VOLATILE_LABELS`(행동방해류, 칩 전용 라벨), 메인 라인에 인라인으로 박힌 `· OO 발동!` 조각들(수십 개), 특성 전용 문구(예: 흑안개 "양쪽의 능력 변화가 전부 원래대로 돌아갔다!", 대타출동 "대타가 대신 맞았다!"), 방어류 전용 문구, `moveRestrictionMessage`(도발/사슬묶기/앙코르). 특성이 발동했을 때 "OO의 [특성명]!"으로 시작하는 것도 있고 그냥 결과만 말하는 것도 있어 형식이 일관되지 않다.
- **필요한 작업**: (1) 전체 로그 문구를 한 번에 나열해서 톤(예: 전부 "OO의 [원인]! [결과]" 형식으로 통일할지)·정보량(포켓몬 이름을 매번 반복할지, 대명사로 줄일지)·기절 시 문구(현재 `battle-fighter-fainted`로 " (기절)"만 붙는데 더 명확한 문구가 필요한지)를 검토. (2) 함수 맵 방식(STATUS_*_TEXT)과 인라인 조각 방식이 혼재하는데 특성/기술이 계속 늘어날 걸 감안하면 어느 한쪽으로 통일하는 게 유지보수에 유리한지 결정. (3) 실제 대전 로그를 몇 판 돌려보면서 정비.
- **범위**: 로직 자체는 건드리지 않고 표시 문구만 다듬는 순수 UI 작업이라 회귀 위험은 낮지만, 문구가 수십 곳에 흩어져 있어 손이 많이 간다.

## 5. 매치업 페이지 추가 정비 후보 (사용자 1차 정리, 2026-08-27)

`docs/Phase6-테스트 중 발견한 수정할 점.txt`로 사용자가 실사용하며 정리해온 결정력&내구력 페이지 관련 항목들. 이 페이지 자체가 이미 Phase 6.5 대상이라 여기로 편입한다. 우선순위는 미정 — 착수 시 조율.

- **UI 문구 수정**: "내 포켓몬과 상대 포켓몬을 고르고, 기술까지 선택하면 몇 타에 끝나는지 판정해드려요." → "내 포켓몬과 상대 포켓몬을 고르고, 기술을 선택하면 타수 판정을 확인할 수 있습니다." (트리비얼)
- **실능치 카드에 랭크/도구/특성 변화 미반영**: 카드에 표시되는 실능치가 포인트 분배 기준 고정값이라, 랭크 변경·능력치 변화 도구(구애머리띠 등)·특성(가속 등)을 선택해도 표시가 안 바뀐다. 데미지 계산 자체(`computeBulkPower` 등)에는 이미 stages가 들어가고 있어(§0 참고) **표시값만 안 따라가는 버그**로 보임 — 중간 규모.
- **물리/특수 내구력 UI 추가**: 지금은 결정력만 계산해 보여주고 내구력 수치 자체는 카드에 없음 — 신규 UI, 소~중 규모.
- **날씨 배경 표시**: 날씨 선택 시 대전 로그 페이지와 같은 배경을 표시(컴포넌트 재사용) — 소~중 규모.
- **필드 선택 UI 신설**: 지금 매치업 페이지엔 필드(그래스필드 등) 선택 자체가 없음 — 대전 로그 페이지 필드 배경까지 재사용. §1의 토글 4종과 별개로 "필드 선택"이라는 축 자체가 빠져있던 것 — 중간 규모.
- **성묘 배율 x0/x1/x2 토글**: `moves.json`에 이미 "1v1이라 항상 기본 위력 50"이라 명시돼 있는 기술 — 쓰러진 동료 0/1/2마리 가정을 토글로 선택해 위력 50/100/150을 계산하도록. §1의 "이전 턴 가정 토글" 패턴과 동일 — 중간 규모.
- **부자유친이 결정력에 미반영**: 확인 결과 배틀 엔진(`battleSimulator.ts`)에는 이미 `followUpHitPowerMultiplier`로 구현돼 있음 — **매치업 페이지의 결정력 계산 함수에만 연결이 안 된 것**이라 예상보다 작은 작업(소~중 규모).
- **다단히트(2~5회) 결정력 세부 표시**: 록블라스트·스케일샷 등 `minHits`/`maxHits` 기술의 x2/x3/x4/x5별 결정력을 UI에 표기 — 신규 UI, 소~중 규모.

## 6. 대전 로그 페이지 추가 정비 후보 (사용자 1차 정리, 2026-08-27)

같은 1차 정리 파일에서 대전 로그 페이지 관련 항목. 순수 문구 성격인 것들은 §4(로그 문구 전면 정비)와 자연스럽게 합류, 로직/데이터 버그는 따로 표시했다.

- **랭크업 로그 표기**: 랭크업 기술 사용 시 "OO의 스피드가 크게 올라갔다!" 같은 결과 문구가 지금은 아예 없음 — §4 범위에 포함해 같이 정비. 중간 규모(문구 추가 자체는 대전 로그의 여러 지점에 배선 필요).
- **실능치 UI에 랭크 변화 반영(UX)**: 위 항목과 짝 — 랭크업 결과를 대전 로그의 실능치 표시에도 반영. §4와 함께.
- **특성 발동 문구(깨어진 갑옷 등) 부재**: 확인 결과 깨어진 갑옷(Weak Armor) 자체가 특성 로직으로 배선돼 있는지부터 확인이 필요 — 로직이 이미 있는데 문구만 없다면 §4 소관, 로직 자체가 없다면 별도 기능 추가. 착수 시 먼저 확인.
- **차징 기술 전용 문구(공중날기 등)**: 순수 문구 — §4에 포함.
- **판별/방어류 문구 버그**: 사용자 재현 시나리오가 "차징 기술(공중날기 등)과 판별이 겹칠 때 문구가 이상함"인데, 확인 결과 연속 사용 성공률 감소 메커니즘(`protectStreak`, (1/3)^n)은 **이미 구현돼 있다** — 말씀하신 "확률이 너무 높다"는 메커니즘 부재가 아니라 특정 조합에서 로그 문구가 잘못 표시되는 버그일 가능성이 높다. **착수 전 재현 시나리오 재확인 필요**(어느 쪽이 어떤 기술을 몇 턴째 냈는지).
- **일렉트로빔 chargeTurn 누락**: `moves.json` 확인 결과 실제로 `chargeTurn` 필드가 빠져있어 1턴 만에 바로 발동하는 데이터 버그였다 — Phase 6 §2-1에서 찾았던 메테오빔과 완전히 같은 패턴. **소규모, 바로 수정 가능.**

## 7. 길동무(Destiny Bond) 신설 — Phase 6로 배정 (사용자 확인, 2026-08-27)

1차 정리 항목 중 유일하게 완전 신규 메커니즘(전용 volatile 상태 + 승패 판정 로직 변경)이 필요해 다른 "다듬기" 성격 항목들과 규모가 다르지만, 별도 문서를 새로 만들 정도는 아니라는 사용자 판단으로 **Phase 6**에 포함하기로 확정했다. 자세한 요구사항은 [phase6-plan.md](phase6-plan.md) §2-1 참고.
