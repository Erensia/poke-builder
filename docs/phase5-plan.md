# Phase 5 기획 — 특성 전투 로직 확장 & 1v1 범위 내 잔여 메커니즘

> 이어서 읽기: [Phase 4.5 기획](phase4.5-plan.md)
> Phase 4.5에서 로스터 확장(§1)·사이드 메뉴 활성화(§2)·필드 개별 기술 상호작용(§3)·도구 개별 효과(§4)를 마쳤다. 남은 건 외부 확인만 하면 되는 항목(§5)뿐이라 그건 Phase 4.5 안에서 마저 처리하기로 했고, 이 문서는 그 대신 "확인"이 아니라 "새 엔진 인프라를 여러 개 새로 만들어야 하는" 대규모 항목들을 모아서 분리한 것이다(사용자 지시).

## 0. 이 문서의 성격

Phase 4.5 §8(특성 60종, 이 문서를 쓰면서 재점검한 최신 수치)과 §7(파티 확장 대기 항목 중 1v1 범위에서 가능한 두 개)을 그대로 옮겨왔다. 항목별 배경은 [phase4.5-plan.md](phase4.5-plan.md)와 그 위 링크를 따라가면 된다.

## 1. 설명 텍스트만 있고 전투 로직 미구현인 특성 60종 (Phase 4.5 §8 이월)

라이츄 추가 때 정전기·피뢰침·일렉트릭메이커·노가드를 abilities.json에 "설명 텍스트만" 넣고 전투 로직 연결은 보류했는데(사용자 확인), 그러면서 보니 이 패턴이 이미 기존 로스터 특성 다수에 광범위하게 퍼져 있었다. `abilityModifiers.ts`가 실제로 소비하는 필드는 `modifiers`(offense/defense 배율)·`setsWeather`·`stabOverride`·`bypassesImmunityForTypes` 4가지뿐이고, 이 필드가 하나라도 채워진 특성만 전투 계산에 실제로 반영된다.

abilities.json은 처음 발견 당시(라이츄 추가 시점) 54개였지만 이후 로스터가 계속 늘면서(망나뇽·불카모스·초염몽·캥카·밀로틱·마폭시·입치트·곤율거니·몰드류·나무킹·하마돈·대쓰여너) 지금은 **72개**다. 이 문서를 쓰는 시점 기준으로 다시 전수 확인한 결과, 저 4개 필드가 하나도 없는 **60개**가 여전히 설명 텍스트만 있고 실제로는 아무 효과도 없다(`battleSimulator.ts` "모래숨기 같은 특성 쪽 배율은 아직 없음" 주석이 사실상 이 전체를 대표하는 TODO).

**이미 연결된 12개** (참고용): 단단한발톱, 가뭄, 메가런처, 두꺼운지방, 페어리스킨, 모래의힘, 모래날림, 적응력, 테크니션, 잔비, 배짱, 철주먹

**미구현 60개**를 메커니즘 유형별로 묶으면:

| 유형 | 필요한 확장 지점 | 해당 특성 |
|---|---|---|
| HP 1/3 이하 자기 타입 위력 1.5배 | `modifiers`에 `hpBelowThird` 같은 조건 추가 | 맹화, 급류, 심록, 벌레의알림 |
| HP 가득 찬 상태 조건부 방어 배율 | 방어측에 `hpIsFull` 같은 조건 신설 | 멀티스케일 |
| 날씨 조건부 스탯 배율/회복 | `modifiers`의 `weatherIs`는 있지만 스탯 배율·회복은 별도 로직 필요 | 선파워, 엽록소, 쓱쓱, 모래숨기(회피), 옹골참, 젖은접시, 모래헤치기 |
| 자신 상태이상 조건부 배율 | `selfStatusIs` 같은 조건 신설 | 이상한비늘 |
| 접촉 피격 시 발동(확률부 상태이상/데미지/랭크변화) | 방어측 트리거 훅 전체가 없음 — 가장 큰 신규 인프라 | 정전기, 저주받은바디, 까칠한피부, 헤롱헤롱바디, 깨어진갑옷, 불꽃몸 |
| 특정 타입 기술 피격 시 발동 | 위와 같은 방어측 트리거 훅 | 정의의마음, 타오르는불꽃, 지구력, 피뢰침 |
| 자신 랭크 하락/풀죽음 시 발동 | 방어측 트리거 훅(스탯 하락·풀죽음 감지) | 승기, 불굴의마음 |
| 상대를 쓰러뜨릴 때 발동 | 공격측 KO 트리거 훅 | 자기과신 |
| 타입 면역 부여 | `bypassesImmunityForTypes`(면역 무시, 공격측)의 반대 방향 — 방어측 스스로 면역을 얻는 경로가 아직 없음. 단, Phase 4.5 §4에서 검은철구(`Item.groundsHolder`)로 "방어측 도구가 스스로 면역을 무시하는" 경로는 이미 한 번 만들어봤으니 그 패턴을 참고 | 부유, 피뢰침(중복 표기, 무효화+랭크업 둘 다 필요) |
| 상태이상/랭크 면역·반사·전이 | 상태이상/랭크 판정 훅 필요 | 유연, 정신력, 싱크로, 클리어바디, 미러아머, 괴력집게 |
| 상태이상 해제 확률 수정 | `statusConditions.ts`의 해제 스케줄(잠듦 등) 확장 | 일찍기상 |
| 턴 종료 시 확률부 자가 치료 | 매 턴 종료 처리에 훅 추가 | 탈피 |
| 명중률/회피율 특수 규칙 | `accuracyCrit.ts` 확장 | 날카로운눈, 노가드 |
| 등장 시 1회 발동(필드/스탯변화/특성복사 등) | `setsWeather`와 같은 패턴으로 `setsField`·`entryStatChange` 등 신설 | 일렉트릭메이커, 트레이스, 긴장감, 습기, 그림자밟기, 위협 |
| 우선도 조작 | `Move.priority`와 별개로 특성발 우선도 가산 필요 — Phase 4.5 §4에서 선제공격손톱(도구)으로 비슷한 우선도 개입을 이미 구현해봤으니 참고 가능 | 짖궂은마음 |
| 벽/대타 무시 | `setsScreen` 방어 로직에 예외 추가 | 틈새포착 |
| 랭크변화 무시(데미지 계산) | `moveContext.ts`에서 랭크 반영 전 분기 필요 | 천진 |
| 상대 방어적 특성 무시 | "특성 무효화" 판정 축 자체가 새로 필요(범위가 넓어 신중하게 설계해야 함) | 틀깨기 |
| 능력치 자체 배율 | `statCalculator.ts`의 실수치 계산에 특성 배율 추가 | 천하장사 |
| 부가효과·위력 트레이드 | 기술 자체를 변형하는 새 로직(우격다짐 전용) | 우격다짐 |
| 추가타 | 기술 실행 후 2차 공격을 자동으로 붙이는 로직 | 부자유친 |
| 도구 상호작용(탈취/소모 트리거) | 도구 이동·소모 이벤트 훅 | 매지션, 곡예 |
| 접촉기 방어 무시 + 최소 데미지 보장 | 데미지 계산에 방어 무시 + 최소 비율 보장 로직 추가 | 관통드릴 |
| 기타(무게·PP·타입변경 등 1회성) | 각각 별도 메커니즘, 재사용성 낮음 | 라이트메탈, 프레셔, 서투름, 촉촉보이스, 변환자재, 텔레파시, 굳건한신념 |

이 60개를 전부 한 번에 구현하는 건 범위가 너무 크다 — Phase 4.5 §4(도구 개별 효과)처럼 항목별로 서로 다른 메커니즘이 필요해서 우선순위를 매겨 나눠 진행하는 편이 낫다. 특히 "접촉 피격 시 발동" 훅은 정전기·저주받은바디·까칠한피부·헤롱헤롱바디·깨어진갑옷·불꽃몸 6개가 동시에 덕을 보는 공용 인프라라 먼저 붙이면 투자 대비 효율이 가장 좋다.

(발견 경위: Phase 4.5 §1 라이츄 추가 작업 중 abilities.json 전수 점검. 이후 로스터가 더 늘어난 걸 반영해 이 문서를 쓰면서 재점검함)

## 2. 1v1 범위 내에서 가능한 잔여 메커니즘 (Phase 4 §9 이월 중 파티 무관 항목만)

원래 "파티 단위 확장이 먼저 논의돼야 함" 백로그에 다른 항목들과 같이 묶여 있었지만, 이 둘은 실제로는 파티 개념과 무관하고 1v1 범위 안에서 바로 만들 수 있다 — 그냥 각각 별도의 신규 메커니즘이 필요해서 우선순위가 낮았을 뿐:

- **고스트다이브의 "상대 방어 무시"**: 나이트헤드류(`Move.fixedDamage`)처럼 고정 데미지 필드를 쓰는 게 아니라, "방어 능력치 자체를 무시하고 계산"하는 새로운 필드(예: `ignoresDefenseStat: true`)가 필요하다 — fixedDamage는 데미지 수치 자체를 고정하지만 고스트다이브는 위력에 따라 데미지가 변하되 방어만 무시해야 해서 별개 메커니즘.
- **잠꼬대**("배운 기술 중 하나를 무작위로 사용"): "잠든 상태에서 이 기술을 선택하면, 실제로는 자신이 배운 다른 기술 중 하나를 무작위로 대신 발동시킨다"는 대체 실행 로직 자체가 `battleSimulator.ts`에 없다. `usageCondition: "sleep-only"`(코골기)와는 다른 축 — 코골기는 "쓸 수 있냐 없냐"만 판정하지 "다른 기술로 바꿔치기"는 안 한다.

## 3. 파티 단위 확장이 먼저 논의돼야 하는 항목 (참고용 — Phase 5 범위 아님)

아래는 Phase 5에도 포함하지 않는다. 1v1 단일 대전 시뮬레이터라는 설계 전제 자체를 안 건드리면 의미가 없어서, 파티 배틀 확장을 언젠가 논의하게 되면 그때 다시 별도 Phase로 검토한다. [phase4.5-plan.md §6](phase4.5-plan.md#6-설계-범위-밖--파티-단위-확장이-먼저-논의돼야-함-phase-4-9-이월-일부-phase-5로-이동)에 그대로 남아있다.

- **엔트리 해저드**(독압정 등)
- **집단구타**
