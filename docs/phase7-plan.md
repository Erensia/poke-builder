# Phase 7 기획 — 대전 로그 문구 전면 정비 & 진영 설치 기술

> 이어서 읽기: [Phase 6.5 기획](phase6.5-plan.md)
> Phase 6.5를 닫으면서 그 문서의 §4(대전 로그 UI 문구 전면 정비)와 §8(상대 진영 설치 기술 · 매직미러)을 이월받았다(2026-08-28). 둘 다 "6.5 범위에서 다루기엔 크거나, 선행 인프라가 필요해서" 미뤄둔 항목이다.

## 0. 이 문서의 성격

Phase 6.5는 "기존 걸 다듬는" 페이즈였고, 그 안에서 대전 로그의 개별 문구 버그·랭크업 결과 문구 같은 건 각 항목의 로직 수정과 함께 처리했다(6.5 §6-2). Phase 7은 그 나머지를 맡는다:

- **§1 대전 로그 문구 전면 정비**: 순수 표시 문구 작업. 로직은 안 건드린다. 지금 바로 착수 가능하지만, 문구가 수십 곳에 흩어져 있어 손이 많이 간다.
- **§2 상대 진영 설치 기술 · 매직미러**: 스텔스록만 6.5 §6-2 ④에서 "설치 상태 + 환경 UI + 설치/실패 문구"까지 부분 선반영됐다. 나머지(스택·제거·독타입 교체 해제·등장 시 데미지)와 매직미러 반사는 **파티 선출·교체 인프라가 선행돼야** 한다 — 교체가 없는 현행 1대1 엔진에선 "등장 시" 이벤트가 발생할 일이 없다.

착수 순서: **§1 먼저**(선행 조건 없음). §2는 교체 인프라를 어느 페이즈에서 만들지 정해진 뒤에.

## 1. 대전 로그 UI 문구 전면 정비 (6.5 §4 이월)

원래 Phase 6 §1-4 → Phase 6.5 §4로 옮겨졌다가, 6.5에서 2차 테스트 개별 항목(6.5 §6-2)이 늘어나면서 "문구를 전부 나열해 톤·형식을 한 번에 통일하는" 이 전면 정비만 다시 미뤄졌다. 개별 문구 버그(탈/지구력 문구, 랭크업 결과 문구, 랭크 상한 문구, 방어 실패 문구, 깨어진갑옷 문구)는 6.5에서 이미 처리됐으므로, Phase 7 §1은 **그러고도 남은 문구 전체**를 대상으로 한다.

### 1-1. 배경

Phase 5에서 특성/기술 로직을 70종 넘게 새로 붙이면서 `BattleLogPage.tsx`의 로그 문구가 그때그때 개별적으로 추가돼왔다. 한 번에 모아서 톤·형식·정보량을 통일하는 리뷰가 필요하다.

### 1-2. 지금 상태 — 흩어진 문구 패턴 (2026-08-28 기준 코드 확인)

`src/components/BattleLogPage.tsx` 한 파일 안에 최소 이만큼의 서로 다른 방식이 섞여 있다:

| 방식 | 위치(대략) | 예시 |
|---|---|---|
| 상태이상 3단계 함수 맵 | `STATUS_ONSET_TEXT` / `STATUS_TRIGGER_TEXT` / `STATUS_CURE_TEXT` (`:135`~) | `"OO는 화상을 입었다!"` / `"OO는 화상 데미지를 입었다!"` |
| 행동방해류 칩 전용 라벨 | `VOLATILE_LABELS` (`:54`), `SCREEN_LABELS` (`:72`), `STATUS_LABELS` (`:45`) | 칩 UI에만 쓰는 짧은 명사(`"풀죽음"`, `"리플렉터"`) |
| 메인 라인 인라인 조각 | 로그 렌더 JSX 곳곳의 `<> · OO 발동!</>` (수십 개) | `· 매지션 발동! 상대의 OO을 빼앗았다!`, `· 상대 편 필드에 뾰족한 바위가 깔렸다!` |
| 특성 전용 문구 | 렌더 JSX 분기 | 흑안개 `"양쪽의 능력 변화가 전부 원래대로 돌아갔다!"`, 대타출동 `"대타가 대신 맞았다!"` |
| 방어류 전용 문구 | 렌더 JSX 분기 (`:754`, `:997`, `:1005`) | `"OO의 방어는 실패했다!"`, `"OO는 방어로 몸을 지켰다!"` |
| 기술 선택 제약 | `moveRestrictionMessage` (`:219`) | `"OO는 도발에 걸려 변화기를 사용할 수 없어요."` (여기만 "~해요" 말투) |
| 랭크 변화 결과 | `stageRiseAdverb` + 조사 헬퍼(`eunNeun`/`iGa`/`eulReul`/`roEuro`) 조합, 6.5에서 추가 | `"OO의 공격이 크게 올라갔다!"`, `"OO의 방어는 더 이상 올라가지 않는다!"` |

일관성이 깨지는 지점:

- 특성 발동을 **"OO의 [특성명]!"으로 시작**하는 것(지구력·깨어진갑옷·탈)과 그냥 **결과만** 말하는 것(정전기 상태이상 부여 등)이 섞여 있다.
- **포켓몬 이름을 매번 반복**한다 — 한 로그 블록 안에서 "따라큐의 탈! 따라큐의 정체가 드러났다! 따라큐는 반동으로…"처럼 3번 나오기도 한다.
- **말투**가 대부분 "~했다!"인데 `moveRestrictionMessage`만 "~해요" 체다.
- 기절 표시가 `battle-fighter-fainted` 클래스로 `" (기절)"`만 붙는다 — 별도 로그 라인이 없다.

### 1-3. 필요한 작업

1. **전체 문구 목록화**: `BattleLogPage.tsx`에서 사용자에게 보이는 문자열을 한 곳에 전부 뽑아 표로 정리(원인·결과·현재 문구·화면 위치).
2. **톤·형식 결정** (사용자와 함께):
   - 특성/도구/기술 발동을 전부 `"OO의 [원인]! [결과]"` 형식으로 통일할지.
   - 한 블록 안에서 포켓몬 이름을 반복할지, 2번째부터 대명사(예: "그 포켓몬은")로 줄일지.
   - 말투를 "~했다!"로 완전 통일(=`moveRestrictionMessage`도 교체).
   - 기절 시 전용 로그 라인(`"OO는 쓰러졌다!"` 등)을 추가할지.
   - 차징 기술 준비 턴 문구(공중날기·구멍파기 등 "OO는 하늘 높이 날아올랐다!") — 6.5 §6-1에서 이 §으로 이월된 항목. 준비 턴·해제 턴 문구를 여기서 같이 정한다.
3. **구조 통일 방침 결정**: 함수 맵 방식(`STATUS_*_TEXT`)과 인라인 조각 방식이 혼재하는데, 특성/기술이 계속 늘어날 걸 감안하면 어느 한쪽(권장: 데이터/함수 맵으로 모으기)으로 통일하는 게 유지보수에 유리한지 판단.
4. **적용 + 검증**: 실제 대전 로그를 여러 판(상태이상·방어·랭크업·차징·설치기·다단히트 조합) 돌려보며 다듬는다.

### 1-4. 범위·리스크

- **로직은 건드리지 않는다** — 표시 문자열만. 회귀 위험은 낮다.
- 다만 문구가 수십 곳에 흩어져 있고, 조사(은/는, 이/가, 을/를, 로/으로) 자동 판별 헬퍼와 얽혀 있어 손이 많이 간다. 헬퍼(`eunNeun`·`iGa`·`eulReul`·`roEuro`)는 6.5에서 정비돼 있으니 그대로 재사용.
- `battleSimulator.ts`가 넘겨주는 로그 이벤트 필드 자체는 충분하다(6.5에서 랭크업·지구력·스텔스록용 필드까지 추가됨) — 새 이벤트 배선 없이 표시층만 고치면 되는 게 대부분.

## 2. 상대 진영 설치 기술 · 매직미러 (6.5 §8 이월)

**전체 메커니즘은 파티 선출·교체가 도입된 뒤에 구현**한다. 스텔스록만 6.5 §6-2 ④에서 부분 선반영됐다(항상 상대 진영, 매직미러 없음, 설치 상태 + 환경 UI + 설치/실패 문구까지).

### 2-1. 정의

변화 기술 중 상대방 진영에 부정적인 장치를 설치하는 기술("장판기"). 압정류는 중복 사용으로 효과가 누적된다.

**해당 기술 6종**: 끈적끈적네트 · 독압정 · 비검천중파 · 스텔스록 · 암석액스 · 압정뿌리기

### 2-2. 스택 규칙

- **독압정**: 1장 = 일반 독, 2장 = 맹독.
- **압정뿌리기**: 1장 = 최대 HP 1/16, 2장 = 1/8, 3장 = 1/4.
- 스텔스록·끈적끈적네트 등 나머지는 1장으로 고정(중복 무의미 → 재사용 시 "실패").

### 2-3. 제거 방법

- **고속스핀 / 안개제거**: 자기 진영(고속스핀) 또는 양 진영(안개제거)의 설치물을 걷어낸다.
- **독압정 한정**: 독 타입 포켓몬이 교체로 나오면 그 즉시 사라진다.

### 2-4. 등장 시 처리 (교체 인프라 선행)

- 교체로 포켓몬이 나오는 순간 그 진영의 설치물이 발동한다 — 스텔스록(바위 상성 배율만큼 HP), 압정뿌리기(스택별 비율), 독압정(독/맹독), 끈적끈적네트(스피드 -1), 비검천중파(고스트 부착) 등.
- 부유·비행 타입·에어벌룬 등 "땅에 닿지 않는" 대상은 압정뿌리기·끈적끈적네트·독압정을 무시한다(스텔스록은 그대로 맞음).
- **설치 시 문구(스텔스록, 6.5에서 선반영)**: `"우리 편 필드에 뾰족한 바위가 떠다니기 시작했다!"` / (상대 진영) `"상대 편 필드에 뾰족한 바위가 깔렸다!"`

### 2-5. 매직미러(Magic Bounce) — 조사 필요

현재 코드에 이 특성이 아예 없다. 본가 매직미러는 스텔스록뿐 아니라 **상대를 겨냥한 변화기 전반**(도발·씨뿌리기·도깨비불·전기자석파·짓궂은태도류·설치기 등)을 시전자에게 되돌려보낸다. 착수 전 확인할 것:

- 반사 범위를 어디까지 볼지 — 스텔스록만? `isOpponentTargetingMove`(현재 `fieldEffects`에서 export, 사이코필드·방어 판정과 공유 중) 전체?
- 반사된 기술의 처리 주체 — 시전자가 자기 자신에게 쓴 것으로 재평가할지, 결과만 뒤집을지.
- 이 프로젝트에서 매직미러를 가질 포켓몬이 있는지(없으면 데이터는 비워두고 로직만).
- `isOpponentTargetingMove`를 그대로 반사 판정에 재사용할 수 있는지.

### 2-6. 선행 조건

- **파티 선출·교체 인프라**. 아직 어느 페이즈에서 만들지 정해지지 않았다 — 정해지면 이 §의 착수 시점도 거기에 맞춘다.
- 교체가 생기면 6.5에서 "1대1·교체 없음"을 근거로 되돌려둔 것들도 같이 복원 대상이다:
  - 특성 가속(Speed Boost)의 "교체로 나온 턴엔 미발동" 예외 (6.5 §6-2 ①에서 `state.turnNumber > 1` 가드를 제거했음).
  - 일루전(조로아크)·일부 등장 효과 특성의 실제 로직.

## 3. 이 페이즈에 넣지 않는 것

- **특성 복안(명중률 1.3배)·인분(추가효과 무효) 로직 배선** — 6.5 §9에서 비비용 로스터를 추가하며 데이터만 등록했다. 1대1 유효 특성이라 언젠가 붙여야 하지만, 문구 정비(§1)나 설치기(§2)와 성격이 달라 별도로 다룬다(작은 항목이라 §1 착수 시 곁다리로 처리할 수도 있음 — 착수 시 판단).
