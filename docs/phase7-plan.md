# Phase 7 기획 — 대전 로그 문구 전면 정비 & 진영 설치 기술

> 이어서 읽기: [Phase 6.5 기획](phase6.5-plan.md)
> Phase 6.5를 닫으면서 그 문서의 §4(대전 로그 UI 문구 전면 정비)와 §8(상대 진영 설치 기술 · 매직미러)을 이월받았다(2026-08-28). 둘 다 "6.5 범위에서 다루기엔 크거나, 선행 인프라가 필요해서" 미뤄둔 항목이다.

## 0. 이 문서의 성격

Phase 6.5는 "기존 걸 다듬는" 페이즈였고, 그 안에서 대전 로그의 개별 문구 버그·랭크업 결과 문구 같은 건 각 항목의 로직 수정과 함께 처리했다(6.5 §6-2). Phase 7은 그 나머지를 맡는다:

- **§1 대전 로그 문구 전면 정비**: 순수 표시 문구 작업. 로직은 안 건드린다. 지금 바로 착수 가능하지만, 문구가 수십 곳에 흩어져 있어 손이 많이 간다.
- **§2 상대 진영 설치 기술 · 매직미러**: 스텔스록만 6.5 §6-2 ④에서 "설치 상태 + 환경 UI + 설치/실패 문구"까지 부분 선반영됐다. 설치기 6종의 스택·제거·독타입 교체 해제·등장 시 데미지는 **파티 선출·교체 인프라가 선행돼야** 한다 — 교체가 없는 현행 1대1 엔진에선 "등장 시" 이벤트가 발생할 일이 없다. **매직미러 반사는 예외로 2026-08-28에 이미 배선했다**(메가픽시 로스터 추가와 함께) — 반사는 교체 없는 대면에서도 완전히 정의되므로. §2-5 참조.
- **§3 곁다리 특성 로직**: 로스터를 넓히다 딸려온 특성 배선. 복안·페어리오라·매직가드·매직미러·인분 완료, 플라워베일·공생만 남음(1대1 엔진 구조상 발동 불가 — 교체 페이즈 대기). §3 참조.

착수 순서: **§1 먼저**(선행 조건 없음). §2 설치기는 교체 인프라를 어느 페이즈에서 만들지 정해진 뒤에.

## 1. 대전 로그 UI 문구 전면 정비 (6.5 §4 이월)

원래 Phase 6 §1-4 → Phase 6.5 §4로 옮겨졌다가, 6.5에서 2차 테스트 개별 항목(6.5 §6-2)이 늘어나면서 "문구를 전부 나열해 톤·형식을 한 번에 통일하는" 이 전면 정비만 다시 미뤄졌다. 개별 문구 버그(탈/지구력 문구, 랭크업 결과 문구, 랭크 상한 문구, 방어 실패 문구, 깨어진갑옷 문구)는 6.5에서 이미 처리됐으므로, Phase 7 §1은 **그러고도 남은 문구 전체**를 대상으로 한다.

### 1-1. 배경

Phase 5에서 특성/기술 로직을 70종 넘게 새로 붙이면서 `BattleLogPage.tsx`의 로그 문구가 그때그때 개별적으로 추가돼왔다. 한 번에 모아서 톤·형식·정보량을 통일하는 리뷰가 필요하다.

### 1-2. 지금 상태 — 흩어진 문구 패턴 (2026-08-28 기준 코드 확인)

`src/components/BattleLogPage.tsx` 한 파일 안에 최소 이만큼의 서로 다른 방식이 섞여 있다:

| 방식 | 위치(대략) | 예시 |
|---|---|---|
| 상태이상 3단계 함수 맵 | `STATUS_ONSET_TEXT` / `STATUS_TRIGGER_TEXT` / `STATUS_CURE_TEXT` (`:135`~) | `"OO는 화상을 입었다!"` / `"OO는 화상 데미지를 입었다!"` |
| 행동방해류 칩 전용 라벨 | `VOLATILE_LABELS` (`:54`), `SCREEN_LABELS` (`:72`), `STATUS_LABELS` (`:45`) | 칩 UI에만 쓰는 짧은 명사(`"풀죽음"`, `"리플렉터"`) |
| 메인 라인 인라인 조각 | 로그 렌더 JSX 곳곳의 `<> · OO 발동!</>` (수십 개) | `· 매지션 발동! 상대의 OO을 빼앗았다!`, `· 상대 편 필드에 뾰족한 바위가 깔렸다!` |
| 특성 전용 문구 | 렌더 JSX 분기 | 흑안개 `"양쪽의 능력 변화가 전부 원래대로 돌아갔다!"`, 대타출동 `"대타가 대신 맞았다!"` |
| 방어류 전용 문구 | 렌더 JSX 분기 (`:754`, `:997`, `:1005`) | `"OO의 방어는 실패했다!"`, `"OO는 방어로 몸을 지켰다!"` |
| 기술 선택 제약 | `moveRestrictionMessage` (`:219`) | `"OO는 도발에 걸려 변화기를 사용할 수 없어요."` (여기만 "~해요" 말투) |
| 랭크 변화 결과 | `stageRiseAdverb` + 조사 헬퍼(`eunNeun`/`iGa`/`eulReul`/`roEuro`) 조합, 6.5에서 추가 | `"OO의 공격이 크게 올라갔다!"`, `"OO의 방어는 더 이상 올라가지 않는다!"` |

일관성이 깨지는 지점:

- 특성 발동을 **"OO의 [특성명]!"으로 시작**하는 것(지구력·깨어진갑옷·탈)과 그냥 **결과만** 말하는 것(정전기 상태이상 부여 등)이 섞여 있다.
- **포켓몬 이름을 매번 반복**한다 — 한 로그 블록 안에서 "따라큐의 탈! 따라큐의 정체가 드러났다! 따라큐는 반동으로…"처럼 3번 나오기도 한다.
- **말투**가 대부분 "~했다!"인데 `moveRestrictionMessage`만 "~해요" 체다.
- 기절 표시가 `battle-fighter-fainted` 클래스로 `" (기절)"`만 붙는다 — 별도 로그 라인이 없다.

### 1-3. 필요한 작업

1. **전체 문구 목록화**: `BattleLogPage.tsx`에서 사용자에게 보이는 문자열을 한 곳에 전부 뽑아 표로 정리(원인·결과·현재 문구·화면 위치).
2. **톤·형식 결정** (사용자와 함께):
   - 특성/도구/기술 발동을 전부 `"OO의 [원인]! [결과]"` 형식으로 통일할지.
   - 한 블록 안에서 포켓몬 이름을 반복할지, 2번째부터 대명사(예: "그 포켓몬은")로 줄일지.
   - 말투를 "~했다!"로 완전 통일(=`moveRestrictionMessage`도 교체).
   - 기절 시 전용 로그 라인(`"OO는 쓰러졌다!"` 등)을 추가할지.
   - 차징 기술 준비 턴 문구(공중날기·구멍파기 등 "OO는 하늘 높이 날아올랐다!") — 6.5 §6-1에서 이 §으로 이월된 항목. 준비 턴·해제 턴 문구를 여기서 같이 정한다.
3. **구조 통일 방침 결정**: 함수 맵 방식(`STATUS_*_TEXT`)과 인라인 조각 방식이 혼재하는데, 특성/기술이 계속 늘어날 걸 감안하면 어느 한쪽(권장: 데이터/함수 맵으로 모으기)으로 통일하는 게 유지보수에 유리한지 판단.
4. **적용 + 검증**: 실제 대전 로그를 여러 판(상태이상·방어·랭크업·차징·설치기·다단히트 조합) 돌려보며 다듬는다.

### 1-4. 범위·리스크

- **로직은 건드리지 않는다** — 표시 문자열만. 회귀 위험은 낮다.
- 다만 문구가 수십 곳에 흩어져 있고, 조사(은/는, 이/가, 을/를, 로/으로) 자동 판별 헬퍼와 얽혀 있어 손이 많이 간다. 헬퍼(`eunNeun`·`iGa`·`eulReul`·`roEuro`)는 6.5에서 정비돼 있으니 그대로 재사용.
- `battleSimulator.ts`가 넘겨주는 로그 이벤트 필드 자체는 충분하다(6.5에서 랭크업·지구력·스텔스록용 필드까지 추가됨) — 새 이벤트 배선 없이 표시층만 고치면 되는 게 대부분.

## 2. 상대 진영 설치 기술 · 매직미러 (6.5 §8 이월)

**설치 기술 6종의 스택·제거·등장 데미지는 파티 선출·교체가 도입된 뒤에 구현**한다. 스텔스록만 6.5 §6-2 ④에서 부분 선반영됐다(항상 상대 진영, 설치 상태 + 환경 UI + 설치/실패 문구까지). 매직미러(Magic Bounce)는 2-5로 분리했고 메가픽시 로스터 추가와 함께 **이미 배선 완료**(2026-08-28) — 아래 참조.

### 2-1. 정의

변화 기술 중 상대방 진영에 부정적인 장치를 설치하는 기술("장판기"). 압정류는 중복 사용으로 효과가 누적된다.

**해당 기술 6종**: 끈적끈적네트 · 독압정 · 비검천중파 · 스텔스록 · 암석액스 · 압정뿌리기

### 2-2. 스택 규칙

- **독압정**: 1장 = 일반 독, 2장 = 맹독.
- **압정뿌리기**: 1장 = 최대 HP 1/16, 2장 = 1/8, 3장 = 1/4.
- 스텔스록·끈적끈적네트 등 나머지는 1장으로 고정(중복 무의미 → 재사용 시 "실패").

### 2-3. 제거 방법

- **고속스핀 / 안개제거**: 자기 진영(고속스핀) 또는 양 진영(안개제거)의 설치물을 걷어낸다.
- **독압정 한정**: 독 타입 포켓몬이 교체로 나오면 그 즉시 사라진다.

### 2-4. 등장 시 처리 (교체 인프라 선행)

- 교체로 포켓몬이 나오는 순간 그 진영의 설치물이 발동한다 — 스텔스록(바위 상성 배율만큼 HP), 압정뿌리기(스택별 비율), 독압정(독/맹독), 끈적끈적네트(스피드 -1), 비검천중파(고스트 부착) 등.
- 부유·비행 타입·에어벌룬 등 "땅에 닿지 않는" 대상은 압정뿌리기·끈적끈적네트·독압정을 무시한다(스텔스록은 그대로 맞음).
- **설치 시 문구(스텔스록, 6.5에서 선반영)**: `"우리 편 필드에 뾰족한 바위가 떠다니기 시작했다!"` / (상대 진영) `"상대 편 필드에 뾰족한 바위가 깔렸다!"`

### 2-5. 매직미러(Magic Bounce) — 구현 완료 (2026-08-28, 메가픽시 로스터 추가와 함께)

메가픽시(픽시 + 픽시나이트)가 이 특성을 고정으로 갖게 되면서, 교체 인프라를 기다리지 않고 **현행 1대1 엔진 기준으로 배선했다**. 반사 자체는 교체 없는 대면에서도 완전히 정의된다(도발·도깨비불·씨뿌리기·랭크 하락기 등이 시전자에게 그대로 꽂힘). 스텔스록 반사만 "등장 데미지가 없어" 진영 플래그만 뒤집히는 실질 무해 상태로 남는다.

**반사 대상 판정** (`battleSimulator.ts` `bouncedByMagicMirror`):
- `move.category === "status"` 이고
- `isOpponentTargetingMove(move)` 가 참이거나 `move.setsHazard` 가 있고 (설치기는 `isOpponentTargetingMove`가 잡지 않아 OR로 포함)
- `move.notReflectable` 가 아니고 (반사 제외: 고스트 저주·추억의선물·멸망의노래·흔들흔들댄스에 이 플래그를 붙였다)
- 방어측 `defenderAbility?.reflectsOpponentStatusMoves` 가 참이고
- 방어측의 방어/대타/황금몸으로 이미 막히지 않았을 때(`!opponentEffectsBlocked`).

**처리 방식**: "방어측 방향 효과" 블록(랭크변화 → 상태이상 → volatile → 씨뿌리기 → 사슬묶기/앙코르 → 스텔스록)에 진입하기 직전 `attacker`/`defender`(+ Ability·Item 바인딩)를 통째로 맞바꾸고, 블록이 끝나면 원위치한다. 그래서 되돌린 기술은 **원래 시전자 기준으로 타입 면역·조사·도구·승기·멘탈허브까지 전부 재평가**된다(예: 개굴닌자의 도깨비불은 시전자에게 반사돼 화상, 리자몽의 도깨비불은 시전자가 불꽃 타입이라 조용히 무산). 반사된 기술은 명중 굴림을 건너뛴다(빗나가지 않음).

**틀깨기 상호작용**: `MOLD_BREAKER_IMMUNE_ABILITY_NAMES`에서 `"매직미러"`를 제거했다(본가에서 틀깨기가 매직미러를 무시하는 게 맞다 — 기존 목록이 부정확했음). 이제 공격측이 틀깨기면 `resolveEffectiveDefenderAbility`가 `defenderAbility`를 `undefined`로 만들어 반사도 자연히 무산된다.

**로그(임시)**: 메인 라인에 `— OO의 매직미러! 기술이 되돌아왔다!` 클립을 붙이고, 상태이상 onset·하품·스텔스록 문구의 주어를 `bouncedMoveName` 유무로 뒤집는 최소 처리만 했다. 상대 랭크 하락 기술은 애초에 이 엔진에 전용 로그 줄이 없어(§1에서 신설 예정) 반사돼도 눈에 보이는 줄이 없다 — §1 문구 정비 때 매직미러 케이스를 함께 다룬다.

**아직 안 한 것**: 뽐내기/부추기기(랭크업+혼란)가 통째로 반사되는지는 `inflictsVolatile` + `statChanges` 둘 다 opponent라 자동으로 되지만, 로그 표기는 §1 대기. 바꿔치기·트릭·스킬스왑은 `isOpponentTargetingMove`가 false라 반사 대상에서 자연히 빠진다(별도 플래그 불필요).

### 2-6. 선행 조건

- **파티 선출·교체 인프라**. 아직 어느 페이즈에서 만들지 정해지지 않았다 — 정해지면 이 §의 착수 시점도 거기에 맞춘다.
- 교체가 생기면 6.5에서 "1대1·교체 없음"을 근거로 되돌려둔 것들도 같이 복원 대상이다:
  - 특성 가속(Speed Boost)의 "교체로 나온 턴엔 미발동" 예외 (6.5 §6-2 ①에서 `state.turnNumber > 1` 가드를 제거했음).
  - 일루전(조로아크)·일부 등장 효과 특성의 실제 로직.

## 3. 곁다리 특성 로직 — 로스터 확장과 함께 처리 중

§1·§2와 성격이 다른 "새 포켓몬을 넣다 보니 딸려온" 특성 배선을 여기 모은다.

### 3-1. 완료 (2026-08-28)

- **복안** (비비용, 6.5 §9) — 자기 기술 명중률 ×1.3. `Ability.userAccuracyMultiplier` → `battleSimulator`의 `accuracyExtraMultiplier`에 합류(모래숨기와 같은 축, 방향만 반대). 필중기·100% 기술엔 무영향.
- **페어리오라** (메가플라엣테, §9와 별개로 플라엣테 로스터 추가분) — 장 전체 페어리 기술 위력 ×1.33. `Ability.auraMoveTypeMultiplier` → `moveContext.resolveMoveContext`가 공격측·방어측 양쪽을 보고 offense 배율에 합류(배틀 시뮬 + 매치업 페이지 공용). 오라브레이크는 로스터에 대상 없어 미구현.
- **매직가드** (픽시) — 공격기 데미지 외 부가 피해 무효. 이 엔진에 실재하는 5경로만 게이팅: 상태이상 지속 데미지(걸린 상태·맹독 카운터는 유지, HP만 0)·씨뿌리기(상대 회복도 없음)·반동기·생명의구슬 반동·까칠한피부류 접촉 반사. `Ability.negatesIndirectDamage`. 혼란 자멸·화상 물리 감소는 막지 않음(본가 일치). 날씨 스립·압정·소금절이·포박기 2차 데미지·스텔스록 등장 데미지는 이 엔진에 아직 없어 대상 없음(생기면 같은 플래그로 확장 — 타입 주석 명시).
- **매직미러** (메가픽시) — §2-5 참조.
- **인분** (비비용) — 방진(Shield Dust)형. 방어측이 이 특성이면 데미지 기술이 자신에게 딸려 거는 **추가효과**를 전부 무산. `Ability.blocksSecondaryEffects` → `battleSimulator`의 4곳(statChanges 필터 · inflictsStatus 블록 · inflictsVolatile per-entry · 왕의징표석 풀죽음)에서 게이팅. 로그 `secondaryBlockedByAbilityName` → "OO의 인분! 추가 효과를 받지 않는다!".
  - **"추가효과" 정의 확정** (§ 별도 논의): 데미지 기술(`category !== "status"`)이 상대에게 딸려 거는 상태이상·행동방해·랭크변화. **`chance` 유무 무관** — 연옥 100% 화상·일렉트릭네트 100% 스피드↓·천추지한 100% 특공↓도 추가효과. 변화기 주효과(도깨비불 등)·자기 대상 효과(반동·자기 랭크변화)는 제외. 왕의징표석(도구발 풀죽음)도 인분이 막는다.
  - 계획 초안에서 `Move`에 `secondary?` 플래그 + 5개 기술 태깅을 예상했으나, 정의가 "데미지기 + 상대 방향"이라는 **순수 구조 규칙**으로 정리되면서 **스키마 변경·데이터 마이그레이션 불필요**해졌다. `hasSheerForceSecondaryEffect`(우격다짐)와 같은 정의를 공유(우격다짐은 여기에 자기 랭크업까지 얹음) — 주석에 단일 기준 명시.
  - **곁다리 버그 수정**: 확률부 `statChanges`(불꽃춤 자기 특공↑ 50% · 브레이크클로 상대 방어↓ 50%)가 `applyMoveStatChanges` 기본 `includeChanceBased=true` 때문에 굴림 없이 100%로 적용되던 걸, battleSimulator에서 명시적으로 굴리도록 수정.

### 3-2. 남음
- **플라워베일 · 공생** (플라엣테) — 현행 1대1 엔진에서 구조적으로 발동 불가라 스텝만 등록(설명 텍스트). 플라워베일은 보유자가 풀타입일 때만 자기 자신을 보호하는데 플라엣테는 페어리 + 로스터에 풀타입 플라워베일 없음. 공생은 아군 슬롯이 없어 트리거 자체가 없음. 프렌드가드(더블 전용, 6.5 §9)와 같은 선례. 더블 배틀이나 풀타입 플라워베일 포켓몬이 생기면 그때.
