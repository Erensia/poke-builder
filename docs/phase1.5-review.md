## 2. 챔피언스 전용 능력치 공식 확정

메인 시리즈와 다르다는 걸 확인하고 새로 정의:

```
HP        = 종족값 + 75 + 능력포인트
기타 스탯 = (종족값 + 20 + 능력포인트) × 성격보정(1.1 / 0.9 / 1.0)
```

- 레벨·개체값 개념 없음 (본가 노력치는 "능력포인트"로 축약)
- 능력포인트: **스탯 하나당 최대 32**, 6스탯 합산 최대 66 (처음엔 스탯당 상한이 없어서 한 스탯에 66을 몰아줄 수 있었던 버그를 사용자가 지적해 수정)
- 성격 21종 (본가 25종 중 무보정 성격 4개가 `성실` 하나로 통합)
- `lib/statCalculator.ts`(계산) / `data/natures.json`(성격 데이터) / `types/nature.ts`

## 3. 결정력·내구력 라이브러리

나무위키 자료를 그대로 구현하되, 사용자가 제시한 실제 예시(마릴리 결정력 53,760 / 냐오닉스 내구력 61,654.5)로 정확히 재현되는 것까지 검증했다.

- **결정력**: 공격(특공) 실능 × 위력 × 자속(기본 1.5, 적응력이면 2.0) × 상성 × 특성/도구/날씨 배율 × 랭크업 배율
- **내구력**: (체력 실능 × 방어(특방) 실능) ÷ 0.411 × 랭크업 배율
- **랭크업 배율**: `(k + max[0,x]) / (k - min[0,x])`, 기본 스탯은 k=2. 확인된 표(-6~+6, 25%~400%)와 정확히 일치
- **5단계 판정**(`evaluateMatchup`): 확정 1타 / 난수 1타 / 확정 2타 / 난수 2타 / 3타 이상 필요
  - 확정·난수 1타는 나무위키 상수(0.374 / 0.411 / 0.44)를 상세 데미지 공식으로 직접 유도해 검증(6,384개 랜덤 케이스 중 99.95% 일치, 나머지는 `+2` 보정항 오차)
  - 확정·난수 2타는 "최저(최고) 난수 데미지가 상대 HP의 절반 이상이면 두 번 합쳐 확정(가능) 격파"라는 사용자 제시 논리로 유도(0.374×2=0.748, 0.44×2=0.88)
  - ⚠️ 도중에 "내구력을 다시 그 상수로 나누는" 이중 나눗셈 버그가 있었다가 발견·수정됨 — 상수는 전부 "체력×방어"에 직접 적용해야 하고, 이미 0.411로 나눠 만든 내구력 값을 재사용하려면 비율(0.411/상수)로 환산해야 한다
- **랭크 상태**(`types/battleStats.ts`, `lib/statStages.ts`): 5개 전투 스탯의 -6~+6 랭크. `Move.statChanges`(칼춤 등 28개 기술에 반영)를 읽어 자동으로 적용하는 `applyMoveStatChanges` 포함, 저주처럼 사용자 타입에 따라 갈리는 조건부 효과도 지원
  - ⚠️ **버그가 있다가 발견·수정됨**: 매치업 화면에서 랭크를 올리고 내려도 결정력·판정이 전혀 안 바뀌는 문제가 있었다. `MatchupPage.tsx`가 `evaluateSlotMatchup()`을 호출할 때 `attackerStages`/`defenderStages` 옵션 자체를 안 넘기고 있어서, 함수 내부 기본값(0랭크)으로만 계산됐던 게 원인. 방어측 카드에 보이는 물리/특수내구 숫자는 별도 계산(`baseBulk`)이라 정상적으로 반영되고 있어서 더 헷갈렸다. 슬롯에 저장된 `stages`를 그대로 넘기도록 고쳐서 해결 — 랭크 +2 → 결정력 정확히 ×2, 방어 -2랭크 → 판정이 "3타 이상 필요"에서 "확정 2타"로 바뀌는 것까지 실측 확인
- **특성 배율**(`lib/abilityModifiers.ts`): 테크니션(위력≤60) · 적응력(자속 2.0) · 모래의힘(날씨+타입 조건) · 두꺼운지방(내구력, 타입 조건) · 메가런처(파동 분류) · 페어리스킨(노말→페어리 타입 변경+배율) · 단단한발톱(접촉기 조건) 7개 구조화, 실제 데이터로 전부 배율 검증
- **다단히트 기술**: 트리플악셀처럼 맞을 때마다 위력이 바뀌는 기술을 `Move.multiHitPowers`(타수별 위력 배열)로 표현. 매치업 화면에 ×1/×2/×3 선택 버튼을 두고, 선택한 타수까지 위력을 합산해서 결정력에 반영
- **결정력 표기 방식**: 상대 타입 상성을 곱하기 전(`rawOffensePower`, 굵은 글씨)과 곱한 후(`offensePower`, 캡션 글씨) 둘 다 한 줄에 보여줌 — 처음엔 상성 반영값 하나만 보여줘서 다른 계산기와 비교할 때 "왜 절반밖에 안 나오냐"는 혼동이 있었다
- **통합 함수**(`lib/matchupEvaluator.ts`): `evaluateSlotMatchup()` 하나로 포켓몬 조회 → 메가폼 → 실수치 → 랭크 → 특성 배율 → 타입 상성 → 결정력/내구력/판정까지 전부 연결

## 4. 새로 확인된 사실: 기술 분류·접촉기·우선도 데이터

기존 "Champions 기술표" 아티팩트에 있었지만 처음엔 버렸던 분류 컬럼(구슬/폭탄·물기·베기·펀치·소리·파동·춤·바람)을 다시 파싱해 복구했고, 이후 사용자가 접촉/비접촉 표시를 추가한 갱신판 아티팩트를 다시 보내줘서 `Move.makesContact`까지 채웠다. 가장 최근에는 우선도·랭크 변화·연속 타격 상세정보가 추가된 표를 받아 331개 기술의 타입/카테고리/위력/명중률/PP/우선도를 전면 재검증했다:

- 접촉기 여부는 규칙으로 추정하지 않고(비접촉 물리기·태그 없는 접촉기 둘 다 있어서 위험 판단) 표에 있는 값을 그대로 가져왔다
- 원본 표에 있던 실제 버그(라우드본·삼삼드래 섹션 127개 행에서 앞 9개 셀이 중복 출력됨)를 파싱 스크립트로 우회
- 21마리 × 여러 기술 데이터를 다수결로 병합한 뒤, 표 자체의 오탈자로 의심되는 항목 3건(나이트헤드/사이코노이즈/트릭)은 사용자에게 직접 확인받아 확정
- 이 과정에서 마이너 시리즈 기준으로 추정해뒀던 5개 기술(게으름피우기·트림·플레어송·양날박치기·트라이어택)의 진짜 수치를 확인 — 예를 들어 양날박치기는 노말/120/100%로 추정했었는데 실제로는 **바위 타입·위력 150·명중 80%**로 전혀 달랐음

## 6. 결정력 & 내구력 UI

새 사이드바 메뉴로 진입하는 별도 화면.

- **좌우 배치**: 왼쪽 "내 포켓몬", 오른쪽 "상대 포켓몬" — 파티 빌더 2열과 동일하게 오른쪽 카드가 15px 아래로 오프셋. (처음에 "15px 아래"라는 말을 문자 그대로 받아들여 상하 스택으로 잘못 구현했다가, 사용자가 실제 화면 스크린샷을 보내줘서 좌우 배치로 정정)
- 포켓몬을 고르면 실수치가 즉시 갱신되고, 특성·도구·성격·능력포인트·랭크 상태를 각각 pip→모달로 편집
- 결정력은 기술을 고른 뒤에만 표시, 내구력(물리/특수)은 상대 포켓몬만 고르면 바로 표시
- 날씨 선택기(없음/쾌청/비/모래바람/눈) — 모래의힘 같은 날씨 조건부 특성과 연동
- 중앙에 5단계 판정 배지, 색상으로 위험도 구분(`--danger` / `--warn` / `--safe` 토큰 추가)
- 파티 빌더 화면에도 성격/능력포인트 pip가 동일하게 추가됨(매치업 화면과 동일 컴포넌트 재사용) — Phase 1에서 보류했던 EV 편집 UI가 자연스럽게 해결됨

### 사이드바 리디자인

hover 시 펼쳐지는 접이식 레일(64px↔220px)로 다시 디자인했고, 완성되기까지 사용자 피드백을 받으며 여러 차례 수정했다:

1. 유니코드 글자 아이콘(⬡⚔▤≡) → 폰트 대체마다 광학 중심이 달라 강조 배경과 안 맞는 문제가 있어 고정 `viewBox`의 SVG 아이콘으로 전면 교체
2. hover(`:hover`)만으로 펼침을 제어하면 메뉴 클릭 후에도 마우스가 사이드바 위에 남아있는 동안 안 접히는 문제 → React 상태(`expanded`)로 직접 제어해 클릭 즉시 접히도록 변경
3. 펼침/접힘 애니메이션이 두 번 움직이는 것처럼 뻑뻑해 보이는 문제 → `justify-content`처럼 transition이 안 걸리는 속성을 상태별로 바꾸던 걸 없애고, 아이콘 위치를 고정한 채 라벨만 자라나게 변경
4. 그래도 접혔을 때 강조 배경 오른쪽이 잘려 보이는 문제 → 원인은 `padding-left`(라벨 자리용, 36.8px)가 접힌 레일의 실제 폭(31px)보다 커서 **버튼 박스 자체가 부모보다 넓게 부풀어 넘친 것**이었다. 접힘/펼침 상태별로 패딩 값을 다르게 주고 그 값 자체를 transition 시켜서 해결
5. 로고 아이콘과 nav 아이콘의 중심이 안 맞는 문제 → 로고 컨테이너의 불필요한 좌우 패딩이 같은 종류의 오버플로 문제를 일으키고 있었음. 패딩을 없애 nav 아이콘과 같은 기준(레일 중앙)으로 정렬

> 참고: 이 세션에서 쓴 브라우저 프리뷰 환경이 화면을 실제로 합성(compositing)하지 못해 CSS `transition`이 중간에 멈춰버리는 제약이 있었다. 검증할 땐 `transition: none`을 임시로 걸어 최종 상태 값을 강제로 확인하는 방식을 썼다.

## 7. 로컬 개발 환경

사용자 환경에 5173 포트를 쓰는 다른 프로젝트("가계부 앱")가 있어서, `vite.config.ts`에 `server.port: 5174`, `strictPort: true`를 고정했다. 이 프로젝트를 열 때는 항상 `http://localhost:5174`를 쓴다. (`strictPort`를 켜서 혹시 5174도 막혀 있으면 조용히 다른 포트로 넘어가지 않고 바로 에러를 내도록 함 — 어느 포트에 떠 있는지 헷갈리는 일 방지)

## 8. Phase 2로 이월된 것 / 다음에 할 것

- **턴 순서 계산 로직 없음**: `Move.priority`는 채워졌고 `computeEffectiveSpeed()`도 있지만, 우선도→스피드 순으로 "누가 먼저 움직이는지" 비교하는 로직 자체가 아직 없다
- **대전 로그/다중 턴 시뮬레이션 없음**: 지금은 1턴 스냅샷 판정(결정력 vs 내구력)만 가능. 상태이상 매턴 데미지, 랭크 누적, PP 소모까지 이어지는 여러 턴짜리 엔진은 미착수
- **레벨 항이 필요한 "상세 데미지 공식"은 여전히 미구현**: 챔피언스가 상시 레벨 50 취급인지 확인 안 됨. 결정력/내구력 비교 판정으로는 이미 5단계까지 커버되므로 시급하지 않음
- **회피율/급소율 랭크는 여전히 스키마 밖**: 그림자분신/기충전/안개제거 등 관련 기술 있음
