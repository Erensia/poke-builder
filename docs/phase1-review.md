# Phase 1 회고 — 파티 빌더 MVP

> 최초 기획: [Champions Party Planner](https://claude.ai/code/artifact/af23cb03-2554-4fde-b789-d3310b4cd607) 문서 기준
> 이 문서는 실제 구현 결과를 기준으로 기획을 재검토하고, Phase 2(전투 시뮬레이터) 착수 전 기준선을 남기기 위해 작성한다.

## 1. 목표 대비 결과

| 원래 계획한 항목 | 상태 | 비고 |
|---|---|---|
| 샘플 포켓몬 10~20마리 + 기술/특성/도구 데이터 | ✅ | 19마리, 실측 종족값/특성/기술 전량 확보 |
| 6슬롯 파티 구성 UI (포켓몬 → 기술4/특성1/도구1) | ✅ | 기획보다 확장 — 도구 장착 시 메가폼 자동 전환까지 구현 |
| 파티 전체 타입 약점·저항 요약 뷰 | ✅ | 클릭 시 포켓몬별 상성까지 드릴다운 |
| 메가진화 대상 포켓몬 진화 후 스탯·타입 토글 | ✅ | 수동 토글 대신 "메가스톤 장착=자동 발동" 방식으로 확정 |
| 로컬 스토리지 파티 저장/불러오기 | ✅ | 슬롯 변경마다 자동 저장, 새로고침 시 복원, 초기화 버튼 |
| 사이드 메뉴 | ✅ (계획에 없었으나 추가) | 파티 빌더만 활성, 포켓몬 도감/기술표는 자리만 확보 |
| EV/성격/레벨 실수치 계산 | ⏸ 보류 | 카드 UI가 망가질 정도로 입력 필드가 많아 별도 모달 패턴으로 Phase 1.5 이후로 미룸 |

## 2. 최종 데이터 규모

- 포켓몬 19종 (메가진화 보유 12종, 그중 리자몽은 메가X/Y 2종)
- 기술 330개
- 특성 43개
- 도구(메가스톤) 13개
- 18타입 상성표 1식

### 데이터 소스의 변화

1차로는 사용자가 직접 구술한 종족값/특성/기술 목록을 받아 입력했고, 확신이 없는 기술은 `type: null` 상태의 TODO로 남겨 표시했다. 이후 사용자가 정리한 **Champions 기술표** 아티팩트(19마리 × 전체 배움표, HTML 표 형식)를 받아 파싱 스크립트로 전량 재추출·병합했다. 이 과정에서:

- 기존에 233개였던 기술이 330개로 늘었고, 기존 기술 중 245개의 위력/명중률/PP가 표 기준으로 보정됨
- `도발`/`부추기기`, `속임수`/`속이기`, `플레어드라이브`/`불꽃세례`, `기습`/`깜짝베기` 등 이름이 비슷해 같은 기술로 의심했던 케이스들이 실제로는 전부 **서로 다른 기술**이었음이 표 데이터로 확인됨 (예: `속이기`는 도구 교환기가 아니라 노말/물리/40 위력의 별개 기술)
- 마지막까지 남았던 34개 TODO 기술 전량 해소, 참조 무결성(learnset ↔ moves) 100% 검증 완료

## 3. 알려진 갭 (Phase 2 전 채워야 할 것들)

- **특성 설명(`Ability.description`) 43개 전부 빈 문자열** — 전투 시뮬레이터에서 특성 효과를 실제로 계산하려면 구조화된 effect 데이터가 필요
- **도구 설명(`Item.description`) 13개 전부 빈 문자열**
- **기술 63개의 `effect` 텍스트 미기재** (기술표 병합으로 새로 추가된 기술 위주) — 수치는 정확하지만 부가효과 서술이 빠져 있음
- EV/IV/성격/레벨 미구현 → 지금은 종족값 기준 상성만 보여줄 뿐 실전 데미지 계산 불가

## 4. 확정된 아키텍처 결정

- **타입/이름 표기**: 모든 id는 한국어 그대로 사용 (`"리자몽"`, `"리자몽나이트X"` 등). 로마자 표기 안 씀.
- **메가진화 스키마**: `Pokemon.megaEvolutions?: MegaEvolution[]` — 폼이 여러 개(메가X/Y) 있는 경우 배열 원소로 구분, 각 원소가 자기 `megaStone` id를 가짐
- **메가 발동 방식**: 파티 슬롯의 `item`에 메가스톤을 넣으면 `useParty.setItem`이 자동으로 `activeMegaForm`을 세팅. 도구를 빼거나 다른 도구로 바꾸면 기본형으로 복귀
- **실효 폼 계산 단일화**: `lib/pokemonForm.ts`의 `getEffectiveForm(pokemon, slot)`이 아바타 색상 · 타입 배지 · 타입 상성 계산에서 전부 공용으로 쓰임 (Phase 2 데미지 계산에도 재사용 가능하게 설계)
- **저장 방식**: `PartySlot[6]`을 그대로 JSON 직렬화해 `localStorage`에 저장 (`champions-party-sim.party.v1`). 다중 파티 저장은 아직 없음 — 필요해지면 같은 스키마에 이름/id만 얹으면 확장 가능

## 5. UI/디자인 결정

- 색상: 플래티넘 톤 뉴트럴(`--bg`, `--surface`) + 바이올렛(`--violet`) 베이스, 블루(`--blue`) 그라데이션 포인트. 라이트/다크 토큰 분리 완료
- 파티 슬롯: 2열×3행, 카드 148px 높이 유지. 기술 pip는 배정된 기술의 타입 색으로 배경이 바뀜
- 2열은 1열보다 15px 아래로 어긋나게 배치(리듬감), 좁은 화면(1열 레이아웃)에서는 자동 해제
- 특성/도구/EV는 전부 "슬롯의 작은 pip → 클릭 시 모달" 패턴으로 통일 — 카드 자체는 항상 미니멀하게 유지

## 6. 폴더 구조 (최종)

```

├─ types/        Pokemon, Move, Ability, Item, Party, PokemonType 등 도메인 타입

                 PokemonPickerModal, MovePickerModal, AbilityPickerModal,
                 ItemPickerModal, Modal, TypeBadge
```

## 7. Phase 2 착수 전 제안

1. 특성/도구 `description`을 구조화된 effect로 채우기 (텍스트만이라도 우선)
2. 남은 기술 63개 effect 텍스트 보강
3. 데미지 계산에 필요한 EV/IV/성격/레벨 입력 모달 추가
4. 턴 순서·우선도·데미지 공식 설계 (기술표에 있던 `우선도` 컬럼 데이터는 아직 스키마에 반영 안 됨 — 필요 시 `Move.priority` 필드 추가 검토)
